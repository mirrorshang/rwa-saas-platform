# RWA SaaS V1｜Token 管理 UI-Ready 最终规格

> 设计日期：2026-11-11  
> 状态：Issuer 企业 SaaS 端产品/UI 规格完成（UI-Ready）；真实合约部署、Signer、Mint/Burn、链上生产执行仍须独立生产准入。  
> 维护分支：docs/r2-current-product-baseline｜PR #8 Draft / Open / Unmerged  
> 适用范围：企业 SaaS → Token 管理  
> 本文件是当前 Token 管理模块唯一 UI-Ready 执行规格；历史 DEC/SCOPE 保留为业务原则依据，不替代本文件的页面字段和交互。

## 0. 依据、边界与收口结论

本规格承接以下已批准内容，不重新批准其业务原则：

- DEC-021：Token 方案、合约参数版本与部署审批、接收钱包、获批准 Mint、链上最终性/Unknown、配售与登记核对、必要合约级转让限制、高风险权限与暂停、依法需要时的赎回销毁/授权调整。
- DEC-054：合约/Token 管理的四页六项产品方向；具体模板、参数、真实链、Signer、法律审批和生产技术仍需独立准入。
- SCOPE-186～193：TokenContractPlan/Version、真实外部受权执行、M11资金/M12配售登记/M07 Token链事实分离、投资者账户/付款地址/Token接收钱包/法定持有人分离、必要转让限制、职责分离、Unknown安全恢复。
- DEC-032、DEC-033：合法配售/登记、Token 交付、存续清偿/公司行动分别保留权威事实；Burn 不能代替真实付款或法律权利终止。
- DEC-068、U01：Free/Standard、企业钱包与生产准入边界；Free 不能真实部署或 Mint，Standard 付费本身也不等于生产授权。
- DEC-071、U02-08：一资产一套当前权益结构；权益类型为股权、债权、收益参与权；Token 总份数及每 Token 对应法律权益量由权益结构版本确定，不能静默舍入。
- DEC-072、U02-09：Offering 固定引用权益结构版本；本期发行数量不能超过权益容量；支付链与 Token 发行链不能被默认视为同一网络。
- DEC-076、U02-13：配售与法定持有人登记各自独立；Token 链上数量与法律权益数量分列；锁仓记录独立归「资产与发行 → 锁仓记录」。
- DEC-077、U02-14：认购款真实到账/退款/募集款划拨归资金与结算；Token 模块只引用相关权威结果。

**本模块目标：** 让企业一眼看清 Token 方案是否准备完成、合约是否真实部署、哪些配售可以申请交付、每项链上操作处于什么状态、链上 Token 与法定登记是否一致，以及异常下一步由谁处理。

**不代表：** 任何具体链、Token 标准、合约模板、法域、真实发行主体、登记主体、Signer/密钥、Provider、链最终性阈值、智能合约安全审计、真实部署/Mint/Burn 或生产准入已经获批。

## 一、导航与页面结构

### 1.1 唯一导航

一级导航：**Token 管理**

二级导航固定为：

1. **合约管理**
2. **Token 操作**
3. **链上记录与对账**

不新增一级/二级菜单，不恢复历史上独立的 Token 发行方案、Token 记录、钱包管理等入口。

### 1.2 页面地图

合约管理：
- Token 方案列表
- Token 方案创建/编辑（单页）
- Token 方案详情
- 部署申请与真实部署结果

Token 操作：
- Mint 与交付
- 限制与暂停
- 销毁与授权调整（仅在适用法律/Instrument 触发时开放）

链上记录与对账：
- 链上事件列表
- 链上事件详情
- Token 与配售/法定登记对账
- 差异调查与处理历史

页面间关系：
- 合约管理维护 TokenContractPlan/Version 及部署结果。
- Token 操作仅引用已部署、可用的合约方案和其他模块的权威业务依据。
- 链上记录与对账只展示真实链上事件、最终性和差异，不另建订单、资金、持有人或 Token 余额主账。

### 1.3 与资产及发行的关系

- 唯一业务入口仍为「Token 管理」；资产详情中的权益结构、发行方案只显示 Token 方案/交付的必要摘要和跳转。
- 一个 Asset 只有一套当前有效 Instrument；多个 Offering 引用确定的 InstrumentVersion 和共享权益容量。
- V1 默认同一 InstrumentVersion 使用同一份当前有效 Token 方案版本；各 Offering 引用该方案，不为每一期复制独立 Token 供给池。
- Token 方案绑定 Asset、InstrumentVersion 和适用发行安排；若实际法律/合约模型要求独立合约或其他映射，必须在相应法域/生产准入中另行确认，不作为企业用户默认自由配置项。
- Token 总份数、每 Token 对应法律权益量、权益单位及精度继承自确定的 InstrumentVersion；Token 管理不得重新定义或覆盖权益结构。
- Offering 的本期发行数量、认购价格、认购时间、收款钱包仍由 Offering 管理；不得在 Token 管理中重复编辑。

### 1.4 核心业务对象必须分开

| 对象/事实 | 权威责任 | Token 管理的处理 |
|---|---|---|
| Asset、Instrument、法律权益单位 | 资产与发行 / 有权法律主体 | 只读引用固定版本 |
| Offering 条款与本期发行安排 | 资产与发行 | 只读引用 |
| 认购订单与投资者账户 | 投资者与认购 | 只读关联订单 |
| 真实到账、退款与资金核对 | 资金与结算及实际有权资金主体 | 只读引用资金状态；不确认收款、不退款 |
| 配售决定与法定持有人登记 | 配售与持有人及实际有权登记主体 | 以唯一获批配售/登记结果作为 Token 操作依据 |
| Token 方案、部署、Mint/Burn、链上最终性 | Token 管理及实际受权 Signer | 本模块唯一维护 Token 链上执行事实 |
| 收益、本息、赎回/清退与实际偿付 | 收益与分配及实际义务/资金主体 | 仅在适用时引用偿付/公司行动结果，决定是否具备 Token 处置依据 |
| 锁仓业务记录 | 资产与发行 → 锁仓记录 | 显示摘要和链上执行引用，不重复创建锁仓记录 |

**关键区别：**
- Token 方案已批准 ≠ 合约已部署。
- 合约已部署 ≠ Offering 已合法发布。
- 付款已到账 ≠ 已完成配售/登记/Mint。
- Mint 已最终确认 ≠ 法定持有人登记已经生效。
- Token Burn ≠ 本金/收益已经支付 ≠ 法律权利已经终止。
- 链上余额 ≠ 法定持有人名册。

## 二、全局产品规则

### 2.1 Token 网络与支付网络分离

- 投资者支付范围仍为 OP Mainnet 上的 USDT；该支付范围**不代表 Token 必须部署在 OP Mainnet**。
- Token 网络仅从平台已经批准、对当前 Instrument/法域和生产环境开放的网络清单中选择。
- 不允许企业输入任意链名、任意 RPC、任意 Token 合约地址或任意标准。
- 当前 Instrument 没有适用且已获准的 Token 网络/标准时，页面显示「尚无可用的生产 Token 方案」，不得默认用 OP Mainnet 或其他链替代。
- V1 每份 Token 方案仅选择一个获准网络；复杂多链部署、跨链桥、跨链供应同步及复杂合约升级不纳入 V1。

### 2.2 Token 标准与合约模板

- 仅展示平台已完成必要产品、法律和安全准入的标准/模板。
- 标准名称、模板版本、可用能力和限制均为受控选项；不允许上传任意合约代码、ABI、Factory 或自定义脚本。
- 当前没有获准模板时，允许保存业务准备资料，但阻断部署申请。
- 不在本模块承诺某一具体 ERC 标准或某一合约实现已经获批。
- 合约模板所需的 Token 名称、符号等展示元数据，只有在已批准模板确实要求时才显示；默认从资产/权益结构派生，允许的修改范围由模板控制，部署后固定。
- 链上 decimals、最小单位和模板专属参数仅展示已批准来源的只读值；未核实的值不得让企业自行猜填。

### 2.3 权益映射与容量

- Token 总供应量、每 Token 对应的法律权益量、法律单位、当前 InstrumentVersion，全部从权益结构读取。
- 股权以股为法律单位；债权以本金 U 为法律单位；收益参与以已批准参与比例为法律单位。
- 1 Token 不必然等于 1 股、1 U 或 1% 权益；页面同时显示 Token 份数与法律权益量，不混用单位。
- 非 1:1 映射按已批准权益结构精确计算；无法精确拆分、超过允许精度或数据来源冲突时阻断 Ready/部署，不舍入、不截断。
- 已发行、可用、有效预留等容量只使用权威事实；无真实数据时不展示虚构的 0、已 Mint 或剩余数量。
- 多个 Offering 共用同一 Instrument 授权容量；Token 管理不自行重置或增加总供应量。

### 2.4 环境与套餐

- 业务资料准备、测试环境与真实生产环境明确分离。
- Free：可查看并完成 Token 方案的业务准备信息；仅内部只读预览；不能真实部署合约、Mint、Burn、改变生产限制或产生对外 Token 交付。
- Standard + KYB 通过：可以使用已开放的 Token 方案准备和查看能力；购买 Standard 不自动取得真实部署、Mint、Signer 或生产权限。
- Standard + 全部适用生产准入通过：仅在已批准的网络、标准、模板、法域和受权主体范围内，才显示相应真实申请入口。
- 降级 Free：历史真实 Token/链上事实只读保留；不得删除合约、交易、持有人权益或在途任务。既有必要存续义务由受控责任方继续承接。
- 不向客户正式页面展示内部 Mock 控制台、模拟 Token、模拟持仓或测试按钮；内部测试数据不得转成真实链上事实。

### 2.5 高风险操作与职责分离

- 企业账号可在自身业务范围内准备方案、查看结果、提交受权申请。
- Tenant 管理员、Issuer 页面编辑者、SaaS 平台运营、客户支持人员不因账号身份自动成为法定发行人、合约管理员、Signer 或密钥托管人。
- 部署、Mint、Burn、冻结/解除、暂停/恢复、管理员权限变更均须由实际合法有权主体按已批准授权执行。
- 若适用规则要求独立审批而当前没有真实批准主体/授权证据，状态保持「待有权主体确认」，不得以当前单账号自行点击代替。
- SaaS 页面不收集、显示或保存生产私钥、助记词、Signer 密码或可直接执行签名的秘密凭证。
- 外部执行方的接受请求、回调成功或返回 TxHash 不等于链上最终确认。

### 2.6 全局列表、展示与交互

| 项目 | 规则 |
|---|---|
| 企业范围 | 仅当前 Tenant 的 Asset、Instrument、Offering、配售/登记与链上记录 |
| 默认排序 | 待处理、Unknown、差异优先；其后按最近事件倒序 |
| 分页 | 20 条/页；返回详情保留筛选和分页上下文 |
| 搜索 | Asset/Instrument/Offering 名称、方案编号、操作编号、交易哈希、合约地址（仅完整授权搜索） |
| 数量单位 | Token 份数与法律权益单位分列；不将金额、股数、百分比混成 Token 数量 |
| 地址 | 默认缩略显示；完整地址仅在有权详情中查看/复制，并同时标明网络 |
| 时间 | 分列外部事件时间、平台接收时间、最后核对时间 |
| Unknown | 明确显示「状态未知/待核实」，不标绿、不视为成功或失败 |
| 审计 | 关键操作、授权、参数版本和链上事件不可删除；纠正通过新事件/新证据追加 |
| 主操作 | 每个页面只突出当前唯一安全下一步；不提供绕过前置条件的快捷按钮 |
| 移动端 | 表格转卡片，保留对象、Token数量、网络、核心状态和主操作 |

## 三、视图一：合约管理

### 3.1 Token 方案列表

**页面目标：** 让企业看到每项权益结构对应的 Token 方案准备状态、已部署合约及当前可执行能力。

顶部摘要（仅在有真实权威数据时显示）：
- Token 方案总数；
- 待补充/待核验方案数；
- 待有权审批的部署申请数；
- 已部署且最终确认的合约数；
- 部署 Unknown/失败/暂停的合约数。

列表筛选：
- Asset；
- Instrument 权益类型；
- 方案状态；
- 网络；
- 环境（内部准备/测试/生产）；
- 部署状态。

列表字段：

| 字段 | 展示规则 |
|---|---|
| 资产/权益结构 | Asset 名称、权益类型、InstrumentVersion |
| 关联发行方案 | 只显示引用该 InstrumentVersion 的 Offering 名称/期次；不重复创建 Offering |
| Token 方案版本 | 当前版本号、最近更新时间 |
| Token 标准/模板 | 仅显示已批准的标准和模板版本；未获准显示待确认 |
| Token 网络 | 已选获准网络；未选显示待配置 |
| Token 总份数 | 从权益结构读取；不得在本页编辑 |
| 每 Token 对应权益 | 从权益结构读取，显示法律单位 |
| 合约状态 | 未配置、草稿、待核验、待审批、部署中、待最终确认、已部署、Unknown、失败、暂停、已弃用 |
| 合约地址 | 只有真实部署且达到对应核验状态后显示；否则不生成占位地址 |
| 最近更新 | 方案变更/部署/核对的最近权威时间 |
| 操作 | 查看详情；符合条件时继续完善/提交部署申请 |

空状态：
- 当前没有权益结构：提示「请先在资产与发行中完成权益结构」。
- 权益结构未 Ready：提示「权益结构尚未完成，Token 方案暂不能提交核验」。
- 尚无获准网络/标准/模板：提示「当前尚无适用于该权益结构的生产 Token 方案；请等待平台完成相应准入」，不得提供任意链/标准输入。
- 有方案但未部署：显示方案状态和下一步，不显示「Token 数量 0」等虚构运营数据。

### 3.2 Token 方案创建/编辑（单页）

入口：Token 管理 → 合约管理 → 新建 Token 方案；或从资产详情的权益结构/发行准备跳转。

页面采用单页 A/B/C 三个分区，不做多步骤向导。

**顶部固定信息**
- Asset 名称/编号；
- 当前 InstrumentVersion；
- 权益类型；
- Token 方案版本；
- 资料状态；
- 保存状态；
- 待补充事项数量；
- 唯一下一步操作。

**A. 权益与 Token 映射（全部只读继承）**

| 字段 | 来源/规则 |
|---|---|
| 资产 | 当前 Asset，只读 |
| 权益结构名称/版本 | 当前 Ready InstrumentVersion，只读 |
| 权益类型 | 股权/债权/收益参与，只读 |
| 法律权利责任主体 | Instrument 已确认主体，只读摘要 |
| 法律权益总规模 | Instrument 总规模和单位，只读 |
| Token 总份数 | Instrument 计划拆分总份数，只读 |
| 每 Token 对应法律权益量 | Instrument 精确计算结果，只读 |
| 权益映射精度状态 | 精确/超精度/无法核验；非精确或 Unknown 阻断提交 |
| 关联 Offering | 显示引用当前 InstrumentVersion 的发行方案；不允许在此创建或修改发行条款 |

**B. 网络、标准与模板（受控选择）**

| 字段 | 控件/规则 |
|---|---|
| Token 网络 | 下拉选择当前 Instrument/法域已获准且平台已开放的网络；无选项时禁用并说明原因 |
| Token 标准 | 下拉选择该网络上已获准的标准；不提供自由输入 |
| 合约模板 | 从对应标准的获批模板中选择；显示模板名称、版本、适用能力和限制 |
| 环境 | 内部准备/测试/生产；生产环境只有真实生产准入通过后才可选 |
| Token 展示名称 | 仅当模板要求时展示；默认继承权益结构名称；模板不允许修改时只读 |
| Token 符号 | 仅当模板要求时展示；默认建议值来自系统；需通过模板的格式和唯一性校验 |
| 链上精度/Decimals | 只读显示获批模板/网络参数；没有已确认来源时标记待核验并阻断部署 |
| 合约能力摘要 | 只读：Mint、必要转让限制、冻结/暂停、Burn（如适用）及当前模板不支持的能力 |
| 法律转让限制引用 | 继承 Instrument 已确认限制条款和适用规则；不得在本页放宽法律限制 |
| 方案说明 | 选填，多行文本，最多 1,000 字；记录选择原因，不代替法律/安全批准 |

**C. 部署准备与证据**

| 字段 | 控件/规则 |
|---|---|
| 适用法律/法域确认 | 只读状态及证据引用；未确认阻断部署 |
| 发行主体/授权状态 | 只读已核验主体和授权范围；不得用 Tenant Admin 身份代替 |
| 合约模板安全审查 | 只读已批准模板/版本/审查状态；未通过阻断部署 |
| Signer/执行主体 | 只读显示真实受权执行主体名称/状态；不显示密钥材料 |
| 外部链服务 | 只读显示已准入服务及健康状态；不允许在本页配置 RPC/API 密钥 |

| 部署前检查 | 系统汇总通过/待补/阻断项及责任方 |
| 方案版本备注 | 版本变更原因，修改已提交/已批准方案时必填 |

页面底部：
- 保存草稿；
- 完成资料检查；
- 提交方案核验（仅在必要资料齐全时）；
- 提交部署申请（仅在所有生产门、审批与执行主体齐备时出现）。

**校验规则**
- 必须有有效 Asset 和 Ready InstrumentVersion。
- Token 总份数及每 Token 权益量必须从 InstrumentVersion 精确继承；不得重新输入或覆盖。
- 只允许一个当前有效 Token 方案版本；新版本不能清除旧方案/已部署合约事实。
- 同一 InstrumentVersion 下多个 Offering 引用同一有效方案，不得各自创建新的 Token 供应量。
- 选定网络/标准/模板不在当前已批准清单时，不能保存为可部署方案。
- 生产网络/模板未通过准入时，可以保留业务准备草稿，但不能提交部署。
- 方案部署后，其网络、标准、模板、法律映射、关键参数和部署证据固定；不得直接编辑覆盖。
- 不提供原始合约代码、ABI、任意 Constructor 参数、任意管理员地址、任意初始供应量、代理升级或多链配置。

### 4.3 Mint 申请与交付表单

- 获配 Token 数量不超过配售、Instrument 总容量和当前未交付余额；
- 没有重复 Mint、同一分配的有效在途 Intent 或相关 Unknown；

**数量规则**
- 一项 Mint 申请绑定一个唯一配售决定；V1 不开放任意批量导入或无来源批量 Mint。
- Token 数量从唯一配售决定和 Instrument 映射自动计算；Issuer 不能在表单中手动增加、减少或覆盖。
- V1 默认按该配售决定应交付的完整数量申请；部分交付只有在适用 Instrument/法律安排和正式授权明确允许时才进入受控例外，不作为普通表单选项。
- 申请提交后生成唯一 Mint Intent；重复点击或重复回调不得创建第二笔有效 Mint。

**提交后状态**
待有权批准 → 已批准待执行 → 已提交链上 → 确认中 → 已最终确认 / 失败 / Unknown / 需对账。实际执行方和链上结果独立展示。

分区展示：
- 订单、配售、法定登记与资金来源；
- InstrumentVersion、权益映射和获配数量；
- 投资者合法接收钱包及核验状态；
- Token 方案/合约/网络；
- 申请主体、授权主体、Signer/执行主体；
- 唯一 Mint Intent、外部执行引用、TxHash、区块/最终性证据；
- 链上实际 Mint 数量、接收地址、执行时间；
- 与应交付数量的差额；
- 事件历史、重试/Unknown 查询、异常和审计记录。

禁止操作：
- 手工将 Mint 状态改成成功；
- 修改已批准配售数量；
- 更换接收钱包而不重新核验/授权；
- 对 Unknown 直接创建第二笔 Mint；
- 以 Mint 成功覆盖法定登记 Unknown 或资金差异。

### 4.5 限制与暂停

该分区处理**法律/管理限制和合约级安全控制**，不取代 Offering 的锁仓安排，也不取代「资产与发行 → 锁仓记录」。

**列表类别**
- 持有人/钱包级限制；
- 限制解除申请；
- 合约级暂停/恢复；
- 权限撤销/恢复（仅限获批模板支持且有真实授权时）。

列表列：事项编号、Asset/Instrument、持有人脱敏引用、钱包缩略地址、限制类型、依据、申请时间、有效状态、真实链上状态、执行主体、最近更新时间。

**限制申请表单**

| 字段 | 控件/规则 |
|---|---|
| 关联对象 | 从有效持有人/合法钱包/异常事项选择；不允许自由创建陌生对象 |
| 限制类型 | 适用法律/管理限制、受权冻结、合约级转让限制；仅显示当前模板支持项 |
| 依据类别 | 法律/监管决定、法院/有权机关文件、合同条款、公司有权决议、已批准合规/安全事件等受控类别 |
| 依据文件/引用 | 必填；固定文件版本或有权决定引用 |
| 影响范围 | 由法律/决定及合约能力带入；显示钱包、持有人、Token 数量/全部范围；不允许扩大范围 |
| 生效时间 | 有权依据规定的时间；不以点击时间冒充实际生效时间 |
| 解除条件/到期 | 依据文件所载条件；没有明确解除条件时显示「待有权主体确认」 |
| 申请说明 | 必填，10～500 字 |
| 受权批准 | 真实批准主体、授权范围和证据；不以当前 Tenant Admin 自批代替 |
| 风险确认 | 确认提交申请不等于限制已生效，实际链上状态须另行核验 |

**限制与暂停规则**
- 法律/管理冻结、合约暂停、Offering 锁仓是三种不同事实，页面必须分别标识。
- 冻结/解冻不等于锁仓/解锁；冻结解除不能自动解除 Offering 锁仓，锁仓到期也不能自动解除法律限制。
- 持有人级限制只能按有权依据和已批准合约能力执行；不提供企业任意冻结任意钱包的功能。
- 合约级暂停/恢复属于全局高风险操作，必须显示影响的合约、所有相关 Offering/持有人及在途 Mint/交付；没有真实紧急授权主体时不得执行。
- 暂停申请已提交不代表合约已暂停；恢复申请已提交不代表限制已解除。
- V1 不提供批量强制转账、任意地址拉黑/解禁、任意管理员权限授予或无依据的全局冻结。
- 与基础锁仓有关的业务计划、投资者可见锁仓期限和锁仓记录，统一跳转「资产与发行 → 锁仓记录」；本模块只显示对应的链上执行/限制事实。

### 4.6 销毁与授权调整

该能力只在 Instrument/法域/合同生命周期明确需要时开放；不把 Burn 作为每个 Offering 的默认步骤。

**适用场景**
- 债权型 Instrument：依法到期清偿或其他合法债务处置确实要求销毁对应 Token 时。
- 股权型 Instrument：存在真实有效的股份回购、注销或其他合法公司行动，并明确需要对应 Token 处置时。
- 收益参与型 Instrument：只有合同/法律安排确实产生可终止/调整的 Token 权利且有权依据时。
- 其他合法更正：必须有权威登记更正和合约支持，不允许以普通运营需求调整 Token 数量。

**前置守卫**
- 有真实有效的 M13 到期/退出/公司行动或其他合法处置依据；
- 需要的真实付款/清偿事实已由资金与结算/有权资金主体核实；若法律时序允许先调整后付款，必须引用明确法律/合同依据和受权批准，不默认；
- 有权登记主体已确认对应法律权益调整/注销结果，或明确了适用的合法先后时序；
- 目标 Token/持有人/钱包和数量可与权威依据唯一对应；
- 合约模板支持该项操作；
- 实际受权批准和 Signer/生产准入有效；
- 不存在重复 Burn/调整 Intent 或 Unknown 未解决事项。

**申请字段**

| 字段 | 控件/规则 |
|---|---|
| 来源事项 | 从已确认的到期/退出/公司行动/登记更正选择；必填 |
| 法律依据/InstrumentVersion | 自动引用，只读 |
| 受影响持有人 | 权威持有人引用和脱敏名称，只读 |
| 目标钱包/合约 | 自动引用已核验目标，只读 |
| 应调整法律权益量 | 来源权威结果，只读 |
| 对应 Token 数量 | 按 Instrument 映射计算，只读 |
| 操作类型 | Burn / 合法授权调整；仅显示模板支持且有依据的选项 |
| 已完成实付/清偿状态 | 只读引用资金与分配权威结果 |
| 法定登记调整状态 | 只读引用有权登记结果 |
| 依据文件/审批 | 必填 |
| 申请说明 | 必填，10～500 字 |
| 风险确认 | 明确「Token 销毁不代表资金已经支付，也不自动证明法律义务终止。」 |

提交后生成唯一操作 Intent；实际链上数量、交易最终性、登记调整和资金清偿分别显示。Burn 失败/Unknown 时不得重新生成操作，先核验原 Intent 和链事实。

### 4.7 Token 操作总状态

页面状态文案按业务阶段展示，不把候选文案冻结为工程枚举：

- 草稿；
- 已提交待核；
- 待补充材料；
- 待有权主体批准；
- 已批准待执行；
- 执行已提交；
- 链上确认中；
- 已最终确认；
- 执行失败；
- 状态未知/待核实；
- 部分完成（仅当真实业务和模板支持）；
- 争议/待调查；
- 已撤销（仅在真实执行尚未发生且有权允许时）。

**Unknown 安全规则：**
- 查询原始 Intent、TxHash、nonce/外部引用和链上事件；
- 保留原操作的数量占用和业务关联；
- 不创建重复 Mint/Burn/冻结/暂停；
- 只有确认原操作未发生且有权主体批准后，才可建立后续新操作，并保留关联关系。

## 五、视图三：链上记录与对账

### 5.1 链上事件列表

筛选：
- Asset / Instrument / Offering；
- Token 合约；
- 网络；
- 事件类型：部署、Mint、Transfer（只读观察）、限制/解除、暂停/恢复、Burn、管理员权限变更；
- 执行状态：提交、确认中、最终确认、失败、Unknown、重组/待复核；
- 时间范围；
- 持有人脱敏引用/钱包缩略地址；
- TxHash。

列表列：

| 字段 | 规则 |
|---|---|
| 事件编号 | 平台唯一事件引用 |
| 事件类型 | 部署/Mint/Transfer/限制/暂停/Burn/权限变更 |
| Asset / Instrument | 固定业务上下文 |
| Token 合约 | 网络 + 缩略合约地址 |
| 关联 Offering/订单/配售 | 有真实关联时显示；无关联不编造 |
| 涉及钱包/持有人 | 脱敏显示 |
| Token 数量 | 有事件数据时显示；部署/权限事件可为空 |
| 交易哈希 | 真实来源存在时显示 |
| 链上状态 | 观察中/确认中/最终确认/失败/Unknown/重组待核 |
| 事件时间 | 外部链上时间 |
| 接收时间 | 平台接收时间 |
| 最近核验 | 最近一次成功查询时间 |
| 操作 | 查看事件详情/查看关联业务 |

重复回调和同一链上事件必须幂等去重；不同交易哈希的真实事件不得误合并。

### 5.2 链上事件详情

固定展示：
- 事件编号、事件类型、网络；
- Token 合约地址和方案/模板版本；
- 交易哈希、区块高度/区块引用、链上事件唯一标识（有权威来源时）；
- 发送方/接收方地址（默认缩略，完整地址按权限）；
- Token 数量及单位；
- 外部发生时间、平台接收时间、最后查询时间；
- 外部数据源/节点服务状态；
- 交易确认/最终性状态及来源；
- 对应的部署/Mint/Burn/限制 Intent；
- 关联配售、持有人登记、资金或收益事项；
- 原始事件证据引用、重组/回滚/冲突说明；
- 历史查询、人工调查、处理决定和审计记录。

不允许在详情中编辑链上交易哈希、实际数量、发送方/接收方或最终性状态。

### 5.3 Token 与配售/法定登记对账

**对账目标：** 比较链上真实 Token 事实与唯一配售决定、合法持有人登记的对应关系，不创建新的持有人名册。

顶部统计（只统计当前筛选和同一有效数据快照）：
- 对账一致项；
- 待交付项；
- Token 数量差异项；
- 持有人/钱包映射差异项；
- Unknown/数据源不可达项；
- 不可比较项。

筛选：
- Asset / InstrumentVersion / Offering；
- 对账状态；
- 法定登记状态；
- Mint 状态；
- 网络/Token 合约；
- 最近核对时间；
- 持有人脱敏引用/配售编号。

列表列：

| 字段 | 展示规则 |
|---|---|
| 持有人引用 | 以法定登记主体/唯一映射引用为主；脱敏显示 |
| 配售决定/订单 | 唯一有效关联引用 |
| 法律权益数量 | 权威登记数量及法律单位 |
| 按映射应有 Token 数 | 根据固定 InstrumentVersion 和配售/登记事实计算 |
| 已确认 Mint 数 | 仅统计达到最终确认的真实链上 Mint |
| 当前链上持有数 | 来自最新权威链上查询；标注 As-of 时间 |
| 限制/锁定状态 | 法律限制、业务锁仓和链上执行状态分别展示 |
| 对账状态 | 一致/待交付/差异/Unknown/不可比较 |
| 差异金额/数量 | Token 份数和法律权益单位分列 |
| 最近核对 | 时间、来源和快照版本 |
| 操作 | 查看差异/查看链上事件/查看法定登记 |

**对账成立条件**
- 同一 Tenant、Asset、InstrumentVersion、Offering/适用权益范围；
- 同一合法持有人主体和经核验的 Token 接收钱包映射；
- 同一适用时点或明确可比较的有效快照；
- 法律权益数量与 Token 数量通过固定 Instrument 映射精确换算；
- 链上事件达到适用最终性；
- 无未解决的重复 Mint、Transfer、Burn、限制或登记更正事件。

任一条件不满足时，显示「待核」「差异」或「不可比较」，不得显示绿色「一致」。

### 5.4 差异类型与处理

| 差异 | 页面提示 | 下一步 |
|---|---|---|
| 已配售/登记，Token 尚未交付 | 「法律权益已确认，Token 交付待完成。」 | 查看交付任务；符合守卫时申请 Mint |
| Token 已 Mint，登记待核 | 「Token 已交付，法定登记仍待有权主体确认。」 | 查看登记事项；不得把 Token 视为法律登记 |
| Mint 数量少于应交付 | 显示应有/已确认/差额 | 查询原 Mint Intent，必要时提交受权复核 |
| Mint 数量超过获配数量 | 标记重大差异并暂停相关后续操作 | 升级受权调查；不自动 Burn 回滚 |
| Token 接收钱包与合法持有人不匹配 | 显示两侧引用及核验状态 | 提交身份/钱包映射复核 |
| 发现未预期 Transfer | 显示链上来源、双方地址及法律映射状态 | 检查合约限制和合法转让/登记证据 |
| 资金状态 Unknown | 显示资金待核 | 跳转资金与结算；不继续 Mint |
| 链上事件 Unknown/数据源不可达 | 显示最后已知状态和时间 | 查询原事件/服务状态 |
| 链重组/最终性撤回 | 原事件标记待复核，保留历史 | 查询权威链事实并受权处理 |
| 登记数量与 Instrument 映射不精确 | 显示「不可比较/映射异常」 | 返回权益结构核验，不静默舍入 |
| 限制状态与链上执行不一致 | 分列法律依据、申请状态和真实链状态 | 提交受权限制复核 |
| Burn 已完成但资金/法律义务未确认 | 明确显示 Token 已销毁、清偿/权利终止待核 | 跳转收益与分配/资金/法定登记，不标记清偿完成 |

### 5.5 差异详情与可用操作

详情分区：
1. **业务来源**：Asset、InstrumentVersion、Offering、订单、唯一配售决定和法定登记引用。
2. **法律权益侧**：合法持有人、法律单位、权威数量、生效时间、登记责任主体及证据。
3. **Token 链上侧**：Token 方案、合约、网络、接收钱包、已确认 Mint/Transfer/Burn、当前链上余额和限制状态。
4. **精确映射**：每 Token 对应权益量、换算结果、比较时点、精度和计算来源。
5. **差异与处理**：差异类别、数量、首次发现、责任方、当前任务、处理依据、历史结果。
6. **审计时间线**：原始事实、每次查询、外部回执、复核请求、受权决定和后续链上事件。

允许操作：
- 重新查询原链上事件；
- 查看对应配售/登记/资金/收益记录；
- 提交差异复核；
- 在符合前置条件时跳转对应受权操作申请。

禁止操作：
- 手工修改 Token 余额/法律权益数量；
- 手工改写交易哈希或事件状态；
- 手工把差异标记为已解决；
- 为解决差异直接 Mint/Burn/转账；
- 在 Token 模块直接创建/修改法定持有人登记。

## 六、跨模块闭环

### 6.1 Token 方案与部署

资产 Ready + InstrumentVersion Ready  
→ Token 管理创建/完善 Token 方案  
→ 选择已获准网络/标准/模板  
→ 继承权益总量、Token 份数和每 Token 权益映射  
→ 法律/安全/发行授权检查  
→ 真实有权主体批准  
→ 受权 Signer 执行部署  
→ 查询原部署 Intent/链上事件  
→ 达到适用最终性后标记合约可用。

### 6.2 认购与 Mint 交付

Offering 有效  
→ 投资者通过统一 KYC 和适用资格核验  
→ 认购订单成立  
→ 资金与结算核实真实到账  
→ 配售与持有人确认唯一配售决定及适用登记条件  
→ Token 管理按该决定生成唯一 Mint 申请  
→ 受权主体批准/Signer 执行  
→ 链上最终性确认  
→ Token 与法定登记对账  
→ 差异解决后展示相应交付完成状态。

实际法律登记与 Mint 的先后顺序由具体 Instrument/法域决定；UI 以独立状态显示，不强制统一顺序。

### 6.3 限制、冻结与锁仓

- 业务锁仓计划及投资者可见期限：资产与发行 → 锁仓记录。
- 法律/管理冻结、合约转让限制：Token 管理的受权限制流程。
- 实际链上限制是否生效：链上记录与对账的真实事件。
- 三者可并存，互不自动覆盖；解冻不等于解锁，锁仓到期不等于法律冻结解除。

### 6.4 到期、清退与 Burn

收益与分配形成适用到期/退出/公司行动事实  
→ 资金与结算核实真实付款/清偿（如适用）  
→ 配售与持有人/有权登记主体确认权益变更或注销（如适用）  
→ Token 管理根据合法依据申请 Burn/授权调整  
→ 有权主体执行并核验链上最终性  
→ 分别更新资金、法律登记和 Token 事实。

Burn 不自动触发资金支付、法律权利注销或企业义务完成。

## 七、Free / Standard、权限与隐私

| 企业状态 | Token 方案 | 真实合约部署 | Mint/限制/Burn | 链上历史 |
|---|---|---|---|---|
| KYB 未通过/审核中/补件 | 按统一准入门禁拦截；可查看导航和说明 | 禁止 | 禁止 | 不展示无权详情 |
| 新开通 Free + KYB 通过 | 可查看/完善业务准备信息和草稿 | 禁止 | 禁止 | 无真实客户 Token 运营数据 |
| Standard + KYB 通过但生产准入未通过 | 可准备方案、查看待准入原因 | 禁止 | 禁止 | 有合法历史时只读 |
| Standard + 生产准入通过 | 仅限已批准网络/标准/模板 | 由实际有权主体执行 | 由实际有权主体执行 | 按授权范围查询 |
| Standard 宽限期 | 不开放新增真实发行 | 禁止新增真实部署 | 允许受控承接既有必要存续义务；须有权授权 | 保留 |
| 降级 Free | 历史方案只读 | 禁止新增 | 不得删除/自动撤销既有法律义务；仅依法受权的必要存续处理可承接 | 历史真实链事实只读保留 |

**权限和隐私**
- 企业只能查看当前 Tenant 的资产、Instrument、Offering、持有人和 Token 记录。
- 投资者默认使用企业内脱敏引用；不展示原始 KYC/证件/AML/制裁报告。
- 钱包和合约地址默认缩略；完整地址仅在有权详情查看/复制。
- 不显示私钥、助记词、Signer 凭证、API Secret 或不必要的外部账户敏感信息。
- 跨租户直达必须拒绝且不泄漏记录是否存在。
- 真实链上事件、授权决定、合约版本和操作历史不可删除；更正只能追加证据/新版本。

## 十、V1 不扩张与交付结论

- 本次仅覆盖现有 Token 管理 V1 范围：Token 方案、批准网络/标准/模板选择、合约版本与部署申请、受权部署结果、接收钱包引用、Mint/交付、链上最终性/Unknown、与配售/法定登记对账、必要合约级转让限制、高风险操作权限/暂停，以及 Instrument 依法需要时的 Burn/授权调整。
- 不新增正式功能 ID，不改变既有功能编号、优先级或首次交付版本归属；复杂多链部署/跨链、复杂合约升级、代理管理、二级市场交易/撮合、自由用户间转让、批量强制转账、通用智能合约部署平台均不纳入 V1。
- 不指定未经批准的具体 Token 标准、链、合约模板、法律主体、Signer、密钥托管、Provider、链最终性阈值、API/Schema 或安全审计方案。
