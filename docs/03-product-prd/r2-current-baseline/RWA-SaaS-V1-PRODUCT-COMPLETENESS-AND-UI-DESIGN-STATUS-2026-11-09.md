# RWA SaaS V1 产品完整性收口与产品/UI 设计现状审计

> 日期：2026-11-09  
> 状态：**V1 产品范围已核对；官网、U01 企业入驻及 Issuer 资产/发行、投资者与认购、资金与结算、Token 管理、锁仓记录、收益与分配均已完成对应 UI-Ready 收口；数据与共享能力、投资者门户及其他产品端仍待设计**  
> 用途：作为当前 V1 产品完整性与后续产品/UI 工作的现状审计，不是新增产品 DEC，不代表整体产品设计完成或 UI 已完成。  
> 维护分支：docs/r2-current-product-baseline｜PR #8 Draft / Open / Unmerged

## 1. 审计结论

本轮以当前有效 V1 产品基线、DEC-057/058/059、U01/U02 专项批准文档、官网历史详细 PRD 和官网现有 UI 实施记录为依据。目标是核对产品范围与设计状态，不进行技术开发审计。

### 1.1 V1 范围已收口的事实

- V1 五端范围已批准：官网、Issuer 企业工作台、Issuer 独立投资者门户、平台统一投资端、平台运营后台；外部责任主体作为业务协作边界。
- V1 正式功能为 **157 项**：原 V1 146 项，加统一投资渠道与统一投资者身份相关的 11 项。
- 全版本追踪为 **204 项**：V1 157、V2 22、V3 20、TBD 5。
- 原有 22 个 Frozen 业务模块保持不变，另追加两个逻辑模块，模块目录合计 24 个；其中当前有 V1 正式功能的模块为 21 个。受控转让、白标、Open API/SDK 等仍按原版本规划后置。
- 五端页面组 IA 为 125 组：官网 14、Issuer 工作台 63、平台统一投资端 16、Issuer 投资者门户 15、平台运营后台 17。页面组进入 V1 范围不代表已完成模块规划、字段设计或 UI。
- Issuer 九个一级导航保持现行批准版本；「企业管理」名称、位置和入口不变。
- 「资产与发行」保留三个二级入口：资产管理、认购记录、锁仓记录；资产详情保留四个 TAB：资产概览、资产资料、权益结构、发行管理。
- Project 是内部业务对象，不单独提供项目管理菜单；发行准备属于 Offering 流程，不独立成菜单或资产详情 TAB。

### 1.2 最新决策已纳入 V1 基线

- DEC-057：统一投资端及对应的渠道、统一投资者身份能力纳入 V1。
- DEC-058：USDable 功能参考后的采纳、V2 后置及不采纳事项已确认；收益上报、清退/兑付、持有人管理、资产相关方等归入既有模块。
- DEC-059：**预期年化信息披露与债权周期付息能力纳入 V1**。本次批准的是功能范围，不是具体适用类型、字段、频率、计息方法和日期算法；这些细节仍待模块产品设计确认。
- U01：邮箱验证码登录、单账号单企业、KYB 五步 v0.3、KYB 通过后激活 Free、企业 MPC 钱包、Free/Standard E09 权益矩阵为现行规则。
- U02：资产集中入口、三项二级导航、四个资产 TAB、房地产首批四模板、单资产一套 Instrument、三类权益、Offering 单页及发行准备边界为现行规则。

**本轮已核对 157 项 V1 功能数量、模块归属和最新 DEC 补充；尚未完成 157 项正式功能与 125 个页面组的逐项双向映射（每项功能对应页面入口、每个页面对应正式功能责任）。该项属于下一阶段整体 SaaS 架构审计，不得把页面组数量或功能清单存在视为映射已完成。**

以上不新增正式功能 ID，不修改 DEC-017 原 193 项主表、原 M01～M22 Frozen 正文和历史版本归属。

### 2.3 官网审计判断

**官网页面结构和基础 UI 已有成果，但官网内容与用户流程尚未完成 V1 一致性收口。**

需要做的是在现有页面上修订内容、CTA 和跳转逻辑，不是重新设计首页或增加大量营销页面。建议优先完成：

1. 首页、产品功能、解决方案：修订 Free/Standard、Project/Offering 和统一投资端说明。
2. 订阅页面与升级说明：统一 E09 权益矩阵、月/年及 USDT/法币口径。
3. FAQ 与联系我们：更新旧 Sandbox、多企业、KYB 和支付网络描述。
4. 登录、企业创建和认证入口：统一为现行 U01 流程，取消多企业选择的正常路径。
5. 统一投资端介绍页：保留筹备状态，明确其属于 V1 产品端，但不暗示真实 Offering 已开放。

官网正式法律正文、真实邮件/支付等服务是否接通不属于本轮产品/UI 完整性判断。

## 3. 官网到 SaaS：登录、企业创建、KYB、钱包与订阅审计

### 3.1 现行完整流程

1. 访客从官网点击「企业登录」或「免费开始」，进入统一邮箱验证码入口。
2. 输入邮箱并完成一次性验证码验证；首次使用该邮箱时自动建立账号，不另设传统注册/密码流程。
3. 一个账号对应一个企业。尚无企业时，用户明确选择「创建并认证企业」。
4. 企业创建直接进入五步 KYB：企业基本信息、企业业务信息、企业关联人员、企业证明材料、预览与确认提交。
5. 支持草稿、提交、审核中、待补件、补件重提、审核通过/未通过及版本记录。KYB 未通过时可浏览工作台导航，但业务内容由统一认证状态拦截。
6. KYB 通过后激活 Free，自动开通企业 MPC 钱包；用户还可绑定多个自有钱包、验证控制权、切换默认钱包。
7. Free 与 Standard 均可创建、编辑和保存正式资产、权益结构、发行方案。Free 仅内部只读预览，不发布真实发行或投资者门户，不开放认购、持仓、收益运营。
8. 企业在原工作台订阅 Standard，选择月付/年付及 USDT/法币；价格待配置。支付确认后激活 Standard。
9. Standard 只有在相应业务、法律和生产条件满足后，才可执行真实发行和发行后运营；订阅本身不自动批准具体 Offering。

### 3.2 审计结论

- U01 的核心产品规则、页面分组和主要字段已形成较完整专项 PRD，不需要重新规划账号、KYB、钱包和套餐体系。
- 当前最大问题在于官网旧页面说明与 U01 最新规则不一致，而不是 U01 业务对象需要推翻重做。
- 官网旧注册/邮箱验证/企业开通/企业选择/升级说明必须统一按上面流程表达。
- KYB 表单以已批准的 v0.3 五步字段为唯一现行版本；更早的 KYB 字段组织和旧 Free Sandbox 说明不再作为现行设计。
- 企业钱包自动开通、多个自有钱包、默认钱包及 Offering 选择收款钱包属于已批准的产品能力，官网只需正确说明，不另造新钱包流程。
- 订阅价格、具体税费/开票和商业条款未确定时只显示待公布，不虚构金额或配额。

**已完成的产品决策与页面结构：**

- 已有全平台基础字段、房地产公共字段、六类房地产子类字段、文件清单、草稿/Ready、资料检查和资产详情四 TAB 设计。

- Asset 资料预览与 Offering 投资者端最终预览明确分开。

**仍需完成的产品/UI 细节：**

2. DEC-058 的资产相关方角色已按 DEC-070 收敛为结构化主体卡片，并整合进资产创建第③步和资产详情「资产资料」。
3. 相关方角色卡片、主体字段、同一主体多角色复用、条件许可资料、文件关联、Ready 校验、历史 Offering 快照及投资者披露位置已在 U02-07 形成完整 UI-Ready 规格。
4. 资产列表搜索/筛选、空状态、详情概览及唯一下一步主动作已在 U02-07 收口。

**判断：资产管理（资产列表、资产资料、资产相关方、房地产四个开放模板）与权益结构的产品/UI 规格均已分别达到 UI-Ready；这表示产品规格完整，不代表源码已实现或浏览器验收通过。Offering 仍需独立完成详细设计。**

### 4.2 权益结构 Instrument

**已完成的产品决策与 UI-Ready 细节：**

- 一项 Asset 最多一套当前有效 Instrument；股权、债权、收益参与权三类模板三选一。
- 保持单页面三区域：权益定义、权益规模与 Token 拆分、法律文件。
- 公共字段、三类权益条件字段及动态责任主体标签已收口；主体可引用 Asset 登记权利人/相关方，但不自动推断法律责任角色。
- 股权仅支持普通股；债权支持无息/固定利率、到期一次/周期付息和明确的计息规则；收益参与使用明确的来源、口径、期限和分配频率。
- 预期年化区间披露按 DEC-059 纳入 V1：股权/收益参与可选填，债权固定利率展示合同利率；不参与实际收益计算。
- 用户填写权益总规模和 Token 份数，系统计算每 Token 对应权益；股权为整数股，债权本金 U 和收益参与比例按明确的产品输入精度校验；无法精确拆分时阻断 Ready，不静默舍入。
- 核心权益文件、Asset 文件固定版本引用、Draft/Ready、类型切换、修订版本、历史 Offering 引用保护均已收口。
- 多期 Offering 继续共享同一 Instrument 授权容量；版本变化不得重置权益池。

**当前权威文件：** [DEC-071](../../../decisions/DEC-071-instrument-ui-ready-v1-approved.md)｜[U02-08](U02-08-INSTRUMENT-UI-READY-CLOSEOUT-2026-11-11.md)。

**判断：权益结构 V1 产品/UI 规格已达到 UI-Ready；法律效力、法定精度、链上 Token decimals、真实发行准入及代码/浏览器验收仍是独立事项。**

### 4.3 Offering 发行方案

**已完成的产品决策与 UI-Ready 页面：**

- 入口固定为资产详情「发行管理」TAB；不新增 Offering 二级菜单、Project 菜单或独立发行准备页面。
- 发行方案列表：搜索、状态筛选、默认排序、分页/移动端卡片、空状态和唯一行操作。
- Offering 创建/编辑：同一单页 A「发行信息」、B「认购规则」、C「发行准备」，不是三步向导。
- 继承 Asset、InstrumentVersion、每 Token 权利和真实可用容量；当前 Instrument 必须 Ready 才能创建 Draft。
- 本期数量、固定单价 U、最低认购金额、计划最高募集额计算、整数 Token 换算、认购时间和时区均有字段、控件与校验规则。
- V1 不提供 Issuer 投资者类型、地区、KYC 等级或额外资格配置；平台统一 KYC 通过为固定认购前置。
- 锁仓仅支持不锁仓/固定天数；支付范围固定 OP Mainnet · USDT。
- 企业最终结算收款钱包、认购协议、风险披露、Asset/Instrument 文件固定版本和 Offering 级资产相关方披露均已完成字段及异常设计。
- 业务资料完整性与真实生产准入分开；Free/Standard、KYB、宽限期和降级只读权限明确。
- 投资者端内部预览、缺项返回定位、发布前最终预览/明确确认和发布快照保护已完成。
- Offering 详情、草稿/等待开始/认购中/暂停/结束/关闭状态、暂停/恢复/关闭操作、在途义务保护和记录跳转已完成。
- 与认购记录、锁仓记录、资产管理、权益结构、企业钱包、文件管理和统一 KYC 的责任边界明确。

### 4.5 投资者管理

**已完成的产品/UI 设计：**

## 8. 2026-11-11 用户批准的投资者与 KYC 范围修订（DEC-069）

本节为 2026-11-09 审计后的增量修订；若与前文历史候选描述冲突，以 DEC-069 和当前产品总体架构基线为准。前文审计结论作为当时状态记录保留，不回写为历史已批准内容。

### 8.1 统一 KYC 与数据可见性

- 投资者在 V/M 投资者端完成平台统一 KYC；第三方 KYC 服务商负责实际核验，平台接收并维护权威结果。
- Issuer 企业 SaaS 只查看本企业范围内的脱敏投资者信息和 KYC 状态，不查看原始证件、完整身份号码、人脸/生物识别材料或完整第三方报告。
- Issuer 企业不承担人工 KYC 审核，不提供手动批准、拒绝、覆盖或绕过核验结果的操作。
- M/V 账户继续保持独立；KYC 结果仅在合法依据和授权范围内引用，不自动合并账户、钱包、订单历史或持仓。

### 8.2 V1/MVP 资格流程收敛

- KYC 通过是进入认购流程的强制前置条件；未开始、核验中、未通过、需重新核验或 Unknown 均不得进入认购确认/付款流程。
- V1/MVP 不提供 Issuer 可配置的 Offering 级投资者资格、投资者分级、资格例外或企业人工资格审核；复杂资格规则及其配置界面后置 V2。
- Offering 的开放状态、认购时间、可用额度、最低/最高认购数量、锁仓、必要签署及付款等普通交易条件继续保留。

### 8.3 导航与页面归属调整

Issuer「投资者与认购」二级导航由原候选五项收敛为三项：

1. **投资者管理**：投资者列表、脱敏档案、KYC 状态及本企业范围内认购/持有人记录。
2. **认购订单**：订单列表、详情、状态、基础取消和异常记录。
3. **配售与持有人**：配售记录/结果、持有人登记、持有人列表/详情及登记与 Token 对账。

页面映射：I-42 原 KYC 审核并入 I-41 投资者管理；I-43 不作为 V1/MVP 独立页面；I-44/I-45 归入认购订单；I-46/I-47/I-48 归入配售与持有人。历史页面 ID 保留追踪，不重新编号。

### 8.4 对整体产品设计进度的影响

- 九个 Issuer 一级导航不变；「资产与发行」三个二级入口及资产详情四 TAB 不变。
