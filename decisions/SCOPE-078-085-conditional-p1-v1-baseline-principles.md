## 一、8 项批准内容（16 个原 P1 功能）

| 决策 | 覆盖的原始功能 | 已批准原则 / 不可省略的最低控制 |
|---|---|---|
| **SCOPE-078** | M05-F011、M12-F010 | 持续购买是 Issuer V1 优先完整实现模式。集中募集和募集截止统一配售不默认首期全量交付；**如首发 Instrument/Offering 法律或合同条件要求**，V1 必须覆盖必要募集条件、集中配售、失败募集、余款与退款闭环。 |
| **SCOPE-079** | M10-F009、M12-F009 | 部分认购、部分配售、余款与额度回退依 Offering 条款裁决；完整复杂订单修改 UI 可后置，但真实少付/多付、合法退款和额度权威核算的最低处置能力不可省略。 |
| **SCOPE-080** | M07-F009、M13-F004～F006 | 赎回/Token 销毁、收益事件、收益额复核、还本与对外实际支付结果对账依首发 Instrument 权利义务裁决；触发时必须形成最小 V1 上线必需链路，保持持有人法律登记、链上 Token 与外部出款不同权威事实。 |
| **SCOPE-081** | M08-F009、M21-F005 | 按金融工具依法或合同规定提供投资者必要披露、收益文件、存续权益和最低可查询信息；高级收益分析、图形和复杂报表界面可后置。 |
| **SCOPE-082** | M11-F010 | 有真实稳定币收款的 V1 **必须具备最低资金差异人工调查、可核验证据、审批和处置路径**；“P1”只适用于完整专用财务调查后台和自动化的增强深度，不能删除资金异常控制。 |
| **SCOPE-083** | M18-F004、M18-F005 | 必要通知/送达及发送失败恢复按适用法域、合同与渠道判断；触发时以最小合法方式保留送达记录、失败告警/受控重试，不把站内消息默认认定为合法通知。 |
| **SCOPE-084** | M19-F006 | 平台强制规则优先于租户/项目/Offering 的**底层 Guard 必须一直生效**；P1 的是复杂规则层级配置与可视化界面，不是平台权限及安全约束可选择交付。 |
| **SCOPE-085** | M20-F007、M21-F006 | 必须保留依据法律/合同所要求的数据访问、受控导出、客户退出/移交与必要报告最低能力；复杂导出界面、高级查询及 BI 可以后置。 |

**覆盖核对**：2 + 2 + 4 + 2 + 1 + 2 + 1 + 2 = **16 项原 P1**，覆盖编号无重复。其余 **5 项 P1**（M03-F003、M03-F004、M04-F008、M06-F007、M17-F006）不属这次的 16 项，仍须独立审核，不能自动划为没有基础义务。

## 二、与第一版交付冻结的关系

- **SCOPE-062 的前置门依旧有效**：最终冻结真实 V1 必交功能清单之前，须选择 **1～2 类具体参考 Instrument**，验证权利/收益、法域要求、发行模式、偿付/赎回、法定登记与通知，再作逐功能裁决。
- 16 项的“触发时最低必需”是**已经批准的判断原则**，不表示 16 项全部获得 V1 自动化全功能交付授权。针对 M11-F010、M19-F006 等已明确不可省略底层控制的项目，不得用“未触发复杂 UI”理解为允许删去控制。
- 已确认的 SCOPE-071～077 外部执行与资金、登记、Token 的独立事实及 Unknown 恢复要求继续适用；ARCH-001 API-Ready 不赋予对外 API 危险执行权限。
- 原 187 项稳定 ID 与分级 **P0 125、P1 21、P2 21、V2 6、批次待定 14** 完全不变；若参考 Instrument 触发 V1 必交能力，应在新的**交付必要性列**标注，不擅自改写原 P1 历史审批。
- 本决策不确定具体收款/兑付主体、法定登记权威、电子送达法律效力、链与服务商或生产许可；不修改第 02/03/04 份 Frozen、功能树、DEC/ARCH 原文；PR #6 保持 **Draft / Open / Unmerged**。
