## 1. 来源与批准边界

本次承接，不重新批准既有业务功能：
- DEC-008：平台默认提供资金工作流编排与状态记录；认购、付款、实收、对账、配售、登记、退款独立；Unknown 不视为成功/失败；退款和人工纠正保留证据；不默认让 SaaS 成为资金收款人/托管方。
- DEC-023：M11-F001～F010、F012～F013 的 V1 资金生命周期功能已 Approved；M11-F011 法币及多通道支付保持 V3.0；M01 SaaS 订阅、M11 认购资金、M13 收益/本息资金严格分离。
- DEC-053：Issuer I-49～I-53 五页责任及 B07-01～06 六项产品方向已 Approved：Offering 合法收款安排、订单级付款指令、真实到账/最终性/匹配、异常与退款、募集款受限/可释放、受权划拨与真实核验。
- DEC-032/DEC-033：真实付款、配售、法定登记、Token、收益/退出各自保留权威事实；已合法登记持有人不得用普通订单取消/退款撤销。
- DEC-069：投资者 KYC 统一核验，Issuer 仅查看脱敏状态，不在企业端人工审批 KYC。
- DEC-075/DEC-076：订单唯一主账、配售与法定持有人登记各自唯一权威；M11 提供真实 FinalMatched 事实供后续使用。
- U01 Free/Standard：Free 仅准备/内部预览，不真实募集；Standard 需 KYB、订阅、Offering 状态及独立生产准入共同满足才开放真实业务。

本决策只将上述已批准方向细化为**完整企业端页面结构、字段、交互、状态文案、异常、权限、入口和验收目标**。不新增正式功能 ID、不变更 V1/V2/V3 归属，不把候选产品状态冻结为工程 enum。

## 2. 页面结构决定

不新增或改动九个一级导航和既有二级导航：

1. **收款与对账**：收款方案只读核对、订单级付款指令、真实到账记录、最终性和订单匹配。
2. **退款与异常**：退款申请/依据/受益人目标核验/有权批准/真实出款与受领对账；少付、多付、错链、迟到账、Unknown 等异常调查。
3. **募集款结算**：资金池真实来源、受限余额、释放资格、划拨申请、授权证据、真实执行与受领到账核验。

既有 I-49/I-50/I-51/I-52/I-53 五个页面责任归入以上三个二级入口；不建立第二套订单、资金、持有人、Token、收益或 SaaS 订阅主账。

## 3. UI-Ready 核心规则

### 3.1 V1 收款范围

- 投资者支付只开放 **USDT / OP Mainnet**，金额统一显示 U；法币/多通道 M11-F011 仍属 V3.0。
- Offering 必须绑定其已批准收款安排及企业已配置的有效收款钱包；如采用收款合约，投资者付款目标展示已核准合约地址，企业收款钱包与合约地址分开显示。
- 收款钱包管理归企业管理；本模块不创建/绑定/解绑钱包，不允许任意替换已发布 Offering 的收款目标。
- 付款指令固定订单、报价/Offering 版本、金额、网络、Token、目标和有效期；过期不等于未付款，Unknown 先查原指令。
- 同一链上事件/外部回调去重；不同真实付款分别保留；FinalMatched 仅表示真实认购款已匹配到订单，不代表配售、登记、Mint 或募集款可释放。

### 3.2 退款与异常

- 退款是独立真实出款，不是撤销原转账；申请、批准、执行、实际出款和受领到账分开。
- 退款必须关联原订单和真实收款事件，验证合法受益主体、退款依据和目标账户/钱包；原始付款发送地址不自动等于合法退款地址。
- 全额/部分退款受 Offering 和适用法律规则约束；累计退款不能超过权威可退款额度。Unknown 查询原 Intent，不得盲目重复退款。
- 已合法配售且法定持有人权益登记生效时，普通认购退款入口阻断；赎回/清退走收益与分配。
- 错链、假币、少付、多付、迟到账、未归属、重复回调、退款失败/退回、外部数据冲突均保留原始证据，走受权调查；不得手工改成成功或删除异常。

### 3.3 募集款受限、释放与划拨

- 概览分别显示 FinalMatched 实收、未匹配/待核、退款义务、争议/冻结、其他受限、已承诺未划拨、Eligible 候选金额、Approved、实际出款、受领到账。
- Eligible 只表示满足当前规则/证据的申请条件，不代表已批准、已出款或已到账。
- 不得使用钱包余额直接推算可释放金额；金额需由 M11 权威来源按同一 As-of 和有效规则计算，来源缺失/冲突显示 Blocked/Unknown。
- 划拨申请绑定资金池、金额、用途、合法接收主体/账户、资产网络、法律依据、授权证据及有效期。
- 批准绑定金额上限、用途、接收方、账户/网络和有效期；任何关键参数变化都不能沿用原批准，需重新核验/授权。
- 实际执行由依法有权的 Issuer/X 资金方或 Signer 完成；M11 记录唯一 Transfer Intent、实际出款和受领到账。Unknown 保留金额占用并查询原 Intent；部分出款/到账单独显示。
- 具体法律完成点按实际资金工具/法域确认，不以 TxHash、Webhook 或 Provider Accepted 单独认定 Settled。

### 3.4 单账号企业与有权审批

- MVP 一个账号对应一个企业，不新增财务/合规/审批多角色配置或内部双人审批系统。
- 企业管理员身份不自动获得法定收款、退款批准、托管或 Signer 权。
- 对依法要求独立批准的事项，产品记录真实有权公司机关/外部主体的批准结果、授权范围、金额上限、目的方、有效期及证据；没有合法授权证据即停留待核，不允许当前唯一账号自行点击替代。
- SaaS 平台不默认收取、保管、转移客户资金，不持有客户私钥，不代替真实资金方执行。

### 3.5 Free / Standard

- Free 可完成正式资产、权益和 Offering 资料准备，但不能生成真实投资者付款指令、真实认购资金/退款/募集款结算记录，也不生成虚拟客户资金。
- Standard + KYB 通过仅满足商业/企业准入；真实收款、退款或划拨还必须通过对应法律、资金主体、钱包/合约、Provider/Signer、安全及生产准入。
- Standard 未通过生产准入时可查看已配置/待准入说明，不开放真实执行。
- 降级后历史资金事实只读保留；已发生退款、争议、在途划拨和法定义务不得删除或自动清零。
