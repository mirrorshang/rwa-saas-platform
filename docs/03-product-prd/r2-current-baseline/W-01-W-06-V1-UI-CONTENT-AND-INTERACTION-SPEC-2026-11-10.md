## 0. 本批范围与设计约束

本批覆盖现有官网的六个公开营销页面：W-01 首页、W-02 产品功能、W-03 解决方案、W-04 订阅方案、W-05 帮助中心、W-06 联系我们。

### 0.1 现有成果与改版方式

- 以 `ui/wdex-saas-website-v1` 当前页面结构为审计对象：Hero、卡片、流程、套餐对照、FAQ、联系说明等基础布局均可保留。
- 本批不重新设计整站，不新增营销模块，不改变现有品牌视觉方向；主要修订内容层级、业务词汇、CTA 和错误的产品承诺。
- 当前代码中的 Mock、Sandbox、角色切换仅是历史 UI 预览证据，不是正式客户权益。面向客户的页面不应暴露内部场景控制器或把模拟状态展示成真实服务。
- 每个页面的主 CTA 应明确下一步，不得多个主按钮争抢注意力；关键流程尽量让用户在页面内看懂，再引导至唯一企业入口。
- 所有文案都要区分：V1 产品范围、当前公开服务开放状态、真实业务的独立准入状态。

### 0.2 全站统一入口与术语

| 事项 | 推荐统一规则 |
|---|---|
| 顶部主导航 | 产品功能｜解决方案｜订阅｜投资者平台（筹备中）｜帮助中心 |
| 顶部辅助入口 | 企业登录；主 CTA「免费开始」 |
| 企业登录/免费开始 | 都进入唯一邮箱验证码入口；可用 `intent=free` 保留用户意图，不得形成两个账户流程 |
| 首次邮箱 | 验证成功后自动创建账号并登录；不是独立注册 + 邮件链接验证 |
| 企业 | 一个账号对应一个企业；官网不显示企业选择器/多企业切换 |
| KYB | 用户创建企业后开始五步 KYB；通过后激活 Free |
| 资产流程 | Asset（资产）→ Instrument（权益结构）→ Offering（发行方案） |
| Project | 内部关联业务对象，不向客户宣传为独立必经创建步骤 |
| 订阅 | Free 永久免费；Standard 月付/年付，SaaS 订阅支持 USDT/法币，价格待公布 |
| 金额 | 平台业务 UI 金额按 U 显示，按 USDT 计价；订阅付款与投资者认购资金分离 |
| 投资者 | V 为 Issuer 独立投资者门户；M 为平台统一投资端；两者与企业账号分离 |

**顶部 CTA 推荐文案：**
- 主按钮：「免费开始」→ 统一企业邮箱验证码入口，并携带 Free 意图。
- 辅助链接：「企业登录」→ 同一邮箱验证码入口，不重复建号。
- 已登录且能读取企业状态时，入口才可变为「继续企业认证」或「进入工作台」；官网不能仅凭前端本地角色推断真实权限。
- M 入口显示「投资者平台 · 筹备中」，点击进入 W 增量投资者平台介绍页，不进入企业登录。

## W-01｜官网首页

### 1. 页面目标

让第一次访问的发行企业/资产管理机构在短时间内理解：产品服务谁、解决什么问题、核心工作流是什么、Free 能做什么、何时需要 Standard，以及投资者入口有哪两种形态。

### 2. 推荐页面结构与文案

| 区域 | 推荐内容 | 交互/跳转 |
|---|---|---|
| Hero | 眉题「面向发行企业与资产管理机构的多资产 RWA SaaS」；标题 **「让资产发行管理更清晰、更有序」**；说明「从资产资料、权益结构到发行方案，在一个企业工作台中组织发行准备，并衔接投资者认购与发行后管理。」 | 主 CTA「免费开始」→ 企业登录；次 CTA「了解产品功能」→ W-02 |
| 六项核心能力 | ①资产管理；②权益结构与发行方案；③Token 管理；④Issuer 独立投资者门户；⑤投资者与认购；⑥发行后运营 | 卡片可点击，进入 W-02 对应锚点；卡片说明不写 Free 可执行真实交易 |
| V/M 投资者入口 | 标题「机构门户独立运营，统一投资端按 Offering 申请」；左侧 V：机构自己的投资者入口；右侧 M：跨 Issuer 一级发行展示渠道，属于 V1 范围但当前筹备中，逐 Offering 独立审核 | V 卡跳 W-02 门户功能锚点；M 卡跳 `/investor-platform` |
| 五步业务路径 | 01 企业登录并创建企业、完成 KYB；02 创建资产档案；03 配置权益结构；04 创建发行方案并完成投资者端内部预览；05 满足 Standard 与独立准入后发布、开展认购和发行后管理 | 每步只做说明，不显示“点击即真实发行”的模拟操作；可跳 W-02 |
| 目标客户 | 资产管理机构：「多资产资料与多期发行方案集中管理」；发行企业：「从首项资产开始，逐步准备发行与后续管理」 | 两卡跳 W-03 对应锚点 |
| 末尾 CTA | 标题「从准备第一项资产开始」；说明「Free 可永久免费准备业务资料；正式发行和运营须升级 Standard 并满足相应准入条件。」 | 主 CTA「免费开始」→ 企业登录；次链接「比较订阅方案」→ W-04 |

### 3. 首页视觉与内容修订

- 现有 DashboardMock 的「项目概览」「Sandbox示例」改为中性的「企业工作台示意」「资产与发行概览」；示意数字不显示看似真实的资产数量、募集额或投资者人数。
- 左侧导航示意与已批准 Issuer 导航保持一致；资产与发行入口不再展示「项目」为独立一级业务模块。
- 「多资产、多项目统一管理」改为「多资产与多期发行方案集中管理」，避免 Project 成为用户主要认知对象。
- 删除「Free 为永久免费的 Sandbox」「Free 可体验完整流程」等旧宣传句。
- 页面不写 Standard 价格、资产数量配额、支持的订阅支付网络或“购买后自动获得真实发行资格”。

### 4. 页面交互与状态

- 六项能力卡点击后应进入 W-02 对应章节；回到首页时不丢失页面滚动上下文（浏览器默认返回行为即可）。
- M 入口在导航、首页和页脚状态一致；筹备状态不能出现「立即投资」「立即认购」等 CTA。
- 桌面 Hero 保留主次两个 CTA；移动端上下排列，主 CTA 在前。
- DashboardMock 为静态示意，必须标明「界面示意，非真实业务数据」，不得提供模拟角色切换。

## W-02｜产品功能

### 1. 页面目标

清楚展示 SaaS 的七项能力和它们如何连接成基础发行闭环。不要让用户误以为所有资产类别、真实生产能力或复杂配置在 V1 一开始全部开放。

### 2. 页面结构

保留现有 Hero、功能锚点导航、七个功能区、底部环境与准入边界说明。七项能力按三阶段组织：

**A. 发行准备**
1. 资产管理
2. 权益结构与发行方案

**B. 发行执行**
3. Token 管理
4. Issuer 投资者门户
5. 投资者与认购
6. 资金与结算

**C. 发行后管理**
7. 收益、存续与退出

### 3. 七项能力的内容口径

| 能力 | 推荐标题 | 内容重点 | Free/Standard 边界 |
|---|---|---|---|
| 资产管理 | 「为不同资产建立清晰、可追踪的资料档案」 | 分类模板、资产基础资料、相关方、权属/估值/法律文件和版本；目录有 8 大类/24 子类，V1 首批只开放 4 个房地产模板创建 | Free/Standard 均可按当前开放模板准备正式资料 |
| 权益结构与发行方案 | 「从资产权益定义到每一期发行安排」 | 一资产一套当前权益结构；股权/债权/收益参与权三选一；一套权益可关联多期 Offering；系统展示 Token 与权益映射 | Free 可配置并保存；不能发布真实发行 |
| Token 管理 | 「将 Token 配置与合法发行记录关联」 | Token 方案、受权部署/Mint/冻结/赎回及链上记录；操作受法律、安全和生产准入限制 | Free 不部署、不 Mint；Standard 仍须独立准入 |
| Issuer 投资者门户 | 「为机构投资者提供独立访问入口」 | 标准门户、机构名称/Logo、法律链接、获授权 Offering 展示、预览/发布/暂停 | Free 仅内部只读预览；Standard 满足准入后才可配置/发布 |
| 投资者与认购 | 「管理投资者资格、订单与配售登记」 | 投资者身份、KYC/KYB、Offering 资格、认购订单、配售和持有人登记 | Free 不产生真实投资者、订单或持仓 |
| 资金与结算 | 「分别跟踪认购付款、对账、退款和结算」 | 订单付款状态、到账匹配、异常、退款、募集款结算；强调 SaaS 不默认持有投资者资金 | Free 不执行真实认购资金操作 |
| 发行后管理 | 「持续管理持有人、收益与到期义务」 | 收益上报、预期年化信息披露（适用范围待详细设计）、债权周期付息（具体字段/算法待确认）、分配、清退/兑付、到期退出 | Free 不开展真实收益/本息运营；Standard 仍须满足适用准入 |

### 4. 页面文案与视觉修订

- 现有第二项「项目与发行」改为「权益结构与发行方案」；不再以「创建 Project」作为第一步。
- 功能示意图中的「Sandbox示例」改为「页面示意」；所有假数据以占位符/中性图形表示。
- 原环境边界区从「模拟体验 vs 商业授权」改为「资料准备能力 vs 真实业务准入」：
  - Free：「创建和保存正式业务资料；内部只读预览投资者展示效果。」
  - Standard：「在订阅有效、企业 KYB 通过且具体业务满足法律与生产条件后，开展获准业务。」
- 统一强调「Standard 订阅不等于具体 Offering 已获准发布」。

### 5. 交互

- 顶部功能锚点在滚动时保持可见；点击后滚动到对应区块，当前区块状态可见。
- 每个能力区最多一个主 CTA；可用能力跳 W-04 套餐说明或统一登录入口；受限能力 CTA 用「了解准入条件」，不假装进入真实操作。
- 移动端锚点可横向滚动并明确当前选中项，不遮挡章节标题。
- 不加入复杂的产品筛选器、功能矩阵展开器或角色配置演示。

## W-03｜解决方案

### 1. 页面目标

帮助用户按业务场景理解产品，不增加新的产品对象、角色和审批复杂度。保留两个主要客户场景：资产管理机构、发行企业。

### 2. 页面结构与文案

| 区域 | 推荐内容 |
|---|---|
| Hero | 标题「不同发行阶段，都有清晰的管理路径」；说明「从准备首项资产，到管理多期发行与后续义务，使用同一企业工作台组织业务。」 |
| 场景选择 | 卡片 A「资产管理机构｜持续管理多项资产与多期发行」；卡片 B「发行企业｜从首项资产开始准备发行」 |
| 场景 A 业务挑战 | 资产资料分散；不同资产权益与发行安排不易对应；发行后事项难以集中追踪 |
| 场景 A 对应能力 | 统一资产档案；按资产查看权益结构与各期 Offering；集中查看认购/存续相关记录 |
| 场景 A 流程 | 创建企业并完成 KYB → 建立资产档案 → 配置权益结构 → 创建多期 Offering → 在满足条件后开展发行和存续管理 |
| 场景 B 业务挑战 | 首次发行不知道从何开始；资产资料与权益设计容易混在一起；发行前难以确认投资者看到的内容 |
| 场景 B 对应能力 | 房地产开放模板引导；权益结构单页配置；Offering 准备检查和投资者端内部预览 |
| 场景 B 流程 | 创建企业并完成 KYB → 创建首项资产 → 配置权益结构 → 创建发行方案 → 检查并预览 → 满足条件后升级/发布 |
| 末尾 CTA | 「从首项资产开始准备」→ 统一企业入口；「查看套餐差异」→ W-04 |

### 3. 必须删除或替换的旧内容

- 不再写「创建项目 → 在项目中关联多个资产 → 创建 Offering」为用户主流程。
- 不宣传企业内部多角色审批、普通成员、团队邀请或多企业切换。
- 将「项目进度」替换为「资产/发行方案准备状态」；若提及 Project，只在说明中标注为系统内部关联对象。
- 不承诺所有 8 类资产都可在 V1 创建和发行；说明目录范围与首批开放模板不同。

### 4. 交互

- 两个场景卡点击锚点进入对应内容，不做复杂多条件筛选。
- 流程以编号步骤呈现；当前步骤无需交互式模拟器。
- 两个场景最终 CTA 统一到企业邮箱入口，避免出现「销售演示」「申请多组织」等未经批准的新流程。

## W-04｜订阅方案

### 1. 页面目标

让客户清楚知道 Free 可以做什么、不能做什么，Standard 为什么收费、订阅后仍有哪些独立准入条件。价格未公布时不制造虚假价格或付款入口。

### 2. Hero 与套餐卡

**Hero 标题：**「从 Free 开始准备业务，按需升级 Standard」

**说明：**「两种方案使用同一企业工作台。Free 永久免费；Standard 支持月付或年付，具体价格以正式公布为准。」

**Free 卡：**
- 标题：「Free｜免费准备发行资料」
- 价格：「永久免费」
- 说明：「企业 KYB 通过后，可创建和管理正式资产资料、权益结构与发行方案，并查看内部投资者端预览。」
- CTA：「免费开始」→ 统一邮箱入口
- 边界：「不包含真实 Token 发行、公开门户、认购募资、投资者持仓或收益运营。」

**Standard 卡：**
- 标题：「Standard｜正式业务订阅」
- 价格：「价格待公布」
- 说明：「按月或按年订阅；在订阅有效、企业认证及具体业务生产准入满足后，使用相应正式发行和运营能力。」
- CTA：「了解升级流程」→ W-13；次 CTA「企业登录」→ 统一邮箱入口并保留 Standard 意图
- 边界：「订阅本身不自动批准任何具体 Offering、资金执行、Token 操作或 M 平台上架。」

### 3. Free / Standard 对照表（13 行）

| 功能 | Free | Standard |
|---|---|---|
| 费用 | 永久免费 | 固定月付/年付；价格待公布 |
| 企业 KYB | 必须完成 | 必须完成 |
| 企业钱包 | 可配置 | 可配置 |
| 创建资产 | 支持 | 支持 |
| 配置权益结构 | 支持 | 支持 |
| 创建发行方案 | 支持 | 支持 |
| 投资者门户预览 | 只读、内部预览 | 支持配置与预览 |
| 真实 Token 发行/部署/Mint | 不支持 | 满足独立准入后 |
| 公开投资者门户 | 不支持 | 满足独立准入后 |
| 认购与募资 | 不支持 | 满足独立准入后 |
| 投资者持仓/锁仓 | 不支持 | 满足独立准入后 |
| 收益与发行后运营 | 不支持 | 满足独立准入后 |
| 白标/API | 不作为已批准的 Standard 交付承诺 | 版本与商业范围待决策 |

说明：不增加资产数、Offering 数、Token 数、投资者数等未经批准的硬配额；不把独立 Mock 控制台或演示角色切换写入套餐权益。

### 4. 订阅支付和生命周期说明

- SaaS 订阅支持 USDT 与法币；订阅页不宣称固定 USDT 网络已开放。
- 订阅支付与投资者认购资金分离。投资者 V1 认购付款网络范围为 OP Mainnet USDT，不在 SaaS 订阅页面作为订阅网络宣传。
- 自动续费默认关闭；只有付款渠道支持有效周期扣款授权且用户主动开启时才开放。
- 到期前 7 天、3 天、1 天及到期当天提醒。
- 到期进入 7 天宽限期：暂停新增真实发行，保留必要存续操作；宽限结束仍未续费则降级，历史业务只读，必要投资者权益通过独立受控机制保障。
- 新开通 Free 与 Standard 到期降级后的历史只读状态不同，不能只根据 Free 标签判断编辑权限。

### 5. 交互

- 套餐卡 CTA 和页面底部升级 CTA 的目标一致，不在价格未公布时显示「立即付款」。

## W-05｜帮助中心

### 2. FAQ 分类与 18 个问题

分类保留：**账户与企业｜订阅与账单｜资产与发行｜投资者与 Token**。

| ID | 建议问题标题 | 回答必须覆盖的当前规则 |
|---|---|---|
| Q1 | 如何开始使用企业工作台？ | 邮箱验证码；首次自动建账号；创建企业后完成五步 KYB；通过后激活 Free |

| Q5 | 投资者是否通过 SaaS 企业入口登录？ | 不是；投资者使用 V Issuer 独立门户或 M 统一投资端独立入口 |

| Q12 | Project 与 Offering 有什么区别？ | Project 为内部关联对象；用户以 Asset 为中心创建权益结构和 Offering，不需单独创建 Project |
| Q13 | Free 能否模拟完整发行流程？ | 不能将模拟认购/资金/Token/收益运营作为 Free 权益；可保存正式准备资料并内部预览 |

| Q15 | 平台会为发行企业寻找投资者吗？ | V 自有门户；M 可对单个 Offering 申请展示并独立审核；不保证上架或募集结果 |
| Q16 | 认购成功是否等于取得 Token 和法定权益？ | 订单、付款、配售、法定登记、Token 交付为不同阶段 |
| Q17 | Free 中的 Token 能否转成真实 Token？ | 不能；Free 无真实部署/Mint，不能把模拟数据转为生产事实 |
| Q18 | Standard 到期后，历史投资者权益会消失吗？ | 不会因 SaaS 降级自动消失；宽限后历史业务只读，必要存续义务由受控机制保障 |

### 3. 六篇教程标题与步骤

| 教程 | 标题 | 主要步骤 |
|---|---|---|
| 01 | 使用邮箱登录并完成企业认证 | 输入邮箱 → 获取验证码 → 首次验证自动建账号 → 创建企业 → 五步 KYB → 查看审核状态 |
| 02 | 认识企业工作台 | 进入唯一企业 → 查看导航 → 了解资产与发行、投资者门户、认购、资金、Token 和存续模块 |

### 1. 页面目标

说明当前能提供的咨询类型和真实服务开放状态。在线接收服务尚未开放时，页面应提供清楚的替代路径，而不是展示一个会假装发送成功的表单。

2. 企业账户与产品支持；
3. Standard 与统一投资端渠道。

咨询分类保留七类，更新为：
- 产品功能与演示；
- 商业合作；
- 注册与账户访问；
- 产品使用支持（替换旧「Sandbox 使用支持」）；
- Standard 订阅与账单；
- 统一投资端渠道咨询；
- 其他问题。

### 3. 表单与服务状态

- 若在线接收服务未开放：显示「在线咨询暂未开放」，提供「查看帮助中心」「查看订阅方案」；不展示可提交表单、不生成模拟回执。
- 若未来真实接收服务开放：表单字段才可启用；咨询类型、联系人姓名、工作邮箱、咨询内容必填；企业名称、国家/地区、联系电话选填。
- 提交前展示隐私告知与必要同意；提交后只在服务端返回真实受理凭据时显示「已收到」，不得用本地状态模拟成功。

### 4. 页面交互

- 咨询场景卡可以带 topic 参数跳转至同一联系页面，但当服务未开放时，显示对应主题说明和帮助入口，不要求用户重复填写。
- 帮助中心是当前可用的主要自助入口；联系页面不重复复制 FAQ。
- 不显示「模拟成功回执」或「演示提交」作为正式客户交互。
- 手机端表单（未来开放时）字段单列、必填错误紧邻字段、保留草稿前须明确告知存储行为；本批不批准存储敏感身份或金融信息。
