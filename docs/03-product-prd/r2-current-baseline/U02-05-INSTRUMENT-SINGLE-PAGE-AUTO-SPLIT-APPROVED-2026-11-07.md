# RWA SaaS R2 U02-05｜权益结构单页创建与自动 Token 拆分（最新修订批准）

> 决策日期：2026-11-07（用户明确回复「同意你的推荐」）。**Approved：覆盖 U02-05 R03 原「四步向导」方案、收敛 R05 / R11 用户可见容量交互，并确认 R17 / R18 的本次交互方向**。仅更新 R2 当前产品基线，PR #8 保持 Draft / Open / Unmerged；不授权合并、代码变更或真实生产发行。**R13～R16 的逐字段 Ready 必填/选填、R17 的技术精度与生产公式、R18 的逐权益法律文件必需清单仍 Draft，不能借本批准越级冻结。**

## 0. 为什么修订：以用户任务取代技术字段
- 原已批准的一资产最多一项当前有效 Instrument、股权/债权/收益参与三选一、多期 Offering 共享该 Instrument 的权益池，**均保持有效**；多 Instrument、多类混合、复杂分层继续 V2.0。
- 资产创建五步因资产分类/基础资料/权属/估值/文件的较大信息量而保留。**Instrument 字段少、对象仅一项**，不应机械套用同样的分步模式。
- 发行人真正需要理解的是「投资者获得什么权利？我拿出多少权利？分成多少份？已发行及剩余多少？」而不是学习「权益容量/单位映射/预留主账」等后台术语。
- 保持法律权利与 Token 凭证有边界：Token 对应权益的数学表达并不单独赋予登记股东身份、自动保本/收益、合法证券发行或部署/Mint 权限。

## 1. 最新有效修订及覆盖关系
| 先前规则/提案 | 此次批准的最终规则 | 边界 |
|---|---|---|
| **R03（原批准四步向导）** | **改为单页面、三区域分组表单**：①权益定义；②Token 拆分；③法律文件；页面底部「保存草稿」和「完成资料检查」 | 删除 Instrument 自身的四步进度条、跨页下一步/上一步和独立第四步预览，不改变资产创建五步，也不取消资料校验/版本保护 |
| **R05 / R11（原权益容量、每 Token 代表权益都以用户录入理解为中心）** | 系统内部继续保持授权权益池、固定 Token 映射、各期有效预留/确认及剩余校验；**UI 让用户输入「本权益覆盖的权利总量」＋「拆分成多少份 Token」**，系统计算每份 Token 对应权利、最大可发行量和剩余可新增份数；避免要求手填同义的映射值 | 内部严谨容量账务不被删除；尤其多期 Offering / 历史版本仍共用同一权益限额 |
| **R17（本轮交互方向批准，细则待审）** | Token 拆分：发行人输入总权益规模与拆分份数，系统自动计算 Token 每份对应权利；形成实时可读解释与校验反馈 | **不自动推断代币精度、合法股权拆分单位、分数权益可用性或链上 Token 标准**；具体整数/精度/四舍五入/异常阻断待后续详细审核 |
| **R18（本轮交互方向批准，细则待审）** | 法律文件区直接列适用必需行和上传操作，允许从资产已存在文件中引用**固定版本**，其他资料按需添加 | **哪些材料在各类权益下必需/条件必需、签署与法律充分性仍待批**；本次批准的是页面组织与引用原则，不自创法定必需证据 |

### 1.1 当前一页 UI 结构（无向导）
```text
资产管理 → 某项资产 → 权益结构 TAB → [创建/编辑权益结构]
──────────────────────────────────────
[状态：草稿 / 资料已完备]  关联资产名称（只读）
1. 权益定义
   权益类型：[股权] [债权] [收益参与]（只选一类）
   权益结构名称、权利责任主体、权利说明
   当前权益类别的少量专属条件（R13～R16 字段级仍需审核）
2. Token 拆分
   计划拿出多少权益？[权益总规模 + 单位]
   计划将这部分权益分成多少份？[Token 总份数]
   → 每份 Token 对应的权益：由系统自动计算，显示具体说明
   → 最多可发行：拆分总份数
   （尚无发行记录时不展示空的「已预留/已确认/剩余」复杂容量报表）
3. 法律文件
   权益类适用必需文件 [上传]
   [引用当前资产已有文件及其确定版本]
   [＋添加其他文件]
──────────────────────────────────────
[保存草稿]  [完成资料检查]
资料未全：在本页准确定位缺项，草稿可继续保存
资料满足：显示完成反馈 → 回资产「权益结构」TAB，
          下一步指向「发行管理 → 创建 Offering」
```
- 这**只有三个分区、不是三个步骤**。选择权益类别即动态切换字段；不因选择不同类型要求翻页。
- MVP 单资产一套当前 Instrument；有现有记录显示单项详情/编辑/版本，不展示创建第二套的入口。
- 页面上清楚写「Token 份数/每份代表什么」，避免把产品本身的权益容量主账名词变为用户必学术语。

## 2. 三类权益使用同一种拆分交互
| 权益类型 | 用户输入的总权益 | 用户输入 | 系统计算并解释 |
|---|---|---|---|
| 股权 | 拟纳入本次权益结构的**法定可用股份数量** | Token 拆分份数 | 每 Token 对应多少股份；必须核对是否允许对应股权/权利拆分与名册映射 |
| 债权 | 可受法律凭证支持的**债权名义本金总额（U）** | Token 拆分份数 | 每 Token 对应多少 U 名义本金；**不是认购销售价格** |
| 收益参与 | 特定收益范围的**授权参与比例（%）** | Token 拆分份数 | 每 Token 对应多少比例的合同收益参与权；**不承诺固定收益或资产产权** |

### 2.1 只用于解释的产品示例
- 股权：10,000 股，拆成 10,000 份 → 每 Token 对应 1 股（需另行校验股东/证券法律关系）。
- 债权：本金 1,000,000 U，拆成 10,000 份 → 每 Token 对应名义本金 100 U；Offering 才设置发行价格/募集金额/认购周期。
- 收益参与：净租金收益的 10% 参与权，拆成 10,000 份 → 每 Token 对应净租金收益的 **0.001 个百分点**（亦即总净租金收益的 0.001%），且必须明确收益计算口径与期限。
- 所有示例均为概念说明，不是实际发行、合同配置或计算精度的生产确认。

## 3. 用户可见的发行后容量摘要
- **首次配置权益结构或尚无任何有效发行时**，表单仅显示「本次权益拆分 X 份 / 每份对应 Y 权利 / 最多可发行 X 份」，避免强制理解 0 份预留、0 份已发等空指标。
- **已有 Offering / 发行事实时**，在权益结构详情展示业务可理解的：**最多可发行、已发行、已预留、剩余可发行**，必要时附解释和分期明细。
- 后台语义映射：已发行仅计**已确认的有效权益分配/占用**，不等于用户刚填 Token 份数已经实际 Mint；已预留仅计有效且未被确认占用重复计算的发行预留；剩余=总可发份数－已确认有效占用－有效预留（在相同权利单位、有效版本范围的受控校验下）。
- 各 Offering 消耗同一 Instrument 的容量；Draft Offering 不生效预留；已生效的权益不因本期 Offering 关闭、删除或历史版本变更而自动释放；跨期不能超发、不能重复确认。
- 技术计算必须进行受控的精度与守卫校验；**如果拆分结果无法在被批准的权利/Token 最小单位内精确表达，不能静默取整损害/放大投资者权利**。具体精度参数与失败文案继续 Draft。

## 4. 草稿、完成检查与文件行为
- 保留 R03 原先已批准的「草稿保存、编辑、资料完整性校验」能力，**只取消四步向导和单独预览步骤**。页面内校验能定位字段/文件；首次创建 Draft 的最低字段门槛沿用待审字段级 PRD，不因本次变更自动规定所有 Ready 必填。
- 法律文件区域遵循 [U02-04 文件差异收口](U02-04-ASSET-FILE-REFERENCE-CLOSEOUT-APPROVED-2026-11-06.md)：引用当前 Asset 已有文件需选定 FileId+VersionId，已引用的原件不受后续更新静默替换；权益专属协议归 Instrument，发行认购协议归 Offering。
- 资料完整 Ready 与法律权利生效、文件真实有效、Token 已部署/Mint、Standard 有真实发行资格等**严格区分**。
- Instrument 已被 Offering/真实持仓使用后，修订应保留旧版本、权益和容量历史，不得直接更改已生效的权利映射；详细的版本修改许可和状态机仍由后续字段级/UI-Ready 批次审核。
- Free/Standard 允许的资料准备范围沿 U01 最新规则；Free 不能真实发行，Standard 仍独立准入。
