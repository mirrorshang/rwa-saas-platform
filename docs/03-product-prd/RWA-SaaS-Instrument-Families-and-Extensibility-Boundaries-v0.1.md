## 一、战略问题与审核结论（设计提案）

**问题**：仅用债权 A、权益 B 能否覆盖 Brickken 等通用 RWA 发行工具以及基金、版税、商品/黄金等产品？

- **适合首批完整产品需求验证**：A（到期本金和收益债权）、B（SPV 股份/类似权益），共享发行、准入、认购、资金、配售、登记、真实 Token 和最小存续期核心。
- **不能当作所有权利的强制归宿**：基金份额/集合投资权益、纯合同收入参与权、特定实物资产或托管权属凭证的投资者**法律主张、计价、分配、赎回与权威记录**不同。把它们强制包装为 A 或 B 会混淆真实权利并产生需求遗漏。
- **推荐长期产品分类 A～E**，其中 **C/D/E 先规划类型定义与扩展边界**。未来何时形成生产支持，以及 C/D/E 每个家族的完整业务规则，都需独立版本/法域/客户和商业评审。
- **非穷尽**：碳信用/环境属性等登记簿原生单位，以及具有储备、发行赎回和支付属性的稳定币，需要**另行判定是否建立 F 类或独立产品线**，不能简单强行当作 E 实物所有权；本次不新增正式 Instrument 类别或版本交付承诺。

## 二、五类候选 Instrument 家族与实际资产示例

| 家族 | 投资者真实权利的产品表达 | 适用资产/经营场景示例 | 关键业务事件及证据 | 产品规划状态 |
|---|---|---|---|---|
| **A 债权型 Debt Claim** | 对发行人/债务人享有依法或合同确定的本金、利息及其他债权请求权；可有担保、优先顺序和到期日 | 企业融资票据、项目融资债券、应收账款融资债权（需核验是否实际债权转让）、房地产/能源债务融资 | 本息计划、债务余额、逾期与违约、偿付/注销、债权登记及适用担保凭证 | **已批准作为 V1 完整验证样本**；不是法域或真实债权工具确认 |
| **B 实体权益型 Entity Equity / Ownership Interest** | 经法域和实体文件确认的股权、公司权益或类似实体剩余权益；可能有分红、表决或类别限制 | 持有房地产的 SPV 股份、新能源项目公司股权、私营企业普通股/优先股 | 股份/份额类别、权利登记、合格持有人、公司决议、利润分配、回购及转让限制 | **已批准作为 V1 完整验证样本**；不默认股东表决 UI/二级交易 |
| **C 基金/集合投资份额 Fund / Collective Investment Interest** | 对基金、集合投资载体或信托的份额、单位或实益权益；具体法律形式可能仍是 B、信托受益权或合同 | 货币市场基金、房地产基金、私募信贷基金、PE/VC 基金、基金型 RWA | 单位份额、NAV/估值日、认申购/赎回窗口、门槛/费用、资本催缴（适用时）、基金权威名册与清算 | **拟作为独立产品能力家族 C**；首期只考虑通用字段/接口扩展与业务边界，不做完整 NAV/申赎/资本催缴引擎 |
| **D 合同收益参与/版税型 Contractual Revenue / Royalty Right** | 收取约定收入流、版税或营业额份额的合同权利；不自动具有公司所有权，也不自动有固定本金债权 | 影视票房分成、音乐版税、IP 许可收益、特定营业收入参与、设备经营收入 | 收入来源与口径、实际结算报表、扣除项、分配公式/上限、应收及已付、合同终止与纠纷证据 | **拟作为独立产品能力家族 D**；首期保留权利/现金流的结构化描述，完整外部收入核算与收益引擎待决 |
| **E 特定资产权属/托管凭证型 Title / Custodial Claim to Asset** | 对可识别实物或托管标的的所有权、受益所有权、提取或兑换请求权；具体权利与托管责任依协议/法律 | 托管黄金与贵金属、已认证库存/仓单商品、艺术品权属凭证、可追索的可提货商品 | 特定资产 ID/批次/序列、保管人和储备/库存证明、权属变更、托管核验、实物交割/赎回、短缺异常 | **拟作为独立产品能力家族 E**；首期不建设全量托管储备、库存证明、实物提货与现场交割系统 |

**边界示例**：同一栋商业楼可以以项目债权（A）、持有物业的 SPV 股份（B）、房地产基金份额（C）、租金合同现金流参与权（D）或依法成立的物业特定权属安排（可能涉及 E）发行；**底层资产不决定 Instrument 家族**。同一 Instrument 可能兼有多种权利（例如优先股及累积分红、可转债），不得以简单互斥枚举剥夺重要合同权利。

## 三、建议的三层区分与可组合权利模型（非数据库/接口实现冻结）

### 3.1 三条互相独立的建模轴

| 轴 | 应表达的事实 | 不应混同为 |
|---|---|---|
| **Asset / Underlying Exposure**（标的） | 房地产、贷款组合、股权、黄金、知识产权、碳信用等；证据、保管位置、估值与发行人对资产的关系 | 投资者已取得资产所有权 |
| **Instrument / Legal Rights**（法律权利） | 谁是债务人或义务人、权利人拥有什么、法律形式/优先级/所有权/受益权益、登记权威、收益/追索、限制与终止 | “底层资产分类”或“某条链上的 Token 类型” |
| **Offering / Tokenization Arrangement**（发行和链上实现） | 本轮条款/价格/数量/准入/资金路径、文档签署/权利生效条件，以及 Token 在权利安排中究竟是证据、记账载体还是特定法律承认的记录 | Token 铸造成功自动等于资金到账、法定登记或债权/股权取得 |

另需分开保留：**权利经济特征**（债权/收益/赎回等）、**法律载体**（公司股份、基金单位、合同、权属凭证）、**法域定性**（是否证券/基金/支付工具等），它们不一定一一对应。产品家族可作为分类入口，但具体合同权利/法域结论具有更高优先级。

### 3.2 建议的产品级权利能力片段（只规划契约，不定义数据库列）

| 可组合片段 | 可能的取值/业务含义 | 典型家族 |
|---|---|---|
| **Right / Obligor** | 法律义务人、权利人、权益类别、优先顺序、有效文书/适用法域与版本 | A/B/C/D/E |
| **Unit / Decimal / Supply** | 份额精度、最小单位、总发行上限、已发行量、法定所有权单位与链上 Token 对应比率 | A/B/C/D/E |
| **Cashflow Obligation** | 固定利息、浮动利率、可选分红、NAV 份额收益、按营业收入比例分成、无现金收益 | A/B/C/D（E 通常为非现金交割，也可能有附属收益） |
| **Valuation / NAV** | 独立评估、定价来源、NAV 日期、最新值与历史版本、有效申赎价 | B/C/E；A/D 按合同需要 |
| **Distribution / Redemption** | 对现金流/持有人快照的权威引用、适格付款方、赎回窗口/条件、部分赎回、应付/已付及 Unknown | A/B/C/D/E（实物交付另有凭证） |
| **Custody / Reserve / Inventory** | 实物或储备权威方、标的批次/序列、权属/保管证明、短缺/对账与实物交付 | E；C 仅按基金法定责任需要 |
| **Register / Beneficial Owner / Transfer Guard** | 法定登记人与 Token 持有人不同、冻结/白名单/转让限制、权利生效日及允许更正 | A/B/C/D/E |
| **Disclosure / Reporting / Corporate Action** | 信息披露、受控通知、违约、重大事件、持有人表决（如适用）、权利变更 | A/B/C/D/E |

**重要限制**：这只是产品规格候选。“可组合能力片段”不等于 V1 必须建设复杂的可视化规则引擎、NAV 系统、收入结算平台或实物托管系统。对于尚未获得支持的家族，接口应清楚显示**未启用/不支持**，不能让用户提交生产交易后才发现缺少法律和业务处理。

### 3.3 版本、审批与状态继承

- M04 对 Instrument 权利结构、正式文件、责任主体和生效版本形成唯一引用；M05 Offering 引用**已批准版本**并按发行时点形成条款快照。重要改动需重新走适用审查，不得以后台字段变更追溯修改历史持有人权利。
- M09 对每个 Offering 和投资者进行资格判定；M10 认购、M11 外部到账/退款、M12 唯一额度/配售与法定登记、M07 Token 链上事实、M13 存续权益保持各自状态，彼此通过受权引用和核验关联。
- 根据 Instrument 的法律要求选择**登记先于链上交付、链上证据先于登记回执、或受控协同确认**的合法状态序列；不在本文件规定所有工具的同一先后顺序。
- 对外商业 Open API（M16）交付时间仍独立；Issuer SaaS V1 应遵循 ARCH-001 的统一应用服务、内部契约和业务授权，不对 C/D/E 预先承诺生产可调用 API。

## 四、A/B 与 C/D/E 分阶段实施边界

| 阶段 | 本次建议纳入 | 明确不包含 |
|---|---|---|
| **当前产品体系设计（现在）** | 描述 A～E 家族、法律形式和能力片段、扩展接口/版本/权威事件规则、不同家族的适用条件与不可用行为 | 不冻结 187 项真实 V1 开发范围；不审批 C/D/E 上线或实际法律结论 |
| **Issuer SaaS V1 核心验证** | **A 固定收益到期债权 + B SPV/类似权益**作为完整产品需求验证样本；共享 M01～M13 等核心能力 | 不新增 C NAV 引擎、D 版税对账、E 储备/实物交付自动化；不以此取消 A/B 必要安全和权益功能 |
| **C 基金路线（后续待定）** | 定位新需要：NAV/估值来源和时点、申赎窗口、份额登记、费用/限制、基金权威记录、资本催缴（适用时） | 不假定基金资产必然属于债权或股权；不借 A/B 测试结论宣称支持真实基金认申赎 |
| **D 收入参与路线（后续待定）** | 定位新需要：外部营业收入源、对账证据、分配合同/上限/期限、权利归属与纠纷更正 | 不把营销意义的“收益分成”默认写为固定本金债务或实体股份 |
| **E 权属/托管凭证路线（后续待定）** | 定位新需要：权属/托管主体、储备/仓单/库存凭证、实物资产关联、赎回与交付、储备差异处置 | 不把单纯“抵押黄金债券”当作黄金直接所有权，也不默认建立真实仓库/审计/托管服务 |
| **其他/潜在独立产品** | 环境属性/碳信用登记与退休、储备支持稳定币等进入单独可行性/法律分类门 | 不自动作为 E 家族、M07 通用 Token 或现有 Issuer SaaS V1 必交 |

**范围纪律**：正式“支持某家族”至少要有一套足够具体的真实法律权利、适格责任主体、资格/条款规则、认购/资金/配售/登记、生命周期和真实 Token 的全闭环；**仅有基础数据模型或 API 字段不能对外宣传为可生产发行该家族**。

## 五、对现有 M01～M22 的影响与缺口归属

| 模块 | 本次设计影响 | 应否修改既有原分级 |
|---|---|---|
| **M01～M03** 客户、组织、运营 | 商业许可与租户/角色控制可按家族和法域授予能力；平台客服无权绕过法律执行授权 | **否** |
| **M04** Asset/Instrument | 优先补充 Asset 类型≠法律家族、权利/义务片段、法律形式、权威证明、版本与“未支持类型”校验 | **否**；沿用 M04-F001/F003/F005/F006/F007 |
| **M05** Project/Offering | 不同家族的定价/募集/申赎条件通过获批准的家族能力/规则定义；C 的 NAV 价格、D 的收入、E 的赎回不可硬塞进持续购买固定价 | **否**；集中募集仍依 Instrument 条件决策 |
| **M06** 文件/专业审查 | 专业意见及文件类型按 Instrument 家族配置；基金章程/版税合同/仓单储备证明只按适用性要求 | **否**；不新增首期专业服务市场 |
| **M07** Token/链上 | 代币代表权利的法律角色与合约限制、实际执行授权、Token/法定登记差异；E 资产赎回后如何注销由未来专门规则确定 | **否**；任何首发 Token 都须真实上链 |
| **M08/M09** 门户、资格 | 家族特定披露、投资者资格/禁售、用户可见证据；实际 KYC 与 Offering eligibility 不混同 | **否** |
| **M10/M11** 认购/支付 | 应付总额、付款币种/链、退款、申赎费用等未来扩展；C 的开放申赎不等于当前 Issuer V1 的普通认购 | **否** |
| **M12** 配售/权威登记 | 法定份额/单位精度、登记权威与 Token 独立、权益变更快照；C/D/E 另按法定结构定义权利生效 | **否** |
| **M13** 存续 | A 本息与 B 适用分红验证；C NAV/申赎、D 版税/分成、E 托管/实物交割是未来单独能力域 | **否**；必要 A/B P1 按现有批准规则裁决 |
| **M14** 受控转让 | 未来转让限制需依不同法定权利/登记/实物托管条件裁决；V1 仅保留适用链上转让限制 | **否**；M14 V2 仍遵循 DEC-011 |
| **M15/M16** 白标/Open API | 未来白标和第三方 API 应共用家族能力许可/权利模型；独立产品商业排期不变 | **否**；API-Ready 不等于 C/D/E 商业对外开放 |
| **M17～M22** 工作流/事件/规则/审计/报表/集成 | 家族适用守卫、法律证据和受控外部回执可扩展；未来 C 的 NAV 服务、D 的收入报表、E 的保管证明是按项目授权的集成 | **否**；不能重复业务权威或资金账本 |

**结论**：候选新增的是“跨模块 Instrument 类型与权利能力规范”和未来能力缺口清单，**不是第 23 个冻结模块，也不新增 Mxx-Fxxx 编号或修改已有 187 项 P0/P1/P2/V2/待定定位**。将来如决定产品化 C/D/E 的专用业务功能，须经功能需求增量编号、影响评审及单独审批，而不是暗中挤进当前 V1。

## 六、推荐能力标识与 API-First 适用性（产品级、不锁技术方案）

建议在产品 PRD 为每一 Instrument 版本标记以下**逻辑字段组**（名称仅为示意，不承诺数据库列、HTTP URL、协议或供应商）：

- **Identity & Legal Form**：asset_ref、instrument_ref、instrument_family_candidate、legal_form、jurisdiction_context、obligor / issuer / registered_holder、rights_document_version。
- **Rights Configuration**：权益类别、法定权利/义务、计价/份额精度、固定/浮动/可选收益、到期/无固定到期、赎回/实物交付、转让和登记限制、权益生效条件。
- **Authority & Evidence**：register_authority、custody_or_reserve_authority（如适用）、signer_authority、evidence_ref/version、approval/reference timestamps；**不能把第三方成功返回当作已获法定权利**。
- **Availability & Capability**：supported_for_design / supported_for_issuance / requires_external_authority / legal_review_pending 的可表达状态；**只有经适用审批授权且技术与运营能力满足时才能开放生产发行命令**。
- **Lifecycle Extensions**：现金流事件、NAV 更新（未来）、收入结算来源（未来）、托管/实物交付事件（未来），统一保留不可逆动作的幂等/Unknown/审计。

**兼容要求**：未来增加家族和权益片段时不重新定义 M10 认购、M11 支付对账、M12 法定登记或 M07 Mint 的权威责任；新的家族适配只能通过受控业务插件/服务接口（逻辑层），不能绕过权限。具体插件机制、模块化单体或微服务拓扑留第 07 份技术架构评审决定。

## 七、已批准的 8 项产品原则（**SCOPE-101～108 Approved**）
