## 一、七条已批准的决策

| 决策 | 具体覆盖 ID | 已确认要求 |
|---|---|---|
| **SCOPE-071** | M07-F002、M07-F008 | 合约参数及高风险密钥/执行操作必须有版本冻结、审批、受权签名人、环境/角色隔离、撤权与暂停和执行结果核验。**允许合法受权的外部签名/部署主体**；不强制 Issuer SaaS 自持私钥或自研全套合约运维平台。 |
| **SCOPE-072** | M07-F004、M07-F005 | Token Mint/交付必须有真实链上执行和可核验结果。执行请求必须关联受权配售/必要登记条件、链/合约/接收钱包、幂等 ID、Tx/Event 和最终性；**Unknown/超时先查询原不可逆操作，不得盲目重复 Mint**。 |
| **SCOPE-073** | M11-F004、M11-F005 | 真实稳定币付款由指定链/币种/合约事实识别，SaaS 可使用节点与合法观察服务，但自身必须维持独立匹配/对账与最终性/Unknown 处理；重复回调去重但**不能丢失不同的真实转账**，迟到账、错链、重组和 Unknown 均受控。 |
| **SCOPE-074** | M11-F009 | 退款由**适格资金控制/付款主体**实际执行；Issuer SaaS 必须有申请、退款资格与金额/地址/币种链校验、授权审批、外部执行 ID/Tx、结果复核与审计。外部结果未知时先核对原指令，**防止双重出款**；SaaS 不默认托管/支付真实资金。 |
| **SCOPE-075** | M12-F006、M22-F004 | 法定或合同权威登记由适用 Instrument/法域认可的责任方完成。M12 将配售、登记结果、Token 交付作为**不同事实**分别关联、核对和纠正；M22 只负责可信登记 API/受控凭证交换，不得再造一套法定权威登记。 |
| **SCOPE-076** | M22-F005 | 适用的电子签署可经外部服务完成；SaaS 在 M06/M10 中保留签署人/身份关联、协议和同意版本、文件哈希、签署证据及可核验结果；服务商签署成功**不自动证明全部法律要件满足**。 |
| **SCOPE-077** | 10 项全部 | 统一最低集成安全与验收要求：调用者和权限范围、外部事件/执行 ID、事件来源真实性、凭证隔离、环境隔离、可核验回执、幂等、真实多笔转账区分、Unknown 查询、受控补偿/人工审核、重要操作可追溯审计。不得因 API-First 把特权执行无限制对外开放。 |

## 二、审核范围及不可省略的核心职责

| 责任模块 | 必须由 SaaS 设计与验证的范围 | 外部法律/技术责任需另审 |
|---|---|---|
| M07 Token 执行 | 授权审批、执行意图/参数快照、钱包与合约校验、链上事实/最终性核验、Token 对账、Unknown 安全恢复 | 适格部署/签名人、生产密钥/合约权限及监管规则 |
| M11 稳定币付款及退款 | 支付指令与真实到账事实区分、到账匹配/独立对账、双付/迟到账/错误链处理、退款审批与结果核验 | 收款账户控制者、实际退款付款方、资产与链路许可 |
| M12/M22 权威登记 | 授权配售决定与法律权威登记回执分离、登记与 Token 核验；技术适配不得改变权威 | 法律规定的登记人、凭证格式及登记权利效力 |
| M06/M10/M22 签署 | 协议/条款版本、签署者身份授权、有效同意与可信签名结果/证据留存 | 具体法域对电子签/送达的要求、服务商适格性 |

外部事件统一穿过受控适配边界，但不得因此把 M22 Webhook 事实、M17 异常工单或 M21 报表变为 M07/M11/M12 的第二套权威。M07 链上 Token 的成功也不自动证明持有人的法定权益已完成登记。
