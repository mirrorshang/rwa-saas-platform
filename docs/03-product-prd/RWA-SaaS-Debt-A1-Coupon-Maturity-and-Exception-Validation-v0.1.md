## 一、工作目标：消除同一 Series 的晚入场与兑付歧义

已批准 A1 主线为**同一债权 Series、统一到期日与票息支付日，在被合法批准的窗口内多次发行/销售**。此处的“多次购买”是**一级发行、同一系列的后续新增债权单位**，不等于 V2 投资者之间二级转让，也不意味着法律上任何时期都能无限增发同一类债券。

待具体法域、契约和发行文件核实的首要问题：
- 后续认购单位与先发行单位是否**法律上可互换、同等受偿**？若权利/价格/起息不同，必须有独立 Lot/Tranche 或采用另一 Series，不能仅用同一 Token ID 隐藏差异。
- 晚入场者应付本金、溢折价、应计利息及手续费如何组成交易价？债券票息的**法律 entitlement**取决于登记/记录日和债券条款，不由 SaaS 自行创造债权。
- 晚入场者如何被告知剩余期限、年票息率不等于实际持有期投资收益率、下一次票息记录日及到期后能否继续购买？
- 需要法律确认“持续购买”究竟代表**首发后增量发行（tap issue）**、一次批准的长期发行计划，还是须另批每个 Tranche；若不可用，启动已批准的条件性 BatchAllocation 或 A2 候选，不绕过法规。

## 三、A1 晚入场认购的示意计价（不是已批准算法）

假设仅用于检验系统：
- 一份债权的名义本金 **1,000 USD**、固定名义票息率 **8%/年**、每 360 天付息（只是演示 convention）、满额第一期票息 **80 USD**；
- 某获批准的同权后续一级发行发生于本期第 180 天；
- 仅当合法条款约定“后续购买人有资格按票息记录日取得整期 80 USD，且本次发行适用应计利息补价”时，示意应计：\(1000\times8\%\times180/360=40\,USD\)；
- 若定义 clean price = 1,000 USD、accrued component = 40 USD、fees = 0，则示意 dirty payment = **1,040 USD**，下一付息日理论票息 **80 USD**。**80−40=40 USD** 只是用于说明晚入场的**跨期现金差额**，**不是投资者净收益、年化收益率或法律票息金额的证明**；实际收益受发行日期、合同条款、价格、期限、税费、币种和能否实际兑付影响。

| 必须询问 | 为什么必须回答 |
|---|---|
| 后续发行是否被法律/合同授权，Series 是否仍 fungible？ | 决定 A1 能否继续使用、是否须新 Tranche/Token/权利版本 |
| 晚入场是否取得整期票息、是否存在 ex-coupon？ | 决定在认购价格中如何处理应计额与下一权益快照 |
| clean/dirty 分拆法、日数基准及精度是什么？ | 影响报价快照、认购资金对账和投资者信息披露 |
| 付息日在出售期内，何时暂停新的报价/登记？ | 避免 record date 与晚到账/晚 Mint 产生错配 |
| 抵押、担保、优先顺序、税务和实付币种如何确定？ | 不可仅由本金与票息字段推出实际支付义务 |

**推荐的产品策略**：报价引擎需支持**被批准的版本化定价策略**与发行时间相关参数；V1 不默认开发开放式通用金融定价引擎、复杂交易市场或零风险收益率计算。未批准的价格和合同权益组合必须阻断发布或新报价。

## 四、Coupon 与到期本金的分离状态（候选词典，非改写第 04 份 Frozen）

### 4.1 定期 Coupon Event 最小闭环

| 事件/对象 | 候选状态 | 唯一事实来源与阻断条件 |
|---|---|---|
| CouponSchedule | Planned / Locked / Superseded | 来源已批准 Series 权利版本与日历；业务日调整、金额与记录日有版本 |
| EntitlementSnapshot | PendingEvidence / Produced / Verified / Disputed | 法定权威持有人/受益人及有效债权名义本金；与钱包 Token 独立 |
| CouponCalculation | Pending / Calculated / UnderReview / Approved / NeedsCorrection | 已核验快照+条款+金额/精度规则；差错须更正新版本 |
| CouponPayoutInstruction | Draft / PendingAuthorization / Authorized / Submitted / Unknown / Failed / Confirmed | 获授权偿付主体执行、查询原出款；不得重复指令 |
| PayoutReconciliation | Unmatched / Matching / Matched / Mismatch / Investigating | M13 保留外部实付事实、款项入账与受益对象核验 |
| InvestorDisplay | Upcoming / AmountUnderReview / Processing / Paid / Delayed / Disputed | 按已确认的权利/实际付款投影；不可将核算 Approved 显示为 Paid |

**不得跳过的 Guard**：权益记录日定义、截止时点、权利持有人证据、不同持有人/系列多币种、重复回调/Unknown 及支付失败后逐笔人工恢复。延期或违约必须触发必要外部报告/通知，而不是静默保持 Processing。

### 4.2 到期本金与登记/Token 的联动退场

| 环节 | 独立事实/审批 | 不允许的替代 |
|---|---|---|
| MaturityDue | 期限到达、权利/本金余额及提前清偿/争议条件复核 | 到期日到达≠债务已被偿还 |
| PrincipalCalculation | 法定债权有效本金与已清偿余额、适用费用/法律扣除 | Token 数量不能自动替代本金账面事实 |
| PrincipalPayout | 受权支付方实际出款、Unknown 查询及资金对账 | SaaS 按钮/支付申请不等于实付或法定清偿 |
| LegalDischarge/Register | 债务清偿的法律生效证据、持有人登记/债权减记或注销 | 原持有人数据库状态直接清空 |
| TokenExit | 受权 Burn/冻结/状态终结，链上回执及 Token ↔登记核对 | Burn 不自动证明偿付；付款也不代表 Burn 成功 |
| LifecycleClosed | 未结款、法律差异、Token 差异和受权交接处理完毕 | Offering 认购销售结束≠债务期限终结 |

**顺序不是固定**：具体债务工具可要求先支付/再确认债务解除，或受权的原子/托管式交换，或法定登记生效优先；本文只规定必须有**规则与独立事实并可恢复**，不冻结任何特定法域的单一序列。

## 五、异常恢复与不可逆执行方案（业务级，非技术接口）

| 异常 | 业务处理和必须保持的事实 | 不可做的事情 |
|---|---|---|
| 晚入场价/应计错误在付款前发现 | 报价作废，重新出新报价/条款同意；释放受保护容量前核验在途资金 | 不静默修改已确认 QuoteSnapshot |
| 晚入场价/权益错误在 Mint 后才发现 | 保留原付款、分配、登记与链上事实，记录纠正案、法定授权及必要补偿 | 不能直接删订单/修改 Token 余额冒充合法更正 |
| record date 期间发生迟到账/迟登记 | 依合法 cut-off 和有效登记权利决定票息归属；未定则调查/冻结相关分配 | 不能按钱包实时余额、Webhook 到达时间猜测收益权 |
| Coupon 计算已批准但出款方超时 | 保留 Coupon Approved、Payout Unknown，查询原付款指令/外部结果，必要人工审批 | 不能因请求超时再次全额付款 |
| 外部资金实付确认与收益登记不一致 | 独立对账 Investigation，合法纠错及可能的补偿/追索 | 不能覆盖旧实付款凭证与原始登记 |
| 本金实付但 Burn/登记减记失败 | 保留已付事实，继续查询执行/补登记；对未完成法律/链状态保留风险 Guard | 不能因 Burn 失败再次支付本金 |
| Token 已 Burn，但本金付款失败/Unknown | 保留 Burn 事实、未付债权及履行义务、风险调查和适用合法纠正 | 不能把 Token 不存在当作债务已消灭 |
| 到期违约/本金不足 | 应付欠付余额、逾期起始和责任人、必要披露/通知、后续合法偿还/追索单独记录 | 不能自动设 Lifecycle Closed 或凭人工完成勾选撤销债权 |
| 合约/付款链重组、外部结果反转 | 增加反转/争议事实，核对法律权益与资金余额，冻结进一步不可逆操作 | 不覆盖历史 Confirmed，也不自动双重 Mint/Refund/Pay |
| 客户暂停/退出但债权未清 | 运营委托/客户退出的数据和责任移交、持续通知及清偿安排 | 不能删除债权/客户权利或因此停止合法兑付责任 |

## 八、后续待审的 8 项产品决策建议（SCOPE-126～133，**尚未批准**）

| ID | 推荐内容 |
|---|---|
| **SCOPE-126** | A1 同 Series 的后续发行必须先核实合法增发/同权同序列的条件，并区分首次发行与后续增量发行；如不满足可同权条件，不得为了持续购买强行共用 Token 或 Series |
| **SCOPE-127** | 计息与兑付严格按获批准版本和法定权利快照计算，支持起息/到期/record date/必要 ex-coupon、合法后入定价和精度；不得将票面利率误显示为持有期保底收益率 |
| **SCOPE-128** | A1 晚入场认购必须通过**获审批的价格策略**明确 clean/dirty、应计利息/溢折价、费用、币种和名义本金与 Token 比率；没有合法定价规则不得自动报价或发行 |
| **SCOPE-129** | M13 的 coupon、到期本金、外部实际兑付、权威登记减记、Token 冻结/Burn 及最终对账形成**独立状态和可恢复编排**；不锁定一套跨法域通用不可逆动作顺序 |
