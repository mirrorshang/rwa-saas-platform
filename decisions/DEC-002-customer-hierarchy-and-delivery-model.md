# DEC-002｜客户层级与交付模式

- **状态：** 已确认
- **确认日期：** 2026-10-18
- **适用文档：** 第 02 份《产品战略与商业模式》
- **决策范围：** 客户关系与 V1 商业产品层级；不代表具体监管许可或资产类别已获批准。

## 决策内容

1. **标准 SaaS：** 主要服务单一发行机构/客户，供其管理自身组织、资产、发行流程及投资者门户。
2. **White-label：** V1 支持一个白标运营商管理多家发行机构，并运营自有品牌门户。
3. **资产授权：** 白标门户只可展示该运营商自有或已获得明确分发授权的资产；仍须遵守客户权限、投资者资格及适用法域规则。不得默认共享全平台资产池。
4. **不做多级代理：** V1 不支持白标运营商之下继续发展多级代理、经销商或转售层级。
5. **Open API / SDK：** 作为第三条商业交付产品线，供机构把平台能力集成进自有产品或业务系统；其权限和数据边界仍受租户隔离及授权规则约束。

## 原因

- 保持标准 SaaS 的清晰客户归属和交付边界。
- 让 White-label 具备有实际价值的多发行机构运营能力，而不仅是品牌换肤。
- 控制 V1 的渠道归属、权限继承、账单分摊和合规责任复杂度。
- 将 API 集成作为独立交付方式，而非仅作为内部实现细节。

## 影响与后续细化

- 第 03 份总体 PRD 需定义 Tenant、White-label Operator、Issuer Organization、Asset、Portal、Distribution Authorization 的关系。
- 第 04/05 份文档需细化授权生命周期、投资者资格、资产可见性和交易/分发边界。
- 第 09 份商业运营方案需明确白标运营商与下属发行机构的计费、合同、配额及责任边界。
- 不得据此推断跨发行方分发在任何法域都可直接开展；具体经营方式需另行法律审查。

## 未被本决策确定的事项

- 是否未来推出平台级自营聚合市场。
- 白标是否支持独立部署、专属基础设施或转售外部服务。
- 具体套餐、定价、限额与上线资产类别。
- 日本及阿联酋具体发行、分销、托管、支付和交易许可路径。
