# RWA SaaS｜Issuer V1 交付深度 Batch 01：客户购买 SaaS、Tenant 开通与组织权限 v0.1

> **Detailed Functional Scope / Draft — 本文件 22 项的“建议最小交付深度”与 SCOPE-152～159 均尚未获得产品负责人批准，不代表研发实施或真实 Issuer V1 冻结。** 2026-10-22。
>
> 依据：[已批准 SCOPE-143～151](../../decisions/SCOPE-143-151-AB-scope-comparison-and-v1-freeze-gates.md)、[正式 187 项范围基线](RWA-SaaS-Module-Function-Inventory-and-V1-Scope-Matrix-v0.1.md)、[六批交付深度路线](RWA-SaaS-Issuer-V1-Delivery-Depth-Batch-Review-Roadmap-v0.1.md)、[ARCH-001](../../decisions/ARCH-001-api-first-unified-business-core.md)。
>
> **批次定位**：从一个**购买 SaaS 的发行企业/机构**视角审核“签约→机构申请/商用审核→Tenant 配置→组织权限→访问发行工作台→暂停与退租”最小闭环。该客户是 SaaS 买方/发行机构，而不是该机构将来招募的投资者；公司有了 SaaS 账号也**不能自动真实发行证券/Token**。
>
> 本批涉及 **M01（8 项）、M02（8 项）、M03（6 项）共 22 个旧功能 ID：P0 17、P1 2、P2 3；既有优先级不变**。运营后台属于 SaaS 平台运营授权面，与客户的 Issuer 工作台必须严格分离。此稿**不设计真实信用卡/法币在线收费系统**，只要求商业合同与订购/授权闭环：在线自动订阅收费 M01-F008 仍 P2。

## 一、客户视角最小旅程与关键任务

| 步骤 | 用户角色 | 交互/动作 | 成功成果 | 必须阻断/区分的条件 |
|---|---|---|---|---|
| **01 了解/申请购买** | 潜在发行机构的联系人 | 产品介绍、申请/咨询、必要机构/联系人信息和授权同意 | 受控申请记录，可跟踪申请状态 | 申请者不能直接创建生产 Tenant |
| **02 商业合同与资料确认** | 客户商务联系人 + SaaS 运营 | 提交机构主体和必要文件，签约/购买意向及授权审核 | 合同/订购服务项目、可用期限与计划能力记录 | SaaS 商业授权≠发行资质、KYC、投资者准入 |
| **03 租户开通** | 平台受权运营 | 受权建 Tenant、分配当前能力和隔离空间、首次管理员 | Tenant 可登录、隔离配置且不重复开通 | 错机构归属、重复点击或创建中 Unknown 不重建租户 |
| **04 机构账号与组织** | Issuer 初始管理员 | 激活、成员邀请、组织结构、角色/项目访问范围 | 有权限的工作台及最小组织配置 | 不能跨 Tenant/Project 读写；高风险动作需分权 |
| **05 就绪/开始发行准备** | Issuer 产品业务人员 | 进入 Asset/Instrument/Project/Offering 的受权导航入口 | 后续 Batch 02/03 的业务资料编辑能力可见 | 登录成功、套餐许可和公司法定发行权是三层不同概念 |
| **06 暂停/恢复/终止** | 平台运营 + 合法客户管理员 | 暂停/恢复/退租和任务、数据、责任的受控交接 | 明确剩余可读/可执行范围、义务交接凭证 | 暂停不能默许新发行；也不能删除已售 Token/债权/合法股东权利 |

### 一个常见但不应该被忽略的产品问题

“客户购买 SaaS”在首期可通过**商务合同/离线收款/人工商业授权**完成，不以完善的在线自助支付系统为前提。**商业开通状态不能与金融发行资格状态合并**：购买成功只代表可进入授权工作台，实际 Offering Publish、真实稳定币付款、法律登记和 Token Mint 仍受后续独立 Gate。

## 二、逻辑页面/入口与最小 UI 规格（不是已冻结路由数）

| 界面组 | 入口与目标角色 | 最低可见字段/操作 | 建议首期边界 |
|---|---|---|---|
| **客户申请/咨询入口** | 发行机构联系人，登录前 | 机构/联系人、服务需求、必要知情/条款同意、提交结果/联系渠道 | 可与营销落地页共用表单，非 CRM 销售全自动 |
| **申请/订购状态** | 已申请客户、受权平台运营 | 申请编号、补件状态、服务/合同授权、有效时间和支持联系 | 不需要给用户自助选择 20 种计费方案 |
| **Tenant 首次设置/访问** | 获授权机构管理员 | 机构概况、Tenant 当前权限/套餐、工作台入口、邀请成员与必要材料提示 | 租户 Active ≠资产合法可发行 |
| **组织/成员/角色** | 租户管理员（受权限） | 成员、角色、邀请状态、项目访问范围、撤权和任务转交 | 最小权限模型，复杂自定义 RBAC 规则构建器可延后 |
| **运营审核/租户管理** | SaaS 平台运营（独立界面/授权域） | 待审申请、合同授权、Tenant 运行状态、开通/暂停/恢复/审计 | 操作员不能无限查看机构投资者敏感信息 |
| **退租/交接与支持** | Issuer 管理员 + 合法受权审核人 | 终止申请、未结权益义务提示、数据导出审批/完成、支持与异常升级 | 不默认全量 SLA 工单、CRM 与在线退费计算 |

**UI 成功口径**：角色只见受权记录，操作按钮隐藏与服务端硬性 Guard 并行；所有有不可逆影响的状态/审批与错误恢复可见。发行核心的资金/Token 审核条件由 Batch 02～06 继续定义，不在 Batch 01 用一个“已购买”标签模拟法律批准。

## 四、建议的领域命令与状态生命周期（产品级，不规定具体技术 URL）

**重要**：下列为逻辑命令与状态，不替换冻结第 04 份状态机、API schema、真实服务身份或合约模型；研发时必须以更高阶批准的正式规格映射。

| 领域对象 | 最少可执行命令（按角色/租户/权限审核） | 候选状态/要求 | 不可忽略的证据 |
|---|---|---|---|
| CommercialApplication | submit / requestMoreInfo / approveCommercial / reject | Submitted / InReview / MoreInfoRequired / CommercialApproved / Rejected | 提交版本、操作者、合同与补件历史 |
| CustomerContract/Entitlement | recordContract / grantCapabilities / expireOrRevoke | Draft / Active / Suspended / Expired | 商业签约或授权来源、有效期、明确许可功能/额度 |
| Tenant | provision / activate / suspend / resume / offboard | Provisioning / Active / Suspended / Offboarding / Closed；Unknown Provisioning 可查同一 intent | 唯一 tenant_id、配置/隔离验证及启动/中止授权 |
| Membership/Invitation | invite / accept / revoke / deactivate / transferTasks | Pending / Accepted / Expired / Revoked；Membership Active/Disabled | token 领取人和租户绑定、会话撤销、组织范围 |
| Permission/Approval | assignRole / restrictScope / requestApproval / approveOrReject | PendingReview / Approved / Rejected / Revoked | 职责分离、审批理由、受权人员和审计 |
| Exit/Handover | requestExit / reviewOutstandingObligations / approveTransfer / close | Requested / ObligationsPending / HandoverInProgress / Approved / Completed | 出口数据、义务承接人、合法授权、保留期限 |

**关系 Guard**：CommercialApproved 只能使租户获得合同内的软件使用权，不是 FinancialIssuanceApproved；Tenant Suspended 要阻断新增金融发行和未受权的新操作，但**已发生的债权/股份、实际资金、退款及法定通知/报表/权利移交义务不能静默取消**。Tenant Closed 只能在适用的出口/承接与保存义务审核完成后受权操作。

| **B01-07** | 客户申请终止，发行债权尚未到期 | 不允许抹去债权、股份、投资者权益和存续信息；受控数据/运营移交 | M01/M13/M20 |
| **B01-08** | 付费流程要求自动订阅/扣款但只上线人工授权 | 允许合法合同授权交付，标 M01-F008 P2 后置，不伪称在线自助收款成功 | M01 |
| **B01-09** | SPV 与集团母公司多法人关联 | 组织关系可审计，客户账号不能直接代表任一法律实体发行 | M02/M04 |
| **B01-10** | 初始管理员邀请链接过期/被另一个租户使用 | 按受权信息拒绝，审计/重新邀请；不提升错误账户权限 | M02 |
| **B01-11** | 停用成员旧会话持有有效 Token | 服务端验证实时权限版本/撤销状态，拒绝新业务命令 | M02 |
| **B01-12** | Tenant Admin 请求直接签链或认定资金已到账 | 无合法资金/链/法定签名授权则拒绝；Tenant Admin 不等于外部执行人 | M02/M07/M11 |
| **B01-13** | 成员尝试读取其他 Project/Offering | 禁止跨业务范围数据访问，必要时不透露对象是否存在 | M02 |
| **B01-14** | 同一人提交并批准高度敏感的发行指令 | 高风险职责分离 Guard 拒绝；保留请求、审批和追责 | M02/M19/M20 |
| **B01-15** | 审核员停用而工单仍 Pending | 任务可审计重派；停用者不得继续审批 | M02/M17 |
| **B01-16** | 客户要求 SSO 但当前非默认上线 | 高级组织集成单独版本门；基础认证/权限不因其缺席而不合规地降级 | M02 |
| **B01-17** | 商务申请处于补件，运营误点通过 | 状态/证据 Guard 阻断，审批撤销留痕 | M03 |
| **B01-18** | 运营试图重启已存在金融风险暂停的 Tenant | 需有法定/风险解除证据和独立权限，不得覆盖金融风险标记 | M03/M19 |
