# RWA SaaS V1.0｜Issuer 订单、资金和自动退款产品增量（V/M 审核衔接）

> 2026-11-24｜本文件仅记录本轮已批准的投资者端简化对 Issuer SaaS、M10/M11/M12/M17 的影响。历史 Issuer 产品/UI PRD、DEC、Frozen 与代码原件不变；真实合约退款需单独合规/安全准入。关联：[V/M 共用 PRD](V-M-SHARED-UI-READY-PRD-v0.1.md) / [跨端收口](CROSS-PLATFORM-CONSISTENCY-AND-ACCEPTANCE-v0.1.md)。

## 1. 业务变化与保留功能

- **投资者端移除**：V/M 用户主动取消有效认购订单、自助退款申请表、金额与退款钱包自选、“手动确认付款成功”。
- **核心金融域保留**：M10 待付款有效期和安全过期、唯一订单/限额，M11 实际付款/退款/受权审批/出款/核验，M12 预留/配售/法定登记，M07 Token，M17 异常调查。只删用户自助入口，不删金融责任。
- **Issuer SaaS**：投资者与认购 → 认购订单继续只读显示当前企业订单与真实业务细分状态；资金与结算 → 收款与对账、退款与异常继续按真实授权支持调查/提交凭证/合规退款。一个 SaaS 企业管理员账号不自动取得资金出款、合法登记或 Mint 权。
- **P-07**：只接收归平台责任或被正式指派的 V/M 工单，能分派、回复、升级、查原业务受权摘要；P-17 处理 M 渠道 Listing 投诉，但两者不接管资金主账。

## 2. 支付及自动退款状态契约

支付主路径：投资者钱包 → 已准入 Offering 专用收款合约（OP Mainnet USDT）→ M11 FinalMatched → 合法配售/登记 → Token 确认交付；Issuer 的最终企业结算钱包不是投资者付款地址。

| 真实情况 | 显示/处置 | 严禁 |
|---|---|---|
| 未发起链上付款且有效期届满 | M10/M12 权威确认无在途后自动过期并安全释放占用 | 让投资者主动取消/盲释放 Unknown 额度 |
| 钱包拒签、Gas/USDT 不足 | 付款未发起或失败，保留订单记录 | 生造退款事实 |
| 合约一笔交易原子回滚 | USDT 未完成转账，无须单独退款；Gas 可能已耗 | 宣称 USDT 已退款 |
| 真实链上交易已广播、结果 Unknown | 查询原 TX、原付款操作，保留订单与额度保护 | 自动过期释放/重复扣款 |
| 已真实到账但未最终匹配 | 资金待核验，不显示“已完成认购” | 把 TX 哈希视为配售凭证 |
| 已收款、业务后续失败 | 仅合同/合约明定且符合受益人、余额、授权、幂等条件时自动退款；否则人工处理 | 承诺任何失败合约必然退回 |
| 自动退款交易已提交但 Unknown | 保留原 Refund Intent，查询原结果，必要时转有权调查 | 用新付款操作盲重试 |
| 少付、多付、错链、迟到账、重复资金事件 | 关联原订单与 M11 资金异常；转受权调查/退款 | 自动记作有效认购或无限额出款 |
| 已登记/Token 生效权益需退出 | 按 M13 合同退出、清退、到期/收益流程办理 | 用“退款”撤销法律权益 |

自动退款**生产 Gate**：适用合同与可退条件、合法受益人/目标地址核验、合约可用资金与金额限制、收费规则、合约授权和安全审计、链最终性、操作幂等/防重入/防重放。任何一项未批准，产品只显示“待核/转人工”，不能凭 Mock 声称自动退款。

## 3. Issuer 订单与资金 UI 增量

I 订单列表仍显示订单号、Offering、脱敏投资者、固定份数/单价/金额、业务状态、付款、登记、Token、异常与更新时间。订单的“已取消”只读兼容有权历史取消决定或状态，不表示投资者 V1 有取消按钮；Issuer 不应代用户改金融状态。

订单详情新增关联支持工单视图：工单号、来源 V/M、所属 Issuer、原订单/付款/退款引用、脱敏问题摘要、责任队列、工单状态、最新回复时间、查看原资金/Token/收益事实入口。无权时仅能提交复核/凭证或联系支持。

I 资金与结算 → 退款与异常保留：真实入账金额、依据与申请、合法受益人/退款目标核验、授权审批、Refund Intent、部分支付、Unknown、实际到账及完整证据。自动合约退款与人工受权退款都写同一 M11 退款领域权威主账，区别仅发起方式和批准证据。失败并不等于已退款，已批准不等于已实付，退款操作发起不等于已到账。

V/M“我的订单”只读退款进度必须引用此原资金记录，不另建第二本账；已过期但之后观测到款项，需要保留资金调查支线而不能抹除。

## 4. 投资者工单至业务责任方

投资者在 V/M 订单/持仓/收益/KYC/钱包点击帮助→新建关联 Ticket（账户 scope、订单/事件 ID、问题类别、说明、可选安全附件）→ M17 按最小权限匹配责任方：
- Issuer 订单、收款、配售、登记、Token、收益：进入本企业 I 受权业务域或有权外部服务方；
- M 渠道、M 账户、平台 Provider 故障、公共通知：进入 P-07/P-17/P-18/P-13 受权队列；
- 混合异常 P 可做沟通协作，但不能自动获得 Issuer 资金执行权。

处理可用“受理、分派、请求补件、追加记录、公开回复、升级、关闭”，必须显示原业务事实。**工单已解决不等于链上退款、Token 交付、法定登记或债权本息已完成**。重复事件、重复回调关联同一业务主键与工单，不重发资金操作。账户降级/退租后历史合法履约工单仍可按授权查询。

## 5. 设计验收目标（未执行）

| 用例 | 通过条件 |
|---|---|
| 用户查看待付款订单 | 没有主动取消、手动申请退款按钮 |
| 待付款超期但链 TX 结果 Unknown | 不强制释放额度，先查询原交易 |
| 链 TX Revert | 未真实收款，不生成伪退款 |
| 已收款后 Mint 失败 | 资金待核或受权自动退款/人工处理，不假称完成 |
| Refund Intent Unknown | 不重复出款、保留金额占用和原证据 |
| 用户工单分配至 I/P | 责任与读权限正确，财务真实事实不被工单篡改 |
| P 工单关闭但 M11 未退款 | 投资者仍可看真实退款待核状态 |
| Issuer 退租/降级 | 既有款项、法定权益与未结义务、工单历史继续受控保留 |

**此处仅收口产品契约，不授权开发或真实链上部署。**
