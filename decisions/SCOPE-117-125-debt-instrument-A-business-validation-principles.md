## 一、九项已批准的产品原则

| 决策 | 已批准结论 | 不应误读为 |
|---|---|---|
| **SCOPE-117** | 样本 A 采用**债务主体依据合法债权文件承担固定利息、明确到期本金偿还义务**的债权 Instrument；权利依合同与适用权威登记判断。 | 不代表 Token 自动产生债权、抵押权或底层实物所有权；不默认有担保、某类证券发行许可。 |
| **SCOPE-118** | 产品级主验证先采用 **A1 同一 Series/统一到期日和付息日**；必须审查不同认购时间的应计利息、价格、记录日与剩余期限。A2 各购买批次独立起息/到期保留作对照，**不默认加入 V1 全量交付**。如法律/合同强制集中募集则依 SCOPE-078。 | 不代表 A1 允许在全球以固定票面价无差别持续销售，或已认可任何具体价格/收益公式。 |
| **SCOPE-119** | 明确名义本金/总额度、Series、固定利率、计息日数基准、起息/付息/到期、票息权利、权限与版本、登记、赎回/转让条款的**最低权利参数组**，与 Token 单位及实付币种分离。 | 不等于数据库、链上合约字段或最终法定合同模板已被冻结。 |
| **SCOPE-120** | Offering 正式发布前必须核对债权合法权利及文件、适用专业意见、发行权限、合法收款/退款/登记/签署/Token 权限、资格/限额与自动配售 Guard；已批准版本变更不得静默影响在途订单。 | 平台审核标记不等于发行监管许可或正式法律意见。 |
| **SCOPE-121** | 沿用 WF-06～10 既有 KYC 与 Offering 资格、条款/价格快照、原子预留、**真实 USDT/USDC 链上资金**及对账、事前受权规则配售；债权增加晚入场价格/应计利息、本金面额与 Token 精度核验。 | 不把报价、资金广播或付款确认自动等同债权交割成功。 |
| **SCOPE-122** | M11 付款和对账、M12 受权配售和权威债权持有人登记、M07 真实 Token Mint/交付保持**独立权威事实**，遵循 Instrument 合法顺序及外部执行 Unknown 查询，禁盲目重复 Mint。 | 不规定所有法域必须先登记后 Mint，亦不允许提前显示“购买完成”。 |
| **SCOPE-123** | 固定票息及到期本金须按 M13 的**权益快照→核算→复核批准→受权实际支付→对账**形成完整产品业务设计；债务解除、登记注销及 Token Burn/冻结应依法确定各自顺序，适用逾期/违约与合法通知路径。 | 不假设 SaaS 控制付息钱包、不把计算完成当作付款完成，也不把 Burn 当作债务已清偿。 |
| **SCOPE-124** | 少付/多付、错误链、迟到付款、并发额度、登记与 Token 不一致、本金已付而 Burn 失败、收益权利争议、到期付款 Unknown 等须有不可覆盖证据和受控恢复路径。 | 不允许运营人员勾选就伪造到账、登记、权益、付款或执行结果。 |
| **SCOPE-125** | 本批批准**产品案例与需求级验证原则**；样本 A 的 A-T01～T16 验收卡与 A/B 187 项底表均未执行，V1 真实逐项交付、权限、法域、债务工具法律效力、适格机构、开发与生产授权继续待定。 | 不构成测试 PASS、工程实施指令、产品范围冻结、PR #6 合并许可。 |

## 二、验证路径与关键未决项

- 目标主线：A1 一笔法律有效的债务 Series 可以在已批准方式下多次认购，但**晚入场者价格、票息权益、剩余期限和合同有效性必须先明确**。A2 仅作产品对照，不自动变成真实首期商业支持。
- 需另行选择并验证：计息日数法、起息/付息日、发行价格与应计利息/溢折价规则、record date 与 ex-coupon 规则、非营业日调整、部分本金提前偿还、税费/舍入/最小单位、债务人/受托方/登记方/偿付方及法律优先顺序。
- A-T01～T16 为产品测试用例**设计**，不是已执行的 E2E；其状态均为 **Not Executed**。A/B 187 项功能验证底表继续 **Not Tested**。
- 具体法域与真实 Instrument 法律结构、收款/退款/兑付责任、Token 标准与链、签名/权威登记主体、White-label/商用 Open API 里程碑仍待独立决策。
- 继续保持第 02～04 份冻结原则及原 187 项 ID/等级不变。参考 SCOPE-080，A 样本的 M13-F004～F006 在**固定票息/到期还本需求级**构成最低必要能力判断，但**不擅自提升原 P1 为 P0、不得据此自动冻结真实实现深度**。
