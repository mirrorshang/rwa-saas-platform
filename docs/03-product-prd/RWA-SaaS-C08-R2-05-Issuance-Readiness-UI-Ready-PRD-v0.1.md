## 1. 产品目标、MVP边界与交付定义

### 1.1 用户目标

已完成Asset/Instrument/Project/Offering的Issuer企业用户，在**同一个发行准备页面**核对系统自动检查、修复缺项、预览投资者可见信息、作出本人企业责任声明，点击一次**「确认并发起发行」**。系统创建唯一且可追踪的执行任务，并按Sandbox或已批准生产执行条件分流。Offering正式发布、M平台渠道上架和投资者购买/Mint是**相互独立的业务结果**。

### 1.2 复用上游对象，禁止重复建账

- 每个Offering引用一个Project、一个Asset和一个明确Instrument Version；一个Instrument对应一个逻辑Token，多轮Offering复用Token身份。
- Offering Confirmed前已经按R2-04完成一次权益池最大量预留；发行准备不得再产生第二笔权益预留。
- 金额以U显示，1 U = 1 USDT；V1投资者真实支付只支持OP Mainnet USDT。支付链网络**不等于**Token发行合约网络。
- MVP单一企业操作账号，无内部角色审批、多人复核或企业Offering资格设置。
- Issuer没有逐轮投资者白名单、分类、法域列表或人工资格准入配置。投资者KYC**通过且有效**即取得MVP基础认购资格；必要AML/制裁/法域适格性及其他生产强制规则继续独立拦截。
- 法律文件提交与扫描完成**不等于**证明真实权属或法定发行获准；平台提供完整性/技术门和自身渠道准入，Issuer负责其法律事实。

### 1.3 页面范围（最小实用）

| 页面/区域 | 角色/入口 | MVP必须承载 |
|---|---|---|
| 发行准备主页面 | Issuer「资产与发行 > 发行准备」或Confirmed Offering详情 | 七组检查、修复入口、投资者预览、责任声明、最终确认、执行任务状态 |
| Offering详情 | Issuer发行方案详情 | 发行准备入口、发布结果、合同/Token核验摘要、M渠道上架申请及状态 |
| 统一投资端上架申请轻量交互 | Issuer Offering已正式发布 | 自愿申请、本轮已发布快照引用、申请结果；不重复录入资产、权益或发行参数 |
| M渠道审核最小入口 | P运营后台受授权入口（后续该端UI开发批次实现） | 申请列表/详情、渠道准入检查、通过/拒绝/暂停与原因、审计；不能替代法律发行审批 |
| M/V合法展示与认购入口 | M统一投资端 / V企业独立门户（各端单独实施） | 仅消费本轮Offering与渠道可见、窗口、KYC/合规守卫；不复制订单资金分配账 |

这里Issuer端R2-05的UI-Ready不代表M/V/P端所有独立页面已完成开发；本文件明确双方所需接口事实和最低产品验收。

## 2. 发行准备主页面：信息架构和常规操作

### 2.1 主界面布局

1. **页头/面包屑**：资产与发行 / 发行准备 / Offering名称及系统轮次编号；提供返回Offering详情。
2. **当前发行摘要**：Project、Asset名称/物业类型、Instrument类型和Version、逻辑Token名称/Symbol、权益量/单位、Token计划最大量、固定单价(U/Token)、最大募资(U)、开始/结束时间及明确时区、环境Sandbox/Standard。
3. **七组自动检查**：显示分组标题、当前状态、具体失败/缺失原因、权威来源时间、回源操作与“重新检查”；不可由企业人工标记PASS。
4. **投资者页面预览**：显示当前被授权披露的Asset/Instrument/Offering/风险/Token/法律文件及购买条件；敏感内部文件默认不展示。
5. **责任声明**：经适法法律审查后生效的声明文本及版本、未预勾选的明确同意选项。
6. **最终动作区**：按钮「确认并发起发行」；必要时「查看问题」「重新检查」。执行任务存在后显示任务进度与可操作修复入口，不显示再次发起相同生产动作的按钮。

### 2.2 页面与字段职责

| 字段/信息 | UI性质 | 权威来源/校验 |
|---|---|---|
| Issuer Tenant及发行环境 | 只读 | M01 Tenant/订阅、安全和平台Gate |
| Asset ID、名称、版本、状态 | 只读/详情跳转 | Asset唯一权威记录；Restricted/Archived禁止正式发布 |
| Instrument ID、类型、版本、状态 | 只读/详情跳转 | Instrument唯一权威与法定权利文书 |
| Project、Offering ID和版本 | 只读 | R2-04唯一关联；不能跨Tenant或跨Asset |
| 权益授权/有效预留/确认分配/剩余量 | 只读 | R2-03容量池，不重复预留 |
| Token逻辑身份、固定映射、最大供应/本轮最大量 | 只读 | R2-03和R2-04，不能在发行准备更换Token、Symbol或映射 |
| Token固定单价、最大募集额、认购窗口/限额 | 只读 | Offering Confirmed版本；改变须回源并重新检查 |
| 合约部署网络、标准、地址/Token ID及验证结果 | 技术状态与条件性展示 | 未批准时显示“待技术确认”，真实链上核验完成才标已部署 |
| 投资者可见法律文件/版本 | 文件预览入口 | 文件版本、扫描与受权披露结果，不允许深链越权 |
| 检查结果与时间 | 系统生成 | 每次基于权威来源及引用版本；变更即失效 |
| 声明文本与确认事实 | 用户明确同意 | 未勾选为未确认，保存声明版本、账号、时间及数据快照引用 |
| 执行任务及Publication Snapshot | 系统创建与只读查询 | 幂等任务ID，发布成功才产生对外快照 |

### 2.3 按钮、反馈与弹窗

| 操作 | 前置条件 | 成功行为 | 异常/提示 |
|---|---|---|---|
| 查看检查详情 | 当前有检查记录 | 展开当前权威结论、原因及目标对象 | Unknown显示服务错误及最近核验时间 |
| 去补充/去修改 | 当前问题对应Asset、Instrument、Offering或企业资料 | 跳对应详情/编辑，保留Offering上下文 | 无权限/对象异常要给出清楚原因，禁止跳错Tenant |
| 重新检查 | 发行准备可读 | 重新获取当前权威事实、更新检查状态及检查版本 | 不用旧PASS代替新结果；网络超时标Unknown |
| 投资者页面预览 | 合法披露版本存在 | 在隔离的预览视图显示即将披露的信息和文件 | 不公开未发布Offering；内部文件不泄露 |
| 勾选责任声明 | 已显示适用版本文本 | 当前用户确认当前版本声明 | 默认未勾选；声明版本变化要求重读重勾 |
| 确认并发起发行 | 所有适用检查PASS、声明已确认、Offering Confirmed、当前版本一致 | 服务端原子/幂等生成唯一发行执行任务，返回任务进度 | 守卫变更、权限、Pending/Blocked/Unknown拒绝，不提示“部署成功” |
| 查看发行执行结果 | 执行任务存在 | 展示步骤/最近状态/原始任务号与修复入口 | Unknown优先查询原任务/Tx，禁止用户重复创建同类任务 |
| 申请上架统一投资端 | Offering Published/适用渠道条件满足 | 创建该轮M渠道申请，展示待P审核状态 | 不默认为渠道已上架；未发布拒绝或引导完成发布 |

本MVP不提供重复的内部“提交审核→部门复核→领导批准”步骤。发布动作本身也必须与合法网络及相关服务生产执行权限分开。

## 3. 七组检查的通过/待补/阻断/Unknown判定

### 3.1 检查统一模型

每个检查项都需要：业务来源、适用环境、当前引用版本/时间、结果（PASS/PENDING/BLOCKED/UNKNOWN）、用户可读原因、回源对象及下一步操作。不可在前端持久化一份伪权威PASS。

- **PASS**：权威事实和当前引用版本满足要求；具备该项继续条件。
- **PENDING（待补）**：有具体可修复资料/声明缺项；需回源完善。
- **BLOCKED（阻断）**：权限、状态、容量、强制法律/风险或生产Gate禁止当前真实动作。
- **UNKNOWN（暂无法核实）**：外部服务超时、无法核验、原任务未确认；**Fail-Closed**。

某项依法/按产品环境确实不适用，系统须保存来源与原因的“不适用”判断，不得由Issuer自行切换为PASS或跳过；七个分组的汇总结果不能以某个子项Unknown仍显示通过。

### 3.2 七个检查组

| 组别 | PASS所需的关键事实 | PENDING示例 | BLOCKED/UNKNOWN示例 |
|---|---|---|---|
| 01 企业与发行环境 | 相关Tenant/账号授权、环境与订阅条件符合当前Sandbox/生产路径，生产必要KYB和法域许可适用性得到权威确认 | 企业基本资料缺项 | 真实发布仅Free、KYB拒绝/失效、法域未许可；生产准入服务超时Unknown |
| 02 Asset与文件 | Asset状态有效、房地产模板必需资料完整、需用文件已上传/扫描合格/版本引用有效且披露许可匹配 | Asset字段/文件缺失 | Asset Restricted/Archived、文件扫描有风险、敏感文件越权；扫描查询Unknown |
| 03 Instrument及容量 | Instrument可用、基础权利/法律文件/Token映射有效、权益总容量和Offering预留一致 | 权益文件缺失 | Instrument Suspended/Terminated、映射不精确或容量超限、容量查询Unknown |
| 04 Offering方案 | Confirmed、Project/Asset/Instrument版本一致、固定价、数量、窗口、最低/累计限额及有效预留全部有效 | 必须改回Offering修复的基础缺项 | 版本冲突、Offering未确认、预留失效、非法映射、窗口错误、并发同轮冲突 |
| 05 投资者展示/准入机制 | KYC和必要AML/制裁与法域阻断机制可用、公开披露文件版本完整、投资者预览合法 | 披露摘要/文件缺失 | 强制风险机制不可用、资料超出合法披露范围或区域准入失败；外部查询Unknown |
| 06 支付及Token技术准备 | 对真实发布所需的OP Mainnet USDT受权支付、Provider/Signer/合约网络/合法文书绑定及链技术Gate均经实际准入确认；Sandbox只检查可模拟路径 | 某适用技术资料待配置，仍为待补 | 真实执行所需Signer/Provider/合约/网络未批准、链结论Unknown或合法性不符；不可以模拟代替生产PASS |
| 07 企业最终声明 | 有权单一企业账号明示同意适用且未变化的声明版本，保存账户与关键对象快照 | 尚未勾选/需重新确认 | 声明版本冲突、账号无权、签署/责任所需法定条件未满足 |

**特别校验**：第05组不要求发布前已有任何通过KYC的投资者。KYC是后续认购条件，而不是Issuer需预先审批每个用户的发行准备任务。若某法域存在法定投资者适格要求且当前MVP不能实现，应阻止该真实Offering的开放/认购，不得以KYC取代法律要求。

### 3.3 修复与重新检查逻辑

- 修改Asset、Instrument、Offering、文件、Token映射、生产服务授权或相关法域信息时，将受影响组的上次PASS标为失效，重新从权威服务核对。
- 已确认Offering核心参数若需更改，应按R2-04撤销/版本化规则处理；已有下游订单不允许原地覆盖。
- 提交最终发行任务的瞬间由服务端再次比较检查版本/对象版本/权益预留，并拒绝竞态下失效的结果。
- 不能把外部HTTP成功、任务排队、合同上传成功、交易广播视为法律/支付/链执行最终成功。
- 网络断开保留用户当前页面和已确认业务事实，显示哪些请求真实提交、哪些结果待查询，不盲目重放不可逆动作。

## 4. 最终企业责任声明与发行任务

### 4.1 责任声明行为

- 展示当前Offering所适用的已获准声明文本版本（文案合法性在法律Gate前为Draft，不在本PRD自拟可投入真实金融发行的合同条款）。
- 用户必须主动阅读与勾选；默认未选。变更声明或相关法律版本需要重新确认。
- 系统持久化：Issuer账号ID、Tenant ID、Offering ID/Version、Asset/Instrument/必要文件快照、声明版本、用户确认时间、环境、操作ID/审计事实。
- 一个账号不等于免除任何外部强制法定批准/专业核验。

### 4.2 发行执行任务

点击「确认并发起发行」成功后创建独立的**Issuance Execution Task**（产品概念，具体schema由工程评审）：
- 任务与Offering ID和指定业务版本关联，唯一幂等键防双击/重试；
- 记录当前环境、最新七组检查引用、企业声明、创建时间及执行状态；
- Free Sandbox走模拟服务，Standard路径依独立生产Gate及合法技术方案调度；
- 后端返回“已提交/待准入/执行中/异常/核验通过”等用户可理解事实；**请求受理不等于合约已部署或Offering已发布**；
- 原执行结果Unknown时必须使用原任务/Intent/链交易标识查询并核对，不另建无法关联的新部署命令。

### 4.3 Sandbox与Standard对比

| 业务事实 | Free Sandbox | Standard且已获相应生产准入 |
|---|---|---|
| 检查页/版本快照/企业确认 | 支持模拟和留存必要Mock | 基于真实业务权威和合法文件 |
| 合约部署 | **仅模拟记录**，禁止真实链操作 | 仅调用获准Provider/Signer/网络，结果核验成功后入账 |
| Offering发布 | Sandbox内部模拟发布 | 满足所有适用发布Gate后正式建立Published快照 |
| M统一投资端 | 仅隔离模拟预览，不进入真实公开M目录 | Issuer主动申请、P审核通过后才进入M合法展示 |
| 投资者认购/资金 | 仅模拟 | KYC、风险、合同、订单及OP Mainnet USDT真实收款守卫 |
| Token Mint/持仓 | 仅模拟Token和持仓 | 由已确认分配/合法交割/Signer/链最终性决定 |

**Standard订阅不自动开启真实发行；尚未配置真实生产技术能力时本PRD允许完整Sandbox演示，但生产动作必须禁用并解释原因。**

## 5. 发行合约部署或复用：产品要求与未决技术门

### 5.1 Token和Contract身份

- 每个Instrument对应一个逻辑Token。多轮Offering引用同一Token身份，不因每轮重新创建新Token或新合约。
- V1“一个生产主合约”是产品批准的架构目标；主合约如何区分不同Instrument的逻辑Token、合约标准、Token ID/地址模式、Decimals、升级及权限必须由安全/技术与法律共同决定。
- Issuer只读看到系统所采用的已批准合约配置与状态，不自行选择网络、标准、Decimals和Signer。
- 合约部署状态、Offering发布状态、Token Mint状态不能折叠为一个“发行成功”布尔值。

### 5.2 受控执行与结果

| 情况 | 产品处理 |
|---|---|
| 已有获准且仍有效的Contract实例 | 核对版本、Instrument/Token身份和受权范围后复用，不重复部署 |
| 首次需要部署/注册逻辑Token | 仅当独立Gate批准时创建受控部署/注册Intent，并核验实际链事实 |
| 部署请求已提交但未达最终性 | 显示进行中/待核实，不显示已部署 |
| 部署失败 | 原任务留痕、展示失败原因与可操作修复；不自动发布 |
| 部署Unknown、链重组或Provider超时 | 查询原意图与链交易，禁止盲重部署或生成双合约 |
| 合约地址需绑定法定文书 | 按具体Instrument/法域受控完成合法绑定或必要重签，再判断发布条件 |

不得在本产品PRD中默认所有法域统一“先部署→再签署→再发布”的硬编码顺序。必须以实际法域、合同及技术生产门决定。

## 6. Offering正式发布与投资者展示快照

### 6.1 Published进入条件

- 发行准备适用七组检查通过，企业最终声明和唯一执行任务有效；
- 需要的Asset/Instrument/Offering/法律文件、容量及固定Token映射版本一致；
- 适用的合约/Token技术事实及实际合约地址法律绑定达到必要条件；
- 无平台合规、法域、资金或技术风险阻断；
- 正式发布操作由有权调用方执行且记录Publication Snapshot。

**只有状态权威服务确认发布成功**，Offering才进入Published。企业点击最终确认、生成执行任务、完成合约部署或签署都不代表已经Published。

### 6.2 发布与认购的状态关系

| Offering阶段 | 可披露 | 可新认购 |
|---|---|---|
| Draft / Confirmed | 非公开；仅授权的Issuer内部或合法私有预览 | 否 |
| Published但窗口未开始 | 依法且经渠道授权可查看 | 否 |
| Active且无暂停/风险阻断 | 依法且经渠道授权可查看 | 仅符合KYC与强制守卫、限额/额度的投资者 |
| Paused/Blocked | 按适用披露许可保留必要信息或限制可见 | 否 |
| Ended/Settling/Completed | 按合法授权保留历史/披露/订单信息 | 否；已发生订单继续处理 |

重要：暂停为主生命周期上的附加阻断；不能用“下架”动作抹掉已发生的收款、配售、法定登记或Token权利。

### 6.3 Publication Snapshot与重大变更

正式发布记录当时合法可披露的Asset、Instrument、Offering、Token、权益经济条件、风险文件及实际生效的合同地址引用；后续变更生成新版本和影响检查，不得直接改写原报价、订单、签署、支付、法定名册和Token历史。受影响时可以暂停新认购，按适用法律重新披露、通知或重新签署。

## 7. M统一投资端上架申请与P审核：跨端契约

### 7.1 Issuer自愿申请上架

- **每轮Offering独立申请M**，不因本轮Published而自动上架，也不要求所有Issuer都使用M。
- 只有已正式Published且满足申请入口条件才可提交；系统直接引用Publication Snapshot与受控披露版本，不重复要求Asset/Instrument/Offering资料输入。
- 申请结果至少区分：未申请、待P审核、批准、拒绝、暂停/下架，记录原因、版本、申请时间与操作人。
- Issuer自有投资者门户V是独立渠道；不申请M或P拒绝M，不自动撤销Issuer自身合法发布。

### 7.2 P运营后台渠道审核

P需要查看的最小必要资料为：Offering及Issuer身份、渠道展示用披露快照、资产权利/风险说明、文件许可、法域与平台渠道商业/监管准入结果，以及以前拒绝/暂停的审核记录。

M渠道审核动作包括：批准、拒绝（必须给原因）、暂停/下架（原因和必要审计）、必要的重新申请/复核。**P审核的是自身渠道展示、招揽、订单受理/路由的准入，不能借渠道批准代替Issuer金融发行、合法配售、资金托管或Signer授权。**

### 7.3 M与V数据及账户隔离

- M统一账户可按获授权资料浏览多IssuerOffering；V保留Issuer独立门户。
- M/V消费共同M05 Offering、M10订单、M11资金、M12配售/法定登记、M07 Token及M09 KYC/强制风险等唯一业务权威。
- 不得因为M/V两渠道产生两份订单、两套收款地址、两套权益容量或两个Token主账。
- M渠道已批准才允许合法范围的列表/搜索/详情展示；未发布、未批准、跨Tenant或未受权的Offering不得通过直链泄露。
- M渠道批准≠投资者可购买；下单前仍检查KYC有效、AML/制裁/法域合法、销售窗口、必要文件/签署、单笔/累计限额、订单及容量。

### 7.4 渠道上架失败与整体Offering暂停

| 事件 | 正确业务处理 |
|---|---|
| P拒绝M上架 | 向Issuer展示拒绝原因、允许按规则修复/重新申请；Offering本身仍按合法状态运行 |
| M渠道临时暂停/下架 | 禁止M渠道新访问或认购，保留历史及在途记录；不默认暂停V门户 |
| Offering强制风险暂停 | 根据统一权威风险守卫阻止所有相应渠道新认购；M/V均反映状态 |
| M审批服务Unknown | M暂不得显示为审核通过；请求保持待核，不重复提交相同申请 |

## 8. 投资者认购、配售、Token与持仓的交接

### 8.1 认购与交付主线

`合法可见Offering → 注册/KYC通过且有效 → 适用AML/法域/销售窗口/额度检查 → 报价与必要文书 → 订单与有效预留 → OP Mainnet USDT付款 → 权威实收确认 → 配售/权益确认 → 依法必要登记 → 受控Mint与链最终性核验 → 合法持仓展示`

具体签署、登记与Mint的法律顺序由Instrument适用法域决定，不能强制所有资产同一顺序。

### 8.2 四套权威事实分离

| 事实 | 权威系统 | 禁止错误 |
|---|---|---|
| 认购订单和报价/签署 | M10/M06 | 点击购买或生成订单就显示付款成功 |
| 钱款、匹配与退款 | M11及合法持款主体 | 广播Tx/观察到账就认为已最终收妥 |
| 权益容量、配售和法定登记 | M12及有权登记者 | Mint成功推导法定登记或提前释放权益池 |
| Token部署/Mint及链终局 | M07/经批准Signer与链证据 | 按计划最大量一次性Mint；Unknown盲重试 |

投资者钱包绑定和合法持有人资格分别管理；付款来源地址、Token接收钱包及法定持有人不必同一，但必须满足适用授权与安全守卫。

### 8.3 用户看到的分段状态

订单已创建、待支付、真实到账待核、已确认收款待配售、权益已确认待登记或Mint、Token已核验、必要交割完成等要分别展示。资金已到但Mint失败不能删除钱款及分配记录；Mint成功但登记结果Unknown不能宣称完整法律权益交付。

## 9. 失败、Unknown、并发和安全保护

| 场景 | 系统必须保证 |
|---|---|
| 七组检查任一PENDING/BLOCKED/UNKNOWN | 禁止不符合条件的真实发布；明确来源与修复入口 |
| 点击确认后断网/双击 | 以唯一业务Intent查询原执行任务，不得重复执行部署/发布 |
| 关键文件/Instrument版本变化 | 作废受影响检查、重新核验；不覆盖原法律快照 |
| 合约部署结果Unknown | 查询原Provider/交易，保留任务和合约引用锁，不重复部署 |
| 合约标准/网络/Signer未获生产批准 | 显示待技术/法律准入；不暴露真实执行接口 |
| 公开Offering发布失败 | 保留Confirmed和任务失败/Unknown事实，不谎称Published |
| 发行已发布但M申请被拒 | 仅M渠道不展示，不自动撤销Offering或V门户 |
| M批准但Offering已Paused/Ended | 按Offer窗口和强制阻断禁新认购 |
| KYC只是已提交或已过期 | 不可认购；不提供Issuer人工覆盖 |
| 真实收款/支付最终性Unknown | 保护原订单与预留，不自动配售或退款 |
| Token Mint失败/Unknown | 保留已确认分配/法定登记，按原MintIntent核对，不能重复Mint或显示完整交割 |
| 订单取消/过期/退款 | 只有权威事件确认后可释放可复用额度；不得重复扣Instrument容量 |
| 修改Offering价格或风险文件 | 保留旧Quote、订单、披露/签署快照，必要时暂停与重新确认 |
| Tenant/渠道/内部文件越权 | 服务端拒绝，不能依靠隐藏前端按钮替代鉴权 |

## 10. UI可运行原型与端到端验收

### 10.1 Issuer Web UI

- 保持原高端深色Web3品牌与现有九个一级导航框架，二级「资产与发行 > 资产管理/权益结构/项目管理/发行方案/发行准备」一致。
- 发行准备为单页；七组检查状态可读且支持定位，不建设企业内部审批步骤、额外KYC筛选、Token任意配置页。
- 1440px与1280px可正常浏览，表格仅局部滚动，不能页面级溢出；确认/暂停/错误等状态文案必须清楚。
- Free/Sandbox模拟结果显著标识，真实Provider/Signer/法域Gate未批准时生产按钮禁用且有原因。

### 10.2 最低验收用例

1. Confirmed Offering进入发行准备时七组来源、对象关联、版本、摘要正确；Draft不能绕过确认。
2. 检查PASS/PENDING/BLOCKED/UNKNOWN四种状态正确；Issuer不能手动改PASS；失败提供回源修复入口。
3. Asset字段、Instrument版本、Offering容量、文件、外部服务变化后受影响检查失效并重新核验。
4. 预览只显示合法授权披露字段和文件；未发布不能凭直链打开正式投资端详情。
5. 无责任声明、声明版本变化、不同Tenant账号或七组未过不能确认发起。
6. 重复点击、断网恢复与重复请求只产生**一个**逻辑发行任务，原任务可查询。
7. Free Sandbox可模拟发布/认购/Mint视图，但无真实链部署、收款或法定权益。
8. Standard但生产Gate未批准：无真实发布、Deploy、Mint；展示具体阻断信息。
9. Contract已有可复用实例时按准入复用，不每轮部署；首次部署Unknown查询原Intent。
10. Offering Confirmed、任务已创建、Contract已部署、Offering Published、M上架批准、投资者Mint分别显示。
11. Offering Published未开售可依法展示但不能下单；时间到与风险守卫正确影响Active与暂停。
12. Issuer选择是否申请M上架；申请被P拒绝、批准或下架只影响M渠道，不覆写Offering及V状态。
13. M/V对同一订单、资金/配售/Token引用统一权威，权限/可见性受控。
14. KYC通过自动MVP基础资格，无Issuer Offering单独名单或审核；法定强制限制阻断时不可下单。
15. 真实支付模拟用Mock权威分段确认，不由页面直接标“已收款”；配售、登记、Mint分段显示。
16. Mint失败/Unknown不抹除已确认分配，不能双Mint；订单Unknown不提前释放额度。
17. 版本快照、操作人、声明版本、时间和重要状态变更可查，不覆盖历史。
18. 运营P渠道审核只提供渠道准入，不能直接替Issuer批准金融发行/资金/Signer行为。
19. 页面/导航/空态/无权限/网络失败/条件变更/并发/重复点击/历史回归在本地浏览器实际测试。
20. Build、Test、Route、交互、截图与Edge Case必须有可复验测试证据，不能只接受“PASS/DONE”字样。

### 10.3 推荐开发切片（非全系统同时开工）

1. 沿现有C07/C08 Issuer框架接入Confirmed Offering的发行准备单页与七组Mock检查；

3. 接入Offering状态/Publication Snapshot及Token部署/Mint**模拟状态视图**；
4. 实现Issuer逐Offering申请M上架的状态视图与必要本地Mock（正式P/M端页面另按各端开发计划交付）；
5. 完成跨R2-02～05浏览器测试、稳定性和实际人工验收；
6. 另立生产技术/法律决策门和外部服务接入任务，不把本MVP UI完成作为生产发行许可。
