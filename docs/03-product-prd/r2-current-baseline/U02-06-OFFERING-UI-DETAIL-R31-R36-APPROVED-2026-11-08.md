## 二、R31～R36 Approved 决策
| ID | 已批准产品规则 | 执行界限 |
|---|---|---|
| **R31｜单页面字段与布局** | 一页三区块：**A 发行信息、B 投资者认购条件、C 发行准备**。Asset / Instrument / 每 Token 权利 / 当前可用份数自动继承；发行名称可自动建议后修改；企业最终结算收款钱包只能从本 Tenant 已绑定、可验证的钱包中选择。**不新增独立发行准备页面**。 | 只允许本期 Offering 参数在本页编辑，Instrument 的权利总量和资产原始事实不重填；快照/旧版不能静默改变。具体字段最大字数、默认合规地区、锁仓天数等未批准。 |
| **R32｜字段计算与校验** | 本期发行 Token 份数为**正整数且≤当前 Instrument 剩余额度**；固定价格 U、单笔最低认购金额 U 为正；本期计划最高募集金额由数量×单价只读计算。最低认购金额换算成 **整数 Token 份数**和**实际需付金额**时明确告知用户，不因金额除不尽而静默截断。认购开始时间早于结束时间，显示时区。 | 最低认购额不等于实际可以购买零碎 Token；**Token / U 生产精度、舍入方式、整数上限、同步后端额度确认、网络 USDT decimals** 仍需正式技术门，不用随意假定精度。 |
| **R33｜两层发行准备检查** | 将检查分为 **业务资料完整性** 与 **真实生产准入** 两组；缺资产资料/权益文件/发行协议/风险披露/已绑定企业钱包/投资者准入条件时提供可点击的定位和修复路径。业务资料已完整不能自动宣布可在生产发行。 | 审核资金合约、Signer、Provider、KYC/法律许可、OP Mainnet USDT 实际地址等后才可发布；不能将 Mock 的绿色演示状态冒充生产核验。 |
| **R34｜按钮与状态** | 草稿可保存、编辑、预览、检查；真实发布必须经过所有准入并明确确认。等待开始不可认购；在售可暂停；暂停恢复需要重新检查；到期停止新认购；处理完在途支付/Token/退款后才能关闭。**发布/暂停/关闭等关键操作需二次确认**。 | 不代表已批准所有状态枚举、发布后改日期/改钱包权限、具体原子事务；仅冻结对应用户操作保护原则。 |
| **R35｜投资者展示预览** | 预览必须使用将来的投资者端实际展示结构/相同字段映射，包含资产卡片与详情、权益说明、认购价格与时间、条件、支付方式及法律/风险文件；编辑中随时可预览，发布前需再正式确认。缺项明示，不展示虚构募集/收益/持仓数据。 | Free 仅标准模板内部只读预览，不能生成或配置公开门户；实际投资者门户后端/生产上架仍独立验收。 |
| **R36｜异常与验收覆盖** | 测试必须包括：草稿刷新恢复、缺必填/非法金额/份额超限、文件上传/扫描失败与版本更换、钱包解绑、未来发行误在售、暂停仍能下单、到期在途订单、关闭误释放额度、跨 Tenant 关联、链支付失败等场景。 | 浏览器演示测试可使用隔离 Mock fixture，但**不能以 Mock PASS 作为真实生产资金/Token 的上线证明**；测试必须注明 PASS / FAIL / BLOCKED / NOT RUN，覆盖真实代码与浏览器截图证据。 |

## 三、批准后的用户页面最小图
```text
资产与发行 → 资产管理 → Asset 详情「发行管理」→ 新建/查看某一期 Offering
顶部：资产名称 / 本期名称 / 当前状态 / 缺项计数 / 下一步主动作

  自动建议名称、投资者简介、本期 Token 份数、固定单价 U、最低认购金额 U
  计划募资上限 = 数量×单价（只读）；认购开始/截止时间（含时区）
B 投资者认购条件：
  个人/机构、许可地区、基础 KYC 条件、无锁仓/固定天数
  OP Mainnet · USDT（只读支付范围）
C 发行准备：
  企业收款钱包（本企业真实已绑定 MPC 或自连接钱包）；
  发行协议、风险披露、引用 Asset / Instrument 的固定文件版本
  [业务资料完整性] [生产准入] 两个独立检查组与可定位阻断原因
操作：保存草稿 / 检查准备情况 / 随时预览投资者端
       仅生产门通过后 → 最终预览与明确发布确认
发布后详情：真实状态 / 份额与计划金额 / 订单、资金、Token 真实事实入口
```

## 四、仍 Open，不应借 R31～R36 A 假装完成
1. 发布后收款钱包/发行条款变更与版本通知的完整白名单、适用时点和签署责任。
2. KYC 级别、地区合法性、投资者资格、法律文件的法定有效性与真实签署流程。
3. 精确到数据库/智能合约的完整状态迁移、订单并发、实际支付确认、退款时限和 Token 精度；无技术法律准入不得开放真实 Mint/募资。
4. OP Mainnet USDT 2026-09 合约迁移后官方地址及合约兼容性需重新核验，不准硬编码旧支付资产。
5. 用户本轮只批准六项产品规则，**没有批准 Codex 立即进行 DEV-05 开发**。后续字段级 UI-Ready、状态与异常矩阵、浏览器验收清单可作为交接候选文档先编制，未再批准的具体实现细则标 Candidate/Open。
