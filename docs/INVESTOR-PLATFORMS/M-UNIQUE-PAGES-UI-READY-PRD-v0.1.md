# RWA SaaS V1.0｜M 总投资者平台独有页面 UI-Ready PRD（PC Web）

> 日期：2026-11-24｜本轮产品方向已确认；待独立 PR 审核。仅覆盖 M 独有部分；共用登录/KYC/钱包/资产详情/企业资料/认购/订单/持仓/收益/工单不得在 M 再建第二套。参见 [V/M 共用规格](V-M-SHARED-UI-READY-PRD-v0.1.md)。

## 1. M 的产品定位及边界

M = 跨多 Issuer 的总投资者平台；投资者在 M 浏览经 P-15 审核通过且自动上架确认成功的 Offering，按相同共用流程认购。V = 单 Issuer 企业品牌专属投资者门户，当前 Offering 只需满足 V 自身公开准入，不因未上 M 而禁止在 V 展示。

M 只持有自身渠道 Listing、账户授权/引用及可见投影；**不复制 Offering/资产/合同、订单、资金、法定持有人、Token、收益主账**。Listing 是渠道展示准入，不是发行合法批准、保本担保或个别投资者资格批准。M/M-03 共用企业资料模板，不因在 M 上架而赋予发行方对平台账户的全局查询权限。

PC Header：左上角 M 平台 Logo，中部“首页｜投资机会｜我的投资”，右侧“帮助与客服｜消息｜账户”；Footer 风险/帮助/条款。未登录可公开浏览；账户/投资/工单受权访问。

## 2. M-01 首页（与 V 差异）

| 区域 | 公开字段/结构 | 主动作 | 守卫/空态 |
|---|---|---|---|
| 平台主视觉 | RWA 是什么、全球多资产投资机会、必要风险提示 | 浏览投资机会 / 了解 RWA | 不展示保证收益承诺 |
| 资产类型浏览 | 房地产、企业股权、借款债权等已开放且存在有效 Listing 的分类 | 进入带类别筛选的 M-02 | 不以历史目录显示“可投资”的未开放模板 |
| 最新上架 | 真实有效 Listing 的卡片，展示分类、地区、权益及价格/状态 | 点击 M-04 | 无 Listing 显示暂无投资机会 |
| 投资流程说明 | 浏览→注册/自动钱包→认购前 KYC→合约 USDT 付款→登记与持仓 | 对应知识/帮助 | 不误写“注册必须 KYC” |
| 基础风险教育 | 法律权益与 Token 的区别、可能损失、非保证收益 | 查看风险说明 | 无法代替具体 Offering 合同 |
| 页脚 | 法律、风险、隐私、平台声明、支持 | 打开文件/客服 | 当前无内容不制造虚构评价 |

**首页不自动选“收益最高”作为精选**；如需“精选”，必须已有可追溯、经批准的编辑排序规则，否则默认“最新上架”，数据源为 M23 有效 Listing + 对应 Offering 公共披露。PC 列表采用宽屏卡片网格，非 APP 底栏。

## 3. M-02 跨 Issuer 投资机会列表

**目标**：同时比较多个 Issuer 的可公开 Offering，同时不误导投资者认为资产类别不同、权益不同的收益具有同质可比性。

桌面结构：顶部标题/搜索/结果数/排序，中间左侧筛选侧栏（可折叠）、右侧 3 列或 2 列 OfferingCard 栅格；组件与 V-04 相同但 M 增加企业筛选。

| 字段/过滤 | 类型 | 规则 |
|---|---|---|
| 关键词 | 搜索文本 | 仅 Offering、Asset、获准公开的 Issuer 名称 |
| 资产大类/子类 | 级联多选 | 仅列已开放且有真实可展示资产类型；V1 六底层模板 |
| 权益类别 | 多选 | 股权/债权/收益参与；不能假设房产只支持收益参与 |
| 国家/地区 | 多选 | 按允许公开的 Asset 所在地 |
| 认购状态 | 单选/多选 | 即将开放/认购中/暂停/结束，具体可见性由 Listing 规则控制 |
| 发行企业 | 搜索多选 | 仅有有效可公开 M Listing 的 Issuer |
| 排序 | 单选 | 最新上架（默认）/认购截止时间；不提供“最高年化收益” |
| 重置筛选 | 按钮 | 清空过滤，不改变账户/Listing 状态 |
| 页码 | 分页/加载更多 | 建议 20 条/页，服务端排序和权限过滤；URL 保留筛选 |
| OfferingCard | 可复用组件 | 项目名、资产类别、地区、权益类型、单价 U、最低认购、状态、Issuer、适用收益摘要 |

**点击动作**：整卡/“查看详情”进入 M-04（共用 AssetDetailShell）；点击 Issuer 进入 M-03（企业详情）。List 不直接创建订单，也不要求登录。只有 Listing 状态已正式可见且对应 Offering 公开 Gate 仍有效时才展示；数据快照不一致/Unknown 则隐藏交易操作，保留合法查看说明。无结果提示“没有符合条件的投资机会”，可清除筛选。

## 4. M-03 Issuer 信息页（与 V 完全同设计）

M-03 使用同一 IssuerProfilePage 组件：Logo＋展示名、法定名称、登记国家/地区、主营业务/简介、经授权公开企业/认证摘要、关联合法披露文件、此 Issuer 在当前渠道可公开的 OfferingCard、风险免责声明。“企业认证通过”不构成资产合法、价值真实或保证收益的认可。

**V 同样可进入该页**：AssetDetailShell 企业卡中点击 Logo、企业名称、查看企业详情均跳转；V 页面只显示当前企业在 V 获准公开的 Offering；M 只显示在 M 有效上架的同一 Issuer Offering。不得将 Issuer 的资产权利人、基金管理人、SPV 与发行企业混为一个主体；可在资产详情中依 Asset/Instrument 版本区分关系。

面包屑：M 首页/投资机会/企业信息；或 V 首页/投资机会/企业信息；从 Offering 进入时提供返回原 Offering。企业介绍为空则展示最小合法主体信息，不能套模板写虚构企业荣誉。

## 5. M-05～M-08 独立范围、共用流程

M-05 登录：共用邮件 OTP 与首次登录建号；登录前可浏览。M-06 个人/机构资料及第三方 KYC：资料只读引用权威，未认证仍可登录使用。M-07 钱包：注册后自动发起本 M 账户 MPC 创建（Provider 未准入/Unknown 不伪装完成），自有钱包签名绑定、可切换默认。

**M-08 历史“Offering 专属投资资格向导”收敛为认购前状态检查**，不建设新的 V1 Issuer 自定义审查页面。检查当前 M Account 有效登录、KYC Passed、平台法定强制准入限制、Offering 正式认购窗口、Listing 有效、价格与可售份数、每笔及本期个人限额、必要协议签署和钱包付款 Gate。若失败，就地提示“需 KYC / 暂不可认购 / 资料待核 / Listing 暂停”等，准确返回原资产；不提供 Issuer 人工批准、资格豁免按钮。KYC Provider 可在合法依据及投资者授权下引用已知认证结果，但**不会自动合并 V 账户**。

## 6. M-09～M-15 共用能力的特殊守卫

**认购与订单**：M-09/10/11/12 与 V-06/07/08/09 相同“四步”；M-13 的“订单/退款/异常”与 V-10/11 相同，无投资者手动取消、手动退款；遇到问题链接共享支持工单。唯一区别：每次进入付款前检查此 Offering 的 M Listing 仍有效，并固定订单 channel=M 归因；M 与 V 共用 Offering 授权总可售数量/支付主账，不因渠道而复制发行容量。

**历史投资**：M-14/15 只聚合本 M 账户依法可见、来源 M 订单/权益的跨 Issuer 本人持仓和收益；不能因为某个 Listing 暂停/下架/Issuer 订阅降级，自动删除已发生订单和法定权益。持仓法律单位 vs Token 数量、收益 vs 本金、Claim/Push/外部收款继续使用共用模板，不能为 M 新建“统一金融余额”。

**消息**：M-15 的我的消息、披露、工单只展示当前 M 账户授权事件；不能默认同步任意 V 企业专属账户的私信与历史凭证。

## 7. M-16 账户安全、隐私与支持

M-16 并入“我的账户”，不新增一级导航。分组：登录邮箱（只读，变更需另行审查）、账户类型与核验状态、最近会话/退出登录、同意的文件版本与隐私说明、钱包管理入口、KYC 历史摘要、我的工单。主操作“退出登录”“查看认证”“管理钱包”“提交工单”。

| 交互 | 条件/结果 |
|---|---|
| 会话过期 | 引导邮箱 OTP 重登，返回先前允许页面；不泄露历史敏感数据 |
| 有权查看个人资料 | 仅当前认证范围，敏感字段脱敏 |
| 撤销授权/更改隐私偏好 | 按法律与服务规则执行，不能删除依法仍需保留的付款、订单和权利证据 |
| 安全异常 | 显示账户服务受限及必要支持入口，不暴露后台风控判断 |
| 自有钱包绑定/更换默认 | 进入 M-07；不自动转移 Token 或历史登记 |
| 客服/工单 | 连接 M17/M18，共用四状态，唯一工单引用，未授权的跨 Issuer 工单不可访问 |
| KYC 需要补件/过期 | 进入 Provider 流程；不妨碍有权查看既有投资和收益 |
| 账户服务限制 | P-18 仅管理 M 账户服务，不决定法定权益灭失；仍允许必要的受控历史查询/履约支持 |

## 8. P 平台后台与 M 数据边界

P-15 对每个 Offering 的 M Listing 申请审核，一次批准触发**自动上架**；只有最终上架同步成功才在 M 展示。P-16 管理已生成 Listing 的暂停/下架/恢复；P-17 统计渠道授权聚合数据与投诉/异常协作；P-18 只处理 M 账户和第三方 KYC 的服务状态。P-07 仅处理有权/被指派任务，不能因投诉而直接更改 M11 退款、M12 法定登记、M07 Mint 或 M13 收益事实。Issuer I 仍是发行/资金/投后主责操作入口，P 为其可受权的协作方而非第二金融主账。

## 9. M 独有验收用例

| ID | 场景 | 应满足 |
|---|---|---|
| M01 | V 可公开、M 未批准 Listing | V 展示；M 不展示 |
| M02 | P-15 审核通过、M 同步 Unknown | M 仍不展示，查原操作 |
| M03 | P-15 上架完成 | M 显示唯一 Listing，进入共用 Offering 详情 |
| M04 | 同一 Issuer 多 Offering，部分只 V 发布 | M-03 只列有效 M Listing |
| M05 | 同一邮箱分别登录 V/M | 会话/默认钱包/私有订单不自动合并 |
| M06 | 先注册未 KYC | 可登录、自动请求 MPC、公开浏览；提交认购前 KYC 检查 |
| M07 | M 端 Listing 下架但已形成持仓 | 历史本人订单、法定权益、应付不丢失 |
| M08 | V/M 同时认购同一 Offering | 共用报价、全局 Offering 容量和支付权威，不超额 |
| M09 | M 企业页入口与 V 企业页 | 同组件、不同授权 Offering 集合 |
| M10 | 不同权益资产同时列表 | 年化摘要按合法权益显示，不能误比 |
| M11 | P-18 限制 M 账户 | 不影响其他 V 账户，不消灭已存在法律权益 |
| M12 | M 收益页债权本金 | 与投资收益严格分列 |

## 10. 非本批内容及生产 Gate

H5/APP 适配、二级市场、跨端账户自动合并/持仓迁移、Issuer 任意个体适格审批、保证收益排序、法币/USDC/多链支付、投资者自助取消/退款、复杂客服 CRM/工作流和高级自动风控均不属于本批 V1。M 实际上线需 MPC/签署/KYC/链上合约、法律披露和 Listing 权限模型独立审计与验收。本文件不构成真实系统已实现的证明。
