## 1. 决策内容

1. **V1 投资者交易功能范围仅规划一级发行认购**：优先建设发行机构发行、Offering、投资者资格、持续购买、USDT/USDC 链上支付、依批准条件自动配售、权威登记、RWA Token 交付及必要的发行后存续期管理。此处“仅一级认购”限定**购买/转让交易能力**，不表示砍掉 SaaS 客户管理、发行后管理、White-label 已确认的产品原则或其他已冻结模块。
2. **V1 不提供投资者之间的受控转让业务工作流**：不提供转让申请、受让人转让资格办理、转让审批、转让交割、转让引起的权威登记/Token 迁移等 M14/WF-14 产品化界面和 API；更不提供公开二级市场、撮合、订单簿、AMM 或 SaaS 平台自营流动性。
3. **V2 再独立详细设计受控转让**：保留 M14 模块和 WF-14 流程架构占位，后续详细 PRD 应遵守投资者资格、Instrument 限制、法律/资金责任、权威登记、链上结果及异常/审计分离；具体支持资产、功能深度、开发排期和生产启用条件须另外批准。这里的 V2 是“下一版本规划方向”，不是已承诺的交付日期。
4. **V1 保留必要的 Token 转让限制/权限控制**：不能因 V1 无转让页面，就默认允许投资者通过任意外部钱包对依法需要限制的 RWA Token 自由转移。根据首发金融工具及合法规则，发行合约应可评估并实现所需的锁定、限制名单/许可名单或其他适用控制。发行、赎回、登记更正等必要授权操作按自身规则处理；这不构成开放投资者之间的 V1 二级转让产品。
5. **不改变第 02/03 份及功能树已冻结的架构**：六领域、22 模块保持不变；M14 仍作为长期逻辑模块，但本决策将其投资者受控转让**产品化交付时间**后移。
6. **不改变 DEC-004/007/008 的法律、资金、KYC 和权威事实原则**：V1 自动认购/交付仍须已获授权的业务规则、必要资格、额度、资金对账、配售、登记和链上执行检查，不能仅以 USDT/USDC 到账事件替代其他事实。

## 2. 与 DEC-009 的准确关系（差异优先级）

[DEC-009](DEC-009-v1-secondary-transfer-boundaries.md) 的“V1 默认不建设公开二级交易市场”、转让限制、资格校验、登记与链上分离、平台不默认控制资金及法律许可边界**全部继续有效**。

**被本次后续明确决策取代的范围，仅是 DEC-009 第 2 条“先支持受控转让工作流”及第 4 节建议纳入 V1 的转让申请、逐笔转让审核/交割等产品交付建议。** 这些内容转为 V2 的规划输入，不再作为 V1 交付要求。

不得将 DEC-009 的原文静默重写成“从未建议在 V1 支持转让”；应通过本决策进行历史追踪。本文件是**后续补充决策**，不是对其他冻结原则的整体撤销。

## 3. 边界与验收判定

| 判定问题 | V1 要求 | V2 规划 |
|---|---|---|
| 投资者是否可在开放的 Offering 中直接认购？ | 按已批准条件允许，优先持续购买模式 | 保持 |
| 投资者间是否可发起受控转让申请？ | **不提供** | 独立设计 |
| 是否建设公开撮合/订单簿/AMM？ | **不提供** | 不默认提供；另行决策 |
| 是否需要合约级转让限制防绕过？ | 对需要限制的工具，**必须具备经验证的必要控制** | 保持并与受控转让流程衔接 |
| 法定登记、链上 Token、真实资金是否分离？ | **必须** | **必须** |
| 是否默认批准生产发行/链上操作？ | **否** | **否** |

**具体 V1 逐功能验收范围尚未冻结**：本决策只确定“一级认购优先、受控转让产品 V2”这一明确的范围门；不自动确定其他模块的 V1 完整开发深度、首发市场/金融工具/链/稳定币/合约或真实资金责任。
