## 1. 分离四类状态（避免只用一个大枚举）
| 事实层 | UI/业务需区分 | 说明与权威 |
|---|---|---|
| **Offering 生命周期** | 草稿、等待开始、认购中、暂停、认购结束、已关闭 | 页面主状态；发布成功与起售时间分开，**业务资料 Ready 不是生命周期状态** |
| **发行准备检查** | 未检查／待补资料／业务资料已完备／生产准入待核／生产准入未通过／生产准入通过（仅真实权威） | 资料完整和生产准入**两套**检查；前端模拟结果不能解锁真实生产 |
| **认购订单进度** | 待支付、支付处理中、已确认付款但待交付、交付完成、失败/超时、退款处理中、退款完成（示意标签） | 订单完成必须有真实付款和 Token 交付；**完整事件名和实现机制 Candidate** |
| **资金与权益容量** | Offering 计划份数、已发布有效预留、确认已发行/交付、在途订单份数、待释放/已释放、USDT 已确认/退款/已结算 | 来自资金/Token/Instrument 等权威主账，不能从表单数字直接推定事实 |

### 1.1 状态关系
```text
Draft 草稿 ──(发布全部独立准入通过+发行人最终确认)──→
  ├─ 开始时刻在未来：Waiting 等待开始 ──(时钟到+持续准入满足)──→ Active 认购中
  └─ 合法时间窗内：Active 认购中
Active ──(受控暂停)──→ Paused 暂停 ──(重新校验通过且未到期)──→ Active
Active / Waiting / Paused ──(到期或受控结束)──→ Ended 认购结束
Ended ──(在途订单、资金、交付、退款处置完成+容量校验)──→ Closed 已关闭
Closed：不可直接再次变为 Active；如需新一轮，应建立新 Offering。
```
- 等待开始时暂停/提前结束、发行过期后立即关闭、起售时生产门临时失效，以及发布后延期属于**Candidate**，未批准可作为随意快捷操作。
- 同一 Instrument 同时最多一个实际可开放认购的 Offering；**跨期预定窗口重叠、Paused/Waiting 是否占未来排他时段、自动到期触发的并发锁细节仍需审查**。最小实现必须保证服务器执行新单入口检查，不能只藏前端按钮。

## 2. Offering 生命周期迁移决策表
约定：A=上游已批准核心规则；C=为开发验收建议的精确守卫；O=需生产法律/技术专项决定。**C/O 不代表全部得到用户批准。**

| 源状态 | 触发 / 目标 | 前置守卫 | 后置事实与副作用 | 操作与反馈 | 级别 |
|---|---|---|---|---|---|
| 空白 | 从 Asset「发行管理」新建 → Draft | 本 Tenant Asset/InstrumentVersion 可引用，具备业务准备授权；未完成资料允许保存草稿 | 创建 Offering+必要 Project 关系；**不预留 Token** | 「创建发行方案」与表单区块 | A |
| Draft | 保存草稿 → Draft | Tenant/订阅/KYB 有权、数据结构可存、禁止跨 Asset 越权 | 保存填写字段与固定文件版本，不创建链上/资金/订单事实 | 保存成功时间；失败重试且保留输入 | A |
| Draft | 资料检查 → Draft | 根据字段、文件/资产/钱包及准入状态逐项检查 | **不推进发行生命周期、不预留**；仅更新检查结果 | 两层检查/缺项定位 | A |
| Draft | 预览 → Draft | 数据有可预览字段，缺项可展示「待补」 | 不生成真实公开链接/订单/上架 | 「内部预览」「非正式」 | A |
| Draft | 发布操作 → Waiting 或 Active | 有效 Standard + KYB + 全部适用生产合规、链、签署、钱包、Provider/Signer/支付服务门+实时容量与并发+最终预览/确认 | **成功发布瞬时**原子地固定快照并预留本期数量；开始时刻未来→Waiting，已到且未截止→Active；失败全部保持未发布 | 未通过时逐项阻断，不能假发布 | A/C/O |
| Waiting | 到开始时间 → Active | 当前时间处于窗口、发布/合规/生产准入仍满足、同 Instrument 无另一轮实际在售 | 开放新认购入口；不重新扣一次发行预留 |「认购已开始」 | A/C/O |
| Waiting | 提前撤回/取消 → ? | 涉及公开披露、资金/签署/法定义务 | **尚无已批准的一键撤回/释放路径**，不可擅自实现；到期规则需明确 | 显示受控处理/联系支持（文案 C） | O |
| Active | 暂停 → Paused | Offering 处于在售且有权；确认暂停后停止新订单进入 | 已有待支付/已收款/待 Mint/退款义务持续；**不直接释放份额** | 二次确认：新认购停止，旧订单继续 | A |
| Paused | 恢复 → Active | 未到截止、真实发布和法定/生产条件重新通过；实际服务端新单入口恢复 | 只解除新增订单限制，**不重新预留**；旧订单不重置 |「恢复认购」，不满足给具体原因 | A/C/O |
| Active/Waiting/Paused | 时间到期 → Ended | 当前时间达到经有效记录的截止时刻 | **立即停止新认购**；在途支付/Token/退款完整保留 |「认购已结束，待完成后续处理」 | A |
| Active/Paused | 受控提前结束 → Ended | 业务允许、发行人授权及通知/法律门，通过确认 | 停新单、继续在途；**是否允许提前结束及具体审批仍待定** | 不提供未经批准的普通立即结束快捷键 | C/O |
| Active/Waiting/Paused/Ended | 修改结束日期 → ? | 适用 R30 发布快照保护、订单权利、投资者通知及批准门 | **USDable 实测有改结束日，但本平台尚未批准发布后可自由改时段**，历史快照不可覆写 | 无已批准条件时只读/说明 | O |
| Ended | 结清并关闭 → Closed | 真实订单/支付/Token/退款/争议完成核对；容量释放条件可信，适用法定义务已满足 | 仅无在途义务的未分配有效预留归还池；已发行不归还；Closed 不可重开 | 列待处理清单，二次确认关闭 | A/C/O |
| Closed | 恢复/重新认购 | **永远不得直接解锁**；新一轮需新 Offering 与容量校验 | 无更改 | 提示「本期已关闭，请新建下一期发行」 | A |
| 任意已发布 | 钱包/Instrument/文件版本直接改写 | 发布时锁定确定快照；任何改动均需受控流程 | 不能重写已生成订单、Token 权利、已支付受益人、原法律版本 | 默认关键字段只读，变更流程 Open | A |

### 2.1 状态派生与时间优先级（C）
- 前台主状态必须来自可核验的 Offering 权威记录及有效时间，不从浏览器当前日期自行替代服务器事实。未来开始绝不显示在售；到截止时刻停止新单的后端入口，不能只显示「已结束」。
- 若生产门临时失效/数据无法确认，必须采取**禁止新真实认购的安全失败模式**，并给出原因；是否自动转 Paused 需正式事件状态机审批，不自创新枚举。
- 「发行已发布，但暂未开始」是生命周期事实；「发行参数检查通过」只是数据校验事实；「已支付」不等于「已完成认购」。

## 3. 权益容量的账务不变量
以同一 Instrument 的可发行上限 `MAX`、已确认交付 `ISSUED`、有效发布预留中尚未交付 `RESERVED`、可用 `AVAILABLE` 为业务示意：
`AVAILABLE = MAX - ISSUED - RESERVED`（仅针对单位一致、经过有效权益和版本核对的份数）。
- Draft 的 `RESERVED=0`；发布成功时本期计划份数成为预留的一部分；订单待支付/已收款/待交付的份数只在本期预留内分类，**不重复从 Instrument 扣减**。
- 成功交付 X：应有 `ISSUED += X` 与 `RESERVED -= X` 的等价权威状态迁移。**实际链上 Mint 事件及法定义务仍需独立准入**。
- 正常关闭：已售已交付仍占 `ISSUED`；待处理订单量必须保留（可置独立锁），无在途义务的未售剩余才可释放。
- 任何文件/权益历史版本更新都不能重置 `MAX`；跨期/跨会话/并发不能出现负剩余、重复 Mint、同一订单重复支付或释放。
- 示例：Max=10,000；本期预留3,000；确认1,800；待处理200；清洁剩余1,000。关闭可释放1,000，仍保留已确认1,800与待处理200；这只是用以说明口径，不授权自动退款/合约执行。
- 实际分布式账本/数据库事务、确认最终性、异常链重组与多方资金责任**O**。

## 4. 订单/资金/Token 子状态候选对照
| 用户看到 | 订单事实（候选） | 资金事实 | Token 事实 | 是否认购完成 |
|---|---|---|---|---|
| 待付款 | 有唯一订单、金额份数已校验 | 尚未确认链上转账 | 尚未交付 | 否 |
| 授权/支付处理中 | 钱包签名、交易提交等待 | 授权 ≠ 扣款；待真实确认 | 尚未交付 | 否 |
| 待分配 | 已确认有效付款但 Token 未交付（仅适用异步路径） | 资金控制与去向可追踪 | 未交付 | 否 |
| 已完成 | 有真实完成证明且身份/份数匹配 | 付款已确认 | Mint/转让交付已确认 | **是** |
| 付款失败/超时 | 无有效完成事实 | 未收到，或结果待核实 | 不得误发 | 否 |
| 分配失败 | 在途异常 | 可能已收款，禁止失联 | 未交付/待恢复 | 否 |
| 退款处理中 | 已决定受控退款/处置 | 退款进行中，保留证据 | 应无应付而未交付的已完成状态 | 否 |
| 退款已确认 | 退款真实确认 | 退款到账事实可核验 | 不得重复交付 | 否 |

**订单状态名、超时时间、链上确认次数、退款时限和资金托管角色都属 Candidate/Open。** 若采用可合法实施的同链原子交易，付款/交付/结算可在同一交易中完成或一起回滚，不必人为制造「待分配」中间态；失败 Gas 费用未必退还。

## 5. 异常场景与处理建议
| 异常 | 必须保持的业务事实（Approved） | UI 反馈/恢复（候选细则） | 禁止 |
|---|---|---|---|
| 文件扫描待完成/失败 | 真实生产检查不可自动通过；旧固定版本不被覆盖 | 「文件暂不可引用」→定位到文件并可重试 | 假绿灯、引用未验证最新文件 |
| 企业绑定钱包被移除/证明失效 | Draft 可保留，但不能以失效钱包发布；已发布钱包快照和旧订单不能被静默改写 | 明示「收款账户需重新验证」，发布后变更走受控流程 | 指向不明收款地址、资金自动重路由 |
| 权益额度被其他期占用 / 并发 | 不得超发，同 Instrument 同期最多一开放认购 | 展示最新可用份数并提示减少数量/检查其他期 | 使用前端缓存重复发布成功 |
| 未来开始的 Offering | 未到时点不可认购 | 状态「等待开始」，倒计时可选（C） | 审批成功即写在售 |
| 暂停后投资者新订单 | 不可新增真实认购，既有订单继续跟踪 | 「本期认购已暂停」，既有订单查看进度 | 只隐藏按钮但后端仍接单 |
| 截止后付款才上链 | 订单/资金必须可追踪，超时处理待专项规则 | 「支付核对中」并给状态查询 | 无条件接受超期新单或私自丢款 |
| 原子支付交易回滚 | 不得把失败交易写成付款或交付完成 | 提示「交易失败，可查看原因并按当前规则重试」 | 写入已发行/已收款事实 |
| 非原子付款成功 Mint 失败 | 已收款必须可追踪，需恢复/退款 |「支付已确认，Token 待交付；正在处理异常」 | 自动把资金结算企业、虚假完成 |
| 发行到期还有未结订单/退款 | 不可强制静默关闭并释放其预留 | 列待处理数与对应记录入口 | 删除订单、误释放、改已发权利 |
| 同一订单重复提交 | 真实唯一订单和额度不得重复占用、重复扣款或交付 | 返回已存在订单进度（C） | 产生双单、双扣款或双 Mint |
| 用户同时多标签编辑 | 不能用旧版覆盖发布快照或旧法律文书 | 版本冲突提示并保留用户输入（C） | 静默最后写入覆盖已发布 |
| Free / 降级 Free 绕过前端按钮 | 后端仍须阻断实际生产动作且保留合法历史 | 清晰区分新 Free 可做资料与降级历史只读 | 仅靠前端隐藏导致越权 |
| 跨 Tenant Asset/Instrument/钱包/文件访问 | 必须阻断并不泄露数据 |「无权访问该对象」并安全返回 | 利用 ID 直接读写他人资料 |

## 6. 状态开发的验收原则

- **不得将状态机文档的 Candidate 条件当成已批准的生产签名、支付或法律有效性实现**；遇到 Open，使用清楚的阻断/未开放状态与可复核提示。
