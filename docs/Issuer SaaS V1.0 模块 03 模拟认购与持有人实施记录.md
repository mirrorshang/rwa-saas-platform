# 模块 03｜模拟认购与持有人实施记录

## 范围与对象

正式实现位于 `apps/issuer`。沿用模块 01 的 Asset／Instrument／Project／Offering 固定引用和模块 02 的 Sandbox 发布、认购窗口。新增 `Allocation` 与 `HolderSnapshot`，订单、支付、配售、持有人登记、Token 交付分别保存；旧 v4 记录缺少新集合时安全补空，损坏或重复新记录隔离并保留原始存储字节。

`Investor`、`Order`、`Payment`、`Holder` 增加 Sandbox 环境或来源字段；订单固定确认版本和单价。Mock 投资者与付款不代表真实 KYC 或收款，模拟持有人记录不代表生产法定名册，Token 记录不代表链上 Mint。

## 实际按钮顺序

进入「演示控制台」→ 选择已发布且「Sandbox 认购中」的 Offering → 依次点击「创建模拟投资者」「Mock KYC 审核通过」「提交模拟认购订单」「记录或查询 Mock 支付」「执行逐笔配售」「模拟持有人登记」「模拟 Token 交付」「固定持有人快照」。付款可选最终匹配、失败、Unknown；Unknown 只能用原支付意图编号查询，失败后增加尝试编号。Record Date 用独立日期输入。

正式「投资者管理」「认购订单」「持有人管理」「资金与结算」「Token 管理」继续展示业务记录。订单行区分配售和登记；持有人页显示 Sandbox 来源及固定快照。模拟动作只在测试控制区。

## 守卫与幂等

- 创建订单要求 Mock KYC 通过、Offering 已发布且认购窗口开放、确认条款版本不变、数量为正整数、金额不低于最低额、累计认购不超本期容量。
- 支付每个意图只形成一条记录；Unknown 阻断新支付意图；已最终匹配禁止重复付款。失败可用新意图重试。
- 配售要求付款最终匹配，且同订单不能重复配售；配售本身不创建持有人。
- 登记只引用已配售订单，登记前没有持有人；交付只引用已登记、已付款订单和已核验的 Sandbox 合约。
- Record Date 快照只读取日期前已生效的 Sandbox 登记；同一 Offering／Record Date 只允许一份固定快照，后续当前名单变化不改历史快照。

## 验收证据

2026-11-19 正式站点 `http://localhost:5174` 实际点击：OFF-3001 的三名 Mock 投资者分别订购 12,500／7,500／5,000 Token，三笔付款最终匹配后配售。配售时「持有人管理」显示空表；单独登记后显示三名 Sandbox 持有人，Token 余额先为 0，模拟交付后分别为 12,500／7,500／5,000。Record Date 2026-12-31 固定快照，再次点击提示已有记录。OFF-3002 同样逐步完成两名投资者 2,500／1,500 Token，对应 250,000／150,000 U。刷新后五名持有人与两份快照仍显示。

自动化覆盖窗口、KYC、容量、版本、Unknown、失败重试、各环节防重、快照不可变以及新集合损坏隔离。当前仅浏览器本地持久化，V／M 平台和真实支付、登记、链上服务仍待接入。
