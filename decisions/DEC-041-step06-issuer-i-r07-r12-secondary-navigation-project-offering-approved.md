## 二、页面层级方向（非最终路由、表单或UI）

```text
I端｜资产与发行
├─ 资产库           → I-20～I-22  资产列表／创建编辑／详情
├─ 金融工具         → I-23～I-25  Instrument列表／创建／条款／版本详情
├─ 项目管理         → I-28～I-29  Project列表／创建向导／项目工作空间
│   ├─ 项目概览／资产与工具／Offering轮次／文件审批／业务进度
│   └─ 从项目进入创建Offering
├─ 发行管理         → I-30～I-36  全企业Offering列表／创建／配置／详情／状态
└─ 文件中心         → I-26～I-27  材料、法律文件、签署版本和专业意见
```

此结构是**已批的页面组织方向**，并非实际组件/物理URL强制拆分；列表页、创建向导与详情可以沿既有逻辑页面组使用弹窗、页签或嵌套流程。其他一级模块的具体二级条目、全局导航选中/折叠、跨模块关联按钮规则、页面中文字段、校验、成功失败和空状态、UI与测试用例仍需逐页审。

## 三、显式保留的未决项

1. **Project与底层Asset关联基数**：项目能否关联多个Asset及资产组合发行约束，继续Draft；本批不能推定已支持组合底层资产Offering。
2. **Instrument复用与关联条件、项目创建流程的必填/顺序、Offering条款变更与历史版本细则**：沿用既有已批业务边界，逐页面PRD仍Draft。
3. **Free/Standard限制、真实金融与链上执行**：继承DEC-036/037/040；Free仅Sandbox，Standard仍需Issuer/Offering合法条件、X真实执行、平台RG及其他适用Guards；本DEC不批准任何生产实务。
4. **Asset类别和金融工具**：按多资产通用能力设计，不等于任意资产类别已获合法发行许可或新增V1正式范围。
5. **页面总数与映射**：W14/I61/V15/P14共104个候选逻辑页面组保持不变；146/146正式V1功能页面关联仅静态追踪，不等于页面PRD签收。
