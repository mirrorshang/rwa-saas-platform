# DEC-005｜首要目标客户与市场拓展优先级

- **状态：** 客户优先级已确认；具体市场规模、客户画像与商业假设待验证
- **确认日期：** 2026-10-18
- **适用文档：** 第 02 份《产品战略与商业模式》；后续用于第 03 份总体 PRD、第 09 份 SaaS 商业运营及市场验证计划

## 决策背景

项目需要明确首阶段面向谁优先设计产品、验证需求和开展客户发现，避免 Issuer SaaS、White-label 与 Open API/SDK 三条产品线在初期争夺同等资源。本决策只确定客户拓展顺序，不代表已验证相关市场规模、客户付费意愿或具体获客渠道。

## 已确认决策

1. **A 类优先：有持续发行需求的资产管理机构与发行企业。** 将其作为首要目标客户群，优先验证其重复发行、投资者管理、发行后存续期管理、报告及收益/利息处理等真实需求，并据此确定 Issuer SaaS 的核心工作流。
2. **B 类重点跟进：RWA 服务商与区域平台运营商。** 作为 White-label 的重点战略客户群，验证其管理多家发行机构、运营自有品牌门户、管理资产授权与客户权限的需求；其战略重要性较高，但不取代 A 类作为首要客户优先级。
3. **C 类独立拓展：金融科技公司及机构 API 客户。** 作为 Open API/SDK 的独立拓展路线，验证集成场景、开发者体验、Sandbox、Webhook、技术支持及用量计费需求；不要求其与 Issuer SaaS 共用同一获客路径或销售节奏。

## 对产品与执行的约束

- 首阶段产品发现与核心流程设计优先围绕 A 类客户的可重复发行及存续期工作流展开。
- White-label 的多发行机构运营能力按 B 类客户需求重点验证，但需遵循 DEC-001、DEC-002 的独立门户、明确授权及客户层级边界。
- Open API/SDK 保持独立产品线和需求验证，不因 C 类客户优先级较后而从长期架构中删除。
- 客户优先级不代表允许平台自行开展受监管活动；具体服务范围、责任主体和上线条件继续遵循 DEC-004，并须取得对应法域法律意见及合作方确认。
- 本决策不等于已确定首发资产类别、具体国家/监管区的上线顺序、价格、销售渠道、客户获取成本或目标收入。

## 尚待验证

- 日本与阿联酋（及其具体监管区域）中，A 类客户的细分行业、发行频率、典型项目规模、采购人/决策人及采购周期；
- A 类客户对发行工具、投资者准入、登记、资金结算、存续期管理和报告的实际优先级；
- A 类客户可接受的实施方式、订阅价格、实施费用及付费意愿；
- B 类运营商的多发行机构治理、品牌/域名、授权分发和运营支持需求，以及其采购决策是否依赖特定牌照或合作机构；
- C 类 API 客户的集成需求、开发者资源、API 用量模型和独立商业可行性；
- 各客户群在日本与阿联酋的可触达性、竞争替代方案及实际销售成本。

## 后续动作

1. 以 A 类为优先开展结构化客户访谈与问题验证，避免只询问对抽象 Tokenization 概念的兴趣。
2. 同步建立 B 类 White-label 与 C 类 API 客户的访谈清单，但按各自产品线分别评估。
3. 将访谈证据、潜在试点、预算/采购信号与法律可行性记录在市场验证材料中；在证据形成前，不将市场规模、转化率或定价假设写成已确认事实。
