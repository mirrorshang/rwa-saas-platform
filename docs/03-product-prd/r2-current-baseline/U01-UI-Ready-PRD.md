# U01 企业入驻、认证、钱包与订阅｜UI-Ready PRD
> R2-04｜2026-11-06｜产品规则批准；本文汇编状态：Draft PR 待评审。产品批准 ≠ 实现完成 ≠ 真实金融/密钥/支付生产准入。

## 0. 通用原则
- 一个邮箱账号对应最多一个企业 Tenant；Account/Tenant/KYBApplication/Subscription/Entitlement/Wallet/OfferingReceivingWallet/PaymentOrder 为不同逻辑对象。V1 一个账号自主操作，无多企业切换、团队成员角色和审批分权。
- 登录后可访问工作台及全部导航（可点击、可知晓功能）；未通过企业 KYB 时业务内容/接口不可访问，主内容区域替换为统一认证引导/状态。账号、认证、帮助、协议、退出等必要操作继续开放。
- 企业 KYB 非登录强制条件；KYB 获批才激活 Free 企业业务。**Free 可在 SaaS 后台创建、编辑并保存正式的资产资料、权益结构和发行方案，但不能真实部署/Mint Token、上架资产、创建或发布投资者门户、开展认购募资、形成投资者持仓、收益分配或真实运营数据。** Free 仅可内部只读预览投资者门户效果，不可配置或生成面向投资者的门户页。**Standard 在订阅有效且完成适用业务、法律、Provider、Signer、网络、资金与安全准入后**可执行真实发行与后续运营。独立 Mock 测试控制台不属于 Free 订阅权益。
- UI 所有导航、字段标签、选项、帮助、通知、校验、错误提示用简体中文；协议与链标识、地址、服务商等必要专有名称除外。V2 才做多语言和按地区登记资料适配。
- 本 V1 KYB v0.3 字段标注为固定必填、选填或有**明确触发条件**的条件必填；禁止开发人员按法域自行补设未定义的强制条件。简化 KYB 不等于全球法定完成保证；实际生产法域额外资料与核验需独立准入另审。
- 金额 UI 使用 U 按 USDT 计价；投资者付款 V1 仅 OP Mainnet USDT。SaaS 商业订阅独立支持 USDT 与法币，不能混同网络、收款账户、资金账。
- 所有正式提交/订单/钱包关联须幂等、有版本、记录操作者与时间；防止旧 Mock 漏入真实账。

## A 账号入口（A01～A03）
**页面结构**：邮箱输入 + 邮箱验证码输入（同一入口两步）；协议首次确认嵌入入口，不设传统注册页。
**字段**：邮箱地址（必填、标准格式、长度上限254）；邮箱验证码（必填、6位数字）；服务协议及隐私政策同意（新账户首次使用必选；记录版本、确认时间及账号）。已有账号无须重复接受原版本，协议重大更新时按需重新确认。
**流程**：官网企业登录 → 输入邮箱获取验证码 → 校验有效期、一次性使用、频率限制 → 旧账号登录/新邮箱验证成功后建账号 → 直接进入企业工作台（即使没有 Tenant）。验证码过期、错误、已用、频控、邮件发送失败、网络异常明确报错；可修改邮箱、重新发送；不能产生重复 Account。
**权限**：账户受限/停用拒绝业务访问；会话过期重新邮箱验证；会话、同意记录以服务端真实状态为准。

## B 创建并认证企业（B01～B08）｜KYB v0.3（R01～R10 Approved）
> 最新批准记录：[U01-KYB-V03-APPROVED-2026-11-06.md](U01-KYB-V03-APPROVED-2026-11-06.md)。本节覆盖原先的「企业信息→资质→UBO→联系人→确认提交」五步字段版本；不改变邮箱入口、账户单Tenant、Free/Standard及真实 MPC 边界。

**入口/形态**：工作台统一「创建并认证企业」入口；一个**五步**向导：①企业基本信息 → ②企业业务信息 → ③企业关联人员 → ④企业证明材料 → ⑤预览与确认提交。另有引导/认证状态/补件视图，不强制每步独立路由。允许返回、前进、保存/自动保存草稿、刷新恢复与错误定位；没有Tenant也可浏览导航，但未过KYB的业务内容继续受C01守卫。录入企业资料不等于审核通过或 Free 激活。

### B01 入驻引导
- 告知准备常规企业注册证明、企业主体信息、相关人员信息，以及可按情况补充的控制/授权/牌照材料；说明审核通过后可用 Free 的正式资产/权益/Offering 资料准备能力，不把完整模拟发行业务当 Free 权益。
- 主操作「开始企业认证」；存在草稿时「继续填写」，可返回工作台。

### B02 第1步｜企业基本信息
| 字段 | 控件及要求 | 校验/动态规则 |
|---|---|---|
| 企业法定名称 | 文本，必填 | 去首尾空白；应与注册证明一致 |
| 企业类型 | 单选下拉，必填 | 有限责任公司、股份有限公司、合伙企业、基金或投资主体、其他；选择其他时**必填**类型说明 |
| 注册国家或地区 | 国家/地区选择器，必填 | 中文显示、稳定代码存储 |
| 企业注册编号 | 文本，必填 | 不接受纯空白；注册地+编号重复提示核验，不自动合并/覆盖；确无法提供常规编号的特殊主体走人工核验，不允许伪造 |
| 注册地址 | 多行文本，必填 | 完整地址，非空 |
| 企业官网 | URL 输入，选填 | 填写时验证 URL 格式 |

不在MVP基础入驻强制收集实际经营地址、英文名称、成立日期、注册资本或额外拆分地址。

### B03 第2步｜企业业务信息
| 字段 | 控件及要求 | 校验/动态规则 |
|---|---|---|
| 所属行业 | 单选，必填 | 房地产、金融与投资管理、贸易与供应链、能源与基础设施、科技与专业服务、工业制造、其他；其他需填写行业说明 |
| 主营业务简介 | 多行文本，必填 | 简短、非空；阻止纯空白 |
| 是否从事受监管金融业务 | 单选，必填 | 是、否、不确定；不确定进入人工判断，不能自动认定不受监管 |
| 监管许可情况 | 单选，条件必填 | 选「是」后显示，区分已持牌/豁免/申请中/尚未取得/不确定等实际状态；不得把申请中或豁免伪称持牌 |
| 许可/监管信息 | 文本组，条件必填 | 仅声称已持牌时填写对应许可证编号及监管机构；第4步提供相应许可证或可核验依据 |

不单独增加平台使用目的、预计交易额、资金来源、AML政策或财务报表等所有企业共同必填项。业务真实性与特殊金融业务风险仍须人工/第三方核验，KYB通过不等于具有真实发行资质。

### B04 第3步｜企业关联人员
一个自然人记录可关联多个身份，不因兼任重复输入基本资料；账号、自然人、角色、控制依据和授权证明必须区分。

**A. 企业授权代表（至少1位，必填）**：姓名（文本、必填）、职务（文本、必填）、授权依据（单选必填：登记/法定代表权限、专项授权）。授权代表不是默认的业务联系人；可选择复用已有自然人。身份真实性与代表权限需按实际KYB核验标准判断；专项授权不能直接核实时，第4步要求授权证明。

**B. UBO／实际控制人识别**：先选择识别路径「可通过持股识别／通过其他方式控制／无法识别」，不得固定要求每家企业都有达到统一百分比的股权UBO。
- 持股路径：支持多位自然人；每位姓名（必填）、控制方式（直接持股/间接持股，必填）、**持股比例（数字百分比，必填，范围大于0且≤100）**；无须将申报人员比例强制加总为100%。
- 其他控制路径：每位自然人姓名（必填）、其他控制方式（必填）、**控制关系说明（必填）**；不强制填写虚构的持股比例。
- 无法识别UBO：**原因说明（必填）+至少一位相关高级管理人员姓名、职务（必填）**，数据角色标为「高级管理人员替代识别」，绝不可伪称为UBO。仍须人工核验，不因表单完整自动批准。
- 对复杂间接控股、信托或基金，仅在需要时转补件/人工审核；不在MVP强制用户绘制完整股权结构图。

**C. 业务联系人（至少1位，必填）**：姓名（必填）、联系邮箱（必填，合法邮箱，默认当前登录邮箱可修改），联系电话（选填）。可选择与授权代表或UBO为同一自然人并复用；不创建第二登录账号。

MVP不统一收集人员身份证件号、出生日期、国籍等额外敏感字段；若适用业务/法域、KYB服务商或生产准入要求额外验证，走独立补充核验，不得因为缺少本表字段就将真实法定身份核验宣称完成。

### B05 第4步｜企业证明材料
按证明目的分组列出文件及上传按钮；动态触发明确、不得对全部企业强迫上传所有文件。
| 文件/证明目的 | 控件与要求 | 触发/可接受的核验方式 |
|---|---|---|
| 企业注册证明/营业执照 | 文件上传，**常规必填** | 特殊登记主体无标准文件时走人工核验，不填虚假文件 |
| 股权或实际控制关系证明 | 文件/可信登记核验，**条件要求** | 已有资料或可信登记不足以核实控制关系、或审核需要进一步证明时要求补充 |
| 企业授权证明 | 文件/登记权限核验，**条件要求** | 专项授权无法从可验证登记或现有文件直接核实时要求提交 |
| 行业许可证明 | 文件/官方核验，**条件要求** | 声称已持牌且相关业务适用时要求，不能把申请中的资质视为已持有 |
| 其他补充材料 | 文件上传，选填/按补件要求 | 用户主动上传或审核补件 |

文件接受 PDF/JPG/PNG，单个最大20MB；显示类别、文件名、格式、大小、上传时间、上传/安全扫描状态和版本。支持上传、预览、替换、删除**未提交**的文件；上传失败、不可预览的非法文件或扫描失败不得用于提交或当作已审核。已有有效文件或可信官方登记核验能满足同一证明目的时不要求重复上传。审核要求补件的项目记录原因、提交结果与证据版本。

### B06 第5步｜预览与确认提交
- 四步分组的只读摘要及「修改」入口；文件可用/安全扫描状态清晰可见。
- **真实性声明及企业提交授权确认**：分别明确主动勾选，均必填；不可预选。
- 校验B02～B05所有固定/已触发条件必填项、UBO识别或替代人员、授权代表、业务联系人、文件扫描/可用性、重复主体；错误定位回对应步骤。
- 提交幂等，生成申请ID、版本快照、提交时间、操作者及审计事件。遇超时结果未知先查询原申请，不能重复创建。正式提交后不得静默改写原快照。

### B07 认证状态与 Free 解锁
维持**未创建、资料草稿、已提交、审核中、待补件、已通过、未通过**。审核中可查看原提交但不可修改当前提交版本；**待补件与未通过统一进入 B08 原资料编辑与重新提交流程**，两者只区分状态名称和审核意见，不拆成两套操作路径。已通过激活**最新E09定义的 Free 正式资料准备权益**，并由已准入真实Provider异步开启企业真实MPC钱包开通任务（失败不回滚KYB/Free）。真实金融发行仍需独立业务、法律、钱包/Signer、资金与网络生产准入；基础企业KYB不能代替全部金融业务合规审核。仅演示环境允许通过独立Mock控制台模拟审核和MPC状态。

> **页面字段与交互审核状态：Approved（DEC-066，2026-11-10）。** 用户已确认五步企业认证的字段组织及交互全部 A，无补充意见。B02～B06 的字段和动态规则仍以本文件及 U01 KYB v0.3 批准记录为准；本次 UI 批准不增加字段、不改变 KYB 业务规则。

### B08 补件、未通过、统一资料编辑与版本
- **待补件与未通过共用同一资料修改流程**：进入后自动载入此前提交的完整五步企业认证资料，包括全部字段、人员信息和已上传文件；不要求用户重新创建企业或从头录入。
- 用户可重新编辑原资料中的任意字段，按审核意见修改或补充信息；**不限制只能修改审核人员点名的字段或分组**。审核意见用于说明问题和辅助定位，不构成编辑权限限制。
- 原上传文件可查看；用户可按需要替换、补充文件。新文件仍须满足正常文件格式、上传和安全扫描要求；新版本提交后，旧文件随旧版本保留。
- 页面只显示一份原资料编辑表单，五步结构沿用 B02～B06；支持保存草稿、离开后继续编辑、预览和统一提交。待补件与未通过的差异仅为状态名称及对应审核意见。
- 统一主操作：「修改资料并重新提交」。重新提交成功后生成新资料版本、提交时间和审计记录，状态回到「审核中」；此前提交版本、审核意见和时间记录完整保留，不覆盖、不删除。
- 审核中仍只允许查看当前提交版本，不允许静默修改。
- **R10已批准**：现有旧版KYB草稿优先无损映射到v0.3字段。原企业名称/类型/注册地/编号/地址/官网、UBO名单、联系人、证明文件及扫描结果应尽量保留，未能可靠映射的新字段（如业务信息、授权依据）提示用户补填，不得直接丢弃。旧版已提交、审核中、已审核资料保持原有不可变快照、审核状态和时间；变更/补件另成版本，不得擅自重置已通过状态。
- 实施迁移前核对旧数据键及已提交状态；兼容代码先迁移/读旧稿再允许写新稿，需可回退与审计。

## C 工作台准入（C01）
登录后始终展示现有侧边一级/二级导航，均可点击；未认证时保留点击菜单的选中态、路径/标题，在主内容区渲染统一 KYB 状态内容，而非真实业务详情，不跳出工作台。未认证首页显示认证 CTA 与能力概览，不显示伪造的业务统计。
| 状态 | 主内容区 | 主操作 |
|---|---|---|
| 无企业 | 入驻引导 | 开始认证 |
| 草稿 | 待完成 | 继续填写 |
| 已提交/审核中 | 当前审核状态 | 查看进度 |
| 待补件 | 审核意见 | 补充资料 |
| 未通过 | 原因与可选后续 | 查看处理意见 |
| 已通过 | 正常业务功能 | 具体业务操作 |
只有认证/账号/帮助/法律页面为未通过状态例外。路由和后端 API 双重门禁；状态未知时拒绝业务数据而非默认放行；认证完成后按实际权益恢复访问。

## D 企业钱包（D01～D05）
**重大覆盖规则**：KYB 获批后**自动分配真实有效 MPC 钱包**（即使 Free），无二选一、无模拟 MPC。MPC 由已准入真实 Provider 执行；可开通中/失败，失败不回滚 KYB/Free，绝不可生成随机模拟地址冒充成功。Provider/Signer、密钥控制与托管责任仍是生产准入门。
**页面**：企业设置→钱包管理，一张钱包列表管理页（系统分配 MPC 固定显示、多个自有钱包），钱包详情、添加自有钱包、设置默认、解绑与异常操作在子视图/弹窗完成。
**自有钱包**：可新增多个，必须连接读取 EVM 地址、OP Mainnet 网络并以一次性消息签名证明地址控制权；服务端核验地址、会话、时间及防重放，绝不收集私钥、助记词。不以浏览器断开连接自动判断链上钱包失效。
**列表字段**：钱包名称（自有钱包选填）、钱包类型、地址（可完整查看和复制）、网络、验证状态、绑定时间、是否默认。系统创建 MPC 额外记录服务商ID、开通状态、失败/重试审计。
**默认钱包**：企业同一时刻只有一个已验证有效钱包为默认，初始为自动分配成功的 MPC；可在 MPC 与任意已验证自有钱包间直接切换默认标记（无需重新签名），原钱包不删除，旧发行收款关联不变。默认是新发行时的预选值，不是唯一可选钱包。
**解绑**：MPC 不允许企业直接删除；已验证自有钱包允许解绑，但正被有效发行使用时不允许直接解绑；默认钱包解绑需先设置其他默认；历史绑定及发行地址快照永久追溯。
**发行关联**：每个 Offering 必须明确关联已验证钱包，默认预选可改选其他有效钱包；保存 walletId、addressSnapshot、chain、type、confirmTime。未有有效钱包时引导先配置/等待真实 MPC 开通，不允许跳过。更改企业默认钱包不静默修改现有 Offering；真实活动发行的收款地址变更需单独受控变更。Free 创建的是可持续保存的真实 Offering 配置记录，但尚不能发布、部署合约、Mint 或收款募资；Offering 关联真实企业钱包不构成 Free 的真实募资许可。
**状态**：MPC 开通中/可用/异常；自有钱包待验证/已验证/失败/解绑；默认切换成功、并发冲突、网络错误、签名拒绝与到期均明确中文反馈。

## E Standard 订阅（E01～E08）
**UI**：企业设置→订阅管理：主页面（当前套餐、周期、到期日、自动续费、历史记录、Free/Standard 功能权益对比）、购买流程（月/年→USDT或法币→订单确认→支付结果）、续费与取消确认弹窗。未通过 KYB 用户只看到 C01 KYB 拦截。
**商业规则**：
- V1 Free + 一个 Standard 固定月/年价，无发行额百分比收费；最终价格、税费、开票和费率为待配置项。
- 订阅支持 USDT 和法币；法币显示真实结算币种/金额/报价有效期；投资者 OP 主网 USDT 与 SaaS 订阅支付网络分别配置，不擅自承诺某网络现已可付款。
- 默认关闭自动续费；用户主动启用，**仅在付款渠道具备有效周期扣款授权能力时开放**。失败通知并允许手动续费，不无限尝试。
- 可信支付服务最终确认收款后幂等激活 Standard；待支付/结果未知/自行提供哈希均不构成激活条件；异常退款经审核，不做无条件自动退款。
- 到期前 **7天、3天、1天及到期当天**提醒（站内及邮件，以确认的通知能力为准）；关闭自动续费只影响未来，不提前终止已付周期。
- 到期进入 **7天宽限期**：保留既有业务必要存续操作，**暂停新增真实发行**；结束未续费转降级，企业业务历史**只读**，保留订阅恢复、认证与账号入口；必要投资者权益履行须由独立受控机制承接，不强行让降级企业恢复普通业务写入权。
- 钱包及合法存续事实不会因降级被删除。重新付款并通过有效企业和业务准入才恢复对应权限。

**字段**：
- 订阅：Tenant、套餐、月/年周期、开始/到期时间、状态、自动续费标志、授权/渠道标识。
- 订单：编号、套餐、周期、应付金额及实际支付币种、支付网络（USDT时）、报价有效期、支付状态、最终确认时间、对应服务期、回调及幂等键。
- 页面状态：Free、待支付、Standard有效、宽限期、已降级；支付待付、确认中、成功、失败、取消、结果未知；异常给出继续支付/查询/重试/联系支持的准确动作。

### E09 Free / Standard 最新已批准能力矩阵（2026-11-06；覆盖旧版 Free 全模拟闭环定义）
本矩阵同时用于官网套餐功能对比与 SaaS 后台「订阅管理」的套餐权益展示；**展示的是已批准的产品能力，不得把尚未完成技术/法务准入的能力宣称为已经上线。** 标记“准入后”指 Standard 的独立生产条件，并非付费即可自动执行。

| 核心能力 | Free 免费版 | Standard 企业版 |
|---|---|---|
| 费用 | 免费 | 固定月付/年付；价格待配置 |
| 企业 KYB | 必须通过后使用业务 | 同样必须通过 |
| 企业钱包 | 通过 KYB 后自动开通真实 MPC；可绑定多个已验证自有钱包、切换默认 | 同 Free |
| 创建/管理 Asset | 正式业务资料，允许创建、编辑与保存 | 同 Free |
| 配置/管理权益结构（Instrument） | 正式业务资料，允许创建、编辑与保存 | 同 Free |
| 创建/管理 Offering 发行方案 | 正式业务资料，允许创建、编辑与保存；**不允许发布真实发行** | 正式业务资料；满足发行及生产准入后可发布 |
| 链上 Token 部署、Mint 等真实发行操作 | 不支持 | 独立生产准入通过后支持 |
| 面向公众的真实资产上架 | 不支持 | 满足上架与业务准入后支持 |
| 投资者门户内部预览 | 只读、内部预览；不得配置/生成/发布面向投资者的门户页 | 支持完整门户配置与发布（受准入限制） |
| 投资者认购与募集资金 | 不支持 | 独立生产准入通过后支持 |
| 投资者 Token 持仓、锁仓等业务 | 不支持 | 支持真实记录与运营（受准入限制） |
| 收益分配、领取等后续资金/Token 运营 | 不支持 | 满足相应准入后支持 |
| 发行后真实运营数据、投资者运营及经营报表 | 不支持（不影响查看自身资产/权益/方案的准备状态和记录） | 支持已开放的真实运营能力 |
| 白标与 API 等扩展能力 | 不支持 | 具体套餐归属、交付版本及开通条件**尚待单独决策**，不得宣传为 Standard 已交付 |

**流程与业务隔离：**
1. 新开通的 Free 是**真实业务准备权限**而不是完整 Mock/Sandbox 募资权限。资产、权益、发行方案记录具有正常业务身份、版本和审计痕迹；不可伪称真实链上动作已发生。未获额外明确批准前，不自行设置“Free 最多两个资产”等数量上限，也不得照搬 USDable 套餐额度。
2. Free 企业的「投资者门户预览」只用于内部查看效果，不能配置门户页面、生成可对外访问的投资者门户、真实上架资产或吸引投资者认购；也不开放模拟认购/持仓/收益作为订阅产品功能。
3. Free → Standard 升级时，已经保存的**真实资产/权益/Offering 静态业务资料**保留并可继续经过审核/检查，不必为了升级重新创建；订阅升级**不会**自动发布、部署、Mint、上架或募集。测试工具生成的模拟资金/Token/认购结果永不迁移或转化为正式账。
4. 到期宽限及降级沿用本节既有 E 规则：宽限 7 天停止新增真实发行、保留必要存续操作；宽限结束后**历史业务只读**，不因套餐标签恢复为 Free 就获得新开通 Free 的新增/编辑资产、权益、发行方案权限。真实钱包、发行历史、投资者权益不删除；必要存续履约通过独立受控机制继续保障。
5. 订阅权限检查须同时考虑 **KYB、订阅状态及历史、对象状态、发行合规与真实生产准入**；不可只按当前套餐名称开关写入权限。正常产品页面不出现 Mock 场景或测试状态按钮；独立 Mock 控制台仅用于产品/研发验收，不是 SaaS 套餐功能。
6. 费用、数量额度、白标/API 版本归属、具体门户模板与跨资产运营报表范围均在后续批次审核；此矩阵不暗示已批准无限制用量或未决功能。

## 跨模块强制验收
1. 新账号不经企业创建即进可浏览导航的工作台；不存在多企业切换或 V1 角色/成员配置。
2. 任意业务导航/深链/API在 KYB 未通过时只得到统一 KYB 状态，绝不泄露真实业务数据。
3. KYB 五步字段符合当前表，不保留旧签约代表、英文名称、联系人电话等废止必填项；提交快照、补件版本可追溯。
4. KYB 通过即 Free + **真实** MPC 开通任务，失败不假成功且不回滚 Free；钱包管理可增多个自有钱包、改默认、发行可改选有效钱包。
5. Free 可保存正式 Asset/Instrument/Offering 资料，无法部署/Mint、公开上架、配置/发布投资者门户、认购募资、持仓与收益运营；只有内部只读门户预览；Standard 真实执行仍需独立生产准入。
6. 月/年、USDT/法币、支付可信确认、提醒7/3/1/0、7天宽限、新增发行冻结、降级只读及受控存续通道严格区分。
7. 中文端到端 UI、异常及邮件通知；实际用户身份数据、签名、支付、文件服务不得以浏览器 Mock 通过冒充生产通过。
8. 正常 Free 允许编辑准备资料；由 Standard 降级的 Free 历史业务只读，受控投资者履约不断；E09 套餐权益须同步官网与后台订阅页，不得将独立 Mock 控制台算作 Free 能力。
