# Issuer R2 独立 Mock 控制台｜产品/UI 规格 v0.1

## 控制台结构（遵循已批准 M01～M12；具体布局由 UI 验收确认）
仅在明确开启的 R2 预览环境出现“测试工具”悬浮入口；默认收起，打开侧边抽屉，含：
1. **数据填充**：填当前正在编辑表单（保留完整校验规则）；生成完整企业/KYB/钱包/订阅/后续资产发行关联测试记录；同一企业上下文。
2. **状态控制**：KYB（未开始/草稿/已提交/审核中/待补件/通过/未通过）；自动MPC（待分配/开通中/已开通/失败）；订阅（Free/待付款/Standard/宽限/降级）；订单支付（待付/确认中/成功/失败/未知）；资产发行模块逐批扩展。
3. **场景预设**：新账号无企业、KYB草稿、审核中、补件、通过并已分配钱包、钱包失败、Free可演示、Standard有效、宽限期、到期降级；后续资产、权益、Offering测试场景。
4. **当前上下文**：演示账号、企业、当前模块、场景、是否有未保存更改；避免误操作到其他企业或浏览器正式服务。
5. **管理**：重置当前场景/恢复干净环境；危险操作需确认；保留必要的状态变更反馈。

## 正式 UI 与测试环境边界
- 正常业务页面不显示“设置KYB通过”“支付成功”等测试按钮，也不出现不属于正式业务的场景选择器。
- 正式业务页面按已批准流程真实校验、跳转和展示；独立 Mock 控制台修改测试输入或外部结果后，正式 UI 响应并展示正常中文业务状态。
- **预览环境外围必须清晰标注“演示/测试环境；数据和钱包并非真实”**，但不会把每个正常业务状态的显示文案改成“模拟已批准”；严禁接入真实账户的资金操作。**独立 Mock 测试场景是内部研发/验收工具，不是 Free 套餐对客户开放的认购、持仓、收益或资金业务权益。**
- 演示 MPC 地址：0x + 40位十六进制、企业隔离、刷新持久、同企业重复审批不重复创建；只是合格的测试地址文本，**不代表持有密钥或能够签名/收款**。支持多个自有演示钱包、默认切换及Offering地址快照；产品 UI 原样显示钱包详情。
- 测试状态变化遵循正常业务依赖；KYB批准→Free解锁→触发演示MPC分配。避免直接构造“无企业但Standard实付”等自相矛盾的常规预设。
- 预览数据与正式钱包、真实资金、生产订单/Token完全隔离。旧 Issuer 的 SessionStorage/fixture 不直接读入新版。
- 测试数据在导航/刷新后保留；可以重置。若存在未保存的表单，填充和场景替换需要防止静默覆盖。
- 产品及UI团队验收只需可复现的交互、状态变化、截图和异常；不要求当前实现真邮件、真KYB服务、真MPC、真资金或模拟API服务端。
- **2026-11-06 套餐决策同步**：正式 Free 允许保存真实资产、权益结构和发行方案资料，内部只读预览投资者门户，禁止配置或生成门户、上架、认购、持仓、收益等业务。Mock 控制台可为 QA 注入模拟后续状态，但不能藉此把测试能力解释为 Free 订阅能力；M01～M12 原批准功能不变。

## 与 Issuer R2 开发的衔接
- 官网 W-01～W-14 保留；复用审核通过的视觉令牌及通用组件。新版从登录开始独立建设，旧 Issuer 作为只读历史比较。
- R2-DEV-00：只读复用/隔离审计；检查预览工具与旧版业务隔离风险。
- R2-DEV-01：新版框架+登录 UI 时同步建悬浮入口及抽屉骨架、预览环境标识，普通用户界面不会看到测试入口。
- R2-DEV-02（U01）：先覆盖登录/KYB/工作台，再加入模拟钱包/订阅状态切换和完整关联数据；U01每完成一个页面同步新增控制台可测场景和异常。
- 后续资产、权益结构、项目与Offering：扩展场景与一键关联填充，不重复造多个Mock平台。
- 审核顺序：真实用户操作（表单/校验）→ Mock外部结果 → 跨页状态一致性 → 重置/异常 → 浏览器截图/回归；演示成功不算真实外部集成通过。

## M09～M12 已确认的交互验收
- **填充当前表单**：默认仅补全空字段；覆盖手工输入前提示确认；取消时原输入不变。
- **生成完整场景**：自动创建一致的前置关联数据和状态；单项状态调整须校验前置依赖，不允许生成自相矛盾的常规状态。
- **重置**：可以仅重置当前模块，也可以重置整个演示企业；确认提示须明确指出将清理的数据范围。
- **同步开发**：只先建设当前需要的控制台框架和对应已开发业务模块的场景，不提前开发尚未设计完成的模块。

以上确认只授权形成产品文档，不代表启动代码开发、发布或真实服务集成。

## 全模块正式 UI 呈现标准与验收门（M01/M02 的执行细化，2026-11-06 用户提出）
- **正式业务内容必须按面向企业客户的最终产品呈现。** 不出现「Mock 数据」「演示数据」「原型」「测试场景」「当前仅提供入口/状态展示」「下一批交付」「开发中」等内部工程/进度说明，也不展示内部编号如 `R2`、`ISSUER WORKSPACE R2` 作为用户可见页面标题/品牌文案。必要的正式协议名称、技术专有名词除外。
- **例外仅限预览环境外围**：显式环境徽标「演示/测试环境」和右下角「测试工具」入口及其独立抽屉可以出现测试术语；所有正常业务页面主体仍使用正式产品文案和合法业务状态。正式部署隐藏测试工具。
- **入口必须有真正的下一步**：未创建企业的账户，工作台主操作为「创建并认证企业」或明确「开始企业认证」，必须进入五步 KYB 向导引导/第一步，不得跳至仅有「返回工作台」按钮的空占位页或出现循环。DEV-01 只做框架不等于五步 KYB 已交付；在五步闭环完成前不可将该用户旅程判为 PASS。
- **全局验收准则**：逐页审查标题、面包屑、导航、空状态、成功/失败/加载状态、按钮/弹窗/链接，禁止开发调试文案、不能完成的承诺与无意义跳转；检查一级任务可以顺利进入下一步，预览控制台不能混入正式业务区。业务页面未实现时不得以「完整可用」或「已通过」宣传。
- **视觉一致性**：沿用已批准的 SaaS 品牌视觉，控制不同页面的标题层级、内容宽度、卡片留白、交互对比度与中英文文案；内部代号只保留在代码/测试报告，不作为用户页面标题。
