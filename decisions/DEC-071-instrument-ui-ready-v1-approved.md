# DEC-071｜V1 权益结构单页 UI-Ready 详细规则收口

> **日期：2026-11-11**  
> **状态：Approved（依据用户授权的详细设计决策权限完成 V1 收敛）**  
> **范围：Issuer 企业 SaaS｜资产详情 → 权益结构**  
> **维护分支：docs/r2-current-product-baseline｜PR #8 Draft / Open / Unmerged**

## 1. 决策背景

现有 U02-05 已批准一资产一套当前有效 Instrument、股权/债权/收益参与三选一、单页三区域、用户填写权益总规模与 Token 份数并由系统计算每 Token 对应权利、多期 Offering 共享同一授权容量，以及固定版本文件引用等原则。

早期权益结构 UI-Ready 稿仍将主体选择、收益参与期限、预期年化收益区间、债权周期付息字段与日期规则、权益数值精度和版本修订行为标记为 Candidate/Open。用户已授权在 V1 详细设计阶段，为提高易用性而精简字段和收敛页面规则。

## 2. 正式产品决定

### 2.1 页面与公共字段

1. 权益结构唯一入口保持「资产与发行 → 资产管理 → Asset 详情 → 权益结构」TAB；不新增二级导航、独立向导或第二套并行 Instrument。
2. 保持单页面三区域：A「权益定义」、B「权益规模与 Token 拆分」、C「法律文件」；底部固定「保存草稿」「完成资料检查」。
3. 公共字段为：关联资产（自动只读）、权益类型、权益结构名称、权利责任主体、投资者获得的权利说明。
4. 权利责任主体字段按权益类型动态命名：
   - 股权：对应股权的法律实体；
   - 债权：债务人；
   - 收益参与：收益责任主体。
5. 主体可从当前 Asset 的登记权利人/资产相关方中选择，也可在 Instrument 内补录；选择或引用同一主体资料不自动推断其法律责任角色。不得自动把 Issuer、登记权利人或 SPV 等同于 Instrument 的责任主体。

### 2.2 三类权益的 V1 字段

**股权型**
- V1 仅支持普通股，不支持优先股、可转换股或分层类别。
- 必填对应股权的法律实体、普通股总数、投资者权利说明。
- 普通股总数和 Token 总份数均为正整数；每 Token 对应股份必须精确为整数股，不支持分数股。

**债权型**
- 必填债务人、债权本金总额（单位 U）、利息方式、到期日期。
- 利息方式为「无息 / 固定利率」二选一；无息不伪造 0% 利率。
- 固定利率时必填年利率、起息日期、付息方式和计息日数规则。
- 付息方式为「到期一次付息 / 周期付息」；周期付息支持每月、每季度、每半年、每年，并要求首个付息日。
- 计息日数规则支持 Actual/365 Fixed、Actual/360、30E/360、合同其他约定；合同其他约定须填写说明并标记人工核算。
- 如合同约定非工作日顺延/提前，记录合同约定；未约定时标记需人工确认。V1 不自动调用法定节假日日历或推算营业日调整。
- V1 固定到期一次还本；不支持浮动/阶梯利率、复利、复杂本金分期或自动罚息。

**收益参与型**
- 必填收益责任主体、收益来源、收益计算口径、参与起止日期、分配频率和授权参与比例。
- 分配频率为每月、每季度或每年；参与比例大于 0% 且不超过 100%。
- 不支持多层收益瀑布、优先劣后、阶梯收益或复杂费用瀑布。

### 2.3 权益规模与 Token 拆分

1. 用户只填写权益总规模与 Token 总份数；Token 总份数必须为正整数。
2. 系统只读计算每 Token 对应权利，不提供手工编辑计算结果的入口。
3. V1 表单精度：股权为整数股；债权本金 U 最多 6 位小数；收益参与比例最多 6 位小数。拆分结果必须在对应精度内精确表示。
4. 无法精确拆分时阻断 Ready；禁止四舍五入、截断或静默取整。
5. 上述是产品输入精度，不代表链上 decimals、法定股份最小单位或法律许可。
6. 多期 Offering 共用同一 Instrument 授权容量；Draft Offering 不产生有效预留；已确认占用与有效预留不得重复扣减；版本更新不增加或重置权益池。
7. 没有真实发行事件时，不显示虚构的已发行、已预留或剩余数量。

### 2.4 预期年化收益披露（DEC-059 V1 范围落地）

1. 股权型和收益参与型可选填预期年化收益区间；最低值与最高值必须同时填写，最高值不得低于最低值。
2. 填写区间时必须填写测算依据与假设；三项全部留空允许 Ready。
3. 债权固定利率直接展示合同固定年利率，不重复录入预期年化区间；无息债权不展示该区间。
4. 投资者端标注「发行方预期年化收益区间」并展示不可关闭的非承诺提示。
5. 该字段只用于信息披露，不参与 Offering 定价、Token 数量、M13 应付金额或实际收益计算；随 InstrumentVersion 固定。

### 2.5 文件、Ready 与版本

1. 三类权益各保留一项固定核心文件：股权权益协议/适用权利证明、债权协议/债权形成证明、收益参与协议。
2. Asset 文件可按 File ID + Version ID 固定引用；文件新版本不得静默替换历史引用。
3. Draft 最低要求为权益类型和权益结构名称；其他字段可暂缺并保存。
4. Ready 检查覆盖当前类型必填字段、条件字段、核心文件可引用状态及 Token 精确拆分。
5. Ready 只表示产品资料完整性检查通过，不表示法律效力、权属/债权真实性、合规许可或生产发行通过。
6. 类型切换仅在未被任何 Offering 引用时允许；切换前确认清除不兼容的类型专属字段及文件关联，但不删除文件实体。切换后回到 Draft。
7. 已被 Offering 引用的 InstrumentVersion 不得原地覆盖；通过「创建修订版本」修改允许变更的披露/说明/付息等条款并重新 Ready。权益类型、责任主体、权益总规模、权利单位和 Token 总份数不得通过修订版本改变。
8. 旧 Offering 继续引用原版本；新 Offering 只能引用最新 Ready 版本。已有认购、持仓或存续义务的 Offering 不迁移至新版本。

## 3. V1 明确不做

- 多 Instrument、多权益池、混合权益、优先劣后和复杂分层；
- 分数股、浮动/阶梯利率、复利、复杂本金摊还、自动逾期罚息；
- 多层收益瀑布、自动收益承诺和复杂费用分配引擎；
- 自动法定节假日日历、自动法律意见、自动牌照验证；
- 复杂权益类型迁移、历史持有人批量转换；
- 以预期年化区间推算实际收益或认购价格。
