> **设计日期：2026-11-11**  
> **状态：V1 企业 SaaS 产品/UI 规格完成（UI-Ready）**  
> **设计授权：用户已批准按模块独立完成 MVP 闭环，并允许在详细设计时为易用性适度精简页面组织。**  
> **适用范围：Issuer 企业 SaaS → 资产与发行 → 认购记录**  
> **维护分支：docs/r2-current-product-baseline｜PR #8 Draft / Open / Unmerged**  
> **边界：本页是已完成认购的历史查询视图，不是完整认购订单操作台；不授权真实支付、退款、配售、Mint 或生产执行。**

## 0. 设计依据与入口职责收敛

本文件承接：
- U02-02：资产与发行保留三个二级入口：资产管理、认购记录、锁仓记录；认购记录用于跨资产、跨 Offering 查询企业真实认购历史。
- DEC-069：Issuer 仅查看本企业范围内的最小必要脱敏投资者信息及平台 KYC 状态；不得查看或导出原始 KYC 资料，不承担人工 KYC 审核，不配置额外投资者资格。
- U02-06 R19～R24：认购订单、支付、Token 交付、企业结算和配售/登记是不同业务事实；只有真实支付和 Token 交付均确认，订单才显示「已完成」；订单、资金、Token 三类事实必须可对账。
- SCOPE-179～181：M10 负责唯一认购订单，M11 负责真实支付确认，M12 是容量、配售及法定登记的权威来源；Allocation、法定登记与 Token Mint/Delivery 独立验证。
- DEC-072 / U02-09：Offering 的发行条款、固定版本、最终收款钱包、文件及披露快照由 Offering 管理；本页只读取，不重复编辑。

### 0.1 两个相近入口的明确分工

为避免「认购记录」和「认购订单」重复、让企业用户知道应该去哪里：

| 入口 | 业务职责 | 包含的数据 | 可执行操作 |
|---|---|---|---|
| **资产与发行 → 认购记录** | 已完成认购的跨资产历史查询 | 付款已确认且 Token 已交付的认购订单；法定登记状态作为独立信息显示 | 只读查询、查看详情、查看 Offering、受控导出 |
| **投资者与认购 → 认购订单** | 认购订单全生命周期工作台 | 全部订单状态，包括待付款、支付核对中、待交付、已完成、异常和退款处理 | 订单详情、状态跟踪、进入有权资金/配售/Token 模块处理 |

- 两个入口引用**同一个订单编号和同一权威订单记录**，不创建两套认购主账。
- 「认购记录」只显示已完成认购；尚未付款、付款 Unknown、Token 待交付或退款处理中订单不进入本列表，统一在「认购订单」处理。
- 两个入口可以复用订单详情的只读信息区；本页不复制认购订单的操作能力。
- 已完成认购不自动代表法定持有人登记已完成；法定登记状态独立显示，以 M12 为准。

## 1. 页面目标与入口

- **使用者：** 已通过企业准入且有权查看当前 Tenant 资产/发行记录的企业账号。
- **入口：** 资产与发行 → 认购记录。
- **页面目标：** 让发行企业跨资产、跨 Offering 查询真实已完成认购，查看认购金额、Token 交付及法定登记状态，快速定位记录来源。
- 本页不是投资者管理页，不提供 KYC 审核、资格配置、投资者编辑或人工认购确认。

## 2. 页面布局与字段

### 2.1 顶部区域

- 标题：认购记录。
- 说明：查看本企业各项资产和发行方案中已完成的认购记录。
- 摘要卡片（随当前筛选条件联动）：
  1. 已完成认购笔数；
  2. 已完成订单金额合计（U）；
  3. 已交付 Token 份数。
- 摘要只汇总当前筛选范围内的权威记录；数据尚未同步完成时显示「统计更新中」，不得用 0 冒充真实结果。
- 不显示投资者个人数量、KYC 原始信息、虚构收益或未经核验的资产经营指标。

### 2.2 筛选与搜索

| 字段 | 控件 | 必填 | 规则 |
|---|---|---|---|
| 关键词 | 单行搜索框 | 否 | 支持认购订单编号、平台投资者引用编号；不支持手机号、邮箱、证件号或原始钱包地址搜索 |
| 资产 | 下拉选择 | 否 | 仅当前 Tenant 有权且存在相关记录的 Asset；默认全部 |
| 发行方案 | 下拉选择 | 否 | 可按资产联动筛选 Offering；默认全部 |
| 完成时间 | 日期范围 | 否 | 按认购完成时间筛选；开始日期不得晚于结束日期 |
| 法定登记状态 | 单选筛选 | 否 | 全部、待登记、已登记、存在差异、更正处理中、待同步 |
| 重置 | 按钮 | 否 | 清空筛选，恢复默认列表 |

- 不提供投资者类型、地区、KYC 等级、资格标签等筛选项。
- 不提供任意投资者个人信息搜索。
- 搜索与筛选同时生效；结果为空时明确区分「没有历史记录」和「没有符合条件的记录」。

### 2.3 列表字段

| 列 | 展示内容 | 数据来源 / 规则 |
|---|---|---|
| 认购订单编号 | 唯一订单编号 | M10 权威订单记录；点击进入记录详情 |
| 投资者 | 平台投资者引用编号；必要时显示脱敏展示名称 | M09 脱敏视图；不展示完整姓名、证件、联系方式或 KYC 原件 |
| 资产 | 资产名称 | Asset 关联信息 |
| 发行方案 | Offering 名称/期次 | Offering 固定快照 |
| 认购数量 | 已确认交付的 Token 份数 | M07 交付事实与 M10 订单数量核对 |
| 每 Token 价格 | 订单成立时固定单价，单位 U | 订单 QuoteSnapshot，不读取当前 Offering 最新价格覆盖历史 |
| 订单金额 | 订单成立时应付金额，单位 U | 订单 QuoteSnapshot；不把平台手续费、Gas 或企业最终结算额混入 |
| 完成时间 | 付款与 Token 交付均确认后的完成时间 | M10/M11/M07 可核验事件 |
| 法定登记 | 待登记、已登记、存在差异、更正处理中、待同步 | M12 权威登记状态；不与订单完成状态合并 |
| 操作 | 查看详情 | 只读 |

- 本页仅显示**已完成认购**；列表中付款和 Token 交付应均为已确认。
- 若 M12 法定登记尚未完成，仍保留认购记录，但单独显示「待登记」或相应状态。
- 不显示完整投资者钱包地址；如需核验链上交易，进入有权限的资金/Token 详情。
- 不显示「预期收益」「投资者总资产」等不属于认购记录的数据。

### 2.4 默认排序、分页与响应式

- 默认按认购完成时间倒序，最新完成的记录在前。
- 每页 20 条；超过 20 条显示简单分页；不提供复杂自定义排序。
- 桌面端使用表格；窄屏/手机端转为纵向记录卡片，保留订单编号、投资者引用编号、Asset/Offering、数量、订单金额、完成时间、法定登记状态和查看详情入口。
- U 金额使用统一格式；较长订单编号可复制；敏感投资者字段不因移动端而放宽显示。

## 3. 页面二：认购记录详情（只读）

### 3.1 页面结构

顶部：
- 面包屑：资产与发行 / 认购记录 / [订单编号]。
- 认购订单编号。
- 状态：认购已完成。
- 完成时间。
- 返回列表。

详情分为六个信息区：

1. **认购摘要**：订单编号、Asset、Offering、期次、认购数量、单价 U、订单金额 U、完成时间。
2. **投资者脱敏信息**：平台投资者引用编号、必要的脱敏展示名称、KYC 通过状态及核验有效时间（如平台提供）。
3. **发行条款快照**：Offering 发布版本、InstrumentVersion、每 Token 权利、认购时单价、最低认购规则、锁仓条款；历史快照不可被当前 Offering 修改覆盖。
4. **支付确认摘要**：OP Mainnet · USDT、付款已确认、确认金额 U、确认时间、支付凭证引用编号；完整交易/资金对账详情跳转至「资金与结算」。
5. **Token 交付摘要**：已交付 Token 份数、交付确认时间、交付状态；链上完整事件与对账详情跳转至「Token 管理」。
6. **法定登记状态**：登记状态、登记数量/单位、登记时间、差异/更正提示；法定登记和持有人详情跳转至「投资者与认购 → 配售与持有人」。

### 3.2 投资者隐私展示

**本页允许展示：**
- 平台投资者引用编号；
- 必要的脱敏展示名称；
- 本次认购相关的 KYC 状态（例如「平台 KYC：通过」）及必要的状态时间；
- 本企业范围内的认购、配售、登记关联信息。

**本页禁止展示或导出：**
- 完整身份证件/护照号码、完整身份识别号码；
- 身份证件、地址证明、自拍/人脸/生物识别资料；
- 第三方 KYC 原始报告、完整 Provider Payload、非必要风险细节；
- 完整手机号、邮箱、家庭/居住地址；
- 完整投资者钱包地址及可直接关联其他 Issuer 的投资者数据。

- 投资者 KYC 原始资料由平台及第三方服务商按授权范围管理；企业端不提供查看、下载、批准、拒绝或覆盖操作。
- 对于企业端确有必要查看的脱敏名称/联系方式，按最小必要原则显示；V1 默认只展示平台引用编号和脱敏展示名称，不展示联系方式。

### 3.3 状态事实分离

详情必须分开展示以下事实，不允许合并成一个「成功」标签：

| 事实 | 完成条件 | 权威来源 |
|---|---|---|
| 认购订单 | 唯一订单成立且固定订单快照 | M10 |
| 付款 | 真实 USDT 付款得到确认 | M11 |
| Token 交付 | 对应 Token 已真实 Mint/交付并得到确认 | M07 |
| 配售与法定登记 | 权威 Allocation / Register 记录成立 | M12 |
| 企业结算 | 按 Offering 固定收款钱包和适用规则确认结算 | M11 |

- 本页记录进入条件：**付款已确认 + Token 交付已确认**。
- 法定登记即使仍待处理，也不得伪装成已登记；单独显示状态和下一步入口。
- 企业结算状态不是认购完成的同义词；只有资金与结算模块的权威事实可标记已结算。
- Token 余额不能自动替代法定登记数量；差异以 M12/M07 的分别核验结果展示。

### 3.4 详情页操作

允许：
- 返回认购记录列表；
- 查看关联 Offering；
- 查看对应认购订单；
- 查看支付与资金核对详情；
- 查看 Token 交付详情；
- 查看配售与持有人登记详情；
- 复制认购订单编号。

禁止：
- 手工标记已付款；
- 手工标记 Token 已交付；
- 手工确认认购成功；
- 手工修改投资者身份/KYC；
- 手工更改认购数量、价格、订单金额或权益版本；
- 手工修改法定登记数量或 Token 余额；
- 在本页发起退款、强制转账、Burn 或资金结算。

本页发现异常时，只展示异常来源、当前状态和负责模块入口；不得在只读记录页直接改变权威事实。

## 4. 认购记录生成条件与数据边界

### 4.1 进入本页的条件

一笔认购只有同时满足以下条件，才进入「认购记录」：
1. 唯一认购订单存在，且订单条款快照有效；
2. 平台统一 KYC 通过记录有效，且适用认购前置条件满足；
3. OP Mainnet USDT 付款已得到权威确认；
4. 对应 Token 交付已得到权威确认；
5. 订单、付款、Token 数量及 Offering 固定条款能够匹配。

任何一项为 Pending、Unknown、失败或无法核对时，不得进入已完成认购记录；应保留在「投资者与认购 → 认购订单」的对应生命周期状态中。

### 4.2 各模块责任

| 业务事实 | 责任模块 | 本页处理 |
|---|---|---|
| 认购订单与订单快照 | 认购管理 | 读取订单编号、份数、价格、金额和完成状态 |
| 投资者身份与 KYC | 投资者身份与 KYC | 只读获取本企业授权范围内的脱敏引用编号和 KYC 状态 |
| 付款与退款 | 资金与结算 | 读取真实付款确认摘要；不在本页处理资金 |
| 配售与法定登记 | 配售与权威登记 | 读取登记状态；不修改登记主账 |
| Token Mint/交付 | Token 管理 | 读取真实交付结果；不执行 Mint |
| Offering 条款 | 资产与发行 | 读取下单时固定的 Offering/Instrument 快照 |
| 报表与导出 | 数据与报表 | 提供受控查询/导出能力；本页仅提供入口 |

### 4.3 订单状态与认购记录的关系

| 订单当前事实 | 是否进入认购记录 | 展示位置 |
|---|---|---|
| 订单已创建，待付款 | 否 | 认购订单 |
| 付款已提交/核对中/Unknown | 否 | 认购订单；必要时资金与结算 |
| 付款已确认，Token 待交付 | 否 | 认购订单；必要时 Token 管理 |
| 付款已确认，Token 交付失败 | 否 | 认购订单异常；资金与 Token 记录分别跟踪 |
| 付款已确认，Token 已交付 | 是 | 认购记录；法定登记状态独立展示 |
| 退款处理中/退款已确认 | 不作为新的已完成记录 | 原订单保留在认购订单历史；不删除既有记录或资金事实 |
| 数据对账差异/Unknown | 不自动进入 | 对应订单异常及资金/Token 对账入口 |

## 5. 导出与权限

### 5.1 导出

- 允许按当前筛选条件导出已完成认购记录。
- 导出字段与页面列表一致，默认脱敏；不导出原始 KYC、完整联系方式、完整证件号码或完整投资者钱包地址。
- 导出前显示确认：「将导出当前筛选范围内的已完成认购记录，投资者信息保持脱敏。」
- 导出行为进入审计记录；大批量、跨期或异常数据导出按平台/企业既有授权控制。
- 不提供单笔记录导出原始 KYC 或完整投资者档案。

### 5.2 企业套餐与认证权限

| 企业状态 | 页面权限 |
|---|---|
| KYB 通过的新 Free | 不展示模拟认购记录；显示「Free 不开放真实认购」说明及 Standard 介绍 |
| Standard 且 KYB 通过 | 可查询本企业真实已完成认购记录；导出按授权开放 |
| Standard 宽限期 | 按 U01 规则保留必要历史查询；不开放新增真实业务 |
| 降级 Free 的历史企业 | 历史真实记录只读保留；不删除、不允许修改 |
| KYB 未通过/补件/审核中 | 按企业认证统一拦截，不泄露业务详情 |

- 所有查询必须限制在当前 Tenant 和授权 Offering 范围。
- 投资者数据按 DEC-069 最小必要和脱敏规则展示；跨 Issuer 不可见。
- 不提供团队角色配置；沿用 MVP 一个账号对应一个企业的现行权限模型。

## 6. 空状态、异常与反馈文案

| 场景 | 页面提示 | 下一步 |
|---|---|---|
| Free 新企业无真实记录 |「Free 套餐不开放真实认购，因此暂时没有认购记录。升级 Standard 并满足发行准入后，可开展真实认购。」| 查看套餐 |
| Standard 尚无已完成记录 |「当前还没有已完成的认购记录。待付款或处理中订单请前往认购订单查看。」| 前往认购订单 |
| 筛选无结果 |「没有符合当前筛选条件的记录。」| 清除筛选 |
| 付款已确认但 Token 未交付 |「该笔订单尚未完成 Token 交付，不会显示为已完成认购记录。」| 前往认购订单 / Token 管理 |
| 付款状态 Unknown |「付款结果仍在核对中，暂不能认定认购完成。请勿重复收款或手工标记成功。」| 前往资金与结算 |
| Token 数量与订单不一致 |「订单数量与交付记录存在差异，已保留原始记录，等待核对。」| 前往 Token 管理 |
| 法定登记待处理 |「认购已完成，法定登记仍在处理中。」| 前往配售与持有人 |
| 法定登记与 Token 不一致 |「法定登记与 Token 记录存在差异，不能自动覆盖任一侧数据。」| 前往配售与持有人 / Token 管理 |
| 数据同步延迟 |「记录正在同步，当前列表可能尚未包含最新结果。」| 稍后刷新 |
| 无权查看 |「你无权查看该认购记录。」| 返回列表 |
| 跨 Tenant 访问 |「记录不存在或无权访问。」| 返回当前企业 |
| 导出失败 |「导出失败，当前筛选条件已保留，请稍后重试。」| 重试 |

## 7. UI-Ready 验收清单（设计目标，尚非代码测试）

| 验收项 | 设计要求 |
|---|---|
| 入口与导航 | 固定在资产与发行 → 认购记录；不新增一级或二级导航 |
| 与认购订单分工 | 仅显示已完成认购；待付款/异常/退款在认购订单工作台 |
| 搜索筛选 | 订单号/投资者引用编号、Asset、Offering、完成时间、法定登记状态 |
| 列表字段 | 订单编号、脱敏投资者、Asset/Offering、数量、价格、金额、完成时间、登记状态 |
| 详情 | 订单快照、脱敏投资者、付款、Token 交付、法定登记分别展示 |
| 完成定义 | 付款已确认且 Token 已交付；不以 KYC 通过、订单创建或支付授权替代 |
| 隐私 | 不展示或导出原始 KYC、完整证件、联系方式及完整投资者钱包地址 |
| 导出 | 当前筛选结果、默认脱敏、记录审计 |
| 空态/异常 | Free、无记录、筛选无结果、Unknown、交付失败、登记差异、同步延迟等反馈明确 |
| 权限 | Tenant 隔离；降级历史只读；不提供手工改账或人工 KYC 审核 |
| 跨模块 | Offering、资金、Token、配售与持有人均跳转权威模块，不复制主账 |

## 8. V1 明确不做

- 不在本页创建、取消、改价、确认或手工配售认购订单。
- 不在本页处理付款、退款、资金结算、Mint、Burn、冻结或强制转账。
- 不建设独立 KYC 审核页、Issuer 资格配置、投资者分级或白名单。
- 不展示或导出投资者原始 KYC、完整身份号码、完整联系方式或完整钱包地址。
