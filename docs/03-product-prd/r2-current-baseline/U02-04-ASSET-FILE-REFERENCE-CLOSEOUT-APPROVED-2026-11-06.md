## 2. D01｜资产登记权利人与发行企业不一致时的授权文件归属（收口）
1. **资产与法律权利人不得默认等同于 SaaS 租户/发行企业**；继续沿用 R18 中「同一主体/关联主体/受托或授权/其他」的关系值及关系说明。仅因主体名称不同，**不自动断言其已获得或缺少法定发行许可**。
2. 资产第③步「法律与估值 → 其他文件」应支持**添加授权/委托/主体关系证明**这一文件类别，选择后按用户已确认的选填文件方式上传；Asset 资料可链接该凭证并显示有效期、版本/状态（后两者以文书系统已有能力为准）。
3. 对**需要借助授权/委托证明发行企业有权开展后续安排**的情境，该凭证应列入**对应 Instrument/Offering 的适用发行前证明检查**，不得仅凭文本「受托/授权」视为已经合法有效。但**是否在 Asset Ready 阶段即设为条件必需、适用哪些法域/权利场景、需何种凭证、由谁认可**，仍留后续法律/产品规则审核；在批准前**不把它添加为所有资产通用的第三/第四项固定必需文件**。
4. 允许文件无有效期等情形如实保存，不能把「上传」当作「审核通过、授权有效、可发行」。

## 3. D02｜Asset 文件在 Instrument/Offering 中的固定版本引用（收口）
1. Instrument 的法律文件关联区应提供「**从当前资产已有文件选择**」的入口；选择时展示文件类型、文件名、版本、状态和可引用范围。允许同一份合规可见的 Asset 证明材料被 Instrument 或 Offering **关联到确定版本**，避免用户重复上传同一个物理文件。
2. 如 Instrument/Offering 本身需要新的权益协议、认购文书或其他专有文件，应在其业务环节**新增本对象文件**，而不是借资产权属证明替代所需发行法律文件。
3. 主文书实体及访问权限/扫描/版本仍由文件管理模块 M06 负责；Asset、Instrument、Offering 保存**有授权范围约束的文件 ID + Version ID 关联**，不是复制另一套内容/签署真相。
4. **旧引用不可静默漂移**：资产文件更换或新上传生成新版本时，不自动把已被权益/发行/投资者确认引用的旧版本替换；应提示影响、保留原引用历史、必要时触发重新检查。只有经受控新版本选择和适用确认，才能将后续有效引用指向新版本。
5. 文件未通过扫描、无可见权限、状态 Unknown/Failed/过期或失效时，应阻止错误引用或显示待检查；上传、扫描、内部核查、法律有效性不得混作一个状态。

## 4. 最小页面交互
```text
Asset / 第③步
  法定/业务必需文件（逐行显示上传按钮）
  其他文件（选填） [+添加其他文件] → 类型「授权/委托/主体关系证明」 → [上传文件]

Asset 详情 → 权益结构 TAB → 新建/编辑 Instrument → 法律文件
  [引用已有资产文件] → 选择文件/确定版本 → [确认关联]
  [上传新的权益结构专属文件] → 按已批准上传/版本/权限机制处理
```
- 能否引用在 UI 中显示明确原因；文件安全及法律有效性独立判断。
- 本批不新增一个独立的文件上传后台页面、额外审批角色或统一的「所有非同主体资产必须上传授权书」规则。
