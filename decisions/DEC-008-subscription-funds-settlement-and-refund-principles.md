# DEC-008｜认购资金、结算与退款产品原则（提案）

- 提案日期：2026-10-19
- 状态：**Proposed（待产品负责人确认；尚未批准）**
- 关联决策：DEC-001（客户独立资产门户与授权分发）、DEC-003（多资产与首期范围）、DEC-004（受监管活动责任边界）、DEC-007（投资者身份与 KYC 数据复用原则）
- 关联文档：[第 02 份《产品战略与商业模式》](../docs/02-product-strategy/RWA-SaaS-Product-Strategy-Business-Model-v01.md)
- 本提案定义软件应管理的业务状态与控制原则，不指定平台、发行方、银行、支付机构、托管方或其他合作方承担任何特定法域下的受监管职责。

## 1. 需要决策的问题

认购业务必须区分投资者提交认购意向、付款发起、资金实际到账/结算、发行方确认配售、登记更新和退款。不能将“已点击付款”“支付服务商已接收请求”“链上交易已提交”或“资金状态未知”直接视为认购成功或最终结算。

产品应提供清晰、可审计、可对账的状态管理与异常处理能力，同时避免默认由 SaaS 平台自行收取、保管、转移或控制投资资金。

## 2. 建议的产品原则（等待确认）

1. **平台默认提供工作流编排与状态记录。** 除非具体业务模式、法律意见、合同与合作方安排已明确允许，否则不将 SaaS 平台设计为投资资金的收款人、托管方或资金控制方。
2. **认购意向、付款、结算、配售、登记彼此独立。** 每个阶段使用独立状态与关联标识；上游状态变化不能未经规则校验自动跳过必要的后续步骤。
3. **状态必须来自可识别的权威来源。** 付款和结算状态应引用相应银行、支付服务商、托管方、链上网络或其他被批准的权威来源，并记录来源、事件时间、接收时间和外部引用。仅有前端操作或单方手动输入不得默认为最终资金事实。
4. **明确“未知”和“处理中”。** 超时、回调丢失、链上确认不足、服务商不可用或对账不一致时，使用待确认/状态未知等状态，允许重试查询和人工调查；不得将未知状态当成成功或失败。
5. **配售与资金确认采用显式规则。** 是否允许预留份额、超额认购、部分配售、分批付款或付款后审核，须由具体 Offering 条款和获批准业务规则确定。不得将“资金已到账”自动等同“投资者已获配售”。
6. **退款是独立业务流程。** 支持全额/部分退款（若对应业务允许）、退款申请、审核/授权、执行中、成功、失败、退回/无法送达、人工处理及对账等状态；退款发起不等于退款完成。
7. **异常处理与账务对账为首期基础能力。** 至少考虑重复回调、重复请求、支付失败、部分到账、超额/不足额付款、取消、过期、退款失败、争议/拒付（适用时）、链上重组/交易失败（适用时）、外部状态矛盾和人工纠错。关键写操作须具备幂等控制和审计。
8. **资金事实、内部账务记录与 Token/登记分别建模。** 银行/支付/托管记录、平台内部业务账本、链上交易及权威持有人登记可能不是同一个事实来源；必须支持核对与差异处理，不能以 Token 转移自动替代法律登记或资金结算。
9. **责任与权限必须可配置且可审计。** 由谁发起收款、批准退款、确认结算、执行配售、调整记录及处理差异，应按已确认的合同、角色和法律责任分配，不允许仅凭管理员权限绕过业务控制。
10. **不以产品配置代替法律批准。** 任何真实资金路径、币种、支付方式、托管/客户资金安排或跨境资金流，都必须先完成具体业务与法域的法律评估、合作方尽调、合同及上线批准。

## 3. 建议的核心对象与状态分层

| 对象/阶段 | 建议状态示例（非最终状态字典） | 关键规则 |
|---|---|---|
| Subscription / 认购意向 | Draft、Submitted、Under Review、Eligible、Rejected、Cancelled、Expired | 记录投资者、Offering、条款版本、金额/数量、时间与资格结果 |
| Payment Instruction / 付款指令 | Not Required、Pending Setup、Initiated、Processing、Unknown、Failed、Cancelled、Expired | 付款请求和真实到账是两件事；状态须关联外部引用 |
| Funds Receipt / 资金到账与结算 | Not Received、Partially Received、Received Pending Reconciliation、Reconciled、Disputed、Reversed（适用时） | 记录金额、币种、价值日/时间、来源和对账结果；未对账资金不得自动进入最终配售 |
| Allocation / 配售 | Not Started、Pending Approval、Partially Allocated、Allocated、Rejected、Cancelled、Reversed（需受控流程） | 按 Offering 规则和责任主体批准，保留数量、价格、舍入与剩余款处理 |
| Register / 持有人登记 | Pending Update、Submitted、Confirmed、Failed、Needs Reconciliation | 区分提交更新与权威登记确认，记录外部登记/链上引用 |
| Refund / 退款 | Not Applicable、Requested、Pending Approval、Processing、Unknown、Succeeded、Failed、Returned、Cancelled | 退款申请、批准、执行和资金实际退回分离；重复执行需防护 |
| Reconciliation / 对账 | Not Started、Matched、Mismatch、Under Investigation、Resolved、Escalated | 对账差异必须有负责人、证据、处置结果和审计记录 |

以上状态为讨论示例，不能直接视为最终状态机。不同资产、支付轨道和 Offering 可在统一核心模型下启用不同的合法状态，但不得删除必要的资金确认、审计和异常控制。

## 4. 必须分开的业务事实

- **认购提交成功**：系统已记录投资者的认购请求，不表示已付款。
- **付款指令已发起**：已向付款渠道提交请求，不表示资金已扣款或到账。
- **资金已收到**：外部来源报告收到资金；仍可能需要核对、确认可用性或处理退回/争议。
- **资金已对账**：外部资金事实与相关认购记录匹配；不自动意味着配售获批。
- **配售已确认**：获授权的流程已决定投资者取得对应数量/权利；不必然意味着权威登记已完成。
- **登记已确认**：相应权威登记机制确认了更新；需根据具体法律工具判断其法律效力。
- **退款已发起 / 已完成**：必须区分指令提交与资金实际退回/渠道最终确认。
- **链上交易已提交 / 已确认**：须区分交易提交、网络确认要求、最终性与权威登记的法律效力；不能只凭交易哈希认定业务完成。

## 5. 首期应覆盖的异常与控制

1. 付款渠道超时或回调未到：通过外部引用查询状态，保持 Unknown/Processing，避免重复扣款。
2. 重复回调或重复请求：幂等处理，防止重复创建付款、重复配售或重复退款。
3. 金额或币种不匹配：进入对账差异，不自动确认认购完成。
4. 部分到账、超额付款或不足额付款：按 Offering 规则进入人工/自动处理队列，不擅自推断配售或退款结果。
5. 付款成功但投资者资格未完成或被拒绝：依据事先批准的规则进入待处理/退款等流程，不将资格状态与资金状态混为一体。
6. 退款失败或外部退回：保留原认购与退款记录，升级处理，不把失败记录覆盖为成功。
7. 链上交易失败、确认不足或外部登记不同步：状态分离并执行对账/重试/人工处理。
8. 人工更正：必须记录原值、新值、原因、证据、操作者、批准者及时间；不允许直接抹除历史。
9. 客户终止或服务商切换：确保未结付款、退款、争议和对账差异有责任承接与迁移方案。
10. 所有资金相关状态与业务账本应可导出并审计；日志访问本身受权限和隐私规则约束。

## 6. 需要进一步确认的产品边界

- V1 是否只支持“外部受监管服务方处理资金，平台编排状态”，还是有经法律与合作方验证的特定资金流程需要支持？
- 资金状态的权威来源分别是什么：银行/支付服务商、托管方、链上网络、发行方财务系统或其他机构？
- 是否允许部分付款、分批结算、超额认购、部分配售与部分退款？由谁配置和批准？
- 认购资格审核发生在付款前、付款后，还是分阶段进行？失败时资金如何处置？
- 发行方取消发行、未达到募集条件、超额募集或投资者撤回时，退款触发条件和时限是什么？
- 是否支持法币、稳定币或其他数字资产作为支付方式？每种轨道的结算最终性、费用、退款可行性和责任主体不同，不能先验统一。
- 对账周期、差异容忍规则、人工升级 SLA、财务报表与审计导出要求是什么？
- 各法域下，谁负责收款、客户资金隔离、托管、支付、退款、争议处理和法定记录？须由法律意见与真实合作安排确认。

## 7. 建议的验收标准

若本提案经确认，后续产品规格至少应验证：

- 认购提交、付款发起、资金到账/对账、配售、登记和退款均有独立状态；
- 每个外部资金事件有来源、时间、外部引用及关联业务对象；
- 未知状态不会被自动视为成功/失败，且有重查、对账和升级路径；
- 重复回调/请求不会造成重复扣款、配售或退款；
- 金额、币种或外部状态不一致会阻止自动完成并生成可追踪差异；
- 退款的申请、批准、执行和完成分开记录；
- 人工修改有权限控制、原因、证据、复核与审计；
- 内部记录、外部资金事实、链上交易和权威登记可分别查询并对账；
- 未完成法律评估、合作方确认与上线批准的资金路径不能仅凭配置启用真实资金业务。
