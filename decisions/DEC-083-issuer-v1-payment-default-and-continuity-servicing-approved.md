# DEC-083｜Issuer V1 默认收款路径与降级存续服务模式（Approved）

> 决策日期：2026-11-12  
> 审核结果：投资者付款路径 A；Standard 到期后的存续义务 B。  
> 适用范围：RWA SaaS V1 Issuer 企业 SaaS；跨端仅规定必要业务数据契约。  
> 决策状态：Approved（产品业务规则）；不代表任何法律、资金、Provider、Signer 或链上生产准入。

## 一、投资者付款路径｜A

1. **默认方案：** 每个真实 Offering 优先使用经合同、法域及生产准入确认的 Offering 专用收款合约作为投资者付款目标；V1 投资者支付限定 OP Mainnet 的 USDT，平台金额统一显示 U。
2. **受控例外：** 若经有权确认该 Offering 不适用合约收款，可采用已获准的企业收款钱包或适格外部收款方；必须记录例外原因、法律/合同依据、真实收款责任主体、审核/授权状态与固定配置版本。此选择不开放任意地址输入，也不新增多方比例分账。
3. **企业结算钱包：** 每个 Offering 仍需从企业已验证钱包中选择一个最终结算收款钱包；该钱包是募集款后续合法结算目标，**不自动等于投资者当次付款目标**。即使采用收款合约，平台也不因此自动取得资金所有权、托管权或出款权。
4. **付款与 Token 交付：** 投资者确认的订单/报价及有效预留 → 合法付款指令 → 真实链上到账与订单匹配 FinalMatched → 受权配售/适用法定登记 → 按法定时序受权 Mint。链上广播、付款 Hash 或 Provider Accepted 均不构成实收或交付成功。
5. **收款配置字段：** Offering 引用与发布快照、目标类型（默认合约/受控例外）、付款目标网络/地址/Token 合约、目标对应的法律收款主体、资金控制及最终结算责任说明、收款配置版本与生效时间、批准证据、例外原因/授权、最终企业结算钱包引用/有效状态、生产准入结论、暂停/失效状态。
6. **变更与在途保护：** 已发布目标不得静默替换；历史付款指令与其目标地址/版本永久保留。合约不可用、资金主体不明、授权失效或准入 Unknown 时暂停**新增真实付款指令**，在途付款继续按原指令核对；变更必须在 Offering 受控版本流程重新批准并处理投资者重新确认。
7. **资金边界：** 募集款释放和划拨仍按 M11 独立核验合法条件及受权执行；合约收款不自动意味着配售、Mint、退款或划拨自动放行。

## 二、Standard 到期后的存续服务模式｜B

1. **触发：** Standard 过期后原有 7 天宽限期规则保持：暂停新增真实发行，既有义务继续按有权规则处理。宽限期结束仍未续费时，企业进入「已降级·存续服务」状态。
2. **角色与责任：** 维持 V1 单账号单企业；不增加内部员工、审批角色或代企业作法律决定的权限。原发行/付款/披露责任主体继续依法或依合同负责；SaaS 仅提供其有权范围内的资料提交、查询和协作，不自动变更义务主体。
3. **默认只读：** 资产、权益、发行、订单、投资者、持有人、资金、Token、收益、审计等历史信息仍可按授权只读查询；不因套餐变化删除数据、终止合法权益或将原企业重新视为新开通 Free。
4. **存续允许动作（仅与降级前已形成的合法 Offering/义务关联）：** 提交既有发行的必要披露文件与说明；提交收益/本息上报、合法计算依据与更正资料；上传已发生付款/注资凭证并申请核验；对现有退款、欠款、清退、合同到期、异常、补件及责任交接提交必要证据或响应；查询受权业务状态、法定义务及未结事项。所有动作都按原领域守卫和独立合法权限执行，**提交并不等于审批、付款、法律登记或 Token 操作成功**。
5. **严格禁止：** 新建或编辑 Asset/Instrument/Offering 并开展新发行；对外发布新门户或新募资；新建真实认购、追加发行、任意转账、Mint/Burn/解锁、收款目标变更、资金划拨，或恢复任意普通 Standard 写权限。已在途的合法资金/链上任务只保留查询和合规履约所必需的受控协作。
6. **最小交互：** 原导航仍可见；历史页面只读。顶部固定状态「已降级 · 存续服务」和订阅恢复入口；在涉及现有义务的原详情页，仅显示「提交履约资料」「补充凭证」「响应异常」等适用动作，不新增一级或二级导航、不复制领域主账。无可履行义务时仅保留历史查询与订阅恢复。
7. **按钮守卫：** 操作必须绑定当前 Tenant + 已存在 Offering + 具体既有义务/事件编号 + 已生效权限及证据；无对应义务、跨企业、超出允许类型、资格/授权失效、Unknown 或冲突时阻断，并显示原因和可用后续入口。任何真实支付、法律登记、Token 执行仍须由有权主体通过独立生产准入。
8. **升级恢复：** 续费并满足有效 KYB、业务及生产准入后才能按 Standard 恢复适用写权限；存续期间提交的资料、版本与真实事件保留历史，不重置法律义务或订单。
9. **商业与法务开放项：** 存续服务是否单独收费、法域/合同中的最低必要动作清单、具体承接 SLA/通知与责任条款，尚未另行批准；V1 UI 不提前展示服务费、不自动赋予 SaaS 资金或法定代理权限。若某项必要操作依法不能由该账号提交，显示责任主体与协作/支持入口，而非绕过法定权限。

## 三、跨文档一致性与验收

- Offering：默认合约收款目标、受控例外、配置快照、失效暂停及历史付款指令保护；Free/降级均不可新发布。
- 资金与结算：支付目标与企业最终结算钱包分开，FinalMatched 与资金释放/划拨分开。
- U01 订阅：宽限期、降级历史只读与受限存续提交并行；不能把存续模式理解成普通 Free 写权限。
- 收益与分配/共享能力：仅在原领域详情绑定既有义务开放资料/凭证/异常响应；收益支付、法定登记和 Token 真实执行仍归权威主体。
- 端到端审计：以上两项原待决策门改为「产品规则已批准」，外部合法收款、钱包身份映射、生产准入及费用/法务细则仍作为单独依赖。

## 四、治理

本 DEC 仅确认用户明确选择的 A / B 以及为实现其最小 UI-Ready 闭环所必需的交互边界。不新增正式功能 ID，不改动 Frozen、历史 DEC/SCOPE、193 项主表或已批准 V1 功能归属；不关闭 X-01～X-13；PR #8 保持 Draft/Open/Unmerged。不得因本 DEC 进入真实生产执行。
