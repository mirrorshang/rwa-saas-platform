# DEC-058｜USDable 功能参考审计后的 V1 功能取舍与详细设计批准

> 日期：2026-11-09  
> 状态：**Approved｜用户明确确认**  
> 依据：用户个人 Library《USDable Mock 网站浏览器产品体验与审计报告》v1.0（2026-11-05）及本轮产品确认  
> 维护分支：docs/r2-current-product-baseline｜PR #8 Draft / Open / Unmerged

## 1. 决策目的与比较原则

本决策将 USDable 已审计的产品功能列表、页面组织、字段点和操作流程作为 RWA SaaS 的产品参考，用于判断 V1 是否需要相应能力。

- 不以 USDable 是否真正完成生产级实现、是否打通真实资金/链上交易、是否通过完整端到端测试，作为是否参考其功能设计的判断前提。
- 仍以原始审计报告中实际可见的导航、功能入口、字段和操作说明为证据来源；不重新访问外网、不重新测试 USDable。
- 不因参考 USDable 而复制其资产模型、套餐、资金主账、角色权限或二级交易设计。
- 优先复用 RWA SaaS 已批准的 M04/M07/M12/M13 等模块责任，不重复建立业务主账、不随意新增正式功能 ID。

## 2. 本轮用户明确确认的取舍

| USDable 功能点 | RWA SaaS 决策 | V1/V2 归属与责任 |
|---|---|---|
| 收款方名录 | V1 不建立独立收款方名录。每个 Offering 在发行配置中选择并确认一个企业已配置、有效的钱包作为该 Offering 的最终收款钱包 | V1 沿用 U01/U02 的企业钱包及 OfferingReceivingWallet 规则 |
| 多收款方、比例分账 | 保留扩展方向，V1 不做多受益方比例分账 | V2；后续在 M11 收款安排中扩展，不改变 V1 单一 Offering 收款钱包 |
| 使用型权益 Right / Usage Right | V1 不支持使用型权益；继续使用已批准的股权、债权、收益参与权三类 Instrument | V2；需另行定义使用额度、核销/消费、期限和履约对象 |
| 发行方收益上报 | V1 补齐 Issuer 手动收益上报 UI、字段、状态和与收益计算/注资/实付的衔接 | 现有 M13-F001/F003/F004/F005/F009 等责任内细化，不新增正式功能 ID |
| 发行方清退/兑付申请 | V1 补齐清退/兑付计划的申请、审核、计算、注资和投资者结算进度 | 现有 M13-F004/F006/F007/F009，并与 M12/M07 权威事实衔接，不新增正式功能 ID |
| 持有人管理 | V1 细化持有人查询、详情、法定登记与 Token 对账、限制状态和受权处理入口 | 现有 M12-F006/F007/F008、M07-F006/F007/F008、M17/M20/M21；不新增正式功能 ID |
| Authenticator / TOTP 双因素认证 | 不增加，不作为 V1 功能缺口 | U01 已批准的邮箱验证码登录方式保持不变 |
| 更完整的资产相关方 | V1 补齐适用的资产相关方角色和结构化信息字段 | M04-F004 及 Asset 模板字段内细化；SPV/托管方/受托方等按实际情况条件化，不设为所有资产必填 |
| 套餐资产数量配额 | 不采用 USDable 的基础 2 个/高级 5 个/定制 10 个资产数量限制；不新增套餐档位 | 严格以 U01 E09 Free / Standard 已批准权益矩阵为准 |

## 3. Free / Standard 套餐权威规则

U01-UI-Ready-PRD 的 E09（2026-11-06）及 U01-FREE-STANDARD-ENTITLEMENT-DEC-2026-11-06.md 是套餐与权益的唯一现行权威；USDable 套餐页不覆盖、不修改该矩阵。

- Free：免费；KYB 通过后可创建、编辑、保存正式 Asset、Instrument 和 Offering 业务资料；可进行内部只读投资者门户预览；不可发布真实发行、部署/Mint、公开上架、配置/生成对外投资者门户、认购募资、形成真实持仓或开展真实收益运营。
- Standard：固定月付/年付；同样必须完成 KYB；可在适用业务、法律、Provider、Signer、网络、资金和安全生产准入通过后，配置/发布真实投资者门户、发布 Offering 并开展真实发行及后续运营。
- Free 与 Standard 均可配置企业钱包；两者在资产、权益结构和 Offering 资料准备能力上相同。
- 不新增 Asset 数量、Offering 数量或 Token 总量硬配额；不照搬 USDable 基础版 2 个、高级版 5 个、定制版最多 10 个的额度模式。
- Standard 付费本身不等于真实发行、资金、Token 或收益生产能力自动获准。

## 4. V1 UI-Ready 细化范围

以下内容通过独立的《USDable 功能参考｜RWA SaaS V1 采纳项与 UI-Ready 补充规格》落地：

1. **M13 收益上报**：发行方选择资产/权益结构/发行方案及收益类型，填写收益期间、权益记录日、金额（U）、说明、无收益声明和凭证；提交后进入复核、权益快照、计算、分配批次、真实注资及 Claim/Push 对账。收益上报不等于应付、已注资或已实付。
2. **M13 清退/兑付申请**：仅允许 Instrument/Offering 已批准的合同到期、合同允许的提前赎回、合法回购/公司行动或其他有依据的结算；支持按单位金额或总金额申报、材料、审核、计算、注资和投资者结算进度。退款仍属于 M11，不得混入 M13。
3. **M12 持有人管理**：在既有「投资者与认购 → 持有人登记」页面责任内补齐查询列表、筛选、详情、法定登记/Token 对账、限制状态和审计入口。M12 法定登记是权威权益来源，M07 Token 余额是独立链上事实。
4. **M04 资产相关方**：在 Asset 法律与估值资料中补充资产持有主体/SPV、托管方、受托方、资产管理/运营主体、估值机构及其他实际相关方；以条件字段表达，不要求所有资产具备全部角色。

## 5. 明确不采纳或后置的 USDable 功能

- 多收款方名录、按比例分账：V2。
- Usage Right / 使用型权益：V2。
- Authenticator / TOTP 2FA：不纳入 V1。
- USDable 套餐资产数量配额：不纳入 V1；继续执行 Free / Standard。
- 持有人强制转账：不纳入 V1；V1 只提供必要的受权限制处理流程，不能直接改变法律持有人或绕过 M07/M12。
- AMM、C2C、订单簿、公开二级交易、流动性池、成交撮合：不属于本次 V1 功能采纳范围，继续按既有版本边界管理。
- USDable 的邮箱+密码注册/登录、忘记密码和修改密码流程不复制；RWA SaaS 继续采用 U01 邮箱验证码登录。

## 6. 不变量与责任边界

- 每个 Offering 在 V1 选择一个企业有效钱包作为最终收款钱包；变更按既有受控规则执行。收款钱包不是收款方名录，也不代表平台托管客户资金。
- M13 负责发行后收益/本息/清退事件、计算、批次、注资和实付对账；M11 负责投资者认购款、退款和募集款结算；两者不得共用或混淆资金主账。
- M12 负责配售和权威法定持有人登记引用；M07 负责 Token、合约及链上事实；持有人页面只能聚合展示，不得产生第二套登记或 Token 主账。
- M04 Asset 相关方与 Instrument/Offering 发行人、债务人、担保人、付款义务方、收款钱包等不同概念分离；不得把资产相关方自动推断为法律付款人或 Token 签名人。
- 资产相关方角色不是所有资产的固定必填项；SPV、托管方、受托方仅在真实结构适用时记录。
- 冻结、限制、解冻等涉及法律/合约效力的操作必须有适用依据、受权审批、M17 任务和 M20 审计；需要链上限制时由 M07 及适格 Signer 执行。Issuer 不得直接强制转移持有人权益。
- 真实法律效力、法定登记、真实资金、Provider、Signer、合约和生产准入仍须单独满足，不因本次 UI-Ready 补充而自动获准。
