# RWA SaaS｜Platform Admin P-14：平台数据与报表 UI-Ready 产品规格（Draft v0.1）

> **文档状态：Draft｜2026-11-19**
>
> 本文细化平台总后台「09 数据与报表」P-14。定位为平台商业经营、统一投资渠道运营、M 投资者服务、平台运营质量的只读统计分析入口。
>
> 本规格不建立第二套业务账，不把 Issuer 端 M21 报表整体复制到平台后台，也不授予平台跨 Tenant 查看投资者、订单、资金、法定登记、Token 或收益明细的权限。

## 0. 范围与权威边界

### 0.1 P-14 的职责

P-14 提供跨平台运营所需的历史趋势、聚合指标、受控筛选和导出申请。与 P-01 的区别：

- **P-01 平台工作台**：当前时点的运营快照、待办、异常预警和少量关键指标，回答「现在发生什么、我下一步做什么」。
- **P-14 数据与报表**：按时间范围分析趋势、比较周期、查询已批准的聚合指标，回答「过去发生了什么、变化趋势如何、运营效果怎样」。

P-14 不承担实时交易操作；不允许在报表中修改任何业务状态。

### 0.2 四类报表

| 报表页签 | 主要数据来源 | 平台可查看内容 |
|---|---|---|
| 商业经营 | M03、M01、M17 | SaaS 客户申请、商业 KYB 状态分布、Tenant 服务状态、Free/Standard 分布、订阅及平台 SaaS 商业收费统计 |
| 统一投资渠道 | M23、M17、M18 | Offering 上架申请、审核结果、自动上架结果、Listing 状态变化、投诉/异常数量及处理趋势 |
| 投资者服务 | M24、M18、M22 | M 统一投资者账户数量、KYC 服务状态分布、状态同步异常、投资者服务通知统计 |
| 平台运营质量 | M17、M18、M20、M22 | 任务处理效率、通知投递状态、Provider 健康/异常、平台安全事件汇总 |

### 0.3 明确不属于 P-14 的报表

以下是 Issuer 业务报表，不因 P-14 存在而转移到平台后台：

- Issuer 的 Project/Offering 发行额度、认购订单、投资者明细及资格统计；
- 投资者认购款到账、退款、受限资金、可结算资金和实际划拨；
- 配售、法定持有人登记、Mint/Token 交付与差异；
- 收益应付、注资、领取、实付、本金余额和逾期；
- 跨 Issuer 投资者关系、个人持仓或交易历史。

上述业务的权威分别属于 M04/M05/M06/M07/M09/M10/M11/M12/M13 等原领域；Issuer 端 M21-F001～F006 继续由 Issuer 授权用户使用。P-14 不复制这些报表，不建立平台级金融主账。

### 0.4 全局安全规则

- 默认只展示平台运营所需的聚合统计，不展示个人 KYC、完整身份资料、单笔投资者订单或资金明细。
- 默认不提供按任意 Tenant/Issuer 穿透查询的能力；必要的个案处理从 P-02～P-18 原业务入口跳转并重新鉴权。
- 任何跨 Tenant 维度、敏感字段、可识别个人的查询或导出均受 M20 权限控制；前端隐藏不是授权。
- 小样本统计存在重识别风险时，按平台批准的最小样本阈值抑制展示；阈值未批准前不得在生产启用可导致重识别的细分维度。
- 报表只读。数据源 Unknown、延迟或缺失必须明确标注，不得把缺失当成 0、把 Unknown 当成失败或成功。
- 导出通过 M20-F007 受控申请/审批并记录于 P-12；P-14 不提供绕过审批的直接下载。
- 所有金额按来源币种分别统计；不混加不同币种、不擅自汇率换算。平台 SaaS 商业收费与投资者认购资金必须分开。

## 1. 页面结构与共用交互

### 1.1 页面结构

P-14 是一个一级导航下的报表工作区，使用四个页签，不新增多个一级导航：

1. **商业经营**
2. **统一投资渠道**
3. **投资者服务**
4. **平台运营质量**

每个页签采用统一的「筛选区＋指标卡＋趋势图＋统计表」结构。需要处理具体对象时，点击有权查看的汇总行跳转对应 P 页面，而不是在 P-14 内展开敏感业务详情。

### 1.2 共用筛选区

| 字段 | 控件 | 选项/校验 |
|---|---|---|
| 统计时间 | 日期范围 | 今天、近 7 天、近 30 天、近 90 天、自定义；开始时间不得晚于结束时间 |
| 对比周期 | 下拉 | 不对比、上一等长周期、去年同期（仅数据源支持时） |
| 统计时区 | 下拉 | 默认平台配置时区；显示具体时区标识，不允许静默切换 |
| 统计粒度 | 下拉 | 日、周、月；根据所选范围限制可用粒度 |
| 数据范围 | 只读标签 | 平台级聚合；若当前权限仅限部分范围，明确显示受权范围 |
| 数据更新时间 | 只读 | 显示各数据源最近更新时间及整体生成时间 |

默认时间范围：近 30 天；默认粒度：日。页面首次加载使用当前用户有权访问的默认范围，不自动加载跨 Tenant 明细。

操作：
- 「查询」：应用筛选条件；
- 「重置」：恢复默认时间范围、时区及粒度；
- 「申请导出」：提交 M20 受控导出申请；无权限时不显示；
- 「查看数据口径」：打开当前报表指标定义弹窗；
- 「刷新数据」：仅重新读取已提供的报表快照/读模型，不触发业务操作。

### 1.3 共用状态与异常

| 状态 | 页面表现 | 操作 |
|---|---|---|
| 加载中 | 骨架屏，保留筛选条件 | 不重复提交相同查询 |
| 数据可用 | 展示指标、图表、更新时间 | 可筛选/查看口径 |
| 部分延迟 | 对受影响指标显示延迟标签与数据源时间 | 可刷新或查看数据源状态 |
| Unknown | 显示「待核实」，不显示为 0 | 跳转相关 P-07/P-13 查询 |
| 数据不足 | 显示「暂无足够数据」 | 不生成误导性趋势线 |
| 无权限 | 显示无权访问及权限申请入口（如适用） | 不泄露该数据集是否存在 |
| 查询失败 | 保留上次成功结果并标注其统计时间，不冒充最新 | 可重试 |
| 导出审批中 | 显示 Export Request ID 与状态 | 查看 P-12 审批记录 |

## 2. P-14-01｜商业经营报表

### 2.1 目标

分析 SaaS 商业客户获取、商业 KYB、Tenant 服务状态、Free/Standard 套餐分布与平台 SaaS 收费情况。该报表不代表 Issuer 发行资产的募资或投资者资金。

### 2.2 指标卡

| 指标 | 统计口径 | 数据来源 |
|---|---|---|
| 新增 SaaS 客户申请 | 所选时间内首次提交的有效客户申请数；撤回/重复提交按唯一申请 ID 去重 | M03 |
| 商业 KYB 通过 | 所选时间内首次进入审核通过状态的申请数 | M03 |
| 新增 Tenant | 所选时间内创建成功的唯一 Tenant 数；Free→Standard 不新增 Tenant | M01/M03 |
| 当前有效 Tenant | 统计截止时点服务状态有效的 Tenant 数 | M01 |
| Free Tenant | 截止时点处于永久 Free 且服务可用的 Tenant 数 | M01 |
| Standard Tenant | 截止时点 Standard 商业权益有效的 Tenant 数 | M01 |
| Standard 订阅收费确认 | 所选时间内已由 M01 确认的 SaaS 商业收费金额，按币种分别列示 | M01 |

不提供「Trial」指标；当前商业版本为永久 Free + 付费 Standard。

### 2.3 图表与统计表

图表：
- SaaS 客户申请趋势；
- 商业 KYB 提交/通过/补件/拒绝趋势；
- Tenant 新增与服务状态趋势；
- Free/Standard 当前分布（截止时点快照）；
- Standard 商业收费确认趋势（按币种分图/分组，不混合）。

统计表字段：
- 时间周期；
- 新增申请数；
- KYB 待审核/补件/通过/拒绝数；
- 新增 Tenant；
- Free Tenant 数；
- Standard Tenant 数；
- 服务受限 Tenant 数；
- Standard 收费已确认金额（币种分列）；
- 收费 Unknown/待核实笔数（如来源可提供）。

### 2.4 口径与保护

- 申请数按唯一申请 ID 计数；重复提交、补件重提不重复计作新客户。
- Tenant 数按统计时点快照，不将周期内新增数与当前存量混为一谈。
- Free 永久有效，不设置到期、恢复窗口或自动只读。
- Free 升级 Standard 沿用原 Tenant；不得计作新增 Tenant。
- Standard 收费仅统计 SaaS 平台商业账单；不包含投资者认购款、资产出售款、退款或收益出款。
- 订阅金额 Unknown 时单列，不纳入已确认收入。
- 多币种金额不汇总成一个无币种总额；不自动换算。
- KYB 通过不代表资产、证券或 Offering 获得发行批准。

跳转：
- 客户申请/KYB 汇总 → P-02/P-03；
- Tenant/Free/Standard 汇总 → P-04/P-05；
- 商业收费异常 → P-06；
- 平台任务异常 → P-07。

## 3. P-14-02｜统一投资渠道报表

### 3.1 目标

分析企业自愿提交至 M 统一投资渠道的 Offering 申请、平台审核效率、审核通过后自动上架成功率、Listing 状态变化及渠道投诉/异常趋势。

P-14 提供跨 Listing 的运营汇总；具体 Offering 审核、Listing 状态、投诉和单项异常仍由 P-15/P-16/P-17 管理。

### 3.2 指标卡

| 指标 | 统计口径 | 数据来源 |
|---|---|---|
| 新增上架申请 | 所选时间内提交的唯一 Application 数 | M23 |
| 审核通过 | 所选时间内审核状态首次进入 Approved 的申请数 | M23 |
| 补件/拒绝 | 所选时间内首次进入对应结果的申请数，按唯一申请计数 | M23 |
| 自动上架成功 | 审核通过后系统成功创建唯一 Listing 并发布 M 的申请数 | M23 |
| 自动上架异常 | Listing 创建/发布为 Failed 或 Unknown 的申请数，分状态列示 | M23/M17 |
| 当前展示中 Listing | 统计截止时点渠道状态为展示中的唯一 Listing 数 | M23 |
| 暂停/下架 Listing | 截止时点分别处于暂停/下架状态的唯一 Listing 数 | M23 |
| 渠道投诉/异常 | 所选时间内登记的唯一投诉/异常记录数 | M23/M17 |

### 3.3 图表与统计表

图表：
- 上架申请及审核结果趋势；
- 审核处理时长分布（仅在提交/决定时间戳完整时展示）；
- 审核通过→自动上架成功/失败/Unknown 漏斗；
- Listing 当前状态分布；
- 投诉/异常数量与处理趋势。

统计表字段：
- 时间周期；
- 新增申请；
- 待审核；
- 补件；
- 审核通过；
- 审核拒绝；
- 自动上架成功；
- 自动上架失败；
- 自动上架 Unknown；
- 当前展示中；
- 当前暂停；
- 当前下架；
- 新增投诉/异常；
- 未解决投诉/异常。

### 3.4 口径与保护

- 一次申请只按唯一 Application ID 计数；补件、复核不重复计作新申请。
- 自动上架成功只以系统确认的唯一 Listing 创建及发布结果为准；「审核通过」本身不直接算上架成功。
- Unknown 单独列示，不纳入成功或失败。
- Listing 当前状态是截止时点快照；状态变化趋势按事件时间统计。
- 不展示认购金额、投资者人数明细、订单、配售、资金、持有人、Token 或收益数据。
- 不把 Listing 浏览量、点击量、成交额或募资额作为默认指标；只有来源已批准且定义明确时才可另行加入。
- 投诉/异常只统计平台渠道责任范围，不推断 Issuer 的法律责任。

跳转：
- 申请/审核 → P-15；
- Listing 状态 → P-16；
- 投诉/异常 → P-17；
- 任务与异常 → P-07。

## 4. P-14-03｜投资者服务报表

### 4.1 目标

了解 M 统一投资者账户服务规模、KYC 服务状态分布、状态同步和服务通知异常。该报表不是投资者投资行为分析，也不是跨 V 门户投资者数据库。

### 4.2 指标卡

| 指标 | 统计口径 | 数据来源 |
|---|---|---|
| 当前 M 账户总数 | 截止时点存在且未删除的唯一 M Investor Account 数 | M24 |
| 新增 M 账户 | 所选时间内创建成功的唯一账户数 | M24 |
| KYC 已通过 | 截止时点平台权威 KYC 状态为 Passed 且有效期未过的账户数 | M24/Provider |
| KYC 待处理 | 截止时点为 Pending/Review 等已定义状态的账户数 | M24/Provider |
| KYC 未通过/已拒绝 | 截止时点为 Failed/Rejected 的账户数 | M24/Provider |
| KYC 已过期 | 已通过但有效期已过的账户数 | M24/Provider |
| KYC Unknown/同步异常 | 平台无法确认最新权威状态的账户数 | M24/M22 |
| M 账户服务受限 | 截止时点 M 账户处于平台服务限制状态的账户数 | M24 |

不提供投资者资格等级、专业/合格投资者分类、投资额度或独立资格审核指标。

### 4.3 图表与统计表

图表：
- M 账户新增趋势；
- KYC 状态分布；
- KYC 状态变更趋势；
- KYC Provider 同步异常趋势；
- M 账户服务受限/恢复趋势。

统计表字段：
- 时间周期；
- 新增 M 账户；
- 当前 M 账户；
- KYC Passed（有效）；
- Pending/Review；
- Failed/Rejected；
- Expired；
- Unknown/同步异常；
- 账户服务受限；
- 通知发送失败（如来源可关联）。

### 4.4 口径与保护

- 仅统计 M 统一投资者账户；不统计 Issuer V 门户内所有投资者，也不合并 M/V 账户。
- KYC 状态以平台接收并验证的权威 Provider 结果为准；Unknown 不得当作 Passed 或 Failed。
- KYC Passed 只表示 KYC 状态通过且有效，不代表某 Offering 的投资资格、适售性或交易批准。
- 不显示姓名、证件号、国籍、生日、证件原件、KYC 报告或 AML/制裁细节。
- 不按单个投资者展开，不提供个人投资记录、持仓或订单。
- 需要处理具体账户问题时，跳转 P-18 并重新校验权限。

跳转：
- M 账户服务状态 → P-18；
- KYC Provider 同步异常 → P-13/P-07；
- 通知投递异常 → P-08；
- 敏感访问证据 → P-11/P-12。

## 5. P-14-04｜平台运营质量报表

### 5.1 目标

衡量平台任务、通知、外部服务及安全事件的处理质量，帮助运营负责人识别积压、故障和重复异常。该页签只统计协作模块状态，不替代原业务处理结果。

### 5.2 指标卡

| 指标 | 统计口径 | 数据来源 |
|---|---|---|
| 新增平台任务 | 所选时间内创建的唯一 M17 Task 数 | M17 |
| 当前未关闭任务 | 截止时点未关闭/未拒绝的任务数 | M17 |
| 已超期任务 | 仅统计原任务提供明确截止时间且截止时点已过的任务 | M17 |
| 平均处理时长 | 已关闭任务从创建到关闭的时间均值；排除缺失时间戳并标注样本数 | M17 |
| 通知发送失败 | 所选时间内状态为 DeliveryFailed 的唯一通知数 | M18 |
| 通知 Unknown | 所选时间内发送结果为 Unknown 的唯一通知数 | M18 |
| Provider 不健康连接 | 截止时点状态为 Degraded/Unavailable/Unknown 的连接数 | M22 |
| 未解决安全事件 | 截止时点尚未解决/关闭的安全事件数 | M20 |

### 5.3 图表与统计表

图表：
- 平台任务新增/关闭趋势；
- 任务类型与状态分布；
- 任务处理时长分布；
- 通知发送成功/失败/Unknown 趋势；
- Provider 健康状态趋势；
- 安全事件严重程度与处理趋势。

统计表字段：
- 时间周期；
- 新增任务；
- 关闭任务；
- 当前未关闭；
- 已超期；
- 平均处理时长；
- 通知 DeliveryFailed；
- 通知 Unknown；
- Provider Degraded/Unavailable/Unknown；
- 新增安全事件；
- 未解决安全事件。

### 5.4 口径与保护

- 任务关闭只代表平台协作任务关闭，不代表原业务完成。
- 平均处理时长只使用可核实的创建/关闭时间；不以估算 SLA 替代真实时间。
- 原任务无截止时间时不计入超期任务。
- 通知 Sent/ProviderAccepted/Viewed/DeliveryFailed/Unknown 分开统计；不得将 Sent 解释为法律送达。
- Provider 健康状态按截止时点统计；探测缺失/Unknown 不得当作健康。
- 安全事件数量只反映平台登记/检测事件，不等于所有安全风险的完整数量。
- 不展示敏感事件原始 Payload、密钥、KYC 原件或其他 Tenant 的详细审计内容。

跳转：
- 任务异常 → P-07；
- 通知失败 → P-08；
- Provider 连接 → P-13；
- 安全事件 → P-12。

## 6. 数据口径、时间基准与质量

### 6.1 指标元数据

每个指标在「查看数据口径」中必须显示：
- 指标名称及唯一 Metric Code；
- 业务定义；
- 统计对象/去重主键；
- 计算公式或状态筛选条件；
- 数据源领域及字段/事件引用；
- 统计时间字段（Created At、Effective At、Decision At、Snapshot At 等）；
- 时区；
- 是否为期间累计或截止时点快照；
- 是否排除 Unknown/撤回/重复记录；
- 最近成功更新时间；
- 当前数据延迟/完整性状态；
- 责任业务模块。

### 6.2 统计时间规则

- 趋势指标按事件/业务生效时间统计；存量指标按所选截止时点快照统计。
- 页面明确区分「期间发生数」与「当前存量」，不把两者放在同一图表中直接相加。
- 所有时间显示时区标识；源系统使用不同时间基准时，展示原始权威时间和报表转换时区。
- 迟到事件到达后可按读模型刷新规则修正历史统计，但必须显示数据更新时间，不静默覆盖已导出快照。
- 比较周期必须是等长周期；不完整数据源不展示误导性同比/环比。

### 6.3 金额、币种与精度

- SaaS 商业收费使用 M01 原始账单金额、原始币种及确认状态；不同币种分开列示，不擅自换算。
- 投资者认购款、退款、收益/本金付款不进入 P-14 平台商业收入指标。
- 数量按原始对象唯一 ID 去重；金额保持源领域原精度，不二次舍入造成差异。
- Unknown、待确认、失败、已确认分别呈现；不得把「已提交」「Provider 已接收」当作到账或已收款。

### 6.4 数据延迟

- P-14 不承诺所有指标实时更新。
- 各数据源单独显示 Last Updated / Data As Of；整体更新时间不得掩盖单个数据源延迟。
- 某数据源超过其已批准更新窗口时，显示「数据延迟」；更新窗口未配置时显示「更新频率待确认」，不得自行承诺分钟级/SLA。
- 数据源不可用时保留最近一次成功快照并明确标注时间；不以空值覆盖成 0。

### 6.5 数据质量异常

| 异常 | 页面处理 |
|---|---|
| 重复事件 | 按原业务唯一 ID/幂等键去重；无法去重时标记质量异常 |
| 缺少关键时间戳 | 不纳入时长指标，显示排除样本数 |
| 状态 Unknown | 单独展示，不强行归入成功/失败 |
| 事件迟到 | 更新数据时间并标注历史修正 |
| 数据源不完整 | 标注部分数据，不显示完整率 100% |
| 来源字段冲突 | 以原领域权威状态为准，生成 P-07/P-13 核查入口 |
| 汇总与明细不一致 | P-14 不修正明细；保留差异并跳转原业务领域核查 |

## 7. 受控查询与导出

### 7.1 默认查询

- 只提供四类报表中定义的固定指标与固定维度。
- 不提供任意 SQL、自由字段选择、跨 Tenant 联表或自定义查询构建器。
- 不允许以 P-14 查询个人 KYC、订单、资金、持仓、登记或 Token 明细。
- 需要查看具体对象时跳转原业务页面并重新鉴权；P-14 不绕过原业务页面授权。

### 7.2 导出申请字段

点击「申请导出」后进入标准页面/弹窗，字段：
- 导出申请编号（系统生成）；
- 报表类别；
- 统计时间范围；
- 时区；
- 选定指标/固定字段；
- 数据范围（平台聚合或已批准范围）；
- 导出用途（必填）；
- 合法依据/业务目的（必填）；
- 文件格式（CSV/XLSX，按平台已批准格式）；
- 是否包含敏感维度（默认否；需更高审批）；
- 期望有效期（仅提供已批准选项）。

提交后通过 M20-F007 进入受控审批；P-12 展示申请、审批、生成、下载、过期与撤销审计。

### 7.3 导出状态

- Draft：草稿；
- Submitted：已提交；
- PendingApproval：待审批；
- Approved：已批准待生成；
- Generating：生成中；
- Ready：可下载；
- Downloaded：已下载；
- Expired：已过期；
- Rejected：已拒绝；
- Revoked：已撤销；
- Failed/Unknown：生成/下载结果失败或待核实。

Unknown 时不重复创建导出，不允许显示下载成功。下载链接必须短时有效、绑定申请人和授权范围，不能转发。

### 7.4 导出保护

- 默认只允许导出聚合结果；禁止完整 KYC、跨 Tenant 业务明细、投资者订单/资金/持仓、客户密钥和敏感审计原文。
- 导出字段与审批范围一致；生成后不得扩大字段。
- 下载必须重新验证用户、权限、时效与申请状态。
- 到期/撤销后立即阻断下载；保留历史导出元数据和审计记录。
- 导出文件包含生成时间、统计时区、数据截止时间、指标口径版本和权限范围说明。
- 受控导出审批、访问和下载记录进入 P-12，不由 P-14 自建审计主账。

### 9.2 桌面 Web 验收用例

1. P-14 与 P-01 分工清楚：P-01 展示当前快照，P-14 提供历史趋势与报表查询。
2. 四个报表页签均可使用统一筛选区，切换页签不会错误丢失/污染时间范围。

8. 投资者服务统计只覆盖 M 统一投资者账户，不合并 V 门户账户。
9. KYC Unknown/Expired/Pending 不得计入有效 Passed。
10. P-14 不展示个人 KYC、单笔订单、资金、持仓、法定登记、Token 或收益明细。
11. 任务关闭、通知已发送、Provider 恢复不被统计为原业务完成。
12. 不同币种不混合汇总；金额保留来源精度。
13. 数据延迟、部分缺失、Unknown、查询失败均有明确状态，不把缺失当作 0。

15. 无 M20 导出授权时不显示直接下载；导出申请可关联 P-12 审批和审计记录。
16. 导出过期/撤销后下载阻断；历史申请和下载记录仍可查。
17. 未执行用例标记 Not Executed，不得标记 PASS。

## 10. 与 M21/M20 的关系及版本边界

- P-14 是平台总后台的报表呈现入口，不新增正式 M 功能 ID。
- M21-F001～F006 的 Issuer 业务报表仍由 Issuer 授权人员使用；P-14 不复制 Project/Offering、投资者/订单、资金、登记/Token、存续收益报表。
- P-14 仅消费平台有权查看的 M03/M01/M17/M18/M20/M22/M23/M24 状态和已批准聚合读模型；具体数据权威仍归原业务模块。
- M20-F001 Tenant 隔离、M20-F007 受控导出和 M20 审计规则适用于全部 P-14 查询与导出。
- P-01 是当前运营快照；P-14 是历史趋势与统计分析；P-17 是统一投资渠道运营监控详情；P-18 是 M 账户单体服务管理；P-12 是安全/审计证据入口。
- M21-F007 BI 预测仍为 V3.0，不在 P-14 加入预测、评分或自动决策。

## 11. 待批准参数与技术决策门

本批不虚构以下参数：
- 各数据源更新频率、延迟 SLA、报表快照生成周期；
- 最小样本抑制阈值和跨 Tenant 聚合的最小权限角色；
- 具体平台商业账单币种、价格、税务和收入确认规则；
- 导出文件保留期限、下载有效期、审批层级及可用格式；
- 报表读模型/数据仓库的物理架构、API、缓存和事件修正机制；
- 各指标最终 Metric Code、数据字典和生产数据质量阈值。

未批准的参数显示「待配置/待确认」，不得以演示数值作为生产规则。P-14 在上述关键安全参数未确定前只可使用 Mock/脱敏演示数据。
