## 1. 页面地图、呈现及下一步
### 1.1 资产详情 → 权益结构 TAB
| 页面场景 | 应显示 | 主操作 |
|---|---|---|
| 当前 Asset 未建立 Instrument |「尚未创建权益结构」「定义投资者获得什么权利，再拆分 Token 份数」；清楚显示 Asset 名称和资产资料状态 |「创建权益结构」；不出现「第二套结构」入口 |
| 当前 Instrument 为草稿 | 类型、名称、摘要、待补字段计数/原因、最近保存时间、授权规模及拆分摘要（有值才显示） |「继续编辑」 |
| 当前 Instrument 已通过资料检查 |「资料已完备」与基本权利说明、拆分总数/每份权益、文件版本摘要 |「前往发行管理，创建发行方案」；若所属 Asset 或生产门未满足，应精确解释阻断 |
| 已有 Offering/发行事实 | 当前 Instrument 摘要、已引用 Offering 链接、版本历史；最大可发行/已发行/已预留/剩余可发行（仅有可信业务事实时） |「查看发行方案」；受控编辑/查看历史版本 |
| 历史业务因订阅降级只读 | 仍可查看历史权利、版本及必要记录，不假装清零重建 | 仅查看或 U01 允许的存续操作入口，不提供新建/编辑 |

```text

顶部：当前企业 | 资产名称（只读）| 资料状态 | 自动保存状态（若实现）
标题：创建权益结构 / 编辑权益结构
A. 权益定义
   权益类型（股权/债权/收益参与单选）
   权益结构名称（初始按资产名+类型生成，可编辑）
   权利责任主体（Ready 必填）
   投资者获得的权利（Ready 必填）
   [仅当前类型专属字段；总权益规模不得在此重复录入]
B. Token 拆分
   拟纳入本权益结构的权利规模 [带当前类单位]
   拆分成多少份 Token [正整数]
   只读结果：每 Token 对应的权利、最多可发行 Token 数
   如发生有效发行：显示真实额度明细，否则不显示空的预留/已发指标
C. 法律文件
   当前类型核心权益文件 [上传] 状态/文件名/版本 [查看] [更换]
   [从当前资产引用文件] → 文件与固定版本选择器
   [添加其他文件]（选填）
底部固定操作：[保存草稿] [完成资料检查]
```

- 必填标识、说明、错误贴近具体字段/文件行；不出现独立第四步确认/预览页面。
- **不应在 Instrument 表单中出现**：认购价格、募集目标 U、开始/结束认购时间、投资者付款钱包、投资者门户发布，这些归 Offering。
- 主体/条款应以实际法律文档确认；产品上的“资料已完备”不得改写为“合法发行通过”。

### 2.5 UI 提示原则
- 「Token 总份数」代表**计划拆分的权益份数**，不等于现在已 Mint 或已被投资者持有。
- 例：收益参与权 10% 拆 10,000 份 → 每份对应**总可分配净租金收益的 0.001%**，需展示适用净收益口径与期间。不要写成“每份年化收益率 0.001%”。
- 表单金额一律显示 U（按 USDT 计价），Token 认购单价/募资额仅在 Offering 配置；实际投资者付款 OP Mainnet USDT 的生产准入不在当前页执行。

## 3. 自动拆分与多期容量数据流
### 3.1 创建阶段
- 输入 `rights_total`（类型对应权利单位）与 `token_count`（**正整数**）。解释性计算：`per_token_rights = rights_total / token_count`；UI **不提供第三个可编辑「每 Token 对应权益」字段**。
- UI 只读显示 `max_token_count = token_count`。**最大可发行量的业务守卫仍受法定权利、可用范围、技术最小单位和后续独立准入制约**，不能把 token_count 视作自动获准 Mint 数。
- 单位：股、U 名义本金、合同收益参与比例；不可混合相加。计算不得用会吞掉余数的格式化结果写回主账；来源、单位和完整精度由可信后端校验。
- 没有有效发行事件时，不要渲染「已发行 0 / 预留 0 / 剩余 100%」一整套运营报表。保留总份数及每份对应权利即可。
- 拆分无法在**经批准**的当前权利单位最小精度内整除/准确表达 → 展示「当前拆分份数无法精确表示每份权益，请调整份数或权益规模」，禁止通过资料检查；**具体允许的股权/债权/收益参与精度仍 Open，不能凭示例推断法定许可**。
- Token 份数为空、0、负数、小数、非数字、超出系统安全值范围，不能通过 Ready；具体上限/数值长度未批准，不能创造任意商业套餐限额。

### 3.2 Offering 共享容量
- 只有真实业务状态产生有效预留后才计入 `reserved`；Draft Offering **不预留**。`confirmed` 为已生效的实际确认占用，**不能同时作为预留再扣一次**。
- 用户可见：`max_token_count`、`issued_confirmed`、`reserved_active`、`remaining = max - confirmed - reserved`（此公式仅为**等价份额**下的业务表述；后台并发、事务幂等及版本账本技术仍待设计/验证）。
- 后续 Offering 创建的可用额度必须**实时由权益主账返回**，不能只信客户端缓存；并发情形不可超过授权规模。Offering 结束不自动释放已确认权益；真实预留释放规则须按 Offering 实际事件及其审批门。
- **版本变化不增加同一个资产的权益池额度**；单 Asset 只有一套当前 Instrument/一份共享容量。旧 InstrumentVersion 的关联明细及其历史确认权利仍不可被覆盖。

## 4. 文件行、版本引用和异常
- 区域 C 首先显示当前类型的**一项核心权益证明行**：股权「股权权益协议或适用权利证明」、债权「债权协议或债权形成证明」、收益参与「收益参与协议」。有「必需」「未上传 / 上传中 / 待扫描 / 可引用 / 失败」状态和上传/查看/更换入口。
- 「引用已有资产文件」选择器仅列**当前 Asset 有权限访问**的文件，显示文件类型、名称、确定版本、文件扫描/可引用状态、引用位置；确认后保存 `file_id + version_id` 固定关联，不能只保存「最新」链接。
- 用户可通过「添加其他文件」自主选择选填文件类型；不空堆上传行。已上传的其他资料不会因更改 UI tab 而丢失；文件失效、版本更换造成的关联需显示受影响事项。
- 失败与重试：传输失败重试不清空表单其他字段；扫描尚未完成/失败不可判 Ready；无权限引用不应显示可选择成功；已被 Offering 引用的旧文件版本不可静默覆盖或删除历史。
- **适用法域另需哪些必需、条件必需法律文书及具体协议是否真实签署/有效**仍是法律生产审查问题，不能用「一项核心文件」当作所有法定证明充分。

## 5. 状态、编辑和跨对象保护
### 5.1 业务事实与用户可见反馈
| 层次 | 状态/事实 | 页面含义 |
|---|---|---|
| Instrument 生命周期 | **Draft（草稿）** | 未完成资料检查，可在已获资格下保存编辑；允许资料缺失 |
| 资料完备事实 | **Ready（资料已完备）** | 已满足当前已定义的字段/文件/单位检查，**不等于法律通过、Token 部署、可发行** |
| 检查结果（非新增持久化生命周期状态） | **资料待补充** | 校验失败的即时反馈；记录缺项列表并定位到字段，不应误作新增审批状态 |
| 引用/约束事实（非独立生命周期） | **被 Offering 引用** | 显示引用期次和已锁定的 `InstrumentVersion`，适用更严格变更保护 |
| 发布/真实资产生命周期（其他模块） | 发行、认购、Mint、收益 | **不得**仅通过本表单触发；由 Offering、M07/资金等主账维持 |

### 5.2 关键保护行为
- 单 Asset 当前已有 Instrument（包括 Draft/Ready）时，禁止通过「新建第二个」「复制并生效」「新版本重置容量」制造并行权益池；请求须在服务端校验租户+Asset 唯一性，不仅隐藏按钮。
- 对尚无 Offering/已生效外部依赖的 Draft：可修订字段并保存；若编辑后缺必填，需要重新执行资料检查才显示 Ready（具体 Ready 失效回退事件细则下文仍为 Candidate）。
- 对**已被任何 Offering 引用的确定版本**，不得原地改变或覆写权益类型、主体、权利总量、Token 份数、法律文书版本、收益口径及其既有历史。修改必须走可追溯新版本及适用重新检查，且旧期仍引用旧版本。
- 对**已出现已生效认购、Mint、存续义务**的结构，不能凭客户端「删除/重建」绕过原法律权利、有效份额和投资者义务；若未来支持修订/终止需另设受控流程，不在当前 MVP 默认提供。
- **Candidate / 需下一轮明确确认**：Draft 切换「股权 ↔ 债权 ↔ 收益参与」时显示确认弹窗，仅清理无法兼容的类型专属输入，保留名称、主体和用户已上传的文件实体（即使不再引用）；原类型相关旧值不作为新类型可提交字段。已被 Offering 引用时不允许直接改类型。这个保护是面向数据安全的实现提案，不能作为已批准的复杂版本迁移能力。
- **Candidate / 需下一轮明确确认**：Ready 状态修改合同/容量/证明后，应使“资料已完备”失效、重做检查；但**何种修改自动触发及何时生成新版本**需要明确产品/技术守卫，不可自行修改已生效版本。

## 6. 交互校验、空状态与错误提示
| 场景 | 推荐 UI 反馈（候选文案，可小范围措辞调整） | 保持事实 |
|---|---|---|
| 尚未创建权益结构 |「该资产还没有权益结构。先确定投资者获得的权利，再设置 Token 份数。」+ 创建入口 | 一资产只能有一套当前权益 |
| 草稿缺主体/权利说明 |「请填写权利责任主体」「请说明投资者将获得的具体权利」并定位字段 | 允许保存 Draft，不能 Ready |
| 固定利率缺年利率/起息日期 | 对应字段红字「固定利率模式需要填写年利率/起息日期」 | 无息不错误要求填写 |
| 股权分数股或权益无法精确拆分 |「当前拆分份数不能精确对应每份权利，请修改份数或总权益规模」 | 不静默舍入/生成虚假合法股数 |
| Token 份数 0/负数/小数/非数字 |「请输入大于 0 的整数份数」 | 不出现 NaN/Infinity/零除 |
| 收益比例超 100% / 未设收益口径 | 对应字段说明「参与比例必须大于0%且不超过100%」「请填写收益计算口径」 | 不能推断收益为保本承诺 |
| 适用核心文件缺失/扫描中/失败 | 缺失/待扫描/失败分别定位核心文件行及下一操作「上传/等待扫描/重试」 | 上传完成不等于安全可引用或法律生效 |
| 引用资产文件已被更换/无权限 |「该文件版本不可引用，请重新选择有权限且可用的版本」 | 不静默引用最新版本 |
| 同时打开两个窗口重复创建 |「该资产已经有权益结构，转到现有记录」 | 服务端拒绝重复创建并保护草稿 |
| 保存草稿网络断开/超时 |「保存失败，请重试」；保留当前输入、当前页面及失败状态 | 不显示虚假“已保存” |

## 8. UI-Ready 交付判定、Offering 的承接及未决清单
### 已可作为 U02-06 Offering 产品设计输入（是）
- 已确定 Asset→一套当前 Instrument→多期 Offering 的对象关系、版本引用、单页字段/区块、三类基础权利、Token 拆分的业务输入输出、同池共享防超额，以及创建 Offering 的页面入口。
- 因而**可以进入 U02-06 Offering 的产品设计**；无需等待真实 Token 合约、精度/Signer/法律准入先落地，Offering 先按 Draft 方案及状态流设计并沿用不可突破的容量/版本边界。

### 尚不能宣称「生产 Code-Ready / 真正上线可发行」
1. 具体 Token decimals 与权益对应最小单位、股份分数合法性、债权金额精度、收益比例精度及无法精确拆分的权利分配办法仍待技术/法律联合确认。
2. 权益核心证明之外的法域/权利关系条件性必需材料、真实签署与专业法律核验、股权名册映射和实际债权来源完整性仍待准入。
3. Draft 切换权益类别时对不兼容输入/文书引用怎么处理，Ready 编辑何时失效、已被**未生效 Offering**引用时哪些编辑可做、InstrumentVersion 新版本何时起效仍待后续小批量决策。
4. Offering 主流程的本期 Token 发行数量、价格 U、募集期限、发行准备/披露、发布预览、预留释放、认购 Token 分配规则，以及各状态精确业务事件和权限，需要在 **U02-06** 逐批审核。
5. 数据层严格原子预留/释放、并发安全、Signer/Provider、合约与真实资金、网络生产执行仍须独立技术门。Free/Standard 订阅及 KYB 从不取代生产准入。
