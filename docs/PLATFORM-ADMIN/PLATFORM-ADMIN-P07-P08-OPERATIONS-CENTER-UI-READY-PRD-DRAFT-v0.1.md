# RWA SaaS｜Platform Admin P-07～P-08：运营中心 UI-Ready 产品规格（Draft v0.1）

> **文档状态：Draft｜2026-11-18**
>
> 本文细化平台总后台「运营中心」的 P-07 平台任务/异常队列与 P-08 通知模板/投递记录。承接已批准的 M17/M18 业务范围和 DEC-034 R03/R04 产品规则。
>
> 本文只定义桌面 Web 页面、字段、交互、状态、Mock 与前端验收；不定义或实现后端、数据库、API、真实邮件 Provider、法定送达或生产权限。

## 0. 范围与核心结论

### 0.1 页面组与功能映射

| 页面组 | 对应功能 | 页面责任 |
|---|---|---|
| P-07 平台任务与异常中心 | M17-F001～F006 | 统一查看和处理**归平台运营负责**的待办、审批协作、补件、异常调查、升级和处理历史 |
| P-08 平台通知与投递管理 | M18-F003～F005（并引用 F001/F002 的平台事件） | 管理平台受控业务通知模板、查看通知投递/阅读/失败记录、对符合条件的失败通知进行受控重试 |

M17/M18 是跨端共享领域能力。P-07/P-08 只是 P 端受权视图，不建立第二套任务或消息主账。

### 0.2 不做事项

- 不把所有 Issuer I 端待办复制进 P-07；只显示归 P 负责、P 被明确指派或需要 P 协作处理的任务。
- 不让 P-07 关闭任务就自动改变 KYB、Offering、KYC、资金、登记、Token 或收益状态。
- 不在 P-07 重复实现 P-03 商业 KYB、P-15 渠道审核、P-18 投资者账户、P-13 Provider 管理等业务详情审批页面；任务详情只展示最小摘要并跳回原业务页面。
- 不建立高级 CRM、客服工单系统、自动化流程编辑器、低代码任务编排或自定义 SLA 引擎。
- 不提供营销群发、营销自动化、投资者偏好营销中心或批量邮件活动。
- 不把邮件 Sent、ProviderAccepted 或 Viewed 等同于法律有效送达。
- 不在 P-08 配置外部邮件服务商密钥、Webhook 或生产凭证；这些属于 P-13/M22。
- 不开发后端/API/真实邮件/KYC/资金/Signer；不做移动端。

## 1. P-07｜平台任务与异常中心

### 1.1 页面目标

让平台运营人员集中处理自己有权负责的任务，知道任务来自哪里、当前业务真实状态是什么、下一步应回到哪个业务页面处理。P-07 是任务协作入口，不是跨域业务审批的第二权威。

### 1.2 页面结构

P-07 采用列表＋详情的两级结构，页面内提供四个页签：

1. **待我处理**：当前账号负责人或明确指派给当前账号的未完成任务。
2. **平台任务池**：当前账号有权限查看/认领的未分配平台任务。
3. **异常与升级**：重要/紧急异常、已超期任务、升级任务。
4. **处理历史**：当前账号有权限查看的已关闭/已拒绝/已完成任务。

不提供全局跨 Tenant 无边界搜索。默认优先展示当前用户有权处理的待办。

### 1.3 任务来源范围

| 来源模块 | P-07 可见内容 | 处理入口 |
|---|---|---|
| P-03 商业 KYB | 商业 KYB 补件、复核、Provider 同步异常 | 跳转 P-03 |
| P-05/P-06 Tenant 与商业收费 | Tenant 服务状态、商业账单异常、恢复任务 | 跳转 P-05/P-06 |
| P-15 统一投资渠道审核 | 上架申请审核、补件、复核、自动上架异常 | 跳转 P-15 |
| P-16/P-17 渠道运营 | Listing 暂停/下架/恢复协作、投诉与重大异常 | 跳转 P-16/P-17 |
| P-18 投资者管理 | M 账户服务异常、KYC Provider 状态同步、通知投资者操作 | 跳转 P-18 |
| P-09/P-10 规则 | 规则变更审批或适用冲突复核 | 跳转对应规则页面 |
| P-11/P-12 安全审计 | 敏感访问审批、安全事件和撤权任务 | 跳转对应安全页面 |
| P-13 外部服务 | Provider 连接、Webhook、服务 Unknown 等平台责任任务 | 跳转 P-13 |

来自 Issuer 或投资者业务域的任务，只有在 P 被正式指派且具备合法业务目的/权限时，才可进入 P-07。P 不能因为任务进入平台队列就获得原业务数据或执行权限。

### 1.4 列表筛选

| 字段 | 控件 | 规则 |
|---|---|---|
| 关键词 | 输入框 | 任务编号、业务对象编号、申请编号、Issuer/Tenant 名称 |
| 任务类型 | 下拉 | 审批、补件、复核、异常调查、服务故障、升级、其他 |
| 来源模块 | 下拉 | P-03/P-05/P-06/P-15/P-16/P-17/P-18/P-09/P-10/P-11/P-12/P-13 |
| 任务状态 | 下拉 | 待处理、待补件、处理中、待复核、已升级、已关闭、已拒绝 |
| 严重程度 | 下拉 | 一般、重要、紧急 |
| 负责人 | 下拉 | 未分配、当前账号、指定负责人 |
| 超期状态 | 下拉 | 全部、未超期、已超期；仅在原任务提供截止时间时显示 |
| 创建时间 | 日期范围 | 任务创建时间 |

默认排序：紧急且未处理 → 已超期 → 待处理时间较长 → 最近更新时间倒序。不得自行推算原任务未提供的 SLA/截止时间。

### 1.5 任务列表字段

| 字段 | 说明 |
|---|---|
| 任务编号 | 原 M17 Task ID |
| 任务标题 | 由原事件生成的简短标题 |
| 任务类型 | 审批/补件/异常/复核/升级等 |
| 来源模块 | 原业务模块 |
| 关联对象 | Tenant、KYB 申请、Offering、Listing、M 账户或 Provider 连接编号 |
| Issuer/Tenant | 仅展示当前账号有权查看的主体 |
| 严重程度 | 一般/重要/紧急 |
| 当前状态 | M17 任务状态的中文映射 |
| 负责人 | 当前负责人或未分配 |
| 创建时间 | 原任务创建时间 |
| 截止时间 | 原业务提供时显示，否则「未设置」 |
| 最近更新时间 | 原任务更新时间 |
| 操作 | 查看任务 |

列表不展示完整 KYC 原件、客户密钥、逐笔资金明细或其他 Tenant 的敏感资料。

### 1.6 任务详情

详情页固定分为五个区块：

**A. 任务摘要**
- 任务编号、标题、类型、来源模块、严重程度、当前状态；
- 创建时间、最近更新时间、截止时间（如有）；
- 当前负责人、创建来源及指派历史。

**B. 原业务对象**
- 原业务对象类型与编号；
- Tenant/Issuer 或 M 投资者关联引用（按权限脱敏）；
- 原业务当前状态、原 Intent/请求编号、最近一次权威查询时间；
- 跳转原业务页面的入口；
- 明确标注「以下业务状态由原业务模块维护，任务状态不能覆盖」。

**C. 任务描述与处理要求**
- 问题/审批事项说明；
- 需要完成的动作或待补充事项；
- 对外说明与内部备注分离；
- 关联材料只显示权限允许的文件名/版本/摘要，敏感原件走 P-11/P-12。

**D. 处理记录**
- 每次指派、退回、补件、调查、升级、审批协作、关闭的操作者/时间/原因；
- 关联通知 ID；
- 原业务状态查询结果及证据引用；
- 历史追加保存，不覆盖。

**E. 下一步操作**
- 根据任务类型和当前账号权限显示可执行操作；
- 不适用的操作不显示，不展示无效按钮。

### 1.7 允许操作与 Guard

| 操作 | 条件 | 结果 |
|---|---|---|
| 认领任务 | 任务未分配且当前账号有权处理 | 当前账号成为负责人，记录指派事件 |
| 指派/转交 | 当前账号具有任务分派权限 | 选择有权处理人、填写原因，记录前后负责人 |
| 开始处理 | 任务处于待处理/待复核且权限有效 | 状态进入处理中 |
| 请求补充信息 | 原任务类型支持补件，且确有可补正事项 | 记录补件项、对外说明、期限（如有）；通过 M18 通知 |
| 添加处理记录 | 当前账号可查看任务 | 追加内部备注/证据引用，不改变原业务事实 |
| 跳转原业务处理 | 存在原业务对象且用户对原页面有权限 | 打开 P-03/P-15/P-18/P-13 等原业务页面完成决定 |
| 升级任务 | 当前责任人无法处理、重大风险或超期 | 记录升级级别、原因和新责任人 |
| 关闭任务 | 任务协作事项完成，且关闭条件满足 | 仅关闭 M17 Task；不自动改变原业务状态 |
| 重新打开 | 新证据/新事件导致原任务需继续处理，且有权限 | 保留原关闭记录，新增重开事件 |

**审批任务特别规则：**如果任务对应 P-03 商业 KYB、P-15 渠道审核、P-18 账户限制或 P-09/P-10 规则审批，必须跳回对应业务页面完成真实产品决定；P-07 的任务「关闭」或「已处理」不得代替原业务审批动作。

### 1.8 异常与保护

- 原业务对象已更新：提示刷新，禁止用过期页面提交旧决定。
- 当前用户权限已撤销：立即隐藏/拒绝操作，保留任务和历史。
- 原 Intent 为 Unknown：显示「原业务结果待核实」，提供查询原记录入口；不允许盲目重试。
- Provider 不可用：保留任务责任人和 Unknown 状态，升级而不是标记失败/成功。
- 任务关闭但原业务仍 Pending/Unknown：任务可显示关闭，但详情持续展示原业务状态未完成；必要时创建后续任务。
- 同一异常重复回调：关联已有任务，不重复创建有效工单。
- 无截止时间：显示「未设置」，不以默认时长伪造超期。

## 2. P-08｜平台通知与投递管理

### 2.1 页面目标

管理平台运营所需的基础业务通知模板和投递记录，确保通知内容与原业务状态一致、收件人有权接收、发送结果可追溯。P-08 不成为营销活动或法律送达系统。

### 2.2 页面结构

P-08 提供三个页签：

1. **通知模板**：查看/编辑受控业务模板、预览及版本状态。
2. **发送记录**：查看平台通知发送、Provider 回执和阅读记录。
3. **发送失败**：查看失败/Unknown 通知，核对原发送意图后受控重试或升级。

外部邮件 Provider 连接、凭证、Webhook 和环境健康跳转 P-13；P-08 不直接维护凭证。

### 2.3 通知模板列表

筛选：
- 模板名称/模板编号；
- 业务事件类型；
- 通知渠道（站内/邮件）；
- 接收对象类型（SaaS 企业客户/M 投资者/平台运营人员）；
- 模板状态（草稿/启用/停用）；
- 语言；
- 更新时间。

列表字段：
- 模板编号；
- 模板名称；
- 关联业务事件；
- 渠道；
- 接收对象；
- 语言；
- 当前版本；
- 状态；
- 最近更新时间；
- 操作：查看/编辑/预览。

仅允许管理平台有权控制的基础业务通知模板；Issuer 自有门户内容或企业自定义营销消息不在 P-08 管理范围。

### 2.4 模板详情与编辑

字段：
| 字段 | 类型 | 必填/规则 |
|---|---|---|
| 模板名称 | 文本 | 必填，≤80 字 |
| 模板编号 | 只读 | 系统唯一 |
| 业务事件 | 下拉 | 仅选择已定义的 M18 事件类型 |
| 通知渠道 | 多选 | 站内消息/邮件；仅显示已接入渠道 |
| 接收对象 | 多选 | 平台运营、SaaS 企业联系人、M 投资者等已授权对象类型 |
| 语言 | 下拉 | 仅使用平台已启用语言 |
| 邮件主题 | 文本 | 邮件模板必填；站内消息不适用 |
| 消息标题 | 文本 | 站内消息必填 |
| 正文 | 富文本/多行文本 | 必填；禁止插入未登记的敏感字段 |
| 可用变量 | 只读列表 | 来自原事件的白名单变量，不允许自由读取任意业务字段 |
| 版本说明 | 文本 | 修改时必填 |

操作：
- 保存草稿；
- 预览（选择脱敏 Mock 事件数据）；
- 启用新版本（需具备模板管理权限，并按平台审批规则通过）；
- 停用模板（确认影响后续通知，不回溯修改已发送记录）；
- 查看历史版本。

模板变更不得改写已发送通知内容或法律/交易事实；每次启用生成新版本，历史版本只读。

### 2.5 模板预览与校验

预览内容包括：
- 渠道；
- 接收对象类型；
- 主题/标题；
- 正文；
- 变量填充结果；
- 当前模板版本。

校验：
- 必需变量缺失时禁止启用；
- 变量不属于事件白名单时禁止保存/启用；
- 不允许在通知正文中自动带出完整 KYC、证件号、私钥、银行账户或其他未授权敏感字段；
- 外部链接打开时仍需服务端鉴权，不因收到邮件就获得业务访问权限。

### 2.6 发送记录列表

筛选：
- 通知编号；
- 原业务事件编号/原 Intent；
- 业务模块；
- 接收对象类型；
- 脱敏收件人；
- 通知渠道；
- 投递状态；
- 时间范围。

列表字段：
| 字段 | 说明 |
|---|---|
| 通知编号 | 原 M18 Message/Notice ID |
| 业务事件 | 原业务事件类型与编号 |
| 来源模块 | P-03/P-15/P-18/P-13 等 |
| 接收对象 | 脱敏显示 |
| 渠道 | 站内/邮件 |
| 模板及版本 | 发送时使用的模板版本 |
| 投递状态 | 已创建/已发送/Provider 已接收/已阅读/发送失败/结果待核实 |
| 创建/发送时间 | 分别显示 |
| 最近更新时间 | 最新状态时间 |
| 操作 | 查看详情 |

### 2.7 通知详情

- 通知编号、原事件 ID、原业务对象和 Tenant/投资者受权引用；
- 模板编号、发送时模板版本及内容快照；
- 接收对象（脱敏）与权限检查摘要；
- 渠道、Provider 引用（脱敏）；
- 状态时间线：Created、Sent、ProviderAccepted、Viewed、DeliveryFailed、Unknown；
- 失败原因类别、重试历史、原操作 ID；
- 关联 M17 任务；
- 法律送达证据仅显示有权 X/原业务领域提供的引用状态，不由 P-08自行认定。

### 2.8 发送失败与受控重试

| 场景 | 允许动作 | 保护 |
|---|---|---|
| 明确 DeliveryFailed | 核对收件人权限、原事件仍有效后重试原通知 | 复用原通知关联与幂等标识，不重复创建业务动作 |
| Unknown | 查询原发送操作/Provider 回执 | 不盲目重发；先确认原请求结果 |
| Provider 不可用 | 跳转 P-13 查看服务状态、创建/关联 P-07 任务 | 不将服务故障标记为业务失败 |
| 收件人权限已撤销 | 禁止重试 | 不向无权对象继续投递 |
| 模板版本已停用 | 历史记录继续可查；新发送使用当前有效版本 | 不修改历史发送快照 |
| 消息已发送/已阅读 | 只读查看 | 不重复发送，除非原领域产生新的有效事件 |

按钮：
- 「查询发送结果」；
- 「重试发送」（仅明确失败且满足权限/事件条件时显示）；
- 「创建/关联任务」；
- 「查看原业务事件」；
- 「查看 Provider 服务状态」（跳转 P-13）。

### 2.9 通知状态与法律效力边界

| 状态 | 中文显示 | 不代表什么 |
|---|---|---|
| Created | 已创建 | 尚不代表发送 |
| Sent | 已发送 | 不代表 Provider 接收或用户阅读 |
| ProviderAccepted | 服务商已接收 | 不代表最终送达或法律有效送达 |
| Viewed | 已阅读 | 不代表投资者同意、合同签署或法律送达 |
| DeliveryFailed | 发送失败 | 不代表原业务动作失败 |
| Unknown | 结果待核实 | 不允许盲目重发 |

法律有效送达状态如适用，必须由原业务责任方及适格 X 按适用法域认定；P-08 只显示证据引用，不提供「标记法律送达成功」按钮。

## 3. 跨页面与跨端关系

| 来源 | 操作 | 目标 | 传递上下文 |
|---|---|---|---|
| P-03/P-05/P-06 | 创建/查看平台商业任务 | P-07 | 原 Task ID、Tenant、商业对象、原 Intent |
| P-15 | 补件/自动上架异常任务 | P-07 | Application ID、Listing ID、审核/上架结果 |
| P-18 | KYC Provider 同步/账户服务异常 | P-07 | M Investor ID、Provider Case 引用、异常 ID |
| P-07 | 发送补件/状态通知 | P-08/M18 | 原 Task ID、业务事件 ID、合法收件人 |
| P-08 | 查看通知失败 | P-07/P-13 | Notice ID、Provider 错误引用、原事件 ID |
| P-08 | 查看原业务事件 | 对应 P 业务页 | 事件 ID、业务对象 ID；重新校验访问权限 |

### 4.3 桌面 Web 验收用例

1. P-07 只显示当前平台账号有权处理的任务，不暴露其他 Tenant 无关记录。
2. 通过 P-07 进入 P-15/P-18 后，原页面仍执行业务审批；关闭任务不能改变原业务状态。
3. M17 Unknown 任务显示原 Intent/操作 ID；不能盲目重复付款、登记、Mint 或上架。
4. 任务关闭后原业务仍 Unknown，详情明确显示未完成，不伪造业务成功。
5. 任务补件通知通过 M18 创建并关联原 Task；投递失败可在 P-08 查询。
6. P-08 模板变量只能使用白名单字段；完整 KYC、证件号和密钥不能插入模板。
7. 修改模板产生新版本，不覆盖历史已发送内容。
8. Sent、ProviderAccepted、Viewed、DeliveryFailed、Unknown 正确区分。
9. 明确失败且收件人仍有权时可重试；Unknown 时先查询原操作。
10. 收件人权限撤销后，通知链接访问被阻断，重试发送按钮不可用。
11. P-08 不提供群发营销、法律送达确认或 Provider 凭证管理。
12. 未执行用例标记 Not Executed，不得标记 PASS。

## 5. 版本边界与后续依赖

- P-07/P-08 细化 DEC-017 原 V1.0 M17/M18 功能；不新增正式功能 ID。
- M17-F007 低代码流程编辑器仍按历史 V3.0 归属，不得借 P-07 扩展。
- M18-F006 营销全渠道偏好仍按历史 V2.0 归属，不得借 P-08 扩展。
- P-09/P-10 提供任务处理权限、通知模板启停及规则审批所需的有效规则；P-11/P-12 提供敏感访问和审计；P-13/M22 提供 Provider 邮件连接及健康状态；P-14/M21 只读统计。
- 法定送达、邮件 Provider 供应商、实际权限码、数据保留期限、SLA 精确值、API/幂等实现均不在本批批准范围。

**本批结论：P-07 平台任务与异常中心、P-08 平台通知与投递管理形成 UI-Ready 产品规格 Draft v0.1。只管理平台有权处理的任务与受控通知，不复制原业务审批或消息主账；待产品负责人审核后进入原型。**
