# DEC-080｜V1 资产与发行全链路跨模块一致性审核收口

> 日期：2026-11-11  
> 状态：**在用户明确同意开展全链路一致性审核后，按既有 V1 产品设计授权完成审核与页面级口径修正**。本决策不新增业务范围，不改变已批准业务规则或正式功能版本归属。  
> 维护分支：docs/r2-current-product-baseline｜PR #8 Draft / Open / Unmerged。

## 1. 审核范围

审核以下六个业务域、八份 UI-Ready 规格：
1. 资产管理（U02-07）；
2. 权益结构（U02-08）；
3. Offering 发行方案（U02-09）；
4. 认购订单（U02-12）；
5. 配售与持有人（U02-13）；
6. 资金与结算（U02-14）；
7. Token 管理；
8. 锁仓记录。

对照 DEC-021、023、032、033、053、058～079、SCOPE-186～193 和既有 U02-04 房地产范围批准文件，核对对象归属、状态、时序、容量、资金、登记、Token、锁仓、导航及跨模块跳转。

## 2. 审核结论

- Asset、InstrumentVersion、Offering、订单、资金、Allocation、法定登记、Token 和锁仓记录的权威责任边界总体一致。
- V1 主链路保持：Asset Ready → Instrument Ready → Offering 发布 → 唯一认购订单 → 真实资金 FinalMatched → 唯一有效配售 → 按 Instrument/法域适用顺序完成法定登记与 Token 交付 → Token/法律权益对账 → 按 Offering 规则跟踪锁仓。
- FinalMatched、Allocation、LegalRegisterEffective、TokenFinality 必须独立；任何一项不得自动代替另一项。
- Offering 发布预留本期 Token 总量；订单只在本期预留内部占用；配售与持有人模块是共享容量权威，禁止重复扣减。
- 投资者支付网络 OP Mainnet USDT 与 Token 部署网络分离；企业最终结算收款钱包与投资者付款目标分离。
- Token 业务锁仓、链上执行限制和法律/管理限制独立；募集款释放资格不由投资者 Token 锁仓状态直接决定。
- 具体 Instrument/法域的法定登记与 Token 交付先后顺序不在 UI 层统一硬编码。

## 3. 已完成的页面级一致性修正

### 3.1 认购订单列表

在 U02-12 增加独立「法定登记」状态列和移动端卡片展示。DEC-075 的订单「已完成」定义保持不变，即实收已确认且 Token 交付已确认；若法定登记仍待确认，列表必须同时展示登记状态，不得暗示合法持仓登记已完成。

### 3.2 Offering 关闭守卫

在 U02-09 关闭发行待处理清单中增加：
- 适用法定登记、登记回执和更正待核；
- 已付款待配售、已配售待 Token 交付；
- 资金、容量、Token 对账差异及 Unknown。

适用法定登记仍待核/回执/差异/Unknown 时不得因订单主进度已完成而跳过关闭守卫。已完成必要配售、适用法定登记和 Token 交付后，仍存续的基础锁仓不单独阻止 Offering 关闭，但继续由锁仓记录跟踪；关闭不解除锁仓。

### 3.3 Token Mint 资金前置

在 Token 管理规格中删除宽于 DEC-076 的「通常 FinalMatched、合法例外」表述，明确 V1 Mint 必须引用依据 DEC-076 通过 FinalMatched 前置核验的唯一有效配售决定。未来如需例外，须先经独立业务决策，不由 Token 管理自行放宽。

### 3.4 持有人锁仓状态

在 U02-13 将以下三种状态拆分为独立筛选和详情字段：
- 业务锁仓状态；
- 链上执行状态；
- 法律/管理限制。

状态文案与 DEC-079 对齐，补齐「期限已到待核」「解除待执行」「执行失败」「异常/Unknown」等必要状态。

### 3.5 募集款释放与锁仓分离

在 U02-14 明确：投资者 Token 的业务锁仓期限/链上解除状态，不直接等同于募集款受限或释放资格。募集款释放仍依据资金条款、合法资金持有人/收款主体、退款义务、争议/冻结、募集条件及有权证据；只有具体合同/法域明确关联时，才引用锁仓状态作为条件。

## 4. 已核实但不修改的范围

- 房地产六个子类的字段方案与四个首批开放模板并不冲突：V1 首批开放住宅、写字楼、商铺、工业园/仓储物流；酒店、土地保留分类和字段设计但暂缓开放。依据 U02-04 R21～R27、R28～R33 和 DEC-070，保持四模板范围。
- 投资者付款优先评估受审智能合约收款，同时按 DEC-053 保留依法适用的 Issuer 有权钱包/适格第三方收款方式；企业最终结算钱包与投资者付款目标继续分列。
- DEC-075 的订单「已完成」状态语义保持不变；本次只增加法定登记独立可见性，不把订单主进度改成法定登记状态。
