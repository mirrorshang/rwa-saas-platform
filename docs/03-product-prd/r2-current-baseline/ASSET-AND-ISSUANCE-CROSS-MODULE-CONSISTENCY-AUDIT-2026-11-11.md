## 2. 统一后的端到端业务主线

\`\`\`text
Asset Draft / Ready
  → 唯一当前 InstrumentVersion（Draft / Ready）
  → Offering Draft / 业务检查 / 生产准入 / 最终预览 / 发布
  → 投资者有效报价、协议/签署和唯一认购订单
  → 真实付款指令与链上到账观察
  → M11 FinalMatched（认购款真实匹配）
  → M12 唯一有效 Allocation（合法配售）
  → 按 Instrument/法域适用顺序确认法定登记
  → M07 按唯一配售和合法交付前置执行 Token Mint/交付
  → 链上最终确认及 Token/法定权益对账
  → 固定 Offering 规则生成并跟踪锁仓记录（如本期选择固定天数）
  → 后续收益、到期、退出和清退由收益与分配承接
\`\`\`

上述为业务依赖主线，不表示所有法域必须使用同一「先登记后 Mint」顺序。法定登记与 Token 交付始终独立显示，适用顺序按 Instrument/法域确认。

## 3. 审核确认：保持不变的统一规则

### 3.1 Asset、Instrument、Offering 的对象边界

- Asset 只负责底层资产资料、权属、相关方、文件和 Draft/Ready；Asset Ready 只代表资料完整性，不等于产权、授权、法律或生产发行准入通过。
- 一个 Asset 只有一套当前有效 Instrument；Offering 固定引用确定 InstrumentVersion。
- Instrument 定义法律权益类型、责任主体、权利总量、Token 总份数及每 Token 对应法律权益；股、债权本金 U、收益参与比例等法律单位与 Token 份数分列。
- Offering 只定义本期发行数量、单价 U、最低认购金额、认购时间、锁仓规则、企业最终结算收款钱包和本期披露；不得重定义 Instrument 总权益或 Token 映射。
- Instrument 的共享权益容量由权威容量事实维护；多个 Offering 共享，不因复制版本或创建新一期重置容量。

### 3.2 预留与容量

- Offering 发布时预留本期总 Token 份数；Draft 不占用容量。
- 订单只在该 Offering 已预留份额内部进行订单级占用，不得从 Instrument 总容量再次扣减。
- 配售与持有人模块是容量、有效预留、冻结/待核保护、已确认占用和可用量的权威来源；前端不得跨来源自行加减。
- Offering 关闭只释放没有待处理义务的未分配预留；已确认配售/已交付 Token 保持占用，存续义务不能因关闭释放。

### 3.3 付款、配售、登记和 Token 四种事实

- 付款指令发出、钱包签署/广播、链上观察、链上最终性和订单匹配是不同阶段。
- 只有资金与结算权威确认 FinalMatched，才是认购款实收已确认。
- FinalMatched 不等于 Allocation；Allocation 不等于法定登记有效；法定登记有效不等于 Token 已交付；Token 已交付不自动证明法定权益已登记。
- DEC-076 的 V1 基础配售前置要求真实资金 FinalMatched；Token 管理不得自行引入未批准的付款例外。
- 法定登记责任分为依法 Issuer 自管、依法委托、强制特定登记主体三种；不得把 SaaS 普通账号当作法定登记者。
- Token Mint 必须引用唯一有效配售决定、已核实接收钱包、有效合约和真实受权执行；Unknown 先查询原 Intent/Tx/事件，不得重复 Mint。

### 3.4 收款钱包、付款目标与 Token 网络

- Offering 选择的是本期企业最终结算收款钱包；它不自动等于投资者付款目标。
- V1 投资者付款固定 OP Mainnet · USDT。受审智能合约收款为优先评估方向；按 DEC-053，依法适用的 Issuer 有权钱包或适格第三方收款方式仍可保留，须有真实主体、授权和独立生产准入。
- 若使用收款合约，投资者付款目标展示已核验的合约地址；企业最终结算钱包与合约地址分别展示，不混为一个字段。
- Token 部署网络与投资者支付网络分离；OP Mainnet USDT 不自动决定 Token 必须部署在 OP Mainnet。

### 3.5 锁仓与资金释放

- Offering 选择「不锁仓 / 固定天数」；固定天数 1～36,500 天，从 Token 实际交付事件达到适用最终确认时起算。
- 业务锁仓期限、链上转让限制、法律/管理限制是三个独立状态；锁仓到期不自动等于链上解除或法律限制解除。
- 投资者 Token 锁仓状态不直接决定募集款是否可释放；募集款释放按资金条款、合法收款与资金持有人、退款义务、争议/冻结、募集条件及有权证据核验。
- Offering 关闭不自动解除锁仓；锁仓存续由锁仓记录持续跟踪，不复制到 Token 管理主账。

### 3.6 版本、租户、套餐和生产准入

- Asset、InstrumentVersion、Offering、报价/协议、披露和钱包配置在相关业务节点固定快照；历史订单不随当前版本编辑而改变。
- 仅当前 Tenant 可访问自己的 Asset、Offering、订单、资金、配售、持有人、Token 和锁仓记录；个人 KYC/身份材料默认脱敏。
- Free 仅业务准备和内部预览，不生成真实订单、资金、配售、持有人或 Token 运营事实。
- Standard、KYB 通过不自动等于真实资金、法定登记、Signer、合约部署或生产执行授权。
- Unknown、待核、来源冲突不能当作成功或失败；查询原始事实，不重复执行不可逆操作。

## 4. 本轮发现并已修正的页面级缺口

| 编号 | 发现 | 风险 | 修正文件与内容 |
|---|---|---|---|
| A-01 | 订单列表显示主进度、付款、Token 交付，但没有独立展示法定登记状态；订单可按 DEC-075 在实收和 Token 交付确认后显示「已完成」，而登记仍可能待核 | 列表用户可能误将订单完成理解为合法持仓登记完成 | U02-12 增加独立「法定登记」列和移动端状态；明确「已完成」不代表登记完成，登记待确认必须并列显示 |
| A-02 | Offering 关闭待处理清单列出付款、Token 交付、退款和争议，但未明确列出适用法定登记/回执/更正待核 | 可能在登记义务未完成时关闭 Offering | U02-09 将适用法定登记、登记回执/更正、待配售、Token 交付和 Unknown 纳入关闭守卫；存续锁仓不单独阻止关闭，但继续保留跟踪 |
| A-03 | Token Mint 规格允许「通常 FinalMatched，若有合法例外」的表述，宽于 DEC-076 的 V1 配售前置 | Token 模块可能自行放宽配售资金条件 | Token 管理 UI-Ready 明确必须达到 FinalMatched 并引用 DEC-076 唯一有效配售；任何例外须先有独立业务决策，不由 Token 模块自行放宽 |
| A-04 | 持有人详情虽然提到三种锁仓/限制状态分离，但筛选和详情没有完整呈现链上执行状态，且部分业务状态文案不全 | 用户无法区分业务到期、链上解除待执行和法律限制 | U02-13 将业务锁仓、链上执行、法律/管理限制拆为独立筛选与详情字段，并与 DEC-079 状态一致 |
| A-05 | 资金释放资格说明未直接阐明 Token 锁仓与募集款释放资格不是同一状态 | 可能误将投资者 Token 不能转让理解为募集款必须继续受限，或反之 | U02-14 明确资金释放以资金条款、退款义务、争议/冻结和合法证据为权威；仅在具体合同/法域明确要求时引用锁仓状态 |

上述修正均为已批准原则的页面表达、状态展示和跨模块守卫补齐，不新增复杂业务模型、不新增正式功能 ID、不改变 V1/V2/V3 归属。

## 5. 经原始决策核实、不属于冲突的事项

### 5.1 房地产四个开放模板与六个子类

经核对 U02-04 R21～R27、R28～R33 及 DEC-070：
- 六个房地产子类的字段方案已分别确定；
- V1/MVP 首批实际开放创建的仍是住宅、写字楼、商铺、工业园/仓储物流四个模板；
- 酒店、土地保留分类与已设计字段，但暂缓开放创建；
- 因此 U02-07 的「四个已开放模板」与既有批准一致，不作扩大范围修改。

### 5.2 投资者付款目标

DEC-053 明确受审智能合约收款为优先评估方向，同时保留依法适用 Issuer 有权钱包或适格第三方收款方式。因此 U02-14 将投资者付款目标与企业最终结算钱包分开、并保留经批准的目标类型，不构成未经批准的范围扩张。

### 5.3 认购订单「已完成」与法定登记

DEC-075 的订单主进度「已完成」定义为真实实收已确认且 Token 交付已确认；法定登记、企业结算和退款仍独立显示。该业务定义保持不变。本轮只补齐订单列表上的法定登记状态，避免主进度标签掩盖登记未完成。

## 6. 全链路责任归属（最终对照）

| 事实/对象 | 唯一权威模块 | 其他模块允许做什么 |
|---|---|---|
| Asset 资料、权属、相关方和文件 | 资产管理 | 其他模块只读引用固定版本 |
| 法律权益定义、总量、每 Token 映射 | 权益结构 / InstrumentVersion | Offering、配售、Token、锁仓读取，不重新定义 |
| 本期发行参数、锁仓条款、企业最终结算钱包、披露快照 | Offering | 订单/资金/锁仓只读引用 |
| 认购订单、报价和签署快照 | 认购订单 | 认购记录只读投影；资金/配售/Token 引用订单 |
| 真实收款、FinalMatched、退款、募集款释放和划拨 | 资金与结算 | 订单/配售/Token 只读引用 |
| 唯一 Allocation、容量、法定登记、持有人和限制依据 | 配售与持有人 / 实际有权登记主体 | 订单/Token/收益/锁仓只读引用或提交受权请求 |
| Token 方案、部署、Mint/Burn、链上事件和最终性 | Token 管理 / 实际受权执行主体 | 配售/持有人、锁仓和收益只读引用 |
| 业务锁仓记录、期限和状态摘要 | 资产与发行 → 锁仓记录 | Offering/持有人/Token 提供跳转或链上执行引用 |
| 投资者收益、本息、Record Date、赎回/清退 | 收益与分配 | 读取权威持有人/Token/资金事实，不复制主账 |

## 7. 未纳入本次审核的独立生产门

- 首发法域、每种 Instrument 的法律定性、合法发行/销售/登记主体；
- 具体 Token 标准、网络、合约模板、锁仓实现方式、最终性阈值；
- Provider、Signer、密钥托管、真实收款/退款/划拨与生产资金控制；

- API/Schema、源码实现、自动化测试、Build、Browser、真实链上执行和人工 UAT。

这些仍按原有 DEC/SCOPE 与独立生产准入处理；本次 UI-Ready 一致性审核不能替代。
