## 一、已确认的范围规划原则

产品负责人已明确同意 **SCOPE-001～SCOPE-058** 及**修订后的 SCOPE-060（ARCH-001：API-First / API-Ready 架构原则）**：SCOPE-001～008 为范围规划原则、SCOPE-009～052 依五批确认 **22 个模块、187 项功能的范围定位方向**，SCOPE-053～058 为全局 **V1 最小实现深度与条件性 P1 复核原则**。SCOPE-059、061、062 已于 2026-10-22 单独明确批准（[正式记录](../../decisions/SCOPE-059-062-issuer-v1-delivery-and-validation-decisions.md)）；修订后的 SCOPE-060 不决定商业 Open API 的具体上线批次。这并不等于 187 项均获准在 V1 开发，**详细功能 PRD、V1 必交清单、White-label/API 实际排期、页面、字段、技术/法律条件及正式开发授权仍未冻结**。

| 编号 | 已确认的产品范围原则 |
|---|---|
| SCOPE-001 | V1 首要目标是 Issuer SaaS 一级发行、认购、Token 交付及必要存续管理闭环 |
| SCOPE-002 | 22 模块长期架构全部保留，仅实现 V1 必需功能而非完整模块 |
| SCOPE-003 | SaaS 客户首期采用申请、合同、后台授权方式；不强制自动在线收费 |
| SCOPE-004 | Offering 优先持续购买；集中募集原则保留，是否完整进入 V1 待单独判断 |
| SCOPE-005 | 投资者必要 KYC、自动 Offering 资格判断、直接购买；不默认逐单人工配售审批 |
| SCOPE-006 | 指定链 USDT/USDC 支付与真实 RWA Token 交付是设计方向，法律/安全/上线门不自动通过 |
| SCOPE-007 | V1 不做用户间受控转让；White-label/API 完整产品交付批次待定 |
| SCOPE-008 | 核心模块优先最小必要功能和强制异常/安全控制；高级 BI 运营等后置 |

## 二、优先级说明

- **P0：V1 核心候选**。建议优先进入详细 PRD 和 V1 范围审查；需产品负责人逐项批准。
- **P1：V1 简化候选**。可用较轻方案实现，或取决于首发金融工具；尚未确认必须交付。
- **P2：后续增强**。不是 V1 推荐，也**不自动等于已批准 V2**。
- **V2：下一版本规划**。依 DEC-011，仅 M14 投资者间受控转让方向；V1 必要的合约级转让限制保留在 M07。
- **待定：完整商业产品交付批次未定**。M15 White-label 的 V1 客户层级模式仍按 DEC-002；M16 Open API/SDK 的商业交付批次尚未冻结。

**评审状态口径**：M01～M22 的 **187 项**已经 SCOPE-009～052 通过五批**范围定位**评审；SCOPE-053～058 又批准其**最小实现深度原则及条件性 P1 的审查要求**，但没有逐项更改 P0/P1/P2 枚举，也没有冻结具体开发范围。M14 受控转让仍按 DEC-011 规划 V2；M15 White-label、M16 Open API/SDK 的完整商业产品批次/具体日期仍**待定**；SCOPE-059 已明确 White-label 不强制首期同步，SCOPE-060/ARCH-001 已明确商业 API 独立交付线。下一步需提供逐功能的「能力必需/实现形式/依赖条件/上线门」清单，再独立审批冻结。功能 ID 不因分级调整重编。
