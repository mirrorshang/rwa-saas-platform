# RWA SaaS V1｜资产目录重构与股权/债权基础模板 UI-Ready 规格

> 日期：2026-11-12｜状态：用户确认资产目录方向与 V1 扩展；本文补齐产品负责人授权范围内的 UI-Ready 页面字段与交互。
> 范围：Issuer 企业 SaaS「资产与发行 → 资产管理」及资产详情「权益结构」。当前产品文档分支 `docs/r2-current-product-baseline`；PR #8 保持 Draft / Open / Unmerged。
> 优先级：用户于 2026-11-12 确认的新资产分类与扩展方向，覆盖旧 8 大类/24 子类**目录设计**；未触及的 U02、DEC-070/071/072 等字段、权益和发行规则继续有效。原 193 功能 ID、既有版本归属、Frozen/历史 DEC/SCOPE 不改。

## 1. 设计决策

1. 资产目录按**底层资产**而非「金融证券/行业/发行权益」混排；采用 **7 个一级类、23 个二级类**。
2. 底层资产类型与投资者获得的**权益结构（股权、债权、收益参与权）**分开配置；不设置简单的一对一硬性限制，也不默认每种组合都可以合法发行。
3. 资产类型决定其资产模板、权属/债权/价值证据、条件字段；权益结构决定权利责任主体、Token 精确拆分、权益法律文件；Offering 决定认购、收款方案、披露和发布。
4. 资产子类可推荐常见权益类型，但**不自动建立 SPV、债务或合法股权**；需要明确主体、合法权利来源与适用文件。资料 Ready 仅代表产品资料齐备，不代表监管/发行批准。
5. V1 以基础闭环为原则：**房地产首批四开放模板 + 非上市企业普通股权基础模板 + 单笔企业借款债权基础模板**。其余目录可见但显示「暂未开放」，不能跳入伪通用表单。
6. 现有 Codex 正在执行的房地产/权益/Offering 批次不追加变更；本文件供下一批目录与新模板原型执行。未经新的明确批准，不扩大其他房地产模板开放范围。

## 2. 正式资产目录（7×23）

| 一级分类 | 二级类型 | V1 创建范围 |
|---|---|---|
| 房地产（6） | 住宅物业；写字楼；商业商铺；工业园/仓储物流物业；土地；酒店/服务式公寓 | 前 4 项开放；后 2 项目录保留，暂未开放 |
| 企业股权（2） | 非上市企业普通股权；资产持有公司/SPV 股权 | 仅非上市企业普通股权开放；SPV 股权暂未开放 |
| 债权与应收款（4） | 单笔企业借款债权；应收账款；供应链贸易债权；资产支持债权 | 仅单笔企业借款债权开放 |
| 基金与投资份额（3） | 私募基金份额；房地产基金份额；信贷基金份额 | 暂未开放 |
| 实物与大宗商品（3） | 贵金属；能源/农矿产品；设备与存货 | 暂未开放 |
| 基础设施与能源项目（3） | 新能源项目；交通/公共设施；数据中心/通信设施 | 暂未开放 |
| 知识产权与合同收益（2） | 知识产权许可权益；版权/版税及其他合同收益 | 暂未开放 |

**数量核验：** 6+2+4+3+3+3+2=23。原先口头方案把 26 个子类误称 23，本文件已收敛至真实 23；保留两种已确认新增 V1 模板。旧房地产目录中「停车及仓储设施」未作为独立子类开放：仓储物流归并至工业园/仓储物流物业，停车可待后续细化时评审，不据此删除历史资产数据。

## 3. 现有资产页面的最小调整

- 创建资产的分类选择器按「一级分类 → 二级类型」展示；标出可创建与暂未开放；禁止进入不开放的表单。
- 已有资产继续按稳定 ID 查看/编辑；历史分类值通过显示映射兼容，不静默批量改写已有资产或已被 Offering 引用的快照。
- 资产列表、五步创建、详情四 TAB、资产相关方与文件版本体系继续沿用 U02-07、DEC-070，不新增一级/二级导航或第五个 TAB。
- 状态仅 Asset Draft/Ready；如有真正的审核/扫描等异步环节，仅允许**本地原型状态控制**改变相关事实，不新造「资产审核通过」法定状态。
- 表单必填/选填、简短提示、条件校验、可编辑示例数据、空/错/成功态遵循全局原型标准。正式用户文案不出现「Mock」「模拟」「演示」，审核与状态测试入口仅对本地原型可用。

## 4. 新增模板一：非上市企业普通股权

### 4.1 范围与对象

记录一项企业有合法权利基础的**存量非上市普通股权**；不把本表单当作「发行新股」或自动创建法律实体。最终投资者可能取得股权型、债权型或收益参与型 Instrument，但必须各自提供成立依据。排除优先股、期权、可转债、上市股票、复杂股权层级、自动股东名册同步。

### 4.2 五步创建映射

沿用原五步向导和公共 Asset 字段，不另造向导：
1. 基本信息：资产名称*、分类/子类*、简介*、所在国家/地区*；被投资企业名称*、注册国家/地区*、企业注册编号*（没有统一编号的法域允许说明替代）、所属行业（选填）。
2. 资产属性：股权类别固定「非上市普通股」；企业已发行普通股总数*（正整数）、本资产涉及股数*（正整数且≤总股数）、本资产占比（按两整数计算只读，显示精度与原值并保留原始分数）、股权是否附带限制*（是/否；是则说明*）、取得日期（选填）。
3. 法律与估值：当前股权登记权利人*、其与发行企业关系*、非同一主体关系说明*；估值方式*（第三方估值/最近交易或可验证依据/其他）、估值基准日*、估值金额 U*（正数）与估值依据说明*；相关方沿用统一主体卡片，按需选择/SPV/估值机构。
4. 文件与媒体：必需「股权权属/股东名册或适用法律证明」「公司主体登记文件」「估值依据文件」；如存在转让/处分限制则补充相关限制文件；与发行企业不同权利人按具体关系配置授权/委托证明；其他章程、股东协议、董事会决议、财务报表为按需附加，不强制所有用户上传。
5. 预览与确认：显示各组字段、文件扫描/可引用状态、缺项定位、保存 Draft、完成资料检查（Ready）与返回编辑。

### 4.3 关键校验与交互

- 普通股总数、涉及股数必须为正整数；涉及股数≤已发行总股数；股权比例只读，不要求用户同时填三个可能冲突的数。
- 股权登记权利人、权利限制与适用依据真实填写；当前企业并不自动等于登记权利人。
- 估值不是 Token 发行价格；金额按全局 U 显示。资产价值不能被误显示为募资已到账。
- 股权权属/限制文件不可引用时阻断 Ready，Draft 可保存；不承诺平台完成真实性核验。
- 股权型 Instrument 中的「普通股总数」是*纳入权益结构的法律权益量*，必须由实际法律权利文件支持，不直接由资产层总股数自动填充或等同。选择关联股权实体需明确。
- 示例数据：一家公司 1,000,000 股已发行普通股，当前资产涉及 100,000 股，显示计算所得 10%；数值只是本地可编辑示例，不能自动宣称可售。

## 5. 新增模板二：单笔企业借款债权

### 5.1 范围与对象

记录**一笔已有借款合同项下的债权资产**，不是让企业通过 Asset 表单直接创建未来的 Token 债券。排除应收账款池、循环额度、联合贷款、多债务人复杂担保池、复杂违约追偿自动化、可转债及分期本金摊还的自动计算。

### 5.2 五步创建映射

1. 基本信息：资产名称*、分类/子类*、简介*、所在国家/地区*、借款合同编号*、合同签订日期*。
2. 债权属性：债权人名称*、债务人名称*、合同本金*（U，大于 0）、当前未偿本金*（U，≥0 且≤合同本金）、合同利息类型*（无息/固定利率）、合同固定年利率（固定利率时*）、起息日（有息时*）、到期日*、偿还安排*（V1 仅到期还本）、目前债权状态*（正常/逾期/已清偿/争议）；逾期/争议时具体说明*；是否存在担保*、有担保时担保摘要*。
3. 法律与估值：债权当前权利人*、与发行企业关系*、第三方债务人主体信息及合同责任；估值依据*、估值日期*、资产估值金额 U*、权利转让或质押限制状态*（有/无；有则说明*）；担保方/受托方按需记录，禁止将债务人混记为普通 Asset 资产相关方。
4. 文件与媒体：必需「借款合同或债权形成证明」「当前债权归属证明」「余额/履约依据」「估值依据文件」；存在担保/权利限制则需相关担保/限制依据；其余为按需。
5. 预览与确认：字段和文件核对、缺项定位、Draft/Ready、可点击详情与版本历史。

### 5.3 关键校验与交互

- 合同本金与未偿本金独立；未偿本金不得超过合同本金，不得因填写过往合同本金把已偿还金额当作仍可融资资产。
- 到期日与起息日、合同日期之间的校验按法律有效期和合同实际情况处理；已到期/逾期可以记录历史，但要提示其风险，不能自动认定为可正常发行。
- 已清偿债权可作为历史记录查看，但不允许以其名义新建可发行权益，Ready 阻断并提示原因。
- 资产层合同利率/期限是*底层借款条件*；债权型 Instrument 的利率/债务人/付息安排是*投资者最终取得的权益条款*。不能直接等同或无确认地复制。
- 债务人不自动等于 Instrument 的债务人；通过明确选择主体及法律依据配置权益责任主体。
- 余额/文件的本地状态变化必须影响 Ready 和后续发行准备，但不得伪称债务人的真实偿付已核验。
- 示例数据：合同本金 500,000 U，未偿本金 380,000 U，固定年利率 8%，到期一次还本；各字段可编辑，状态和业务规则联动。

## 6. 权益结构兼容原则（维持 DEC-071 核心规则）

| 基础资产 | 股权型 Instrument | 债权型 Instrument | 收益参与型 Instrument |
|---|---|---|---|
| 房地产 | 可选，需有合法股权实体和权利证明 | 可选，需真实债务主体及偿付义务 | 可选，需收益来源和合同权利 |
| 非上市企业普通股权 | 可选，核实股权归属/对应实体及普通股数量 | 可选，需另有明确的债务合同/偿付义务，不自动由持股产生 | 可选，需明确可执行的收益来源及分配合同 |
| 单笔企业借款债权 | 可选，仅当另有依法成立的股权实体及其对应权利；V1 不提供自动 SPV/证券化编排 | 优先推荐，需明确投资者对应债务人及债权关系 | 可选，需有合法约定的回款参与合同和责任主体 |

**交互要求：**
- 类型卡片默认显示相应推荐，而不禁用其他两种；不设资产类别与权益类型的刚性硬编码矩阵。
- 用户选择非默认权益时，展示一条简短说明「请确认该权益已有合法责任主体及对应协议」，不要求额外审批角色或自由配置法律规则引擎。
- 公共三类权益表单沿用 U02-08：单页 A 权益定义 / B Token 拆分 / C 法律文件。每资产一套当前 Instrument；股权对应普通股数不可分数、债权本金最多 6 位、收益参与比例最多 6 位；均精确拆分，不静默舍入。
- 股权型的股份法律实体、债权型债务人、收益参与型收益责任主体均须用户明确指定。文件资料完整、Ready、Standard 付费，均不构成合法发行或资金/Token 执行准入。
- Offering 不复制 Asset 合同本金、企业估值或普通股总数当作发售规模；只能引用当前 Ready InstrumentVersion 授权容量、权益单位及条款，按 DEC-072 配置本期发行。
- 当基础资产发生重大权属、股数、未偿本金、限制/逾期等变化时，应提示重新检查 Instrument/Offering 引用与可发行性；已引用历史版本不可静默覆盖。

## 7. UI-Ready 验收矩阵（目标，不代表已执行）

1. 目录按 7/23 展示；六个可创建模板（房地产四、股权一、债权一）准确开启；其他入口禁用并解释。
2. 股权模板的「已发行股数/涉及股数/占比」计算正确；错误输入定位；对应权属证明必填。
3. 借款模板的「合同本金/未偿本金」约束、逾期/争议条件说明、担保条件文件正确；已清偿阻断新发行准备。
4. 两个模板均有真实五步表单、Draft/Ready、示例数据一键填入、可编辑、详情分组、文件状态控制、版本保护。
5. 三种 Instrument 仍可由两类资产进入；非默认选项提示合法依据；切换类型规则、发行关联与 Token 精确拆分符合 U02-08。
6. 多期 Offering 不重复占用或重置容量；Asset、Instrument、Offering 权限与历史快照隔离。
7. 只做桌面 Web；不得将测试状态工具暴露成生产审核能力；不调用真实 KYC、资金、Token、Signer 或外部服务。
8. 浏览器/Build/截图/交互验收须单独执行，不因本规格 UI-Ready 就标记代码或生产完成。
