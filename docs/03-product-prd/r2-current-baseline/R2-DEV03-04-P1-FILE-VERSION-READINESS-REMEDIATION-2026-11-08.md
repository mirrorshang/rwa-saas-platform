## 3. P1 复现与修复目标

### 3.1 审计报告中的复现路径
1. 准备一个 Asset Ready、Instrument Ready 的资产。
2. Instrument 的权属证明引用 Asset 文件固定版本 V1。
3. 在 Asset 编辑页更换权属文件，生成 V2；模拟扫描通过。
4. 完成 Asset 资料检查，使 Asset 再次 Ready。
5. 返回「权益结构」TAB。
6. 现状：Asset Ready；当前 Asset 文件已是 V2；Instrument 仍固定引用 V1，却仍显示 Ready，并出现「前往发行管理」。

### 3.2 修复必须达到的行为
- Asset 文件 V1 与 V2 都保留为可追溯历史版本；不能覆盖、删除或自动把 Instrument 的固定引用从 V1 改为 V2。
- 系统必须检测到：当前 Asset 的被引用文件已有新版本，而 Instrument 仍引用旧版本。
- 该变更必须形成明确的「受影响、需重新检查」信号；在复核完成前，Instrument 不得被 UI 当作当前可直接进入 Offering 的 Ready。
- Instrument 页面明确显示受影响文件的名称、原引用版本、Asset 当前版本及下一步操作；隐藏/禁用「前往发行管理」或「新建发行方案」入口，展示「复核权益结构」等明确操作。
- 用户进入权益结构后，应能查看固定旧版本和新版本；不得静默替换引用。用户按既有文件选择器明确选择新版本（若需要）后，重新运行现有资料检查；若旧版本仍适用，也必须执行明确的复核/重新检查，不能仅因 Asset 的 Ready 标记恢复就自动恢复 Instrument Ready。
- 只有完成复核并通过现有 Instrument Ready 检查后，才可恢复「资料已完备」及发行管理引导。
- 刷新、返回、直接进入 TAB、切换路由、重新打开浏览器上下文后，影响信号必须一致，不能因页面初始化顺序或缓存丢失。
- 若现有数据模型不能安全表达文件版本影响/复核完成状态，先提出最小实现方案并停止等待确认；不得擅自引入复杂的新状态机、法律审批或服务端生产能力。
- DEV-05 后续必须复用相同的「当前有效 Ready」判断；不得仅读取一个陈旧的 `instrument.status === "ready"` 标记。

### 3.3 保持的边界
- 资产文件固定版本引用是刻意设计的历史保护，不是要消除的缺陷。
- Asset Ready 与 Instrument Ready 是两个不同对象的资料完备事实，不得互相自动恢复或替代。
- 本次只处理产品已批准范围内的文件影响识别、Ready 复核与入口阻断；不宣称真实文件安全扫描、生产后端授权或法律有效性已实现。
- 若需要新增持久化状态、版本快照或复杂版本迁移，先列出现有模型和最小差异，等待用户决策，不可自行设计扩展。
