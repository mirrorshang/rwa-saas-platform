### 1.1 已批准的 Offering 创建前置条件（DEV-05-01）
- 用户于 2026-11-08 选择 A，正式批准 [Instrument Ready 前置门](U02-06-DEV05-01-INSTRUMENT-READY-GATE-APPROVED-2026-11-08.md)：**当前 Asset 的 Instrument 必须 Ready，才显示/允许创建 Offering Draft**。
- 无 Instrument → 只显示「创建权益结构」；Draft/检查失败/核心文件扫描中或失败/Ready 失效 → 只显示修复/继续编辑入口，不允许创建 Offering；Ready → 可创建 Offering Draft。
- 创建动作必须再次验证 Tenant、Asset、Instrument 当前确定版本及 Ready 状态；深链/API 不得绕过。
- Offering 创建后固定引用该 InstrumentVersion；后续修改不得静默改变历史 Offering。该规则不改变 Free/Standard 权限和真实生产准入。

### 1.1 页面视觉和信息密度
- 顶部只突出 **当前状态、未完成数、唯一下一步动作**；A/B/C 分区可导航定位，**不是三步向导**。
- 继承信息用独立只读概览：「资产：…」「权益结构：…（版本）」「每 Token 对应权利」「当前可发行：… Token」，避免重复可编辑字段。
- Draft 不伪造「已售 0 / 累计募集 0 / 已 Mint 0」为生产看板；只有已发生、可核验的事实才显示对应指标。
- 保存/检查/预览三类动作不混淆；**资料检查成功不等于已经发布**。

### 2.1 推荐计算与防错说明（C/O，不是新业务权利）
- 只在 **Token 可按整数份数出售** 的前提下展示：`min_tokens = ceil(min_subscription_u / price_per_token_u)`；`actual_min_payable_u = min_tokens × price_per_token_u`。示例单价 120 U、门槛 200 U → 最低 2 Token、实际支付 240 U。**这只是界面解释性公式，正式金额/精度/计算单位需可信服务端和生产支付合约共同验证**。
- 「本期最大募集额」不是「最低募资成功目标」；未批准默认最低募集目标或超募规则，不出现假必填项。
- 时间应按有时区语义的完整时间点校验；**工程候选**：保存 UTC 瞬时值并带原输入时区显示，不允许不同时区本地文本直接比较。
- 对不足、非法或无法精确计算的场景显示阻断信息，**不使用 NaN/Infinity、JS 浮点舍入后值、隐式截断等结果写权威主账**。

## 3. 操作与弹窗（按阶段）
| 场景/按钮 | 显示与反馈 | 写入及保护 |
|---|---|---|
| 「保存草稿」 | A/B/C 可不完整；显示成功时间或失败重试；保存后回原页或留页 | 保存实际输入/文件版本引用；**不预留 Token、不发布、不 Mint、不扣款** |
| 「检查准备情况」 | 两组检查；定位缺项字段，缺 Instrument、钱包、协议等给可点击的修正入口 | 检查不改发行生命周期；检查成功不触发区块链 |
| 「预览投资者端」 | 在创建/编辑期间随时可用；缺失字段标「待完善」，注明非公开/非正式 | 只读，不创建公开链接，不生成投资者订单；未保存改动若用于预览须明确提示快照来源 |
| 「发布发行」 | Free 显示升级 Standard 说明并返回原方案；Standard 若生产门未知/失败显示具体阻断，**绝不假成功** | 只有有效订阅/KYB/合规/法定/链/支付/Signer/Provider/资金等全部通过，并完成最终预览和责任确认后才可以触发；技术实际执行仍 Open |
| 发布二次确认 | 展示本期数量×价格 U/开始结束/准入/锁仓/钱包/文件版本等摘要，提供「确认/取消」 | 原子检查容量与固定快照；关闭弹窗不得丢草稿；发布前再次检查状态/并发 |
| 「暂停认购」 | 仅实际在售且有权时，展示「新认购将停止；在途订单继续处理」，二次确认 | 不丢订单，不释放有义务的份额；真实链上可接单入口也须受控（生产实现 O） |
| 「恢复认购」 | 仅在有效期内重新满足条件时可操作，否则给原因 | 不因暂停恢复造成再预留；不改变历史支付和 Token |
| 「认购结束/关闭」 | 截止停止新单；关闭前列出待处理的付款/配售/退款；关键不可逆操作需确认 | **关闭不是立即销毁 Token**，仅释放确已无在途义务的未分配份数，关闭后不可直接重开 |
| 「查看认购/锁仓记录」 | 从 Offering 关联视图跳原全局记录/主账详情 | 不在 Offering 复制或重建资金/Token 账本 |
| 发布后「编辑」 | 默认关键条款只读、留历史与变更说明；受控变更流程另审 | **不提供直接改已生效钱包/协议/权益版本的自由文本保存** |

## 4. UI 文案候选（可依 UX 规范微调）
| 情形 | 推荐提示 |
|---|---|
| 没有当前可用 Instrument |「请先完成这项资产的权益结构，再创建发行方案。」|
| Draft 尚未填写完毕 |「可先保存草稿。完成缺少的资料后，再检查发行准备。」|

| 企业收款钱包未选 |「请选择本企业已绑定的收款钱包。它是最终结算账户，不是投资者付款地址。」|
| 文件扫描失败 |「该文件暂不可引用，请重新上传或选择已验证的文件版本。」|
| 生产门尚未确认 |「业务资料已完备，但真实发行尚未获准。请完成下方生产准入检查。」|
| Free 点击发布 |「Free 可保存正式发行方案并内部预览。真实上架和募资需要 Standard 及全部生产准入。」|
| 发布后未来开始 |「发行已发布，尚未到认购开始时间；投资者当前不能认购。」|
| 暂停时有在途付款 |「已暂停新增认购。之前的订单、付款和 Token 交付将继续受控处理。」|
| 到期而仍有退款 |「认购已结束，仍有待处理订单/退款；全部处理完成后才能关闭。」|
| 钱包解绑或文件引用失效 |「发行准备信息已发生变化，请重新核对收款钱包／文件版本。」|
| 保存失败 |「保存失败，当前输入仍在本页面。请检查网络后重试。」|

## 5. 版本与权限（必须联合判断）
| 企业状态 | 创建/编辑 Offering Draft | 内部投资者预览 | 真实发布/收款/Mint | 历史记录 |
|---|---|---|---|---|
| **KYB 通过的新 Free** | 允许 | 标准模板只读 | 禁止；升级解释 | 自身业务资料可查看 |
| **Standard 且 KYB 通过** | 允许 | 允许相应发布准备/预览 | **只有法务/生产/资金/Token 实际门均通过才可能允许**；目前未授权实接 | 可查看真实主账 |
| **Standard 宽限期** | 以 U01 已批准宽限规则限制新增真实业务 | 按历史授权和安全策略 | 禁止新增真实发行；必要存续操作受控 | 保留已存在真实投资者义务 |
| **降级 Free（历史 Standard）** | 历史业务只读，不等同新 Free | 历史可查看范围受控 | 禁止新增真实发行 | 不删历史资金/Token/文件 |
| **KYB 未通过 / 跨 Tenant** | 不得越过已批准业务准入 | 不泄露他人数据 | 禁止 | 仅经授权的必要状态 |

## 8. 2026-11-11 补充｜统一 KYC 与资产相关方披露（DEC-069 / DEC-070）

### 8.1 投资者准入规则按 DEC-069 收敛

- 投资者在 V/M 投资者端完成平台统一 KYC；第三方服务商核验，平台维护权威结果。
- Issuer 不配置投资者类型、地区、KYC 等级或 Offering 级资格条件，不人工批准/拒绝投资者。
- 本 Offering 的认购前置只读取平台统一 KYC 状态：**通过**才可进入认购确认；未开始、核验中、未通过、需重新核验或 Unknown 均阻断。
- Offering 仍可配置普通认购交易条件：认购起止时间、单笔最低认购金额、可发行 Token 数量、锁仓规则及其他已批准交易参数。这些不是额外投资者资格配置。
- 原表中的 `investor_types` 与 `allowed_regions` 为历史候选字段，V1/MVP 已移除；`kyc_requirement` 改为平台固定只读状态，不得作为企业配置项。

### 8.2 资产相关方披露按 DEC-070 增补

- 在 C「发行准备」增加折叠分组「投资者披露 → 资产相关方」。
- 从当前 Asset 相关方记录中选择本期需要披露的主体；每个 Offering 独立选择，不修改 Asset 的内部资料。
- 投资者端仅展示所选主体的名称、角色、简要职责说明及可披露的注册地区；注册编号、联系人、电话、邮箱、许可编号、内部备注、原始附件不对投资者显示。
- 没有选择主体时，投资者端不显示空白区块；Issuer 最终预览提示确认本期是否存在适用披露义务。
- 最终发布确认时固化本 Offering 的披露快照；Asset 资料后续变化不得自动回写已发布 Offering。
