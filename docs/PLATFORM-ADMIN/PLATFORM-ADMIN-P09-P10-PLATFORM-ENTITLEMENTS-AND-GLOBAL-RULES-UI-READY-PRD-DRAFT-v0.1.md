# RWA SaaS｜Platform Admin P-09～P-10：平台权益与全局规则 UI-Ready 产品规格（Draft v0.1）

> **文档状态：Draft｜2026-11-18**
>
> 本文细化平台总后台「平台规则与套餐」模块：P-09 管理 Free/Standard 商业套餐能力与资源配额版本；P-10 管理平台级强制规则、统一投资渠道展示范围规则及规则版本生命周期。
>
> 当前商业模式以 DEC-037 为准：永久 Free + 付费 Standard；旧 14 天 Trial/30 天恢复窗口已废止。本文不建立独立投资者资格审核规则引擎。

## 0. 范围、批准依据与责任边界

### 0.1 页面组

| 页面组 | 主要依据 | 责任 |
|---|---|---|
| P-09 平台权益与套餐管理 | M19-F001、M19-F005/F006；DEC-037 | 维护 Free/Standard 套餐能力矩阵、资源限制及生效版本 |
| P-10 平台全局规则管理 | M19-F005/F006；DEC-034 R05；M23-F004 | 管理平台强制规则、统一投资渠道展示地区/受众选项及版本审批 |

### 0.2 现行商业规则

- V1 仅有**永久 Free**与**付费 Standard**，不再存在 Trial，不设置 14 天倒计时或 30 天恢复窗口。
- Free 可长期使用绝大部分 Issuer SaaS 的配置与 Sandbox 模拟能力；不得产生真实认购、真钱支付、法定登记、主网 Token 或真实收益出款。
- Standard 为唯一付费套餐，按月/年订阅；商业 KYB、合同、商业付款满足后获得商业权益。
- Standard 不是生产许可。每个 Issuer/Offering 的真实发行、认购、资金、法定登记、Token 与收益仍须满足独立法律、Provider、Signer、安全及业务 Gate。
- Free→Standard 沿用同一 Tenant；Sandbox 模拟事实不得通过改套餐/改状态转换为真实生产事实。
- Standard 失效、暂停或降级不得删除既有真实投资者权益、真钱、登记、Token、收益或法定义务。

### 0.3 本模块明确不管理

- 不管理单个 Tenant 当前套餐开通/暂停/恢复动作；P-05 负责平台运营入口，M01 是 Subscription/Entitlement 商业主账。
- 不管理 Issuer 自身的 Instrument/Offering 权益条款；这些由 Issuer 原业务模块负责。
- 不建设独立投资者资格规则、投资者类别/等级、单个 Offering 的资格引擎、投资限额或认购上下限。
- 不建设自动配售规则编辑器；付款最终性、配售和订单 Gate 由原交易领域负责。
- 不提供可视化脚本、任意表达式、低代码流程或动态策略编程。
- 不把套餐状态直接映射为真实生产权限，不绕过法律/资金/Token Gate。
- 不修改历史已签合同、订单、Quote、持有人登记或既有权益。

## 1. P-09｜平台权益与套餐管理

### 1.1 页面目标

平台运营人员能查看和维护当前 Free/Standard 的商业能力定义、Sandbox/Production 能力边界及资源配额版本。套餐配置是商业授权规则，不是发行合法许可或真实执行授权。

### 1.2 页面结构

P-09 提供三个页签：

1. **套餐列表**：Free、Standard 当前生效版本及状态。
2. **能力矩阵**：按产品模块查看 Free/Standard 的能力差异及环境限制。
3. **资源配额**：查看/维护已批准的资源额度和限制版本。

套餐价格/账期如尚未完成商业批准，只显示「待配置/待批准」，不能用 Mock 数字冒充正式价格。

### 1.3 套餐列表

| 字段 | 规则 |
|---|---|
| 套餐名称 | Free / Standard；不允许新增 Trial/Growth |
| 套餐代码 | 系统固定代码 |
| 套餐类型 | 永久免费 / 付费订阅 |
| 计费周期 | Free 不适用；Standard 月付/年付 |
| 当前价格 | 只读显示已批准价格；未批准显示「待配置」 |
| 当前版本 | 生效的 Plan/Entitlement Version |
| 状态 | 草稿、待审批、生效、已停用（历史版本只读） |
| 适用范围 | Issuer SaaS V1 |
| 最近更新时间 | 时间与操作人 |
| 操作 | 查看详情、查看版本历史 |

V1 不显示 White-label/API/SDK 的套餐，它们不属于当前 Issuer SaaS 套餐配置。

### 1.4 套餐能力矩阵

按产品域展示，不以大量散乱开关堆砌页面：

| 能力域 | Free | Standard | 关键约束 |
|---|---|---|---|
| 企业资料与 KYB | 可使用 | 可使用 | 商业 KYB 状态独立显示；Standard 商业转化需满足 KYB |
| 企业钱包配置 | 可配置/模拟 | 可配置；真实业务使用须独立验证 | 钱包存在不等于已获生产 Signer 权限 |
| Asset / Instrument / Offering 准备 | 可完整配置与模拟 | 可配置及在满足 Gate 后用于真实业务 | Free 模拟事实不能转生产 |
| 投资者门户 | 内部只读预览 | 可生成真实门户能力（仍需独立发布/域名 Gate） | 不与统一投资平台 M 混同 |
| 投资者 KYC / 认购 | 仅演示/模拟 | 有资格使用真实业务流程，强制有效 KYC | 不建立独立投资者资格引擎 |
| 真实资金/退款/结算 | 不允许真实执行 | 商业权益允许进入流程，但须资金/Provider/法域 Gate | Standard 不是资金托管或划拨授权 |
| Token / 链上操作 | 仅模拟/批准测试环境 | 可进入独立生产准入流程 | 不自动授予主网部署、Mint 或 Signer 权限 |
| 收益/本金/退出 | Sandbox 模拟 | 真实业务仍须法律义务及资金执行 Gate | 不得将模拟批次转为真实出款 |
| 白标/Open API/SDK | 不包含 | 不包含在本版 Standard | 独立商业产品规划 |

以上是商业能力矩阵，不是对每个业务模块当前代码完成度的宣称。生产能力仍以服务端 Entitlement 和原领域 Gate 为准。

### 1.5 资源配额

资源配额仅管理有成本、性能或安全意义的技术资源，不新增企业成员席位（MVP 一个账号=一个企业）。

| 配额项 | 单位/类型 | 配置规则 |
|---|---|---|
| Asset 数量 | 个 | Free/Standard 分别显示；具体值未批准时显示待配置 |
| Offering 数量 | 个 | 不等于实际发行容量 |
| 文件存储空间 | MB/GB | 受文件服务端限制 |
| 单文件大小 | MB | 必须与文件服务校验一致 |
| Sandbox 模拟资源 | 次/额度 | 只限制模拟资源消耗，不影响真实法律义务 |
| 其他已批准资源 | 由平台定义 | 不允许创建任意脚本或未知配额 |

字段：
- 配额名称、代码、单位；
- Free 当前值、Standard 当前值；
- 是否启用；
- 超额处理方式（阻止新建/提示升级/只读查看；仅可选择已批准选项）；
- 生效版本、开始时间；
- 变更原因、审批记录。

**数值决策门**：本批不虚构 Asset/Offering/存储等具体数量。未有正式批准值的配额只能显示「待配置」，不能在生产中按 0 或无限额度解释。

### 1.6 套餐版本编辑与审批

允许操作：
1. 创建新草稿版本（从当前生效版本复制）；
2. 修改待批准的能力/配额字段；
3. 预览 Free 与 Standard 差异；
4. 提交审批；
5. 审批通过后按设定生效时间启用新版本；
6. 查看历史版本与影响摘要。

必填字段：
- 版本名称/编号；
- 变更原因；
- 变更项及变更前后值；
- 影响的套餐与能力域；
- 生效时间；
- 对现有 Tenant/订阅的适用方式（仅新订阅/续费生效，或需客户重新确认）。

保护：
- 不允许覆盖已生效版本；修改必须生成新版本。
- 不允许追溯改变已有合同、有效订阅和既有真实业务权利。
- 已有 Tenant 的能力状态由 M01/M19 服务端按有效版本计算；P-09 不直接修改 Tenant。
- 如变更影响现有客户，应显示影响数量与客户通知要求；未知时阻断生效。
- 任何套餐能力不得放宽法律、KYC、资金、Token、Signer、安全或法定登记硬性 Gate。

### 1.7 套餐详情页面字段

顶部：
- 套餐名称、代码、版本、状态；
- 免费/付费类型、计费周期；
- 当前生效时间；
- 当前订阅数量（仅汇总，按权限）；
- 最近更新时间。

分区：
1. 商业信息：价格状态、周期、合同模板引用、账单策略引用；
2. 能力矩阵：按 1.4 展示；
3. 资源配额：按 1.5 展示；
4. 生产 Gate 说明：显示独立 Gate，不提供“打开真实生产”开关；
5. 版本历史：变更项、审批人、生效时间、影响摘要。

### 1.8 P-09 异常与验收

- Free 不显示试用倒计时、Trial 到期或恢复窗口。
- Standard 付款 Unknown 时不得显示商业权益已生效；先查询原 M01 Intent。
- 修改套餐版本不能直接改写 Tenant 当前状态。
- 套餐生效不等于生产 Gate 通过。
- 配额数值待批准时不得自动填 0 或无上限。
- 旧版本只读可查，不能删除或覆盖。
- 验收必须覆盖 Free 永久有效、Free→Standard 同 Tenant、模拟数据不转生产、Standard 失效保留既有义务、版本变更不追溯覆盖。

## 2. P-10｜平台全局规则管理

### 2.1 页面目标

维护平台必须统一执行的规则版本和统一投资渠道展示规则，确保不同 Tenant、Offering 和运营人员不会绕过平台硬性边界。

P-10 管理的是**平台级规则**，不是 Issuer 业务条款，也不是投资者个人资格判断。

### 2.2 页面结构

P-10 提供三个页签：

1. **平台规则目录**：查看当前有效规则、适用范围、状态及版本。
2. **渠道展示规则**：管理总投资者平台 M 的可申请展示地区和预设展示受众范围。
3. **规则审批与版本历史**：处理规则草稿、审批、生效、停用和历史影响。

### 2.3 规则类型（V1 限定）

| 规则类别 | 主要内容 | 编辑边界 |
|---|---|---|
| 平台强制业务 Gate | Free/Standard 商业权益与生产 Gate 分离、KYB/KYC 必要条件、Offering 正式发布及渠道申请前置条件 | 核心硬性 Gate 以批准决策/代码规则为准；页面只读显示，不允许运营自由关闭 |
| 统一投资渠道展示地区 | Issuer 可申请的地区范围、已限制/暂停地区、规则来源和生效时间 | 只维护平台可接受的展示范围；不能宣称法律许可或自动批准发行 |
| 统一投资渠道展示受众 | M 页面允许使用的固定展示受众选项与适用条件 | 仅控制页面可见范围，不得创建投资者资格类别或投资限额 |
| 支付/网络支持信息 | 当前平台支持的支付网络与资产标识 | V1 基线为 OP Mainnet USDT；只读显示，未通过技术/安全批准不得新增网络 |
| 资产模板开放信息 | 当前平台开放的资产类型/模板版本 | 与 P-09 产品能力矩阵一致；不得在此临时增加未经批准的模板 |

### 2.4 投资渠道展示地区规则

列表字段：
- 规则编号、规则名称；
- 地区/法域代码及显示名称；
- 规则状态：可申请、暂停申请、不支持、待核实；
- 允许展示的 M 页面范围；
- 生效时间/失效时间；
- 规则依据/批准引用；
- 规则版本；
- 最近更新时间；
- 操作：查看/编辑草稿/查看历史。

规则详情字段：
- 地区代码（系统标准代码）；
- 地区名称；
- 申请状态；
- 是否允许 Issuer 提交该地区上架申请；
- 是否允许在 M 展示；
- 适用受众选项（仅平台固定枚举）；
- 适用资产/Offering 范围（仅引用已批准枚举，不提供自由分类）；
- 规则依据/外部法律审查引用；
- 生效日期、复核日期；
- 变更原因、审批记录。

**硬限制：**
- 没有适格法律/合规依据的地区，不得设置为「可申请」或「可展示」。
- 「可展示」只代表平台渠道范围允许，不等于该 Issuer/Offering 在当地获得发行许可，也不等于某投资者有资格认购。
- P-15 审核通过前必须读取当前有效地区规则；地区规则 Unknown/过期/冲突时阻断审核通过及自动上架。
- P-15 批准展示范围不得超过 Issuer 原申请授权范围，也不得超过本规则允许范围。
- 规则收紧影响已上架 Listing 时，标记待复核；涉及明确强制限制时按规则立即暂停/限制展示，并保留历史。

### 2.5 展示受众规则

- 受众选项必须来自平台固定枚举，不提供任意自由输入。
- 受众仅用于 M 页面展示可见范围，不作为独立投资者资格规则。
- 不创建专业投资者/合格投资者/风险等级/投资限额等资格分类引擎。
- 投资者有效 KYC 是强制认购 Gate；是否可认购由 M 原认购业务按 KYC、地区法律限制、Offering 窗口、必要签署及交易条件判定。
- P-10 不允许通过受众规则把 KYC 未通过/已过期/Unknown 的用户改为可认购。

### 2.6 规则目录列表字段

| 字段 | 说明 |
|---|---|
| 规则编号 | 唯一 Rule ID |
| 规则名称 | 平台规则名称 |
| 规则类型 | 平台强制 Gate/渠道地区/展示受众/支付网络/资产模板 |
| 适用范围 | 全平台/M 渠道/指定地区/指定产品能力 |
| 规则版本 | 当前或历史版本 |
| 状态 | 草稿、待审批、生效、已暂停、已停用、待核实 |
| 强制级别 | 法律/安全强制、平台统一、产品能力约束 |
| 生效时间 | 规则开始生效时间 |
| 来源依据 | DEC/法律意见/安全决策/平台产品批准引用 |
| 最近更新时间 | 时间及操作人 |
| 操作 | 查看详情 |

### 2.7 规则详情与版本编辑

允许操作：
- 查看当前生效版本；
- 基于当前版本创建草稿；
- 编辑草稿字段；
- 预览影响范围；
- 提交审批；
- 审批通过后按批准时间生效；
- 暂停/停用未来适用规则；
- 查看历史版本和审计记录。

禁止：
- 直接修改已生效版本；
- 删除历史版本或历史审批证据；
- 自由编写脚本/表达式；
- 降低法定/安全强制规则优先级；
- 把平台规则应用为某 Tenant 的私人 Offering 条款；
- 用 P-10 手工改变投资者 KYC、认购资格、订单、付款或持有人登记状态。

### 2.8 规则优先级

规则冲突按以下顺序处理：

1. 适用法律、制裁/AML、安全及其他不可覆盖的强制要求；
2. 平台全局强制规则；
3. 平台产品能力与商业 Entitlement；
4. Tenant/Issuer 在允许范围内的配置；
5. 单个 Offering 的展示与交易条款。

低层级规则不得放宽或覆盖高层级约束。平台运营人员无权通过 P-10 绕过法律、安全或原业务领域 Gate。

### 2.9 规则生效与历史保护

- 新版本默认只影响生效时间之后的新申请/新业务动作。
- 已提交申请固定其提交时授权与披露资料；规则发生强制变化时，P-15 必须重新核验。
- 已签署 Quote、订单、合同、法定登记和既有权益不得被新规则静默覆盖。
- 法律/安全强制规则需要立即生效时，必须有适格依据、授权人、影响范围和审计记录；对现有 Listing 的限制/暂停只影响 M 渠道展示，不删除 Issuer Offering 或历史交易。
- 规则启停、审批、生效与停用均追加版本事件，不能覆盖。

### 2.10 P-10 异常与保护

- 规则依据缺失：不允许启用。
- 审批权限失效：拒绝提交或审批，记录原因。
- 规则版本冲突：要求刷新后重新审批。
- 地区规则 Unknown：P-15 不得通过自动上架。
- 受众选项不在固定枚举：拒绝保存。
- 规则更新影响已上架 Listing：生成复核任务并显示受影响范围。
- 规则停用不等于删除历史；旧版本继续可查。

## 3. 明确取消/排除的旧规则能力

| 历史/候选能力 | 当前处理 |
|---|---|
| 14 天 Trial、30 天恢复窗口 | 已由 DEC-037 明确废止；P-09 不得创建 Trial 套餐或倒计时 |

## 6. 尚未批准的参数与技术决策门

本批 UI 不伪造下列值或权力：
- Free/Standard 的具体价格、税费、账单币种/周期参数、发票规则；
- Asset/Offering/存储等资源配额数值及超额计费；
- 具体可申请国家/地区、法律依据、适用投资者展示范围；
- 受众固定枚举的正式选项与各法域差异；
- 法律/安全规则双人审批角色码、紧急暂停权限与阈值；
- 规则服务端表达、缓存失效、版本冲突、事件幂等及 API；
- 真实支付网络扩展、资金/Signer/合约及生产执行授权。

未批准地区不得默认开放；未批准价格/配额不得作为正式商业承诺；未知规则不得默认为通过。

**本批结论：P-09 平台权益与套餐管理、P-10 平台全局规则管理形成 UI-Ready 产品规格 Draft v0.1。只管理永久 Free/Standard 商业权益和平台级强制/渠道展示规则；不恢复 Trial、不建设独立投资者资格审核或低代码规则引擎。待产品负责人审核后进入原型。**


## 7. UI-Ready 补充收口：编辑表单、审批状态与影响确认

本节补齐 P-09/P-10 的页面级编辑控件、状态转换、审批前确认和异常反馈。具体价格、配额数值、法域及受众枚举仍是开放决策门，不得以演示值替代正式配置。

### 7.1 P-09 套餐/权益版本状态机

| 当前状态 | 操作 | 目标状态 | Guard |
|---|---|---|---|
| 草稿 | 保存 | 草稿 | 字段格式校验通过 |
| 草稿 | 提交审批 | 待审批 | 变更原因、差异、适用范围、生效方式完整 |
| 待审批 | 批准 | 已批准待生效/生效 | 审批权限有效；审批人与申请人职责分离 |
| 待审批 | 退回 | 草稿 | 必须填写退回原因 |
| 已批准待生效 | 到达批准生效时间 | 生效 | 生效前再次检查商业批准和影响范围 |
| 生效 | 创建新版本 | 新草稿 | 复制当前版本，不覆盖当前生效版本 |
| 生效 | 停用/替换 | 已停用/历史只读 | 必须有替代方案或明确不再销售说明 |

- 历史版本永远只读，不提供删除。
- 未配置具体价格/配额时，套餐仍可展示结构，但不得提交为可供客户承诺的商业版本。
- Free 永久有效，不允许设置到期日、试用天数或恢复窗口。
- Standard 月付/年付的具体金额、税费、发票和账单币种须引用商业批准记录。

### 7.2 P-09 套餐版本编辑字段

| 字段 | 控件 | 必填/校验 |
|---|---|---|
| 套餐 | 只读 | 仅 Free 或 Standard |
| 版本名称 | 文本 | 必填，≤80字 |
| 版本说明 | 多行文本 | 必填，≤500字 |
| 计费周期 | 单选 | Free 不适用；Standard 月付/年付 |
| 价格 | 金额字段 | 仅已批准价格可填；未批准保持「待配置」，不得输入临时 Mock 值 |
| 能力域 | 结构化矩阵 | 仅使用已定义产品能力项；不得新增自由能力开关 |
| Sandbox/Production 边界 | 只读规则摘要 | 不允许在 P-09 放宽法律、安全或生产 Gate |
| 资源配额 | 数值/单位 | 未批准值锁定为「待配置」；不允许负数、空值转 0 或无限值 |
| 超额策略 | 固定枚举 | 阻止新建/提示升级/只读查看；仅可使用已批准选项 |
| 适用对象 | 固定枚举 | 新订阅/续费/全部现有订阅；必须说明对现有合同影响 |
| 生效时间 | 日期时间 | 必填；不得早于批准时间，除非存在明确追溯法律依据 |
| 变更原因 | 多行文本 | 必填，≤1000字 |
| 依据/批准引用 | 引用选择 | 涉及价格、配额、客户权益时必填 |

保存时校验字段完整性；提交审批前显示「变更前/变更后」差异、受影响 Tenant 数量、现有订阅适用方式及未解决依赖。受影响 Tenant 数量 Unknown 时阻断提交生效。

### 7.3 P-09 操作确认弹窗

**提交审批：**
- 版本编号、套餐、变更原因；
- 变更字段及前后值；
- 适用对象与生效时间；
- 受影响 Tenant 数量/统计时间；
- 是否影响现有合同或订阅；
- 按钮：「提交审批」。

**批准生效：**
- 当前审批人及职责分离校验；
- 商业依据引用；
- 影响范围与客户通知要求；
- 生产 Gate 不受套餐配置覆盖的确认；
- 按钮：「批准该版本」。

**停用版本：**
- 停用原因；
- 替代版本或后续销售安排；
- 现有订阅处理方式；
- 按钮：「确认停用」。

### 7.4 P-10 规则状态机

| 当前状态 | 操作 | 目标状态 | Guard |
|---|---|---|---|
| 草稿 | 保存 | 草稿 | 规则字段格式正确 |
| 草稿 | 提交审批 | 待审批 | 规则依据、适用范围、影响分析完整 |
| 待审批 | 批准 | 已批准待生效/生效 | 审批权限有效且不自批 |
| 待审批 | 退回 | 草稿 | 退回原因必填 |
| 生效 | 创建修订 | 新草稿 | 当前版本只读保留 |
| 生效 | 暂停/停用 | 已暂停/已停用 | 需填写依据、影响范围和应急/替代安排 |
| 已暂停 | 恢复 | 生效 | 原因解除、规则依据有效、重新审批 |

### 7.5 P-10 规则编辑字段与验证

| 字段 | 控件 | 校验 |
|---|---|---|
| 规则名称/编号 | 文本/系统编号 | 名称必填≤100字；编号唯一只读 |
| 规则类型 | 固定下拉 | 平台强制Gate/渠道地区/展示受众/支付网络/资产模板 |
| 适用范围 | 固定枚举/受控选择 | 必须明确平台、M渠道、地区或产品能力范围 |
| 强制级别 | 固定枚举 | 法律/安全强制、平台统一、产品能力约束；不得降低上级规则级别 |
| 规则内容 | 结构化字段 | 不允许脚本、任意表达式或自由执行逻辑 |
| 依据引用 | 引用选择 | 必填；地区/受众规则必须具备适格法律/合规依据 |
| 生效/复核时间 | 日期选择 | 必填；复核时间不得早于生效时间 |
| 影响范围 | 系统计算摘要 | Unknown 或无法确定受影响 Listing 时阻断生效 |
| 变更原因 | 多行文本 | 必填，≤1000字 |
| 版本说明 | 多行文本 | 必填，≤500字 |

**地区规则专属校验：**
- 地区代码必须来自标准地区枚举；不允许自由输入自造代码。
- 状态为「可申请/可展示」必须同时具有适格依据、批准引用、生效时间和复核时间。
- 「待核实」和「不支持」均不得作为可上架地区。
- Issuer 原申请授权范围、P-10 当前规则范围、P-15 最终批准范围三者取交集；不得扩大任一方范围。
- 规则收紧影响现有 Listing 时，先计算受影响 Listing 并生成复核任务；强制限制可依批准规则立即暂停展示。

**受众规则专属校验：**
- 仅允许选择平台批准的固定展示枚举。
- 不提供投资者等级、风险等级、合格投资者判断、投资限额或 KYC 结果覆盖字段。
- 展示受众变更不得使原本不符合 KYC/法律/交易 Gate 的投资者变为可认购。

### 7.6 P-10 规则影响确认

提交审批或生效前展示：
- 规则 ID/版本；
- 变更前后内容；
- 受影响产品端、地区、Tenant/Listing 汇总；
- 现有申请是否需重新核验；
- 已上架 Listing 的处置建议（待复核/限制展示/暂停）；
- 是否需要通知 Issuer；
- 法律/安全依据及复核日期；
- 未知或无法计算的影响项。

影响范围 Unknown 时，不允许将规则标记为已生效；不得以「先发布后补数据」绕过。

### 7.7 P-09/P-10 异常与页面反馈

| 场景 | 页面反馈 | 下一步 |
|---|---|---|
| 价格/配额未批准 | 「该配置尚未获得商业批准」 | 保存草稿，不得对客户生效 |
| 规则依据缺失/过期 | 「缺少有效规则依据，无法提交审批」 | 补充依据 |
| 受影响对象计算失败 | 「影响范围暂不可确认」 | 保持草稿/待核实，不得生效 |
| 审批人与申请人相同 | 「申请人不能审批自己的变更」 | 转交其他适格审批人 |
| 规则版本冲突 | 「规则已更新，请刷新后重新提交」 | 读取最新版本 |
| 地区规则 Unknown | 「地区规则待核实，已阻止自动上架」 | P-15 保持待核实并关联 P-07 |
| 规则变更与更高优先级冲突 | 「该变更不能覆盖更高优先级的强制规则」 | 修改草稿或取消 |
| 新版本生效后历史数据查询 | 仅展示历史版本 | 不允许覆盖或删除 |

### 7.8 UI-Ready 验收补充

- P-09 只能出现 Free/Standard；不存在 Trial/Growth 新建、编辑或到期倒计时。
- P-09 能力矩阵与配额矩阵有明确字段、单位、版本和未批准状态。
- P-09 变更前后差异、影响范围、审批、生效与历史版本可追溯。
- P-10 地区规则、受众规则使用固定结构化字段；不存在任意脚本或资格规则编辑器。

- 所有危险操作均具备确认弹窗、原因、结果反馈及重复提交保护。
