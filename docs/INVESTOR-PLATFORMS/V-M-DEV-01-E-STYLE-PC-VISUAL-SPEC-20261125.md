# V/M 投资者平台｜DEV-01 E 风格 PC Web 视觉与关键页面规格

> 2026-11-25 用户正式选择：**E = 极简机构金融 × 现代资产投资商城**。本文件是 DEV-01 前端原型视觉和页面结构依据。参考 DEV-00 报告、[V/M 共用 PRD](V-M-SHARED-UI-READY-PRD-v0.1.md)、[M 专有页面 PRD](M-UNIQUE-PAGES-UI-READY-PRD-v0.1.md) 与 [开发计划](V-M-PC-WEB-DEVELOPMENT-PLAN-v0.1.md)。本批只做 PC Web 前端 Mock 原型，不做真实后端、API/数据库、KYC/MPC/链/合约服务，H5 后期适配。视觉 token 属本轮新确认方向；原 PRD 业务规则不得被视觉要求覆盖。

## 1. 品牌气质与设计原则

- 网站定位：**专业可信的 RWA 投资者网站**。首页与投资发现参考投资商城的直观浏览；详情、认购、持仓等采用机构金融的清晰、克制信息组织。
- 关键词：清爽、国际化、优质、可信、资产直观、合同权益清楚；拒绝黑金土豪风、重度霓虹 Web3 风、交易所行情终端风、Issuer 管理工作台外壳。
- V：顶部左侧显示当前 Issuer 授权 Logo/展示名，主页 RWA 与公开 Offering 优先；不在 V 首页展示大块企业档案。M：平台 Logo，多 Issuer 分类和发现；底层同 Offer 详情组件完全复用。
- 设计优先顺序：可理解的投资流程 > 风险/权益准确表达 > 视觉装饰。禁止“保本、高收益保证、稳赚”等无依据文案。
- PC-only：以 1440px 为主设计，检查 1280px 和 1920px；非本轮要求 H5 响应式或手机导航。低于既定 PC 宽度时可安全横向容纳/滚动，但不能溢出遮挡关键内容。

## 3. 通用 PC 页面骨架

全站 SiteHeader：左侧 V Issuer Logo/品牌或 M Platform Logo；中部“首页｜投资机会｜我的投资”；右侧“帮助与客服｜消息｜登录/账户”。SiteFooter：风险、隐私、法律政策、帮助与声明。主页和发现页避免营销弹窗；资产详情禁止强迫登录才能阅读合法公开资料。

共用卡片 OfferingCard：横向 16:10 或 4:3 资产图片/合法占位图；项目名、资产大类/地区、权益类别、单价 U、最低认购 U、可披露的合法收益摘要与“查看详情”。M 卡片额外显示发行企业名称；V 不在每张卡重复大块企业介绍。无受权收益资料时显示“收益以权益条款为准”，不得自动造年化。

信息优先：底层资产是什么 → 投资者取得什么法律权利 → 本期价格与认购条件 → 风险和文件 → 下一步。资产估值、募集发行额和实际分配不能混合。

## 4. 第一批四组视觉样板

### A｜V 企业投资者门户首页

- Hero（建议 2 栏）：左侧大标题“探索现实世界资产的投资机会”或更克制的批准文案、短简介、主按钮“浏览投资机会”；右侧资产主题视觉，不放投资收益承诺、发行企业资质排名。
- 主体：可见 Offering 卡（建议桌面 3 列）、按资产分类浏览、简单“三步了解投资”/风险教育、必要免责声明与 Footer。
- Issuer 识别：仅站点左上角 Logo/展示名及资产来源；企业详情统一在资产详情的企业信息模块和独立信息页查看。
- 模拟空态：无可公开 Offering 时显示“目前暂无可展示的投资机会”，附帮助或首页说明，不伪造数据。

### B｜M 总投资者平台首页

- Hero：标题“探索多元 RWA 投资机会”，主按钮“查看投资机会”；清楚表述“由不同发行企业提供”，不能暗示平台担保。
- 资产分类浏览：房地产/非上市股权/企业借款等已开放种类。下方“最新上架”有效 Listing OfferingCards，展示 Issuer 名称。
- 简单分类/快捷筛选入口通往列表；DEV-01 可先做最小真实路由和现成 Fixture，完整多维筛选留 DEV-02。
- 避免大盘式币价行情、年化排行榜、“精选”无批准算法。Listing 未批准/同步 Unknown/下架的不出现在 M 公共列表。
- 无有效 Listing 时说明空态，不展示无授权其他 Issuer 的 V 专属 Offering。

### C｜V/M 共用资产详情页面（两种样例）

- PC 两列结构：左侧主内容约 8/12，右侧认购摘要卡约 4/12，正文宽足够阅读；认购卡可在有空间时 sticky，但不得遮挡页脚或错误提示。
- 顶部：面包屑、Offering 标题、Asset 类别、权利类型、状态、合法资产图片/占位图。
- 左侧依次：资产概览 → 底层资产关键字段（六类模板以已开放模板为准，DEV-01 重点 住宅、企业借款）→ 投资者法律权益（Instrument）→ 发行与项目说明 → 发行企业卡（Logo/名称/查看企业信息）→ 风险与文件。
- 右侧：每 Token 单价 U、最低认购额、份数/金额、认购起止与状态、锁仓与风险提示、唯一主按钮“认购”或受限状态说明。
- 住宅收益参与：住宅面积/位置/运营状态/合法净收益摘要按真实 Fixture，有合同参与比例，不能将租金当保证分红。企业借款债权：债务人/合同事实/固定年利率（如 12%）、月付息/到期还本、利率与风险分开；本金不算利息。
- 两端必须使用同一 AssetDetailShell，唯一差别是品牌、已授权页面入口和 Listing Gate；同一 Offering 不得有两套价格或权益事实。
- 企业卡入口可进入最小可运行企业信息页，DEV-02 再补全；不得出现死按钮。

### D｜四步认购向导样板

- 顶部横向步骤条：①确认认购 → ②协议与风险 → ③钱包付款 → ④交易进度。
- 主区+右侧摘要卡；每步只突出一个主动作和清晰的“上一步/返回资产详情”，右侧保持项目名、权益、单价 U、份数和总额（按快照）。
- Step1：整数份数、单价 U、总额 U、最低金额/份数、必要错误提示，金额计算采用十进制稳健处理；不得让数量输入任意小数 Token。
- Step2：协议/风险文件版本摘要、阅读确认与必要签署的 UI 占位。真实签署在后续 DEV-04 Mock；本批不可把“已阅读”叫成合法签署。
- Step3：固定 OP Mainnet USDT、演示钱包/接收地址字段、收款合约标签、演示按钮。需要**明显 Mock 标记**，绝不调真实链/钱包签名或模拟虚假的实际付款完成。
- Step4：付款观察→配售→法定登记→Token 交付独立时间线，Demo 场景可以显示各个 Pending/Unknown/Final 状态；付款成功不自动等于完全完成。
- DEV-01 仅验证步骤条 UI/页面跳转/输入反馈/摘要实时更新/Mock 状态展示与返回路径；DEV-03/04 再做完整 OTP/KYC/订单/资金业务流程，不提前研发这些模块。
- 登陆/KYC 未接时明确展示“DEV-01 演示占位，正式业务守卫将在后续原型阶段补齐”，不通过隐藏状态假装已完成。

## 5. 最小路由与演示数据

演示入口建议 `/v/:issuerSlug` 与 `/m`（源自 DEV-00 报告），下设 `/opportunities`、`/opportunities/:offeringId`、`/issuers/:issuerId`、`/subscribe/:offeringId/{quote,documents,payment,progress}`、`/demo`。首页到详情、详情到企业信息页、详情到认购、四步前后跳转必须可点击、可刷新直接访问；非本批完整业务页可受控展示“后续阶段实现”，不可死链接/空白屏。

Fixture：两个 Issuer、住宅收益参与与企业借款债权两条真实关联的模拟数据，M Listing 只展示有效模拟上架 Offering；V 只展示本企业资产；所有金额、钱包、交易和企业资料为明确 Mock 示例。Mock 控制台最小提供“载入住宅案例/载入债权案例/重置”，DEV-02～06 再扩展功能。

## 6. DEV-01 交付和验收门

1. 新独立代码分支 + `apps/investor-portal` 可运行；**不改**现有 `apps/issuer` 和 `apps/website` 正式代码。
2. V 首页、M 首页、共用详情（住宅/企业借款）、认购四步 PC 样板和最小企业信息页存在真实路由与交互。
3. React/TypeScript 类型检查、Build、自动化基本路由/计算/渠道过滤检查实际执行并记录结果；没有则标 NOT EXECUTED。
4. Chrome/Playwright 打开 **1280/1440/1920** 宽屏，截取 V 首页、M 首页、两种 Asset 详情、四步认购；至少覆盖直接刷新、错误 URL、无 Listing、数量校验、Mock 标记和返回路径；记录 Console Error。
5. DEV-01 视觉验收重点：顶部导航、首页视觉层级、资产卡片清晰度、资产详情两列结构、认购栏可读性、风险提示、主次按钮、V/M 品牌一致但不过度雷同。
6. 不提前宣称 DEV-02～06 已完成、不声称真实钱包/付款/签署/登记通过。不因 Build PASS 推断业务完整。
7. 提交文件清单、截图路径、测试报告、缺陷列表、Commit SHA 与 Github Draft Code PR/后续推送状态，完成后**停止，不自动执行 DEV-02**。

## 7. 业务和技术边界

只做**产品设计及真实可运行的 PC Web 前端原型**，其业务状态以 Mock 表达。所有后端/数据库/API/合约/Provider 技术实现留给交接开发工程师；最终依据完整原型生成产品 PRD。不为本批开发生产级认证/投资资金状态服务，不进行真实资金、Signer、链上交易。历史 DEC/Frozen/SCOPE、PR #16 Draft/Open/Unmerged 不修改。
