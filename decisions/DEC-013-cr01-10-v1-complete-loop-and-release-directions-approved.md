## 一、十项正式决定（全部 A）

### CR-01｜企业 SaaS 在线注册、KYB、订阅及自动开通

- **已批准产品选择 A**：V1.0 包含官网自助申请、套餐选择、完成KYB后商业付费/订阅、授权Tenant自动或半自动开通，允许审核及线下合同例外。
- **原有对应模块或功能**：M01-F008 / M01-F001～007 / M03 / M19。
- **实施前必须核实**：自动收费与企业KYB前后次序、收款服务商、退款、账单/发票、合同/隐私、暂停/续费/失败恢复均应有受控状态。SaaS 订阅费不能和认购投资款同一账本。
- **决策理由**：优先完成自助商业闭环，但 KYB/商业合法条件不满足时不能把“付费成功”当成真正发行授权；没有实际收费通道与合法契约时不得宣称生产可用。

### CR-02｜Issuer 标准独立投资者门户与高级 White-label 划界

- **已批准产品选择 A**：V1.0 每个Tenant具有可访问的标准独立URL、机构名称Logo、条款及Offering访问控制；V2.0 才支持自定义域名/高级品牌主题/多Issuer白标运营商。
- **原有对应模块或功能**：M08-F001/002/003 + M02 / M15-F004。
- **实施前必须核实**：标准URL、站点状态、公开/定向Offering、投资者账户绑定Tenant、受限访问、邀请和隐私链接要可验收；明确高级域名与M15原ID的关系，避免把M15完整商业模块挪入首期。
- **决策理由**：首期有发行机构自己的投资者前台是核心销售闭环；标准URL与高级White-label不混同。

### CR-03｜受控金融工具模板和标准发行向导

- **已批准产品选择 A**：V1.0 包含A债权及B SPV股份两类最小有审查版本的表单模板与向导，必须在适用法域依法审核后才能发布；高级模板市场 V2.0/后续。
- **原有对应模块或功能**：M04-F008 / M04-F003～007 / M05 / M06。
- **实施前必须核实**：模板必须指向 InstrumentVersion、真实法律权利、适用证据/必填项/风险提示和审批对象；‘收益型/利息型’只是用户表达，不能代替债权/股权/合同权益法律分类。
- **决策理由**：模板提升标准化发行效率，但不可以自动生成法律效力、公司/SPV合法存续或默认收益承诺。

### CR-04｜专业服务由谁承担及平台协作深度

- **已批准产品选择 A**：V1.0 以Issuer自选律师/评估/SPV服务商、上传其成果和受控审核引用为默认；完整服务商在线协作、竞价与Marketplace在 V2.0/V3.0。
- **原有对应模块或功能**：M06-F001～008 / M04 / M22。
- **实施前必须核实**：资产权属、法律文书、评估、公司实体与SPV设立、有效签署、责任主体及法域证明分别列清单；复核/补件、有效期和版本归档首期必须可用。
- **决策理由**：降低首发外部服务集成依赖；不存在‘选了SPV模板就自动合法成立公司’的产品承诺。

### CR-05｜合约模板 Factory 与部署自动化

- **已批准产品选择 A**：V1.0 支持经批准合约版本和单一受权链的模板参数→审查→DeploymentIntent→由合法受权签名主体自动/半自动部署→链上Finality与恢复；认购合约与收益合约是否独立由产品模式选择。
- **原有对应模块或功能**：M07-F001～010 / M22 / M05。
- **实施前必须核实**：需要确认标准、Token权益映射、审计过的合约模板、签名权限、可升级/冻结权限、沙盒/生产隔离、部署Unknown恢复；并非每笔订单部署新合约，Mint须在合法配售和适用登记后单独触发。
- **决策理由**：自动化提高发行效率，但不能因自动化让 SaaS 平台默认控制全部生产私钥或法定Token权益。

### CR-06｜投资者钱包：EOA 与嵌入式账户

- **已批准产品选择 A**：V1.0 提供连接外部钱包及一个安全审查通过的嵌入式钱包方案（MPC可选但不是唯一技术实现），包括创建、恢复、风险控制与签名、手续费提示。
- **原有对应模块或功能**：M08/M09/M07/M22及候选CAND-02。
- **实施前必须核实**：嵌入式钱包供应商、密钥模型、托管/非托管责任、恢复失窃、EOA/智能账户兼容、Gas、KYC法律主体与付款/Token接收地址映射须单独验证。
- **决策理由**：无钱包经验的投资者能完成首购，但不能用钱包等同法律身份、法定股东名册和KYC。

### CR-07｜募集资金合法结算与发行方提取

- **已批准产品选择 A**：V1.0 提供真实募集款收款/冻结/受限/合法可划拨/划拨中/已实付/Unknown的报表和经授权的结算提取申请，由实际有权资金方执行出款。
- **原有对应模块或功能**：M11/M21/M17/M20/M22及候选CAND-03/04。
- **实施前必须核实**：谁实际收款/托管、募集是否成功或达到释放条件、退款准备金、净额/费用、企业合法收款账户和提现白名单、审批、外部出款/到账、重复划款风险要明确。
- **决策理由**：这是业务闭环缺口，但 SaaS 不默认开设投资者法币钱包或直接持有/挪用募资款。

### CR-08｜收益实际注资和 Push/Claim 分配

- **已批准产品选择 A**：V1.0 必须具备合法收益事件/RecordDate快照/审批/资金注入/资金足额确认，并首期选择一种可依法履约的执行方式；推荐 Claim-first，Push预留架构接口。
- **原有对应模块或功能**：M13-F004/005/006 + M07/M22/M08/M21及候选CAND-05/06。
- **实施前必须核实**：A债权到期票息/本金是法定义务；B SPV分红仅合法决议后产生。Claim须落实Gas、领取期限、暂停冻结、Unclaimed/Partial、名单争议与真实法律清偿时点；‘Funded’不等于Paid。
- **决策理由**：你的11步明确把收益分配当成核心，首期应有真实可运行的一种合规分配闭环；不得对任意SPV强加固定年化/保证回购。

### CR-09｜到期、回购、赎回与 Token Burn

- **已批准产品选择 A**：V1.0 支持A债权本金到期清偿、部分付款/逾期及其必要的登记/Token冻结销毁；B SPV有真实批准的回购/注销/清算事项才按合法条件触发，复杂重组后置。
- **原有对应模块或功能**：M13/M12/M07-F009/M17/M22。
- **实施前必须核实**：M07-F009历史P1，但针对A参考样本需要最低链动作；法律清偿、真实资金实付、名册变化、Token Burn/Freeze四套事实分离。
- **决策理由**：A债权首期若不支持到期还本会破坏完整业务模型；B股份不应默认有固定到期和本息。

### CR-10｜历史187功能向版本的转换及新功能缺口

- **已批准产品选择 A**：保留187原ID及已批原则，审核原187到V1.0/V2.0/V3.0的唯一版本映射，必要的门户/钱包/结算/收益和合约Factory能力先核原ID可否扩深，真正新增再正式编号和调整总数。
- **原有对应模块或功能**：DEC-012 / 187原ID / CR与CAND新增候选。
- **实施前必须核实**：禁止改写Frozen/Approved历史；只有产品负责人批准了的新版本清单才是实际V1.0开发范围，Step02图v0.3和Step03双向矩阵作为审批证据；V1不再包含可选P1。
- **决策理由**：转化的核心是消除版本模糊与遗漏，不是把历史优先级简单换名字。


## 二、批准边界与旧决策关系

1. **DEC-012 已批准 V1.0 = 第一版完整开发交付清单**。DEC-013 确立本轮十项业务能力属于首版设计目标或后续版本方向，**不能据此将旧 187 项的每一行自动视为正式获准进入某版本**；版本清单必须再逐 ID 审核。P0/P1/P2/V2/待定仅作为历史审计源数据保留。
2. **与旧 Batch 01～06 的阶段建议存在差异时，今后以 DEC-013 对对应能力的目标方向为准**（例如原 M01-F008 P2 后置、M04-F008 P1 模板非默认、M07-F009 P1 条件性），同时**不抹掉这些原文，也不否定其安全、法定权利及资金事实独立原则**。需要明确功能的 V1 最小实现、后续增强和必要新功能时，通过 Step 03 双向追踪及新的正式功能变更审批。
3. **CR-01 商业费与认购资金独立**：企业在线商业 SaaS 订阅/收款与投资者认购资金对账/退款是不同权限、账本和合规事实，不能混用。
4. **CR-02 标准独立门户 ≠ 高级 White-label**：标准 Issuer Portal 的独立 URL、机构基本品牌、Offering 访问和租户隔离列为 V1.0 目标；自定义域名、运营商多发行机构高级版本可规划 V2.0，**不因此默认将 M15 的全部商业白标功能并入首期**。
5. **CR-03/04 标准模板不得代替合法专业意见**：参考 A 固定票息债权与 B SPV 股份类适用工具可提供经受控审核的模板及向导；具体 SPV 是否设立、律师/评估责任和文件法律效力需由真正主体核实，复杂服务商市场可后置。
6. **CR-05 合约自动化必须受权**：批准的是标准合约模板、参数校验、审批、ExecutionIntent、受权自动/半自动部署及真实链结果核验的目标；不默认每个 Asset 三份合约，不授权 SaaS 保管全量生产密钥，不预设合约具体协议/链部署方案，也不使 Mint/法定登记合并为一事实。
7. **CR-06 嵌入式钱包选型未决**：批准“双入口体验目标：外部钱包+一种合规安全的嵌入式钱包方案”，**没有批准 MPC 作为唯一技术**；控制权证明、密钥恢复、Gas、钱包与法律持有人身份映射仍待技术/法务验证。
8. **CR-07 募集资金可结算、划拨、已出款必须分开**：Issuer 申请和审批，真实资金的合法控制/托管/付款方执行外部结算；SaaS 不凭报表数值取得真实募资款操作权。
9. **CR-08 收益核算、合法决议、权益快照、注资、实际出款及 Claim/Push 独立**：批准首版具有**至少一种合法可执行的收益/本息分配闭环**，**Claim-first 是推荐实施路线，不是已冻结的技术/法定履行方案**；B SPV 不默认固定票息或保本，未领取余额、合法送达与实付状态独立。
10. **CR-09 合法到期与回购不能强加同一退出机制**：A 债权需票息/本金/部分清偿/逾期的最低合法实现，B 类回购/注销仅当法律及公司授权有效；法定权利、付款、登记、Token Burn/冻结各自留证。
11. **CR-10 V1.0 功能清单未冻结**：原 187 ID 守恒，新增候选 CAND-01～08 只能在 Step 03 判断合并、扩深或正式新增，未获批准前不得编造新 Mxx-Fxxx 功能编号或将总数 187 改写。
12. **未决生产门**：国家法域/发行资格、实际资金保管/支付/结算权限、专业责任、钱包服务商/密钥与恢复、智能合约标准/审计/部署权限、法定名册主体、收益资金实际履约以及外部 API/安全与必要授权均保持 **G-01～G-07 / TBD**。本决策**不批准真实生产操作、UI/工程研发或合并 PR #6**。
