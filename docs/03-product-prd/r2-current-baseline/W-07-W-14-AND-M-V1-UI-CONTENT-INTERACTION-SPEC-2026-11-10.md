## 0. 本批范围与统一规则

本批覆盖：
- W-07 法律与政策；
- W-08 历史企业注册入口兼容；
- W-09 历史邮箱验证入口兼容；
- W-10 统一企业邮箱验证码登录；
- W-11 企业创建、KYB 与 Free 激活状态引导；
- W-12 历史企业选择入口兼容；
- W-13 Standard 订阅与升级说明；
- W-14 本地存储/Cookie 说明；
- M 统一投资端筹备介绍页（增量页面，不增加 W-01～W-14 编号）。

### 0.1 本批必须遵循的产品事实

1. 一个邮箱账号对应一个企业；V1 不提供多企业选择、成员角色、团队邀请或企业内部审批分权。
2. 企业登录采用邮箱 + 一次性验证码；首次验证成功自动创建账号并登录，不再有独立注册和邮件链接验证两套流程。
3. 用户登录后创建企业并进入五步 KYB；Free 和 Standard 均须企业 KYB 通过。KYB 通过后激活 Free。
4. Free 可创建、编辑和保存正式 Asset、Instrument（权益结构）及 Offering（发行方案）业务资料；只可内部只读预览投资者门户；不部署/Mint、不公开上架、不认购募资、不产生真实投资者持仓或收益运营。
5. 企业钱包能力与 Free/Standard 套餐相同；钱包配置/开通状态与 KYB、Free 激活状态分开表达，不得把钱包异步状态误判为企业未通过 KYB。
6. Standard 为 SaaS 商业订阅，支持月付/年付及 USDT/法币；价格待公布。Standard 订阅不自动批准具体 Offering、资金、Token、投资者认购或 M 平台展示。
7. SaaS 订阅付款与投资者认购付款是两条独立资金流程。投资者 V1 认购付款范围为 OP Mainnet USDT；不得将其写成 Standard 订阅固定支付网络。
8. Standard 自动续费默认关闭；仅当实际付款渠道支持且用户主动授权时才可开启。到期提醒按 7/3/1/到期当天；到期进入 7 天宽限期；宽限期后降级，历史业务只读，必要存续义务由受控机制保障。
9. M 统一投资端已纳入 V1 产品范围，但当前公开状态仍为「筹备中」；按 Offering 申请并由平台独立审核，不保证展示或募集结果。
10. 当前正式账号、邮箱、KYB、订阅付款、咨询接收和 M 真实投资者服务并未因页面规划而视为已开放。页面必须区分「产品范围已批准」与「当前服务未开放」。

### 0.2 全站入口统一

| 用户意图 | 唯一入口 | 规则 |
|---|---|---|
| 免费开始 | `/login` | 统一邮箱验证码入口；首次验证自动创建账号 |
| 企业登录 | `/login` | 同一入口，不出现登录/注册二选一 |
| 旧注册链接 | `/register` | 直接进入 `/login`，不显示独立注册说明页；安全保留可识别的 Standard 意图 |
| 旧邮箱验证链接 | `/verify-email` | 直接进入 `/login`，不显示独立说明页或邮件链接验证状态 |
| 企业创建/KYB | 登录后进入 Issuer 企业工作台 | W-11 只说明状态与引导，不复制五步 KYB 表单 |
| 旧企业选择链接 | `/organizations` | 不显示企业列表；按单企业状态进入唯一下一步 |
| Standard 升级说明 | `/standard-upgrade` | 登录后进入原企业工作台订阅管理；不创建新企业 |
| M 统一投资端 | `/investor-platform` | 独立于企业登录；当前筹备中 |

## W-07｜法律与政策（`/policies` 与 `/policies/:slug`）

### 1. 页面目标

让访客清楚了解 SaaS 法律文件有哪些、各自负责什么、当前是否正式发布。当前文件正文、生效日期与适用主体尚未完成发布时，不能以摘要或示意内容冒充正式条款。

### 2. 页面结构与推荐文案

**页面标题：**「法律与政策」

**说明：**「查看 WDEX SaaS 企业服务相关文件的发布状态。正式文件正文、适用主体及生效日期以经审核公布的版本为准。」

保留四张政策卡：

| 文件 | 页面说明 | 当前状态 |
|---|---|---|
| SaaS 服务条款 | 企业账户、订阅、服务范围及双方责任 | 正式文件尚未发布 |
| 隐私政策 | 个人信息处理方式、使用目的及相关权利 | 正式文件尚未发布 |
| Cookie / 本地存储说明 | 网站本地存储与 Cookie 的使用情况 | 正式文件尚未发布；当前说明可查看 |
| 免责声明 | 技术服务边界、真实发行与投资风险提示 | 正式文件尚未发布 |

每张卡显示状态、文件职责、最后更新时间（仅有真实日期时显示）和「查看发布状态」。尚未发布的详情页显示：
- 标题与文件职责；
- 「正式文件尚未发布」状态；
- 简短说明：「当前无法提供经审定的正文、生效日期与适用主体。请在正式文件发布后阅读，再决定是否使用相应服务。」
- 返回政策列表。

### 3. M 投资者法律文件边界

- SaaS 企业服务文件不替代投资者服务条款、Offering 法律披露、投资者隐私告知或其他投资者适用文件。
- M 统一投资端和 V Issuer 独立门户的投资者文件，应按各自适用服务和 Offering 独立审核、发布。
- 不把 M 投资者条款混入 SaaS 四份政策卡，也不暗示 SaaS 企业注册即同意未来 M 投资者条款。

### 4. 交互与异常

- 点击卡片进入对应详情状态页；详情页可返回政策列表。
- 未发布文件不得出现「下载正式协议」「同意并继续」「接受条款」等会产生法律效果的 CTA。
- 若未来发布，卡片应展示正式版本号、生效日期、适用主体和真实正文入口；旧版本保留可追溯性。
- 未发布状态下，W-10 不能要求用户勾选一个不存在的正式服务条款来伪造注册完成；真实服务开放前，账号/注册服务本身应显示不可用。
- 不在官网自行撰写未经法律审核的条款正文。

## W-08｜历史企业注册入口兼容（`/register`）

> **审核结果：A / Approved（DEC-062）；历史 URL 的无说明直达方式由 DEC-063 补充批准。W-08 不再是独立用户可见页面。**

### 1. 页面职责

`/register` 仅作为历史 URL 兼容入口，直接进入统一邮箱登录页面 `/login`。不渲染独立注册表单、注册说明页或迁移提示。

### 2. 用户体验与系统规则

- 官网「免费开始」「注册」「登录」等企业账户入口统一进入 `/login`。
- 用户只看到同一个邮箱验证码流程，不选择「注册」或「登录」。
- 首次验证成功由系统自动创建账号并登录；已有账号直接登录。
- 如历史链接携带合法的 `intent=standard`，跳转时安全保留该意图，使用户登录后继续原企业的 Standard 订阅流程。
- 不携带或回显未经验证的邮箱、令牌或其他敏感参数。

### 3. 必须移除

- 独立注册表单、注册说明页、独立 Free 注册按钮和「已有账户？登录」分叉；
- Free Sandbox 永久试用、完整模拟认购/Token/收益等套餐描述；
- Free 无需 KYB、商业 KYB 仅 Standard 才需要的旧表述；
- 邮件链接验证作为 OTP 登录后的第二次强制验证；
- 前端演示角色切换或虚拟企业授权。

### 4. 异常处理

- 无效或过期的历史 URL 参数不应导致白屏、错误页或跳转循环；忽略无效参数并进入 `/login`。
- 浏览器返回行为保持正常。
- 邮箱服务未开放时，由统一登录页如实显示服务不可用；不在历史入口伪造注册成功。

## W-09｜历史邮箱验证链接兼容（`/verify-email`）

> **审核结果：按 DEC-063 Approved。W-09 不再是独立用户可见页面。**

### 1. 页面职责

`/verify-email` 仅作为历史 URL 兼容入口，直接进入统一邮箱登录页面 `/login`。不显示「邮箱验证已整合」「旧验证方式已取消」等解释，不渲染独立邮箱验证页面。

### 2. 用户体验与系统规则

- 用户点击旧邮件中的验证链接后，直接看到正常的邮箱登录界面。
- 不显示历史邮件链接的「验证成功」「链接过期」「验证失败」等页面状态。
- 不再通过邮件链接完成账户验证，也不将旧链接本身视为登录凭证。
- 如链接携带合法的 `intent=standard`，安全保留该意图；不读取或回显未经验证的邮箱和敏感参数。
- 验证码发送、输入、错误、过期、已使用、重发受限等状态，全部在 W-10 统一登录流程内处理。

### 3. 异常处理

- 无效或过期的旧链接参数：忽略后进入 `/login`，不展示旧式错误页面。
- 邮箱服务未开放：由统一登录页如实显示当前服务不可用；不得声称已发送验证码。

## W-10｜统一企业邮箱验证码登录（`/login`）

> **审核结果：A / Approved（DEC-064，2026-11-10）。** 用户批准极简居中单栏登录卡片、两步邮箱验证码流程；无密码、无独立注册、无多企业选择、无营销介绍。

### 1. 页面目标

一个入口完成已有账号登录和新用户首次进入。用户不需要判断自己是注册还是登录，也不需要在验证码后再经历独立邮件链接验证。

### 2. 页面内容

**主标题：**「邮箱登录」

**说明：**「使用邮箱验证码安全登录。」

首次使用时自动创建账号、已有账号直接登录，均为系统内部处理，不在页面上区分或要求用户选择。

**安全提示：**「登录验证码仅用于企业账户身份验证。WDEX 不会通过邮件要求您提供钱包私钥、助记词或向个人地址转账。」

登录页以邮箱登录为唯一重点，采用简洁、聚焦的单栏布局；不需要额外解释注册/登录差异，也不放置干扰登录的营销内容。不得显示虚构的真实企业、募集额、投资者数量或账户权限。

### 3. 两步交互

**步骤 1：邮箱**
- 字段：邮箱，必填。
- 主按钮：「获取验证码」。
- 校验：空值、格式错误；发送中禁用重复点击。
- 成功：显示已发送提示及脱敏邮箱，进入步骤 2。
- 失败：邮箱格式错误、发送服务不可用、网络异常、请求结果未知、请求频率限制。
- 错误提示应紧邻输入项或按钮，保留已输入邮箱，允许修改后重试。
- 不通过不同提示泄露某邮箱是否已经注册。

**步骤 2：验证码**
- 字段：一次性验证码，必填；长度与格式按最终安全方案确定，页面不在本阶段虚构有效期或重发频控数字。
- 主按钮：「登录」。
- 次操作：「重新发送验证码」「修改邮箱」。
- 状态：验证中、验证码错误、过期、已使用、重发受限、网络异常、结果未知。
- 验证成功：系统识别账户状态；首次使用自动创建账号并建立登录会话，已有账号直接登录。
- 用户始终只经历同一登录流程，不出现注册分支、注册成功页或第二次验证。

**登录后的下一步：**
- 已有唯一企业且 KYB 已通过：进入该企业工作台。
- 尚无企业：进入创建企业引导并开始五步 KYB。
- KYB 草稿/待补件/审核中/未通过：进入对应申请状态与唯一下一步。
- KYB 通过：Free 权益激活；钱包状态单独展示。
- Standard 意图：登录后进入原企业的订阅管理说明/页面，不新建企业、不自动付款。
- 不显示多企业选择器或团队角色选择器。

### 4. 当前服务开放状态

- 邮箱发送、验证码核验和真实账户服务未开放时，公开页面显示「企业账户登录暂未开放」及原因；不显示可提交后假装成功的邮箱表单。
- `?demo=1` 等内部预览状态不得出现在普通访客页面，也不得用本地演示状态生成真实账户或企业权限。
- 账户服务真正开放后，才启用上述 OTP 交互；启用状态由真实服务开放情况决定。

### 5. 视觉与可用性

- 登录表单单列、聚焦；验证码状态清晰，不将所有错误塞入一个通用提示。
- 主按钮在桌面/移动端位置一致；移动端输入框和按钮满宽。
- 错误出现时不重置邮箱；验证码失败时保留邮箱并允许重试/改邮箱。
- 键盘可完成输入、提交和步骤切换；焦点顺序与视觉顺序一致。

## W-11｜企业创建、KYB 与 Free 激活状态引导（`/free-onboarding`）

> **审核结果：A / Approved（DEC-065，2026-11-10）。本页仅为登录后的企业创建/KYB 引导与状态分流，不承载五步 KYB 表单；五步表单以 U01 KYB v0.3 已批准文档为准。**

### 1. 页面职责

W-11 是企业创建/KYB/Free 激活的状态引导页，不是新的独立注册页面，也不是 Issuer 五步 KYB 表单的官网复制品。真实 KYB 资料录入、提交、补件和审核发生在 Issuer 企业工作台。

### 2. 页面状态与唯一下一步

| 真实企业状态 | 页面标题/说明 | 唯一主 CTA |
|---|---|---|
| 未登录 | 请先登录企业账户 | 「企业登录」→ W-10 |
| 已登录、尚无企业 | 创建企业并开始认证 | 「创建企业」→ Issuer 企业创建/KYB |
| KYB 草稿 | 企业认证尚未完成 | 「继续填写」→ 原 KYB 草稿 |
| KYB 已提交/审核中 | 企业认证正在审核 | 「查看申请状态」→ 原 KYB 申请 |
| KYB 待补件 | 需要补充企业资料 | 「补充资料」→ 原申请补件步骤 |
| KYB 未通过 | 企业认证未通过 | 「查看审核结果」→ 显示原因及允许的后续方式 |
| KYB 已通过、Free 已激活 | 企业工作台已可使用 | 「进入企业工作台」 |
| KYB 已通过、钱包处理中 | Free 已激活；企业钱包仍在处理中 | 「进入企业工作台」；钱包状态另有「查看钱包状态」入口 |
| 钱包开通失败 | Free 与 KYB 状态保持，不得误判为 KYB 失败 | 「查看钱包状态/联系支持」；不重复创建企业 |

### 2.1 待补件与未通过的统一资料修改体验（DEC-067）

- 两种状态保留各自状态名称和审核意见，但不拆分为两套流程。
- 点击「修改资料并重新提交」后，载入此前提交的完整五步资料和已上传文件。
- 用户可以编辑任意字段、补充信息、替换或补充文件，不限制只能修改审核意见点名的字段或分组。
- 支持保存草稿、继续编辑、预览和统一提交；无需重新创建企业或从头录入。
- 重新提交成功生成新资料版本，保留此前提交版本和审核记录，状态回到审核中。
- 实际资料编辑由 Issuer 企业工作台承载；W-11 负责显示状态、审核意见和唯一入口。

### 3. 内容边界

- 明确「KYB 通过后激活 Free」；不把邮箱验证码成功等同于 KYB 完成或 Free 激活。
- 五步 KYB 的字段、文件、草稿、提交和补件状态由 Issuer 页面承载；官网只显示状态、说明和跳转。
- Free 可管理正式 Asset、Instrument、Offering 准备资料并内部只读预览；不再宣传 Sandbox 完整模拟投资流程。
- 企业钱包在 KYB 通过后自动分配 MPC 钱包的处理，与 Free 权益激活分开显示；Free/Standard 钱包能力相同。
- 一个账号一个企业，不展示创建第二家企业或选择多家企业的 CTA。

### 4. 异常处理

### 4. 付款与自动续费

- SaaS 订阅支持 USDT/法币；不在官网固定宣称 TRON、BNB Smart Chain、Ethereum 或其他未批准网络。
- SaaS 订阅付款与投资者认购付款明确分离；OP Mainnet USDT 是投资者 V1 认购付款范围，不等于 SaaS 订阅网络。
- 自动续费默认关闭；只有真实付款渠道支持且用户主动授权时，才显示并允许开启自动续费。

### 5. 订阅状态与到期说明

| 状态 | 官网/工作台应解释的内容 |
|---|---|
| 价格/付款方式未开放 | 仅展示升级说明，不生成账单、地址或二维码 |
| 待付款 | 显示原订阅订单和付款期限；避免重复创建订单 |
| 付款核验中/结果未知 | 明确尚未确认，不提前激活、不建议重复付款 |
| 付款已确认、权益开通中 | 显示处理状态；不误报 Standard 已生效 |
| Standard 生效 | 展示订阅周期、到期日和当前权益 |
| 到期前提醒 | 到期前 7 天、3 天、1 天及到期当天提醒 |
| 到期进入宽限期 | 7 天宽限期；暂停新增真实发行，保留必要存续操作 |
| 宽限期结束降级 | 历史业务只读；真实钱包、发行历史和投资者权益不因 SaaS 降级删除；必要存续履约通过受控机制保障 |
| 自动续费失败 | 提示扣款失败及恢复/手动续费路径；不得假定已续费 |

新开通 Free 与 Standard 到期降级后的历史只读状态不同；页面不得将二者统称为「Free 可编辑」。

### 6. 交互与视觉

- 不展示原方案中「多企业选择」「商业 KYB」「TRON/BNB/Ethereum 首期网络」等与最新规则冲突的步骤。

- 价格未批准时，CTA 不得写「立即付款」。
