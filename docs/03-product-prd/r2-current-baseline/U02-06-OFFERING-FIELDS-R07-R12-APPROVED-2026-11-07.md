## 1. R07～R12 已批准（仅字段范围与交互原则）

| 编号 | 用户批准的规则 | 当前交互责任及不得越界事项 |
|---|---|---|
| **R07｜发行名称与简介** | 系统默认建议「**资产名称＋第 N 期**」，允许用户修改；**投资者展示简介**单独填写 | 建议名称不等于必须采纳；「第 N 期」为用户可理解的期次，需关联正确 Asset，不能无依据给已有 Offering 重新编号；简介不同于资产事实及权益条款，不重复让用户填写底层权属事实。具体字数与 Ready 必填条件待 UI-Ready 审核 |
| **R08｜数量、价格与最低认购** | 用户填写**本期发行 Token 份数、固定单价 U、单笔最低认购额 U**；**本期计划最高募集金额自动计算**，且校验本期额度不超过可用权益份数 | 自动计算 `计划最高募集额 U = 本期 Token 数量 × 每 Token 单价 U`；不得把 Token 数和募集金额混淆、把预算当实际到账、手填第三个同义募集字段。具体小数精度、最小金额对份数的换算、最小/最大单笔、退款与金额舍入细则仍 Draft |
| **R09｜认购时间** | 填写**开始日期时间、结束日期时间**，UI **明确时区**；不能让结束时间早于开始时间；**未来开始的 Offering 不得提前显示「在售/认购中」** | 发布准入与开始时间是不同事实。结束日等于开始日是否允许、起止具体边界/允许延长时段、时区存储和状态触发事件下一批审核；不得把 USDable 模拟审核直接套为发行已开始 |
| **R10｜基础投资者准入** | Offering 提供选择**个人/机构、允许认购地区、基础 KYC 要求**，**不得默认全球任何地区无限制开放** | 没有批准实际国家地区白名单、KYC 数字等级、规则引擎/制裁筛查实现、投资资格声明与法域合法性自动结论；发布时需要对应独立合规门。不要把竞品「地区不限/L1」当默认 |
| **R11｜锁仓最小选项** | MVP 提供 **不锁仓** 或 **固定锁仓天数** 两种基础选项；**复杂分期解锁暂缓** | 锁仓起算事件（认购/Token 分配/发行结束等）、最短最长天数、不可转让与链上权限如何执行、与权益法律限制冲突时的优先级仍待细化。选择「不锁仓」并不豁免法律转让限制 |
| **R12｜支付与收款展示** | 投资者**支付网络和币种在 V1 页面固定展示「OP Mainnet · USDT」**；**收款钱包来源、费用承担及到账确认规则单独审核**；不能擅自给出 95%/5% 等分账比例 | 当前不批准用户自由选链、自由改币种、手动收款方的生产可用性、资金托管/自收/平台代收责任划分、自动分账、网络费用承担、对账与支付安全；正式外部资金服务与 Token 执行保持 Draft/技术审查门 |

## 2. 面向用户的 Offering 表单最小结构（R01～R12 的组合视图）
```text
资产详情 → 发行管理 → 创建发行方案
固定展示：资产名称、当前权益结构确定版本、每份 Token 对应权利、可用 Token 份数
A. 发行信息
  发行名称（按资产+第N期建议，可编辑）
  本期投资者展示简介
  本期发行 Token 份数
  每 Token 认购价格（U）
  单笔最低认购金额（U）
  计划最高募集金额（系统自动计算，只读）
  认购开始/结束日期时间＋明确时区
B. 投资者认购条件
  投资者类型：个人／机构
  适用地区：按将来确认的受限候选配置，不默认全球不限
  KYC 要求：按将来确认的基础规则
  锁仓：不锁仓／固定天数
  支付网络/币种：OP Mainnet · USDT（只读）
C. 发行准备
  资料检查、待补事项、相关文件/披露与生产准入状态
  预览投资者端、正式发布前最终确认
底部：[保存草稿] [检查准备情况]；发布须独立权限与签署/生产校验
```
- 三个**区块**不是三步向导。仅建议展示结构；确定字段布局、可折叠方式、最终 Ready 必填门槛、输入格式及文件类型均属于后续 UI-Ready 审核。
- 仪表数据必须区分「本期发行 Token 份数」「本期计划最高募集金额 U」「实际已确认认购 Token 数」「实际到账金额 U」「实际已分配 Token」，即使技术实现尚未获准也不可在 UI 概念上混用。
- 本页不能重新设置 Instrument 权益总规模或每 Token 权利映射，也不让用户因为收款依赖未配置就丢失已填写草稿。
- 未批准「最低募集成立门槛」的必填要求，也未批准默认锁仓天数、默认开放地区或默认 KYC 等级。

## 3. 明确保留 Open / Draft（当前未批准）
1. **同一 Instrument 并行开放多个 Offering** 的允许性及并发份额占用；之前建议「一次只能一轮」**并未被用户批准**。
2. 何时确认 `reserved`（有效发行额度预留），如何在暂停、结束、取消、关闭及零认购情形释放；已确认权益不得因关闭被错误释放。认购失败、退款、Token Mint/分配/余额主账仍待专项流程设计。
3. 本期 Token / U 最小精度、份额整数约束与最小认购 U 是否能精确换算整数 Token、极端价格/数量保护、最低募资成功门槛及超额认购/部分成交的策略。
4. 法域适用性、允许国家地区清单、KYC/AML/资格来源、分销渠道合规、基础锁仓真正链上控制起算和解除。
5. **收款账户新确认**：企业在 Offering 中自主选择已绑定的 MPC 钱包或自连接钱包作为**最终结算收款账户**。但投资者实际付款地址是否为经审查认购合约、合约资金法律控制主体、费用、到账/对账、退款及失败恢复仍须独立审核；**企业钱包不是投资者直接付款目标的自动默认**。
6. 发行准备文件/认购协议的固定版本引用、投资者页面映射与必需披露、发布/等待开始/在售/暂停/结束/关闭的精确状态事件与操作权限，以及内部预览/正式发布的技术安全门。
7. 真实 Provider/Signer、Token 合约/部署/Mint/支付执行、生产链与法律权利的最终批准，均不因 R07～R12 审核 A 而获准。

## 6. 2026-11-11 DEC-069 补充｜R10 投资者准入字段的当前执行口径

- 「个人/机构」和「允许认购地区」不再作为 Issuer 可配置字段，不在 V1/MVP Offering 表单显示。

- 普通 Offering 交易条件（时间、额度、最低认购、锁仓）继续保留。
- 该补充优先于本文原 R10 字段示例及「待确认地区/KYC 等级」候选项；不改变其他 R07～R12 已批准规则。详见 [DEC-069](../../../decisions/DEC-069-investor-kyc-centralization-and-issuer-masked-view-v1-approved.md)。
