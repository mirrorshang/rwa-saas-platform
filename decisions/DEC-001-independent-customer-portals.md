# DEC-001｜客户独立资产门户与授权分发

- 日期：2026-10-16
- 状态：**Approved（已由产品决策确认）**
- 文档关联：[第 02 份战略草案](../docs/02-product-strategy/RWA-SaaS-Product-Strategy-Business-Model-v01.md) §9
- 决策范围：商业和产品层面的基本原则；**不代表第 02 份战略文档整体冻结**。

## 已确认决策

1. **Issuer SaaS / White-label 客户独立管理自己的发行资产和投资者门户**，不默认进入 SaaS 厂商统一全球资产池。
2. **投资者的可见资产以门户授权、发行条件及适用资格规则为准**；不同客户的数据、品牌和管理权限必须被合理隔离。
3. **跨发行方、跨门户资产分发必须取得明确授权**，并满足相应资产、渠道、投资者、市场及法律许可条件；不是平台自动开放。
4. **自营聚合 Marketplace/统一公开交易市场不是当前 ToB SaaS 默认产品**；如未来考虑，需要单独评审商业模式及适用监管。

## 不包含的决策

- 是否支持白标运营商管理多个子发行客户、是否允许多层转售；
- 私有/邀请制/合作分发的具体权限和页面结构；
- 投资者账户/KYC 在不同客户门户之间如何依法复用；
- 法定授权合同内容、发行证券的实际营销/分发牌照；
- 是否在未来独立建设聚合分发产品。

## 原因与影响

本项目的商业主线是多资产 ToB SaaS、White-label 与 API，而非强制统一公开的投资交易市场。该原则影响多租户、投资者门户、发行资产可见性、权限、合规、计费、API 及 UI 信息架构。旧 RWA V2 PRD 的全平台市场统一设计不得视为本项目已批准要求。

## 后续工作

在第 02 份战略与第 03/05 份产品需求/合规规格中落实客户与角色层级、资产授权范围、投资者资格和数据隔离，并设计相应 UI 流程。

该决策仅由后续明确的产品变更决议修改，不得因为竞品推断或工程便利而暗中覆盖。
