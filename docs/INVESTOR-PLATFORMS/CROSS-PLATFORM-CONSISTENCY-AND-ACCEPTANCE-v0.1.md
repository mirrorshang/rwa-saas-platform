> 2026-11-24｜产品跨端收口草案，伴随 V/M PRD 提交独立 Draft PR；不覆盖历史 DEC、Frozen、V1.0 固定前端交付事实或产品批准范围。审计范围：W 官网、I Issuer SaaS、V 企业投资者、M 统一投资者、P Platform Admin，外部 KYC/MPC/合约/法定登记/Signer 仅作为接口依赖。当前 V/M/P 独立前台尚未开发。实际生产对账、合约、安全/法务决策仍未验证。

## 1. 单一业务对象与来源

| 对象/事实 | 唯一权威及责任 | V/M 投影 |
|---|---|---|
| Issuer Enterprise / Portal | I 租户和门户（Logo/名称/域名前缀），KYB Provider 引用 | V 企业品牌；V/M 同一企业信息组件，按已授权公开资料读取 |
| Asset / InstrumentVersion / Project / OfferingSnapshot | I 资产发行域，固定权利、法律条款、发行参数和版本 | V/M 相同 Offering 的法律字段相同；展示 Asset/权益/发行三层 |
| M Listing / Application | I-67/I-68 发起；P-15 审核；P-16 维护；M23 授权渠道读模型 | V 不受 M 上架控制；M 必须 Listing 最终展示成功 |
| Investor Account | V 账户按 Issuer 专属 scope，M 账户按 M scope 独立 | 同邮箱/同钱包不自动合并历史账户；可依法授权引用同一 KYC Provider 事实 |
| KYC/KYB Investor | 第三方真实审核；M09 接收权威结果和有效期 | 认购前 Passed，浏览/注册不强制，Issuer 只看脱敏状态 |
| Wallet | 投资者账户对应 Provider/M08；自动 MPC 与已验证自有钱包 | 注册后请求 MPC；默认切换仅后续预选，交易固定地址快照 |
| Order/Quote/Reservation | M10 认购唯一订单、个人金额额度；M12 Offering 内 Token 容量权威 | V/M 共享同一 Offering 容量、订单号、下单报价条款快照；channel 记录来源 |
| Payment/Refund | M11 唯一资金/链监听/退款事实；外部收款/Signer 真实执行 | OP Mainnet USDT 合约付款；自动退款条件受核准合约约束；人工异常走有权资金流程 |
| Allocation / Holder | M12 配售、法定权益名册、权利生效 | Token 不自动证明法定所有权 |
| Token / Lock | M07 合约/Token 链真实事实，依法限制另有权威 | 交付、可核余额、业务锁仓/链限制/法律限制分开 |
| Distributions / Principal | M13 收益与本金事件、Record Date、实付结果 | 股息、利息、收益参与权、本金分列；不能从预期年化推导已应付 |
| Ticket / Message | M17 工单及任务历史；M18 通知；原域保留真实业务结果 | V/M 提交、查询、回复；P-07/I 有权范围处理；关闭工单不改变金融事实 |

**主账约束**：同一个 Offering 经 V/M 同时认购，不复制可发行份额；请求幂等、版本快照、并发限额、资金最终性由权威服务统一控制。一个投资者在 V 与 M 不同账户下的身份/额度是否可依法聚合是独立法定与身份授权问题，V1 不因同邮箱/钱包简单合并；当前 Issuer 已批准个人累计额度口径按 Tenant+Offering+授权 InvestorRef，须遵循原权威服务判定，不由 UI 自行合并/拆分。

## 2. 投资成功主链及守卫

访客浏览 V/M 已获准公开 Offering → 邮箱 OTP 首登自动建当前范围账户和异步 MPC → 认购前 KYC 通过（必要时第三方/合法引用）→ 报价/最低额/最高份数/当前个人限额/容量检查 → 阅读并完成必要法律签署 → M10 唯一订单与 M12 有效预留双边确认 → 投资者通过已验证钱包向 Offering 收款合约支付 OP Mainnet USDT → M11 FinalMatched → M12 合法配售与法定持有人登记 → M07 Token 交付最终确认 → V/M 详情展示完整完成与持仓 → M13 收益/本金事件依合同及权威名册进行合法支付。

M 额外 Gate：Listing 已正式显示且未暂停/下架；V 独立 Gate：企业门户已获准公开 + Offering 有效。都不以“Provider Accepted”替代链上最终结果。此链表示业务条件关系，实际法定登记/Mint 先后由生效合同及法域决定；前台同时记录每个事实，不强制用一个伪造顺序覆盖真实状态。

## 3. 付款失败、回滚、自动退款和人工异常的边界

| 真实情况 | 订单与付款展示 | V/M 操作 | I/P/有权服务职责 |
|---|---|---|---|
| 未发起付款，订单有效 | 待付款 | 可在有效期内继续付款；无主动取消 | 期限到达且无在途证据后 M10/M12 安全过期释放 |
| 钱包拒签、余额/Gas不足 | 未发起或付款未完成 | 修正钱包/余额，沿有效订单重试 | 保留原订单，不伪造已收款 |
| 单交易原子回滚 | 付款失败，USDT 交易未转移（Gas 可能已消耗） | 可查看失败原因/原 TX | 不生成虚假退款 |
| 已广播/链观察/未知最终性 | 付款核对中 | 只查原 TX 与工单，不重复盲付款 | M11 链核验/重组恢复，保护原订单/额度 |
| 已最终入账，尚未 FinalMatched | 真实资金待核对 | 查看状态/工单 | M11 对账差异，不凭链观察认购成功 |
| 合规合约支持自动退款，条件满足 | 自动退款已发起/核对中/完成（真实 Final 后） | 查看退款进度，无手动申请 | 已批准受益人/金额/目标/Intent 复用，链上执行与结果核验 |
| 已收款但后续履约失败、自动退款不适用 | 履约异常/人工核对 | 提交客服工单 | I 资金/配售/Token 领域有权处理；P 协作但不越权出款 |
| 少付/多付/错链/迟到账/重复付款 | 异常处理中 | 查看交易/回复工单 | M11 保留事件、受权调查/退款，Unknown 不双重出款 |
| 合同到期/应付本金 | 收益与本金，非认购退款 | 查看实付/Claim（若批准） | M13 而非 M11 管理 |
| 已登记合法权益 | 持仓/退出相关状态 | 无普通取消/退款按钮 | 必要退出/清退按 M13/M12/M07 依法处理 |

**未决生产门**：自动退款是否发生于合约原子步骤、合约保管后撤销、或经授权合约出款，必须在合约设计和法定受益人/权限审查中确认；不可把“技术上失败”当作“合约已经退款”。该待确认事项不阻断 PC UI 设计，但**阻断真实资金生产启用**。

## 4. 工单协作与管理后台对齐

工单最小字段：ticket_id、source V/M、scope、investor_ref、optional offering/order/payment/tx/refund/distribution references、类型、问题描述、附件安全引用、owner_org、owner_user_or_queue、状态、公开回复、内部处理记录、业务权威状态摘要、更新时间；一单重复上报同事件时可合并关联，禁止隐式删除问题历史。不得上传或记录私钥、助记词、验证码、KYC 原件。

投资者视图：待处理/处理中/待用户回复/已解决；能提交、查看、补充、阅读公开结果。Issuer I：仅本企业已授权真实订单/资金/收益问题的只读工单及来源业务入口，受权处理退款/对账等仍归原金融域。Platform P-07：只处理平台负责或正式指派工单，含受理、分配、向 Issuer 或外部服务流转、跟踪、补件、答复、升级；P-17 仅 M 渠道投诉/Listing 问题。M17 是工单/异常协作主账，P/I 仅受权视图；P 不因此自动获准资金、登记、Token 或收益执行权。

工单基本事件：Submitted→Triage→Assigned→InProgress→NeedsUserInfo/NeedsIssuerAction/NeedsProviderAction→ResponseSent→Resolved；用户页面仅映射四状态。工单“已解决”必须解释其支持事项的处理结论，且**不将未完成的原资金/Token/名册结果标记完成**。被退租/降级 Issuer 的已发生存续义务仍需要有效的受权协作入口。
