# RWA SaaS｜统一投资渠道业务闭环与 I-67/I-68、P-15～P-17 UI-Ready 产品规格（Draft v0.1）

> **文档状态：Draft｜2026-11-17**
>
> 本文把已批准的 M23 V1 业务范围细化为 Issuer 申请端与平台总后台运营端的桌面 Web 产品规格。M23 的业务范围已由 DEC-057 Approved；本文字段、页面交互和验收规格仍为 Draft，待产品负责人审核后方可进入前端原型实施。
>
> 本文只定义产品业务、页面、字段、交互、状态、Mock 与前端验收。不定义或实现服务端、数据库、API、智能合约、真实资金、Signer、KYC Provider 或生产权限。

## 0. 本批结论

1. **渠道申请对象是单个 Offering。** 不把 Asset 作为独立申请对象，也不建立第二套 Asset、Instrument 或 Offering。
2. Asset、Instrument、Issuer 主体资料和披露文件作为该 Offering 的关联资料；申请记录固定提交时实际展示的必要字段与文件引用快照。Issuer V1.0 不建立独立 Project，也不依赖 Asset/Instrument 通用业务版本历史。
3. 同一 Asset 下有多个 Offering 时，每个 Offering 独立申请、独立审核、独立展示和独立暂停/下架。
4. I-67/I-68 融入 Issuer 现有「资产与发行 → 发行管理」，不新增一级导航或二级导航。
5. P-15/P-16/P-17 归入 P 端「统一投资渠道管理」一级导航，分别承担申请审核（审核通过即触发自动上架）、已上架渠道管理、渠道监控。
6. Issuer Offering 正式发布、M 渠道审核通过/自动上架、M 渠道实际展示、投资者 Eligible/Purchasable 是不同事实；平台审核通过后由系统自动上架，不设置独立人工发布步骤。
7. M/V 共用唯一订单、资金、配售、法定登记、Token 与收益业务事实；渠道来源独立记录。不得因 M 渠道操作删除或覆盖历史交易事实。

## 2. 业务对象与状态边界

### 2.1 对象关系

| 对象 | 在渠道流程中的责任 | 是否为独立申请对象 |
|---|---|---|
| Issuer 企业主体 | 申请主体；提供企业身份、商业准入状态和渠道授权 | 否 |
| Asset | 底层资产资料、权属/估值/运营信息和相关文件来源 | 否 |
| Instrument | 投资者权益结构、法律权利定义及版本来源 | 否 |
| Offering | 单轮发行的经济条款、发行窗口、披露和发行发布状态 | **是，唯一渠道申请对象** |
| Channel Application | 记录某 Offering 对 M 渠道的申请、审核、补件和授权快照 | 是，渠道业务记录 |
| Channel Listing | 记录某 Offering 在 M 的展示范围、发布、暂停、下架与恢复状态 | 是，渠道展示记录 |

同一 Asset 下有 Offering A、Offering B 时，必须产生两份独立 Channel Application。共用的 Asset/Instrument 资料可以引用，但每份申请都必须固定其提交时所引用的版本。

### 2.2 四组状态必须分开显示

| 状态组 | 示例状态 | 权威来源 | 不得等同 |
|---|---|---|---|
| Issuer Offering 生命周期 | 草稿、已确认、已发布、进行中、已暂停、已结束、已关闭 | Issuer Offering 原业务 | 不代表 M 已批准或展示 |
| M 渠道申请审核 | 草稿、已提交、审核中、待补件、补件已提交、审核通过、审核拒绝、已撤回 | M23 / P-15 | 审核通过即触发系统自动创建唯一 Listing 并上架；只有自动上架成功后 M 才展示 |
| M 渠道展示 | 展示中、已暂停、已下架、待复核、自动上架异常（技术状态） | M23 / P-16 | 审核通过后系统自动上架；暂停/下架不改变 Issuer Offering 或历史交易 |
| 投资者可认购状态 | 待开放、开放中、已结束、不可认购、资格待核 | Offering 条款 + M09 + M10/M11 等原领域 | 展示中不等于每位投资者可认购 |

**产品表达规则：**
- M 页面可以展示一个已审核、已发布的 Offering，同时显示「即将开始」「认购已结束」或「暂不可认购」。
- 投资者是否可认购，必须按本人 KYC、适用规则、Offering 时间/额度、必要签署和订单前置条件逐项判断。
- P-16 不提供手工将投资者改为 Eligible、开放认购或绕过 Offering 条件的按钮。
- M 渠道暂停/下架只改变 M 渠道展示和新入口，不删除既有订单、实收、退款义务、配售、法定登记、Token 或收益记录。

## 3. I → P → M 完整业务流程

1. **Issuer 建立业务对象：** 企业在 I 完成 Asset、Instrument 和 Offering，使用现有发行管理流程完成 Offering 确认、发行准备及正式发布。
2. **企业自主申请：** 在单个已正式发布且当前可用的 Offering 详情中，选择「申请上架统一投资平台」。Free 只能内部 Sandbox 预览；真实 M 渠道申请/发布须满足 Standard、商业 KYB 和适用准入要求。
3. **I-67 提交申请：** 企业确认关联资料、选择可公开披露文件、选择申请展示地区、确认渠道授权并提交。系统固定本次申请的披露、条款、授权及文件版本快照。
4. **P-15 审核：** 平台审核人员在渠道申请队列查看申请。可以开始审核、要求补件、确认本次批准的展示地区/受众（不得超出 Issuer 授权范围及 P-10 有效规则）、批准或拒绝。补件通过 M17 任务与 M18 通知协作，不复制 P-03 商业 KYB。
5. **批准即自动上架：** 审核人员点击「审核通过并自动上架」后，系统在同一业务流程中记录审核决定、创建唯一 Channel Listing，并按批准的展示范围将 Offering 自动发布到 M；不进入待发布队列，不需要 P-16 再点一次发布。只有自动上架结果确认成功后，M 才展示该 Offering。
6. **P-16 持续管理：** P-16 仅管理已经自动上架的 Listing，提供查看、暂停、下架、恢复及历史记录；不承担首次发布或再次手工发布。P-17 监控渠道访问、订单归因、投诉与异常。
7. **M 展示：** M-02 投资机会列表和 M-03/M-04 Issuer/Offering 详情仅展示自动上架成功、当前渠道状态为展示中且满足展示条件的 Offering。
8. **投资者认购：** M 账户、KYC、Offering 交易条件、签署、订单、支付、配售、登记和 Token 按 DEC-057 复用 M24、M09、M10、M11、M12、M07、M13 等唯一业务权威。平台上架不代表任何投资者自动 Eligible 或 Purchasable。
9. **Issuer 查看状态：** I-68 显示申请审核状态、自动上架结果、当前渠道展示状态、平台审核意见、补件要求、批准展示范围、暂停/下架原因和渠道汇总统计。
10. **平台持续运营：** P-17 监控渠道访问、订单归因、投诉与异常；需要改变展示状态时跳转 P-16 执行受控暂停、下架或恢复。
11. **跨端状态同步：** I/M/P 显示同一渠道申请和展示事实的不同受权视图；不得各自创建重复申请、Listing、Offering 或交易主账。

V 企业自有门户 I-13 保持独立。I-13 不出现 M 渠道申请按钮；V 门户发布与 M 渠道发布互不自动触发。

## 4. I-67｜统一投资渠道申请

### 4.1 页面入口与定位

- 入口一：Issuer「发行管理 → Offering 详情」中的「统一投资渠道」区块。
- 入口二：Issuer「发行管理 → Offering 列表」的行操作「申请上架 M」。
- 不新增 Issuer 一级或二级导航；申请向导可使用独立标准页面。
- 每次仅针对一个 Offering 发起申请，不提供多选 Offering 批量申请。

### 4.2 提交前置条件

| 条件 | 不满足时的页面反馈 |
|---|---|
| 当前企业为 Standard，且商业 KYB 已通过 | 显示当前套餐/认证状态及跳转企业管理入口；Free 仅显示内部预览，不允许真实提交 |
| Offering 已完成 Issuer 端正式发布且当前未整体暂停/关闭 | 显示当前 Offering 状态及「前往发行管理」入口 |
| Asset 与 Instrument 引用有效，Offering 当前版本完整 | 显示具体缺失对象和「返回原页面处理」入口 |
| 发行披露文件具备可用版本及对外披露权限 | 显示文件名称、版本及缺失原因；跳转原文件管理 |
| 当前企业具有提交该 Offering 渠道申请的权限 | 无权时禁用提交并提示联系企业账号管理员/平台支持 |

以上条件只允许提交申请，不代表平台审核通过或真实生产准入完成。

### 4.3 向导结构

**步骤 1｜确认发行方案**

| 字段 | 展示方式 | 规则 |
|---|---|---|
| Offering 名称/编号/轮次 | 只读 | 来自原 Offering |
| Issuer 企业名称 | 只读 | 来自当前 Tenant |
| Issuer 发行项目背景 | 不作为独立业务对象；如有必要仅展示 Offering 已有的发行说明 |
| Asset 名称/类型/所在地 | 只读 | 引用原 Asset |
| Instrument 名称/类型/版本 | 只读 | 引用原 Instrument |
| Offering 发布状态 | 只读 | 引用原 Offering |
| 发行窗口、价格、发行数量、目标募集额 | 只读摘要 | 不在 I-67 编辑；需修改时返回原 Offering |
| 版本状态 | 只读 | 显示本次申请引用的 Asset/Instrument/Offering 版本 |

**步骤 2｜确认展示资料**

| 字段 | 控件 | 必填/规则 |
|---|---|---|
| M 展示地区申请 | 多选 | 必填；仅显示平台当前允许申请的地区选项，不提供自由输入法域 |
| Issuer 介绍 | 只读预览 | 引用企业资料；需修改时返回企业资料 |
| Asset 展示摘要 | 只读预览 | 引用资产原始资料；不重复创建资产描述 |
| Offering 展示摘要 | 只读预览 | 引用 Offering 原始资料；不重复输入价格、份数、认购窗口或权益条款 |
| 风险与披露文件 | 从现有文件中勾选 | 必须满足当前渠道披露清单；固定文件 ID/版本 |
| 补充说明 | 多行文本 | 选填，仅用于向平台解释申请背景，不替代披露文件 |

必需披露文件清单由平台适用规则决定，不在 Issuer 页面硬编码全球统一文件清单。只允许选择属于当前 Tenant/Offering、版本有效且具备披露权限的文件。

**步骤 3｜渠道授权与确认**

| 字段 | 控件 | 必填/规则 |
|---|---|---|
| 渠道展示授权确认 | 必选复选框 | 必须确认有权代表发行主体提交本次申请 |
| 资料披露授权确认 | 必选复选框 | 确认所选企业、资产、Offering 和文件可按申请范围向 M 展示 |
| 申请人 | 只读 | 当前登录企业账号 |
| 申请时间 | 系统记录 | 提交后生成 |
| 授权确认记录 | 只读历史 | 保留确认文本版本、申请人和时间 |

本页不实施电子签名或真实法律签署；如某法域要求正式授权文件，作为披露材料上传/引用并交由适格主体审核。

### 4.4 页面操作

- 「保存草稿」：保存本次未提交申请；不进入 P 审核队列。
- 「上一步 / 下一步」：保留已填写内容。
- 「预览申请」：展示企业将提交给平台的资料、文件版本和授权范围。
- 「提交申请」：完成前置检查后提交；生成申请编号和不可覆盖的版本快照。
- 「取消」：有未保存修改时先确认；不影响原 Offering。
- 提交结果 Unknown：显示「提交结果待确认」，只允许查询原申请，不允许重复创建申请。

### 4.5 I-67 提交后状态

申请审核状态与 M 渠道 Listing 状态分别显示。审核通过后系统自动创建 Listing 并上架，不再进入「待发布」。

| 状态 | Issuer 可见信息 | 允许操作 |
|---|---|---|
| 草稿 | 未提交申请资料 | 编辑、删除未提交草稿 |
| 已提交 | 申请编号、提交时间、快照版本 | 查看、符合条件时撤回 |
| 审核中 | 当前审核状态、提交版本 | 查看；不允许覆盖申请快照 |
| 待补件 | 平台补件事项、原因、要求材料、截止时间（如有） | 补充资料、重新提交 |
| 补件已提交 | 补件时间、新版本和历史版本 | 查看 |
| 审核通过 | 审核结论、批准展示范围、自动上架状态及 Listing 编号 | 查看；不得自行修改平台展示状态 |
| 审核拒绝 | 拒绝原因和审核记录 | 修正原资料后重新发起新申请；保留旧记录 |
| 已撤回 | 撤回人、时间、原因 | 查看历史 |

### 4.6 补件与撤回

- 补件时只允许补充/替换被要求的资料，原申请版本完整保留。
- 补件提交生成新版本，旧版本仍可查看；P-15 收到后进入重新审核。
- 审核通过或拒绝后，不允许继续编辑原申请快照。
- Issuer 只能在平台尚未完成最终审核前撤回申请。
- 已上架 Offering 如需退出 M，Issuer 在 I-68 发起「申请下架」；实际下架由平台在 P-16 审核/执行，不允许 Issuer 直接改写平台渠道状态。

## 5. I-68｜统一投资渠道状态与记录

### 5.1 页面结构

I-68 作为 Issuer「发行管理」内的渠道视图，不新增导航。

- Offering 列表增加「M 渠道状态」摘要列。
- Offering 详情增加「统一投资渠道」分区。
- 渠道分区提供申请记录、审核历史、展示范围、渠道状态、平台意见和汇总统计。
- 不在 I-68 重复显示或编辑 Offering 原有条款。

### 5.2 列表字段

| 字段 | 说明 |
|---|---|
| Offering 名称/编号 | 原 Offering 主体 |
| 关联 Asset | 资产名称及编号 |
| Issuer Offering 状态 | 原 Offering 生命周期状态 |
| M 申请状态 | 当前申请审核状态 |
| M 渠道展示状态 | 上架处理中/展示中/已暂停/已下架/待复核/上架异常 |
| 批准展示地区 | 平台最终批准的地区 |
| 最近审核/操作时间 | 最近一次渠道事件时间 |
| 平台审核意见 | 最新补件/拒绝/暂停说明摘要 |
| 操作 | 查看渠道详情、处理补件、申请下架 |

筛选：关键词（Offering/Asset/申请编号）、申请状态、渠道展示状态、Offering 状态、时间范围。

### 5.3 渠道详情

- 申请基本信息：申请编号、申请版本、提交时间、当前状态。
- 发行对象：Offering、Asset、Instrument 及提交时固定的资料引用；不要求独立 Project。
- 审核记录：审核时间、处理结果、补件意见、拒绝原因、平台操作人/角色摘要。
- 展示范围：申请地区、平台批准地区、受众范围、当前有效规则版本引用。
- 渠道状态：上架处理中/展示中/已暂停/已下架/待复核/上架异常及原因；审核通过后系统自动上架，无人工发布环节。
- 渠道统计：M 页面访问、Offering 详情访问、M 渠道归因订单数和有效订单数；只展示有权汇总值及统计更新时间。
- 事件历史：提交、补件、审核通过并触发自动上架、上架结果核验、暂停、下架、恢复、重新申请等追加记录。

### 5.4 Issuer 允许操作

| 操作 | 条件 | 结果 |
|---|---|---|
| 查看申请 | 当前 Tenant 有权访问该 Offering | 打开 I-68 详情 |
| 处理补件 | 状态为待补件 | 跳转 I-67 补件步骤 |
| 撤回申请 | 申请未完成最终审核 | 撤回当前申请并保留历史 |
| 申请下架 | 当前 M 渠道展示中 | 创建平台下架请求；不直接改变渠道状态 |
| 查看统计 | 有渠道统计权限 | 只读汇总 |
| 修改 Offering | 通过原 Offering 页面 | 修改后按版本规则判断是否需要渠道重新审核 |

不得提供「强制上架」「手工改为审核通过」「直接恢复平台下架」「修改平台批准地区」等操作。

## 6. P-15｜Offering 上架审核与补件

### 6.1 页面目标与边界

P-15 是平台审核单个 Offering 是否满足 M 渠道准入条件的工作区。它审核的是平台渠道展示授权、披露资料、申请完整性和适用平台规则，不是：
- Issuer 商业 KYB 审核（由 P-03 负责）；
- Issuer 的合法发行批准或底层资产权属法律意见；
- 投资者个人 KYC/AML 或某一投资者的 Offering 资格判断；
- Offering 的价格、数量、权益、销售窗口或发行状态编辑。

### 6.2 页面入口与结构

P 端「03 统一投资渠道管理」下的二级页面：
1. 上架审核（通过即自动上架）；
2. 已上架渠道管理；
3. 渠道监控。

P-15 采用「审核队列列表 + 申请详情审核工作区」结构。复杂审核使用标准独立页面，不默认使用右侧 Drawer。

### 6.3 审核队列筛选

| 字段 | 控件 | 选项/规则 |
|---|---|---|
| 关键词 | 输入框 | 申请编号、Issuer 名称、Offering 名称/编号、Asset 名称 |
| 申请状态 | 下拉 | 全部、已提交、审核中、待补件、补件已提交 |
| 资产类型 | 下拉 | 全部及现有开放资产类型 |
| 申请地区 | 下拉 | 当前平台支持的地区 |
| 提交时间 | 日期范围 | 申请提交时间 |
| 审核负责人 | 下拉 | 全部、未分配、当前账号、指定负责人 |
| 超期状态 | 下拉 | 全部、正常、已超期 |

### 6.4 审核队列列表字段

| 字段 | 说明 |
|---|---|
| 申请编号 | 唯一渠道申请编号 |
| Issuer | 企业名称及企业编号 |
| Offering | 名称、编号、发行轮次 |
| Asset | 名称及资产类型 |
| 申请地区 | Issuer 请求展示的地区 |
| Issuer Offering 状态 | 只读显示原发行状态 |
| 商业 KYB / 套餐 | 只读摘要，不在本页审核 |
| 申请状态 | M23 渠道申请状态 |
| 提交时间 | 最近一次提交/补件提交时间 |
| 审核负责人 | 当前负责人 |
| 待处理时长 | 从进入当前待处理状态开始计算 |
| 操作 | 查看审核 |

默认排序：待处理时间较长优先；已完成申请不默认进入待办队列。

### 6.5 申请详情信息区

**A. 申请摘要**
- 申请编号、版本、状态、提交人、提交时间、当前负责人。
- 历史申请版本与最近补件轮次。
- 申请地区与 Issuer 授权声明。

**B. Issuer 主体摘要**
- 企业名称、企业编号、注册国家/地区。
- 商业 KYB 状态、Standard/Free 状态、Tenant 服务状态（只读）。
- 企业资料来源及最近更新时间。
- 跳转 P-03/P-05 查看商业主体状态；不在 P-15 重复审核。

**C. Offering 与底层资料**
- Offering 名称、编号、轮次、原发行状态、认购窗口。
- Asset、Instrument 名称/编号及提交时固定的展示资料快照；不读取独立 Project 或通用业务版本历史。
- 发行数量、单价、目标募集额及关键权益摘要（只读）。
- Offering 发布快照与当前版本是否一致。
- 跳转 Issuer 原 Offering 详情（只读授权范围内）。

**D. 披露与授权快照**
- 申请提交时的企业、Asset、Instrument、Offering 版本。
- 已选择文件名称、类型、版本、上传时间、披露权限/扫描状态摘要。
- 渠道授权确认文本版本、确认人、确认时间。
- 文件缺失、版本失效、授权不完整等差异提示。

**E. 渠道准入检查**
- 申请资料完整性。
- Issuer 商业 KYB / Standard 状态（只读 Gate）。
- Offering 是否已正式发布且当前可用。
- 申请地区是否在平台当前有效规则范围内。
- 披露文件与授权版本是否有效。
- 是否存在影响渠道展示的未处理重大风险/投诉。
- 检查结果只显示通过/不通过/待核，不产生底层资产法律意见。

### 6.6 审核操作

| 操作 | 条件 | 结果 |
|---|---|---|
| 开始审核 | 已提交/补件已提交，当前无人处理或符合交接规则 | 状态转审核中，记录负责人 |
| 要求补件 | 存在可补正的缺项 | 生成补件要求，回到 Issuer I-67 |
| 审核通过并自动上架 | 申请资料、Issuer 授权、Offering 状态、批准展示范围及 P-10 规则 Gate 全部满足 | 一次确认审核通过；系统自动创建唯一 Listing 并发布至 M，成功后渠道状态为「展示中」；不经过 P-16 人工发布 |
| 审核拒绝 | 存在不可接受或无法补正的渠道准入问题 | 结束本申请版本，记录原因；Issuer 可修正后新建申请 |
| 转交/升级 | 超出当前审核权限或出现重大风险 | 创建/关联 M17 任务并指定适格负责人 |

### 6.7 补件弹窗字段

- 补件类别（必填，多选）：企业授权、Asset 披露、Instrument/权益文件、Offering 条款/披露、地区适用材料、其他。
- 具体缺项（必填，多行文本）。
- 要求补充的文件或信息（选填）。
- 补件截止时间（如适用）。
- 内部备注（选填，不发送给 Issuer）。
- 对外补件说明（必填，发送给 Issuer）。
- 通知方式（按 M18 当前可用渠道显示）。
- 按钮：「发送补件要求」「取消」。

补件提交后由 M17 建立/更新原申请任务，M18 发送通知。Sent/ProviderAccepted/Read/合法送达不得混为同一状态。

### 6.8 审核通过/拒绝确认

**审核通过并自动上架确认页/弹窗：**
- 显示申请版本、Offering、Asset、Issuer 已授权的申请地区、拟批准展示地区/受众、披露与授权快照、P-10 规则版本、M 页面预览和全部 Gate 检查结果。
- 批准展示地区/受众：默认取申请范围与当前有效规则允许范围的交集；不得扩大 Issuer 已授权范围。若需扩大，必须退回 Issuer 重新授权。
- 审核结论备注（必填）。
- 明确影响：「确认后将批准该申请，并由系统自动创建 Listing、上架至总投资者平台；无需再次人工发布。上架成功后投资者可发现该 Offering，但是否可认购仍由 KYC、发行窗口、适用规则及交易条件独立决定。」
- 主按钮：「审核通过并自动上架」；次按钮：「返回修改审核结论」。确认前必须再次检查申请快照、Offering 状态、展示规则和授权未失效。

**审核拒绝弹窗：**
- 拒绝原因类别（必填）。
- 具体说明（必填）。
- 是否允许修正后重新申请（默认允许；若涉及明确禁止事项则按规则限制）。
- 确认后记录终态；不删除原申请和证据。

### 6.9 P-15 异常与保护

- 申请版本与当前 Offering 版本不一致：阻断审核通过，提示 Issuer 更新申请快照后重新提交。
- 文件引用失效或权限撤销：显示具体文件及版本，不允许通过。
- 商业 KYB / Standard / Tenant 服务状态 Unknown：保持待核，不得当作通过。
- 地区/受众规则 Unknown、冲突或已失效：阻断批准及自动上架，转 P-10 规则负责人。
- Issuer Offering 已暂停、关闭或不再正式发布：阻断批准及自动上架。
- 自动上架结果 Unknown：申请审核决定保留为「审核通过」，渠道状态显示「上架结果待核实」；系统按原 Application ID/Listing ID/幂等键查询与重试，不创建第二个 Listing；创建 M17 异常任务，禁止人工绕过或重复发布。
- 自动上架明确失败：显示「自动上架异常」，保留审核通过证据和唯一 Listing/操作引用；由系统重试或通过 P-17/P-07 跟进技术异常，不提供 P-16 人工首次发布按钮。
- 同一 Offering 重复提交：聚合展示原申请；不得产生重复有效上架记录。
- 审核人无权或审批权限撤销：禁止操作并保留审计。
- M17 任务关闭但申请/Listing 状态未更新：仍以渠道申请及 Listing 原业务状态为准，不得把任务关闭当成上架成功。

## 7. P-16｜已上架渠道管理

### 7.1 页面目标

P-16 管理 P-15 审核通过后由系统自动上架的 Offering Listing，负责查看展示结果、暂停、下架、恢复及展示历史。

**P-16 不承担首次发布或再次手工发布。** P-15 审核通过即触发系统自动上架；P-16 不创建 Offering、不修改 Issuer Offering 条款、不管理投资者个人资格，也不提供真实认购开关。

### 7.2 页面列表与筛选

内部状态页签：
- 展示中；
- 已暂停；
- 已下架；
- 待复核；
- 上架异常（系统自动上架未确认成功，仅供排障，不是人工待发布队列）。

筛选字段：
- 关键词：Listing 编号、申请编号、Issuer、Offering；
- 渠道状态；
- Asset 类型；
- 批准地区；
- 发布/暂停/下架时间；
- 规则版本；
- 负责人。

列表字段：
- M Listing 编号；
- Issuer；
- Offering 名称/编号；
- Asset 类型；
- 申请版本/批准时间；
- 批准展示地区；
- 当前展示状态；
- Issuer Offering 状态；
- 可认购状态摘要（只读、按 Offering 条件汇总，不代表所有投资者均可认购）；
- 最近渠道操作时间；
- 操作入口。

### 7.3 Listing 详情与展示信息

**A. 已批准申请快照**
- 申请编号及版本；
- Offering/Asset/Instrument 引用及版本；
- 已批准披露文件与授权版本；
- P-15 审核结果、审核人和时间；
- 当前是否与原 Offering 最新重大披露版本一致。

**B. 已生效展示范围（只读）**
- 展示地区：显示 P-15 批准时确认的地区，引用 P-10 当前有效规则。
- 展示受众：显示 P-15 批准时确认的受众范围；不在 P-16 自由创建投资者等级或扩大受众。
- 展示内容：Issuer/Offering 原资料的只读预览；不复制内容编辑器。
- 展示规则版本：显示 P-15 批准时引用的 P-10 规则版本和生效时间。
- 当前规则变化：若新规则影响现有 Listing，标记待复核并按规则暂停或限制展示；不得静默扩大范围。

**C. M 页面实际展示预览**
- M-02 投资机会列表卡片；
- M-03 Issuer 介绍；
- M-04 Offering 详情与披露；
- 显示已批准地区、受众、当前渠道状态及最后同步时间；
- 该预览对应已存在的 Listing，不再提供预发布/发布操作。

**D. 渠道状态历史**
- 状态前后值、原因、操作者、时间；
- 对应申请/规则/任务/投诉引用；
- 暂停、下架和恢复的证据与备注。

### 7.4 自动上架结果核验

首次上架由 P-15 审核通过动作自动触发。P-16 只读展示自动上架结果及其核验信息，不提供「发布」「确认发布」或「重新发布」按钮。

自动上架前的全部 Gate 在 P-15 最终批准时一次性校验：
1. P-15 审核结论通过，申请版本与审核快照一致；
2. Issuer 商业 KYB、Standard 和 Tenant 服务 Gate 有效；
3. Issuer Offering 已正式发布且未整体暂停/关闭；
4. 批准地区/受众属于 Issuer 授权申请范围，且符合 P-10 当前有效规则；
5. 披露材料和渠道授权仍有效；
6. 不存在阻断上架的重大安全/合规事件或 Unknown。

P-16 展示：自动上架触发时间、结果、Listing ID、M 同步状态、最后核验时间及异常引用。Standard 和商业 KYB 通过不等于发行合法性或投资者认购资格自动通过。

### 7.5 渠道操作

| 操作 | 影响 | 保护要求 |
|---|---|---|
| 暂停渠道 | 暂停该 Offering 在 M 的新发现/新入口 | 不暂停 Issuer Offering，不删除已有订单/持仓/收益 |
| 下架渠道 | 从 M 的公开投资机会目录移除 | 保留 Listing、申请和历史交易；既有投资者仍按合法授权查询本人历史业务；如需再次上架，Issuer 发起新申请并由 P-15 重新审核 |
| 恢复渠道 | 恢复此前被暂停的 Listing 展示 | 仅适用于暂停而非已下架；核对暂停原因已解决、申请/披露版本有效、规则仍允许 |
| 查看上架记录 | 查看 P-15 审核决定自动触发的上架结果 | 只读，不创建第二个 Listing，不提供人工发布 |

### 7.6 确认弹窗字段

**暂停确认：**
- 暂停原因（合规/资料争议/投诉/安全/Issuer 请求/其他）；
- 暂停范围（M 渠道展示）；
- 现有订单和投资者权利保护说明；
- 关联任务/证据；
- 操作备注；
- 按钮：「确认暂停 M 渠道」。

**下架确认：**
- 下架原因；
- 下架生效说明；
- 既有投资者查询与历史业务保留说明；
- 是否需通知 Issuer/投资者（通过 M18）；
- 按钮：「确认从 M 下架」。

**恢复确认：**
- 原暂停/下架原因；
- 原因解决证据；
- 当前 Offering/资料/规则复核结果；
- 恢复展示地区/受众；
- 操作备注；
- 按钮：「确认恢复 M 渠道」。

### 7.7 P-16 状态与异常

- 审核通过并自动上架成功：显示「展示中」，M 可见；可认购状态仍独立计算。
- 审核通过但自动上架结果 Unknown/失败：显示「上架结果待核实/自动上架异常」，M 不应被前端标记为已展示；系统按原操作核对/重试并生成运营异常，不允许人工再次发布。
- Offering 认购窗口未开始/已结束：M 可按展示政策显示 Offering，但显示「即将开始/已结束」，不得显示可认购。
- Issuer Offering 整体暂停：M 显示原 Offering 暂停事实；不把它改写为平台渠道审核拒绝。
- 重大披露/权益/发行条款变化：标记「待复核」；旧快照保留。未经复核不得把新版本当作已批准披露展示。
- 平台渠道暂停/下架：只改变 M 渠道状态，不影响 V 渠道或 Issuer 原 Offering。
- 已下架 Listing 不允许 P-16 直接恢复；重新上架必须由 Issuer 新建申请并经过 P-15 审核。
- 恢复条件 Unknown：阻断恢复，转 P-15/P-17 复核。
- 自动上架/暂停/下架/恢复操作结果 Unknown：查询原操作和 Listing 历史，不重复创建 Listing 或重复执行不可逆操作。

- Issuer Offering 状态；

- 展示地区；

### 8.3 渠道监控列表字段

| 字段 | 说明 |
|---|---|
| Listing 编号 | M 渠道展示记录 |
| Issuer | 企业名称 |
| Offering | 名称/编号 |

| Issuer Offering 状态 | 原 Offering 状态只读 |

| 操作 | 查看渠道详情、查看异常、跳 P-16 |

### 8.4 投诉与异常列表字段

| 字段 | 说明 |
|---|---|
| 事件/投诉编号 | 原始事件引用 |
| 来源 | M 投资者反馈、Issuer 申请、平台监控、外部服务异常 |
| 类型 | 披露争议、资产信息问题、Issuer 行为、地区展示不符、渠道状态异常、订单/页面信息不一致、技术故障、其他 |
| 严重程度 | 一般、重要、紧急；具体分级阈值由平台规则定义 |

| 发生时间 | 事件时间 |
| 当前状态 | 复用 M17 任务状态语义 |

| 下一步 | 补充信息、调查、升级、P-16 受控处置 |
| 最近更新时间 | 事件时间 |

### 8.5 投诉/异常详情

- 投诉/异常基本信息；
- 关联 Listing、Offering、Issuer；
- 报告内容与证据引用；
- 已有处理记录；
- M17 原任务状态和责任人；
- M18 通知记录摘要；
- 当前渠道展示状态；
- 相关订单/资金/登记/Token 状态只显示最小必要只读摘要；
- 处理结论、升级记录和后续动作。

不向普通渠道运营人员展示投诉人的完整 KYC 原件、完整个人身份资料或其他 Issuer 的无关业务数据。

### 8.6 允许操作

- 查看渠道监控详情；
- 创建/关联 M17 异常任务；
- 指定责任人、升级处理；
- 通过 M18 通知 Issuer 补充资料；
- 跳转 P-15 复核申请/披露；
- 跳转 P-16 暂停、下架或恢复渠道；
- 查看只读统计。

关闭投诉/工单不自动恢复渠道、不代表真实资金/登记/Token 业务完成，也不替代 P-16 的渠道状态操作。

### 8.7 运营统计口径

- 统计来源：M21 只读报表与 M23-F007 渠道归因。
- 指标：上架数量、展示中数量、暂停/下架数量、页面访问、详情访问、M 渠道订单数、有效订单数、确认金额（U，如有授权）。
- 所有指标必须显示统计区间、统计基准时间、数据更新时间、来源和延迟。
- 不将 Unknown 当成 0；部分数据源故障时明确显示「数据不完整」。
- 不把 M/V 入口订单重复计算；按唯一订单事实和渠道来源归因。
- 不提供逐投资者订单列表、资金余额、私钥、完整 KYC 或法定名册导出。

| P-17 | 发现异常 | M17 / P-15 / P-16 | 原事件、Listing、Offering、任务 ID |
| P-16 | 暂停/下架/恢复 | I-68 | 最新渠道状态、原因、时间和操作者 |

### 9.1 重大版本变化

以下变化视为影响已批准披露快照的重大变化：Issuer 主体身份、Asset 关键事实/权属/估值、Instrument 法律权益、Offering 经济条款/份额/价格/销售窗口、重大风险披露、授权文件或批准展示地区。

- 申请审核中发生重大变化：阻断当前版本通过，Issuer 更新后重新提交。
- 审核通过后自动上架结果尚未核实：不创建第二个 Listing；按原申请和幂等操作核验，重大变化阻断自动上架完成。
- 已展示发生重大变化：标记待复核；如涉及安全/法律/重大误导风险，平台可先暂停 M 渠道，再要求更新审核。
- 历史版本不可覆盖；已产生订单、付款、配售、登记、Token 和收益仍引用其当时有效版本。
- 非重大文字/联系方式更新是否免复核，按平台有效规则决定；本批不提供自由跳过审核的按钮。

### 9.2 M/V 共享业务事实

- M/V 的订单归属、资金、配售、法定登记、Token 和收益仍由 M10/M11/M12/M07/M13 等原领域持有。
- M23-F007 记录来源渠道并进行共享路由，不创建第二份订单、资金账或名册。
- M 与 V 的账户、身份和历史持仓不自动合并；KYC 结果引用仍须合法依据和授权。
- P-17 仅查看受权汇总和渠道归因，不因平台管理员身份取得投资者原始身份或资金执行权限。

## 10. 页面通用状态、异常与文案

| 场景 | 页面表现 | 允许的下一步 |

| 无权访问 | 显示无权查看，不展示敏感字段 | 返回上级页面/申请授权 |
| 规则服务不可用 | 显示「规则状态待核实」，阻断发布/恢复 | 转 P-17/M17 核查 |

## 11. 权限与审计边界

| 操作角色 | 允许范围 | 禁止范围 |
|---|---|---|
| Issuer 企业账号 | 本 Tenant 的 I-67/I-68；申请、补件、撤回、查看和申请下架 | 修改平台审核结果、平台展示规则、直接恢复平台下架 |
| 平台渠道审核员 | P-15 审核、补件、批准/拒绝；批准通过后由系统自动创建 Listing 并上架 M | P-03 商业 KYB 以外的发行法律批准、资金/Token 操作 |
| 平台渠道运营 | P-16 查看 Listing、暂停、下架、恢复；处理自动上架异常的运营跟进 | 首次发布/手工发布、修改 Issuer Offering 原始条款、投资者资格、订单/资金/法定登记 |
| 平台渠道监控 | P-17 查看聚合数据、创建/关联任务、升级和跳转 | 直接修改原订单、资金、配售、名册、Token 或收益 |
| 安全/审计 | 按合法目的查看最小必要记录、审计操作 | 无目的查看完整 KYC、客户私钥或批量导出个人数据 |

审批人与执行人是否需要职责分离，按 M02/M20 和平台有效规则控制；本文件不定义最终角色码。审核通过触发的自动上架必须记录审核决定、Listing 创建及 M 展示结果；暂停、下架、恢复、审核、补件和敏感访问动作均保留追加历史。

### 12.2 验收用例

1. 一个 Asset 下两个 Offering 分别申请，产生两份独立申请。
2. I-67 不允许编辑 Offering 价格、份数、权益条款或认购窗口；修改必须回到原 Offering。
3. Free 用户不能提交真实 M 渠道申请，只能内部预览。
4. Offering 未正式发布/已整体暂停时不能提交新的 M 渠道申请。
5. I-67 提交后 P-15 能看到同一 Application ID 和固定版本。
6. P-15 要求补件后，I-68 显示待补件，I-67 可补交并形成新版本。
7. P-15 点击「审核通过并自动上架」后，系统自动创建唯一 Listing；成功时 I-68 显示「审核通过/展示中」，M-02/M-04 可见，无 P-16 人工发布动作。
8. 自动上架结果 Unknown 时，I-68/P-16 显示「上架结果待核实」，M 不伪装展示成功；系统按原操作核验，不产生重复 Listing。
9. M Listing 展示中但认购窗口未开始，M 显示即将开始，不允许认购。
10. 投资者 KYC 通过但 Offering 资格/其他条件未满足时，仍不可认购。
11. P-16 只管理自动上架后的 Listing；暂停/下架只改变 M 渠道，不修改 Issuer Offering 或 V 门户状态；已下架后需 Issuer 重新申请，不提供 P-16 手工重新发布。
12. 暂停/下架后，既有订单、资金、配售、登记、Token 和收益历史仍可查询。
13. Issuer 在 I-68 申请下架只产生请求，不直接改变平台 Listing 状态。
14. Offering 重大版本变化后，旧快照保留，新版本进入待复核。
15. P-17 投诉创建 M17 任务，关闭任务不自动恢复渠道。
16. M/V 订单归因正确，不产生重复订单或重复统计。
17. 任一提交/发布操作 Unknown 时查询原记录，不重复创建。
18. 无权角色无法执行审核、发布、暂停、下架、恢复或查看高敏材料。

验收只对本地 Mock 前端执行；未运行的场景标记 Not Executed，不得标记 PASS。
