## 4. 端到端业务闭环核对

| 阶段 | 页面责任 | 审计结果 |
|---|---|---|
| 邮箱登录/企业创建 | 登录、企业创建引导 | 单邮箱账号；显式创建企业；不自动创建多个 Tenant |
| KYB | 五步企业认证、状态/补件 | 草稿、提交、补件、未通过、通过；原资料可编辑重提并保留版本 |
| Free/Standard/钱包 | 企业管理、订阅、钱包 | KYB 后激活 Free 与 MPC 钱包任务；Standard 付费不自动取得生产权限 |
| 资产创建 | 资产管理、资产详情 | 房地产六子类分类保留，四模板开放创建；Ready 仅代表资料完整 |
| 权益配置 | 权益结构单页 | 一资产一套 Instrument；三类权益模板；Token 拆分不整除拒绝，不静默舍入 |
| Offering | 资产详情「发行管理」TAB | 固定引用 InstrumentVersion；含发行参数、披露、收款钱包、准备检查和最终预览；不独立创建 Project 菜单 |
| 门户展示 | I-13 | Free 只读内部预览；Standard 受控配置；门户发布不等于 Offering 发布或投资者可认购 |
| 投资者 KYC | 投资者管理（Issuer 脱敏视图） | 第三方服务商核验，平台维护状态并返回 SaaS；Issuer 不看原件、不人工审核、不覆盖 |
| 认购 | 认购订单；认购记录只读视图 | 唯一订单主账；订单完成不自动代表法定登记、募集款结算或收益支付完成 |
| 付款/退款/募集款 | 资金与结算 | OP Mainnet USDT；付款指令、到账观察、Finality、FinalMatched、退款和募集款释放分开 |
| 配售/持有人 | 配售与持有人 | 唯一 Allocation、容量与法定名册权威；Token 余额不替代法定登记 |
| Token | Token 管理 | 必须引用唯一有效配售、FinalMatched、有效合约与真实授权；Unknown 先查原 Intent/Tx，不重复 Mint |
| 锁仓 | 锁仓记录 | 真实 Token 交付达到适用最终确认后起算；业务期限、链上限制、法律限制分开 |

| 到期/清退 | 到期与退出 | 到期、逾期、部分清偿、清退/兑付与认购退款分开；保留未结义务和责任交接 |

| 对象/事实 | 唯一权威页面/模块 | 其他页面允许行为 |
|---|---|---|
| 企业主体、KYB、订阅 | 企业管理/U01 | 只读摘要、状态守卫和回源 |
| 企业钱包与默认钱包 | 钱包管理 | Offering 选择收款钱包；Token 只读取接收地址/Signer 相关受权事实 |

| Instrument 权益定义、总量、Token 映射 | 权益结构 | Offering/配售/Token/收益引用，不重新定义 |
| Offering 本期参数、窗口、披露、收款钱包、锁仓条款 | Offering | 订单/资金/锁仓引用发布快照 |

| Token 方案、部署、Mint/Burn、链上最终性 | Token 管理/实际受权执行主体 | 其他页面只读链上事实 |
| 业务锁仓记录与期限 | 锁仓记录 | Token 仅提供链上限制执行引用 |
| 收益、Record Date、应付、实付、到期和清退 | 收益与分配/实际义务主体 | 读取持有人、资金、Token 事实，不复制主账 |
| 待办、异常、通知、规则、审计、报表、Provider 状态 | 数据与共享能力 | 协调、只读引用和回源，不覆盖领域真值 |

## 6. 全局状态、异常与交互一致性

- 业务状态、技术服务状态、法律/披露状态、资金状态、法定登记状态、Token 链上状态必须分开显示；不得合并为单一「成功」。
- Unknown、待核、来源冲突不默认成功或失败；先查询原始 Intent、交易、事件或服务回执。
- 对付款、退款、Mint/Burn、登记、清退等不可逆/高风险操作，Unknown 时禁止盲目重试或创建第二个请求。
- 部分成功必须显示已完成部分、未完成部分、责任来源和唯一下一步；技术恢复不代表业务恢复。
- 页面加载失败保留最后成功核验时间；局部来源失败允许局部重试，不清空其他有效表单/草稿。
- 切 Tenant、会话过期、账号停用或授权撤销时，重新核验服务端权限并清理不再有权访问的敏感预览/文件。
- 所有跨页跳转保留当前 Tenant 和来源对象；返回时重新核验版本、状态和访问授权。
- 每个页面应显示当前状态、阻断原因和唯一下一步；无下一步时给出明确空态或等待说明。

## 7. Free / Standard 与单账号规则一致性

- Free：可创建、编辑、保存正式 Asset/Instrument/Offering 准备资料；不可发布真实 Offering、生成对外门户、真实认购/募资、持仓、Token 或收益运营；仅可内部只读预览投资者门户。
- Standard：在订阅有效、KYB 通过及适用业务/法律/Provider/Signer/资金/网络/安全生产准入全部满足后，才可使用已批准的真实业务能力。
- Standard 降级后的历史业务按 U01 规则只读；保留历史数据与未结存续义务，不因当前套餐标签为 Free 而重新开放写操作。
- V1 一个账号对应一个企业；无团队邀请、角色模板、企业 RBAC、内部审批人分配或多级审批。
- 统一 KYC 由平台/适格服务商负责；Issuer 只查看脱敏状态，不提供人工 KYC 审批或投资者资格覆盖。
