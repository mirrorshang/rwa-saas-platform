# DEC-076｜V1「配售与持有人」模块 UI-Ready 收口

> 2026-11-11｜**产品负责人按用户已授予的 V1 小模块详细设计权限完成收口**。本决策仅确认企业端 UI/产品规格；不批准实际金融、法律登记、资金或 Token 生产执行。
>
> 产品端：Issuer 企业 SaaS；唯一导航「投资者与认购 → 配售与持有人」；维护分支 \`docs/r2-current-product-baseline\`；PR #8 Draft / Open / Unmerged。

## 1. 来源及权限

本轮承接：
- DEC-022：配售容量、基础自动配售与逐笔有权处理、法定登记三种责任模式；不得将 SaaS 操作员视为有权登记者。
- DEC-032：真实资金最终核实、合法配售、权威法定登记和 Token 交付分别有独立结果及法定时序。
- DEC-033：收益 Record Date 必须引用合法有效的权威持有人记录；退出/清退、登记与 Token 处置分开。
- DEC-052：Issuer 既有配售与持有人三类页面职责，M12 权威容量和配售；不是金融生产授权。
- DEC-058：持有人管理纳入 V1，补充查询、详情、Token 对账、限制状态与受权复核；强制转账不纳入 V1。
- DEC-069：KYC 第三方统一核验，Issuer 仅查看脱敏状态，不人工批准/拒绝或设置额外资格。
- DEC-071、DEC-072、DEC-073、DEC-074、DEC-075：权益映射、Offering 固定条款、已完成认购、投资者档案与全生命周期订单的当前 UI-Ready 规格。
- 用户授权产品负责人按小模块独立完成 MVP UI 细节，只有重大业务、法律或已批准规则冲突才需再决策。

## 2. 页面结构决定

**不改变九个一级导航及现有二级入口。**

在「投资者与认购 → 配售与持有人」下，以同一页面的三项视图组织：
1. **配售管理**：共享权益容量摘要、配售候选/记录列表、配售详情及受权决定入口。
2. **持有人登记**：持有人列表、持有人详情、依法有权的登记材料/结果承接抽屉。
3. **差异与限制**：差异/待处理事项列表、差异详情、限制及解除限制的受权申请抽屉。

不建立第二套订单、资金、法定登记、Token 或收益主账；页内切换不是新增导航。

## 3. MVP 页面/业务规则

### 3.1 容量与配售

- 一套 Instrument 只有一份共享授权权益容量，多期 Offering 共享；已发布 Offering 预留本期容量，订单只占该预留的内部份额，不能再次扣减 Instrument 总容量。
- 容量卡分列最大授权、已确认占用、有效预留、待核保护/冻结和权威可用量；数据 Unknown 不当作 0，不在前端从不同来源推算可用数。
- 配售候选不等于有效 Allocation；必须有唯一合法决定、有效订单/合同、当前适用强制准入、真实资金 FinalMatched、有效容量/预留和受权主体或预先批准的基础配售策略。
- 自动基础配售依事前批准的合法适用规则执行；需要逐笔决定时，只有已确认有权主体和相应授权流程才可提交/处理。普通企业账号不能直接点「已配售」。
- 配售结果的 Token 份数与法律权益数量/单位按确定 InstrumentVersion 精确映射；不静默舍入，也不把债权本金/股权份数/收益参与比例混为同一单位。

### 3.2 登记与持有人

- 法定持有人及有效权益量由有权登记主体的真实结果/证据确定；Investor Account、付款钱包、Token 接收钱包、合法持有人必须区分。
- 登记模式：发行人依法自管、依法委托登记机构、依法强制指定登记者；不强制所有企业聘用外部机构，也不让 SaaS 平台当然成为登记者。
- 企业端登记事项抽屉按模式条件化：自管且确有合法授权时可以承接真实权威结果及证据；委托/强制模式只提交合法材料或查看真实回执；未知主体时阻断。
- 登记材料提交、回执待核和权威登记生效分开；缺少有效有权主体和回执不得标「已登记」；更正必须保留旧版本。
- 持有人列表/详情分别展示脱敏持有人、权益法律单位与数量、法定登记状态、Token 交付/余额摘要、锁仓/限制、配售来源、历史和差异。

### 3.3 Token 对账、限制与退出

- 只有对应主体、InstrumentVersion、范围及适用时点一致时，才可将 Token 份数按每 Token 对应权益量换算，与法定权益单位比较；缺少条件显示「待核/不可比较」，不能直接拿 Token 余额与股票、债权本金或参与比例原值比较。
- 法定登记有效不等于 Token 已交付；Token 已交付不自动等于法定登记有效。差异、Unknown、登记拒绝、重复回执、链失败要显示原事实及责任模块。
- 冻结/解除限制仅可按适用法律、合同及实际授权提交受控复核申请；包含原因、依据、影响权益量/Token 映射、原限制编号、确认弹窗、结果和操作历史。**申请提交不等于法律/链上限制生效或解除。**
- 基础锁仓/解锁只展示并跳转「资产与发行 → 锁仓记录」；合法转让事件可只读核对，**不新增强制转账或自由交易**。
- 赎回、到期与清退仍属于「收益与分配 → 到期与退出」，持有人页面只展示关联事项及有权入口，不自行清偿/改账。
- 收益 Record Date 引用 M12 权威法定持有人快照，不把 Token 余额当成合法权益来源。

### 3.4 简洁、权限与异常

- 页面统一三视图，列表仅保留必要搜索、Asset/Offering/登记/对账/限制筛选，20 条分页、桌面表格及移动端卡片。
- 持有人默认脱敏，不展示原始 KYC、完整个人身份证件/联系方式或无授权完整钱包地址；跨 Tenant 不可检索。
- Free 新企业无真实配售/持有人数据；Standard KYB 通过也不自动有金融、法定登记或链执行权；降级历史只读，已生效合法权益不消失。
- 付款 Pending/Unknown、迟到账、容量争议、登记回执 Unknown、Token 失败/Unknown、限制申请处理中、解除待核均保留历史和下一步，不制造假成功。
- 所有关键界面明确当前状态、事实来源、阻断原因及唯一主动作。
