# 模块 05｜债权本息与模拟清偿实施记录

## 正式范围

在 `apps/issuer` 的「收益与分配」复用固定持有人快照、分配批次及逐笔 Sandbox 支付；债权单独保存固定计划、每期应付利息事件和模拟清偿记录。本金批次与投资者收益记录分账。发行人没有新增内部审批角色。所有动作只修改本地 Mock 数据，不构成真实法定清偿、付款或链上 Burn。

## 页面操作

1. 「存续管理」点击「生成债权付息计划」。OFF-3002 固定 400,000 U、年息 12%、2026-12-01 起息、2028-12-01 到期和 Actual/365 Fixed，共 24 期；计划按实际天数逐月产生应付事件。2026-12 为 31 天，4,076.712329 U；4,000 U 仅是简化参考。
2. 到应付日后，在「演示控制台」为该期 Record Date 固定 Sandbox 持有人快照；回到「存续管理」点击对应行「创建月息批次」。页面预览快照编号、计息天数和持有人金额。进入批次详情点击「确认合法批次」及弹窗「确认分配批次」。只有确认后可在「演示控制台」逐笔模拟支付，Unknown 必须查询原支付意图。
3. 到期时在「到期与退出」点击「创建到期本金偿还批次」。必须先固定到期日 Record Date 快照；400,000 U 分为 250,000／150,000 U。批次独立确认、逐笔 Mock 支付；本金收据不计累计利息／租金收益。
4. 所有 24 期利息和本金均支付完成后，在「演示控制台」依次点击「更新清偿后模拟持有人登记」「模拟到期 Token 处置」「确认 Sandbox 债权清偿完成」。名册权益和 Token 模拟余额分别归零；每笔 Token 处置有独立记录。若仍有未结义务，不能显示完成。

「演示控制台」另设「逐期模拟剩余债权月息」，只在测试日期推进至到期日后加速重复的 Sandbox 步骤：逐期固定快照、建立并确认批次、逐笔记录支付，各期都有独立可查记录。已有 Unknown 时停止并提示先查询，不合并成一笔付款。正常业务页面只展示计划、事件、批次和清偿状态。

## 规则与验收证据

计息区间按当前已确认测试条款使用 `[起息日, 到期日)`，实际天数／365；此边界属于 Sandbox 验收口径，正式合同边界和节假日规则仍需法务确认，不擅自扩展提前还款、逾期或违约。到期后的正常利息事件不生成。同 Offering、事件类型、期间的有效批次只能一份；快照和条款版本在确认时复核。支付失败可用新意图重试，Unknown 只能查询原意图。

2026-11-19 在正式站点 `http://localhost:5174` 实际点击 OFF-3002：首期未到日及本金缺到期快照均显示阻断提示；首期 `DST-1002` 由正常页面创建和确认，两名持有人分别收 2,547.945206／1,528.767123 U。余下 23 期在独立测试控制区逐期生成，每期批次和两笔支付均可在列表查到。到期 `DST-1026` 两笔本金分别为 250,000／150,000 U；本息已付但未处置名册／Token 时完成受阻。随后名册更新、两笔模拟 Token 处置与唯一完成记录成功；刷新后「到期与退出」显示已偿还 400,000 U、未偿 0 U、Sandbox 清偿完成。HOL-3004 详情显示原始本金 250,000 U、已还 250,000 U、本金独立收据；累计收益只计已支付利息。
