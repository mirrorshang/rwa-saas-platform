## 1. V1 产品定义

V1 是面向发行企业与资产管理机构的标准化多资产 RWA Issuer SaaS，提供从企业入驻、资产建档、权益结构、发行方案、投资者门户，到投资者准入、认购、资金对账、配售、法定登记、Token 交付和发行后收益/退出的基础业务闭环。

V1 采用“五个产品端 W/I/V/M/P + 外部责任主体 X”的完整形态：发行企业工作台、Issuer 独立投资者门户、平台统一投资端同时纳入第一版。

### 1.1 V1 产品端

| 产品端 | V1 定位 | 主要用户 | V1 职责 |
|---|---|---|---|
| **W 官网** | SaaS 官网及企业入口 | 潜在发行企业、现有客户、投资者访客 | 产品介绍、解决方案、套餐、帮助、联系、法律政策、企业登录入口，以及依法开放的 M 统一投资机会入口 |
| **I Issuer SaaS** | 发行企业工作台 | 发行企业/资产管理机构 | 企业管理、资产、权益、Offering、投资者、认购、资金、Token、收益及报表 |
| **V Issuer 投资者门户** | 单一 Issuer 的独立投资者前台 | 该 Issuer 的投资者 | 浏览该 Issuer 已发布 Offering、身份/资格、认购、付款指引、订单、持仓、收益和消息 |
| **M 平台统一投资端** | 跨 Issuer 的一级发行聚合与分发入口 | 跨不同发行企业寻找投资机会的投资者 | 汇总展示经批准上架的 Offering；提供统一投资者账户、跨 Issuer 资格/认购、本人订单、持仓及收益查询 |
| **P 平台运营后台** | SaaS 平台内部运营后台 | 平台运营人员 | 商业客户与 Tenant 管理、M 渠道上架审核、平台展示规则、受控敏感访问、异常任务、服务连接和只读运营报表 |
| **X 外部责任主体** | 外部服务与有权执行泳道，不是独立 SaaS 菜单 | KYC/KYB/AML 服务商、支付/托管方、登记主体、电子签署方、Signer、链服务等 | 提供真实核验、资金、签署、法定登记、密钥签名和链上执行等外部事实与回执 |

**M 统一投资端已正式纳入 V1。** DEC-057 将 DEC-045 中 M23/M24 的 11 项功能全部批准为新增 V1 范围；M-01～M-16、I-67/I-68、P-15～P-17 与 W 官网的 M 投资入口共同组成跨 Issuer 一级发行聚合渠道。M 不是二级交易市场；AMM、C2C、订单簿和投资者间受控转让不属于本次 V1。V 与 M 两种投资者入口同时保留，账户与历史权益不自动合并。

### 1.2 V1 产品总体业务链

1. 企业从 W 官网进入，使用邮箱验证码登录；首次验证邮箱自动建立账号。
2. 企业创建并提交 KYB，审核通过后激活 Free，并触发真实 MPC 钱包开通。
3. 企业在 I 工作台创建 Asset，完成资产资料检查。
4. 在该 Asset 下创建唯一当前有效 Instrument，定义股权、债权或收益参与权，并完成权益/Token 拆分检查。
5. Instrument 达到 Ready 后，企业从该 Asset 的「发行管理」创建 Offering；Offering 自动关联内部 Project 和 Instrument 确定版本。
6. 企业完成 Offering 资料、投资者条件、文件、收款钱包及发行准备检查，进行投资者端预览。
7. 有效 Standard、适用法律/业务条件及全部独立生产准入满足后，Issuer 才能发布 Offering 至其 V 门户；如申请 M 渠道，还须逐 Offering 提交申请并通过 P 的独立渠道审核。
8. 投资者可从 V 门户或 M 统一投资端进入：V 使用对应 Issuer 的独立账户；M 使用平台统一投资者账户。两种账户不自动合并，均须按适用范围提交资料、完成 KYC/KYB/AML 与 Offering 级资格判断。
9. 投资者确认认购、必要签署并按 Offering 指引支付 OP Mainnet USDT。
10. 系统核验链上到账、最终性、订单匹配与异常；再按已批准规则完成额度转换、配售和权威持有人登记。
11. 在适用生产授权下执行 Token 部署/Mint/交付，并将链上结果与法定登记、配售结果核对。
12. 发行后管理权益快照、披露、利息/收益/本金事件、应付核算、注资、领取/实付对账、到期、赎回和退出。
13. M 统一投资端仅展示经 P 渠道审核的 Offering；M 投资者按独立账户完成跨 Issuer 资料授权、逐 Offering 资格判断和认购，后续订单/付款/登记/Token/收益均读取同一套权威业务事实，不另建主账。

以上为 V1 产品业务闭环。支付广播、链上最终性、资金可用、订单匹配、配售、法定登记、Token 交付和法律权利成立是不同事实，不能合并为一个“成功”状态。

## 2. V1 全局产品规则

### 2.1 账号、企业与 KYB

- 登录方式：邮箱 + 验证码；不设置独立注册表单。首次邮箱验证成功后自动建立账号并登录。
- V1 一个账号对应一个企业 Tenant；不提供多企业切换。
- 登录后可浏览工作台导航；KYB 未通过时，业务页面和 API 统一拦截到 KYB 状态，不泄露业务数据。
- KYB 采用五步：企业基本信息、企业业务信息、企业关联人员、企业证明材料、预览与确认提交。
- KYB 状态包括未创建、草稿、已提交/审核中、待补件、已通过、未通过；补件和重新提交保留版本及审计记录。
- KYB 通过后激活 Free 业务准备权限，并由真实 Provider 开通企业 MPC 钱包；Provider 失败不得用随机模拟地址冒充成功。

### 2.2 Free / Standard

| 能力 | Free | Standard |
|---|---|---|
| 费用 | 永久免费 | 固定月付/年付；最终价格待配置 |
| KYB | 必须通过 | 必须通过 |
| 企业钱包 | 真实 MPC + 多个自有钱包管理 | 与 Free 相同 |
| Asset | 可创建、编辑、保存正式业务资料 | 相同 |
| Instrument | 可创建、编辑、保存正式业务资料 | 相同 |
| Offering | 可创建、编辑、保存正式发行方案 | 相同 |
| Issuer 独立投资者门户 | 仅内部只读预览；不可配置/生成/发布公开门户 | 可按 V1 范围配置、预览和发布，但须通过全部适用准入 |
| M 统一投资端渠道 | 不可申请真实上架；仅内部预览 | 可按单个 Offering 申请上架，须通过 P 渠道审核及全部适用法域/业务/生产准入；不自动上架 |
| 真实发行/部署/Mint | 不允许 | 生产准入通过后才允许 |
| 真实认购/募资/持仓/收益运营 | 不允许 | 生产准入通过后才允许 |
| 白标/API | 不提供 | 不视为 V1 已交付能力 |

补充规则：

- M 渠道上架不是 Offering 发行发布的自动结果。Issuer 必须逐 Offering 申请，P 完成渠道审核；展示、可认购、投资者资格通过分别判断。
- V 门户与 M 统一账户独立；V 历史账户、订单和持仓不会自动迁入 M。M 仅汇总本人通过 M 渠道产生且依法授权可见的数据。
- Free 是正式业务资料准备版，不是完整 Mock 募资版。Free 创建的 Asset、Instrument、Offering 是真实业务资料，不是模拟业务对象。
- Free 内部预览不生成公开链接、真实订单、支付、持仓或收益记录。
- Free 升级 Standard 不自动发布、部署、Mint、上架或募资；必须重新检查资料、版本、法律、钱包、Provider/Signer、支付、合约及其他生产条件，并由用户再次确认。
- Free/Standard 不设置 Asset、Offering 或 Token 数量硬配额；不得照搬 USDable 的基础2/高级5/定制10资产限制。
- Standard 默认不自动续费；只有付款渠道支持有效周期扣款授权且用户主动启用时才开放自动续费。
- 订阅支持月付/年付，SaaS 订阅可使用 USDT 或法币；投资者认购支付与 SaaS 订阅收款完全分离。
- 到期前 7/3/1 天及到期当天提醒；到期进入 7 天宽限期，暂停新增真实发行；宽限期结束未续费则降级，历史业务只读，必要存续义务由受控机制保障。
- 新开通 Free 与 Standard 降级后的历史只读状态必须区分，不能只根据套餐名称判断写权限。

### 2.3 金额、网络与支付

- V1 平台业务金额统一显示单位 **U**，按 USDT 计价。
- V1 投资者认购付款仅支持 **OP Mainnet · USDT**；旧文档中 USDT/USDC 多币种描述不作为 V1 支付范围。
- SaaS 订阅支付可使用 USDT 或法币，但其支付网络、收款账户和结算账与投资者认购资金分离。
- 每个 Offering 在 V1 选择并确认一个企业已配置且有效的钱包作为最终收款钱包；不建立独立收款方名录，不做多收款方比例分账。
- 真实支付、退款、资金托管/结算方、Signer、合约地址、精度及生产网络配置均须独立准入；产品范围确定不代表生产 Provider 已获批准。

### 2.4 统一状态与安全原则

- 每个业务事实有唯一主责模块；其他模块只引用或展示，不复制主账。
- 订单、Payment、Allocation、Register、Token、Yield/Repayment 分别保留自己的状态和证据。
- 所有关键操作必须记录版本、操作者、时间、来源和审计证据；关键请求具备幂等、防重复和 Unknown 查询/恢复路径。
- 文件上传、扫描完成、资料 Ready、法律审核、生产准入是不同状态。
- Mock/Fixture 仅用于内部测试控制台，不出现在正式客户业务页面，不得迁移成真实资金或 Token 记录。

### 3.1 资产与发行页面组织

### 3.2 M｜平台统一投资端导航与职责

- **M-05～M-08 账户与资格**：M 统一账户注册登录、投资者资料与 KYC 引导、钱包连接/管理、Offering 专属资格核验。
- **M-09～M-12 认购流程**：报价和认购确认、法律文件确认/必要签署、OP Mainnet USDT 付款指引、付款/配售/登记/Token 进度。
- **M-13～M-16 投后与账户**：本人跨 Issuer 订单/退款、持仓/登记/Token、收益/文件/通知、安全/授权/隐私。

- M 渠道上架申请仅向有效 Standard 且通过适用生产准入的 Issuer 开放；Free 仅可内部预览，不生成公开链接或真实投资者记录。
- Issuer 上架申请、P 渠道审核、M 渠道展示和投资者可认购资格是不同状态。
- M/V 账户保持独立；跨 Issuer 资料复用必须有合法授权，且每个 Issuer/Offering 独立核验资格。
- M-11 付款 UI 服从 V1 支付范围，仅展示 **OP Mainnet · USDT**；旧页面候选中的 USDC 泛化描述不覆盖 U02 最新规则。

## 4. V1 资产、权益结构与 Offering 规则

### 4.1 Asset 资产管理

- 资产分类目录：8 大类、24 个二级分类。
- V1 实际开放创建的资产模板仅四种房地产子类：**住宅、写字楼、商铺、工业园/仓储物流**。
- 酒店、土地以及其余七大一级资产类别的模板暂不开放创建；房地产不包含在建项目。
- Asset 创建采用五步：①选择分类；②基础信息；③法律与估值；④专属属性；⑤预览提交。
- 字段按全平台基础字段、一级类别公共字段、二级子类专属字段三级组织；不采用一个大而全的万能表单。
- 资产 Ready 表示资料达到已定义的完整性要求，不代表产权真实、法律批准或获得发行许可。
- 必需文件固定逐行展示并在每行提供上传按钮：资产权属证明、资产估值依据文件；存在抵押/其他权利限制时增加条件必需文件。其他材料通过「添加其他文件」按需上传。
- 文件状态至少区分未上传、上传中、待扫描、可引用、失败；文件换版不得覆盖已被后续业务引用的历史版本。
- 资产资料预览与 Offering 投资者端预览是两种不同预览。

### 4.2 Instrument 权益结构

- MVP 一个 Asset 最多一套当前有效 Instrument；不允许同一 Asset 并行创建第二套有效权益结构。
- 权益类型三选一：股权、债权、收益参与权。
- 创建/编辑采用一个页面、三个区域：权益定义、Token 拆分、法律文件；不是多步向导。
- 用户输入本次权益总规模及 Token 总份数，系统计算每 Token 对应的权益量。
- 股权型、收益参与型可选填发行方预期年化收益率区间（最低/最高值及测算依据）；不填写不阻断 Ready。投资者端明确标注为发行方估算，不构成收益或保本承诺，不参与 M13 应付/分配计算。
- 债权型固定利率除合同年利率、起息/到期日期外，V1 支持到期一次、每月、每季度、每半年、每年付息；周期付息需记录首个付息日、日期递推规则和计息日数规则。无息债权不配置付息计划；本金仍到期一次偿还。
- Offering、V/M 投资者端引用 InstrumentVersion 快照，预期年化披露和债权付息计划不得被 Offering 单独覆盖。
- Token 拆分必须精确表达；无法整除或超出权利最小单位时拒绝，不得静默四舍五入。
- 多期 Offering 可引用同一 Instrument 的确定版本并共享容量；Draft Offering 不占用正式发行容量，不能跨期超发或重复占用。
- Instrument 必须达到 Ready，才允许创建 Offering Draft；Offering 固定引用创建时的 InstrumentVersion。

### 4.3 Offering 发行方案

- Offering 从 Asset 详情「发行管理」TAB 创建，创建/编辑采用单页面三区域：
  - A：发行信息；
  - B：投资者认购条件；
  - C：发行准备。
- Project 由系统按需关联，不要求用户先进入 Project 菜单。
- Offering 继承 Asset、Instrument 确定版本、权益映射和可发行容量；不重新创建权益池。
- 核心发行参数包括本期 Token 数量、每 Token 认购价格（U）、最低认购金额（U）、认购起止时间、投资者类型/地区/KYC 条件、锁仓条件、企业收款钱包及必要法律文件。
- 计划最高募集额由本期 Token 数量 × 每 Token 价格自动计算，不设置重复的等义编辑字段。
- Offering 业务资料完整性检查与真实生产准入检查分离；检查成功不等于已发布。
- 提供编辑中预览和发行前最终预览；不得虚构募集进度、已售数量、已 Mint 数量或收益数据。
- Free 可以保存正式 Offering Draft 和内部只读预览；不能真实发布、公开上架、认购、收款或 Mint。
- Standard 只有在订阅有效、KYB 有效且所有适用法律、投资者资格、钱包、Provider/Signer、合约、支付、资金、安全和网络准入通过后，才能执行真实发布。
- Offering 暂停/结束/关闭不得删除在途订单、实收、配售、登记或 Token 事实；历史条款、文件和 Instrument 版本不得被静默覆盖。

## 7. V1 明确不包含的功能边界

以下内容不属于本次 V1 交付清单，不在后续 V1 产品设计中默认加入：

- M14 受控投资者间转让工作流（V2）；M14-F007 公开订单簿/AMM（TBD）；C2C、AMM、二级交易撮合、平台自营流动性及投资者间公开交易。
- 多收款方名录、按比例分账和复杂多受益方资金路由（V2）；V1 每个 Offering 仅选择一个企业有效收款钱包。
- Usage / 使用型权益及其额度、消费/核销和履约模型（V2）；V1 Instrument 继续限于股权、债权、收益参与权。
- Authenticator / TOTP 独立双因素认证；V1 保持 U01 邮箱验证码登录。
- USDable 式套餐资产数量配额；V1 继续执行 Free / Standard 权益矩阵，不设置 Asset / Offering / Token 数量硬配额。
- 普通 Issuer 直接强制转账、直接改写法定持有人或 Token 余额。
- M/V 跨门户 SSO、历史 V 账户/持仓自动迁移、未经授权的跨 Issuer KYC 原件共享。
- M15 高级 White-label 运营商能力、M16 高级 Open API/SDK，按既有版本归属后置。
- 多 Asset 复杂组合 Project、多 Instrument、多层权益结构、复杂分层与复杂审批。
- 房地产酒店、土地和非房地产资产模板的实际创建能力。
- Free 套餐中的模拟认购、模拟募资、模拟持仓、模拟收益等商业功能；内部 Mock 控制台只供测试。
- 将平台自身变成投资者资金持有人、托管人或未经授权的法定发行/登记主体。

此节用于锁定 V1 范围，不代表删除历史 DEC、Frozen 文件或未来版本功能身份。

## 8. 生产准入与产品交付的区别

V1 产品功能包含真实资金、Token、登记和发行后管理的目标能力，但以下条件必须单独通过后才可进入真实生产：

- 首发经营法域、产品法律定性、发行主体及适用许可；
- 平台自身对 M 渠道展示、跨 Issuer Offering 分发、投资者身份/资格编排、认购受理与运营行为的适用法域、牌照/合作方及合同责任；
- Issuer 与外部法律/评估/登记责任主体的职责及证据；
- KYC/KYB/AML 服务商与实际核验能力；
- 企业 MPC、投资者钱包、Signer、密钥控制和托管责任；
- OP Mainnet USDT 的真实支付、合约地址、到账监测、最终性和退款方案；
- Token 合约标准、部署参数、权限、暂停、Mint/Burn 和链上事件核验；
- 募集款持有人、释放条件、结算/划拨及收益/本息真实付款责任；
- 法定持有人登记来源及其与 Token 的法律关系；
- X-01～X-13 风险/准入门仍保持 Open，未经正式决策不得标记关闭。

**Standard 订阅不等于生产准入。** 产品设计 Approved、代码 Implemented、独立验收 Passed、Production Ready 必须分开记录。
