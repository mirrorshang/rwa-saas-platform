# R2 U02-03｜资产分类体系与五步创建向导（已批准）
> 决策日期：2026-11-06｜**R01～R08 全部 Approved（用户逐批明确确认）**｜分支 `docs/r2-current-product-baseline`，PR #8 Draft / Open / Unmerged。本文件为设计权威候选基线，不代表 24 个模板均已制作、可在 MVP 使用或可进行真实链上发行。

## 1. 决策背景与证据边界
- U02-02 已决定「资产与发行」采用 USDable 式资产集中入口。用户进一步批准优先参考 USDable 的**一级/二级分类选择、五步向导与动态子类模板**；同时要求精简 MVP 分类候选总数。
- 用户提供的 USDable 分类页截图明确显示八个一级分类：房地产、金融资产、企业资产、商品、基础设施、自然资源、艺术与收藏、其他资产。该截图的「房地产」二级项为：住宅、写字楼、商铺、酒店、工业园、土地。
- 2026-11-05 USDable 浏览器审计实操过「房地产→写字楼」五步表单；其他七个大类的完整二级列表、专属字段与校验**未逐一实操核实**。本项目以下 24 项是结合 USDable 可见结构及 RWA 产品需要**自主制定并获用户批准的 R2 分类候选**，不能标注为「USDable 原样分类」。
- 2026-11-06 用户确认八大一级、24 个精简二级模板分类；并明确 **房地产不包含在建项目**。不因为一级/二级分类范围已批准就扩展 V1 实际交付范围。

## 2. R01：批准的 8 大一级 / 24 个二级资产分类
| 一级编号与名称 | 二级分类（候选模板） | 数量 |
|---|---|---:|
| 01 房地产 | 住宅；写字楼；商铺；酒店；工业园／仓储物流；土地 | 6 |
| 02 金融资产 | 债券；基金份额；贷款债权；应收账款 | 4 |
| 03 企业资产 | 企业股权；项目公司股权 | 2 |
| 04 商品 | 金属商品；能源商品；农产品 | 3 |
| 05 基础设施 | 新能源设施；数据中心／算力设施；交通设施 | 3 |
| 06 自然资源 | 矿产权益；碳资产 | 2 |
| 07 艺术与收藏 | 艺术品；收藏品 | 2 |
| 08 其他资产 | 知识产权／版权；设备资产 | 2 |
| **合计** | **8 大类、24 个二级分类** | **24** |

### 分类口径与约束
1. 「房地产」不设置**在建项目／期房／开发融资**二级类；土地为独立子类，但不代表未完成权属核验的开发项目可以用土地模板发行。住宅、写字楼、商铺、酒店、工业园／仓储物流均按后续批准的底层资产证明和适用条件处理。
2. 一级/二级分类描述的是**底层 Asset 是什么**；Instrument 定义权利结构（如收益参与、债权或股权），Offering 定义本轮发行参数。不可把同一资产的收益方式直接当成资产类别；避免 Asset / Instrument / Offering 字段重复。
3. 「金融资产」中的基金指**基金份额**，企业资产中的股权指底层股权或股权相关资产；碳资产、矿产权益、知识产权等需在专属模板中区分法律权利和可核验凭证。跨类别对象不能仅凭营销名称改类。
4. 将「工业园／仓储物流」设为一个二级分类，是**MVP 精简**结果；未来如确有必要可细分模板，不默认为两个已经批准的二级分类。
5. **分类目录≠MVP 实际可创建模板清单**。是否在 V1 开放全部 8 大类/24 子类尚未批准。此前 R2 优先实施常见基础闭环、房地产模板先行的原则继续适用；未实现类别不得显示成可创建并最终可发行。
6. 此次不批准任何 Free/Standard 资产数量限制，也不照搬 USDable 的套餐资产名额；分类数量与订阅配额无关。

## 3. R02：批准的创建方式——参考 USDable 五步向导
```text
资产管理 → 创建资产
  第一步 选择分类（一级类别 → 二级子类）
  第二步 基础信息
  第三步 法律与估值
  第四步 专属属性（根据二级分类独立加载）
  第五步 预览提交（检查输入、可回退修订）
保存资产 → 资产详情「资产概览 / 资产资料 / 权益结构 / 发行管理」
```
- 统一**五步框架和顶部步骤进度**，每步显示当前任务及下一步；第四步的字段由对应二级模板决定，不采用一个大而全的万能表单。
- 保留 R2 已确认的**随时保存草稿、恢复编辑、分步骤校验、Draft 与 Ready 区分**；不要求创建草稿时就完成后续真实发行的法律/资金/生产条件。
- Free 和 Standard 使用同一套**正式资产资料**创建流程；Free 可以创建/编辑并保存正式 Asset，但不能发布、上架、募集、Mint 或配置投资者门户；升级 Standard 后需要独立发行准备与生产准入。
- 不因参考 USDable 而批准其中「发行模式属于 Asset 基础字段」「认购协议必须在 Asset 阶段上传」等具体字段归属；字段逐项归属 Asset / Instrument / Offering 及文件版本关系留待字段审核。
- 仅批准**步骤组织方式**；各步骤具体字段、哪些必填、哪些仅在 Ready 时必需、估值口径、文件类别与校验方式、预览摘要、资产状态机和审批机制仍保持待审核。

## 3A. R03～R08：三级字段体系与动态模板规则（已批准）
> 本节是**字段架构、模板继承、呈现和校验机制**的批准，不代表任何具体字段清单、必填性、数值约束或实际开放的模板已获批准；原字段审核缺口仍待下一批。

| 编号 | 已批准规则 | 产品/UI 执行解释 |
|---|---|---|
| **R03** | 资产采用「全平台基础字段 + 一级资产类别公共字段 + 二级资产专属字段」三级结构 | 全平台基础层只放极少数真正适用于全部类别的字段；二、三级不相互覆盖 |
| **R04** | 八大一级分类分别定义其共享字段，不采用统一复杂表单 | 房地产、金融资产、企业资产、商品等可以有不同的权属、估值、存放、主体、计量与法律材料要求；同一级内部也只放该级所有子类真正通用的字段 |
| **R05** | 保持五步向导，第二、三步按一级类别动态加载，第四步按二级模板加载专属字段 | 步骤顺序不变：分类→基础信息→法律与估值→专属属性→预览提交；**字段所属层级不等于所在向导步骤**，例如房地产公共权属字段可显示在第三步 |
| **R06** | 一级、二级模板分别定义必填、校验和展示规则，允许复用通用字段组件 | 相同字段组件可复用，但不能因此强制不同资产类别/子类共用不适用的含义、选项或必填条件；具体规则逐字段审核 |
| **R07** | Asset / Instrument / Offering 字段职责严格分离，避免重复收集 | Asset 描述底层资产与可验证资料；Instrument 记录投资者权利与授权容量；Offering 记录本期发行和认购参数。法律文件按实际约束对象引用并保留版本关系 |
| **R08** | 随时保存草稿、草稿创建校验与 Ready 完整性校验分离 | 创建草稿不要求先完成所有正式发行资料；缺失/无效项有明确定位，后续 Ready 与生产发布检查仍分别实施 |

### 示例仅用于解释规则，**不视为已确认字段**
- 房地产共同候选：国家/地区、产权或使用权基础、位置、权利主体；写字楼子类候选：建筑面积、可出租面积、出租率。
- 酒店子类候选：客房数、运营信息；金融资产另有合同、期限、发行/债务主体等可能字段。
- 上述名称、控件、必填条件、单位、法域适配及所属步骤的详细判定，仍由后续逐字段审核决定，不因本次 R03～R08 同意 A 而自动批准。
