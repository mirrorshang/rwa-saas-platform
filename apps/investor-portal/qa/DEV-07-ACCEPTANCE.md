## 全新依赖安装与运行复现

1. 本机全局 npm 不可用，原全局 pnpm 指向缺失的 Corepack 文件；原型目录的 `node_modules` 是旧 Website 项目的 Junction，不能证明独立安装。
2. 按用户批准，在 D 盘项目工作树内临时下载 npm 官方 registry 的 pnpm 10.34.9 包，并与 registry `dist.integrity` 的 SHA-512 值核对一致；未修改全局 PATH 或现有 Issuer/Website 依赖。
3. 在**无 node_modules** 的独立副本生成 `pnpm-lock.yaml`；执行 `pnpm install --frozen-lockfile --ignore-scripts`，独立下载 21 包；`pnpm run typecheck` PASS、`pnpm test` 27/27 PASS、`pnpm build` PASS（Vite 6.4.6，48 modules）；5184 端口启动后真实浏览器点击首页→投资机会，Console Error 0。
4. 再从仓库最终 package.json/锁文件/源码建立第二个**无 node_modules** 的副本，执行标准 `pnpm install --frozen-lockfile`，PASS；再次执行类型检查 PASS、27/27 测试 PASS、生产构建 PASS。pnpm 默认提示 esbuild 安装脚本未获准运行，但本机实际构建正常。
5. 首次尝试将第二次安装强制为离线时，独立缓存缺少 scheduler tarball，明确失败；随后按标准在线冻结安装成功。此离线尝试不影响已完成的全新在线安装复现，不宣称离线复现通过。
