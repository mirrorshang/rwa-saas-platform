## 0. 最新优先级和产品边界
- [U02-05 单页面与自动 Token 拆分最新修订](U02-05-INSTRUMENT-SINGLE-PAGE-AUTO-SPLIT-APPROVED-2026-11-07.md) > 旧 U02-05 四步向导；[U02-05 R01～R06](U02-05-INSTRUMENT-FOUNDATION-APPROVED-2026-11-06.md) 与 [R07～R12](U02-05-INSTRUMENT-FIELD-GROUPS-APPROVED-2026-11-06.md) 的其余不冲突规则继续有效。
- **MVP：一个 Asset 最多一套当前有效 Instrument**；三种权益类型（三选一）；一个 Instrument 可以供多个 Offering 分期引用，所有期共享同一个真实可用权益额度。不提供复杂多 Instrument/优先劣后分层，延后 V2.0。
- **Instrument 仅三个分区**：权益定义、Token 拆分、法律文件；不在 Instrument 中填募集目标、Token 认购单价、募集期限、付款网络，此类参数留给 Offering。
- 当前批准仅代表三类权益的**产品设计**，不等于三类已经具备实际法律发行/合约部署/Mint/资金执行许可。

## 1. R13｜公共基础字段（Approved）
| 字段 | 数据来源/UI | 草稿/Ready 规则 |
|---|---|---|
| 关联资产 | 从当前 Asset 自动继承，仅展示/只读 | 系统关联，不允许切换到第二 Asset |
| 权益类型 | 股权 / 债权 / 收益参与，单选；选择后即时切换类型专属字段 | 草稿需选类型；后续变更受版本/引用守卫 |
| 权益结构名称 | 默认以「资产名称 + 权益类型」自动生成，可修改 | 草稿需有名称；具体最大字符与去重规则尚未独立批准 |
| 权利责任主体 | 文本/主体信息 | **Ready 必填**；不得默认声称等于资产持有人、发行 Tenant 或已通过法律审核 |
| 投资者获得的权利 | 权利说明文本 | **Ready 必填**，应写清权利类型与范围，不自动赋予资产所有权 |
- **草稿最低条件：选定权益类型、填写/接受生成的名称**；草稿保存不因尚缺其他 Ready 必需字段而阻塞。所有字段最终格式校验及详细主体结构仍须按技术实现安全约束补齐，但不能引入未经批准的新业务必填门。

## 2. R14｜股权型（Approved）
| 字段 | 推荐已批准界限 |
|---|---|
| 对应法律实体 | Ready 必填；明确股票对应的法律主体 |
| 股份类别 | MVP **仅普通股**；不配置优先级、复杂类别、可转换权利 |
| 纳入权益结构的普通股数量 | 在 **Token 拆分**区填写一次，不在权益定义区重复输入；正整数 |
| 股东/持有人权利说明 | Ready 必填，解释所提供的权利和 Token 的法律/合同映射 |
- 不默认支持「Token 分数份额即直接登记分数股份」。股份最小合法登记单位、名册/股权合法归属、法域适配及特殊凭证细节仍属于法律与技术审查门。
- 一个 Token 对应多少股**由系统从总股数/Token 总份数计算**，不让用户重复手填映射率。

## 3. R15｜债权型（Approved）
| 字段 | 推荐已批准界限 |
|---|---|
| 债务主体 | Ready 必填；与责任主体不同可分别说明关系，不凭字段推断法定责任 |
| 债权本金总额 U | 在 Token 拆分区填写一次，正值；**不是募集金额** |
| 利息方式 | 无息 / 固定利率；Ready 必填 |
| 固定年利率及起息日期 | **仅固定利率时 Ready 必填**；无息时不强制补伪利率 |
| 到期日期 | Ready 必填 |
| 还款方式 | MVP 先做简单**到期一次还本**及适用利息约定；复杂分期、浮动利率、提前赎回及违约机制不在本批内扩展 |
- **每 Token 对应名义本金**由系统计算；不能被当作 Offering 的 Token 认购售价或对投资者自动担保的支付承诺。
- 起息/到期合法顺序、率值格式、合同履约例外和生产息额计算的精度仍由后续专业规则审查。

## 4. R16｜收益参与型（Approved）
| 字段 | 推荐已批准界限 |
|---|---|
| 收益来源 | Ready 必填；例如约定房产的租金收入 |
| 收益计算口径 | Ready 必填，说明收入及适用费用扣除范围；不可仅填「收益」两字默认净收益已定义 |
| 授权参与比例 | 在 Token 拆分区填写一次；**大于 0%、不超过 100%** |
| 权益期限 | Ready 必填；适用起止或明确期限文本（期限字段展现形式后续 UI 细化） |
| 分配频率 | 月度 / 季度 / 年度，Ready 必填 |
- 不强制填预计收益率、预计年化、保本金额；Token 不自动代表底层资产产权或确定收益。
- 收益范围/计算口径/适用期间须与权益协议一致，且法律充分性仍需外部合规核验。

## 5. R17｜Token 总份数与自动映射（Approved）
1. 用户输入两项：**纳入本权益结构的权利总规模**（股权普通股数 / 债权本金 U / 收益参与比例 %）和 **计划拆分的 Token 总份数**（正整数）。系统自动推算「每份 Token 对应什么权利」；Token 最大可发行数以拆分份数为基础，但仍受授权合法性与技术准入守卫。
2. 映射计算结构：`每份权益 = 总权益规模 ÷ Token 拆分份数`，需带单位显示（股、U 名义本金、合同收益参与比例）；**遇不可按适用最小单位精确拆分时提示调整总量/份数并阻断 Ready，不得静默取整**。
3. **股权**不得未经法律/名册和技术许可将不能精确登记的分数股当作已成立合法股份权利；其余类型需校验相应允许精度。
4. 首次无发行历史时页面仅显示「拆分总份数 / 每份权益」；已有 Offering 和实际发行事件时，在详情页显示「最多可发行、已发行（已确认占用）、已预留（有效预留）、剩余可发行」。
5. 多期 Offering 共用同一个容量池：同一次有效占用不重复计入预留和已发行；Draft Offering 不占有效预留；已生效权益不因 Offering 结束/历史版本更新而自动释放。**已关联有效发行后不得直接原位修改总权益规模或拆分份数以覆盖历史**。
6. **尚未批准**的具体参数：Token 链上 decimals、可分割最小量、业务小数精度/舍入、Token 合约标准、跨链与 Provider/Signer、并发事件原子性与资金真实执行。不能凭这个 Approved 直接把任何三类送入生产发行。

## 6. R18｜法律文件、状态与资料检查（Approved）
- 每种权益类型在法律文件区首先呈现**一项对应的核心权益文件**：
  - 股权：**股权权益协议或适用权利证明**；
  - 债权：**债权协议或债权形成证明**；
  - 收益参与：**收益参与协议**。
- **固定必需文件行紧跟上传入口与状态**；继续支持「引用当前 Asset 的既有文件（固定 FileId + VersionId）」与「添加其他文件（选填）」。不因本批决定任何法域只需要这唯一一份文件；其他法定/适用条件资料另由 Offering/独立准入门核验。
- 文件必须处于**通过安全扫描、权限允许及可引用**的状态才能满足资料完整性；上传成功≠已安全可用，更不等于文件已签署有效或合法权利已经成立；替换文件不得静默更新历史 Instrument/Offering 的引用版本。
- **三个用户可见状态/反馈**：草稿（可以继续编辑/保存）、资料待补充（检查失败时在单页定位缺项）、资料已完备（完成资料检查后返回资产详情「权益结构」TAB，主 CTA 引导「发行管理 → 创建 Offering」）。
- Instrument 已被 Offering 引用后：保留确认时版本，禁止把已生效权益关键条款、总规模、Token 拆分数及合法权利说明原地覆盖；后续合法修订的具体状态/行为仍需核定。
- 单页不使用「第 1/2/3/4 步」或独立最后预览步骤；页底「保存草稿」「完成资料检查」；完整性检查不等于生产准入。
