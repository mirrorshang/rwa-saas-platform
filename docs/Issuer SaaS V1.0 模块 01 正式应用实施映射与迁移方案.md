## 3. 模块 01 对象与页面实施映射

1. 以正式 `AppState` 为唯一前端 Mock 对象来源；新增内部 `Project` 集合，不建立第二套 Offering 存储。Project 绑定一组 Asset ID 与 Instrument ID/版本，一组可有多轮 Offering；首次保存 Offering 草稿时自动创建或复用匹配容器。当前企业无需项目创建页。
2. 保留全部正式 Asset、Instrument、Offering 既有 ID、名称、轮次、金额、文件和下游引用。给 Offering 补充 `projectId`、确认时的 Asset/Instrument 版本、条款与文件引用快照、修订号；新字段兼容旧草稿。Asset 当前无版本、BusinessFile 当前无版本，需明确记录旧值为迁移基线版，后续修改生成新版本，不能伪称历史版本已经存在。
3. ID/轮次由统一分配函数从所有现存对象和保留号扫描后产生；不再用数组长度或时间戳截断生成。不同 Project 的轮次可同号，同一 Project 内不可重复；重复提交草稿保存/确认不得新建对象或再次预留容量。
4. 确认事务必须在**最新状态**中复核 KYB、Mock Standard、Asset Ready、Instrument Ready、同资产关联、钱包、披露文件、价格/日期/容量，并同时写入确认快照和唯一容量预留。`confirmed`、Offering 状态、Instrument 已用容量要同进同退；重复点击只返回已有结果。确认前草稿可编辑，确认后不可静默修改被引用资料。
5. `/assets/:id` 显示精确关联权益和 Offering；发行列表、详情共用同一个 Offering。详情显示“当前状态／未完成事项／下一步”；确认后出现“进入发行准备”，用 Offering ID 打开独立准备资料视图，读取同一 Asset、Instrument、Project、Offering 和文件引用。模块 01 只接通路由与资料展示，不在该页伪造七组 PASS、发行任务、发布或链上结果。
6. Offering 确认状态、发行任务、销售、Contract、Token 分开保存。保留现有状态含义；不新增 `Pending Issuance`。确认成功只代表内部方案确认和容量预留，不代表正式发行或认购开放。

## 4. 安全迁移方案（先验证，后写入）

当前 `src/App.tsx` 的 `loadPersistedState` 在解析/装载异常时会删除 `rwa-issuer-state-v3`，随后首屏 effect 将空状态写回同一键；缺失集合又会被静默替换为空数组。这是**已有草稿和引用可能丢失的重大风险**。在修复前，不在可能已有正式演示数据的浏览器同源打开新版应用，也不执行案例导入/重置。

建议的模块 01 迁移步骤：

1. 将旧键 `rwa-issuer-state-v3` 作为只读源；引入带 `schemaVersion` 的新命名空间。加载时先解析、逐集合校验类型、ID 唯一性与 Asset→Instrument→Offering→下游引用，生成迁移盘点。解析失败时保留原字节并阻断业务写入，提供可核验的错误；不得清除或自动覆盖旧键。
2. 对无冲突的正式应用旧 Offering 按 `(assetId, instrumentId, instrument.version)` 建立或复用 Project；同一 Offering ID 只迁一次。对于重复 ID、跨资产引用、缺失上游、轮次冲突、`used` 与已确认 Offering 总预留不一致，记录隔离清单并停止自动确认/容量变更，不猜测合并。
3. 已确认 Offering 只补 Project 关联，不再加一次 `used`；缺失历史快照时显示“旧版已确认记录缺少历史确认快照”，不得凭当前资料伪造过去的确认事实。旧草稿维持草稿。文件记录按现有 ID、名称和状态保留；没有版本号的旧文件标记“旧记录未版本化”。现有订单、持有人、收益引用仍指向原正式 Offering ID。
4. 完成对象数、引用、容量和版本核对后，才将迁移结果写入新命名空间；写入失败保持旧键可读。重复装载应得到相同 Project 关联与对象数。旧键保留作回退证据，未经单独授权不删除。
5. 原型 `OF-0001/OF-0002` 只取业务参数重建新正式案例，不读 `wdex-*` 存储，不复制原型 Mock 或 localStorage；如正式应用已存在同名/同号案例，先做冲突报告，不覆盖。

此方案是前端 Mock 迁移，不能声称具备生产数据库事务、租户隔离或后端权威状态。正式后端接入时需按 `docs/V1.0/V1.0-BACKEND-DEVELOPER-PRD.md` 的 ID、版本、幂等与审计契约另行实现。

## 6. 实施顺序、验证与暂停点

1. 数据安全修正及迁移测试：坏 JSON/缺失集合不删原键；重复迁移、重复 ID、缺失引用、容量不一致、已有订单引用均有明确结果。
