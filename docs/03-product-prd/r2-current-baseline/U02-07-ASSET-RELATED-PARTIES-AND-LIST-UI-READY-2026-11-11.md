# RWA SaaS V1｜资产管理补充 UI-Ready 设计：资产列表、相关方与房地产模板控件

> **设计日期：2026-11-11**  
> **状态：V1 详细设计基线（依据用户授权，由产品负责人完成字段/页面精简；不改变已批准业务范围）**  
> **适用范围：Issuer 企业 SaaS｜资产与发行 → 资产管理**  
> **维护分支：docs/r2-current-product-baseline｜PR #8 Draft / Open / Unmerged**

## 0. 依据与边界

本文件补齐资产管理中尚未形成统一 UI-Ready 的页面与字段细节，承接以下已批准规则：

- U02-02：资产管理、认购记录、锁仓记录三个二级入口；资产详情四 TAB（资产概览、资产资料、权益结构、发行管理）；不为权益结构、Project、Offering、发行准备另设二级导航。
- U02-03：8 大一级/24 个二级资产分类目录；五步创建向导；资产公共字段、房地产公共字段、必需文件行、Draft/Ready 区分。
- U02-04：房地产六子类字段及首批四模板开放范围；R28～R33 的创建、草稿、校验、文件和详情交互。
- U02-04 文件收口：发行企业与登记权利人不同的授权/委托证明按实际关系处理；Asset 文件可供 Instrument/Offering 固定版本引用。
- DEC-058：资产相关方属于 V1 既有 M04 能力；SPV、托管方、受托方等按真实结构条件化记录，不要求所有资产都具备。
- DEC-069：不改变 Issuer 九个一级导航，不新增投资者资格配置；本文件不涉及投资者 KYC 页面。

**本文件不改变：** 资产对象、Instrument/Offering 对象边界；四个资产详情 TAB；五步资产创建；房地产四个首批可创建模板；Free/Standard 权益；不新增正式功能 ID。

**本文件不授权：** 真实产权核验、法律意见、牌照核验、外部文件扫描服务、Provider/Signer、合约部署、Mint、支付或生产发行。

## 1. 最终页面结构与导航

### 1.1 导航保持

```text
资产与发行
├─ 资产管理
├─ 认购记录
└─ 锁仓记录

资产管理 → 选择资产 → 资产详情
├─ 资产概览
├─ 资产资料
├─ 权益结构
└─ 发行管理
```

- 资产相关方是「资产资料」内部的一个信息分组，不新增二级导航或第五个 TAB。
- 资产创建向导第三步「法律与估值」承载登记权利人及其他相关方信息。
- Asset 详情「资产资料」复用同一字段和卡片结构，允许查看/编辑，不建立第二套相关方数据。
- 资产相关方不是收款方名录，也不是 Instrument/Offering 的全部责任主体清单。

### 1.2 资产管理列表（UI-Ready）

**页面目的：** 快速找到资产、判断资料是否完备、识别其权益/发行进度，并进入唯一正确的下一步。资产列表不是收益或募集运营看板。

| 区域 | 内容 | 交互与规则 |
|---|---|---|
| 页面头部 | 标题「资产管理」；说明「管理企业底层资产资料、权益结构与发行方案」 | 主按钮「创建资产」；无权限时显示原因和可用下一步 |
| 搜索 | 资产名称、资产编号 | 输入后筛选；清空恢复 |
| 筛选 | 资产分类/子类、资产资料状态（草稿/资料已完备） | MVP 不提供复杂组合筛选 |
| 列表 | 资产名称及编号、资产类别、所在地区、资料状态、发行情况、最近更新、操作 | 默认按最近更新倒序 |
| 发行情况 | 无 Offering 显示「尚未创建」；有多期时显示期数及最近一期状态 | 不显示模拟认购量、模拟募集金额、虚构 Token 数 |
| 操作 | Draft「继续完善」；Ready「查看详情」 | 不把资产列表行操作混为「发布资产」 |

**空状态：**

- 标题：「还没有资产」
- 说明：「先登记底层资产资料，再配置权益结构和发行方案。」
- 操作：「创建第一项资产」
- 不展示示例资产、模拟募集额或虚构发行状态。

**列表状态规则：**

- Asset 只使用已批准的 Draft / Ready 资料状态；不增加「已审核」「已发行」等混淆 Asset 与 Offering 的状态。
- 权益结构、Offering 状态作为关联对象摘要展示，不覆盖 Asset 自身状态。
- Free 与有效 Standard 均可创建/编辑正式资产资料；Standard 降级后的历史业务按 U01 规则只读，不因套餐名称显示 Free 而重新开放写操作。
- 不新增资产数量硬配额、批量编辑或批量删除入口。

## 2. 资产详情：四 TAB 的职责与唯一下一步

### 2.1 详情头部

固定展示：资产名称、资产编号、一级/二级分类、所在地区、Asset 资料状态、最近更新时间。

头部不显示未经核验的「资产价值」「已募金额」「投资者人数」等汇总数据。只有存在可信业务事实时，才在对应 TAB 显示。

### 2.2 资产概览

按以下顺序展示：

1. **资产摘要**：名称、分类、地区、资产简介、封面（如有）。
2. **资料完整性**：Draft/Ready；如 Draft，显示缺项数量和「继续完善资产资料」。
3. **权益结构**：未创建 / Draft / Ready；显示类型、当前确定版本及 Token 拆分摘要（存在时）。
4. **发行方案**：尚未创建 / 草稿 / 已发布 / 认购中 / 暂停 / 已结束等真实状态；多期时显示列表入口。
5. **唯一下一步主动作**：由当前业务事实决定，不并列出现多个竞争性主按钮。

| 当前真实状态 | 唯一主动作 |
|---|---|
| Asset Draft | 继续完善资产资料 |
| Asset Ready，尚无 Instrument | 创建权益结构 |
| Instrument Draft | 继续完善权益结构 |
| Instrument Ready，尚无 Offering | 创建发行方案 |
| 存在 Offering Draft | 继续完善发行方案 |
| 已有有效 Offering | 查看发行进度 |

如果同时存在多个历史 Offering，概览优先显示最新一期及「查看全部发行方案」入口；不把历史已结束 Offering 当作当前待办。

### 2.3 资产资料

按信息分组呈现，不增加新 TAB：

- 基础信息与展示媒体；
- 位置与使用情况；
- 权属信息与登记权利人；
- 资产相关方；
- 估值信息；
- 文件与证明材料；
- 当前房地产子类专属属性。

每个分组显示摘要、编辑入口和必要的资料状态。用户进入编辑后仍使用既有字段，不另建第二套表单。

### 2.4 权益结构 / 发行管理

本文件不重复定义两者字段。权益结构遵循现行 U02-05 单页三区域和一资产一套当前有效 Instrument；发行管理遵循 U02-06 Offering 单页及 Ready 前置门。相关补充规则在对应后续收口文件中更新。

## 3. 资产相关方：角色与业务边界

### 3.1 角色目录

| 角色 | 适用情境 | V1 处理 |
|---|---|---|
| **登记权利人** | Asset 当前登记或法律权利文件所载明的主体 | 必填；沿用 R18，作为主权属主体，不得由 Issuer 自动替代 |
| **资产持有主体 / SPV** | 由独立公司或 SPV 持有/控制资产时 | 条件添加；若与登记权利人是同一主体，复用同一主体卡片并增加角色标签 |
| **托管方** | 资产存在独立实物保管、托管安排时 | 条件添加；不代表资金托管方 |
| **受托方 / Trustee** | 资产或相关权利确有信托/受托安排时 | 条件添加；需说明受托职责 |
| **资产管理方** | 有独立主体负责资产管理时 | 条件添加；替代原来仅填写名称的松散文本 |
| **资产运营方** | 有独立主体负责租赁、物业、设施或日常运营时 | 条件添加；可与资产管理方为同一主体 |
| **估值机构** | R19 选择「第三方评估」作为估值依据时 | 条件必填；与 R19「评估机构」共用同一主体记录，不重复录入 |
| **其他相关方** | 对资产权利、管理、运营或专业服务有实际影响的其他主体 | 选填；必须说明具体职责，不用于登记债务人、担保人、付款义务方或 Token Signer |

登记权利人由 R18 主权属区单独维护；如该主体同时是 SPV/资产持有主体，在主权属主体记录上增加对应角色关联，不再创建第二张卡片。其他相关方卡片的角色选择不包含「登记权利人」。

**主体复用规则：**

- 同一主体在同一资产中承担多个角色时，只维护一张主体卡片，可勾选多个角色，避免重复录入。
- SPV 与登记权利人为同一主体时，使用「与登记权利人相同」关联，不生成重复主体。
- 不建设跨资产的全局主体名录、受益所有权穿透图谱或多层信托关系引擎；不同 Asset 可分别录入必要主体资料。
- Issuer 企业本身由当前 Tenant 自动关联，不作为用户重复新增的资产相关方。
- Instrument/Offering 的发行人、债务人、担保人、付款义务方、法定签署人、收款钱包和 Token Signer，分别在其所属对象和责任主体流程管理，不放入 Asset 相关方。

### 3.2 主体卡片字段

**核心信息（展开即见）：**

| 字段 | 控件 | 必填/校验 |
|---|---|---|
| 相关方角色 | 多选标签 | 至少选择一个角色；仅可选资产持有主体/SPV、托管方、受托方、资产管理方、资产运营方、估值机构、其他相关方；登记权利人作为 R18 主权属主体单独维护，不重复添加为普通相关方卡片 |
| 主体名称 | 单行文本 | 必填；去首尾空格，最大 160 字符 |
| 主体类型 | 单选：企业、自然人、政府/公共机构、其他 | 必填 |
| 注册国家/地区 | 搜索选择 | 企业、政府/公共机构必填；自然人选填 |
| 注册编号 | 单行文本 | 选填；无统一编号时不强制，不收集完整个人身份证件号码 |
| 与发行企业的关系 | 单选：同一主体、关联主体、受托/授权、独立第三方、其他 | 必填；「其他」须补充说明 |
| 职责说明 | 多行文本 | 必填；说明该主体在本资产中的实际职责，最大 500 字符 |
| 关系/职责补充说明 | 多行文本 | 选填；「其他」角色或关系时条件必填 |

**更多信息（默认折叠，按需填写）：**

| 字段 | 控件 | 规则 |
|---|---|---|
| 许可/资质名称及类别 | 文本 | 选填；仅适用角色/法域需要时填写 |
| 许可/资质编号 | 文本 | 填写许可信息时条件必填 |
| 发证/监管机构 | 文本 | 填写许可信息时条件必填 |
| 许可有效期 | 起止日期 | 许可有有效期时填写；结束日期不得早于开始日期 |
| 官方网站 | URL | 选填；格式校验 |
| 联系人 | 单行文本 | 选填 |
| 联系邮箱 | 邮箱 | 选填；填写时格式校验 |
| 联系电话 | 电话 | 选填；按国际号码格式保存，输入时允许常见分隔符 |
| 委任/合作有效期 | 起止日期 | 选填；结束日期不得早于开始日期 |
| 备注 | 多行文本 | 选填 |

- 联系人、邮箱、电话只用于 Issuer 企业内部管理，绝不默认进入投资者端披露。
- 不要求填写个人身份证号、护照号、人脸或生物识别信息。
- 角色卡片已存在时，角色、主体名称和职责说明不可留空；非适用角色不生成空白必填卡片。
- 许可信息由企业填报，平台不据此宣称牌照真实、有效或足以开展受监管活动。

### 3.3 登记权利人与其他相关方的关系

登记权利人继续使用 R18 已批准字段：

- 登记权利人名称：必填；
- 权利性质：所有权、土地使用权、租赁/经营权、其他；
- 与发行企业的关系：同一主体、关联主体、受托/授权、其他；
- 非「同一主体」时，关系说明条件必填；
- 资产运营/管理主体：由本文件结构化相关方卡片承接，不再要求用户在独立文本字段重复填写。

当登记权利人与发行企业不同：
- 不自动认定发行企业已获得合法发行授权；
- 继续支持「授权/委托/主体关系证明」文件类别；
- 不把同一种授权书设为所有资产 Asset Ready 的固定必需文件；
- 如对应发行结构/法域要求授权凭证，应在 Offering 适用发行前检查中列为阻断项；不能因用户选择「受托/授权」就自动通过。

### 3.4 估值机构复用

- R19 估值依据选择「第三方评估」时，必须填写评估机构名称。
- 评估机构以相关方卡片形式维护，角色固定包含「估值机构」，职责默认提示「提供本资产的第三方估值服务」，用户可补充。
- R19 与相关方卡片双向引用同一主体记录；不出现两份不同的「评估机构名称」字段。
- 选择「近期成交价」或「其他可核验依据」时，不强制创建估值机构卡片。

## 4. 相关方文件、Ready 和编辑保护

### 4.1 文件处理

- 资产权属证明、资产估值依据文件、条件性抵押/权利限制证明继续使用 U02-03 固定文件行。
- 相关方卡片可按实际关系关联委任书、授权/委托书、托管/受托协议、管理/运营协议、许可资质证明等。
- 相关方附件默认属于**按需添加的关联文件**，不新增所有角色通用必传文件。
- 文件选择/上传遵循 M06：显示文件名、类型、版本、上传时间、扫描/可引用状态；引用固定 `file_id` + `version_id`；失败/扫描中/无权限不能标为可引用。
- 已被 Instrument/Offering 引用的旧文件版本不得静默替换；需要新增版本并保留历史引用。
- 发行企业与登记权利人不同的授权/委托证明是否为当前 Offering 的生产阻断项，按具体关系及适用规则检查，不由 Asset Ready 自动推断。

### 4.2 Asset Ready 校验

**必需项：**
- R18 登记权利人名称、权利性质、与发行企业关系；
- 非「同一主体」时的关系说明；
- 当前适用的资产权属证明、估值依据文件及条件性权利限制证明；
- R19 估值字段及条件字段；
- 选择第三方评估时，估值机构主体名称和角色记录。

**有填写才校验的相关方项：**
- 每张相关方卡片至少有角色、主体名称、主体类型、职责说明、与发行企业关系；
- 企业/公共机构主体填写注册国家/地区；
- 选择「其他」角色/关系时补充说明；
- 已填写许可/资质信息时，相关编号、发证机构和适用有效期应完整；
- 已添加的文件若被作为适用必需证明引用，则必须可引用；仅作为补充资料的选填附件不额外阻断 Ready。

**不作为 Ready 阻断条件：**
- 不存在 SPV、托管方、受托方、资产管理方或运营方；
- 不存在独立估值机构（估值依据并非第三方评估）；
- 未填写联系人、电话、邮箱、网站、许可信息或合作期限；
- 未上传不适用的角色附件。

Asset Ready 只表示产品定义的资料完整性检查通过，不代表产权真实、主体适格、牌照有效、授权合法或法律意见通过。

### 4.3 编辑、移除与历史引用

- Draft：可新增、编辑、移除相关方卡片；移除前仅在卡片已关联文件时提示确认，不删除文件实体。
- Ready 且未被 Offering 引用：可编辑相关方并重新执行资料检查；修改后相关字段的 Ready 结果需重新计算。
- 已被已发布 Offering 用于投资者披露：修改 Asset 当前主体资料不回写已发布 Offering 的披露快照；后续新 Offering 读取当前资料。
- 被历史 Offering 快照引用的相关方记录，不物理删除历史快照；当前资产如不再使用该主体，可从当前资料中移除，历史 Offering 仍保留当期披露内容。
- 已创建但未发布的 Offering，在最终发布预览前读取当前 Asset 资料；最终确认时固化该期披露快照。
- 不增加复杂的资产相关方审批状态机；资料变更留必要操作记录，法律/许可审查不由此 UI 自动完成。

## 5. 投资者端披露位置与隐私边界

**披露发生在 Offering 级，而不是 Asset 全局自动公开。** 同一资产的不同期 Offering 可以按各自披露材料选择相关方。

- Issuer 在 Offering「发行准备」中的「投资者披露 → 资产相关方」选择本期需要对投资者展示的主体。
- 该选择在 Offering 最终投资者端预览中呈现；最终确认后写入该期 Offering 的披露快照。
- 默认不自动公开全部相关方。页面提示发行企业确认适用法域和本期发行文件要求的披露义务；平台不替企业判断法律上哪些主体必须披露。
- 投资者端允许展示：主体名称、相关方角色、简要职责说明、注册国家/地区（如有且选择披露）。
- 投资者端不得展示：注册编号、个人身份资料、联系人、电话、邮箱、许可编号、内部备注、未选择披露的角色、原始附件或第三方核验材料。
- 若没有选择任何相关方披露，投资者端不显示空白模块；Issuer 最终预览显示提示「当前未选择资产相关方披露，请确认本期发行是否存在适用披露要求」。
- Offering 发布后，披露快照不随 Asset 资料编辑自动改变；需要变更已发布披露时，走该 Offering 受控变更/通知规则，不直接覆盖历史快照。

## 6. 房地产四个已开放模板：控件、单位与交叉校验

本节只细化首批开放的住宅、写字楼、商铺、工业园/仓储物流；酒店、土地继续保持「暂未开放」，不显示为可创建模板。

### 6.1 面积单位与数值统一

- 面积字段统一提供 **平方米（m²）/平方英尺（ft²）** 两种单位；用户在资产第④步首次录入面积时选择一次，该 Asset 的所有面积字段共用同一单位。
- 所有面积输入允许正数，最多 2 位小数；不允许 0、负数、非数字、NaN/Infinity。
- 更换单位时展示换算预览并要求确认；按固定换算关系转换当前 Asset 全部面积值，保留内部足够精度，页面显示两位小数。不得只改变单位标签而不转换数值。
- 可出租面积必须小于或等于对应建筑面积；比较前统一换算到同一标准单位。
- 数值输入失焦后可加千分位展示；编辑时保持可直接输入的数字格式。

### 6.2 百分比与数量

- 出租率/入住率：0%～100%，最多 2 位小数；空值允许，不自动推算。
- 住宅套数、客房数量：正整数；仅在对应模板条件触发时显示/必填。
- 所有错误在对应字段下方显示，不使用整页笼统报错；不静默截断或四舍五入改变用户输入。

### 6.3 四模板字段与校验

| 模板 | Ready 必填 | 选填/条件字段 | 主要交叉校验 |
|---|---|---|---|
| **住宅** | 住宅形态：单套/整栋/住宅社区；建筑面积 | 住宅套数：整栋/住宅社区或实际包含多套时必填 | 套数为正整数；单套住宅不强制重复填写「1」 |
| **写字楼** | 建筑面积 | 可出租面积、出租率 | 可出租面积 ≤ 建筑面积；出租率 0～100% |
| **商铺** | 商铺形态：临街商铺/商场铺位/商业综合体；建筑面积 | 可出租面积 | 可出租面积 ≤ 建筑面积 |
| **工业园/仓储物流** | 物业形态：工业园/仓库/物流设施；建筑面积 | 可出租面积 | 可出租面积 ≤ 建筑面积 |

- 资产用途由所选子类带入，不再重复选择。
- 当前使用情况沿用 R17：自用、出租、混合使用、闲置、其他；选择「其他」时说明条件必填。仅展示当前模板适用选项，不将「在建项目」作为选项。
- 不新增建成年份、主要租户、酒店等级、仓储容量、经营类别等 MVP 结构化必填字段。
- 酒店和土地即使保留分类及字段候选，也不得开放创建入口，不能通过修改 URL/深链绕过。

## 7. 状态、套餐和异常交互

| 场景 | 页面反馈/操作 | 业务保护 |
|---|---|---|
| 无资产 | 「还没有资产」+「创建第一项资产」 | 不显示模拟资产 |
| Asset Draft | 「资料草稿」+「继续完善」 | 允许补资料；不宣称 Ready |
| Asset Ready | 「资料已完备」+「配置权益结构」 | 不代表法律/发行准入 |
| 相关方未添加 | 显示「暂无其他相关方；如无独立持有、托管、受托、管理或运营主体，可保持为空」 | 非适用角色不阻断 Ready |
| 相关方卡片缺字段 | 定位到角色、主体名称、主体类型、关系或职责说明 | 已存在卡片不能以空白资料通过 Ready |
| 同一主体重复添加 | 提示「该主体可能已存在，可为现有主体增加角色」 | 允许用户确认是否合并角色，不静默丢资料 |
| 文件上传失败/待扫描 | 在对应文件行显示原因及重试 | 不误报可引用/Ready |
| 相关方资料变更 | 提示对当前资产和未来 Offering 的影响 | 不回写已发布 Offering 快照 |
| Free | 正式资产资料可创建/编辑/Ready | 不允许真实发布、上架、认购、Mint |
| Standard 降级历史只读 | 显示「当前为历史业务只读状态」 | 不开放新建/编辑写操作 |
