## 2. 资产列表/第一步：分类选择（R28）
### 2.1 入口与空状态
- 主入口：**资产与发行 → 资产管理 → 创建资产**；在企业首页符合权限时可提供「创建第一项资产」快捷入口，但**不新增独立「权益结构」或「项目管理」侧边导航**。
- 列表的空状态应显示「暂无资产」「创建资产」「先登记底层资产资料，再配置权益结构与发行方案」；有历史资产时显示资产名称、子类、当前资料状态、更新时间和「查看/继续完善」操作，禁止为尚未开展的发行填入伪造指标。
- 没有业务编辑资格（KYB 未完成、受限订阅、降级历史只读等）要给出原因、允许的查看范围及合法可用的下一步，不以空白页代替权限反馈。

### 2.2 分类选择
- 先显示 8 个一级类别；点击一级可查看对应 24 分类体系内的二级项和开放状态。
- **仅房地产 → 住宅、写字楼、商铺、工业园／仓储物流四项可进入第②步新建**。房地产 → 酒店、土地显示「暂未开放」且不允许进入新建；其余七大类的二级项均显示「暂未开放」而不可创建。
- 分类界面不标注「升级 Standard 即可解锁暂未实现的资产模板」；这是**产品交付范围**限制而非 Free/Standard 权益限制。Free/Standard 使用相同已开放模板。
- 已选择可用类别才激活「下一步」；提示「选择资产类别和子类后继续」。MVP 明确不包含房地产在建项目。
- 页面可解释未开放的类别将来扩展；但不得承诺具体推出日期、价格/套餐或真实发行条件。

## 3. 第二～五步：向导布局、按钮与草稿（R29）
### 3.1 五步始终显示
| 步骤 | 页面主体 | 底部固定操作 | 推荐页面辅助内容 |
|---|---|---|---|
| ① 选择分类 | 一级/二级、开放状态 | 返回资产管理；下一步（有效选中时） | 标明哪些为 MVP 已开放 |
| ② 基础信息 | R15～R17、R16 展示信息 | 上一步；**保存草稿**；下一步 | 字段说明、草稿/Ready 标记、必要格式提示 |
| ③ 法律与估值 | R18～R19、固定文件清单 | 上一步；**保存草稿**；下一步 | 文件是否待上传/扫描/可引用 |
| ④ 专属属性 | 当前 R21/R22/R23/R25 已批准精简字段 | 上一步；**保存草稿**；下一步 | 不出现其他子类字段，不重复公共项 |
| ⑤ 预览提交 | 资产摘要、缺失/失败项目、文件状态、下一步 | 上一步；**保存草稿**；**完成资料检查** | 明确「这不是投资者端最终发布预览」 |

- 步骤进度包含「当前步骤 / 5」、已访问可返回步骤；**进度条不是五个资料 Ready 状态**。跳步/返回时不丢失已填内容。
- **草稿最低条件**：房地产一级 + 可创建二级 + 资产名称非空且最大 120 字符；唯一资产编号和所属企业关联由系统处理。首次进入第②步但尚无名称时，点「保存草稿」提示去填写名称，不生成不完整记录。
- 有效输入可以前后步切换；当某些 Ready 字段尚未填写时可仍作为 Draft 保存，不因缺失权属文件/估值强迫返回。已填写的不合法数值/日期必须明确报错，不得假装有效保存。
- 保存成功显示明确反馈，数据包含当前已保存步骤与字段；再次从资产管理打开草稿回到此前位置，已有文件引用及可用数据仍在。
- 有未保存变更时尝试关闭/刷新/导航离开，应出现离开确认（按浏览器可支持机制），取消保留编辑，确认后**不错误宣称未保存内容已保存**；保存在服务端/本地演示存储的机制须以真实项目实现审计为准。
- 提交中避免重复保存/双击重复创建；成功/失败必须区分；失败显示可重试且原输入保留。不宣称已做服务器持久化或正式授权隔离，直到测试验证。

## 4. 草稿修改二级分类及保护历史（R30）
### 4.1 Draft 改二级子类
1. 从第②～⑤步返回第①步，用户在房地产内部改选另一**已开放**子类。
2. 若无原专属字段值，可直接切换；**通用 Asset 字段与房地产公共字段保持不变**。
3. 若原子类已有专属值，切换前展示确认弹窗：「切换资产类型后，原类型的专属属性将被移除；资产名称、位置、权属、估值及文件保留。」操作「取消 / 确认切换」。
4. 用户取消则保持原二级子类与全部已填写内容；确认后清除/不再引用与新类型不兼容的专属字段，并重新计算该子类 Required/Ready 缺项。不能把住宅套数错误映射为写字楼面积。
5. 不改变企业归属、编号、通用权属证据；已绑定的条件必需文件与旧选项关系变化，应重新展示必要项并保留可追溯的已上传文件（不得静默物理删除文件历史）。

### 4.2 禁止改类条件
- 资产处于 Ready，或已有 Instrument/Offering/签署/引用等后续业务事实依赖时，**禁止直接切换资产类型**；界面说明「此资产已进入资料完备或被后续业务引用，不能直接切换类别」，提供返回详情查看相关引用。
- 对 Ready 后普通字段修改与被引用关键字段的版本保护另见 §7；不能通过改 URL、状态伪装或复制提交绕过类型变更限制。
- 从「房地产」改成其他一级类别的迁移流程及已存在已发布资产的纠错/法定变更不属于本批批准的直接转换能力，不擅自实现自动迁移。

## 5. 校验与错误定位（R31）
### 5.1 明确分离两层校验
- **输入级 / 步骤级**：已输入数据的类型、合理范围、长度与即时条件验证。例：面积 > 0；可出租面积 ≤ 建筑面积；百分比 0～100；套数/客房数为正整数；日期不得为未来已发生估值日；文件格式 PDF/JPG/PNG、单文件上限 20 MB（媒体按其已批准格式要求）。
- **资料完备级 / Ready**：只有在用户点击「完成资料检查」时，汇总所有当前适用的 Ready 必需字段、选项触发的条件字段与文件状态；不把每一步「下一步」当成 Ready 审核。
- 单次「下一步」校验当前已输入内容的格式及触发条件的格式；缺失但用于以后进入 Ready 的字段不得阻止用户继续浏览/保存 Draft。
- 第⑤步展示「第②步 基础信息：缺城市」「第③步 文件：估值文件待扫描」「第④步 专属属性：建筑面积无效」等**精确可操作项目**，每项可点击定位到相应步骤和控件。总提示不得仅有「提交失败」而无原因。
- 「尚未确认」的抵押/权利限制只能继续做 Draft，不能 Ready；用户因变更估值依据/权利限制而触发的新条件文件必须重算；不得沿用过时的 Ready 结果。
- 如底层校验依赖扫描状态/外部服务，Unknown、Pending、Failed 必须区分；需要等待合法结果时显示「尚未通过资料完整性检查」，不能自动冒充通过。

### 5.2 已批准资产字段与子类的具体校验引用
- 所有公共字段和 Ready 条件以 U02-03 R15～R20 文件为准，不在本文件重新制定一套冲突的字段要求。
- 四个首批子类仅引用 U02-04 R21、R22、R23、R25；酒店 R24、土地 R26 **虽已审字段，但未开放创建**。
- 本批不新设资产数量限额、自动兑换汇率、隐式专业估值复核通过、金额精度或跨法域产权法律充分性认定。

## 6. 文件上传 UI 与异常恢复（R32）
### 6.1 必需文件按行列示、选填动态添加
```text
第三步 · 法律与估值
资产权属证明 [必需]            当前状态：未上传       [上传文件]
资产估值依据文件 [必需]        当前状态：可引用       [查看] [更换]
抵押/权利限制证明 [条件必需]    存在限制时显示         [上传文件]

其他文件（选填） [＋ 添加其他文件] → 选择类型 → 上传
```
- 每一行拥有**文件类型名、必需/条件必需标签、状态、文件名/版本和直接上传/查看/更换操作**。非必需文件不预先展示多余空白行。
- 资产的必需证明文件/格式上限以 U02-03 R19 为准；后续不能用 Instrument 权益协议或 Offering 认购文书替换资产证明。
- 上传流程至少区分未上传、上传中/进度、待安全扫描、可引用、失败/需重新上传；失联/超时/网络失败应保留其他有效输入和已上传文件，不自动丢记录。
- 文件在扫描未通过、失败或只完成传输未可引用时，**不能满足 Ready**；用户可重试/替换；更换文件保留历史引用、上传者/时间/版本与不可覆写的必要审计记录（具体底层存储由开发技术审计确认）。
- 更换已被 Instrument/Offering 引用的文件不能原地覆盖历史签署或旧版本证据；需要产生新版本并重新判定受影响的 Ready/发行准入。
- 文件类型不匹配、超限、扫描失败、上传未知等在**对应文件行**显示清晰原因及操作，不误报整页成功，也不因一个文件失败清空其他成功文件。
- 本处只设计正式 SaaS 上传交互；内部 Mock 控制台的模拟扫描属于独立测试能力，不能出现在 Free/Standard 商业页面作为“人工通过”按钮。

## 7. 第五步摘要、状态机、权限与后续操作（R33）
### 7.1 第五步结构
- 页面顶部显示「资产资料预览（内部）」、所属企业、分类/子类、资产名称、资产编号（若已持久化）、当前状态。
- 分组摘要：基本信息、位置及媒体、权属与主体关系、估值、文件清单状态、当前子类第④步专属属性；每组显示「编辑」回跳对应步骤。
- 缺项卡片列出按组整理的“待填写、格式错误、待安全扫描、扫描失败、权利限制未确认”等，指引到对应字段，包含具体行动「返回补充」或「重试上传」。
- 页面操作统一为「上一步」「保存草稿」「完成资料检查」，避免以「发布资产」「发行成功」混淆 Asset 与 Offering。

### 7.2 最小前台状态与许可转换
| 当前状态/结果 | 允许动作 | 不允许或需要重新检查 |
|---|---|---|
| **Draft 草稿** | 编辑、五步恢复、保存、检查资料、在规则内换二级子类 | 不表现为已合法可发行 |
| **Draft 完整性未通过** | 仍保持 Draft；逐项展示缺项/失败/未知并回跳补充 | 不能进 Ready |
| **资料检查通过 → Ready（资产资料完备）** | 显示当前资料完备；转入资产详情，指引「配置权益结构」 | **不自动**创建 Instrument、Project、Offering、Token 或公开上架 |
| **Ready 后修改关键字段/文件** | 依权限进入修订流程、记录历史并重算适用完整性与受影响引用（详细版本与状态规则依上游权威） | 不静默保留过时 Ready、不得覆盖已引用/签署历史版本 |
| **已有业务引用** | 查看真实引用、在既有受控规则内修订 | 禁止直接改子类、越权改历史法律/经济文件 |
| **Standard 宽限期** | 按 U01 允许既有必要存续服务 | 不新开真实发行 |
| **Standard 降级后历史只读** | 查看既有资产/发行事实及必要受控服务 | **不能因为套餐显示 Free 就重新赋予新建/编辑权** |

- 新开通 Free（通过 KYB）和获准 Standard 的资产资料准备操作一致；**Free 的 Ready 不代表可部署/Mint/对外上架**。Standard 真实发行仍受所有独立生产准入约束。
- 资产详情页按 U02-02 已批准四 TAB「资产概览 / 资产资料 / 权益结构 / 发行管理」显示。概览聚合来自该资产的真实当前进度，**唯一明确主下一步**一般是「配置权益结构」；若资料仍缺项，优先显示「继续完善资产资料」。
- **Asset 的第⑤步预览仅用于发行方核对 Asset 内容；Offering 的「投资者端最终发布预览」属于后续独立流程。**
- 复杂的法定审批/多角色复核不在当前 V1 单账号 UX 中擅自新增；状态名与法律门不得通过新增 UI 简化为自动法定批准。

## 8. 异常交互与边界检查
| 事件 | 期望表现（MVP 最低要求） |
|---|---|
| 在尚未选择已开放二级分类时点击下一步 | 禁止继续，并说明选择可用子类 |
| 点击酒店、土地或其他未开放资产 | 明确「暂未开放」，不进入可保存的创建表单，不引导错误升级 |
| 已完成基础信息但文件未上传 | 允许保存 Draft，缺少文件的 Ready 检查失败且有定位 |
| Draft 改子类，原子类已填写字段 | 明确丢失影响/确认；取消保留，确认只清除不兼容专属值 |
| 已 Ready 或有 Instrument/Offering 引用时改子类 | 拒绝直接修改，显示原因及返回资产详情入口 |
| 输入负数面积、超 100% 出租率、可出租面积 > 建筑面积 | 对应字段报错，不能 Ready；避免静默截断或异常自动计算 |
| 文件上传/扫描失败 | 文件行展示状态和重试；原文件版本与其他输入不丢失 |
| 上传尚未扫描完点击完成资料检查 | 维持 Draft、提示等待/重试，不能误 Ready |
| 点击保存时网络失败/超时 | 不显示成功，不清空当前编辑，支持重试，并避免重复新建记录 |
| 确认离开未保存草稿，或浏览器刷新取消离开 | 未确认则保留编辑上下文；确认丢弃仅丢弃未保存内容 |
| Standard 过期/降级历史记录打开编辑 | 不开放写权限，保留可查看的历史内容及必要存续指引 |
