# DEC-004｜受监管活动的责任边界与平台定位

- **状态：** 原则已确认；具体责任分配待法律意见与合作方案验证
- **确认日期：** 2026-10-18
- **适用文档：** 第 02 份《产品战略与商业模式》；后续落实到第 03/04/05/07/08 份文档

## 决策背景

本项目定位为面向企业客户的多资产 Tokenization SaaS 基础设施，而不是默认自行经营证券发行、投资者招揽、资金托管或交易业务的金融机构。软件提供者的技术定位不能替代目标法域对实际业务活动的法律定性，也不能仅凭合同措辞或“技术服务商”标签排除许可义务。

## 已确认原则

1. **平台的首要交付是软件与技术基础设施**，包括发行及存续期工作流、权限与审计、合规规则配置、客户门户、数据与报告、API/SDK，以及与合格第三方服务商的系统集成。
2. 对证券或其他受监管金融工具，涉及**发行安排、投资者招揽/营销、投资建议或分销、认购资金收取与转移、资金托管、法定持有人登记、交易撮合/执行、赎回或收益支付**等活动时，不预设由 SaaS 平台自行承担，也不预设一定可以外包。
3. 每项活动的实际责任主体、合同关系、资金流、数据控制、授权与监督机制，必须根据目标市场的具体法律意见、实际业务模式及合作机构安排逐项确定。
4. 若某项活动依法需要许可、注册、合格中介或特定金融基础设施，产品设计必须将其作为上线前置条件；软件配置、用户协议或第三方 API 本身不能替代法定要求。
5. 日本与阿联酋须分别进行辖区级分析；阿联酋内部不同监管区域和制度不可视为单一市场。法律意见应明确适用范围、前提条件、禁止事项及尚待确认的问题。
6. 产品需求、流程状态机、数据模型、权限设计和商业收费模式必须与经确认的责任分配保持一致，避免产品先行假设平台可以执行尚未获准的活动。

## 对产品设计的约束

- 将“软件工作流状态”与“法律/资金/登记的最终状态”分开建模；不得把链上交易成功自动等同于法定权利转移或资金最终结算。
- 对支付、托管、KYC/KYB、AML、法定登记、签署及投资者资格核验等能力，优先定义服务商接入与责任边界；是否可由平台直接提供须经法律审查。
- 所有需要外部机构完成的环节，应明确责任方、输入/输出、失败处理、对账、审计证据及升级路径。
- 在目标法域与首批资产类别尚未取得足够法律及合作方确认前，不将对应功能标记为可正式开展真实金融业务。

## 尚待验证（不是本决策已解决的事项）

- 日本及阿联酋具体经营主体、许可/注册要求与可提供服务范围；
- 各类金融工具下发行人、平台、经纪/分销机构、托管/支付机构、登记机构及其他合作方的职责；
- SaaS 订阅费、实施费、API 费用或其他收费是否会因具体服务内容触发额外监管要求；
- 投资者招揽、跨境营销、资金路径、客户资产隔离、个人信息跨境传输及记录保存要求。

## 后续动作

1. 在第 08 份《法律及经营资质方案》中分别列出日本、阿联酋及其相关监管区域的法律问题清单，并由当地合资格律师验证。
2. 在第 03 份总体 PRD 和第 04 份业务流程/状态机中，将已确认的责任主体、外部服务商边界和上线门槛映射到具体流程。
3. 在法律意见和合作方方案不足以支持某项活动时，默认将该活动设计为待接入、待审核或不可用状态，而不是假设可直接执行。
