# RWA SaaS V1｜认购订单模块 UI-Ready 最终规格

> **日期：2026-11-11**  
> **状态：Issuer 企业 SaaS V1 产品/UI 规格已收口（UI-Ready）；不代表开发或生产验收通过**  
> **入口：投资者与认购 → 认购订单**  
> **决策依据：用户授权产品负责人独立完成各小模块的 MVP 业务闭环，维持已批准规则；仅重大冲突或法定责任问题提交进一步确认。**  
> **分支：docs/r2-current-product-baseline；PR #8 保持 Draft / Open / Unmerged。**

## 0. 原则、已批准依据与责任边界

本文件是**Issuer 企业端认购订单模块**的当前完整 UI-Ready 执行规格。保留既有 SCOPE/DEC/Frozen/193 项功能编号及版本，不改写历史文件。

已批准的适用业务规则：
- DEC-069：平台第三方统一 KYC 强制；Issuer 只查看最小必要的脱敏信息和当前状态，不人工审核或配置 V1 额外投资者资格；法定/平台强制限制仍独立生效。
- DEC-052：订单列表/详情要拆分报价、签署、真实资金、配售、法定名册与 Token 事实；基础取消、过期、异常不能当作已退款或已释放额度。
- DEC-032：唯一订单与报价/签署/预留，付款核验、合法配售、登记和 Token 交付相互独立；付款/退款和外部 Unknown 必须保留原事件等待核查。
- U02-06 R19～R24：投资者按整数 Token 数量认购、单位 U（USDT），V1 仅 OP Mainnet USDT；真实付款与 Token 交付均已确认后订单才标「已完成」；Offering 发布时预留本期总量，订单只占用其内部额度，不再扣同一 Instrument 总量。
- DEC-072/U02-09：Offering 条款、最终收款钱包、协议、文件、权益结构版本在发布快照中固定；暂停/结束不删除在途订单。
- DEC-073/U02-10：「资产与发行 → 认购记录」仅展示已完成认购的跨资产历史记录；本模块处理**所有订单状态**并使用同一唯一订单号。
- DEC-074/U02-11：投资者基本资料/KYC 结果从本企业脱敏关系视图读取；不建立第二套投资者档案。
- SCOPE-179～181：认购订单、资金、容量与配售/名册、Token 分别有权威来源，受控异常/合法受权处理不可被企业运营直接改写。

### 0.1 模块一句话定位

**帮助发行企业查看每一笔认购走到了哪一步、哪里被阻断、应该去哪个责任模块处理。** 不做订单代下单工具、人工支付确认工具或企业自行配售/发币工具。

### 0.2 简洁页面结构

```text
投资者与认购
 └─ 认购订单
     ├─ 订单列表（含异常筛选/待处理视图，不额外建一级菜单）
     ├─ 订单详情（单页信息区 + 分阶段进度）
     └─ 基础取消确认弹窗 / 异常详情侧栏（嵌入详情，不另设导航）

关联入口：
  资产与发行 → 认购记录（仅已完成历史）
  资产管理 → 资产详情 → 发行管理 → Offering 详情
  投资者与认购 → 投资者管理
  投资者与认购 → 配售与持有人
  资金与结算 → 收款与对账 / 退款与异常
  Token 管理 → 交付/对账及相关记录
```

本期不新增子菜单或批量操作页面，不更改九个一级导航。

## 1. 页面一：认购订单列表

### 1.1 目标、使用者、入口

- **使用者：** 当前企业有权管理自身发行运营的账号；MVP 一个账号对应一个企业。
- **入口：** 投资者与认购 → 认购订单；也可从 Offering 详情或投资者详情带筛选进入。
- **目标：** 快速区分待付款、核对中、待履约、异常和已完成订单，打开订单核对事实，定位下一步。
- 列表仅显示当前 Tenant 和授权 Offering 的订单，任何筛选、导出和直接访问都不能穿透租户隔离。

### 1.2 页面布局

**页头**
- 标题「认购订单」，副说明「跟踪本企业各发行方案的认购、付款与交付进度」。
- 三张概览卡：当前筛选内订单数、需要关注的订单数、已完成订单数。指标来自权威订单/异常状态；尚未确认显示「统计更新中」，不能把缺数据当 0。
- 唯一重点操作「查看待处理」，行为是切换到待处理筛选，不直接修改订单；次操作「重置筛选」。

**轻量快捷筛选**：全部｜待处理｜处理中｜已完成｜已取消/过期。该标签**仅为查询视图，不是可写业务状态**。

**详细筛选**

| 字段 | 类型/默认值 | 条件与校验 |
|---|---|---|
| 搜索订单 | 文本；默认空 | 支持订单编号、当前企业范围内投资者引用编号；不搜索完整姓名、证件、邮箱、完整钱包地址；去空格；最多 120 字 |
| 资产 | 下拉；默认全部 | 仅当前 Tenant 可访问的 Asset |
| 发行方案 | 下拉；默认全部 | 根据所选 Asset 联动，显示当前企业有效/历史 Offering |
| 订单进度 | 单选；默认全部 | 全部、待付款、付款核对中、履约处理中、已完成、已取消、已过期、异常处理中 |
| 付款状态 | 单选；默认全部 | 未发起、待付款、待确认、已确认、差异/异常、退款处理中、已退款（状态来自资金权威） |
| 创建时间 | 日期范围；默认全部 | 起始日期不能晚于结束日期；按界面所选时区展示 |
| 仅看异常 | 开关；默认关 | 仅过滤本企业存在未结清异常关联的订单，不直接改变订单状态 |
| 重置 | 按钮 | 恢复默认筛选，不清除页面外的业务状态 |

列表默认按订单创建时间倒序，20 条/页，页码切换保留筛选。Offerings 跳转带入的过滤条件明确以标签展示并允许清除。

### 1.3 列表字段

| 列 | 内容、来源与展示 |
|---|---|
| 订单编号 | 唯一认购订单号；可复制，点击进入详情 |
| 投资者 | 当前企业脱敏展示名称 + 投资者引用编号；不暴露身份原件 |
| 资产 / 发行方案 | Asset 名称、Offering 名称和期次 |
| 认购数量 | 整数 Token 份数；取订单快照，不用当前 Offering 修改历史 |
| 订单金额 | 下单报价快照的总应付金额 U；不等于实际到账/结算 |
| 订单进度 | 友好的主进度标签；显示一条当前下一步说明 |
| 付款 | 独立付款状态；例如「等待付款」「核对中」「实收已确认」「金额差异」 |
| 法定登记 | 独立法定登记状态；「未开始」「待登记」「待回执/核验」「已有效」「差异/更正中」「Unknown」「不适用」；来源为配售与持有人，不由订单页改写 |
| 交付 | 独立 Token 交付状态；「未开始」「待交付」「核对中」「已交付」「异常」 |
| 创建时间 | 精确到分钟并展示业务时区 |
| 操作 | 唯一「查看详情」 |

- 移动端改为卡片：保留订单号、脱敏投资者、Offering、数量、金额、主进度、付款、法定登记、Token 交付和查看详情；不横向撑破屏幕。
- 不把「已付款」与「已完成」混为同一列；没有可核验资金/交付状态时显示「待确认」，不显示虚假 0 或成功。
- 订单主进度按 DEC-075 仍以「实收确认 + Token 交付确认」判定；若此时法定登记尚未有效，列表必须同时显示独立的「法定登记待确认/处理中」状态，不得仅凭「已完成」主标签暗示法定权益登记已完成。
- 订单主进度是业务**展示摘要**，其底层支付、容量、配售、登记、Token、退款仍各有独立状态；禁止仅通过主标签修改真实事实。
- 无“确认付款”“重新 Mint”“退款成功”“手工标记完成”快捷按钮，不提供批量取消/人工改状态。

### 1.4 空态/异常

| 场景 | 页面文案 | 下一步 |
|---|---|---|
| Free 新企业 | 「Free 套餐不开放真实认购订单。完成发行资料准备与内部预览后，可查看 Standard 套餐。」 | 查看套餐 |
| Standard 无订单 | 「还没有认购订单。投资者在已开放的发行方案中完成认购确认后，订单将显示在这里。」 | 查看发行方案 |
| 筛选无结果 | 「没有符合当前筛选条件的订单。」 | 清除筛选 |
| 订单状态尚未同步 | 「正在同步订单进度，请以核实后的状态为准。」 | 刷新（只重查状态） |
| 付款或 Token 服务不可确认 | 「部分业务状态暂不可确认，请打开订单详情查看来源与待处理事项。」 | 查看详情 |
| 无权访问/跨企业 | 「订单不存在或无权访问。」 | 返回当前企业列表 |

## 2. 页面二：认购订单详情（完整进度工作台）

### 2.1 页面架构

顶部固定：
- 面包屑「投资者与认购 / 认购订单 / [订单编号]」；返回列表保留筛选位置。
- 标题「认购订单 [订单编号]」；创建时间、当前主进度。
- 明确提示：「订单进度、真实付款、配售、法定登记、Token 交付、退款是不同状态」。
- **唯一主动作**：按当前未完成事项展示「查看待处理事项」；如果没有待处理，则「查看完成记录」。唯一不具备金融后果的快速操作「刷新状态」，只查询最新事实。
- 重要风险提醒栏：例如「付款状态无法确认」「付款已确认，Token 待交付」，点击定位到对应详情区。

主体采用**一条阶段进度导航 + 六个信息分组**，页面纵向滚动，分组可折叠；默认展开异常或当前需要处理的分组，不堆叠多个 TAB/向导。

阶段导航：
```text
订单与条款 → 付款 → 配售 → 法定登记 → Token 交付
             ↘ 取消/到期/退款/异常（独立支线）
```
- 每阶段状态来自各自权威记录；不是固定执行顺序或承诺所有法域「先登记后 Mint」。
- 签署和额度预留是付款前置事实，在「订单与条款」分组明确展示。
- 法定登记和 Token 交付始终分开。**订购完成**采用 DEC-073 的「实收确认 + Token 交付确认」口径；**法定权益/登记完成**另由权威登记模块表达，不从订单完成推断。
- 每个阶段都展示：当前状态、最近更新时间、源业务引用编号、异常（如有）和该阶段责任模块入口。

### 2.2 详情分组 A：订单概要、投资者与关联关系

| 字段 | 控件、来源、规则 |
|---|---|
| 订单编号 | 唯一订单号，只读，可复制 |
| 投资者 | 当前企业脱敏名称 + Tenant 内引用编号，点击「查看投资者」 |
| KYC 状态（订单前置） | 下单时权威通过事实摘要 + 当前必要状态提示；不展示原始报告，不将历史通过冒充当前有效 |
| Asset | 资产名称和 Asset ID，进入本企业资产详情 |
| Offering | 发行方案名称/期次、发布快照版本、发行状态，进入 Offering 详情 |
| Instrument | 权益类型、固定权益结构版本；引用不可改写 |
| 订单创建时间 | 日期时间及时区 |
| 最近订单事件 | 最近进度更新时间；没有结果时标为「待同步」 |
| 订单状态 | 当前主进度标签 + 下一步说明 |
| 投资者端来源 | 如有：本企业投资者门户/统一投资端；仅展示渠道来源，不提供跨 Issuer 账户识别信息 |

- 不显示或编辑完整姓名、证件、电话、邮箱、KYC 报告、非必要的风险标记。
- Issuer 不能替投资者新建订单、代签署、修改付款/接收钱包或代为支付。
- 历史订单始终引用下单时有效的 Offering/Instrument/文件/报价快照，而不是实时覆盖为最新版本。

### 2.3 详情分组 B：认购条款与签署

| 字段 | 控件、来源、校验/条件 |
|---|---|
| 认购 Token 份数 | 正整数，**只读历史快照**，来自唯一订单 |
| 认购规则快照 | 下单时单笔最低认购金额、单笔最高 Token 份数（如设置）、单投资者本期累计最高认购金额（如设置）及适用结果；固定保留订单创建时的规则版本 |
| 投资者累计额度核算 | 当前 Offering 下该投资者此前有效占用金额、本单计入金额、下单后剩余额度；只显示该投资者自己的额度摘要，不披露其他投资者或订单明细 |\n| 累计额度释放记录 | 已确认取消/过期/退款金额、释放时间、权威资金/容量事件引用；部分释放与全额释放分开显示 |
| 每 Token 价格 | 以 U 表示的下单报价单价，保持精确十进制展示 |
| 订单应付金额 | 数量 × 单价 U；来自 QuoteSnapshot；与实收金额分开 |
| 可能存在的适用费用 | 仅在订单批准报价快照实际包含时显示对应金额/承担方；未批准的费率不自行推断或加收 |
| 报价生成/失效时间 | 如有明确权威有效期则显示；不得自行承诺固定超时分钟数 |
| 报价状态 | 有效、已失效、待重新确认、无法确认等只读结果 |
| 认购协议版本 | 文件名、版本、签署时引用；有权限则进入文件预览 |
| 风险披露版本 | 文件名、版本、必要确认状态 |
| 签署状态 | 未开始、等待签署、已完成、失败/需重新确认、暂不可确认 |
| 签署证据摘要 | 受权签署结果引用、完成时间；不得提供伪造的「已签」按钮 |
| 适用认购限制 | 订单创建时校验结果引用（KYC、Offering 开售/额度/最低额、法定强制限制）；不开放额外企业资格配置 |

异常提示：
- 报价或文件失效：「原报价/协议版本已失效，请投资者按门户指引重新确认；已保存的历史文件和签署引用仍保留。」
- 签署待确认：「尚未取得有效签署结果，不可视为付款条件已满足。」
- 无权查看文件：「该文件无可用的查看权限，仍保留引用记录。」
- 不提供改价、改数量、直接修改文件版本、补写签署或手工改变订单条件。

### 2.4 详情分组 C：额度预留与订单时限

| 字段 | 展示规则 |
|---|---|
| 本期可售关联 Offering | 固定 Offering 引用 |
| 订单申请预留数量 | 只读整数份数 |
| 订单容量状态 | 待确认、已预留、待核保护、已转配售、已释放、无法确认（M12 权威） |
| 预留有效期 | 仅有已批准且实际存在的时限才显示，带时区；不自行创造固定倒计时 |
| 实际预留引用 | M12 容量事件引用 |
| 保护原因 | 只显示必要业务解释，如「付款待核，不可立即释放」 |
| 已释放/转配售时间 | 仅有权威事件时展示 |
| 操作 | 「查看容量/配售记录」，进入配售与持有人；无手动扣减或释放按钮 |

**容量不变量：** Offering 发布时已经预留本期总 Token 份数。订单级占用仅在该 Offering 预留内部划分；不得从 Instrument 总可用量再扣一次。订单过期/取消也不能自行认定容量已释放；M12 对释放/保护/转配售拥有唯一权威。

### 2.5 详情分组 D：真实付款

| 字段 | 展示规则 |
|---|---|
| 支付网络/币种 | OP Mainnet · USDT（V1 固定） |
| 订单应付金额 | U，来自订单 QuoteSnapshot |
| 付款状态 | 未发起、待付款、已提交待确认、核验中、实收已确认、金额/网络异常、暂不可确认、退款处理中、退款已确认（来自 M11） |
| 付款状态更新时间 | 权威时间 |
| 已确认实收金额 | 仅 M11 最终匹配成功时展示真实金额 U；未确认显示「待确认」，不显示推测值 |
| 付款引用 | 权威支付指令/交易引用的缩略标识，支持复制受权引用；完整证据在资金模块查看 |
| 付款来源地址 | 只读引用 M11 已核验链上事件的发送方地址；默认缩略展示，完整地址仅按授权查看；不得自动等同于投资者账户或 Token 接收钱包 |
| 付款来源地址核验 | 已与投资者授权钱包匹配 / 不匹配 / 无法关联 / Unknown；没有可靠映射时不得推断付款人身份 |
| 差异原因 | 仅允许对 Issuer 展示的业务类别，例如少付、多付、错链、非支持币、迟到账、无法匹配；不暴露内部风控机密 |
| 企业最终结算收款钱包 | Offering 发布快照中的企业钱包名称与缩略地址，明确是最终结算账户，**不是投资者支付地址** |
| 结算状态 | 未结算、待确认、已结算、存在差异，来自资金模块；与「付款已确认」独立 |

- 只有权威 **FinalMatched** 才显示「实收已确认」。钱包授权、签名、广播、截图、交易哈希或链上观察不等于已确认实收。
- 支付方向、实际收款地址、资金持管责任和真实操作均由独立准入决定；本页不绘制可执行付款二维码或向企业开放实际资金操作。
- 禁止在此点击「标记已到账」「确认付款」「重新扣款」「直接退款」。
- 若付款 Unknown 或有迟到账/错链/金额差异，显示「查看资金核对」，跳转「资金与结算 → 收款与对账 / 退款与异常」，并保留原订单关系与订单快照。
- 已支付不自动代表已配售、已登记、Token 已交付或企业已到账结算。

### 2.6 详情分组 E：配售、法定登记与 Token 交付

**配售**
- 状态：未开始、待审/处理中、已确认、受阻、暂不可确认。
- 展示唯一配售记录编号、配售数量/法律单位、决定时间、授权事实摘要（可见范围内），入口「查看配售」。
- 只有合法条件、付款事实与批准规则满足，才可能得到有效配售；发行企业不能在订单页人工标记「已配售」。

**法定登记**
- 状态：未开始、待登记、已登记、差异/更正处理中、无法确认。
- 展示法定登记引用、登记数量或权益单位、有效时间；入口「查看持有人登记」。
- 钱包余额、Token 已交付、订单完成不单独证明法定权益已登记或生效。

**Token 交付**
- 状态：未开始、待交付、交付核验中、已交付、交付失败、暂不可确认。
- 展示 Token 交付份数、受权交付事件引用、确认时间和异常摘要，入口「查看 Token 交付」。
- 无法核验时不可显示「已交付」；不开放 Issuer 直接 Mint、Burn 或强制转账。

**必要时序**
- 采用具体已获法律/生产授权的业务顺序，不在 UI 硬编码全法域固定先后。
- 即使「实收已确认 + Token 已交付」使订单按当前规则进入「已完成」，法定登记仍在核验/差异时，要并列醒目显示**「认购已完成，法定登记待确认」**，并链接权威登记页。
- 「已配售」「已登记」不能由订单后台直接改写，且不能当成 Token 已交付。

### 2.7 详情分组 F：取消、退款、异常与操作历史

- 显示「取消/过期结果」：无、取消申请处理中、已取消、已过期、取消受阻；附权威时间。
- 显示「退款状态」：无、待评估、处理中、已批准待实际退款、真实退款已确认、失败/暂不可确认；**审批通过 ≠ 已退到账**。
- 显示「异常记录」：关联异常编号、类别、责任模块、处理状态、最新进展、跳转入口。
- 显示「操作及业务时间线」：订单创建、报价/签署、预留、付款观测与匹配、配售/登记、Token 交付、取消/退款/异常的来源和时间。不可隐藏已发生的真实交易事件。
- 「查看完整异常」跳转「资金与结算 → 退款与异常」或共享异常处理；不在本页设计第二套金融审批流程。

## 3. 主进度、付款和异常的展示状态模型

### 3.1 订单主进度（摘要而非新的财务主账）

| 对用户展示 | 触发事实 | 下一步提示 |
|---|---|---|
| 待确认 | 报价/文件/签署/容量前置尚未全部就绪，或等待投资者确认 | 查看订单前置条件；必要时由投资者在门户操作 |
| 待付款 | 有效订单与付款前置满足，尚未确认真实支付 | 投资者端完成支付；Issuer 仅查看 |
| 付款核对中 | 钱包已提交/观察到待确认事实或 M11 暂不可确认 | 查看资金核对，不得宣称已到账 |
| 履约处理中 | 实收已确认，配售/登记/Token 交付仍在进行 | 查看尚未完成的独立业务阶段 |
| 已完成 | 真实付款已确认 **且** Token 交付已确认 | 查看已完成认购历史与登记情况 |
| 已取消 | M10 确认订单取消，且未把仍有实际支付/合法权益义务的记录作废 | 查看容量/退款的独立真实状态 |
| 已过期 | 订单/报价等已超时且满足安全的过期关闭条件；未知付款不自动放行 | 查看是否有晚到账/待核保护 |
| 异常处理中 | 存在未结清异常且本单无法安全沿正常主路径推进 | 查看异常与责任方 |

- 「退款处理中」「已退款」「容量待释放」「法定登记待确认」为**独立的退款/容量/登记状态**，不构造成隐含订单完成/取消结果。
- 主标签与明细出现冲突或某权威状态 Unknown 时，优先显示「核对中/异常处理中」与警示，禁止展示确定性的“认购成功/退款成功”。
- 取消和过期后若真实款项后来被确认，必须保留/重新打开资金调查支线；不得删除真实付款事件或自动恢复已释放的容量。

### 3.2 按状态的唯一重点操作

| 场景 | 页面唯一主操作 | 次级操作 |
|---|---|---|
| 待确认 | 查看缺少的条件 | 查看签署/额度事实 |
| 待付款 | 查看付款进度 | 仅满足安全前提时可「申请取消」 |
| 付款核对中 / Unknown | 查看资金核对 | 刷新状态（不重发交易） |
| 实收已确认待配售/交付 | 查看待处理事项 | 跳转配售或 Token 详情 |
| 异常处理中 | 查看异常处理 | 查看原订单事实 |
| 已完成 | 查看已完成认购 | 查看法定登记/历史 |
| 已取消或过期 | 查看历史记录 | 查看真实退款、容量释放结果 |

在实际需要处理的有权模块没有开放操作权限时，显示只读状态和责任方/支持入口，不造假「可处理」按钮。

## 4. 基础取消与到期：页面操作和确认

### 4.1 允许取消的安全窗口

**订单取消是有条件的业务请求，而不是 Issuer 自由修改状态。**

只有当前订单满足以下条件，才展示可执行「申请取消」：
1. 当前订单仍处于可依法撤销的待付款阶段，并满足适用合同/规则；
2. M11 没有已确认支付，也没有待核/Unknown/已观察付款或未识别资金风险；
3. M12 未产生不可撤销的有效配售/法定登记，M07 未产生 Token 交付；
4. 当前订单版本和预留状态可核实，且平台返回可安全受理取消的判断。

如果任一条件缺失/Unknown，按钮不可执行；显示「当前不可直接取消，请先核对付款/预留/权益状态」及对应责任模块入口。

**明确不做**：实收已确认后的普通取消、用取消一键退款、撤销法定登记、撤销 Token 持仓、转移/强制释放额度。

### 4.2 「申请取消」弹窗 UI

- 标题：「取消认购订单？」
- 只读摘要：订单号、发行方案、脱敏投资者编号、Token 份数、应付金额 U、当前订单/付款/预留状态。
- 警示文案：「取消订单不代表已退款，也不保证额度已释放。若存在真实付款或其他在途义务，将转为核对处理，不会删除原始记录。」
- 原因单选：投资者已放弃 / 订单重复需核对 / 其他业务原因。默认为未选；若无可证明的投资者意思表示，不得虚假选择「投资者已放弃」；选其他时允许不含敏感身份材料的简短备注，最多 200 字。
- 必需复选框：「我已核对当前状态，理解取消申请不能替代付款、退款、配售或 Token 处理。」
- 操作：「提交取消申请」/「返回订单」；提交时重查状态及权限。
- 成功显示「取消请求已受理」或权威「已取消」结果；**只能依据真实结果用词**。若容量释放尚未确认，继续显示「容量待核/待释放」。
- 状态冲突、付款已出现或并发修改时不再执行取消，提示「状态已变化，请先查看最新付款和权益记录」。
- 重复提交返回原取消请求和现有结果，不重复触发新的资金、配售或容量操作。

### 4.3 到期与迟到账

- 订单期限与预留期限从各自权威事实读取；不擅自设置统一 15/30 分钟倒计时或硬编码超时释放。
- 到期且无付款证据、无 Unknown、无不可撤销义务，并收到权威释放/到期决定时，主进度可显示「已过期」。
- 单投资者本期累计额度按唯一订单状态聚合：有效订单/预留、已付款待配售和已确认配售持续占用；同一订单状态迁移不重复累计。只有权威确认取消/过期/退款等释放条件后才释放；任何 Unknown 或待核状态继续占用。部分退款只释放已由权威资金记录确认的退款金额；未退款部分继续占用个人累计额度。全额退款只有在全额退款事实确认、订单/容量权威同步释放后，才可释放剩余占用；退款申请、审批通过或 Provider Accepted 均不释放额度。
- 已观察付款但最终性 Unknown：进入「付款核对中」与「额度待核保护」，不能只因倒计时归零直接取消/释放。
- 预留已合法释放后发现真实迟到账：保留真钱、订单与旧预留历史；不得重新占用他人的额度或自动认购成功；引导资金异常与依法退款/恢复评估。
- 已支付且订单取消申请中：不假定款项未到；取消受阻需进入资金和合法权益调查。

## 5. 异常管理：保持一个入口，不复制领域主账

异常默认在订单详情的「异常与操作历史」中展示；列表顶部「仅看异常」提供跨单筛选，无独立订单异常导航。

| 异常 | Issuer 可见提示 | 下一步 | 必须保护 |
|---|---|---|---|
| KYC 已过期/撤销/Unknown | 「身份核验当前不可确认，请投资者按平台指引处理」 | 查看脱敏 KYC 状态 | 不披露证件/AML 信息，不绕过 KYC |
| Offering 暂停/结束 | 「本期停止新增认购，既有订单仍按事实处理」 | 查看 Offering / 原订单 | 不删除或自动取消在途义务 |
| 报价或签署版本失效 | 「需要重新确认有效条款/签署」 | 指引投资者在其端处理 | 不覆盖旧快照和已签署证据 |
| 余额不足/授权拒绝 | 「投资者未成功完成付款操作」 | 投资者端依据有效付款指引重试，Issuer 仅查询 | 不伪造实收 |
| 交易已提交但未确认 | 「付款待核实」 | 查看资金与结算 | 不因 TX Hash 直接确认到账 |
| 少付/多付 | 「实收金额与订单应付金额不一致」 | 资金与结算异常 | 不自动改订单价/擅自退款 |
| 错链/非支持资产 | 「付款网络或资产不符合当前发行条件」 | 资金与结算异常 | 不把非合规款当有效认购 |
| 支付 Unknown / 重组 | 「无法确认最终资金结果」 | 核查原支付事实 | 不重复扣款、释放额度、转配售 |
| 取消/到期后迟到账 | 「订单已取消/过期但发现待核/实收付款」 | 资金异常及受控退款/恢复 | 不自动恢复额度 |
| 容量并发不足 | 「有效可认购额度不足」 | 查看 M12 预留状态 | 不二次扣减、超售 |
| 单个投资者本期累计上限达到/剩余额度不足 | 显示本期上限、该投资者已占用金额、本单申请金额和剩余额度；不展示其他订单明细 | 投资者按当前剩余额度调整认购数量；若占用状态 Unknown，等待权威核验 | 不绕过上限、不重复累计同一订单、不提前释放 Unknown/待核订单占用 |
| 已实收但配售受阻 | 「付款已确认，配售仍受阻」 | 配售与持有人 / 资金异常 | 不把付款成功当法定获配 |
| 法定登记暂不可确认 | 「法定登记待核实」 | 配售与持有人 | 不用 Token 余额替代名册 |
| Token 交付失败或 Unknown | 「Token 未确认交付」 | Token 管理异常 | 不手工标完成、不重复 Mint |
| 退款申请通过但未实付 | 「退款待实际执行/确认」 | 资金与结算 → 退款与异常 | 不把审批当已退款 |
| 退款交易 Unknown | 「退款结果暂不可确认」 | 查询原退款指令 | 不重复退款 |
| 跨 Tenant 引用 | 「订单不存在或无权访问」 | 返回本企业订单列表 | 不泄露他人投资者/订单 |
| 状态来源不可用 | 「当前进度暂不可确认」 | 保留快照，稍后刷新 | 不用缓存改写真实状态 |

- 异常侧栏字段：异常编号（可复制）、业务类别、首次发现时间、最近更新、责任模块、当前处理状态、可见的下一步和「查看责任模块」链接。
- 可以关闭侧栏，不可以通过关闭侧栏“解决”异常；共享待办/支持工单关闭也不能改变资金/Token/登记权威事实。
- 没有责任模块访问权限时显示「请联系平台支持/有权责任方」，不提供无权按钮。
- **刷新状态**只查询，不生成新的支付、Mint、退款、配售或释放动作。

## 6. 套餐、权限与隐私

| 企业条件 | 订单列表 | 订单详情 | 取消申请/业务操作 |
|---|---|---|---|
| KYB 未通过、审核中、补件 | 使用既有企业认证拦截引导 | 禁止绕过 | 禁止 |
| Free 新企业 | 显示真实业务未开放空态，不生成 Mock 订单 | 无真实订单 | 禁止 |
| Standard 且 KYB 已通过 | 当前企业受权真实订单 | 脱敏展示本企业订单与各权威状态 | 仅安全取消条件且具有真实受权时允许申请；不能直接执行金融操作 |
| Standard 宽限期 | 按 U01 保留必要历史查询 | 只读，显示在途责任方 | 不开放新增真实发行/认购业务；历史义务不能因此删除 |
| 历史 Standard 降级 Free | 历史真实订单只读保留 | 只读状态及对应记录入口 | 不新增订单、代操作、退款/Mint |
| 当前订单或投资者授权关系无效 | 仅按 Tenant/合法数据保留与最小权限展示 | 隐藏不再有权展示的个人字段，保留必要法律/财务业务证据 | 不借授权变化修改已发生真款/合法权益 |

- Issuer 默认只看到当前企业的投资者引用号、脱敏名称及本企业订单关系；无原始 KYC、完整姓名、证件、个人联系方式、完整钱包地址。
- 不开放 Issuer 创建订单、代投资者确认报价或签署、不提供个人信息编辑和 KYC 人工审核。
- 不提供订单财务状态手工修改、伪造付款凭证上传、Token Mint/Burn、法定登记改写或批量执行。
- 本模块不默认提供订单级明细导出；统计报表/受控导出由数据报表模块在独立权限与脱敏规则下承载。
- 操作和敏感状态查看保留可追踪业务记录；不增加 V1 团队角色管理。

- 订单是唯一认购主账，不再创建单独「认购记录主账」。
- 订单 Quote、文件版本、Offering 和 Instrument 版本为不可静默变更的历史引用。
- 容量预留属于配售/权威容量主账；资金属于资金主账；法定登记属于法定登记主账；Token 属于 Token 主账。
- 无法确认为真实的跨模块事实显示「待核实」，不得推断成功、释放、退款或合法权益生效。

## 8. V1 明确不做与风险隔离

- 不提供企业代投资者下单/签署/发起付款。
- 不提供复杂批量认购、集中募集、竞价匹配或超募/部分配售高级流程；原有功能版本归属不动。
- 不允许 Issuer 配置额外投资者资格、等级、区域白名单或人工 KYC 审批。
- 不允许订单价/份数/权益版本/签署文件在下单后直接编辑。
- 不允许钱包授权/链观察/Hash/截图直接标资金确认；不允许取消直接等于退款。
- 不允许在订单页执行真实退款、真实资金移动、重新 Mint、强制转账、法定名册改写或私钥/Signer 操作。
- 不在本模块实现具体合约、付款地址、手续费规则、精确付款时限、链确认参数、生产 Provider 或实际法域决定。
- 不为便于演示虚构真实投资者、真实到账、真实 Token 交付或「已完成」订单。
- 已成立合法权益的退出、赎回、清退按发行后有权模块处理，不作为普通订单取消。
