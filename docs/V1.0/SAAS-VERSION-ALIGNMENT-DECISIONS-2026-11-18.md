# RWA SaaS 当前版本归属决策记录

> 决策日期：2026-11-18。性质：产品负责人明确确认的当前交付版本归属覆盖记录。本文只更新当前执行口径，不改写历史 DEC、Frozen 文件或 193 项原始批准版号。

## 1. 本记录的范围与版本定义

本轮只审计并规划 GitHub 当前已有的 **官网 Website + 企业 SaaS（Issuer）**。企业投资者平台、总投资者平台、平台总管理后台均尚未进入本轮开发与版本规划；三个平台各自独立规划 V1.0，不在本文分配版本。

- **SaaS V1.0**：当前已交付的官网/Issuer 前端基线及已批准的基础业务闭环；真实生产后端仍按 V1.0 Backend Developer PRD 的范围推进。
- **SaaS V1.5**：在现有基础上补齐常见资产模板、基础权益结构、基础发行生命周期，以及认购/资金/Token/收益运营的企业端基础操作。
- **V2.0 统一需求池**：跨产品端的统一后续需求池，不限制归属某一个平台端。本文新增项目仅表示本轮从 SaaS 审计识别并获准进入需求池，不代表其他平台已经规划或开发。

## 3. V1.0 基础闭环保留边界

### 3.1 Asset / Instrument / Offering

V1.0 保留直接关联：一个 Asset 对应一套当前有效 Instrument，Offering 直接引用该 Asset 和 Instrument。V1.0 不要求先创建独立 Project。

V1.0 不提供 Asset/Instrument 的业务版本历史、Project 版本关系或 Offering 历史快照管理。技术字段 `version` 如用于并发编辑，只是记录并发控制版本，不代表业务历史版本。

虽然完整历史快照进入 V2.0，V1.0 仍必须保留交易本身所需的事实：订单创建时固定该笔订单的数量、单价、币种、费用、支付网络/收款指令及必要的已接受条款/披露引用；收益分配仍必须按 Record Date 取得并保留法定持有人/权益数量快照。这些是订单和分配的必要业务记录，不等同于通用 Asset/Instrument/Offering 版本历史系统。

### 3.2 投资者准入

投资者必须完成有效 KYC，KYC 未通过、已过期、待补件或被拒绝时，不得进入认购。取消的是独立的“投资者资格审核/资格规则引擎”，不是取消 KYC，也不自动取消依法或经适用服务商要求的 AML/制裁检查。

认购仍需校验 Offering 是否开放、基础最小/最大认购数量（如该 Offering 配置）、可用发行容量、必要文件/签署、付款和网络条件；这些是交易条件，不构成独立投资者资格评估。
