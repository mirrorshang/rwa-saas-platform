# DEC-071｜权益结构 V1 单页 UI-Ready 与三类权益字段收口

> **日期：2026-11-11**  
> **状态：Approved（依据用户授权，由产品负责人自主完成 V1 详细设计、字段精简及 UI 收口）**  
> **适用范围：Issuer 企业 SaaS｜资产与发行 → 资产管理 → 资产详情 → 权益结构**  
> **维护分支：docs/r2-current-product-baseline｜PR #8 Draft / Open / Unmerged**

## 1. 决策背景

U02-05 已批准一资产一套当前有效 Instrument、股权/债权/收益参与三选一、单页面三区域、用户填写权利总规模和 Token 拆分份数、系统计算每 Token 权利、多期 Offering 共用权益容量及固定版本引用。R13～R18 字段级基础规则已批准。

DEC-059 将预期年化收益区间披露和债权周期付息纳入 V1，但具体字段、适用范围、付息频率、日期规则、精度、版本编辑和 UI 交互仍停留在 Candidate。用户于 2026-11-11 授权详细设计时可按 V1 易用性精简和完成字段/页面收口。

## 2. 正式设计决定

### 2.1 页面与主体

1. 继续使用资产详情「权益结构」TAB；不增加二级导航或独立向导。
2. 单页三区域固定为：**权益定义｜权益规模与 Token 拆分｜法律文件**。
3. 权利责任主体按类型动态命名：股权「对应股权的法律实体」、债权「债务人」、收益参与「收益责任主体」。
4. 主体可引用当前 Asset 已有的登记权利人/相关方资料，也可在 Instrument 中录入独立主体；引用主体资料不自动推断其法律角色，不默认等同于 Tenant 或 Asset 登记权利人。
5. 不新增全局主体名录，不将 Asset 相关方角色与 Instrument 法律责任主体混为一谈。

### 2.2 股权型

- V1 只支持普通股，不提供优先股、可转换股或复杂类别。
- 权益规模为正整数普通股总数；Token 总份数为正整数。
- 每 Token 对应股份数必须为整数股；不能精确拆分时阻断 Ready，不支持分数股。
- Token 不自动等于法定股东名册登记或已取得股东身份。

### 2.3 债权型与周期付息

- 利息方式：无息 / 固定利率。
- 固定利率需填写固定年利率、起息日、到期日。
- 付息方式：到期一次付息 / 周期付息；周期频率为每月、每季度、每半年、每年。
- 周期付息需填写首个付息日；系统按日历周期生成合同日期，目标月份不存在对应日时取当月最后一个自然日。
- 若最后一个完整周期未到达合同到期日，增加到期日作为最后一期并标记「非完整周期，需人工核算」。
- 计息日数规则支持 Actual/365 Fixed、Actual/360、30/360、合同其他约定；合同其他约定需人工核算/复核。
- V1 不自动执行周末/法定节假日顺延；合同约定的实际支付日期由有权主体在收益/付款环节确认。
- 无息债权不生成付息计划；本金固定到期一次偿还。
- 不支持浮动/阶梯利率、复利、复杂本金摊还、任意不规则日期列表和自动逾期罚息。

### 2.4 收益参与型

- 必填：收益来源、收益计算口径、参与开始日、参与结束日、分配频率。
- 参与期限采用起止日期；结束日必须晚于开始日。
- 分配频率仅支持每月、每季度、每年。
- 授权参与比例大于 0% 且不超过 100%。
- 不支持复杂多层收益瀑布、优先劣后、阶梯分配或复合权益。

### 2.5 精度与 Token 拆分

- 股权：整数股，Token 份数必须整除总股数。
- 债权本金 U：最多 6 位小数；每 Token 名义本金必须在 6 位小数内精确表示。
- 收益参与比例：最多 6 位小数；每 Token 参与比例必须在 6 位小数内精确表示。
- 不能精确拆分时拒绝 Ready，不允许静默舍入或截断。
- 上述为 V1 产品输入精度，不等于链上 Token decimals、法律允许的最小股份单位或生产合约精度；生产门仍需独立确认。

### 2.6 预期年化披露（DEC-059 V1）

- 股权型、收益参与型可选填预期年化区间；债权型固定利率直接展示合同固定年利率，不重复填写预测区间；无息债权不显示。
- 最低值/最高值同时填写，最低不得高于最高；填写区间时测算依据必填；全部留空不阻断 Ready。
- 投资者端显示「发行方预期年化收益区间」及固定非承诺提示。
- 预期年化只作信息披露，不参与 Offering 定价、M13 应付计算或实际收益分配。

### 2.7 草稿、Ready 与版本

1. Draft 最低条件为权益类型和权益结构名称；其他 Ready 字段可暂缺。
2. 完成资料检查时校验当前类型字段、核心文件、条件字段和 Token 精确拆分。
3. Ready 仅表示资料完整，不代表法律权利成立或真实发行获准。
4. 未被 Offering 引用的权益结构可编辑；变更 Ready 必填字段或核心文件后 Ready 失效，需重新检查。
5. Draft 或未被引用的 Ready 可切换权益类型；确认后清除不兼容字段与核心文件关联，但保留文件实体，状态回到 Draft。
6. 已被 Offering 引用的版本不可原地覆盖；V1 提供「创建修订版本」，新版本可修改说明、文件版本、预期年化、付息安排和收益参与条款，但不得改变权益类型、责任主体、权益总规模、权利单位或 Token 总份数。
7. 新版本不增加或重置权益容量；旧 Offering 继续引用旧版本，新 Offering 只可引用最新 Ready 版本。已产生认购、配售、持仓或存续义务的 Offering 不自动迁移。

## 3. 与其他模块衔接

- Offering 继承确定 InstrumentVersion；只配置本期发行参数，不重复配置权益总量或 Token 映射。
- M13 从 InstrumentVersion 读取周期付息计划；M13 负责收益上报、应付核算/复核、注资与实付对账。
- 预期年化区间仅用于投资者披露，不得被 M13 或 Offering 认购定价引用。
- 真实法律权利、资金付款、Token 部署/Mint、Signer、Provider 仍须独立生产准入。
