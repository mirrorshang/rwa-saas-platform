# RWA SaaS｜Platform Admin P-18：统一投资者账户管理 UI-Ready 产品规格（Draft v0.1）

> **文档状态：Draft｜2026-11-18**
>
> 本文细化平台总后台「投资者管理」模块，只管理总投资者平台 M 的统一投资者账户及其必要 KYC 服务状态。不是所有 Issuer / V 门户投资者的全局客户库。
>
> 本文只定义桌面 Web 页面、字段、交互、状态、Mock 与前端验收，不实现后端、数据库、API、真实 KYC Provider 或生产账户控制。

## 0. 本批范围与结论

### 0.1 对应页面组与批准依据

| 项目 | 归属 |
|---|---|
| P-18 | 平台总后台投资者管理页面组（平台运营 UI 扩展） |
| M24-F001 | 统一投资者身份与 Issuer 关系映射，DEC-057 已批准 V1 |
| M24-F002 | 跨 Issuer 资料授权与 Offering 条件编排，DEC-057 已批准 V1 |
| DEC-069 | 平台维护统一 KYC 权威结果；适格第三方实际核验；Issuer 仅查看本企业授权范围内的脱敏状态 |
| DEC-074 | Issuer 投资者管理只覆盖本企业脱敏视图，不等于 P 端全局投资者管理 |

P-18 不新增 M 功能 ID，不改变历史 125 页面组统计；P-18 是为平台运营已批准 M24 业务增加的 P 端管理 UI。

### 0.2 页面结构（保持精简）

P-18 只包含两个主要页面：

1. **M 统一投资者账户列表**：搜索、筛选、查看账户及 KYC 服务状态。
2. **M 投资者账户详情**：账户摘要、KYC 结果摘要、Issuer 授权关系、服务异常与账户访问限制。

KYC 核验异常处理、通知投资者、限制/恢复账户等操作均在详情页完成；不另建复杂 KYC 审批台、CRM 或客服工单系统。跨模块任务统一关联 P-07/M17，通知使用 M18。

## 1. 产品边界与核心规则

### 1.1 P-18 管理什么

- 仅管理总投资者平台 M 的统一投资者账户。
- 查看账户基础状态、脱敏身份信息、KYC 权威结果摘要及同步状态。
- 查看该 M 账户与 Issuer/Offering 的必要授权关系摘要。
- 处理 KYC Provider 同步异常、资料过期/待补件等服务事项：查询原结果、通知投资者、创建/关联运营任务。
- 在平台自身授权范围内限制或恢复 M 账户的平台服务访问，并完整记录原因和历史。

### 1.2 明确不管理什么

- 不建立所有 V 企业专属门户投资者的全局数据库。
- 不合并 M 与 V 的账户、钱包、订单、持仓或历史记录；相同邮箱、证件或钱包不能触发自动合并。
- 不替第三方 Provider 作出 KYC 通过/拒绝结论，不提供人工覆盖 KYC 状态的按钮。
- 不代替投资者填写或修改身份资料、上传材料、完成 KYC。
- 不建立独立投资者资格审核/资格规则引擎；该能力已取消。有效 KYC 仍是认购 Gate，Offering 条件由原业务领域判定。
- 不复制订单、付款、配售、法定登记、Token 或收益主账；必要时只读显示本人 M 渠道业务的授权摘要。
- 不默认展示完整证件、原始 KYC 报告、AML/制裁细节、Provider 原始 Payload；敏感资料只能按 P-11/P-12 受控访问规则申请。

### 1.3 三类状态必须分开

| 状态 | 说明 | P-18 能否直接改变 |
|---|---|---|
| M 账户状态 | M 账户是否正常使用平台服务 | 仅可按授权执行平台访问限制/恢复 |
| KYC 核验状态 | 第三方 Provider 返回的平台权威核验结果 | **不可手工改变**；只能查询、同步、通知或发起核查 |
| Offering 认购状态 | 某投资者是否满足某 Offering 的 KYC、地区、窗口、签署及交易条件 | P-18 不作决定，不提供 Eligible/Purchasable 开关 |

KYC 有效不代表所有 Offering 都可认购；M 账户受限也不代表投资者既有订单、持仓、收益或法定权利被取消。

## 2. 全局页面与交互规范

- 仅桌面 Web；沿用平台总后台左侧 9 个一级导航。
- P-18 位于「04 投资者管理」。
- 列表默认只显示完成日常运营所需的最小脱敏信息；不显示证件号码、完整住址或原始 KYC 文件。
- 详情页采用清晰分区，不把所有字段塞入长表单；操作集中在对应状态卡片。
- 所有状态变化显示来源、时间、原因和关联任务；Unknown 不显示为成功或失败。
- 不提供投资者批量导出。需要敏感资料时跳转 P-11/P-12 受控访问流程。
- 所有查询/刷新/通知/限制操作必须有明确结果反馈；操作超时保留原操作 ID，不盲目重复执行。

## 3. P-18-01｜M 统一投资者账户列表

### 3.1 页面目标

平台运营人员快速定位 M 账户、查看账户与 KYC 状态、发现服务异常，并进入单个账户详情。列表不是所有 V 门户用户的搜索入口。

### 3.2 页面结构

1. 页面标题：「投资者管理」；副标题：「管理总投资者平台账户及其核验服务状态」。
2. 摘要区（最多 4 项）：M 账户总数、正常账户、KYC 待处理/待补件账户、KYC 同步异常账户。每项注明统计更新时间；Unknown 不计为 0。
3. 搜索与筛选区。
4. M 投资者账户表格。
5. 分页与数据更新时间。

### 3.3 搜索与筛选

| 字段 | 控件 | 规则 |
|---|---|---|
| 关键词 | 输入框 | M 账户编号、脱敏姓名、脱敏邮箱；不支持证件号全文搜索 |
| M 账户状态 | 下拉 | 全部、正常、受限、暂停、关闭（如有权威状态） |
| KYC 状态 | 下拉 | 全部、未开始、处理中、待补件、通过、未通过、已过期、状态待同步 |
| KYC 服务异常 | 下拉 | 全部、无异常、同步失败、结果 Unknown、需投资者操作 |
| Issuer 关系 | 下拉 | 全部、有有效授权关系、无有效授权关系 |
| 注册时间 | 日期范围 | M 账户注册时间 |

默认展示最近更新且有待处理事项的账户；无待处理时按最近更新时间倒序。切换筛选回到第一页。

### 3.4 列表字段

| 字段 | 展示规则 |
|---|---|
| M 账户编号 | 唯一 M Investor ID |
| 投资者 | 脱敏显示名；不得显示完整身份信息 |
| 邮箱 | 脱敏邮箱 |
| M 账户状态 | 正常/受限/暂停/关闭；与 KYC 状态分列 |
| KYC 状态 | Provider 权威状态摘要 |
| KYC 有效期 | Provider 提供时显示到期日；未提供则显示「未提供」 |
| Issuer 授权关系 | 有效关系数量；点击进入详情关系区 |
| 服务异常 | 无/同步失败/待核实/需投资者操作 |
| 最近更新时间 | 明确是账户更新时间或 KYC 同步时间 |
| 操作 | 仅「查看详情」 |

不展示投资者资产余额、完整订单、逐笔付款、完整持仓或收益流水。

### 3.5 列表空状态与异常

- 无账户：「当前暂无 M 投资者账户」。
- 筛选无结果：「没有符合条件的账户」，可清除筛选。
- 数据源不可用：「账户数据暂不可用」，不得展示旧缓存为最新。
- 部分字段缺失：「部分状态暂不可用」，缺失字段显示「待核实」。
- 无权限：不展示记录总数或敏感筛选项，提示返回。

## 4. P-18-02｜M 投资者账户详情

### 4.1 页面布局

顶部：M 账户编号、脱敏姓名、M 账户状态、最近更新时间。

主体分为五个区块：

1. 账户基本信息；
2. KYC 核验摘要；
3. Issuer 授权关系；
4. 服务异常与运营任务；
5. 账户访问限制与状态历史。

### 4.2 账户基本信息

| 字段 | 规则 |
|---|---|
| M 账户编号 | 只读、唯一 |
| 展示名称 | 默认脱敏 |
| 登录邮箱 | 脱敏展示 |
| 国家/地区 | 仅展示账户服务所需的国家/地区 |
| 注册时间 | 只读 |
| 账户状态 | 只读摘要；变更通过专门操作 |
| 最近更新时间 | 只读 |

不提供编辑身份信息、替换邮箱、修改证件或合并账户功能。资料更正由投资者在 M 端发起，并由原身份/KYC 流程处理。

### 4.3 KYC 核验摘要

| 字段 | 规则 |
|---|---|
| KYC 状态 | Provider 返回的平台权威状态 |
| Provider 名称 | 只读 |
| Provider Case 引用 | 脱敏/部分隐藏，不暴露原始 Payload |
| 提交时间 | 有数据时显示 |
| 最近核验时间 | Provider 结果时间 |
| 平台最近同步时间 | 区分核验时间和同步时间 |
| 有效期 | Provider 提供时显示 |
| 结果原因 | 仅显示标准化原因类别/可对投资者展示的说明 |
| 当前同步状态 | 正常、同步中、失败、Unknown |

详情区必须明确提示：「平台展示的是第三方核验结果摘要，平台运营人员不能手工修改核验结论。」

### 4.4 Issuer 授权关系

仅显示 M 账户通过 M 平台建立的必要关系，不显示 V 账户数据。

| 字段 | 规则 |
|---|---|
| Issuer 名称/编号 | 只读 |
| 关系编号 | 唯一引用 |
| 授权状态 | 有效、撤回、过期、待确认等原领域状态 |
| 授权范围 | 仅展示必要的资料/Offering 关系摘要 |
| 授权时间/失效时间 | 有数据时显示 |
| 来源 | M 端授权流程 |

关系数量不等于可认购数量；P-18 不提供代投资者新增、撤回或扩大授权的按钮。需要变更授权时由投资者在 M 端完成。

### 4.5 服务异常与运营任务

展示：
- KYC Provider 同步失败/超时/Unknown；
- KYC 结果已过期或需要投资者补件；
- 投资者通知发送失败；
- M 账户服务访问异常；
- 关联 M17 任务编号、负责人、状态、最近处理记录；
- M18 通知发送状态摘要。

「任务已关闭」不代表 KYC 已通过或 Provider 状态已更新；必须以原 KYC 权威状态为准。

### 4.6 允许操作

| 操作 | 条件 | 结果 |
|---|---|---|
| 查询最新 KYC 状态 | 存在 Provider Case 引用且当前账号有权限 | 查询原 Case；不创建新 KYC 申请，不修改核验结论 |
| 通知投资者补充/更新资料 | KYC 状态为待补件、已过期或 Provider 明确要求投资者操作 | 经 M18 发送通知，记录模板、接收方、发送结果 |
| 创建/关联服务任务 | 存在同步、通知或账户服务异常 | 创建/关联 M17 任务；任务状态不替代 KYC/账户状态 |
| 限制 M 账户服务 | 有明确平台安全/服务依据，当前账户可限制 | 进入限制确认；不修改 KYC、订单、持仓、法定登记或 Token |
| 恢复 M 账户服务 | 原限制原因已解决，且当前账号有权限 | 记录恢复依据，恢复平台账户服务；不改变 KYC 结果 |

### 4.7 限制账户确认弹窗

必填：
- 限制原因类别：账户安全、疑似冒用、平台服务滥用、依法/依规则要求、其他；
- 具体原因说明；
- 影响范围说明（M 平台服务访问，不涉及资产/订单/资金主账）；
- 关联证据或 M17 任务；
- 操作备注。

系统显示：
- 当前账户状态；
- 限制后影响；
- 既有订单、持仓、收益和法定义务继续保留；
- 是否需要按平台规则进行第二人复核（若规则要求）。

按钮：「确认限制 M 账户」「取消」。

### 4.8 恢复账户确认弹窗

必填：
- 原限制原因；
- 原因解决说明；
- 证据/任务引用；
- 操作备注。

按钮：「确认恢复 M 账户」「取消」。

限制/恢复均追加状态历史，不覆盖原记录。

## 5. 状态与业务守卫

### 5.1 KYC 状态展示

| 状态 | P-18 展示 | 业务含义 |
|---|---|---|
| 未开始 | 未开始 | 投资者尚未提交；不满足认购 KYC Gate |
| 处理中 | 核验中 | 等待 Provider 结果 |
| 待补件 | 需要投资者补充资料 | P-18 可通知投资者；不能代填 |
| 通过 | 已通过 | 仅表示 KYC Gate 满足，其他 Offering 条件仍需独立判断 |
| 未通过 | 未通过 | 不满足 KYC Gate；不由 P-18 改写 |
| 已过期 | 已过期 | 需按 Provider 流程重新核验 |
| Unknown/同步失败 | 状态待核实 | 不得按通过处理；查询原 Case 并建立异常任务 |

### 5.2 M 账户状态

- 正常：可按 M 业务规则使用账户。
- 受限：P-18 在获授权且原因、影响范围完整时，点击「确认限制 M 账户」由正常转为受限；具体范围和期限在详情中明确。原限制解除并完成确认后，点击「确认恢复 M 账户」由受限返回正常。重复提交同一操作先查原操作 ID，不形成第二次状态变化。
- 暂停：若 M 账户权威领域已有暂停状态，P-18 只读展示原因、来源和恢复路径；本规格未授权 P-18 通过限制/恢复按钮新建或解除暂停。
- 关闭：若原账户领域已有关闭状态则只读展示；P-18 不提供删除、恢复关闭账户或清除历史数据的操作。

账户状态与 KYC 状态分开更新，不允许以「限制账户」伪造 KYC 未通过，也不允许以「KYC 通过」自动恢复平台账户。

### 5.3 交易与权利保护

- KYC 未通过、已过期、待补件或 Unknown 时，M 认购流程必须由原交易 Gate 阻断新认购；P-18 不手动设定单个 Offering 的 Eligible/Purchasable。
- 账户限制不删除或重写已有订单、付款、配售、持有人登记、Token、收益或本金义务。
- 账户暂停后，投资者既有权利查询与法定义务履行仍须有合规可用路径；不能因登录受限而消灭权利。
- KYC 状态恢复以 Provider 新的权威回执为准；通知发送成功不等于补件完成，Provider 接收不等于审核通过。

## 6. 页面异常与反馈文案

| 场景 | 页面反馈 | 下一步 |
|---|---|---|
| KYC 查询成功 | 「已获取最新核验状态」 | 更新显示 Provider 返回值及同步时间 |
| KYC 查询 Unknown | 「查询结果待核实，请勿重复发起」 | 保留原 Case/操作 ID，查询原请求 |
| Provider 不可用 | 「暂时无法获取核验状态」 | 创建/关联 M17 任务；不修改 KYC 状态 |
| 通知发送失败 | 「通知未成功送达」 | 查看 M18 记录并按规则重试 |
| 账户限制结果 Unknown | 「账户状态变更待核实」 | 查询原操作，不重复提交 |
| 限制/恢复成功 | 「账户服务状态已更新」并显示原操作 ID、操作人、时间 | 留在详情，刷新状态卡和历史；返回列表时同步状态 |
| 账户状态已被他人更新 | 「账户状态已变化，请刷新后再操作」 | 刷新详情后重新判断按钮条件 |
| 无权访问敏感信息 | 「当前账号无权查看该资料」 | 如有业务目的，走 P-11/P-12 受控申请 |

## 7. 角色与权限边界（逻辑级）

| 角色职责 | 允许 | 禁止 |
|---|---|---|
| 投资者运营 | 查看 M 账户脱敏资料、KYC 摘要、授权关系；通知、建任务 | 手工改变 KYC 结论、修改身份资料、合并账户 |
| 平台账户安全运营 | 在授权范围限制/恢复 M 账户服务访问 | 修改投资者订单、资金、持仓、法定名册或 Token |
| KYC 服务运营 | 查询 Provider Case、跟踪同步异常、通知投资者 | 代替 Provider 审核或手工通过 |
| 安全/审计 | 按合法目的走 P-11/P-12 受控访问和审计 | 无目的查看完整 KYC/AML 原件或批量导出 |

具体角色码、审批人和职责分离沿用 P-09/P-10、P-11/P-12 的后续权限矩阵；本文件不新增后台角色系统。

## 9. 桌面 Web 验收用例

1. 列表只展示 M 统一投资者账户，不出现 V 企业门户账户。
2. 搜索支持 M 账户编号及脱敏姓名/邮箱，不提供证件号全文搜索。
3. KYC 通过、处理中、待补件、未通过、已过期、Unknown 分别正确显示。
4. 点击「查询最新 KYC 状态」只查询原 Provider Case；不创建第二个 KYC 申请，不手工修改结果。
5. KYC 待补件/已过期时通知投资者，通知状态与 KYC 状态分开。
6. Provider Unknown 时显示待核实，不能被前端标记为通过。
7. 限制 M 账户服务后，KYC 状态不变化，既有订单/持仓/收益/法定登记事实保留。
8. 恢复账户服务须填写原因解决说明，历史限制记录不删除。
9. 相同邮箱/姓名/证件不触发 M 与 V 账户合并。
10. 普通运营账号无法查看完整证件、原始 KYC 报告或 AML/制裁详情。
11. P-18 不提供逐笔订单、资金余额、法定名册、Token 操作或收益出款。
12. 未执行用例标记 Not Executed，不得标记 PASS。

- 不建设全平台跨 V 投资者库、投资者 CRM 或高级客服系统。
- 不恢复已取消的独立投资者资格审核。
- 不做批量导出、批量账户限制或批量 KYC 状态覆盖。
