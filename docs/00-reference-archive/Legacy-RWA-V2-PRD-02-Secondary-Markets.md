二级市场交易（AMM 市场 + C2C 市场，快捷交易聚合 / 专业版交易终端）
文档状态：草稿 v2.0（重构为双市场架构）
PRD 系列共 4 份：① 身份认证与一级市场 ② 二级市场（本文档） ③ 合约功能 PRD ④ Open API / SaaS / 白标 PRD
覆盖范围：投资者端（Investor App）买卖双方交易操作、发行方后台（Issuer Console）二级市场上架与版税配置、平台运营后台（Admin）手续费与市场管控

1. 需求背景
1.1 为什么做
一级市场认购解决了资产"从0到1"发行的问题，但投资者退出、调仓、议价的诉求需要依靠二级市场承接。V1 没有真正意义上的二级市场，用户之间转让资产只能靠链上点对点操作，既无价格发现机制，也无流动性保障。
1.2 当前存在的问题
- 纯链上点对点挂单/撤单：每次建单、撤单都要消耗 Gas 且冻结资产，用户"试探性挂单"的成本极高，导致市场深度不足。
- 没有区分资产特性设计交易方式：份额型资产（ERC-20）与单件/批次型资产（ERC-721/1155）的流动性特征完全不同，用同一套机制处理会导致定价失真或无法成交。
- 普通用户理解门槛高：若要求用户自己判断"这个资产该去哪个市场、用什么方式交易"，会大幅提高使用门槛。
- 发行方缺乏二级市场的持续收益机制：一次性发行费之外，发行方无法从资产后续的二级流通中获得收益，降低了发行方对资产长期价值维护的动力。
1.3 解决什么问题
建立"AMM 市场 + C2C 市场"双底层市场架构：AMM 面向份额型资产提供即时流动性，C2C 采用类 Seaport 协议的链下签名订单机制面向份额型与单件/批次型资产提供灵活议价能力，并支持版税分成。在此之上提供"快捷交易"聚合入口屏蔽底层市场差异，同时提供"专业版交易终端"满足深度定价与限价委托需求。

---
2. 产品目标
2.1 业务目标
- 通过聚合路由降低普通用户的二级交易认知门槛，提升二级市场活跃度。
- 通过专业版交易终端满足高频/机构用户对深度行情与限价委托的诉求。
- 通过版税机制为发行方提供持续性二级收益，增强发行方长期入驻与维护资产的意愿。
- 建立平台二级交易手续费收入来源（覆盖 AMM 与 C2C 两个市场）。
2.2 用户目标
- 普通投资者：无需理解 AMM/C2C 的区别，输入价格数量即可完成买卖，系统自动处理底层执行路径。
- 专业投资者：能看到完整行情、K线走势、订单簿深度，可自主选择限价或市价方式委托。
- 发行方：可自主决定资产是否上架 AMM（并提供流动性）、是否上架 C2C，以及是否为 721/1155 类资产开启版税并从后续每笔转手交易中持续获益。
- 平台运营：统一管控二级市场手续费与异常熔断，监控订单簿健康度（巡检机制运行状态）。

4. 需求范围
4.1 本期做什么
1. AMM 市场：面向 ERC-20（份额型）资产，由发行方注入初始流动性上架，提供实时兑换报价。
2. C2C 市场（类 Seaport 协议风格）：面向 ERC-20 / ERC-721 / ERC-1155 资产的链下签名订单撮合，支持出售挂单（Listing）与求购挂单（Offer/Bid）两个方向，链上原子结算时支持多收款方分账（卖方 + 平台手续费 + 版税）。
3. 版税（Royalty）：仅 ERC-721 / ERC-1155 资产支持，由发行方配置开关、比例与接收地址，每笔 C2C 成交自动按比例分配。
4. 快捷交易（聚合路由）：用户输入价格与数量，系统自动判断从 AMM 或 C2C 执行，屏蔽底层市场差异。
5. 专业版交易终端：交易标的列表、行情信息、价格走势图（K线）、内嵌快捷交易、限价单/市价单委托、订单簿深度、订单记录。
6. 平台手续费统一配置（Admin，覆盖 AMM 与 C2C 两个市场）。
7. 挂单过期机制：C2C 挂单必须设置过期时间。
8. 订单维护巡检：系统定时检测挂单人余额/授权是否仍满足挂单条件，自动清理失效挂单。
9. 二级交易与 PRD-01 熔断机制的联动。
4.2 本期不做
- 二级市场（AMM/C2C）本身即为全平台统一公开市场，不存在按发行方/租户/接入渠道的隔离设计，故无需讨论"隔离与互通"（【已确认，见《Open API / SaaS / 白标 PRD》模块七的最新澄清】）。
- AMM 具体做市算法、Seaport 风格结算合约的技术实现（见《合约功能 PRD》）。
- 荷兰拍卖、英式拍卖等高级订单类型（Seaport 协议本身支持，但本期只做限价单与市价单，不做拍卖机制）。
- 场外大宗交易（OTC）、第三方做市商专项协议接入。
- 向普通投资者开放 AMM 流动性提供（LP）——本期流动性仅由发行方提供。
- 期权、期货、借贷、质押等衍生与组合玩法。

5. 产品流程
5.1 资产上架二级市场流程（发行方视角）
```Plaintext
发行方进入资产的"二级市场管理"页
  → 配置是否上架 AMM 市场（仅 ERC-20 可选）
       若选择上架 → 注入初始流动性（Token + 计价币种）→ 钱包签名转入 → AMM 市场生效
  → 配置是否上架 C2C 市场（ERC-20/721/1155 均可，默认开启）
  → 若资产为 ERC-721/1155 → 可选开启版税（比例 + 接收地址）
  → 保存生效```
5.2 快捷交易（聚合路由）流程
```Plaintext
用户在快捷交易面板输入 买入/卖出 + 数量 + 价格（作为可接受价格的保护线）→ 提交
  → 系统查询该资产已上架的市场
      ├─ 仅上架 AMM → 查询 AMM 报价，满足价格条件则直接兑换
      ├─ 仅上架 C2C → 查询订单簿中满足条件的对手单，直接吃单；
      │              无法完全满足时，剩余部分转为一笔新的 C2C 限价委托挂入订单簿
      └─ AMM 与 C2C 均已上架 → 比较两个市场的可执行价格，选择对用户更有利的一方执行
  → 展示执行结果：全部成交 / 部分成交并转为挂单等待撮合 / 提交失败```
5.3 专业版限价/市价委托流程
```Plaintext
用户进入专业版交易终端 → 选择交易标的 → 查看行情、K线与订单簿深度
  → 选择委托类型
      ├─ 限价单：输入价格 + 数量 + 过期时间 → 提交为 C2C 的 Listing（卖出）或 Offer（买入）→ 挂入订单簿
      └─ 市价单：输入数量 → 按当前最优可执行价格立即成交（逻辑与快捷交易一致）
  → 在"订单记录"中查看当前委托 / 历史成交 / 历史委托（含已撤销/已过期/已失效）```
5.4 挂单过期与失效巡检流程
```Plaintext
系统定时巡检任务（频率见 14.5 待确认）：
  → 扫描全部 C2C 有效挂单
      ├─ 已超过设置的过期时间 → 标记"已过期"，从可撮合订单簿移除
      └─ 检测挂单人当前资产余额/授权是否仍满足挂单条件
             不满足 → 标记"已失效"，从订单簿移除，并站内通知挂单人
  → 巡检任务运行状态记录，供 Admin 监控```

6. 功能需求
模块一：AMM 市场（发行方主导流动性）
功能 1.1 资产上架 AMM 与流动性注入
- 功能描述：发行方为 ERC-20 资产开通 AMM 市场，注入初始流动性，确定起始兑换价格。
- 操作流程：进入资产"二级市场管理" → 开启"AMM 市场" → 输入初始流动性数量（Token + 计价币种）→ 钱包签名转入 → AMM 市场生效。
- 页面元素：AMM 开关、流动性双边数量输入、预计初始价格展示、流动性池状态展示（TVL、当前比例价格）、提交按钮。
- 业务规则：
  - 仅 ERC-20（份额型）资产支持 AMM 市场。
  - 【已确认】AMM 初始流动性由发行方提供，不由平台垫资，本期不向普通投资者开放做市（LP）参与。
  - 【待确认】流动性注入后是否允许发行方追加/撤出？撤出是否需要限制条件（如公告期、最低保留比例），避免发行方单方面抽干流动性损害持有人。
- 成功结果：AMM 市场生效，可被快捷交易与专业版路由和展示。
- 异常情况：流动性数量不合理导致初始价格异常、发行方钱包余额不足、重复开通。
功能 1.2 AMM 报价与兑换执行（底层能力）
- 功能描述：为快捷交易与专业版市价单提供 AMM 侧的实时报价与兑换执行能力。
- 业务规则：报价随池内比例实时变动；兑换需做滑点保护；手续费从成交额中扣除（比例见模块五）。
- 说明：具体交互界面在模块三、模块四中呈现，此处仅定义底层规则。

---
模块二：C2C 市场（Seaport 协议风格挂单撮合）
功能 2.1 发起出售挂单（Listing）
- 功能描述：卖方将持有资产（ERC-20/721/1155）以指定价格挂出，设置过期时间，供买方直接购买或被快捷交易路由匹配。
- 操作流程：选择资产 → 输入价格、数量（ERC-721 固定为1）、过期时间 → 若资产已开启版税，展示版税信息（只读）→ 钱包 EIP-712 签名 → 提交至链下订单簿。
- 页面元素：价格输入、数量输入、过期时间选择器（预设选项+自定义，见8.2上限）、费用明细预览（成交后：卖方到账=成交额−平台手续费−版税）、签名确认弹窗。
- 业务规则：
  - 【已确认，本次新增】挂单必须设置过期时间，不支持"永久有效"。
  - 挂单为链下签名，不锁定链上资产；系统通过定时巡检（模块六）主动检测余额是否仍充足，降低"吃单时才发现失效"的概率，吃单时的链上校验作为最后一道防线。
  - 版税信息仅展示不可由卖方编辑，由发行方在资产层面统一配置。
  - 卖方资产处于锁仓期内时不可挂单。
- 成功结果：挂单生效，进入 C2C 订单簿。
- 异常情况：过期时间不合法、价格非法（≤0）、同一 ERC-721 资产重复挂单【待确认处理方式，见 14.4】。
功能 2.2 发起求购挂单（Offer / Bid）
- 功能描述：买方主动出价求购某资产，等待卖方接受，或被快捷交易/市价单路由匹配。
- 操作流程：选择资产 → 输入愿意支付的价格、求购数量、过期时间 → 钱包签名（需具备对应支付资金的锁定/授权，具体机制见《合约功能 PRD》）→ 提交至链下订单簿。
- 页面元素：与 Listing 类似，标记为"求购"类型；资产详情页展示"当前最高求购价"供潜在卖方参考。
- 业务规则：与 Listing 对称，过期时间同样必填；同样纳入巡检范围（检测买方资金是否仍充足）。
- 成功结果：求购单生效，卖方可在资产详情页/专业版看到并选择接受，或被路由匹配。
- 异常情况：买方资金不足、重复求购。
功能 2.3 撤单
- 功能描述：用户撤销自己发起的挂单（Listing 或 Offer），零 Gas 完成。
- 操作流程：进入"我的订单记录" → 选择目标订单 → 确认撤单 → 系统标记订单为已撤销并递增该用户订单 nonce。
- 业务规则：撤单不消耗 Gas，仅修改链下订单簿状态；已进入吃单结算流程（对手方已提交链上交易未确认）的订单不可撤销。【待确认】nonce 递增策略是否会误伤用户其他有效挂单，需与《合约功能 PRD》对齐。
- 成功结果：订单从可撮合订单簿中移除。
- 异常情况：撤销结算中的订单被阻止并提示。
功能 2.4 吃单成交
- 功能描述：用户接受订单簿中一个或多个 Listing/Offer 完成成交，支持批量吃单一次性结算。
- 操作流程：选择一个或多个挂单 → 系统对选中订单做链上有效性预检查 → 组装为一笔批量结算交易 → 用户签名广播 → 链上完成资金结算与资产转移。
- 业务规则：
  - 结算时按顺序从成交总额中扣除：平台手续费 → 版税（如已开启），剩余部分为卖方（或求购单场景下资产原持有人）实际到账金额。
  - 批量吃单时若部分订单已失效（资产/资金已变动），自动剔除失效订单，仅结算有效部分并告知用户。
  - ERC-1155 支持部分数量成交，剩余数量继续挂单；ERC-721 只能整单成交。
  - 买卖双方均需满足 KYC 与 Eligibility 规则。
- 成功结果：链上完成批量结算，双方持仓更新。
- 异常情况：全部选中订单已失效、部分失效、Gas不足、买方资格不满足。
功能 2.5 版税（Royalty）配置
- 功能描述：发行方为 ERC-721/1155 资产开启二级交易版税，设置比例与接收地址，每笔 C2C 成交自动分配。
- 操作流程：进入资产"二级市场管理" → 开启"版税"开关 → 设置比例、接收地址（默认发行方地址，也可指定其他 Party）→ 保存。
- 页面元素：版税开关、比例输入、接收地址选择/输入、生效范围说明。
- 业务规则：
  - 【已确认】版税仅在 C2C 市场生效；AMM 市场因是同质化份额兑换池，不支持版税。
  - 【待确认】版税比例是否设置平台侧上限（行业惯例通常 ≤10%），避免发行方设置过高比例影响流通性。
  - 【待确认】版税配置创建后是否允许修改；若允许，是否只对未来新挂单生效，已挂单按挂单时的快照执行。
  - 平台手续费 + 版税比例之和不可超过合理上限（【产品建议】不超过成交额的 100%，且需设定一个更严格的软上限如 20%，防止卖方到账过低引发投诉，具体数值待确认）。
- 成功结果：该资产后续 C2C 成交自动按比例扣除版税并转给接收方。
- 异常情况：比例超出上限、接收地址格式错误。

模块三：快捷交易（聚合路由）
功能 3.1 快捷买入/卖出
- 功能描述：用户输入价格与数量，系统自动判断路由到 AMM 或 C2C 完成交易，无需了解底层市场结构。
- 操作流程：见 5.2 节。
- 页面元素：买入/卖出 Tab、数量输入、价格输入（作为可接受价格的保护线）、执行结果预告展示（"预计从AMM即时成交" / "当前价格暂无法完全满足，将转为挂单等待撮合"）、确认按钮。
- 业务规则：
  - 价格含义：买入时为愿意支付的最高单价，卖出时为愿意接受的最低单价。
  - 【待确认，见 14.1】AMM 与 C2C 都可满足条件时的路由优先级规则；两者均无法完全满足数量时，是否支持"部分从 AMM 成交 + 剩余转 C2C 挂单"的拆分执行——【产品建议】本期先不做拆分，按"能否被单一市场满足"判断，不满足则全部转为一笔 C2C 挂单，降低体验复杂度。
  - 若资产未上架 AMM，直接按 C2C 求购/吃单逻辑处理。
- 成功结果：交易完成，或转为 C2C 挂单等待撮合。
- 异常情况：两个市场均无法满足最低成交条件；价格保护线设置不合理（如买入价远低于当前最低卖价）时，提示"当前价格可能长时间无法成交"。

模块四：专业版交易终端
功能 4.1 交易标的列表
- 功能描述：展示平台内可交易资产列表，支持切换查看不同标的的行情与交易面板。
- 页面元素：标的列表（资产名称、最新价、24h涨跌幅、24h成交量）、搜索/筛选（按资产类型/所属市场）。
- 异常情况：列表为空、数据加载失败。
功能 4.2 行情信息与价格走势图
- 功能描述：展示选中标的的关键行情指标与历史价格走势（K线）。
- 页面元素：最新成交价、24h最高/最低价、24h成交量、K线图（周期切换：分钟/小时/日）。
- 业务规则：行情数据来源于链上成交事件（AMM兑换 + C2C成交）经 Indexer 解析聚合生成。
- 异常情况：新上架资产无历史数据时的 Empty 态展示（"暂无历史行情"）。
功能 4.3 内嵌快捷交易面板
- 功能描述：在专业版页面内提供与模块三一致的聚合快捷交易能力，便于用户无需切换页面即可快速下单。
- 说明：功能逻辑与功能 3.1 完全一致，此处仅为界面位置说明，不重复定义规则。
功能 4.4 专业委托（限价单 / 市价单）
- 功能描述：支持用户发起限价委托（挂入 C2C 订单簿等待撮合）或市价委托（立即按最优价成交）。
- 操作流程：
  - 限价单：输入价格、数量、过期时间 → 提交为 C2C 的 Listing/Offer（见功能2.1/2.2）。
  - 市价单：输入数量 → 系统按当前最优可执行价格（AMM 或 C2C 最优对手价）立即撮合成交。
- 页面元素：限价/市价切换 Tab、价格与数量输入（限价）、数量输入（市价）、预计成交结果展示、订单簿深度（买卖盘）。
- 业务规则：市价单本质是快捷交易的另一入口，共用同一撮合与路由逻辑，不单独定义。
- 成功结果：限价单生效挂单；市价单立即完成成交。
- 异常情况：市价单在流动性不足以满足全部数量时的处理方式【待确认，见14.6：部分成交自动放弃剩余，还是转为限价单挂单等待】。
功能 4.5 订单记录
- 功能描述：查看当前委托（未成交/部分成交挂单）与历史成交/历史委托记录。
- 页面元素：当前委托列表（含撤单入口）、历史成交列表、历史委托列表（区分已撤销/已过期/已失效三种终止原因）。
- 业务规则：明确区分"已过期"（到达设置的过期时间，正常终止）与"已失效"（巡检发现余额/资金不足，异常终止），分别展示不同的状态提示文案。

模块五：手续费与版税管理（Admin）
功能 5.1 平台手续费配置
- 功能描述：Admin 统一配置二级市场交易手续费比例，覆盖 AMM 与 C2C 两个市场。
- 操作流程：进入手续费配置页 → 设置 AMM / C2C 手续费比例（是否分开配置见待确认）→ 保存生效。
- 业务规则：
  - 【已确认，本次澄清】二级市场交易手续费由平台统一收取；发行方的二级收益诉求通过独立的版税机制满足，不再从平台手续费中分成。
  - 【待确认】AMM 与 C2C 是否使用同一费率，还是分别配置。
  - 手续费与版税是两笔独立扣除项，均以成交总额为基数计算，互不影响彼此。
  - 【产品建议】新挂单/新兑换生效时锁定当次手续费比例快照，避免历史挂单因全局费率调整而与挂单时预期不符。
- 成功结果：新成交按更新后费率执行。
- 异常情况：比例设置超出合理范围。
功能 5.2 版税监控
- 功能描述：Admin 可查看全平台已开启版税的资产列表及配置详情，异常时可介入处理。
- 业务规则：【待确认】Admin 是否有权强制修改/关闭发行方设置的版税，还是仅有只读监控权限。

模块六：订单维护巡检（系统）
功能 6.1 挂单过期自动清理
- 功能描述：系统定时扫描全部 C2C 挂单，将超过设置过期时间的挂单标记"已过期"并从可撮合订单簿移除。
- 业务规则：过期挂单不可再被吃单，记录保留供用户在订单记录中查看，不做删除。
- 成功结果：订单簿中不再展示已过期的挂单。
功能 6.2 挂单有效性巡检（余额/授权检测）
- 功能描述：系统定时检测所有有效挂单对应用户的资产余额/授权额度是否仍满足挂单条件，不满足则自动清理并通知用户。
- 操作流程：定时任务扫描 → 核对链上余额与挂单所需数量/资金 → 不足 → 标记"已失效"、从订单簿移除 → 站内通知用户。
- 业务规则：
  - 【待确认】巡检频率（如每5分钟/每小时），直接决定"挂单已失效但仍展示"窗口期的长短。
  - 巡检本身不产生费用（挂单未上链，无 Gas 成本）。
- 成功结果：订单簿中长期保持"大概率可成交"的有效挂单，降低吃单失败率。
- 异常情况：巡检任务故障导致清理不及时——仍有吃单时的链上校验作为最后防线，双重保障不会导致资金损失，只影响体验。

8. 业务规则
8.1 金额与数量
- ERC-721 挂单数量固定为1，不可部分成交；ERC-1155 支持部分数量成交。
- 成交扣除顺序：成交总额 → 扣除平台手续费 → 扣除版税（如已开启）→ 剩余部分为卖方到账金额；手续费与版税均以成交总额为基数独立计算，不叠加计算基数。
- 【待确认】平台手续费 + 版税比例之和的软上限（防止卖方到账过低）。
8.2 时间
- 【已确认】C2C 挂单必须设置过期时间，不支持永久有效。
- 【待确认】过期时间的可选范围与上限，【产品建议】提供 1天/7天/30天预设选项，并设置自定义上限（如不超过90天）。
- 巡检任务按固定频率运行【待确认具体频率】。
8.3 权限
- 仅资产的发行方可配置该资产的 AMM 上架/流动性、C2C 上架开关、版税。
- 仅 KYC 已通过且满足 Eligibility 规则的用户可参与买卖。
- 仅 Admin 可配置平台手续费、监控版税、管理熔断开关。
8.4 状态
详见第9节状态流转。
8.5 限制条件
- 平台不代签：挂单、撤单、吃单均由用户钱包签名。
- AMM 仅支持 ERC-20；版税仅支持 ERC-721/1155。
- 锁仓期内资产不可挂单/参与快捷卖出。
8.6 计算规则
- AMM 兑换结果按实时报价公式计算（具体见《合约功能 PRD》），前端展示"预计获得数量"与"价格影响百分比"。
- C2C 成交金额 = 挂单/委托单价 × 成交数量；平台手续费 = 成交金额 × 手续费比例；版税 = 成交金额 × 版税比例；卖方到账 = 成交金额 − 平台手续费 − 版税。

13. 验收标准
正常场景
- 发行方可完整走通"开启AMM+注入流动性"或"开启C2C（+可选版税）"的资产上架流程。
- 用户可通过快捷交易输入价格数量完成买卖，系统正确路由至AMM或C2C并展示执行结果。
- 用户可在专业版查看标的列表、行情、K线，并完成限价单挂单与市价单即时成交。
- C2C成交时手续费与版税（如开启）按配置比例正确扣除并分配。
- 挂单必须设置过期时间方可提交；到期后自动从订单簿移除。
- 巡检任务可定时检测并清理余额不足的失效挂单，用户收到站内通知。
异常场景
- 未满足KYC/Eligibility的用户无法交易，即使绕过前端也应被合约拒绝。
- 平台手续费与版税之和不会导致卖方到账为负。
- AMM与C2C均无法满足快捷交易价格条件时，给出明确提示而非静默失败。
边界场景
- ERC-1155挂单被部分吃单后剩余数量正确保留。
- 挂单恰好在被吃单的同时到达过期时间，系统应有明确的优先级判定【待确认】。
- 版税比例设置为上限值时计算结果仍正确（手续费+版税不超过约定软上限）。

14. 风险与待确认事项
14.1 产品风险（路由决策规则）
- 快捷交易在AMM与C2C均可满足条件时的路由优先级规则，以及是否支持拆分执行，直接影响用户体验与实现复杂度，建议尽快明确（本文档产品建议为"本期不做拆分，单一市场判断"）。
14.2 业务风险（版税可持续性）
- 版税机制依赖交易在平台内完成才能强制执行；如果资产的转让权限允许绕过平台前端直接链上转移（如直接调用合约转账而非通过市场结算），版税与手续费都可能被规避。需要与《合约功能PRD》确认版税强制执行的技术边界，并如实向发行方说明"版税可被规避"的可能性，避免过度承诺。
14.3 技术依赖
- 依赖 PRD-01 中已确立的身份、KYC、Eligibility、Capacity 等合规基础设施。
- 依赖《合约功能PRD》中 AMM 合约、Seaport风格结算合约、多收款方分账机制的实现。
- 依赖 Indexer 服务作为成交、行情、持仓数据的唯一来源。
14.4 待确认问题（订单规则）
- 同一 ERC-721 资产是否允许重复挂多笔（Listing/Offer）。
- 过期时间的可选范围与上限。
- 巡检任务的运行频率。
- nonce 撤单策略：全量失效 vs 单笔失效。
14.5 待确认问题（AMM流动性）
- 发行方注入流动性后是否允许追加/撤出，撤出是否需要限制条件。
- AMM 与 C2C 手续费是否分开配置。
14.6 待确认问题（版税与手续费）
- 版税比例是否设置平台侧上限。
- 版税配置创建后能否修改，修改是否只影响未来新挂单。
- 平台手续费+版税比例之和的软上限具体数值。
- 专业版市价单在流动性不足以满足全部数量时：允许部分成交、自动转为限价单挂单，还是直接失败，三选一需要确认。
