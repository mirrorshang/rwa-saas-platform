# DEC-072｜RWA SaaS V1 Offering 发行方案模块 UI-Ready 收口

> **日期：2026-11-11**  
> **状态：V1 企业 SaaS 产品/UI 规则已收口**  
> **决策依据：用户明确批准发行方案列表推荐方案 A，并明确授权产品负责人独立完成后续各模块 MVP 闭环，尽量不逐页重复征求确认。**  
> **适用范围：Issuer 企业 SaaS 的 Offering 发行方案模块。**

## 1. 决策背景

Offering 的基础业务原则 R01～R36 已逐批获得用户批准；DEC-069 已将投资者 KYC 收敛为平台统一强制规则并取消 Issuer 额外资格配置；DEC-070 已补充 Asset 相关方的逐期投资者披露。

此前 Offering 字段级文档和状态/异常矩阵仍标记为候选，缺少完整的页面信息结构、字段控件、状态操作、空态/错误态、投资者端预览和跨模块跳转。

用户于 2026-11-11 明确：
1. 同意发行方案列表推荐方案 A；
2. 授权产品负责人独立完成后续模块的 MVP 闭环和产品细节设计，尽量不再逐页询问；
3. 每完成一个模块，将其独立写入 GitHub 文档。

据此，产品负责人在既有批准规则和授权范围内完成 Offering 模块 UI-Ready 收口。

## 2. 已确认的页面结构

Offering 继续位于：

**资产与发行 → 资产管理 → Asset 详情 → 发行管理 TAB**

模块包含：
1. 发行方案列表；
2. Offering 创建/编辑单页；
3. 发行准备与两层检查；
4. 投资者端内部预览及发布前最终确认；
5. Offering 详情与生命周期管理。

不新增 Offering 二级菜单、Project 菜单或独立发行准备页面。创建/编辑仍采用单页 A/B/C 分区，不采用三步向导。

## 3. V1 产品/UI 收口规则

### 3.1 发行方案列表

- 展示发行名称、状态、认购时间、发行数量、每 Token 价格、计划最高募集额、最近更新和唯一操作。
- 支持发行名称搜索、状态筛选，按创建时间倒序；简化分页和移动端卡片。
- 草稿提供「继续完善」，其他状态提供「查看详情」。
- 不在列表直接执行暂停、恢复、结束、关闭等高风险操作。
- 只有当前 Asset 的 Instrument 确定版本 Ready 时，才允许创建 Offering Draft；创建时再次校验并固定版本。

### 3.2 创建与编辑

- 发行信息、认购规则、发行准备为同页三个分区，不是步骤。
- 自动继承 Asset、InstrumentVersion、每 Token 权利及真实可用容量；不要求重复录入。
- 本期发行数量为正整数且不得超过最新可用份数；每 Token 固定价格和单笔最低认购金额以 U 表示；计划最高募集额由数量×价格计算。
- 最低认购金额换算为整数 Token 份数，并展示实际最低应付金额；不能整除时向上满足最低金额，不静默截断。
- 认购开始时间、结束时间和明确时区均须填写；开始早于结束；未来开始不得提前显示认购中。
- V1 锁仓仅支持不锁仓或单一固定天数，不支持分期/分层锁仓；固定天数从 Token 实际交付时点起算。
- OP Mainnet · USDT 为固定只读支付范围。
- 企业最终结算收款钱包从本企业已绑定、已验证且有效的钱包中选择；默认预选企业默认钱包；不允许任意输入陌生地址。
- 认购协议、风险披露及 Asset/Instrument 相关文件按固定文件版本引用。
- Asset 相关方按 Offering 逐期选择披露；对投资者仅展示名称、角色、简要职责和允许公开的注册地区，不展示注册编号、联系人、联系方式、许可编号、内部备注或原始附件。
- 投资者类型、地区、KYC 等级和额外资格配置在 V1 不展示；统一 KYC 通过是固定认购前置条件。

### 3.3 发行准备与预览

- 业务资料完整性与真实生产准入分开显示。
- 业务检查逐项列出 Asset、Instrument、发行参数、认购规则、钱包、文件、披露及最终预览状态，并提供可定位的修复入口。
- 生产准入由套餐/KYB、适用法律合规、平台发行能力、支付结算能力和本期发布条件构成；Unknown/未开放/待确认/未通过均不能视为通过。
- 投资者端预览使用实际投资者端展示结构和字段映射；缺项明确标记，不生成虚假认购、募集、持仓、收益或 Mint 数据。
- Free 仅内部只读预览，不生成公开链接、不发布、不认购、不募资、不 Mint。
- 发布前必须再次最终预览，展示发行条款、权益版本、文件版本、企业最终收款钱包和资产相关方披露快照，并由企业明确确认。

### 3.4 生命周期与操作

- 生命周期状态：草稿、等待开始、认购中、已暂停、认购结束、已关闭。
- 业务资料 Ready 不等于已发布；发布成功且开始时间未到时为等待开始。
- 同一 Instrument 同时最多一轮对外开放认购；允许预先建立多个 Draft，发布时再次检查冲突和权益容量。
- 暂停停止新增认购，不取消既有订单、付款、Token 交付和退款义务；不释放预留。
- 恢复仅在认购期内且生产准入重新满足时可执行；不重复预留。
- 到期停止新认购并进入认购结束；待支付、交付、退款等义务未结清时不得关闭。
- 关闭仅释放没有待处理义务的未分配预留；已交付 Token 保持占用；关闭后不可重新开放。
- V1 不提供发布后直接修改价格、数量、收款钱包、权益版本、法律文件、起止时间、提前结束或延期的自助快捷入口；需要受控处理。
- 认购记录、锁仓记录从 Offering 详情跳转到各自模块，不复制订单、资金、Token 或锁仓主账。

## 4. 权限与边界

| 企业状态 | Offering 产品权限 |
|---|---|
| KYB 通过的新 Free | 可创建/编辑/保存业务 Draft、检查资料、内部只读预览；不可真实发布 |
| Standard 且 KYB 通过 | 可准备和预览；只有全部真实生产准入通过才可能发布 |
| Standard 宽限期 | 按 U01 限制新增真实业务，不可新增真实发行 |
| 降级 Free 的历史企业 | 历史 Offering 只读，不因当前 Free 身份获得新写权限 |
| KYB 未通过/补件/审核中 | 按企业准入规则拦截，不得绕过 |

本决策只收口产品/UI，不授权任何真实资金、Provider、Signer、支付、合约、Mint、链上部署或生产发行操作。
