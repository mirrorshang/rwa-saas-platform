## 一、为何优先使用两类差异明显的 Instrument

| 参考样本（均已批准为**产品验证样本**） | 用来压测哪些产品能力 | 暂不预设的真实法律结论 |
|---|---|---|
| **A｜固定利率、明确到期日的债权型 Instrument**（例：发行机构依法可发行的债权票据/债务证券权益） | 募集/持续认购方式、认购资格、利息周期、计息规则、持有快照、到期本金与利息支付、赎回/销毁、逾期/争议、资金和权威登记核对 | 不假定任何地区均允许持续购买、可直接 Token 化债权、必须采用某种链/监管证券类型，也不假定某服务商有收款/登记资质 |
| **B｜无固定到期日、具有分配或表决可能性的权益型 Instrument**（例：依法成立的项目实体/SPV 的股份或其他权益） | 出资/认购、法定权益持有人登记、份额和稀释、可选分配、披露、转让限制、投票/公司行为的首期取舍、退出和存续期 | 不假定 Token 就是登记在册股份/法定股权，不假定所有 SPV 股份可以数字化转让，也不默认在 V1 实现投票、二级交易或复杂公司行动 |

**已确认**：同时采用 A 债权型与 B 权益型作为两类产品需求验证样本。它们比单用“房产/债券/基金”等资产名称，更能检验 Instrument 法律权利怎样驱动产品功能；**不等于选定真实发行标的、首发国家或生产 Token 权利设计**。

## 二、两种样本需共用的 V1 业务闭环

机构合同/租户开通 → Asset 与 Instrument 结构化权利参数 → Project/Offering 资料/版本/文件/审核发布 → 机构投资者门户 → 投资者 KYC 与 Offering-specific Eligibility → 条款与认购报价快照 → M12 唯一额度预留 → 指定链的真实 USDT/USDC 付款与 M11 独立核验 → 依事先批准规则配售 → 权威登记事实 → 真实链上 RWA Token 交付及独立对账 → 权益快照/必要披露/到期或分配处理。

- 任何样本都不允许 M10 订单成功代替 M11 资金最终到账、M12 配售/登记或 M07 Token 执行成功。
- 参考样本仅用于**产品要素、合法性问题清单和异常路径验证**，不能用假定的法律条件直接推断生产可行。
- 若 A/B 的真实发行模式依法必须集中募集，SCOPE-061 持续购买优先目标应在此类样本上标记为**条件不适用/必须增加募集最小闭环**，不能为了坚持持续购买而违反工具条款。
- 电子签署、正式通知、赎回支付、法定登记和 Token 链上限制以适用责任主体和法域意见为准，产品先列可配置结构。

## 三、参考 Instrument 对关键功能的触发性验证表

| 功能主题 / ID | 样本 A（债权型）检查点 | 样本 B（权益型）检查点 | 对 V1 的可能影响 |
|---|---|---|---|
| M04 Instrument 字段与权利 | 利率、计息基准、到期日、本金债权、违约 | 份额类别、分配规则、权益证明、持有人权利 | 权利字段/合法证据可配置、不可被资产标签代替 |
| M05-F011 / M12-F010 集中募集 | 条款是否允许开放式持续认购或须统一发行 | 是否需封闭募集期、董事/股东批准等 | 触发时提升最小集中募集及失败处置 |
| M10-F009 / M12-F009 部分配售 | 少额、超额、部分接受是否合法 | 份额精度、超额接受/部分配售可否发生 | 资金余款/退款及额度回退 |
| M07-F009 赎回/销毁 | 到期清偿后应否 Burn/冻结/注销、谁有权执行 | 公司退出/份额回购/注销的特定条件 | Token 与法定权益双向核对 |
| M13-F004～F006 收益/兑付 | 应付息日、本金到期、实际对外支付及失败追踪 | 有/无分配、分红决议、资金来源/收款人 | 必要收益/支付最小闭环由权利条款决定 |
| M12-F006 / M22-F004 权威登记 | 法定债权持有人登记方式及权利生效 | 法定股东/份额持有人登记、投票基准时点 | 不能把 Token 持币地址直接当作法定持有人 |
| M07-F007 受控转让限制 | 锁定期、合格投资者/受让人要求 | 受让资格、发行人/董事会许可、ROFR 等 | V1 合约级限制必需，M14 二级受控转让仍 V2 |
| M08-F009 / M18-F004～F005 披露与通知 | 利率调整、兑付通知、违约及正式送达 | 披露、分配与法定事项通知 | 必要通道、送达凭证和失败恢复 |
| M20-F007 / M21-F005～F006 数据报告 | 本息、权利、客户退出/报告 | 持有人、股份/份额、权益变动、客户移交 | 最低受控查询/导出是保障，非大型 BI |
| API-First / ARCH-001 | 统一服务端业务核心支持利息和到期事件 | 同一核心支持权益快照和有条件分配 | 不为每个资产类别重建第二套 SaaS/API |

**执行输入现已获批准**：A 是固定收益且有到期本金义务的债权型，B 是 SPV 股份/类似权益型，两者都只作为**权利结构需求样本**。以下输出要求仍是待完成的验证工作，不应误写成已有实际发行法律合规结论。

## 四、验证输出及门槛

针对每种参考 Instrument 输出以下**产品级规格草稿**：
1. 权利与参与方：发行主体、法律权利人、服务商、法定登记人、收款/退款/兑付执行主体及链上签名授权链。
2. 条款与数据结构：Instrument 参数、Offering 生命周期、投资资格与认购规则、通知/披露、Token 合约应表达的限制与非表达的法律权利。
3. **端到端状态案例**：持续购买成功、KYC/资格不符、少付/多付/迟到账、Unknown/reorg、配售与登记不一致、Mint 失败、退款重复、到期/收益支付失败。
4. 以所有 **187 个 Mxx-Fxxx ID** 为索引新增独立「样本 A 触发」「样本 B 触发」「需要哪些最低功能」「法域决定点」「外部权威证据」列，但**不修改原等级或默认分类**。
5. 最终生成 Issuer SaaS V1 实际必交候选清单；发起正式冻结评审，**仅由产品负责人另行批准**。第 07 份具体技术架构和首发法域/许可/资金责任仍需独立核验。

## 五、已确认的五项参考 Instrument 验证决策（SCOPE-096～SCOPE-100）

| 建议决策 ID | 提案 |
|---|---|
| **SCOPE-096** | V1 范围冻结前使用**两类参考 Instrument** 做需求验证，而非现在锁定首发国家、协议或资产底层 |
| **SCOPE-097** | 样本 A 采用**有固定利息/本金到期义务的债权型 Instrument**，主要验证收益、到期偿付、赎回/Token 销毁及必要通知 |
| **SCOPE-098** | 样本 B 采用**权益型 Instrument**（如依法成立的 SPV 股份/权益），主要验证登记/份额、可选分配、持有人权利与转让限制；不预设 Token 自动产生股权或 V1 具备二级交易 |
| **SCOPE-099** | 对 A/B 使用同一功能树和 API-First 核心，逐 ID 建立能力/状态/证据验证矩阵，按工具触发重新判定条件性 P1；不因样本差异开发两套发行系统 |
| **SCOPE-100** | 两类样本仅用于产品范围验证；法域、真实发行资格、外部资金/登记/密钥责任、具体链/协议、正式 V1 交付清单及商业 White-label/Open API 批次仍属于独立决策门 |
