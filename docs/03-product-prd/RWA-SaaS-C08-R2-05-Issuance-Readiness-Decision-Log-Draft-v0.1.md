| R06 | 检查投资者与披露准备 | 检查KYC服务、必要强制风险规则及披露完整性；不建设Issuer独立Offering投资者资格配置 |

| R10 | 发布和关键变更保护 | 所有适用检查通过后才可发布；发布前关键变化重新检查，发布后不得改写Publication Snapshot及已存在订单条款 |

### 1.1 企业操作路径（MVP）

`Offering Confirmed → 发行准备（单页）→ 查看七组检查/补缺 → 预览投资者页面 → 企业最终声明与确认 → Sandbox模拟发布或受控真实发布`

**Confirmed不等于Published。** 发行方案确认后仅建立本轮有效权益预留；发行准备完成和企业声明也不构成资金/Token生产准入。正式发布还必须通过适用法域/监管、KYB、平台自身生产服务门、Signer、Provider、合约及链网络等独立检查。

### 1.2 七组检查

| 检查组 | 业务来源与职责 | 页面状态口径 |
|---|---|---|
| 01 企业与发行环境 | Tenant、订阅、必要KYB、当前账号授权、Sandbox/Standard、生产服务门 | 通过/待补充/阻断 |
| 02 资产及文件 | Asset状态、权属及必要文件、扫描、版本和披露范围 | 通过/待补充/阻断 |
| 03 权益结构及容量 | Instrument状态、权益法律文件、授权容量、映射、版本 | 通过/待补充/阻断 |
| 04 Offering发行参数 | 单轮权益量/Token量/单价、总募集额、窗口、最低/累计限额、有效预留、快照 | 通过/待补充/阻断 |
| 05 投资者展示与必要准入 | KYC服务能力、强制AML/制裁/地区法律阻断机制、允许披露的资料和投资者预览 | 通过/待补充/阻断 |
| 06 支付及Token技术准备 | OP Mainnet USDT支付、Provider/Signer/合约/链网络的技术安全与生产Gate | 通过/待补充/阻断 |
| 07 企业最终声明 | 企业有权账号就自身资产、权益、披露和合法性责任作出最终确认 | 未确认/已确认；声明有版本、时间与引用快照 |

检查结果由对应权威数据/受控服务生成，**不得让企业通过人工按钮改写检查为“通过”**。待补充项提供“去补充/去修改/查看原因”入口并返回原业务对象处理。

### 1.3 责任边界与术语

- 平台做资料字段/文件版本/扫描状态/对象关联/容量/参数的技术和完整性检查，并维护自己服务、风险和生产准入门。
- 发行企业对其资产信息、真实权属、法律文件、合规资格、披露和发行合法性负责；平台检查“资料已提交”不等于对法律真实性作背书。
- KYC通过且有效只赋予MVP**基础认购资格**，不代表所有法域和工具均可以发行或销售；强制AML/制裁、法域适用及生产准入仍需阻断。
- 不引入企业内部多成员/多级审批；法律或监管所要求的第三方、专业机构及平台自身强制审批不能因MVP简化而省略。
- Free Sandbox模拟发布不能生成真实投资者权益、收款、链上Token、法定登记或Mint。
- Standard订阅不自动授予真实发布权限；合同/法域、KYB、Provider/Signer及平台风险Gate仍保持独立控制。
- 企业声明的正式法律措辞、文件要求及法域差异在法律与生产门确定前仍Draft，不在本批自称已获得有效法律审查。
