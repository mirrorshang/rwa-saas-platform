# RWA SaaS V1｜企业注册至发行后管理端到端流程与字段完整性审计

> 审计日期：2026-11-11  
> 状态：**第一阶段 Issuer 产品文档端到端审计通过（有外部依赖；非 Browser/生产验收）｜2026-11-12**  
> 范围：Issuer 企业 SaaS V1 及其与投资者端/外部服务之间的必要业务数据衔接；不设计 V 投资者前台、M 统一投资端或 P 平台运营后台页面。  
> 维护分支：docs/r2-current-product-baseline；PR #8 保持 Draft / Open / Unmerged。  
> 说明：本报告不代表源码、API、真实 Provider/Signer、真实资金、法定登记、合约部署或 UAT 已完成。

## 1. 审计目标

核验真实企业从 SaaS 注册到成功发行、投资者购买、付款、配售、持仓和发行后管理的业务路径，判断现有产品设计是否具备：
- 完整页面与唯一责任；
- 完整字段、控件、校验和数据来源；
- 对象、版本、数量、金额和状态在模块间正确传递；
- 每一步明确前置条件、成功结果和唯一下一步；
- 失败、超时、重复、Unknown、部分成功及状态冲突的处理；
- Free/Standard、KYB、法律、资金、Token 与生产准入边界。

本轮不重新逐页重写 PRD；以当前权威专项规格为依据，发现缺项直接修正普通字段/交互，重大商业、法律、资金、Token 或生产权限决策单独提交用户。

## 2. 审计方法

按实际用户旅程而非导航顺序审计：
1. 企业账号与企业主体；
2. 企业 KYB、Free/Standard、钱包；
3. Asset、Instrument、Offering；
4. 投资者门户展示及 KYC 结果回传；
5. 认购报价、签署、订单；
6. OP Mainnet USDT 付款、到账核验、FinalMatched；
7. 容量、配售、法定登记；
8. Token Mint/交付、持仓与锁仓；
9. 收益/本息、领取支付、到期/退出/清退；
10. 降级、异常和存续义务保护。

每个环节核对「输入字段 → 权威来源 → 输出对象/状态 → 下一模块消费字段 → 异常回退路径」。

### 5.1 业务对象与唯一引用链（已纳入本轮字段核验）

`Tenant → Asset/AssetVersion → Instrument/InstrumentVersion → Offering/OfferingVersion → InvestorRef/KYCDecision → QuoteSnapshot → Order → PaymentIntent/ChainEvent/FinalMatched → AllocationDecision → LegalRegisterRecord → TokenContractVersion/MintIntent/TokenEvent → LockupRecord → RecordDateSnapshot/YieldEvent → DistributionBatch/PayoutResult → ExitPlan`

| 对象 | 必须稳定引用的标识/版本 | 后续消费方 |
|---|---|---|
| Tenant | tenant_id、当前企业状态、套餐/准入状态 | 全部企业业务对象 |
| Asset | asset_id、Asset 资料版本、文件 file_id/version_id | Instrument、Offering、披露 |
| Instrument | instrument_id、InstrumentVersion、权益类型、法律单位/总量、Token 映射 | Offering、配售、Token、收益 |
| Offering | offering_id、OfferingVersion、Asset/Instrument 固定版本、价格/数量/上限/时间/锁仓/披露快照 | 投资者展示、报价、订单、资金 |
| InvestorRef / KYCDecision | 当前企业授权的投资者引用、KYC 决策引用/状态/有效时间 | 报价、订单、配售、持有人 |
| QuoteSnapshot / Order | quote_id、order_id、Offering/Instrument/文件版本、数量、价格/金额、签署证据、认购限额快照 | 付款、容量、配售 |
| PaymentIntent / ChainEvent | payment_intent_id、chain/network、token_contract、from/to、tx_hash、event_id、amount、finality、match status | FinalMatched、退款、募集款 |
| AllocationDecision | allocation_id、order_id、Offering、法律单位数量、Token 数量、容量事件 | 法定登记、Token 交付 |
| LegalRegisterRecord | register_record_id、合法持有人引用、法律单位/数量、生效时间、登记主体/回执版本 | 持有人、Record Date、退出 |
| MintIntent / TokenEvent | mint_intent_id、配售引用、合约版本、接收钱包、tx_hash、实际数量、最终性 | 持仓、锁仓、Token 对账 |
| LockupRecord | lockup_record_id、Token 交付事件、Offering 锁仓快照、起算/到期、链上解除状态 | 持有人查看、收益/退出 |
| RecordDateSnapshot / DistributionBatch | record_date_snapshot_id、权威持有人登记版本、权益单位、计算版本、批次号 | 应付计算、注资、Claim/Push |
| PayoutResult / ExitPlan | payment/payout 引用、实际到账证据、exit_plan_id、法律依据、登记/Token 处置结果 | 投资者收益/退出结果、存续档案 |

任何下游对象不得只保存可变名称或当前值；必须保存上游唯一 ID 和当时有效版本。状态变化追加事件，不覆盖历史事实。

### 5.2 跨模块字段交接矩阵（产品数据契约）

以下是服务端与前端需要共同遵守的业务字段交接，不规定数据库表名或 API 实现。每个交接必须保留来源对象引用、当时有效版本、状态更新时间和证据来源；不可只传展示名称或当前值。

| 交接 | 上游必须提供 | 下游必须固定/消费 | 不能推断或覆盖 |
|---|---|---|---|
| Tenant → Asset | Tenant 引用、KYB 当前状态、套餐/历史状态、业务写权限结果 | Asset 归属 Tenant、创建/编辑来源 | 登录成功不等于 KYB 通过；新 Free 与降级 Free 权限不同 |
| Asset → Instrument | Asset 引用及资料版本、登记权利人/关系、核心权属文件版本、相关方披露资料 | Instrument 固定 Asset 引用及必要文件版本 | 资产相关方不自动等于债务人、收益责任主体或法定登记人 |
| Instrument → Offering | Instrument/InstrumentVersion、权益类型、法律单位/总规模、Token 总份数及每 Token 精确映射、责任主体、债权付息/到期计划、核心权益文件版本 | Offering 固定 InstrumentVersion；继承权益说明、法律单位、权利映射、文件和相关条款 | 新 Instrument 版本不得覆盖旧 Offering；不得通过新版本重置权益池 |
| Offering → 投资者展示/报价 | Asset/Instrument/Offering 版本、价格 U、发行 Token 数、认购窗口及明确时区、最低金额、单笔最高 Token（如设）、个人累计最高金额（如设）、锁仓规则、披露/协议文件版本、已批准付款安排 | 投资者端展示快照、报价快照、订单规则快照 | 草稿不能生成公开发行；不得用当前编辑值覆盖已发布版本 |
| Investor/KYC → Quote/Order | 平台 InvestorRef、当前 Tenant 关系、KYC 决策引用/状态/有效期、适用强制限制结果 | 报价/订单固定投资者引用和下单时 KYC 事实，并在需要时核验当前状态 | KYC 通过不代表所有 Offering 自动合格；Issuer 不得改写身份或资格 |
| Quote → Order | QuoteSnapshot 引用/版本、Token 数量、单价/应付 U、M10 个人累计额度权威占用/剩余、投资者确认的 Token 接收钱包快照/核验版本及幂等引用、协议/披露版本、签署证据、订单幂等引用 | 唯一 Order、历史报价/条款快照、订单预留引用 | 订单不得读取最新 Offering 值覆盖历史；重复提交不得创建第二订单 |
| Order → Payment | Order 引用、QuoteSnapshot、应付金额 U、OP Mainnet/USDT、批准付款目标/配置版本 | PaymentIntent、真实付款事件、from/to、tx/event、金额、最终性、资金匹配状态、付款主体关联状态 | 付款来源地址不自动等于投资者；付款指令/Hash/广播不等于 FinalMatched |
| Payment + Order + Capacity → Allocation | FinalMatched 资金事实、订单唯一引用、M10 个人累计额度占用有效、M12 有效 Offering 内部预留/Instrument 授权剩余容量、KYC/强制限制结果 | 唯一 AllocationDecision、法律权利数量/单位、Token 份数、规则/授权依据 | 同一订单不重复配售；不重复扣 Instrument 容量；候选不等于决定 |
| Allocation → Legal Register | AllocationDecision、合法持有人主体引用、登记模式/责任主体、法律权益单位/数量、依据文件版本 | 权威登记记录、回执/名册编号、生效时间、历史更正版本 | InvestorRef/付款钱包/Token 接收钱包不自动等于合法持有人；提交不等于生效 |
| Allocation/Register → Mint | 唯一配售决定、适用法定登记前置、Token 方案/合约版本、Token 数量、订单中投资者确认的钱包快照或其后追加的有效重新确认版本、真实生产授权 | 唯一 MintIntent、接收地址快照、实际链上事件、TxHash、最终性和失败/Unknown | 不从付款来源地址静默推导接收钱包；不重复 Mint；Mint 不替代法定登记 |
| Mint → Lockup/Holdings | 已最终确认 Mint 事件、实际交付时间、Offering 锁仓快照、法定持有人登记引用 | 锁仓记录、起算/预计到期、链上执行状态、持仓对账 | 不以付款/配售时间起算；业务锁仓到期不等于链上或法律限制解除 |
| Legal Register → Record Date | 有效登记版本、合法持有人、法律权益单位/数量、生效期间、适用限制/争议、Record Date 与时区依据 | 不可变 RecordDateSnapshot 版本、符合条件单位和来源时间 | 不以 Token 余额替代法定名册；登记 Unknown/争议不能进入正式收益计算 |
| Record Date/Event → Distribution | InstrumentVersion、事件/合同依据、每位持有人计息/应付单位、计算期间/规则、扣项依据、已核验快照 | 计算版本、毛额/扣项/净额、唯一分配批次、注资证据、Claim/Push/外部实付结果 | 预期年化不参与计算；未发行授权本金不计息；已批准不等于已注资/已支付 |
| ExitPlan → Payment/Register/Token | 合法退出依据、受影响权益范围、Record Date/余额、应付金额、合法付款主体 | 实际清偿事实、登记变更、Token 限制/Burn、未结义务和最终结清证据 | 计划不等于付款；付款不等于登记变更；Burn 不等于债务清偿 |

### 5.4 钱包、身份与法律持有人的分离关系（重点跨端契约）

现行文档已经明确以下对象不能合并，但目前缺少一个完整、统一的跨端字段契约：

| 对象 | 权威事实 | 必须关联/展示的字段 | 不得推断 |
|---|---|---|---|
| 投资者账户 | 平台统一身份 | 平台投资者引用、当前 Tenant 业务关系引用 | 不自动等于付款人、Token 接收人或法律持有人 |
| 投资者已验证钱包 | V 端 M08-F011 投资者钱包生命周期 + M07-F003 接收地址登记/校验；M24-F001 投资者身份关系 | 钱包引用、网络、地址、用途、控制权核验状态/时间/依据、有效/撤销状态及 InvestorRef 关联 | 不自动等于本次付款来源地址 |
| 付款来源地址 | M11 链上事件 | from address、网络、Token、事件/交易引用、匹配状态 | 不因订单关联而认定为投资者本人 |
| 投资者 Token 接收地址 | 投资者在订单确认时选择的钱包快照；Mint 前重新确认则追加新版本（M08-F011/M07-F003） | 接收钱包引用、网络/地址、控制权或受权托管证明、确认时间、有效状态及历史版本 | 不得由 Issuer 企业账号自由替换；不得从付款来源地址静默推导 |
| 合法持有人 | M12 有权登记结果 | 法定主体引用、登记编号、法律单位/数量、生效时间/版本 | 不因投资者账户或 Token 余额自动等同 |
| 企业最终结算钱包 | U01 企业钱包 + Offering 发布快照 | 企业钱包引用、网络/地址、验证状态、Offering 固定版本 | 不得与投资者付款目标混同 |
| 投资者付款目标 | M11 已批准收款安排 | 目标类型、目标主体、合约/钱包引用、网络/Token、配置版本/有效期 | 不得默认等于企业最终结算钱包 |

**建议作为 V1 跨端数据契约的最低要求（不等于指定技术实现）：**
1. 平台必须为投资者账户与其钱包建立可追溯的授权关联；至少保留钱包引用、网络、地址、用途（付款/接收/其他）、核验方式类别、核验结果、核验时间、有效期/撤销状态及证据引用。
2. Token 接收钱包必须由投资者本人或有权代表在投资者端明确确认，并在 Mint 前满足适用控制权/合法托管授权核验；Issuer 只读查看必要的脱敏地址和核验状态。
3. 付款来源地址只作为链上付款事实记录。与投资者已验证钱包不匹配时，进入核对/风险状态，但不能仅凭不匹配自动否定真实到账，也不能自动将其认定为投资者身份。
4. 法定持有人与 Investor Account 不一致时，必须有合法主体关系/授权依据引用；不能把 Token 接收地址当作法律持有人名称。
5. 钱包更换、撤销或失效必须保留历史绑定及其有效期间；不能覆盖旧订单、付款或 Mint 的历史快照。订单保存投资者确认的 Token 接收钱包快照；Mint 前变更必须由投资者重新核验并确认，Mint 只使用最新有效确认版本。原 MintIntent 已提交/Unknown 时，不得直接换址或重复 Mint。
6. 投资者钱包生命周期及控制权校验已在 V1 功能范围中（M08-F011、M07-F003）；本轮不设计 V 端页面，但必须明确其结果如何通过 M24 投资者身份关系映射给 Issuer，并由 M07-F004 在 Mint 前消费。

**审计结论：** Issuer 现有页面能够分别显示付款来源地址、Token 接收钱包摘要、合法持有人和企业收款钱包；但投资者端如何建立和更新「Investor Account → 已验证钱包 → Token 接收目标」关联尚未形成可核验的统一契约。此项列为跨端重大待确认项，不得用 Mock 绑定或人工填写代替真实权威验证。

### 5.5 Offering 交易额度与平台投资者资格规则的边界

## 6. 本轮已发现并直接修正的产品规格缺口（不改变既有决策）

### E2E-F01｜Offering 缺少已批准的单投资者累计最高认购金额

**发现：** 历史 R2-04-03 R06 已批准「当前 Offering 下的累计最高认购金额」选项；认购额度按同一投资者在当前 Offering 下的有效订单/预留、已付款待配售和已确认配售金额累计。最新 U02-09 曾错误写成不设置投资者累计认购限额；原释放口径也未明确区分退款事实与认购义务减少。

**修正：**
- 恢复「单个投资者本期累计最高认购金额 U」选填字段；
- 当前 Tenant + Offering + 本企业投资者引用编号为累计范围；不跨 Offering、Issuer 或 V/M 账户合并；
- 未确认报价、KYC 未通过、签署未完成的草稿不占用额度；投资者确认有效报价并完成必要签署，且 M10 个人额度预留与 M12 Offering Token 预留均有效后，才进入有效待付款并开始占用。
- 同一订单状态迁移只累计一次；M10 唯一订单主账按 Tenant + Offering + InvestorRef 原子维护个人累计额度占用；有效订单/预留、已付款待配售、已确认配售均继续占用；M12 只维护 Token/Offering 容量，不重复计算个人金额额度。
- M10 个人额度预留与 M12 Token 预留必须关联同一有效订单；任一侧失败/Unknown 时不得进入有效待付款或继续引导付款，先核对原请求；
- 只有权威订单/配售/容量记录确认认购义务或有效预留减少/取消后才释放对应额度；退款本身不自动释放。仅退还多付款/手续费而不改变认购义务时不释放；部分认购义务减少只按权威确认的减少金额释放。已确认配售后的赎回、清退、Token Burn 或后续持仓减少不回滚历史累计认购金额。Unknown、付款待核、退款待核和预留待核均不释放。
- U02-12 固定保存上限、历史已占用、本单计入及剩余额度摘要，不披露其他投资者订单。
- 因 Token 份数必须为整数，个人金额上限按整份 Token 向下计算可购买数量；不整除时展示实际可用金额和不足一份的剩余额度，不静默向上取整。

### E2E-F02｜付款来源地址未在到账详情明确展示

**发现：** 资金模块已有交易哈希、目标地址和金额等字段，退款规则也明确原始付款地址不必然等于退款受益人/退款目标，但到账详情没有明确列出链上发送方/付款来源地址。

**修正：**
- 增加链上发送方地址（from address），只读记录；
- 默认缩略展示，完整地址受权查看；
- 增加与投资者已验证钱包的匹配状态；
- 明确「付款来源主体关联状态」与「资金事件是否匹配订单」分开判断；若适用规则要求付款主体核验，则在合法主体/代付依据核实前不进入 FinalMatched；不自动认定付款人，也不因地址不匹配直接否定真实到账；
- 不因订单关联自动认定发送地址属于投资者本人；
- 付款来源地址、投资者账户、Token 接收钱包、合法持有人和退款目标继续分离。

### E2E-F03｜债权利息/本金不得把 Instrument 授权本金当作实际存续本金

**发现：** U02-08 的「债权本金总额」属于 Instrument 权益池规模/授权容量；一个 Instrument 可通过 Offering 分期发行，未发行的授权容量不构成已发行债权。原 U02-13/M13 计算口径仅写「生效 Instrument 的本金」，可能被理解为对全部授权本金计息或兑付，未明确区分实际已发行、已登记和未偿本金。

**修正：**
- 固定利息应按合同计息基准，对每位合法持有人在相应计息期间的实际未偿本金计算，再汇总；利率、期间、日数规则来自生效 InstrumentVersion。
- 到期本金以 M12 有效登记快照中的合法持有人本金余额为基础，扣除已由权威确认的真实本金偿付。
- Instrument「债权本金总额」只作为权益池授权上限/容量，不得直接作为已发行或实际应付本金。
- 如无法根据合同、M12 登记快照和真实本金偿付事件还原计息期间余额，必须转人工核算/待核，不得自动形成正式应付。
- M13 已补充持有人计息/应付本金基数、计算来源及阻断规则；I-57 已明确按事件类型分离本金/利息实际支付证据，I-58 到期清退只累计已确认的本金支付，禁止以利息支付冲减本金；I-58 到期清退计划已明确债权本金只读计算来源，禁止以 Instrument 授权本金总额代替实际未偿本金。

文件：[U02-08 权益结构](U02-08-INSTRUMENT-UI-READY-CLOSEOUT-2026-11-11.md)、[收益与分配](YIELD-AND-DISTRIBUTION-UI-READY-CLOSEOUT-2026-11-11.md)。

### E2E-F04｜收益参与比例可能被重复计算的口径歧义

**发现：** Instrument 定义「授权参与比例」；I-55 要求发行方填报「本期可分配收益金额」；I-56 原计算说明同时引用 I-55 金额和 Instrument 授权参与比例，未明确该金额是否已经扣除/应用参与比例，存在重复乘算风险。

**修正：**
- I-55 填报金额定义为：按生效 Instrument 合同参与比例及适用费用口径核定后，实际归属于该 Instrument 权益池的本期可分配金额，而非底层资产/业务原始总收入。
- I-56 按 Record Date 合法参与单位计算每位持有人的分配权重；不再次乘以 Instrument 授权参与比例。
- 发行方必须填写金额口径说明和依据；金额未经核定时不得进入正式计算。

## 7. V1 已批准产品边界与未验证跨端依赖

### E2E-C01｜持有人转让未纳入 V1 是已批准边界，不属于缺项

经核对 DEC-009、后续补充决策 DEC-011 及 DEC-058：
- V1 交易能力仅支持一级发行认购；
- V1 不提供投资者之间的受控转让申请、受让资格办理、转让审批、交割、法定登记迁移或 Token 转移产品化流程；
- 不建设公开二级市场、C2C、订单簿、撮合或强制转账；
- V1 仍必须保留依法需要的 Token 转让限制/许可控制，以及对非预期 Transfer 事件的观察、告警、登记核对和审计；
- 受控转让工作流明确后置 V2。

### E2E-D01｜已批准：Offering 合约收款默认路径（DEC-083）
