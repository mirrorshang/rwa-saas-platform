## 3. 关键跨端业务链路审计

### 3.1 SaaS 企业入驻与商业服务

W 官网 → I 邮箱登录/企业资料/KYB → P-02/P-03 商业客户与 KYB → M01 Tenant/商业权益 → P-04/P-05 服务状态 → P-06 商业收费异常。

一致性要求：
- 一个企业一个 Tenant；Free 升级 Standard 沿用原 Tenant。
- 当前商业模式为永久 Free + 付费 Standard；旧 Trial/14 天/30 天恢复窗口不再作为现行流程。
- 商业 KYB、合同、订阅付款、Tenant 服务状态分别记录。
- Standard 不是发行、资金、Signer、Token 或收益生产许可。
- SaaS 商业收费与投资者认购款/退款/收益付款完全分离。
- 暂停、降级、退租不得抹除既有真实金融义务、证据及必要查询/交接。

<badge color="success">一致</badge> 未发现当前页面组仍需要 Trial 业务状态或独立 Trial 恢复页面。

### 3.2 Issuer Offering 申请 M 渠道上架

Issuer I-35 Offering → I-67 提交单 Offering 上架申请 → P-15 审核/补件 → 审核通过触发系统自动创建唯一 Listing 并发布 M → P-16 管理已上架 Listing → M 展示 → I-68 查询审核及展示状态 → P-17 持续监控。

一致性要求：
- Issuer 必须主动申请；平台不自动把企业所有 Offering 上架。
- 一份 Offering 对应一份独立 Channel Application；审核申请固定提交资料和授权快照。
- P-15 审核通过即触发自动上架；不进入待发布队列，不要求 P-16 再点一次发布。
- 只有系统确认 Listing 创建及发布成功后，M 才展示。
- 自动上架 Unknown/失败时，按原 Application ID/Listing ID/幂等键查询和恢复；不得创建第二个 Listing。
- P-16 只管理已上架 Listing 的查看、暂停、下架、恢复；不负责首次人工发布。
- M 展示不等于投资者可认购；KYC、适用地区、Offering 时间/额度、必要签署和订单条件仍独立判断。
- M 渠道暂停/下架不修改 Issuer Offering，不删除既有订单、资金、登记、Token 或收益事实。
- Issuer V 门户与 M 总投资者平台保持独立，二者不自动发布或同步全部资产。

<badge color="success">一致</badge> 已修正 P-15 状态表旧文案「审核通过不等于已发布」，并在 V1.0 追踪矩阵 M23-F001/F003/F006 对齐自动上架规则。

### 3.3 M 统一投资者账户管理

M 投资者注册/登录 → M24 账户 → 第三方 KYC → M24 平台权威状态 → P-18 受权账户服务视图 → P-13/P-07 处理 Provider 同步异常 → M18 必要通知。

一致性要求：
- P-18 只管理 M 统一投资者账户，不建立所有 Issuer V 门户的投资者全局数据库。
- 不自动合并 M/V 账户、钱包、订单、持仓。
- P 只查看脱敏 KYC 状态和必要授权引用；不得手工覆盖 Provider 结论。
- KYC Passed 不等于特定 Offering 的资格/认购许可。
- 账户服务限制不得修改原订单、资金、法定登记、Token 或收益状态。

<badge color="success">一致</badge>

### 3.4 平台任务、通知与原业务状态

原业务模块 → M17 平台责任任务 → P-07 处理/指派/升级 → M18/P-08 通知 → 原业务模块更新其权威状态 → P-14 只读统计。

一致性要求：
- 任务只代表平台协作责任，不是付款、登记、Mint 或收益记录。
- 审批任务必须回到原业务审批页完成决定；P-07 关闭任务不能替代原审批。
- M18 通知状态与法律送达、合同签署、业务同意分离。
- Unknown 先查询原 Intent/回执，不盲目重发或重复执行。
- P-08 模板版本不覆盖历史发送内容；重试沿用原通知关联和幂等约束。

<badge color="success">一致</badge>

### 3.5 套餐、平台规则与业务 Gate

P-09 套餐权益/配额版本 + P-10 平台强制/渠道展示规则 → P-05/P-15 等原业务入口读取 → 原业务模块执行自身 Gate。

一致性要求：
- Free/Standard 是商业权益，不是法律/生产执行权限。
- P-10 地区规则仅允许/限制渠道展示申请，不等于法域发行许可或投资者资格。
- 法律/安全强制规则优先于平台配置、Tenant 配置和 Offering 展示设置。
- 不恢复独立投资者资格引擎、不开放低代码规则编辑器。
- 套餐和规则新版本不静默改写历史合同、订单、权益或既有金融义务。

<badge color="success">一致</badge>

### 3.6 安全、审计和 Provider

P-11 访问申请/审批 → 限时最小权限授权 → 原业务受控访问 → M20/P-12 追加审计 → 到期/撤销；P-13 负责 Provider 连接/凭证状态，P-12 负责安全事件与审计引用。

一致性要求：
- P 后台登录不等于默认拥有所有 Tenant/KYC 原件访问权。
- 敏感访问绑定具体人、Tenant、对象、字段、目的、方式和期限；申请人不得自批。
- 到期/撤销由服务端立即阻断；不能只依赖前端隐藏。
- P-12 审计追加保存；不覆盖/删除历史事实。
- P-13 不显示 Secret，不因持有 Provider/RPC 凭证而获得客户资金或 Signer 权限。
- Provider 恢复不等于原付款、登记、签署或 Token 业务完成。

<badge color="success">一致</badge>

### 3.7 数据与报表

P-01 当前运营快照 → P-14 历史趋势/聚合查询 → 必要时跳转原 P 业务页面；导出由 M20-F007 审批，P-12 留存审计。

一致性要求：
- P-14 只覆盖平台商业、M 渠道、M 投资者服务、平台运营质量。
- Issuer M21-F001～F006 的 Project/Offering、订单、资金、登记/Token、存续收益报表继续由 Issuer 授权用户使用。
- P-14 不形成第二本资金/权益账，不穿透查看跨 Issuer 投资者明细。
- 所有指标显示统计口径、数据源、时间基准、时区、数据更新时间、延迟和 Unknown。
- 平台金额遵循 U（USDT）展示基线；未批准换算的其他币种单独标示，不混算。
- 导出须受 M20 权限、用途、字段、时间范围、审批、有效期和审计控制。

<badge color="success">一致</badge>

## 5. 本轮发现并已修正的问题

1. **旧 Trial 术语残留：**总体架构曾保留 Tenant/Trial/Paid。已统一修正为 Tenant/Free/Standard；P-01～P-06 已按 DEC-037 删除现行 Trial 状态/操作，仅保留历史决策引用。
2. **上架审核状态冲突：**P-15 状态表曾写「审核通过不等于已发布」，与用户批准的审核通过自动上架冲突。已改为「审核通过即触发系统自动创建唯一 Listing 并上架；仅自动上架成功后 M 才展示」。
3. **平台报表越权风险：**总体架构曾将 M21 作为 P-01 的聚合来源，容易误解为平台可访问 Issuer 金融报表。已修正 P-01 来源为 M03/M01/M17，并明确 Issuer M21-F001～F006 仍由 Issuer 授权用户使用；P-14 只消费平台受权聚合数据。
4. **P-14 与 P-01/P-17 重叠：**已明确 P-01 当前快照、P-14 历史分析、P-17 渠道监控详情的分工。
5. **金额单位：**P-14 已对齐平台金额 U（USDT）展示基线，保留原账单币种元数据；未经批准换算的金额不得混合统计。
