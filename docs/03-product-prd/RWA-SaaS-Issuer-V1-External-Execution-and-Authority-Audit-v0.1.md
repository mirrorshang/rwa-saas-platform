## 一、审核原则与可复用责任模型

**四层职责**：① SaaS 领域业务模块授权、前置 Guard 与业务状态；②具备适格权限和法律责任的执行或证据来源；③ M22 提供受控连接、事件校验、凭证隔离；④权威业务模块核对、独立留痕、审计和受控恢复。外部结果为 **Unknown/Failed/Confirmed** 不等于所有法律与链上状态合并成成功。

**交付层次**：不是要求 V1 建设第三方服务商平台、自动托管资金或私钥；但必须形成可靠的受控请求/审批、可验证原始凭证、外部执行关联 ID、同链同资产与金额精度校验、可重入/不可逆幂等、失败/超时/reorg/重复真实事件处理及独立核对。

**监管限制**：是否可以由某类第三方执行须按首发法域/Instrument、客户/发行方合同与实际资质另行判断。测试通过不构成真实金融许可。

## 四、风险联审（继承 B02/B07/B08）

- **B02 权限**：发行审核人、业务操作人、资金授权方、密钥执行者、外部登记机构可以是不同受控主体；在 M02/M20 留授权链，不允许运营客服超权执行。
- **B07 钱包用途**：付款来源地址、发行方或合法收款地址、Token 接收钱包、退款收款地址必须分别校验用途、链、币种/合约和所有权/授权，不能在 UI 复用一个未经区分的钱包字段。
- **B08 财务与 Token 独立事实**：M10 订单/预留、M11 付款与退款、M12 配售和法定登记引用、M07 链上 Token 状态、M22 集成事件不能互相代替。
- **外部延迟与可用性**：业务可展示“核验中/处理中/未知结果”及人工受控恢复，不强制 SaaS 在每个外部系统短暂失联时直接判交易失败。
- **法律判断门**：选择具体链/Token 标准/权利、收款和退款主体、签名/登记/电子签服务商之前，不能将任一外部执行形式标为可生产交付。
