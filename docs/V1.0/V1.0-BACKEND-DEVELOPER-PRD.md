# RWA SaaS V1.0 Backend Developer PRD

> 工程设计输入，2026-11-16。前端基准：`05bda87a`。产品交付范围为官网、邮箱登录、Issuer SaaS 九模块；本文件定义服务端及外部权威接入责任，不宣称这些服务已上线。历史 DEC/Frozen/SCOPE 保存在 `archive/docs-before-final-handover-20261116`，任何冲突先按已批准最新决定核对；未决见第 16 节。

## 1. 系统边界与开发顺序

官网只承载公开内容和登录入口；Issuer 前端只负责输入、显示、客户端易用性校验。服务端是账号、企业、订阅/Entitlement、业务对象、版本、权限、资金匹配、配售、法定登记引用、收益应付、审计的唯一权威。浏览器 localStorage 示例不得迁移为生产记录。认证、企业、业务服务、数据库、文件/扫描、通知、审计、外部 Provider Adapter、钱包/Signer、链监听之间用有版本的事件及关联 ID 协作；不预设未批准语言、数据库品牌或部署拓扑。

建议实施顺序：①认证/企业隔离/审计基础 → ②KYB/订阅/权益与文件 → ③Asset/Instrument/Project/Offering/版本/容量 → ④投资者 KYC 引用/订单 → ⑤付款最终性/匹配/退款 → ⑥配售与法定登记 → ⑦合约/Token → ⑧收益和资金划拨 → ⑨报表/门户发布。各阶段先完成数据约束与模拟 Adapter，再接生产 Provider；真实资金、法定登记及链上写操作需独立准入。

统一约定：所有受企业约束实体含 `tenant_id`，服务端从会话取得，客户端不得指定或覆盖；所有写接口返回 `id,version,status,updated_at`，并以版本条件更新；金额为最小单位整数和币种/网络，不用浮点主账；UTC 时间及不可变事件时间、业务本地时区分别保存。外部回调先验签、去重、落原始证据，再异步归约；Unknown 不按失败重放资金/链上操作。

## 2. 账号、企业、KYB

邮箱 OTP：请求时归一化邮箱、限流、设置短有效期和发送次数；只存验证码摘要；验证须原子消费、限制尝试，首次成功创建 User，再建立安全会话。失效/错误返回统一错误，不泄露账户是否存在；重复发送按冷却期回应；会话过期返回 401 并清理前端身份。官网跳 Issuer 用同一受控会话或一次性交换票据，票据短期、单次使用、绑定目标和反重放；不得用 URL 邮箱/验证码/登录标记。退出撤销会话。MVP 一个 User 绑定一个 Tenant/Enterprise；未建企业可登录但业务操作受限；不设计多角色 UI，服务端仍对高风险动作做授权和职责分离。

企业 KYB 五步：基本信息 → 业务信息 → 关联人员 → 证明材料 → 预览确认。每步草稿可保存并保留版本；提交前必填、文件扫描及关联人员校验。状态 `Draft→Submitted→Reviewing→Passed/NeedsInfo/Rejected`；补件仅回到需补项，原资料和审核历史保留；重新提交生成审核版本，不能覆盖旧证据。Provider 回调必须验签、关联申请版本、幂等处理，过期回调存档但不覆盖新决定；结果发通知。KYB Passed 才能按批准矩阵开通相关能力，但不自动开通生产资金/Token。

## 3. 订阅、Entitlement

Free/Standard 的价格、支付渠道、试用及宽限参数来自批准的套餐规则配置，不硬编码在前端。Subscription 记录 plan、状态、周期、应收/实收、续费次数、取消生效时间、版本。状态 `Free→PendingPayment→ActiveStandard→PastDue→Grace→Suspended/Expired→Free`；取消分即时停止未来续费与到期生效，已存业务及法定义务仍履行。Webhook 去重并与账单核对；失败重试不能重复开通；降级仅关闭新建/运营能力，不删除 Asset、订单、名册和审计。

Entitlement 按操作而非页面判定：Free 可创建/编辑 Asset、Instrument、Offering 草稿并内部预览；真实发布、认购、资金、登记、Token、收益运营须 Standard 且 KYB、法律/Provider/钱包/支付/合约等独立 Gate 均满足。服务端逐次判定并返回拒绝原因码、缺少的 Gate；前端 Mock Standard 不具备授权。

## 4. 企业钱包

KYB Passed 后异步请求 MPC Adapter 分配钱包，保存 Provider 引用、网络、地址、验证证据和状态；超时/Unknown 查询原请求，不盲目重复创建。自有钱包绑定须服务端生成一次性挑战，绑定企业/地址/网络/有效期，验证签名和防重放。默认钱包切换需乐观锁与审计。Offering 创建时选择经验证收款钱包，并把 `wallet_id,address,network,verification_version` 固定为快照；后来修改默认钱包不改历史 Offering。私钥/助记词不进入业务数据库或日志，Signer 凭证外部安全管理。

## 5. Asset、Instrument、Project、Offering

对象关系：Tenant 1:N Asset；Asset 1:N AssetVersion，且一个当前有效 Instrument；Instrument 1:N InstrumentVersion；Project 是独立发行项目主账，关联确定的 Asset/InstrumentVersion；Project 1:N Offering；Offering 引用不可变的 AssetVersion、InstrumentVersion、钱包和条款快照。当前 Issuer 前端已自动创建内部 Project 并关联 Asset/Instrument/Offering，但该对象仍存于浏览器 v4 Mock 状态；生产服务端必须建立权威 Project 主账，迁移时不能把 Project 和 Offering 合并。

Asset 共有字段：`id,tenant_id,name,category,subtype,owner,operator,status,current_version,created_at`。模板版本包含专有字段与约束：住宅地址/户型/面积/用途/租用状态/权利人/约定价/估值/租金/租期/权属、估值、租约文件；写字楼、商铺、工业园/仓储物流使用各自经营和产权字段；普通股权使用公司/股类/股数/权利限制；单笔债权使用合同号/债权人/债务人/本金/未偿本金/利率或无息模式/起息和到期/还本方式/估值及合同证据。类型专属字段、条件必填和 Ready Gate 必须在模板配置中版本化，不能强行共用房地产字段。目录目标为 7×23、六模板；相对历史 R2 的批准冲突未决，生产开放前核对。

Asset Ready 仅表示已填写、文件扫描通过且版本引用齐全，**不代表产权真实或发行许可**。文件记录 `owner_type,owner_id,category,object_key,checksum,scan_status,document_version,access_policy`；上传先取得限时上传授权，再扫描/隔离，Passed 后可引用；感染/超时不得 Ready。引用后的编辑产生新 AssetVersion，不能静默覆盖历史。

Instrument 包含权利主体、权利描述、类型（股权/债权/收益参与权）、权益单位、总容量、Token 比例、现金流条款、转让/锁定、法律文件及版本。权益单位和 Token 映射用整数有理数验证；无法精确拆分拒绝，不能静默取整。股权的表决/分红/清算、债权利息模式/未偿本金/到期、收益参与权收益口径分别建条款。Ready 时检查资产 Ready、权利/文件/容量完整性；已被 Offering 引用的版本不可原地改写。

Project 保存发行主体、资产和确定 InstrumentVersion、法域/法律审查引用、目标及状态；Offering 保存轮次、发行数量、单价、最小/最大认购、币种、OP Mainnet USDT 收款安排、钱包快照、起止时间、披露/资格规则、合约计划、状态。确认/发布需 KYB、Standard、文件/法律/钱包/Provider、容量和时间窗通过；使用事务锁定同一 Instrument 总容量，草稿不正式占用。条款变更产生新快照，明示在途订单处理；暂停/关闭不抹去订单。合约部署为独立异步任务，不能把“申请”视为部署成功。

## 6. 投资者、认购、登记

Investor 为平台权威身份引用；Issuer 仅获本企业有授权的脱敏视图。第三方 KYC/AML/制裁结果及有效期由 Adapter 接收，状态与原始证据受限保存；Offering 资格是独立规则版本的决定，不因 KYC Passed 自动通过。一个投资者可有不同付款、接收钱包和法定权利主体。

Order 创建时固定 `offering_id,investor_ref,quantity,price,currency,fee,terms_version,eligibility_version,expiry,network`；唯一请求键防重复。资格、窗口、限额、容量、必要签署均须通过，预留容量有过期和链上待核保护。Payment 与 Order 一对多；最终匹配后才能形成 Allocation，且同一订单配售数量/总容量原子核算。Holder/Register 是外部法定登记结果的引用和快照，不能由 Token 余额推导。Token Delivery 在法定登记及合约准入后独立推进；“订单已完成”必须满足最终到账、配售、登记及 Token 交付最终确认，不能只看支付。

## 7. 资金与结算

投资者按 Offering 快照向受控发行合约地址支付 OP Mainnet USDT。链监听将 `tx_hash,log_index,network,token_contract,from,to,amount,block,confirmations` 作为不可变观察，核对目标网络、合约、收款地址、金额和订单。广播、上链、确认、最终性、匹配为不同状态；重组回滚未最终事实，Unknown 需查询。少付、多付、错误链、迟到账、多人/多笔付款、重复回调进入异常队列，不能自动当成功。退款按申请→授权→外部执行→最终核验走独立指令/证据，禁止重复出款。募集款可结算余额只由已最终匹配且合法可释放金额减退款、冻结、已划拨计算；申请、审批、执行、到账核验分离。SaaS 订阅资金与投资者募集资金分账、分权限、分报表。

## 8. Token 与链

合约配置保存标准、网络、参数、代码/审计/法律版本、部署批准和目标钱包；部署请求到 Signer Adapter 返回操作 ID，记录 `Submitted→Confirmed→Final`，失败/Unknown 查询同一操作。Mint 必须关联最终匹配付款、有效配售、法定登记结果、接收地址验证及容量，按配售决定幂等；链上交付仍需最终性核验。转账与业务锁仓、链上限制、法律冻结分开；链事件按链 ID/交易哈希/日志序号去重，与平台主账每日对账。链重组、nonce 冲突、Gas 失败与 Provider 超时均进入可审计补偿；不得把请求成功当 Mint 成功。

## 9. 收益、本息与退出

DistributionBatch 记录 Offering、事件类型（租金/利息/本金）、期间、Record Date、币种、总额、规则版本、HolderSnapshot、状态。零有效持有人可存 Draft，不得 Confirm 或 AwaitingFunding。同 Offering/事件类型/期间用唯一约束拒绝重复确认；支付用批次/明细唯一外部指令键。先取得权威法定名册和权益数量快照，再按明确的精度/尾差规则生成 DistributionLine；复核、注资、受权支付、逐笔最终回执和对账分开。租金按真实净收益凭证，不按预期收益率生成；债权利息按实际未偿本金、合同利率及已批准日计数口径，超过到期或全额还本停止正常利息，逾期利息须另批准；本金事件独立批次且不计累计收益。失败/Unknown 不重复支付。

## 10. 投资者门户

Issuer 仅配置企业 Logo、展示名、平台域名下唯一前缀，查看专属地址、预览和已上架资产；不是 CMS。Logo 真实文件经过扫描和访问控制；slug 归一化、保留词/唯一性校验及变更保护由服务端完成。Free 仅内部预览；公开状态必须 Standard 且 Offering 披露、法域、企业及外部服务 Gate 通过。页面只读取企业及 Offering 权威数据，不建立第二份资产或订单主账。

## 11. 数据模型与约束

下表是逻辑模型；物理表和索引实现可调整，但主键、租户键和唯一约束不可省略。

| 实体 | 必要字段/关系与约束 |
|---|---|
| User, Session | `user_id,email_norm` 唯一；`session_id,user_id,expires_at,revoked_at`，会话令牌只存摘要 |
| Enterprise/Tenant, Membership | `tenant_id,legal_name,status`；MVP `user_id` 唯一绑定一个 `tenant_id` |
| KYB, KYBDocument | `kyb_id,tenant_id,version,status,provider_ref`；材料 FK、扫描状态、版本；`tenant_id,version` 唯一 |
| Subscription, Invoice, Entitlement | `tenant_id,plan,status,period`；Provider 账单/回调 ID 唯一；操作权益按租户/版本索引 |
| Wallet, WalletChallenge | `tenant_id,address,network,type,status,provider_ref`；挑战 nonce 唯一/一次消费；默认钱包按租户唯一 |
| Asset, AssetVersion, AssetDocument | `asset_id,tenant_id,current_version`；`asset_id,version` 唯一；文件校验和/扫描/引用版本 |
| Instrument, InstrumentVersion | `instrument_id,asset_id,tenant_id`；一 Asset 当前有效 Instrument；`instrument_id,version` 唯一 |
| Project, Offering, OfferingSnapshot | `project_id,asset_id,instrument_version_id,tenant_id`；`offering_id,project_id,round,status`；确认快照不可变 |
| Investor, KYC, Eligibility | 平台身份引用与企业授权关系；KYC 决定版本/期限；`investor_ref,offering_id,rule_version` 索引 |
| Order, Payment, ChainObservation | `order_id,offering_id,investor_ref,status,request_key`；`tenant_id,request_key` 唯一；交易 `network,tx_hash,log_index` 唯一 |
| Allocation, Holder/Register | `allocation_id,order_id,quantity`；每订单/决定版本唯一；法定登记 Provider 引用与快照 |
| Token, OnChainTransaction | `token_id,offering_id,contract_address,network`；外部操作键唯一；提交/确认/最终区分 |
| Distribution, DistributionLine | `offering_id,event_type,period` 已确认唯一；`batch_id,holder_ref` 唯一；本金/收益类型分开 |
| AuditLog, Outbox, ProviderEvent | 追加式 `actor,tenant_id,object,action,before_hash,after_hash,time,correlation_id`；回调外部事件 ID 唯一 |

所有租户业务查询的主索引以前导 `tenant_id` 建立；订单、付款、链事件、状态任务按外部引用与时间另设索引。PII、材料、密钥引用分级访问；审计记录不允许普通业务更新。

### 11.1 最低字段、类型和关系约束

这是逻辑 DDL 契约（`uuid` 可由工程选定等价的不可猜测 ID；`decimal(p,s)` 只用于输入/展示，权威金额存最小单位 `bigint`）。`NN` 表示非空，`UQ` 表示唯一；外键必须在相同租户边界内校验。每张可变表另有 `version:int NN`、`created_at:timestamp NN`、`updated_at:timestamp NN`，审计/链观察为追加式。

| 实体 | 主键与必填字段（类型） | 外键、唯一约束与关键索引 |
|---|---|---|
| User | `user_id:uuid PK; email_norm:varchar(320) NN; status:enum NN` | `UQ(email_norm)` |
| Session / OTP | `session_id:uuid PK; user_id:uuid NN; token_hash:binary NN; expires_at:timestamp NN`；OTP 有 `request_id,code_hash,attempts,expires_at,consumed_at` | FK User；`UQ(request_id)`；按 `user_id,expires_at` 索引 |
| Tenant / Membership | `tenant_id:uuid PK; legal_name:text NN; status:enum NN`；Membership `user_id,tenant_id` | FK User/Tenant；MVP `UQ(user_id)`，防一账号多企业 |
| KYB / Material | `kyb_id:uuid PK; tenant_id:uuid NN; revision:int NN; status:enum NN`；材料 `file_id,step,scan_status,checksum` | `UQ(tenant_id,revision)`；文件 FK 与版本绑定 |
| Subscription / Entitlement | `subscription_id:uuid PK; tenant_id:uuid NN; plan:enum NN; status:enum NN; period_start/end:timestamp`；Entitlement `operation,enabled,rule_version` | `UQ(provider_invoice_id)`（非空时）；`tenant_id,status` 索引 |
| Wallet / Challenge | `wallet_id:uuid PK; tenant_id:uuid NN; network:text NN; address:text NN; status:enum NN`；挑战 `nonce_hash,expires_at,consumed_at` | `UQ(network,address,tenant_id)`；`UQ(nonce_hash)`；每租户至多一个默认钱包 |
| Asset / Version | `asset_id:uuid PK; tenant_id:uuid NN; category/subtype:text NN; status:enum NN`；版本 `asset_id,revision,template_version,details_json,ready_result` | `UQ(asset_id,revision)`；`tenant_id,status` 索引；详情按模板 schema 校验 |
| File / Document | `file_id:uuid PK; tenant_id:uuid NN; owner_type/id; category; object_key; sha256; scan_status` | `UQ(tenant_id,sha256,owner_type,owner_id,revision)`；对象引用和访问策略必须校验 |
| Instrument / Version | `instrument_id:uuid PK; tenant_id,asset_id NN; type:enum NN`；版本 `revision,rights_units:bigint,token_num/den:bigint,terms_json` | FK Asset；`UQ(asset_id,current_active_flag)`（仅当前有效行）；`UQ(instrument_id,revision)` |
| Project | `project_id:uuid PK; tenant_id,asset_id,instrument_version_id NN; status:enum NN` | FK 必须同租户；`tenant_id,status` 索引 |
| Offering / Snapshot | `offering_id:uuid PK; tenant_id,project_id NN; round:int NN; quantity:bigint NN; unit_price_minor:bigint NN; currency/network NN; start/end NN`；快照含 `wallet_id,address,terms_hash` | `UQ(project_id,round)`；同 Instrument 容量锁；快照确认后不可更新 |
| Investor / KYC / Eligibility | `investor_ref:uuid PK`（平台级）、`kyc_revision,status,valid_until`；资格 `offering_id,rule_version,decision` | 授权关系按 `tenant_id,investor_ref`；KYC PII 与 Issuer 视图隔离 |
| Order | `order_id:uuid PK; tenant_id,offering_id,investor_ref NN; quantity:bigint NN; price_minor:bigint NN; status:enum NN; request_key:text NN` | `UQ(tenant_id,request_key)`；`offering_id,status` 索引；条款/资格快照 FK |
| Payment / Observation | `payment_id:uuid PK; order_id NN; amount_minor:bigint NN; status:enum NN`；观察 `network,tx_hash,log_index,block_hash,finality` | `UQ(network,tx_hash,log_index)`；Order FK；重组保留历史观察 |
| Allocation / Register | `allocation_id:uuid PK; order_id NN; units:bigint NN; decision_version:int NN`；名册 `holder_ref,provider_ref,record_date,status` | `UQ(order_id,decision_version)`；登记 Provider 结果/版本唯一 |
| Token / OnChainTransaction | `token_id:uuid PK; offering_id NN; network,contract_address,status NN`；交易 `operation_key,tx_hash,submitted/confirmed/final_at` | `UQ(network,contract_address)`（非空时）、`UQ(operation_key)` |
| Distribution / Line | `batch_id:uuid PK; offering_id,event_type,period,record_date,status NN; gross_minor:bigint NN`；Line `holder_ref,amount_minor,payment_ref` | 已确认批次 `UQ(offering_id,event_type,period)`；`UQ(batch_id,holder_ref)` |

## 12. API 契约目录

以下为设计契约，路径版本 `/api/v1`。成功返回资源及版本；列表带 cursor；写请求统一 `Idempotency-Key`（创建/外部指令必需）、`If-Match`（编辑必需）。错误体 `{code,message,correlation_id,details}`；共通码：400 VALIDATION、401 UNAUTHENTICATED、403 ENTITLEMENT/WRONG_TENANT、404 NOT_FOUND、409 VERSION_CONFLICT/DUPLICATE/STATE_CONFLICT、422 GATE_NOT_MET、429 RATE_LIMIT、502 PROVIDER_UNAVAILABLE、504 PROVIDER_UNKNOWN。外部异步操作返回 202 + operation_id，绝不返回虚构“完成”。除公开认证/内容接口外均用服务端会话，tenant 从会话导出；投资者来源及平台后台 API 本轮仅定义内部 Adapter，不开放独立端。

详细接口以第 12.1 节为唯一开发目录；Provider Webhook 也逐项编号。

### 12.1 逐接口开发契约（85 个）

以下端点覆盖 21 个业务模块及 Provider 回调。API 版本固定前缀 `/api/v1`；只允许向后兼容新增字段，破坏性变更升版本。所有字段规则中 `!`=必填非空、`?`=选填可省略；传入显式 null 不允许，除非专项规格另批；未写 ? 的响应字段必有。UUID/enum/object 须按第 11 节实体及第 13 节状态机约束，金额为 USDT 最小单位整数，UI 的 U 仅为展示。所有响应还含 `correlation_id:string`；列表采用 cursor、limit≤100、稳定排序；日期/时间分别 ISO 8601 date 与 UTC datetime。错误统一 `{code:string,message:string,correlation_id:string,details:object?}`，共通 400/401/403/404/409/422/429/502/504。请求键在同租户/操作范围内持久化，相同键不同负载 409 KEY_CONFLICT。外部 Unknown 查询原操作，不盲重试。

| 对象 | 主要流转；触发者和前置 | 失败、重试、撤销、外部影响 |
|---|---|---|
| Session | OTP Verified→Active→Expired/Revoked；认证服务 | 错误/过期不建会话；重新 OTP；无资金影响 |
| KYB | Draft→Submitted→Reviewing→Passed/NeedsInfo/Rejected；企业提交、Provider/授权审核 | 补件保留旧资料；审核版本防旧回调覆盖；无自动资金影响 |
| Subscription | Free→Pending→Active→PastDue/Grace→Expired/Cancelled；计费事件 | Unknown 查账单；取消不删既有业务 |
| Wallet | Requested→Provisioning→Active/Failed/Unknown；MPC/Signer | 同 provider_ref 查询；已引用地址不能改；绑定挑战不可复用 |
| Asset | Draft→Ready→Archived；企业保存/检查 | Ready 失败仍 Draft；新版本编辑；已引用版本不可撤销 |
| Instrument | Draft→Ready→Superseded；企业/规则检查 | 容量/文件不合格拒绝；已引用版只新建版本 |
| Project | Draft→Ready→Active→Closed；企业+法律 Gate | 无独立前端；发布失败保持可审计待处理 |
| Offering | Draft→Confirmed→Published→Paused/Closed；企业受权确认 | 窗口/容量/钱包/条款失败不确认；发布后变更新快照 |
| Investor KYC | Unknown→Pending→Passed/NeedsInfo/Rejected/Expired；Provider | 旧决定不覆盖新版本；Issuer 不得人工放行 |
| Order | Draft→Reserved→AwaitingPayment→Paid→Allocated→Completed；投资者/系统 | 取消/到期释放容量但链上 Unknown 保护；历史不可删除 |
| Payment | Observed→Confirming→Final→Matched；链监听/匹配 | 少/多/错链进 Exception；重组回退未最终；退款独立 |
| Allocation | Pending→Decided→Registered→Reconciled；受权规则/登记机构 | 重复决定拒绝；登记失败留差异，不能假称交付 |
| Token | Planned→DeploymentSubmitted→DeployedFinal→MintSubmitted→DeliveredFinal；Signer/链 | Unknown 查询，不盲重放；链上影响不可简单撤销 |
| Distribution | Draft→Calculated→Confirmed→AwaitingFunding→Paying→Paid/ReconcileException；企业/支付机构 | 零持有人不确认；重复期间拒绝；Unknown 不重复付款 |

所有状态变化输出追加式事件、操作者/服务身份、前置版本、理由、关联 ID；涉及资金/链的状态不能仅靠 UI 撤销，须走冲正/补偿并保留双向证据。

## 14. 外部 Adapter 接入与准入

| Adapter | 输入/回调与控制 | 生产准入 |
|---|---|---|
| 邮件 OTP/通知 | 受限邮箱、模板、发送 ID；失败退避/重试，不回传验证码日志 | 域名、送达、反滥用、隐私 |
| KYB/KYC/AML | 最小资料、申请/决定版本、验签回调；过期/补件/拒绝保留 | 法域、数据处理协议、责任主体 |
| MPC Wallet/Signer | 企业/网络/操作 ID、签名挑战；Unknown 查询而非重建 | 密钥隔离、审批、恢复和签名审计 |
| OP Mainnet USDT/链监听 | 合约地址、交易/日志、确认数与重组；去重和最终性 | 合约地址、RPC、确认策略、监控 |
| 智能合约/法定登记 | 已审计版本、部署/Mint 指令、登记结果与回执 | 法律/技术审计、权限、签署和责任边界 |
| 文件存储/扫描 | 限时上传、校验和、隔离扫描、保留策略 | 恶意文件、加密、访问/删除策略 |

供应商未选定时只定义 Adapter 契约。所有回调验签/时间窗、防重放、超时、死信/人工升级、原文哈希及关联日志必须可测试；生产凭证放外部密钥管理，环境严格隔离。

## 15. 安全、运行和验收

服务端逐请求检查租户和对象级权限；跨租户 ID 返回 404/403 且不得泄露存在性。PII 脱敏、文件私有存储与扫描、密钥分权、TLS、审计追加、备份及恢复演练、API 限流、异常告警、Outbox 和幂等约束为上线 Gate。须定义 RPO/RTO、容量与延迟目标，并经工程/运营批准；本文件不虚构数值。测试至少覆盖：正常、字段失败、越权、并发写、重放、Provider 超时/旧回调、链重组、幂等重试、恢复后对账。

每个模块的最低验收：认证验证过期/重放/首次建号；KYB 五步保存/补件/旧回调；订阅续费失败/宽限/降级保留；钱包挑战重放/Provider Unknown；Asset 六模板专属必填与文件版本；Instrument 整数映射/共享容量；Project/Offering 窗口和并发确认；KYC 脱敏/资格过期；订单唯一/付款异常/退款；配售/登记/Token 三者分态及链最终性；收益零持有人、重复期间、实付差异和还本停息；门户唯一 slug 与未授权发布。每项需 API 集成、数据库约束和外部 Adapter 模拟/故障测试，不能仅由页面演示判 PASS。

住宅基准：北京朝阳住宅、两室一厅 80㎡、约定价 ¥2,000,000、估值 ¥1,900,000、月净租金 ¥8,000；**仅测试换算** 1 U=¥8，募集 250,000 U，月收益 1,000 U，50/30/20% 分别 500/300/200 U。债权基准：合同本金 400,000 U、年息 12%、月付息、到期还本；历史简化月息 4,000 U 已由第 17 节 Actual/365 Fixed 逐期计算取代，首个 31 天期间为 4,076.712329 U。两名投资者持有本金权益 250,000/150,000 U；到期本金分别偿还 250,000/150,000 U。测试应先手工创建资料、完成前置状态，再断言计算；预置快照不算通过。还需覆盖少/多付款、零持有人、重复分配、部分认购/未足额募资、部分偿还和到期后的阻断。

### 17.1 债权 Sandbox 全额认购约束（2026-11-20 审计收口）

当前 V1 Mock 仅支持完整合同本金的单次发行闭环，不支持部分募集、分期放款或动态未偿本金模型。生成债权利息或本金批次时，必须检查对应 Record Date 的有效 Sandbox 持有人快照：快照权益合计必须等于固定合同本金，Token 合计必须等于 Offering 发行数量；否则拒绝生成批次，不能将完整合同利息或本金分配给少数已认购持有人。批次确认时须重复校验快照和金额引用，防止数据被修改后绕过创建时校验。

此约束仅是当前前端 Mock 的防错规则。生产后端不得仅依赖 Token 数量推导真实放款或未偿本金；必须以权威资金放款/回款证据、法定名册和合同约定的本金余额作为计息依据。部分募集或部分放款若未来纳入范围，须另行设计并批准本金余额、计息起止、还款分配和对账状态机。
