## 1. 目标与边界

在现有九模块 Issuer 前端内补齐资产模板、权益结构、创建体验和可复现的 Mock 演示；复用 V1.0 已有页面、列表、详情、状态和交互。交付仅含页面、UI/UX、字段、表单校验、前端状态与 Mock；不开发后端、数据库、API，不接入真实支付、KYC、钱包或区块链，不新增独立管理端、复杂审批或导航。涉及法域、法律权利、估值口径及外部服务真实性的规则，未获批准前标“待确认”，不可由前端推定。

## 2. V1.0 现状：保留并复用

`App.tsx:379-416` 的九模块为工作台首页、资产与发行、投资者门户、投资者与认购、资金与结算、Token 管理、收益与分配、数据与报表、企业管理；各模块已有列表/页签或详情与 Mock 操作入口（`App.tsx:811-857,1347-3108`）。`data.ts:257-433` 提供演示资产、权益及发行数据。状态存在浏览器本地存储（`App.tsx:190-240`）；文件“扫描”、付款、Token 等均为模拟。现有 UI 的存在不等于完整业务闭环或生产可用。

资产与发行已有 Asset、Instrument、Offering 列表、详情与新建草稿；现有表单会计算缺项、提供“填充示例”、模拟文件并在 Mock 检查后推进 Ready（`App.tsx:251-376,5860-6680`）。发行页、门户、投资者/订单/持有人、资金、Token、收益、报表和企业管理已有演示页面，V1.5 不重做这些页面。已确认 Offering 引用的 Asset 禁止静默覆盖（`App.tsx:5888-5898`），沿用此保护。

## 4. 八种资产模板

字段中“基础”指资产名称、类别/模板、所在地、权利/责任主体、规模或估值口径、资料清单；保存草稿可容缺，Ready 才校验必需字段与模拟“可引用”资料。币种、计量单位、估值方法须显式显示，不能把住宅示例的 `1 U=¥8` 当通用换算。下列新增字段为 V1.5 前端建议规格；法律必需性和真实证明材料以待确认产品/法务规则为准。

| 模板 | 当前源码状态 | 专属字段与交互要求 |
|---|---|---|
| 住宅物业 | 专属表单和 Ready 校验已有 | 保留地址、户型、面积、用途、出租状态、权属、价格、评估、租金、租期、运营方及资料；空置时不强制租约/租金，出租时检查租期与合同，修正现有一律要求租约的条件（`App.tsx:251-283`）。 |
| 写字楼 | 入口已有，通用草稿 | 楼宇/楼层、建筑与可出租面积、使用/出租状态、出租率、租约和租金口径、权属、估值；按出租状态显示租约字段。 |
| 商业商铺 | 入口已有，通用草稿 | 商铺位置、建筑/套内面积、业态、使用/出租状态、租约期限、租金与权属估值；不复用住宅户型字段。 |
| 工业园/仓储物流物业 | 入口已有，通用草稿 | 园区/仓库地址、建筑与可出租面积、用途、租户/出租状态、合同期限、租金与权属估值；库区/厂房差异按适用项呈现。 |
| 非上市企业普通股权 | 分类展示已有，创建下拉不可选 | 目标公司、注册地、股权类别、持股数量/比例、权利人、权属链、估值日期/依据、限制或负担、章程/股权证明；比例范围校验并显示稀释/转让限制提示。 |
| 单笔企业借款债权 | 专属表单和 Ready 校验已有 | 保留合同编号、债权人/债务人、本金、未偿余额、合同利率、起息/到期、还本方式、履约与估值；余额不得超本金，已清偿不可 Ready（`App.tsx:286-319`）。无息合同如何表达待确认，避免用“利率必须大于 0”误拦。 |
| 企业应收账款（新增） | 仅分类目录有泛称，无专属创建 | 债务人、基础交易/合同、发票或付款凭证编号、应收金额/币种、已收与未收金额、到期日、账龄、转让/质押限制、权利人、回款状态、估值日期/依据；余额非负且不超过应收，逾期显示提示。资料建议为基础合同、发票/验收或对账、债权归属、回款证明；单笔与批量边界待确认，V1.5 默认单笔 Mock。 |
| 贵金属（新增） | 仅分类目录有泛称，无专属创建 | 金属种类、形态、重量及单位、纯度、批次/编号、保管地点和保管方、权属人、估值日、单价/总估值、检验/保管证明、保险状态；重量和纯度做范围校验，估值单位明确。是否支持多批次、交割及托管责任待确认，V1.5 只演示单批次资料。 |

两种新增模板的必要性：原分类目录已有其名称，却不能从创建表单完成资料录入；补齐可避免“目录可见、业务不可建”的误导。它们是 Asset 模板，不自动生成投资者法律权益，仍需独立选择权益结构。

## 5. 三种权益结构

`data.ts:31` 和 `App.tsx:6520-6720` 已有股权、债权、收益参与权选项、共通责任主体/权利描述/起止日/权益总量/Token 份数和整除校验；复用。当前只有债权专属字段，股权与收益参与权共用收益字段；不得标记三种结构“完成”。

| 结构 | V1.5 前端完善 |
|---|---|
| 股权 | 单独展示股权类别、发行/转让股份数、表决权、分红权、清算剩余权、限制条款及权益单位；与底层股权资产的关系明确显示，不以收益参与比例替代股份权利。是否允许非股权资产配置股权结构待确认，默认只作前端提示、不编造法律准入。 |
| 债权 | 沿用本金、固定利率、计息、付息、还本、到期字段；允许有息/无息选择并据此条件校验，清晰区分底层资产债务人与发行人对投资者的偿付义务；无息、提前还款和逾期规则待确认。 |
| 收益参与权 | 沿用收益来源、参与比例、分配频率、期限和退出安排；补收益口径、扣除项说明及是否保本的显式展示，避免将资产产权或固定利息暗示为投资者权利。 |

更换结构时提示将隐藏/清空哪些不适用字段，保存草稿后仍可查看原输入；Ready 检查按当前结构执行。法律条款和 Token 映射仅为 Mock 展示，不视为真实登记。

## 6. 创建流程与 UI/UX

问题需按实际源码修正：`Drawer` 是状态类型名，`openSurface` 已将 Asset、Instrument、Offering、收益批次的新建及详情转入 `BusinessWorkspace` 独立页面（`App.tsx:635-656,897-975`）；其他轻量操作仍调用侧栏 `DrawerPanel`。因此不做“全部 Drawer 改弹窗”的重构。长表单继续独立页面；短确认、选择、预览可用标准弹窗/现有轻量容器。检查实际仍在右侧侧栏的创建操作，只有内容超出单屏或需要多段校验时才迁移。

资产 → 权益结构 → 发行方案沿用现有入口；每步显示对象名称、所选模板/结构、完成状态和下一步。必填/条件字段就地提示，Ready 缺项可定位；保存草稿、返回、刷新后回显、切换模板和离开未保存内容都应有明确结果。现有离开确认只覆盖资产/发行编辑（`App.tsx:912-919`），新建流程需补齐。无需新增 Project 独立导航或审批中心。

## 7. Mock 演示与验收

- 八模板均可从空白创建、保存草稿、重开编辑、补齐条件字段与模拟资料后得到相符的 Ready/缺项；不同模板不混用住宅字段。四个现有通用模板及两个新增模板必须实际走通，不能以种子数据代替。
- 三权益结构各建一条草稿，验证结构切换、专属字段、错误提示、整数 Token 映射和 Asset/Instrument/Offering 引用；股权不显示收益参与权字段，债权无息不生成正常利息文案。
- 长流程在桌面及窄屏下无内容裁切；刷新和返回保留已保存 Mock 草稿，未保存内容离开有提示；列表/详情/状态一致。
- 付款、KYC、钱包、文件扫描、Token/链上等操作持续标明 Mock；清除本地存储后的恢复/重置路径可演示。验收以实际浏览器手工记录为准，本次静态审计不宣称通过。
