## 1. 内部工作阶段（一次 Goal 自主推进，独立提交）
S0 基线复核：阅读 PR17/18/20、20 验收证据，复核 F01–F05、UX01–09，尤其历史 Claim/本金、渠道隔离及公开页服务边界。将实测/源码/未验证分开，重大 FAIL 修复后再继续；不接受直接复用历史 PASS。列出六模板字段缺口和 V1.5 剩余项。
S1 Issuer 三权益表单：按 PRD §3 完成股权独立字段、债权及收益参与条件校验、Ready、详情、映射、草稿恢复及引用版本保护；原住宅/债权核心闭环回归。
S2 主体与 SPV：在现有流程中登记/引用主体、角色和证据；无需新一级导航；缺证据阻断不适格结构；支持非 SPV 与已存在单层 SPV 样例，不能据样例批准真实发行。
S3 Offering 投资者披露：配置预期回报（可选）与依据、回报口径；引用合同年利率、权益期限、收益频率；最终发布预览包含首屏公开信息及文件；固定版本、价格及测算依据；公共 DTO 白名单导出与权限测试；动态容量与募集数据独立。保留所有历史快照。
S4 V/M 页面：卡片与详情核心回报显著、简明权益摘要、完整权益文件入口、条件 SPV 模块；读取由 Issuer 输出的固定 fixture，而非复制硬编码条款。V/M 同一快照显示一致；M Listing gate 独立；模板不出现报价或认购入口。延续 PR20 正式产品 UI、中文文案、页面流程与异常守卫。
S5 跨端验收：完成下列矩阵；修复后复测。记录 fixture/export 生成命令、schema 版本、hash/字段映射、commit SHA、各端真实浏览器截图；不将本地 fixture 称为真实跨端后端集成。
S6 文档交付：字段追溯表（来源对象/字段、转换、公开条件、组件、测试、版本归属）、工程 README/操作手册增量、接口候选及待决项、验收报告；不覆盖冻结文件。建立相互引用的独立 Draft PR；完成后停止，等待独立审核。

## 3. 工程质量与交付
两端分别运行实际项目脚本（typecheck、全量测试、build、git diff --check）；干净 worktree、依赖锁文件、命令及结果、浏览器真实操作日志与本轮截图，不能复用历史截图冒充。对核心变更逐项记录 PASS/FAIL/NOT VERIFIED/BLOCKED。共享模型候选字段须具备迁移兼容策略，不能写回冻结历史数据。后端 API/数据库集成、真实资金及法律合规仍是后续工程。
最终 PR 报告提供两端基线与 HEAD、分支/PR、字段映射、批准范围对照、测试数量及截图索引、未完成/待决事项、生产边界及推荐合并顺序（不执行合并）。

## 4. 版本追溯
新增本轮 V1.1 增量映射：R01–R06 → 上述 S1–S5/X01–X12。V1.5 保留未纳入的功能及六模板深度闭环；V2.0 保留复杂 SPV/治理/分配及其余复杂功能。现有历史文件仅作为参照，不直接改写。产品负责人最终核验后才决定新的冻结版本。
