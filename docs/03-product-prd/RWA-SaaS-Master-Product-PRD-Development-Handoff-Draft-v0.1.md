## 1. 产品概述

### 1.1 产品定位【已确认】

RWA SaaS 是面向发行机构、资产管理机构和发行企业的**通用多资产Token化技术SaaS**。企业购买服务后，可在同一个工作台管理不同类别资产、多个发行项目及发行轮次，并向其自行拓展的投资者提供独立投资者门户。

产品以标准化、全球可配置为方向；**支持产品配置不等于已获某个国家、资产或金融工具的实际发行许可**。平台提供技术与业务协作能力，不默认替代发行方、持款方、法律登记方或Token签名方的真实法律责任。

### 1.2 产品目标【已确认】

1. 让发行机构从开通SaaS开始，完成资产/权利工具准备、项目与发行、投资者准入和认购、资金对账、配售登记、Token交付、收益及存续管理的完整工作流程。
2. 支持**一个企业同时管理多资产类别、多资产、多项目及多个Offering轮次**，以Project作为主要业务工作空间，模块间信息可关联和按权限筛选。
3. 建立每个发行机构独立的投资者门户，帮助其投资者完成认购和持有后的查询、领取与文件获取。
4. 将SaaS商业订阅、实际发行资格、真实资金、法定权益登记和链上Token事实清晰分开。

### 1.3 目标用户【已确认】

| 用户 | 主要目标 |
|---|---|
| 发行企业/资产管理机构 | 购买SaaS，配置机构、资产与发行，管理投资者及存续义务 |
| 发行机构管理员与业务员工 | 按角色处理项目、合规资料、审批、资金对账、Token和收益等工作 |
| 发行机构的投资者/合法代理人 | 访问该机构门户，浏览获授权Offering、完成资格与认购、查看权益及收益 |
| SaaS平台运营人员 | 商业开户/KYB、租户管理、套餐权益、权限安全、运营支持和审计 |
| 外部合法服务主体 | 按合同和适用法律提供身份核验、法律/评估、资金执行、登记、链签名等服务 |

### 1.4 非目标【已确认】

V1不默认建设平台自营的跨发行机构投资交易市场、公开自动撮合/流动性市场、高级白标多发行方运营平台或商业OpenAPI开发者产品；也不默认由SaaS平台持有投资者募集款或代客户进行有法律效力的Token签名。

### 2.2 Free与Standard【已确认】

| 项目 | Free | Standard |
|---|---|---|
| 商业模式 | **永久免费**，无试用到期倒计时 | 付费SaaS套餐 |
| 工作台 | 与Standard共用同一主要信息架构 | 同一主要工作台 |
| 业务环境 | **Sandbox模拟**：可演示资产、发行、模拟投资者、认购/资金、Token及收益流程 | 可在满足相应条件后申请/使用真实业务 |
| 真实资金/真实Token发行 | **不允许**通过Free模拟结果产生真实交易或权益 | **付费本身不等于获准生产执行**；必须另外满足发行方、具体Offering、平台自身及外部合法执行条件 |
| 升级 | 保留原Tenant与可复用合法草稿 | 不把模拟资金/订单/Token/名册直接转为真实事实 |

**待完成**：价格、账期、额度/配额、付费渠道、发票/税务细节、外部服务资源限制以及套餐展示/升级的逐页交互。

## 3. 产品组成与信息架构

产品包含四个面向用户的端；外部服务属于业务依赖，**不作为默认的第五个产品端**。

### 3.1 W｜SaaS官网【部分已确认】

**主要导航**：首页｜产品功能｜解决方案｜价格｜帮助中心；另有登录和“免费开始”。

**主要页面与功能**：
- 产品首页：价值主张、核心能力、发行流程、应用场景、套餐、FAQ。
- 产品和解决方案：展示多资产管理、发行、Token、投资者门户及发行后能力；优先面向资产管理机构和发行企业。
- 套餐/价格：展示Free与Standard；尚未定价时使用“联系销售”，不得捏造价格。
- 帮助/咨询/政策：FAQ、教程、联系销售简单表单、服务条款/隐私/Cookie/免责声明入口；不默认交付完整CRM。
- 企业注册和登录：邮箱注册及验证，成功后进入Free企业工作台；已拥有单个受权企业时直达，多个时选择企业。投资者从发行机构专属门户登录。
- Standard升级：官网提供了解/升级入口；商业KYB、合同与真实SaaS付款在企业工作台办理。

**待完成**：官网14个候选页面组逐页结构、文案、表单校验、邮件异常、Cookie管理、法律正文、响应式和视觉设计；完整官网页面范围尚未整体签收。

### 3.2 I｜发行机构企业SaaS工作台【一级和部分二级已确认】

| 一级导航 | 已确认的页面/二级组织方向 |
|---|---|
| **工作台首页** | 受权多项目进度、发行/认购/资金/Token摘要、待办、异常、快捷入口 |
| **资产与发行** | **资产库｜金融工具｜项目管理｜发行管理｜文件中心** |
| **投资者门户** | 独立一级入口；标准门户基础设置、页面展示配置入口、预览与发布 |
| **投资者与认购** | **投资者管理｜资格审核｜认购订单｜配售管理｜持有人登记** |
| **资金与结算** | **收款与对账｜退款与异常｜募集款结算** |
| **Token管理** | **合约管理｜Token操作｜链上记录与对账** |
| **收益与分配** | **存续管理｜收益分配｜到期与退出** |
| **数据与报表** | 项目/投资者/资金/登记/收益统计，审计及授权导出 |
| **企业设置** | 机构资料、成员、角色权限、套餐订阅、商业KYB与账单、安全及受权外部服务配置 |

**全局区域**：顶部当前企业/切换、消息、帮助、个人账户；待办审批、异常、通知等按权限跨模块进入。个人安全/登录设置主要从**右上个人账户**访问。

**已确定对象关系**：Asset、Instrument、Project、Offering分别管理和关联。Asset/Instrument提供列表、创建和详情；统一Project列表及创建引导；项目工作空间展示概览、资产和权利工具、Offering轮次、文件审批、业务进度；Offering从项目创建，也可在企业发行列表中查看，**每个Offering必须属于明确Project**。同企业可同时开展多项目及轮次，不按房地产、债权、黄金等资产类别拆一级菜单。

**投资者门户管理已确认的V1基础**：标准独立URL/实例、机构名称/Logo、必要法律链接、授权展示策略、预览、发布及暂停。**页面内容可视化配置的实际能力（首页板块、Banner、导航编辑、排序、保存/版本等）待完成**；高级白标域名不在V1。

### 3.3 V｜发行机构投资者门户【业务功能已确认，页面架构待完成】

**候选功能区域**：门户首页/登录、投资者资料和KYC、可见Offering列表与详情、报价和认购、法律文件/签署、钱包与稳定币付款、订单/退款、我的持仓、收益、披露/消息。

**已确定规则**：门户按Issuer隔离，投资者只能查看该机构依法允许披露的内容；身份核验、Offering专属资格与钱包控制分开；订单、资金、配售、法定登记、Token、收益各自有独立真实状态；V展示投资者本人或合法代理人有权查看的内容。

**待完成**：V端15个候选页面组的正式一级/二级导航审核与全部逐页面PRD，包括账户、交易、钱包、持仓及收益的按钮/提示/异常和样式。

### 3.4 P｜SaaS平台管理后台【业务功能已确认，页面架构待完成】

**候选功能区域**：平台总览、企业客户和商业KYB、Tenant状态与订阅权益、计费异常、任务审批、通知、套餐规则、安全审计、第三方连接、运营报表。

**已确定规则**：P只管理平台SaaS商业、授权、技术运营和必要安全支持；敏感访问要最小化且可审计；**不因拥有平台管理员权限就能代客户审批真实发行、划拨募集款或执行Token签名**。

**待完成**：P端14个候选页面组的正式导航审核与全部逐页面PRD、岗位权限和运营操作规范。

## 4. 核心业务流程【主流程已确认】

| 顺序 | 用户业务步骤 | 页面及业务应达到的结果 |
|---:|---|---|
| 1 | **购买/启用SaaS** | 企业从官网注册、验证、开通Free；需要真实商业权益时完成KYB、合同及Standard付费/授权 |
| 2 | **配置企业工作台** | 企业设置人员、角色、项目访问范围；创建并配置独立投资者门户及访问地址 |
| 3 | **准备资产与权益工具** | 建立Asset和Instrument、确认发行及相关主体、收集权属、法律/评估等必要资料 |
| 4 | **创建并发布发行项目** | 建立Project和Offering、配置价格/窗口/资格/Token/披露，审核必要发布条件并由有权人员明确发布 |
| 5 | **投资者登录及准入** | 投资者访问所属Issuer门户，完成身份、KYC/KYB/AML、Offering资格及钱包控制检查 |
| 6 | **认购及付款** | 查看合法条款、取得报价、完成必要签署、提交唯一订单及预留，按获批网络/币种付款 |
| 7 | **配售、登记及交付** | 确认真实资金匹配、完成合法配售和权威登记、按适用顺序Mint/交付Token，投资者查看持仓 |
| 8 | **募集款管理** | 企业查收款及受限/可结算金额，有权申请和审核，外部合法执行者核准划拨并确认真实到账 |
| 9 | **收益计算及准备** | 按合法记录日快照与条款计算应付，审核分配条件，核对真实注资 |
| 10 | **收益领取/实付** | 投资者查看可领与实付，按合法适用的Claim、Push或外部支付模式执行及核验 |
| 11 | **发行后与退出** | 存续披露、到期/逾期、还本/回购/赎回、法定登记变更与Token合法处置及移交 |

**待完成**：四端页面间的逐按钮跳转、每步成功/失败分支、跨端回调和异常恢复、最终可执行状态机、泳道级产品验收用例。

## 7. 核心业务规则与状态【原则已确认，精确定义待完成】

### 7.1 必须遵守的全局业务规则

1. **Portal已发布≠Offering合法可见≠当前投资者适格≠允许认购**；需要分别判断受众、法域、销售窗口和授权。
2. 投资者的**身份/KYC、当前Offering资格、代理授权、钱包控制**为不同事实。
3. **报价/签署/订单/预留、实际资金到账、配售、法定登记、Token Mint**不可用一个“购买成功”状态替代。
4. **实际到账须有最终匹配证据**；付款截图、交易哈希、提交广播不等于真正实收。
5. 收益应付、分配审批、真实注资、可领取、Claim提交和真实已支付分别显示；**Burn Token不等于法律清偿**。
6. 同Tenant多项目列表只能显示当前受权范围；**P平台管理员不自动拥有Issuer资金、登记、Signer权限**。
7. Free一律明确标Sandbox；Standard付费仅商业授权，合法发行/真实资金/Signer等需另行满足相关条件。
8. Unknown或外部超时**先查询原业务意图及权威记录**，再授权恢复；禁止盲重复扣款、退款、登记、Mint或收益发放。

## 10. 验收标准与交付要求
