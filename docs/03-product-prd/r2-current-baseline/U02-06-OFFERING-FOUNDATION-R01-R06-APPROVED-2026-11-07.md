## 1. 本批已批准的六项规则

| 编号 | 用户已批准的规则 | 明确的界限 |
|---|---|---|
| **R01 创建入口与自动关联** | Asset 详情「发行管理」TAB 进入 **创建 Offering**；自动关联当前 Asset、该 Asset 的唯一当前 Instrument **确定版本**；不要求用户再手动创建 Project | 后台保留 Asset / Instrument / Project / Offering 独立身份，必要 Project 关系自动建立；不允许关联其他 Tenant 或无有效权益来源。创建时 Asset/Instrument Ready 校验细则后批设计 |
| **R02 页面组织** | Offering 采用**单页面分区编辑**，分为「发行信息」「投资者认购条件」「发行准备」；发布拥有独立的**投资者端预览与明确确认**操作，不采用 USDable 三步创建向导 | 页面分区不是跨页步骤，详情可延续展示发行后运营状态；具体固定/可折叠布局、操作按钮、错误定位尚待 UI-Ready 设计 |
| **R03 发行数量、价格、期限与基础认购额** | 用户填写本期发行 **Token 数量**、每 Token **固定认购价格 U**、认购开始与结束时间、**单笔最低认购额**；系统自动计算本期**计划最高募集额 = 本期 Token 发行数量 × 每 Token 固定价格** | 募集上限 ≠ 实际认购额 ≠ 实际确认到账；数量不能超过 Instrument 当期可用份数；具体最小/最大认购约束、数字精度/舍入、时区及时间顺序规则下一批审核 |
| **R04 基础投资者准入** | Offering 包含基础**投资者类型（个人/机构）**、**适用地区**、**KYC 要求**、**基础锁仓期限**；由适用合规规则校验，不能默认全球任何投资者均可认购 | 本批未批准具体地域清单、默认准入规则、KYC/等级分层、资格阈值、锁仓起算事件及跨法域合规自动结论；不照抄 USDable 地区不限/L1/180天作为默认值 |
| **R05 支付边界与收款/费用待审** | V1 投资者支付方案维持 **OP Mainnet（Optimism）上的 USDT**；收款钱包、到账确认以及平台费用/分账逻辑**单独审核**，不照搬 USDable 95%/5% 自定义分账 | 不在本批批准真实资金收取、资金托管、分账服务、任何 Provider/Signer、自动退款、链上入账、收款地址归属或固定费率。SaaS 订阅支付渠道边界另按 U01 现有决策 |
| **R06 发行准备与状态区分** | 允许 **Draft 方案保存**；执行资料/配置完整性检查、投资者端预览及发布前最终确认；Free 只有内部只读预览且无法真实发布，Standard 在全部适用准入满足后才可主动发布。UI/状态应**明确区分等待开始、认购中、暂停、结束、关闭** | 字段完整 **不等于** 生产合规或链上已执行；尚未批准状态枚举名/技术事件/发布时间与起售时间冲突处理、暂停恢复权限、关闭后余量释放或无法回滚动作的具体时序，留到状态机详细批次 |

## 2. 用户视角的最小闭环（已经确认的层次，不是完整 UI-Ready）
```text
资产与发行 → 资产管理 → 某 Asset 详情 → 发行管理 TAB
  ├─ 已有 Offering：按期查看卡片/状态 → 打开独立 Offering 详情
  └─ 新建 Offering
       自动带入 Asset + 当前 Instrument 的确定版本 / 剩余 Token 可用额
       A. 发行信息：本期 Token 数量、固定单价 U、开始/结束时间
          → 系统计算计划最高募集金额
       B. 投资者认购条件：单笔最低认购额、个人/机构、地区、KYC、基础锁仓
       C. 发行准备：资料检查、适用风险与法律披露、生产准入状态
       [保存草稿] [预览投资者端]
       发布前：[最终预览与明确确认] → 再依套餐和生产技术/法律权限门
       成功发布后：在同一 Offering 详情显示等待开始/认购中等实际状态
```
- Asset 负责资产事实，Instrument 负责权利定义及 Token 权利映射，Offering 负责**本期**数量、销售价格、期限、认购准入、发行状态。不得重新录入 Asset/Instrument 已有原始权属或权益总量。
- 募集进度、认购记录、锁仓/持仓、资金、Mint 等**以各自真实主账为准**，不得将计划金额、预览示例或假数据充当事实。
- Offering 创建、保存 Draft/内部预览 **均不自动预留 Token、不触发部署/Mint、资金/募资或公开发布**；具体何时发生有效预留的业务事件后续决定。
- 用户同意单页编辑 **不等于** 不需要不可逆操作的额外确认；发行状态应由实际业务与时间条件共同决定，不能审批结束即自动当作正在认购。

## 3. 重点 Open / Candidate｜本次未批准
1. **并行 Offering 问题仍 Open**：同一 Instrument 是否允许多个 Offering **同一时间对外开放认购**，以及容量预留、撤销和释放。不能把先前未经批准的「同时最多一轮」写成已生效限制；可以先多期 Draft，最终并行限制单独审查。
2. 本期 Offering 的最低/最高认购份额或金额、最低募集成立门槛、提前结束/延期、超额认购与超募处置、限购细则、退款/退款失败、认购确认/结算/Token 分配状态。
3. 地区范围、投资者身份/资格与 KYC/AML Provider/制裁筛查、锁仓开始与解除时点、相关法规下是否允许面向个人/某法域开放。
4. 资金接收方、钱包绑定、平台费用承担及计收模型、交易与网络费用、资金到账/支付超时、链上/链下对账、平台是否可能涉及受监管资金控制。
5. Offering 信息及投资者门户字段（简介、风险披露、文件/认购协议固定版本、宣传合规、预览如何区分缺失数据）、Free/Standard 编辑差异，状态完整迁移表和异常/并发守卫。
6. 实际 Token 标准、网络、合约签署/Mint/分配、技术 Provider/Signer、生产法律证明与持有人权利确认；**R03 的数量×单价公式并不自动证明发行可安全执行**。
7. 本次未决定强制「最低募资目标」必填或把复杂阶梯/动态定价、多阶段认购一律永久排除；这些另行以 MVP 必需程度分批判断。
