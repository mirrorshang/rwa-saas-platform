# RWA SaaS × USDable｜整体产品功能差距审计（排除二级交易）

> **版本：v0.1｜日期：2026-11-09｜状态：产品对比审计稿**
> **RWA SaaS 对比基线：** DEC-057 批准后的 V1.0 五端范围（W/I/V/M/P），157 项 V1 功能。
> **USDable 依据：** 用户个人 Library 中已保存的《USDable Mock 网站浏览器产品体验与审计报告》v1.0，审计日期 2026-11-05；本次不访问外网、不重新测试 USDable。
> **比较边界：** 全面比较官网、开户、KYB、Issuer 后台、资产、权益、发行、投资者、资金、Token、收益、清退、合规、钱包、套餐、运营和报表；排除 AMM、C2C、订单簿、流动性池及其他二级交易功能。

## 1. 结论摘要

### 1.1 两个平台的产品完整度不是同一个维度

USDable 本轮审计对象主要是一个 Issuer 发行方后台 Mock 原型。它的优势是发行方后台若干运营模块已经有可见页面和可操作的 Mock 流程，尤其是收款方名录、收益上报、清退申请、持仓管控和账户安全设置。

但这次审计**没有完成投资者认购 → 持仓 → 收益领取/清退兑换的端到端闭环**，也没有验证真实钱包、真实资金、真实链上交易、多租户隔离或完整投资者门户。因此，不能将其页面入口视为已具备生产业务能力。

RWA SaaS 的 V1 产品范围则是五端体系：W 官网、I Issuer 工作台、V Issuer 独立投资者门户、M 平台统一投资端、P 平台运营后台。DEC-057 已将 M23/M24 的 11 项功能纳入 V1。我们的产品架构覆盖面更广，但许多 I 后续模块、V/M 页面和真实生产服务仍处于产品设计或待开发阶段，不能把 Approved 当成 Implemented。

### 1.2 USDable 有、而我们当前 V1 规格尚未明确覆盖的主要能力

1. **收款方名录与分账比例配置**：USDable 可建立收款方名称/钱包并在 Offering 中关联，展示 95% + 平台 5% 的分账；我们当前 Offering 主要选择一个企业最终收款钱包，没有明确的多收款方名录和比例分账 UI。
2. **使用型权益 Right**：USDable 可创建 Usage 类型、面积单位和期限；我们当前 Instrument 只批准股权、债权、收益参与权三种类型。
3. **发行方手动收益上报表单**：USDable 明确提供收益期间、金额、说明、凭证文件和“本期无收益”选项；我们 M13 已覆盖收益事件、计算、复核、注资和实付，但当前 UI-Ready 规格尚未明确同等完整的 Issuer 手动上报页面。
4. **发行方清退/兑付申请表单**：USDable 可选择 Offering、填写币种、单份兑付金额/总额、原因和材料，再进入审核与注资；我们 M13 有到期、赎回、清偿和存续责任，但当前页面字段级规格尚未明确同等的“清退申请”操作表单。
5. **发行方持有人管理视图与管控记录**：USDable 有用户持仓筛选入口，以及拉黑/解冻、强制转账的管控记录类型；我们已有 M12 法定登记、M07 Token 限制、M17 异常和 M20 审计，但没有明确的 Issuer 端持有人查询/管控页面规格。强制转账不应直接照搬，仍受 DEC-011 V2 受控转让边界约束。
6. **TOTP/Authenticator 双因素认证设置**：USDable 有 2FA 扫码和六位码设置页面；我们 U01 当前批准的是邮箱验证码登录，没有单独批准 TOTP 二次认证。
7. **更细的资产相关方字段**：USDable 资产表单可见 SPV、托管方、受托方、管理方、评估机构、注册地、许可资质、官网和联系方式等；我们已有登记权利人、发行企业关系、资产运营/管理主体、估值机构和责任主体关联，但托管方、受托方等尚未形成完整的条件字段矩阵。
8. **套餐资产数量配额**：USDable 套餐页显示基础版 2 个、高级版 5 个、定制最多 10 个资产；我们 U01 明确没有批准 Free/Standard 的资产数量、Offering 数量或 Token 总量配额，不能直接照搬。

上述第 3、4、5 项主要是**现有 V1 功能的页面与操作细节缺口**，优先在 M13/M12/M07/M21 的既有责任内补齐，不应随意新建重复主账。第 1、2、6、7、8 项需要按商业价值、MVP 简化原则和现有批准规则决定是否纳入或后置。

## 3. 重点差距清单与建议处理

### P1｜应在 V1 详细 PRD 阶段补齐的操作闭环

| 差距 | 建议承载位置 | 建议处理 |
|---|---|---|
| Issuer 手动收益上报 | M13 收益/本息管理 | 增加收益期间、收益类型、金额/币种、依据、凭证文件、本期无收益声明、审核与修正状态；与 M13 计算/注资/实付主账衔接 |
| Issuer 清退/兑付申请 | M13 到期/退出/清偿 | 明确申请对象、法律依据、每单位兑付金额/总额、币种、原因、材料、审核、真实资金注入、持有人兑换/登记/Token 注销的分离状态 |
| Issuer 持有人查询 | M12 + M21 + I 投资者/认购页面 | 至少提供按 Offering、投资者、登记状态、Token 状态查询的只读列表和详情；链上余额与法定登记分开展示 |
| 资产/发行审核责任 | M04/M05/M17/P | 明确资料 Ready、专业审核、平台渠道审核、真实发行准入的不同角色和状态，不复制 USDable 的单一“审核通过”含义 |

### P2｜是否纳入 V1，需要业务确认，不自动复制

| 差距 | USDable 做法 | 推荐判断 |
|---|---|---|
| 多收款方名录与比例分账 | 收款方钱包名录 + Offering 95%/5% 分账 | 当前 R2 已明确 Offering 选择企业最终收款钱包。先保持单收款钱包的 MVP 简化；若首发客户确有 SPV、资产方、管理方等多方分账需求，再决定是否扩展 M11 收款安排，不另建资金主账 |
| Usage 使用型权益 | Right 类型可选 Usage，按面积等单位和期限记录 | 当前只批准股权/债权/收益参与权三类 Instrument。Usage 涉及使用额度、核销、周期和服务履约，应先明确业务对象；建议 V2，不直接塞入当前 Instrument |
| TOTP/Authenticator 2FA | 有 2FA 设置页 | U01 邮箱 OTP 已是登录验证；可将 TOTP/Passkey 作为 Standard 高风险操作增强候选，不应阻塞当前基础登录闭环 |
| 托管方/受托方等资产相关方字段 | 多个第三方主体字段 | 在 M04-F004 与房地产/其他资产模板中按实际责任条件化补充；不是所有资产必填，不能默认每个项目都必须设 SPV/托管人/受托人 |
| 持有人冻结/限制名单 | 拉黑/解冻、管控记录 | 可在适用法律和有权主体授权下补齐冻结/限制状态与审计；不得把“强制转账”作为普通 Issuer 操作 |
| 套餐资产配额 | 基础 2、高级 5、定制最多 10 | U01 已明确未批准资产/Offering/Token 数量配额；不照搬竞品商业限制，后续按成本与定价单独决策 |

### P3｜可作为体验优化，不构成业务范围缺口

- 首页快捷入口、待办、最近活动和 CSV 的可见性；我们已有 I 首页与 M21，但应确保信息层级清楚。
- 宽表横向滚动和关键列固定；属于 UI/UX 细节。
- 多页面 CSV 入口统一；M21/M20 已有受控导出原则，需在页面 PRD 逐页落实。
- 公开首页 FAQ、安全介绍和帮助内容；W 已有相应页面组，后续以真实已实现能力更新文案。

## 4. USDable 本轮审计发现的 15 项问题：对我们的反向约束

本节保留原报告 F01～F15 的产品教训。二级交易相关 F02 不展开功能比较，仅记录为排除项。

| USDable 问题 | 审计事实 | 对 RWA SaaS 的设计约束 |
|---|---|---|
| F01 持久化不一致 | 收益和清算记录刷新/重登后丢失 | 所有订单、资金、收益、清退事件必须有持久化权威记录；不能靠页面局部状态 |
| F02 AMM/C2C 覆盖 | 同一 Offering 的市场行被覆盖 | 本次二级交易范围排除；仍要求不同业务对象不可互相覆盖 |
| F03 募集金额计算 | 5,000 份 × 100 USDC，募集上限却显示 5,000 USDC | 我们必须坚持本期最高募集额 = Token 份数 × 单价；金额与份数分字段展示 |
| F04 种子数据污染 | 新机构出现预置收益和其他资产领取记录 | Demo/Mock 数据按 Tenant 和 Offering 隔离；正式客户页面不展示固定预置资金/收益 |
| F05 时间状态错误 | 未来开始的 Offering 审核通过后立即显示发售中 | 已发布待开始、在售、暂停、结束、关闭必须按真实时区和时间事件转换 |
| F06 空持有人仍可注资 | 持有人为 0 仍可执行模拟收益/清退注资 | 注资/分配必须基于有效持有人快照、合法应付和真实资金，不允许无依据操作 |
| F07 Usage 周期显示异常 | 使用型 Right 的期限列显示为 — | 若未来支持 Usage，期限、单位、核销状态必须完整，不允许只做创建表单 |
| F08 关闭后容量未释放 | 0 认购关闭后仍占用全部权益容量 | 预留、实际配售、Mint、未分配释放分别定义；只释放确无在途义务的份额 |
| F09 收款方依赖体验差 | 未建收款方时发行向导不能继续，离开向导后重填 | Offering 依赖项应前置检查；草稿保留，提供就地补充或明确跳转，不丢表单 |
| F10 字段/媒体校验差 | 示例年份错误，图片预览与列表不一致 | 示例数据必须满足字段类型；上传、扫描、缩略图、列表展示状态一致 |
| F11 页面跳转断裂 | 资产市场页提示跳 Offering，但无对应入口 | 每个下一步提示必须有真实可达路由；无功能时不展示误导入口 |
| F12 投资者闭环缺失 | 无投资者/模拟认购入口，不能生成本次持仓 | V/M 投资者流程须与 M10/M11/M12/M07/M13 实际业务事实闭合；预览不能冒充认购 |
| F13 法律链接占位 | 隐私政策和服务条款链接为 # | W/V/M 上线前法律政策必须真实可访问、版本受控；Mock 不得宣传法律内容已完备 |
| F14 宽表可用性 | 关键列在横向滚动区域外 | 列表固定身份、状态、关键数量和操作列；响应式与横向滚动需验收 |
| F15 术语混用 | Right/Offering 中英文混用，关系不清 | 统一使用 Asset「资产」、Instrument「权益结构」、Offering「发行方案」；对象关系由页面明确说明 |

## 5. 不应误判为 USDable 优势的内容

以下项目虽有可见页面或入口，但本次审计未证明其完整能力：

- 投资者认购、实际付款、订单、配售、持仓、收益 Claim 和清退兑换未形成端到端闭环。
- 钱包连接显示固定 Mock 地址，没有真实签名；收益/清退哈希是占位表现。
- 收益与清算记录重登后丢失，领取页展示的是预置资产数据。
- CSV 下载内容、完整筛选、文件 MIME/大小校验、邮件送达、2FA 绑定、密码重置均未验证。
- 只有一个测试租户，不能据此判断真实多租户隔离。
- 八类资产是网站和分类页面可见范围；除写字楼外，本次没有逐一创建并验收其他类别。
- USDable 发行页面的 Ethereum/USDC 配置是 Mock UI，不等于其真实链上生产能力。
- 市场模块属于本次明确排除的二级交易范围。

## 6. 我们 V1 相比 USDable 的产品范围优势

1. **五端体系**：不仅有 Issuer 工作台，还包含 Issuer 自有 V 门户、跨 Issuer M 统一投资端、平台运营 P 和官网 W。
2. **跨 Issuer 一级投资**：Issuer 按 Offering 自愿申请上架，P 独立审核，M 统一账户和投资视图；这次 USDable 审计没有发现相应产品。
3. **投资者完整业务设计**：从身份、资格、报价、签署、订单、付款、退款、配售、法定登记、Token 到收益/本息/退出，均有明确主责模块和状态边界。
4. **资产与法律权益分离**：Asset、Instrument、Project、Offering 不混为一个对象；每 Token 权益量精确映射，不能整除则拒绝静默舍入。
5. **真实资金事实分层**：订阅款、认购款、募集款结算、收益/本息付款分别记账；到账、最终性、配售、登记、Mint、实付不能混成一个成功状态。
6. **文件版本与准备检查**：文件固定版本引用、扫描状态、Ready 失效联动、Offering 最终预览和生产 Gate 已有明确规则。
7. **多租户与统一投资者数据授权**：M/V 身份关系、Issuer 数据隔离和跨 Issuer 资料授权有明确边界；不是单个 Mock 账户的演示数据。
8. **生产准入独立**：产品页面、订阅、KYB、Provider、Signer、法律、资金、合约和真实执行权限分别检查，不以 Mock 按钮或 Standard 付费代替。

以上是产品规格和责任架构优势，不代表这些功能已经全部开发或通过独立验收。

## 7. 最终建议

- **必须补齐到 V1 详细设计**：M 端 16 页面组和 M23/M24 的 UI-Ready、M13 收益上报/清退申请页面、Issuer 持有人只读查询、资产/发行/平台渠道审核状态的边界。
- **优先评估但不自动新增范围**：多收款方分账、资产托管/受托角色字段、TOTP、冻结/限制名单。
- **暂不照搬**：Usage Right、套餐资产硬配额、强制转账、复杂多方分账默认流程。
- **继续排除**：AMM、C2C、订单簿、公开二级交易及平台自营流动性。
- **所有状态必须区分**：Product Approved、UI-Ready、Implemented、Independently Accepted、Production Ready。
