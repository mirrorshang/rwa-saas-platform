# V1.1 Issuer SaaS × V/M 跨端增量 PRD（R01–R06）

日期：2026-11-28。依据 [正式 DEC](DEC-VM-ISSUER-R01-R06-20261128.md)。状态：产品方向已批准；以下字段、校验及交互为工程实施细化，不是生产法律准入。以原 PRD 为底线，本补充仅覆盖明确的差异。未明确的生产规则不得自行填充。

## 0. 版本及兼容边界
V1.1 为 V1.0 正式交付后的独立增量版本，V1.0 继续作为工程师当前开发基线。旧接口及旧对象语义优先保持；新增字段在存量读取时允许缺失并显式标识待核实，不默认无 SPV、不将未知回报填 0、不虚构股份/本金/法律主体。新增或变更的 V1.1 发行须按本 PRD 校验；存量已确认的条款、历史订单、登记及支付记录不可原地改写。若旧接口无法安全支持新结构，以新 schema/version 或兼容适配层隔离；任何破坏性变更单独列出，等待工程师确认。未取得真实后端源码时，接口、迁移及 OpenAPI 均为候选，不宣称部署或实际迁移完成。详细交接见实施计划 §5。

## 1. 对象、来源与权限
Tenant / Issuer（企业及门户）→ AssetVersion（底层资产事实及持有人）→ InstrumentVersion（投资者法律权益、条款与映射）→ Project（自动关联）→ OfferingSnapshot（发行价格、数量、期限、披露版本及公开字段）。SPV 为主体引用，不是第四种 Instrument，也不等同 Asset subtype。区分操作 SaaS 的企业、资产法定持有人、证券/权益发行主体、债务人/偿付主体、收益责任主体；允许相同，但须有证据。只支持已有单层 SPV 的登记引用，不开发法人注册、复杂结构或穿透。保持一 Asset 一套当前有效 Instrument；历史快照不可变。

## 2. R01 六资产的公开字段映射
共同：项目名称来自 Offering；资产名称、类型、已获准公开的地区、简述、图片、估值/估值日期/口径（如披露）来自 AssetVersion；资产权利人/运营主体按授权；币种 U 的折算须有披露依据，不自行转换；无数据显示未披露，不使用 0 替代。私人住址、原始证件、合同中的个人信息、非公开估值及 KYB 材料不得默认公开。

| 类型 | 公开候选字段（源 AssetVersion，逐字段显式许可） | 证明引用（按授权，非默认公开） |
|---|---|---|
| 住宅 | 地区、户型、面积、用途、租赁状态、净租金/周期/核对日期（如有）、估值 | 权属、估值、租赁 |
| 写字楼 | 地区、面积、办公类型、出租率/时点、租赁或经营情况、估值 | 权属、估值、出租经营 |
| 商铺 | 地区、面积、商业类型、出租及经营情况、估值 | 权属、估值、租约 |
| 工业园/仓储物流 | 地区、面积、设施类型、出租/运营情况、估值 | 权属、估值、运营 |
| 非上市企业普通股权 | 标的公司、主营业务、股类、股权比例（明确分母及归属）、估值 | 公司及股权证明、估值 |
| 单笔企业借款债权 | 债务人、合同原始本金/未偿本金及核对日、底层合同利率、期限、担保/抵押披露状态 | 合同、债权证明、担保文件（如实际存在） |

以上是映射候选，不授权开放未完成模板的真实认购；保留当前开放策略和原 Ready gate。债权资产利率、余额与投资者债权条款/余额独立；底层净租金不是承诺分配金额。若模板缺少字段，列缺口；只为本次必要的核心公开字段补齐，不开展整套 V1.5。

## 3. R02 权益创建/编辑/详情（Issuer）
流程：选择 Ready Asset → 选择经法律文件支持的权益类型 → 填独立条款 → 配置总权益与 Token 精确映射 → 上传并引用核心权益文件 → 检查 Ready → 发行方案引用固定版本。原校验继续有效；草稿可保留缺项；Ready 需字段/文件/映射完整。三种表单切换不得串用其他类型值；已引用版本不直接改写。

| 字段/控件 | 适用 | 必填/校验 |
|---|---|---|
| 权益名称（文本）、权利描述（文本域） | 全部 | 必填；简明摘要，不替代合同 |
| 法律主体引用、角色（选择/引用） | 全部 | 必填；按实际结构明确权益对象、债务人或收益义务人 |
| 权益起止/期限类型（日期/固定或无固定期限） | 按类型 | 债权必须固定期限；股权允许无固定期限；收益参与按合同；有起止则先后正确 |
| 总权益、单位、Token 容量（数字） | 全部 | 正数、精准映射；保持原整数/容量守卫，不静默取整 |
| 每 Token 法律权益映射（只读推导/确认） | 全部 | 必须可核验，写入固定版本；不从认购金额推定 |
| 转让/锁定、退出/终止、风险摘要（结构化选项+说明） | 全部 | 明确有/无/按文件及具体依据；不擅自新增赎回或转让能力 |
| 股份类别、股份数量/单位、标的公司、表决权、股息及清算安排 | 股权 | 必填/明确是否有权利；分红依合法决议；股数与总权益映射一致 |
| 投资者本金总额、固定年利率/无息（仅在已批准范围）、计息规则、付息频率、还本方式 | 债权 | 本金正数且与总权益一致；现有固定利率及 Actual/365 Fixed、按月付息、到期一次还本闭环保留；无息/其他规则如未实现则列后续，不假装支持 |
| 收益来源、可分配金额口径、参与比例、分配频率、到期安排 | 收益参与权 | 明确合同扣项；参与比例 0–100% 范围内且正数；不默认返还本金 |
| 核心权益文件（引用已可用文件版本） | 全部 | Ready 必需；引用与类型、主体、条款相符 |

权益详情展示同类型字段、映射、文件版本、Ready 缺项和下一步。股权不再以收益参与比例作为必填代理；现存股权草稿需按真实文件补充，不自动把旧比例转为股份。当前两条真实 Mock 闭环（住宅/债权）必须保留。

## 4. 投资回报披露（Issuer Offering）
合同利率属于 InstrumentVersion；投资回报与认购价格有关，最终公开值固定到 OfferingSnapshot。现有发行方案增加“投资者展示信息”小区块，不新增一级菜单。引用已确认权益摘要与分配/期限，只允许在源权益编辑未引用版本；发行层不重复维护法律字段。

| 字段 | 类型及规则 |
|---|---|
| 回报披露类型 | 合同固定年利率 / 发行方预期年化（单值或区间） / 未提供；固定利率只从已确认债权权益引用；不是保证兑付 |
| 预期年化下限、上限或单值（%） | 可选；有限数值，下限≤上限；允许负值，不强制正收益；缺依据时不披露，不填 0；不可将参与比例当收益率 |
| 回报口径 | 净/毛、是否含资本增值、测算期间；明确每个展示值口径，不混用收益率与总回报 |
| 测算依据 | 披露时必填：本期发行价、现金流/估值假设、费用/税费处理、测算日期及获准披露说明/附件；不在 V1 自动生成 IRR 或保证收益 |
| 重要风险摘要 | 必填来源引用；预期非承诺，合同利率非保证兑付 |
| 版本 | 源 Asset/Instrument/Offering 引用、披露批准/确认时间及文件引用；发布后修改需新版本及披露流程 |

股权/收益参与权无获准预期回报则显示“未提供预期年化”，仍可展示真实收益来源、周期、退出。债权折溢价使收益率可能不同于合同利率：未有经核准测算时只展示合同固定年利率；不推导实际到手收益。预期回报不参与实际收益分配/金融账本。价格变化不得继续沿用不适用的测算；发布前重新确认。

## 5. R03 SPV 主体（Issuer）
在既有资产配置或关联权益页面提供“是否涉及 SPV”选项（无/有）。主体资料统一保存并引用；实现位置根据原代码最小改动，不新增独立一级导航。
涉及时：
- 法定名称、注册法域、注册编号（文本，保留前导零）、主体角色（资产持有人/权益发行主体/偿付或收益义务主体，可多角色）、与 Asset、Issuer 的关系（说明+主体引用）均必填；
- 注册证明、资产持有或授权证明、相关核心权益文件按角色与法域要求引用；不通过上传自动宣称合法；
- 股权必须明确实际股份发行主体和股份映射；债权必须明确债务人；收益参与必须明确收益义务人。SPV 存在不意味着投资者自动成为股东；
- 不涉及时隐藏 SPV 专属字段，但仍须明确真实资产持有人和权利主体；旧数据缺证据不默认不存在 SPV；
- 不默认允许任意资产×权益组合；无适格依据时阻止 Ready/发布，不自行建立全球法律规则。
前端只展示授权的法定名称、注册地区、登记编号（如可公开）、主体角色、资产/发行企业关系、投资者取得的权益、主体/权益文件入口。非 SPV 项目不展示 SPV 模块。资产持有与发行者不同即明确显示，不用 Issuer Logo 替代主体信息。

## 6. R04 发行与动态数据
| 字段 | 权威来源/校验 |
|---|---|
| 项目名、轮次、份数、单价、最低额、认购起止时间 | OfferingSnapshot；沿用 U 和原校验；最低额与份数/价格一致 |
| 发行总额 | 固定发行份数×发行单价；不等于资产估值、实际募集金额或债权本金 |
| 可售份数 | 权威容量读模型；V/M 同 Offering 同总容量；待核实不当 0 或可售 |
| 募集进度 | 已确认募集口径；注明时点与口径，不按发起支付或预留冒充到账；真实服务未接入仅用明确示例 |
| 投资期限/分配周期/退出 | InstrumentVersion；不可将认购截止日当到期日 |
| 锁定及转让限制 | 权益/发行已确认条款；不引入新市场能力 |
| 投资回报 | 本期已确认披露快照，固定利率来源可追溯 |

## 7. R05 文件与版本
以已有文件引用机制扩展公开权限与适用渠道：fileRef、category、version、所属 tenant/asset/instrument/offering、可用状态、授权范围、显示名、访问条件。分类：权益文件、认购协议、资产资料、风险披露、SPV 主体资料（适用时）。具体必需清单依据项目/法域规则；现有核心协议和发行披露 gate 不降低。确认和发布快照冻结文件引用，不自动公开全部 KYB/原始材料。直接 URL 必须同样验证访问权限；历史订单使用当时授权版本。详情页“查看完整权益文件”可定位真实可读的已授权版本；下载未接入时如实标识。阅读/下载/同意/有效签署分离。不得编造法律正文。现有示例文件保留示例提示，不假装有效。

## 8. V/M UI（PC only）
首页及卡片：项目名、公开资产类型/地区、发行企业（M 必须）、权益类型、核心回报指标（可披露时突出）、最低额、周期/期限、项目状态。待开放模板无实际报价/回报承诺/认购入口。真实服务未接入，示例资产与操作边界明确，不暴露 Mock/DEV/internal ID。沿用 PR #20 正式体验规范，V 单企业资产、Logo 品牌，M 跨企业 Listing，不增加 V 大段企业介绍，不要求遮盖 Logo 后强行差异。

详情首屏：标题、发行企业、资产图片与明确示意状态、最重要回报指标（固定年利率或预期回报，标签准确）、最低认购额、分配/付息周期、投资期限、认购状态与 CTA；缺失不编造。右栏简洁，避免与主区重复。权益模块：简短权利说明 + 关键经济条款（收益来源、分配及退出/还本/限制）+ 完整权益文件入口 + 主要风险；不堆四格内部业务对象、不隐藏重大风险。股权突出持有何主体、股息/退出条件；债权突出利率、付息、还本及风险；收益参与突出收益来源、周期及参与规则。SPV 模块条件渲染，V/M 同项目同结构/条款，公开范围按渠道授权。认购报价及文件确认引用同一版本；已形成订单/持仓保留当时版本，不因新展示条款变化而回写。1280/1440/1920 桌面验收，既有登录/KYC/钱包/认购/投后守卫不退化。

## 9. R06 公开读模型与版本
概念接口（字段名为工程候选，不宣称真实 API 已实现）：
PublishedOfferingDisclosure {schemaVersion, tenantRef, assetRef/version, instrumentRef/version, projectRef, offeringRef/revision, publicationRef, authorizedAssetSummary, publicIssuer/roleSummary, publicSpv?, rightSummary (discriminated by type), returnDisclosure?, offeringTerms, authorizedFiles[], riskSummary, confirmedAt, publishedAt, environment}
独立动态读模型：capacity/confirmedFunding/asOf/status。Issuer 确认快照保存完整内部引用；从发布快照按白名单投影公开 DTO，不将完整内部 Asset、Instrument、KYB 或文件存储地址直接送给 V/M。V/M 不另存独立可编辑回报或法律条款。M 还需 I-67/I-68 提交和 P-15 审核通过、自动上架成功、P-16 展示中；M 授权展示范围独立，暂停/下架不影响 V 或历史订单。P 不能编辑金融条款；不在本轮开发 P 页面。V/M 实际数据共享尚待后端，前端用共享 schema + Issuer 导出的固定 Mock fixture 或真实本地适配验证，明确区分与真实集成。不能以两套独立硬编码值相同作为跨端通过。不得为演示伪造真实金融服务。

## 10. 待决与范围
法律适格性、正式文件、真实数据访问和 Provider 集成；法定本金映射、跨事件本金去重、Claim 失败重试尚未批准。已确认债权总权益/Token 映射只作为来源，不能把 PR #20 示例或认购额推定为法定本金。本轮不新增线上 SPV、二级交易、复杂审批、多个权益结构、复杂现金流或生产权限。详见实施计划。
