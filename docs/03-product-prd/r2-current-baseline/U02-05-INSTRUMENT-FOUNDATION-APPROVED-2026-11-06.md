## 0A. 后续已批准的 R01 修订｜MVP 一资产一权益结构（覆盖原 R01 中的“多个”）
> **用户 2026-11-06 明确确认**：MVP 一个 Asset 最多一项**当前有效** Instrument；从「股权、债权、收益参与」三选一，允许此 Instrument 被多个 Offering（不同期）引用；不同 Instrument 并行、混合权利、优先级与分层结构推迟 V2.0。修订仅覆盖 U02-05 R01 的多结构能力及关联 UI，**R02～R06 的其余原则保留**。本条是最新有效产品设计基线，不覆盖或篡改历史文件的原始审批记录。

**对象与状态边界**：
- 一个 Asset 只能有一套当前业务 Instrument，保存 Draft、Ready、关联 Offering 后仍视为**同一套权益结构的不同状态/版本**；不可通过新增并行草稿、删除旧记录、修改路由或另建第二 Instrument 绕过 MVP 约束。
- Instrument 变更需生成可追溯历史版本；如果已被 Offering、认购、持仓、法律文件等引用，不得原地替换生效条款、解除锁定权利、清除历史容量占用或将旧 Token 映射无条件重新计算。具体修改守卫/新版本生效仍待 UI-Ready 字段与状态审查。
- Offering 可以有多个：每一期引用同一 Instrument 的**确定版本**并共享其真实授权容量；历史版本只作证据与受控引用，不能被当作新的独立权益池重复发行。
- V2.0 才考虑同一资产多 Instrument、不同权利池、混合和优先级/分层安排；**不修改原193项历史版本主表**，本次只更新 R2 产品设计交付范围。
- **三选一不等于所有三类真实生产发行可用**；仍须独立法律与技术/Provider/Signer/合约准入。

## 1. 已批准决策
| 规则 | 用户批准内容 | UI/数据责任解释 |
|---|---|---|
| **R01（后续修订，最新有效）** | Instrument 在资产详情「权益结构」TAB 创建/管理；**MVP 每个 Asset 最多一项有效 Instrument**；旧版「一资产可关联多个 Instrument」在 MVP 被明确覆盖，复杂多 Instrument 推迟 V2.0 | 用户无 Instrument 时显示创建入口；存在 Instrument 时显示**单项权益结构详情、编辑/版本和容量摘要**，不再提供「创建第二个权益结构」；历史版本记录保留，不等于第二个并行有效权益结构 |
| **R02** | MVP 产品设计采用 **股权（Equity）、债权（Debt）、收益参与（Income Participation）** 三种基础权益方向，每类采用不同动态字段 | 类型反映投资者取得的**合法或合同权利**；底层资产分类不等于权益类别；不自动把收益参与权等同股权/债权或承诺固定收益。**三类型 UI 产品范围≠三类型实际生产发行权已授权** |
| **R03** | Instrument 创建采用**四步向导**，支持草稿、返回修改、内部预览和资料完整性检查 | ①选择权益类型 → ②定义权益条款 → ③配置容量及 Token 映射（含法律文件固定版本引用）→ ④预览并确认；Draft 与完整性达标必须分开 |
| **R04** | 容量依据不同权益类型独立计量：股权「股份/份额」、债权「本金 U」、收益参与「权益比例」 | 不把股份、U 与百分比相加；不同主体、权利范围或期间的容量不得默认合并；本金数额是债权权利名义容量，不等同募集金额或资产参考估值 |
| **R05** | 一个 Instrument 在确定版本上定义**固定 Token 对应权益映射**，多个 Offering 共同占用同一 Instrument 授权容量，并展示最大可发行量、已占用与剩余可用量 | 视图至少区分：**已确认有效占用、有效预留、可新增额度**；理论 Token 最大量由授权容量与映射比例按受控精度计算；不可超发、重复预留或重复确认。发行 Draft 不产生已生效预留；关闭 Offering 不自动释放已生效权利 |
| **R06** | 支持引用 Asset 已有文件的**固定版本**，并上传当前权益结构专属法律协议；资料完整不等于真实合约部署或发行批准 | 资产文件选择器展示来源、类别、文件/版本 ID、状态、可见性；Instrument 专属文书单独归集；M06 为文书实体/版本权威；不静默覆盖旧引用 |

## 2. 前台推荐的最小路径（不新增导航）
```text
资产与发行 → 资产管理 → 选择某项 Asset → 权益结构 TAB
  ├─ 无权益结构：空状态「尚未配置权益结构」+ [创建权益结构]
  ├─ 已有权益结构：只显示该 Asset 的一项当前权益结构（含版本历史）、名称、类别、资料状态、授权容量与可用额度；不展示新建第二项
  └─ 创建/编辑 Instrument：
       1. 选择权益类型（股权 / 债权 / 收益参与）
       2. 定义权益条款（当前类动态字段 + 履约责任主体）
       3. 配置权益容量、固定 Token 映射、引用资产证明文件/上传权益协议
       4. 预览与确认（保存 Draft / 资料完整性检查）
  → 资产详情「发行管理」TAB → 从该 Asset 的 Instrument 中选择版本创建 Offering
```
- 页面每个状态都回答「我现在处于什么状态、缺什么、下一步操作是什么」；MVP **一资产一套当前权益结构**，建立后以单项详情及「编辑/查看历史版本」呈现，不展示多权益结构的列表管理/新增按钮。
- 新建、编辑、保存、资料完整性通过，均不能自动创建 Project/Offering 或触发智能合约部署、Mint、Token 发行、募资。
- 文件及权利条款需要固定版本引用；后续发行引用 InstrumentVersion，不能因为源表单变更而回溯篡改已发布条款。

## 3. 三类权益类型的业务方向（获批为类型与动态分组，不是字段冻结）
| 类型 | 主要权利 | 后续需独立审核的专属字段 |
|---|---|---|
| **股权** | 对适用法定实体股权/股份的权利 | 权益主体、股份类别/数量、持有人权利、转让条件、法定名册关系 |
| **债权** | 对债务人的合同债权 | 债务主体、本金 U、利息方式、起息/到期、偿还义务、限制及相关协议 |
| **收益参与** | 对明确收益来源、期间、口径的合同收益参与，不默认取得底层资产所有权 | 收益来源/范围、参与比例、计算和分配频率、期限、履约责任、风险披露 |

- 上述字段仅说明下一批审核的**类别与业务必要性**，**尚未批准字段逐项必填/选填、模板名称、数值精度或计算公式**。
- 对股权关联 SPV/发行载体、债权人法定权利及收益参与产品适用性，须结合原有 R2 权益类型规则和适用法律/生产准入校验。不可用模板选择直接认定法律效力。

## 4. 容量映射与防重复占用设计边界
1. 每个 Instrument/InstrumentVersion 必须明确**授权容量及单位**；具体Token 对应权益比例的计量必须量纲一致、适用精度可验证，并能在展示中解释「每个 Token 代表什么」。
2. 理论 Token 上限为固定映射与授权容量约束下的可发行总量；例如授权容量是 10% 收益参与，每 Token 对应 0.25%，理论上限 40 Token，**仅为产品解释示例，非实际发行参数**。
3. 用户应看到**最大可发行数量（Token）、已确认占用、有效预留、当前可新增的 Token 上限**；多期 Offering 共享余额不能因各自独立页面而重复使用。
4. 生效的 Token 预留/确认、释放或撤销依 Offering 真实业务状态及适用授权事件；具体幂等/并发账务、四舍五入和小数精度、Token 标准/小数位、跨链映射和 M07/Signer 技术接入均留后续详细设计及生产准入，不能预设已能安全部署。
5. **MVP 禁止同一 Asset 并行配置第二个有效 Instrument**，因此暂不设计同一 Asset 跨 Instrument 权益池分割、互斥规则与容量去重；这些复杂机制转入 V2.0。单一 Instrument **多个 Offering** 仍需共享额度，严格阻止各期重复预留、重复确认或超发。历史版本不能清空已生效的权利及容量占用。
6. 真实持有/分配/受限可转让状态不能仅从链上 Token 余额推定；Token 映射配置不是 Token 已经 Mint。
