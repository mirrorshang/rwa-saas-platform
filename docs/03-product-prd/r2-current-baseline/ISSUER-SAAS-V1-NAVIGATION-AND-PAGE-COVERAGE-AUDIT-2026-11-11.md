# RWA SaaS V1｜Issuer 企业 SaaS 导航与页面覆盖审计

> 审计日期：2026-11-11  
> 状态：**静态产品文档审计 Draft；供当前产品总控复核，不是新增 DEC 或 V1 冻结决定**  
> 审计范围：仅 Issuer 企业 SaaS；不包含官网、Issuer 投资者前台、平台统一投资端、平台运营后台和二级市场。  
> 审计目的：核对现行九个一级导航、页面入口、UI-Ready 规格、正式功能归属、旧页面冲突和剩余产品设计缺口。  
> 维护分支：docs/r2-current-product-baseline｜PR #8 Draft / Open / Unmerged。

## 1. 审计结论

### 1.1 总体结论

- Issuer 企业 SaaS 继续保持现有 **九个一级导航**，不新增菜单。
- 企业入驻与管理、资产与发行、投资者与认购、资金与结算、Token、锁仓、收益与分配、数据与共享能力的大部分当前 V1 页面规格已完成 UI-Ready。
- 原静态审计识别的 I-13 规则冲突已通过 [I-13 当前 V1 UI-Ready 收口规格](I13-ISSUER-INVESTOR-PORTAL-MANAGEMENT-UI-READY-CLOSEOUT-2026-11-11.md)修正：Free 仅内部只读预览，不配置/生成/发布门户；Standard 可配置标准基础信息，但发布/暂停/恢复须通过独立法律、服务和生产准入。
- 历史 Master 中的 63 组候选页面不能直接视为现行有效导航，也不能以“63/63 有详细文字”推断当前 V1 页面已全部 UI-Ready。该历史候选数包含已合并/取消的旧页面以及 M 渠道候选页面。
- 共享能力八个页面组已完成 UI-Ready，但入口必须遵循现行架构：待办/异常/消息/安全告警为全局入口；规则设置/外部服务归企业管理；审计记录/业务报表归数据与报表。
- 本轮只完成静态产品文档核对；未执行 UI 视觉验收、源码、Build、Browser、自动化、真实 Provider/Signer、资金、法定登记或 Token 生产验收。

### 1.2 当前页面完成状态

**审计判断：** 页面规格基本收口，门户管理仍待最终对齐。

当前可确认的企业 SaaS UI-Ready 模块：
1. 企业登录、企业创建、五步 KYB、企业管理、钱包与订阅。
2. 工作台首页与全局任务入口。
3. 资产管理、资产详情四 TAB、权益结构、Offering。
4. 认购记录、投资者管理、认购订单、配售与持有人。
5. 资金与结算。
6. Token 管理。
7. 锁仓记录。
8. 收益与分配。
9. 数据与共享能力八个页面组。

仍需处理：
- 生成唯一的 Issuer 现行导航—页面—正式功能双向映射矩阵，避免历史候选页面数量与现行导航混用。
- 完成企业 SaaS 全局状态、异常、空态、跳转、主账唯一性与体验审计。

### 6.1 全局一致性审计已核对的横向规则

1. 工作台首页的待办、异常、消息摘要应只引用全局共享页面，不在工作台重复创建任务/工单/通知主账。
2. 企业管理中规则设置、外部服务与顶部安全告警入口应保持当前导航归属，不重复添加到数据与报表二级菜单。
3. 数据报表中 Free 只可查看自身资产/权益/Offering 准备状态，不展示真实投资者、资金、Token、收益运营报表。
4. 外部服务中 Free 可使用 U01 已批准的真实 KYB/MPC 钱包等非交易型服务状态，但不得开放真实资金、生产 Signer 或 Token 执行服务。
5. 旧 Master 的角色/审批/资格页面候选应仅保留历史，不得被 Codex 或后续设计误当成当前 V1 入口。
