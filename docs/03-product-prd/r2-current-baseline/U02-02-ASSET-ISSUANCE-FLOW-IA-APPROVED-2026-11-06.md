# R2 U02-02｜资产与发行：流程、导航、详情页面结构与预览发布边界
> **状态：Approved（用户确认 R01～R08 全部 A）**｜2026-11-06｜属于 R2 当前产品基线候选，PR #8 Draft / Open / Unmerged。本文是产品决策记录及下一阶段 UI-Ready 设计约束，**不是完整字段级 PRD、生产功能准入或开发授权**。

## 0. 设计出发点与来源
- 主要参考：2026-11-05 USDable 真实浏览器审计的**按单项资产展开工作、顶部 TAB、逐步提示下一步**等体验；**不照搬**其字段、资产模板、业务权限、发行状态或 Mock 处理。
- 目标使用情境：用户判断目标企业通常约 **1～3 项资产、非高频发行**。该数字是导航简化的体验依据，**不是套餐资产数量或业务额度上限**。
- 旧 R2 的「资产管理、权益结构、项目管理、发行方案、发行准备」五个独立二级菜单被本决策取代为集中式页面入口；**底层 Asset / Instrument / Project / Offering 等业务对象及其责任边界保留**。
- 订阅、KYB、企业钱包及发布门以 [U01 最新 PRD E09](U01-UI-Ready-PRD.md) 和 [最新套餐 DEC](U01-FREE-STANDARD-ENTITLEMENT-DEC-2026-11-06.md) 为准。

## 1. R01～R08 批准决策
| ID | 已批准规则 | 对 UI/操作的影响 |
|---|---|---|
| **R01** | 发行准备并入 Offering 发行流程，保留原有发布前检查、责任确认和生产准入 | 不保留单独「发行准备」二级菜单、也不作为资产详情独立顶层 TAB |
| **R02** | **资产详情固定四个顶部 TAB：资产概览、资产资料、权益结构、发行管理** | 用户围绕同一资产切换与执行；TAB 是页面组织方式，不代表取消独立业务对象 |
| **R03** | 「资产与发行」一级导航包含 **资产管理、认购记录、锁仓记录** 三个二级入口 | 资产管理为创建入口；认购/锁仓提供跨资产查询；其记录以对应业务主账为准 |
| **R04** | Asset 详情「发行管理」TAB 按该资产列出各期 Offering，并可进入每一期独立详情，贯穿发行全生命周期 | Offering 配置、准备、发布、募集及状态管理围绕同一 Offering 详情处理；相关专业存续操作可链接原有模块 |
| **R05** | 不设置独立「相关记录」TAB | 权属/资料/文件归资产资料；认购/锁仓与发行操作归 Offering 关联视图或全局记录；收益/清算/合规由各自模块承载，不复制主账 |
| **R06** | **Offering 详情必须有投资者端预览入口**；编辑中可随时预览，发行准备结束前还要有**最终预览与明确确认** | 预览上架后的资产卡片、详情、权益说明、认购区域等实际展示样式与内容；预览读取当前真实配置，不伪造募集数据 |
| **R07** | **Free 仅可使用标准模板内部只读预览**，不能配置/生成/发布对外投资者门户页面 | 预览没有可对外访问的公开上架效果，不允许认购等真实写入；Standard 的门户配置及上线能力以 U01 条件为准 |
| **R08** | Free 即使完成全部资料准备并点击「发布发行」，也**不得**执行真实发行；进入升级 Standard 说明与入口 | 允许取消/返回，保留全部资料与预览；升级后须重新检查各项生产准入并由用户**再次主动确认发布**，不可自动部署、Mint、上架或募资 |

## 2. 已批准的导航树
```text
资产与发行（一级）
├─ 资产管理（二级）
├─ 认购记录（二级）
└─ 锁仓记录（二级）
```
- **资产详情不是第四个二级菜单**，而是经「资产管理 → 选择资产」进入的工作页面。
- 原「权益结构」「项目管理」「发行方案」「发行准备」不继续作为独立二级入口：Instrument 由资产详情管理；Project 保留必要的内部关联容器、首次创建 Offering 时自动产生，用户无须单独手动创建；Offering 从资产详情创建，发行准备在 Offering 中。
- 认购与锁仓入口用于企业真实历史的全局查询。新开通 Free 无此类业务数据、也不开放模拟认购/锁仓；前台应准确解释套餐限制，不呈现伪造记录。Standard 降级后的历史真实记录按 U01 规则只读保留。
- 发行的真实资金、Token、法律凭证、合规与收益主账不因集中式页面重新创建或复制。

## 3. 资产详情的四个顶部 TAB
| TAB | 核心职责 | 主要入口/信息 |
|---|---|---|
| **资产概览** | 资产摘要、整体准备进度、阻断原因与**唯一清晰的下一步主动作** | 到资产资料补充、权益结构创建、进入相应 Offering 等；状态必须与实际对象一致 |
| **资产资料** | 基础信息、独立子类模板属性、资产法律/估值/图片与文件信息 | 查看、编辑与保存草稿；正式字段、提交与 Ready 门槛待 U02-03 / U02-04 确定 |
| **权益结构** | 此资产关联的 Instrument 列表、创建/查看/编辑、权利定义、授权容量、Token 映射与版本引用 | Instrument 继续是独立逻辑对象，容量与法律约束沿用已批准 R2 规则 |
| **发行管理** | 此资产关联的 Offering 列表、创建/查看各期发行与状态 | 进入某期 Offering 详情：配置→检查→预览→受控发布→运营；不要求用户另开 Project |

- 四 TAB 为已批准的主要信息架构；**细分表单、子页面、Offering 内部次级 TAB 标签及字段顺序尚未批准**。
- 对外投资者端的预览并非「资产概览」中独立导航，而是**与具体 Offering 的发行条款绑定**。

## 4. 连贯业务流程与跨页面关系
1. 「资产管理」创建/保存 Asset，按已确认的分类与模板逐步完成资料；可持续保存 Draft。
2. 「资产详情 → 权益结构」创建/管理 Instrument，并维护其与 Asset 的法律/容量关联。
3. 「资产详情 → 发行管理」创建 Offering；必要 Project 关联自动建立，选择关联 Instrument；查看该资产全部轮次。
4. 进入 **Offering 详情**：填写发行方案 → 发行前资料及业务完整性检查 → 投资者端最终展示预览与确认。
5. **确认发布**：对 Free，出现升级 Standard 的限制说明，不发生生产副作用；对 Standard，先通过全部适用准入和发布校验，再由发行人明确确认并执行获准操作。
6. 成功发行后，仍由**同一 Offering 详情**呈现状态与该期募集/认购等关联记录和操作入口；对应认购、锁仓、资金、Token、收益、清算及合规实际业务分别归所属模块与主账处理。

### 4.1 Offering 预览入口与行为
- 入口一：**Offering 详情的常驻「预览投资者端」操作**，允许编辑过程中随时查看已有配置。
- 入口二：**发行准备最后阶段「最终预览与确认」**，位于确认发布之前。
- 预览展示该 Offering 未来上架后的**资产列表卡片、详情、权益/认购说明、相应法律及风险信息**的真实呈现效果。预览应区分内容缺失，不能用虚构收益率、募集进度或持仓量填充成正式披露。
- Free 只读预览标准模板，**不能编辑门户布局、创建/生成对外门户、上架、开放认购**；内部预览不生成公开链接。预览交互模拟到什么程度、完整字段映射、响应式状态与版本快照由后续 UI-Ready 批次审核，不擅自填充。

### 4.2 Free 点击「发布发行」的状态守卫
1. Free 可完成**资产、权益和 Offering 的资料/配置完整性检查**，**不可**因准备完成而显示「生产发行全部条件已通过」。
2. 可正常看到并点击发布入口；服务端权限门阻止真实写入，前端弹出明确的 **Standard 升级说明与升级入口**；「取消」回到当前 Offering。
3. 不触发合约部署、Mint、上架、资金/认购 API 或任何生产状态变更；原已保存数据、确认记录与内部预览保留。
4. 升级 Standard 后按最新版业务资料重新检查有效性、资产/Instrument 容量、版本/法律文件、钱包、网络、Provider/Signer、支付和合规等**全部适用生产准入**；用户再次主动确认，不自动发布。
5. Standard 有效亦不等于自动具备法律或技术发行许可；校验未知/失败时阻止发布并展示明确待解决项。
6. Standard 到期进入宽限/降级时，沿用 U01 **7 天宽限、停止新增真实发行、降级只读、投资者权益必要存续保障**，不能把其已有业务当成新开通 Free 的空业务重置。

## 5. 明确保留、取代与待进一步确认
### 保留与适用
- R2 原有 Asset/Instrument/Project/Offering 独立业务身份，法律/文件版本引用、权益容量管理、发行条件、链与资金执行安全门及跨模块归属。
- 企业 Free/Standard 产品权限最新决策；V1 统一 U 计价、真实投资者付款 OP Mainnet USDT；Mock 测试工具与正式 Free 权益分离。
- 资产管理与发行流程要求**每个页面让用户看懂当前状态、缺什么、下一步做什么**。

### 被本次批准取代的前台方案
- 五个独立二级菜单作为用户默认操作路径。
- 单独「发行准备」一级工作页面/导航入口。
- 「相关记录」泛化 TAB。
- Free 可通过 Mock 完成发行、募集、持仓、收益闭环作为订阅商品权益的旧假设（此项在 U01 已正式覆盖）。
