## 1. 用户已批准 R25～R30

| 编号 | Approved 产品决定 | 明确边界（Candidate/Open 不得当作已批准） |
|---|---|---|
| **R25｜发行状态机** | Offering 必须明确呈现 **草稿 → 发布成功后等待开始或认购中 → 可暂停/恢复 → 认购结束 → 必要结算处理完成后已关闭**。资料完整是检查结果、**不是**已经发布/正在认购。未来开始的 Offering 绝不因为发布/审核成功立即显示「认购中」。 | 这是面向用户的基础状态/概念，**并非**全部后端状态枚举和无条件线性顺序；被暂停发行不必经过每一状态，异常可能长期等待处理。发布成功与开放认购还受生产准入/时间/资格限制，真实事件与具体迁移守卫留给状态机 UI-Ready。 |
| **R26｜暂停与恢复** | 发行暂停时**停止接受新认购**；已经发生的支付、待交付、退款和订单继续按原义务受控处理。只有仍处于有效认购期、发布和准入条件仍满足时才能恢复。 | 暂停不是冻结/取消所有未完成订单，也不是安全地自动释放本期预留。权限/暂停原因、原子链上入口同步阻断、窗口边界、恢复重新校验与用户确认文案下一阶段细化。 |
| **R27｜结束与关闭** | 认购到截止时间后停止新增认购；**在途订单、付款、Token 交付和退款不可消失**。待必要处理完后才显示关闭；**关闭后不可直接再次开放认购**。 | 截止结束与实际业务全部结清/关闭是两件事，已确认 Token 继续保留；未分配且无在途义务的剩余预留按 R14/R24 有条件释放。提前结束/延期、异常关闭、资金冻结和退款未决的最终守卫仍须 UI-Ready 审核。 |
| **R28｜发行准备检查** | Offering「发行准备」区集中检查 **Asset、Instrument 及确定版本、本期发行参数、文件及有效引用、企业最终收款钱包、投资者准入条件**；必须**分开显示「业务资料完整」与「真实生产准入」**的结果，逐项说明缺项和下一步。 | 业务检查 Ready 不是法域法律许可、链上可部署/支付/Signer 授权。Provider/合约/钱包/USDT 合约/实际支付技术门未确认不能显示「生产可发行」。Free 保存和内部预览可完成，但不得真实发布。 |
| **R29｜投资者端预览** | Offering 可在编辑过程中随时**预览真实将呈现给投资者的页面**，包含资产卡片、资产详情、权益/每 Token 说明、认购价格、开始结束时间、资格限制与锁仓、支付币种/网络、风险和发行披露；**正式发布前再进行最终预览及明确确认**。 | 预览取 Asset/Instrument/Offering 的真实已保存/可提示未保存草稿数据，缺项须标识，不得生成虚构收益率、认购量、持仓或正式合同签署证据。Free 只有标准模板**内部只读预览**，不创建公开链接、不配置/发布对外投资者门户。 |
| **R30｜发布快照与变更保护** | Offering 发布时，对**关键业务发行配置、InstrumentVersion/法律文件固定版本、企业收款钱包**保存可审计的**确定快照**。发布后关键条件变更需受控并保存历史，不能重写已生成的订单、投资者权益或既有收款受益人事实。 | 具体字段变更白名单、快照版本、二次签署/重新披露、投资者通知及实际链上路由变更需独立审核；不能允许改钱包地址就将已付款/在途订单款项静默切走。 |

## 2. Offering 最小状态与 UI 操作（批准的方向，待细化表）
```text
新建 / 编辑：
  草稿 Draft
   ├─ 保存草稿：允许不完整资料，**不预留权益**，不触发合约/资金副作用
   ├─ 资料检查：显示资料缺项与是否完成（业务检查结果，不是发行状态）
   ├─ 预览投资者端：随时可用的内部预览，标出缺项与非正式状态
   └─ 发布操作：仅经过全部独立生产准入 + 投资者端最终预览 + 发行人明确确认

成功发布：
  ├─ 开始日期时间未到 → 等待开始（不得认购）
  └─ 合法认购期且生产门持续满足 → 认购中
 认购中 → 暂停（停止新认购，原订单仍受控处理）
 暂停 → 恢复（仅期限内且重新通过准入）
 到期/受控提前结束 → 认购结束（不再接受新认购）
 认购结束 → 完结在途支付/交付/退款与主账校验 → 已关闭（不可直接重新开放）
```
- 「暂停」在时间到达截止日时不能由简单恢复按钮绕过关闭期限；用户可见动作必须受业务状态/真实权限共同控制。
- 成功发布时按 R14/R24 占用本期额度；已交付 Token 转为确认占用；在途支付/退款争议不能被释放。正式发布没有生产准入时只能提示阻断，不得在 Mock 或 Free 页面模拟成功改成真实已发布。
- 异步收款模式支付成功但 Token 尚未交付的订单，发行到期/暂停也应保留待分配/可退款的受控义务；不能因 UI「已结束」虚构资金结清。

## 3. 页面用户体验要求（继承批准项，不追加字段审批）
- Offering 页面以 **「当前状态 / 待完成事项 / 下一步主操作」**为信息中心；避免复刻 USDable 三步向导或添加独立发行准备二级菜单。
- 草稿：首要操作「继续完善资料」/「检查发行准备」；预览随时可用。
- 发行准备：逐条展示 Asset/Instrument、Offering、投资者合规、钱包/支付和法律/技术准入的结果，并分别标「业务资料已完备」「生产准入待确认/未通过」，不误导用户。
- 发布：提交最终投资者展示版本与配置快照摘要供发行企业确认；选 Free 则展示升级 Standard 的限制说明和入口（不触发真实发行）；Standard 仍须全部生产关口通过。
- 等待开始/认购中/暂停/结束/关闭：主按钮依据当前状态选择，禁用操作应解释原因，状态变化不丢订单历史/资金和容量事实。

## 4. 仍 Open / 下一步 UI-Ready 应覆盖
1. 最终字段的输入控件、必填条件、数值精度/金额舍入、Token 整数份数及单笔最低认购 U 与价格/最小可售份数之间冲突处理。
2. 认购时间区间、暂停/恢复/延期与提前结束、结清并关闭的**完整状态迁移矩阵**（合法触发、前置条件、后置账务、副作用、幂等/异常恢复、不可逆确认）。
3. 正式发布前的生产检查清单与法律/文件有效性、资产/权益准备状态、企业钱包控制权和付款网络、Instrument 共享额度、不超过总量与未决付款义务。
4. 上架展示字段、用户文案、资产/权益/发行快照来源及缺项标记，订单支付/Token 交付/企业结算状态在投资者端与企业端的差异化呈现。
5. 发布后哪些字段可以修改、变更适用时点/哪些订单受影响、文件版本、收款账户变更二次确认、审计及对投资者的告知。
6. 付款网络 OP Mainnet USDT 的**真实当前合约及来源核验**、合规和支付 Provider/Signer、合约选型/DvP 与退款托管、手续费费率/法定责任，仍是独立技术/法律/生产准入；不能借产品状态机批准而自动通过。
7. Free、Standard、Standard 宽限与降级后的权限矩阵，独立 Mock 场景测试，不得混淆。
8. 需要定义 Browser 验收矩阵，覆盖未开始错报在售、暂停误接新单、关闭错放额度、退款在途丢失、钱包/文件快照漂移、跨租户和并发重复认购等。
