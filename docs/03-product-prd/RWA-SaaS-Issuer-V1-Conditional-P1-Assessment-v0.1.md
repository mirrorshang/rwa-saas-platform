## 一、结论概要

本次审核发现两种性质不应被混为一谈：

1. **依赖金融工具/发行模式才决定是否需要完整功能**：集中募集、部分认购/配售、收益与赎回、部分存续查询、合法送达。这些需选出 **1～2 类参考 Instrument** 才能作真实 V1 最终必需性判断；SCOPE-062 已批准此冻结前置门。
2. **基本控制本来就不可删，只有增强 UI 可后置**：M11-F010 的最低人工资金差异调查、M19-F006 强制规则优先级、M20-F007 依法或合同要求的受控数据退出/移交能力。这里“P1”描述的是**增强管理深度**，不能误解为 V1 可没有任何处理路径。

**注意**：M08-F009、M18-F004/F005、M21-F005/F006 可能因法定披露/送达/数据责任触发最低能力；必要通知或披露不能仅靠页面标注 P1 而省略。

## 三、八项已批准审核原则（SCOPE-078～085）

| 编号 | 覆盖功能 ID | 建议正式确认的业务原则 |
|---|---|---|
| **SCOPE-078** | M05-F011、M12-F010 | 集中募集/统一配售应作为一套依赖模式审核。连续购买仍为 V1 优先；首发工具要求募集期、集中配售或募集失败退款时，必须补齐最小完整业务闭环 |
| **SCOPE-079** | M10-F009、M12-F009 | 部分认购/配售和余款处理按首发 Offering 条款确定；复杂订单调整页可后置，但真实少付/多付及需要的退款、额度恢复不能丢失 |
| **SCOPE-080** | M07-F009、M13-F004、M13-F005、M13-F006 | 赎回、销毁、收益、到期偿付与外部出款对账由首发 Instrument 权利义务决定；强制/约定场景所需最小能力属于 V1 上线必要，权威登记/链上状态需独立核验 |
| **SCOPE-081** | M08-F009、M21-F005 | 收益/文件和存续期基础查询按工具应具备的投资者披露/权益可见性覆盖；必要披露保留，可后置高级收益展示与自定义报表 |
| **SCOPE-082** | M11-F010 | 资金差异人工调查路径是 V1 基础安全要求而非可有可无；P1 仅表示高级财务调查 UI/自动化可后置 |
| **SCOPE-083** | M18-F004、M18-F005 | 必要通知送达和失败恢复取决于法域/合同及渠道；需要时采用最小合规发送、记录、失败告警/重试方式，不能简单认定站内消息已合法送达 |
| **SCOPE-084** | M19-F006 | 平台强制安全/合规规则优先于租户/项目配置的底层 Guard 是必要控制；P1 仅为增强规则层级编辑界面 |
| **SCOPE-085** | M20-F007、M21-F006 | 依法/合同必需的数据退出、移交、授权报表/导出必须保留最低可用能力；复杂自定义报表和批量导出 UI 可后置 |

**正式批准的范围**：用户已明确同意 SCOPE-078～085 的八项规则，对应 16 项 P1 的**必要性判定逻辑**。本表所述条件不是已判断必然适用于首发资产的事实；参考 Instrument 的选择及是否触发需另行评审。参见[正式决策](../../decisions/SCOPE-078-085-conditional-p1-v1-baseline-principles.md)。

## 四、必须与参考 Instrument 联合验证

需先确定 **1～2 类参考金融工具** 的真实权利结构，而非直接假定“房产代币”、“债券代币”在各法域具有同一法律待遇。产品侧可采用类型化验证表（不预设国家/法律结论）：

| 检查主题 | 首发工具 A / 工具 B 应提交的验证材料 |
|---|---|
| 投资者权利 | Instrument 的法律权利与持有人登记权威、Token 法律效力及证据 |
| 募集模式 | 持续购买是否合法可行、是否要求募集截止/资金条件/统一配售、失败募集 |
| 部分配售 | 是否允许部分成交/部分接受/余额退回与额度重置 |
| 收益/偿付/赎回 | 分红/利息/租金/本金与到期义务，是否需 Token Burn 或权益注销 |
| 通知/披露 | 正式送达方式、必要文件、失败重试与披露访问义务 |
| 数据/报告 | 法定/合同报告、客户数据出口、投资者权益及审计留存 |

未完成上述核验，只能确认**通用产品规则和需要适配的能力**，不能宣称 16 项最终 V1 实际交付全部落定。
