# RWA SaaS V1｜资金与结算 UI-Ready 最终规格

> 2026-11-11｜状态：**Issuer 企业 SaaS 端产品/UI-Ready**（不代表真实资金通道、托管、退款、划拨或生产执行已获准）
>
> 唯一导航：**资金与结算**；二级导航固定为「收款与对账｜退款与异常｜募集款结算」。维护分支 \`docs/r2-current-product-baseline\`；PR #8 Draft / Open / Unmerged。
>
> 承接 DEC-008、DEC-023、DEC-053、DEC-058、DEC-069、DEC-075、DEC-076 及 U01 企业钱包/套餐规则。M11-F001～F010、F012～F013 仍是现有正式功能 ID；M11-F011 法币及多通道支付继续 V3.0，不新增正式功能 ID。

## 一、模块定位、边界和导航

### 1.1 模块目标

Issuer 企业在一个模块中看清：
1. 每个已发布 Offering 使用什么合法收款安排、企业收款钱包和收款目标；投资者应向哪里支付、金额和有效期是什么。
2. 真实资金是否到账、是否达到链上最终性、是否匹配到唯一认购订单；少付、多付、错链、迟到和 Unknown 如何处理。
3. 退款是否有合法依据、是否已批准、是否真实执行、投资者是否实际收到；不能将「申请成功」当作「退款成功」。
4. 募集资金有多少仍受限、多少仅具备申请释放条件、多少已获授权、多少已实际划拨并核实到账。

**核心原则：订单、付款指令、真实到账、对账、配售、法定登记、退款和募集款划拨是不同业务事实。** 本模块只拥有 M11 认购资金、退款和募集款释放/划拨事实，不建立第二套订单、持有人、Token 或收益主账。

### 1.2 导航（不新增一级或二级菜单）

\`\`\`text
资金与结算
├─ 收款与对账
│  ├─ 收款方案（按 Offering 查看已批准配置）
│  ├─ 付款指令（订单级）
│  ├─ 到账记录（真实资金观察）
│  └─ 认购款对账（自动匹配/待核差异）
├─ 退款与异常
│  ├─ 退款申请与处理
│  ├─ 资金异常调查
│  └─ 退款/异常详情与历史
└─ 募集款结算
   ├─ 募集资金概览与受限余额
   ├─ 释放资格核对
   ├─ 募集款划拨申请
   └─ 划拨执行与到账核验
\`\`\`

对应既有页面责任：
- **I-49**：Offering 收款安排、支付目标和付款指令。
- **I-50**：到账观察、最终性、订单匹配与认购款对账。
- **I-51**：少多付/错链/迟到账等异常、退款申请/审批/真实退款核验。
- **I-52**：募集资金受限、释放资格及可申请金额。
- **I-53**：受权划拨申请、授权证据、实际执行与到账核验。

五个既有页面责任按三个二级入口归组；不新增菜单、不调整九个一级导航，也不把资金与结算并入企业 SaaS 套餐账单。

### 1.3 资金对象隔离

| 资金类别 | 唯一责任模块 | 本模块处理 |
|---|---|---|
| 企业购买 SaaS 的 Free/Standard 订阅费 | 企业管理/商业订阅 | 不显示、不计入募集资金 |
| 投资者认购款、错款、退款 | 资金与结算（M11） | 本模块唯一负责收款、到账、订单匹配、退款事实 |
| 募集款受限余额、释放资格、受权划拨 | 资金与结算（M11） | 本模块唯一负责募集款释放/划拨事实 |
| 投资者收益、票息、股息、本金、赎回/清退 | 收益与分配（M13） | 不在本模块创建收益、赎回或清退批次 |
| 法定配售/持有人登记 | 配售与持有人（M12） | 本模块只读取其适用的配售/登记结果作为条件 |
| Token 与链上 Mint/Transfer/Burn | Token 管理（M07） | 本模块只引用链上付款事实，不控制 Token 交付 |

**已批准的三段式资金事实：**
- 收款：付款指令已发出 ≠ 投资者已付款；链上已观察 ≠ 最终到账；最终到账 ≠ 已匹配订单。
- 退款：已申请 ≠ 已批准；已批准 ≠ 已提交真实付款；已提交 ≠ 投资者已收到。
- 募集款：账面余额 ≠ 受限余额 ≠ 可申请释放；Eligible ≠ Approved；Approved ≠ Settled。

## 二、全局产品规则

### 2.1 V1 支付范围

- **V1 投资者支付：仅支持 OP Mainnet 上的 USDT。** 金额统一显示单位「U」，按 USDT 计价；不得展示尚未批准的法币、其他稳定币或其他支付网络选项。
- M11-F011 法币/多通道投资者支付仍属 V3.0，不在 V1 页面显示为可选支付方式。
- 每个 Offering 必须使用其已批准的收款安排，并关联企业已配置、有效的收款钱包；如果采用合约收款，投资者付款目标展示已核准的收款合约地址，企业收款钱包与合约地址分别显示，不混成一个地址字段。
- 收款合约、钱包或外部服务方只有在真实主体、授权、网络/币种、合约/地址和生产准入全部通过后才可启用。未部署/未核验的合约地址不得生成真实付款指令。
- 多方比例分账、平台抽成比例和多接收方拆分为 V2；V1 不提供多个收款方比例编辑器或复杂资金瀑布。
- 本页面不允许用户自行输入任意收款地址替换已批准 Offering 目标。需要变更时回到 Offering 的受控版本变更/重新确认流程；已发出的历史付款指令保留原版本。

### 2.2 收款钱包和收款目标

- 企业钱包管理仍归「企业管理 → 钱包管理」；本模块不创建、绑定、解绑或切换企业钱包。
- Offering 创建/发行准备时选择本期企业收款钱包；本模块只读取该已选钱包及与之对应的有效收款安排。
- 已发布 Offering 的收款目标不可静默修改。若钱包失效、被撤销或收款合约不可用，暂停新付款指令，提示回到受控 Offering 变更及授权流程。
- **DEC-083 已批准默认路径为经准入的 Offering 专用收款合约**。若合同/法域/生产安排不适用，才显示已获权的企业钱包或适格外部收款方作为受控例外，并记录例外依据/批准状态；不将技术地址自动视为合法收款主体。
- 地址默认缩略展示；完整地址仅提供授权详情查看/复制，并显示链、Token 合约和配置版本。

### 2.3 账号、授权和责任边界

- MVP 一个账号对应一个企业，不新增多账号、团队角色、财务角色配置页或复杂内部审批矩阵。
- 企业管理员身份不自动获得法律上的资金收款、退款批准、托管、Signer 或募集款出款权限。
- 页面可记录有权公司机关/授权主体的决定、外部受权审批、合法责任方及其证据；若适用规则要求独立批准而当前没有真实授权主体或批准证据，流程停在「待有权主体确认」，不能用单账号自批替代。
- 实际收款、退款、募集款转出由依法有权的 Issuer 主体或外部资金/托管/支付/Signer 主体执行。SaaS 负责工作流、状态、证据和核对，不默认持有客户私钥或控制客户资金。
- Free、Standard、KYB、Offering 状态和生产准入必须联合判断；购买 Standard 不等于真实资金执行许可。

### 2.4 全局列表与交互

| 项目 | 规则 |
|---|---|
| Tenant 范围 | 仅当前企业自己的 Offering、订单、付款和资金池；不得跨企业查询 |
| 默认排序 | 待核/Unknown/待处理优先，其后按最近事件时间倒序 |
| 分页 | 20 条/页；筛选、分页和返回详情保留上下文 |
| 搜索 | Offering 编号/名称、订单号、付款指令号、交易哈希、退款编号、划拨编号；投资者只用企业范围内脱敏引用编号 |
| 共同筛选 | Asset、Offering、时间范围、状态；不重复显示投资者 KYC 原始信息 |
| 金额 | U（USDT），展示实际收到/退款/划拨金额与原订单金额；部分款不隐藏差额 |
| 地址 | 默认缩略；完整地址仅在受权详情显示/复制，旁边始终显示网络和 Token |
| 事件时间 | 同时记录外部发生时间、平台接收时间和最后核对时间；不可把本地点击时间冒充链上/银行时间 |
| 未知状态 | 显示「待核实/状态未知」，不显示绿色成功，也不按 0 处理 |
| 主操作 | 每页/详情只突出当前唯一安全下一步；不显示可绕过前置条件的按钮 |
| 移动端 | 表格转卡片；保留金额、Offering/订单、链/币、核心状态和主操作 |

## 三、视图一：收款与对账（I-49 / I-50）

### 3.1 页面首页摘要

顶部按当前筛选 Offering 显示：
- 待付款指令数；
- 已观察待最终性确认数；
- 已最终到账待匹配数；
- 已匹配认购款金额；
- 部分到账/少付/多付数；
- 错链/未归属/Unknown 异常数。

每项都标注数据截至时间。某一外部数据源不可用时显示「部分数据待核」，不得把未知当作无异常。

### 3.2 收款方案列表（只读核对 Offering 配置）

| 字段 | 控件/规则 |
|---|---|
| Asset / Offering | 搜索与下拉筛选；只显示当前企业 |
| 收款方案状态 | 未配置、待核验、待生产准入、已启用、暂停、已失效 |
| 合法收款主体 | 已确认主体名称/责任说明；未确认显示「待确认」 |
| 收款目标类型 | 默认 Offering 专用收款合约；企业钱包 / 适格外部收款方仅为经批准的受控例外 |
| 企业收款钱包 | 企业钱包名称、缩略地址、有效状态；点击查看企业钱包详情 |
| 投资者付款目标 | 若采用合约，显示已核验合约地址；若采用钱包，显示已授权目标地址；不与收款钱包混同 |
| 支付资产/网络 | V1 固定显示 USDT / OP Mainnet；未获生产准入则标「不可生成真实指令」 |
| 版本与生效 | Offering 版本、收款配置版本、生效时间、最近核验时间 |
| 例外与授权依据 | 仅非默认路径显示合法收款/托管主体、例外原因、合同/法域依据、批准文件、权威许可状态 |
| 操作 | 查看详情；未发布 Offering 可「返回发行方案」调整；已发布只可走受控变更 |

**收款方案详情只读字段**
- Offering 编号/版本、Asset、InstrumentVersion；
- 法律收款主体、依据/授权材料引用；
- 收款钱包名称、地址缩略、钱包有效状态；
- 收款方式、收款合约名称/地址（适用时）、合约核验状态；
- 网络、USDT Token 合约、精度信息（只读展示已批准来源）；
- 付款有效期规则及订单金额来源；
- 生产准入状态、最近核验时间、暂停原因；
- 变更历史与引用的审批/法律文件版本。

**页面交互**
- 不提供本页直接新建任意收款方、替换地址、修改链/币种的自由编辑。
- 收款配置缺失：提示「请返回资产与发行 → 对应 Offering，完成企业收款钱包和发行收款安排」。
- 钱包失效/地址被撤销/合约 Unknown：显示警告，暂停生成新付款指令；历史交易仍可查询。
- 已发布 Offering 变更收款对象：提示需要受控版本变更、必要投资者重新确认及合法审批；不能覆盖已存在付款指令。

### 3.3 付款指令列表

| 字段 | 控件/规则 |
|---|---|
| 搜索 | 付款指令编号、认购订单号、交易哈希 |
| 筛选 | Offering、付款指令状态、订单付款状态、创建日期 |
| 列表列 | 指令编号、订单编号、脱敏投资者、Offering、应付金额 U、实收金额 U、支付网络/Token、目标地址缩略、有效截止时间、付款状态、最近核验时间、操作 |
| 操作 | 查看付款详情、查看订单、查看关联到账；不允许手工标记已付 |

**付款指令详情字段**
- 付款指令唯一编号及幂等引用；
- 认购订单编号、投资者脱敏编号、Offering 和 Quote/订单快照版本；
- 应付金额 U、已匹配金额 U、剩余待付金额 U；
- 固定支付资产 USDT、网络 OP Mainnet、Token 合约；
- 已批准付款目标类型、目标合约/钱包地址；
- 指令创建时间、有效截止时间、到期规则；
- 投资者支付状态、链上观察状态、最终性状态、订单匹配状态（分开显示）；
- 外部交易哈希/事件引用、来源和最后查询时间；
- 事件历史、异常原因、关联任务。

**付款指令规则**
- 指令只基于有效认购订单和其固定报价/Offering 版本生成；订单变更不得静默改写已发指令。
- 同一订单可按批准规则有多个真实付款事件，但同一链上事件/外部回调只能记账一次。
- 指令过期不证明未付款；若付款已观察或状态 Unknown，先查询原指令，不释放预留或生成重复支付要求。
- 指令生成/展示不代表投资者已付款，也不代表配售、登记或 Token 已完成。

### 3.4 到账记录列表与详情

**筛选字段**
- Asset、Offering、认购订单；
- 资金事件状态：观察中、待最终性、最终确认、Unknown、无效、重组/退回（适用）；
- 匹配状态：未匹配、部分匹配、已匹配、多付、少付、争议；
- 日期范围、交易哈希、目标地址（仅授权后）。

**列表列**
- 事件/到账记录编号；
- 外部交易哈希/事件编号；
- 关联订单（未匹配显示「未关联」）；
- 脱敏投资者引用（仅成功关联后显示）；
- 网络 / Token；
- 实际转入金额 U；
- 目标地址缩略；
- 链上观察时间、平台接收时间；
- 最终性状态；
- 匹配金额 U / 未匹配金额 U；
- 差异状态；
- 查看详情。

**到账详情**
- 交易哈希、事件唯一标识、来源数据源；
- OP Mainnet 网络、USDT Token 合约、转入目标；
- **链上发送方/付款来源地址（from address）**：按链上事件只读记录，默认缩略展示；有权查看时可复制完整地址；若为合约/托管/交易所地址，不推断为投资者本人钱包；
- 付款来源地址核验状态：未核验 / 与投资者已验证钱包匹配 / 不匹配 / 无法关联 / Unknown；仅在存在可靠授权钱包映射时判定匹配，不因订单关联自动认定；
- 实际金额 U、发生时间、接收时间、最后核对时间；
- 外部观察/确认/最终性证据；
- 对应付款指令和认购订单（如已匹配）；
- 已匹配金额、剩余差额、关联的其他真实付款事件；
- 重复回调识别结果、链重组/数据冲突/Unknown 原因；
- 原始证据引用、人工调查记录、审计历史。

**对账匹配规则**
- 只有网络、Token 合约、真实目标地址、交易事件、金额/订单义务和合法匹配规则均符合，才可进入 FinalMatched。
- **资金事件匹配状态**与**付款来源主体关联状态**必须分开记录。来源地址与投资者已验证钱包不匹配、无法关联或 Unknown 时，不得自动认定付款人身份，也不得仅凭不匹配自动拒绝真实到账；应按已批准的付款主体/第三方代付规则核验。若适用规则要求确认付款主体，则在主体关系或合法代付依据核实前不得进入 FinalMatched；若适用规则不要求来源地址必须属于投资者，则按其他已批准匹配条件判断，不能把地址不匹配本身作为资金未到账的证据。
- 单个订单多笔真实转账可在规则允许且有清晰证据时合并匹配；不同订单不能因金额相同而随意合并。
- 同一事件重复回调去重；不同交易哈希的两笔真实付款不得误判为重复。
- 少付/多付/未归属/错链/假币/迟到账必须单独标记，不自动变成订单已付款。
- 手工关联只允许「提交匹配复核」并附原因/证据；普通企业账号不能直接改写真实到账事实。最终匹配以受权规则和真实来源证据确立。
- FinalMatched 仅表示某笔认购款已被真实核实并匹配到订单；不表示合法配售、法定登记、Token Mint 或募集款可释放。

## 四、视图二：退款与异常（I-51）

### 4.1 退款概览与列表

顶部摘要：

### 4.3 退款详情与处理步骤

详情按五组展示：
1. **订单与收款来源**：订单/Offering/InstrumentVersion、Quote 快照、原付款指令、真实收款事件及 FinalMatched 金额。
2. **退款依据与受益人**：全额/部分、原因、法律/合同依据、合法退款受益主体、目标地址/账户核验和文件版本。
3. **审批与授权**：申请人、实际有权批准主体、授权证明、批准金额上限、有效期、拒绝/补件/撤销理由；若适用独立审批但没有合法证据则保持待核。
4. **实际退款执行**：唯一退款 Intent、真实执行主体、外部交易/付款引用、提交/最终性/实际出款与收款核对、费用和差额。
5. **事件历史与异常**：原始请求、每次外部回执、Unknown 查询、部分退款、退回、人工复核和审计记录。

**退款状态（产品可读状态，不冻结工程枚举）**
- 草稿/待提交 → 已提交待核 → 待有权审批 → 需补件 / 已拒绝 / 已批准；
- 已批准 → 待执行 → 执行中 / Unknown → 部分退款 / 已核实完成 / 执行失败 / 已退回 / 争议调查。
- 申请已提交不能显示「退款成功」；已批准不能显示「已退款」；链上交易已广播不能显示「投资者已收到」。
- Unknown 只能查询原退款 Intent 和真实付款方，不得直接再发一笔。
- 部分退款保留未退金额及责任，不把订单或退款标记为全额完成。

### 4.4 退款的明确业务守卫

- 退款是新的真实出款，不是原认购转账的撤销。
- 退款总额不能超过已核实可退款实收、扣除已退款金额、其他有效承诺和依法受限金额后的权威可退额度；金额由权威资金事实提供，前端不自行估算可退余额。
- 退款目标必须是合法受益人经核验的目标；原始付款地址可能是交易所、托管钱包或代付地址，不自动等于退款地址。原始付款来源地址作为资金事件证据保留，与退款受益人/退款目标分别记录。
- 已合法配售且法定持有人权益登记已经生效时，普通认购退款入口阻断；如需赎回/清退/到期退出，跳转「收益与分配 → 到期与退出」，不得以订单取消撤销法定权利。
- 资格未通过、订单取消、发行失败或多付等情况，仍需依据合同/法律和资金实际状态决定退款，不自动推断必退或可退。
- 退款失败、退回、错链或制裁/司法限制时保留资金及证据，进入受权调查；不承诺不可逆转账一定可追回。

### 4.5 异常调查列表与详情

**异常类别**：少付、多付、错链、假币/错误 Token 合约、迟到账、未归属付款、重复回调、重复付款指令、资金来源/收款目标不匹配、支付 Unknown、链重组/确认不足、退款目标不匹配、退款失败/退回、退款 Unknown、外部数据冲突。

列表字段：异常编号、类别、订单/Offering、相关付款/退款 Intent、金额 U、发现时间、当前状态、责任方、下一步、最近更新。

详情字段：原始订单义务、所有真实收款/退款事件、差异金额、网络/Token/目标地址、来源和证据、异常原因、当前资金事实、关联退款/配售/登记状态、负责的业务主体、调查记录、处理决定与审计历史。

**调查操作**
- 「重新查询原指令/外部事件」：仅查询，不创建新支付/退款。
- 「提交匹配复核」：填写建议订单/证据/说明，待权威核验。
- 「发起退款申请」：只有满足退款守卫时出现。
- 「升级受权调查」：生成异常任务引用并保留原事实。
- 不提供「手工改成已到账」「删除异常」「覆盖交易哈希」「忽略差异并继续配售」等操作。

### 5.2 释放资格与受限资金详情

筛选：Asset、Offering/资金池、资格状态、限制类别、更新时间。

字段：
- 资金池/合法资金持有人/收款主体引用；

- 退款义务及有效承诺；
- 冻结/受限原因、文件/决定依据、有效期间；
- 计算后的受限金额、已承诺金额、可申请释放候选金额（权威结果）；
- 计算规则版本、来源完整性、核验责任方；
- 当前状态：Restricted / EvidencePending / Eligible / Blocked / Unknown（产品可读候选标签）。

**释放资格规则**
- Eligible 仅表示在当前已确认规则和证据下可以提交申请，不代表 Issuer 已批准、X 已同意、资金已转出或收款人已到账。

- 投资者 Token 的业务锁仓期限/链上解除状态，不直接等同于募集款受限或释放资格；募集款是否可释放仍以 Offering/Instrument 资金条款、合法收款与资金持有人、退款义务、争议/冻结、有效募集条件及受权证据为准。若具体合同/法域明确将锁仓或其他持有人限制设为资金释放条件，必须引用该适用依据和权威状态，不得由页面自行推断。
- 不得用钱包当前余额直接推导可释放金额；必须同时考虑合法收款来源、退款义务、争议/冻结、有效募集条件、已承诺未划拨及同一 As-of 的来源证据。
- 法律/合同/资金来源规则缺失或冲突时显示 Blocked/Unknown，并列出缺失证据；不开放申请按钮。
- 一个资金池可存在多个独立合法划拨申请；每个申请须对金额进行有效占用，防止并发超额承诺。

### 5.5 划拨详情与执行跟踪

按五个阶段分开展示：

1. **释放资格**：Eligible/Blocked/Unknown、来源和规则版本、快照时间、有效期。
2. **申请**：申请人、金额、用途、接收主体/账户、Offering 依据和文件版本。
3. **审批授权**：真实有权审批主体、批准/拒绝/补件、金额上限、目的方、有效期、撤销/过期记录。没有合法独立批准证据时不进入执行。
4. **实际执行**：真实付款/Signer主体、唯一 Transfer Intent、外部交易哈希/银行或服务方引用、提交时间、实际出款金额 U、状态。
5. **受领到账核验**：受款方实际到账金额 U、证据、时间、费用/差额、部分/退回/Unknown 及对账结论。

**划拨状态（产品可读候选）**
- 资格：Restricted / EvidencePending / Eligible / Blocked / Unknown。
- 授权：NotRequested / Requested / NeedsInfo / ApprovedScoped / Rejected / Revoked / Expired。
- 执行/对账：NotSubmitted / Submitted / PendingFinality / Unknown / PartiallySettled / Settled / FailedVerified / ReturnedOrDisputed。

三个状态独立展示。不能以审批状态绿色覆盖真实执行 Unknown，也不能以链上 TxHash/Provider Accepted 显示 Settled。

**不可变更规则**
- 批准必须绑定接收主体、账户/钱包、资产/网络、金额上限、用途和有效期。
- 批准后若更换接收方、账户、金额、币种/网络或用途，原批准不可继续复用；应依法重新核验/授权并生成新的 Intent。
- Unknown 先查询原 Intent，保留金额占用；禁止盲目重发。
- 真实部分出款/到账显示 PartiallySettled，保留未结差额和后续责任。
- 只有实际出款与适用的受领到账事实均达到该资金安排的合法核验条件，才可显示 Settled；具体法律完成点仍由实际资金工具/法域确认。
- 本页面不直接操作私钥、签名或客户钱包，不提供平台管理员代客户转账。

## 六、跨模块流程与业务状态

### 6.1 投资者认购收款闭环

\`\`\`text
Offering 已发布且收款方案/企业收款钱包有效
 → M10 唯一认购订单与固定报价
 → 生成订单级 USDT / OP Mainnet 付款指令
 → 投资者按指令付款
 → M11 观察真实链上事件与最终性
 → 真实到账事件与唯一订单匹配（FinalMatched）
 → M12 独立执行合法配售/登记
 → M07 独立执行 Token 交付并对账
\`\`\`

任一环节 Unknown 均保持独立状态；付款成功不自动配售、登记或 Mint。

### 6.2 退款闭环

\`\`\`text
真实认购款已核实
 → 存在 Offering/合同/法律允许的退款事由
 → 关联原订单与原始实收事件
 → 核验合法退款受益主体与目标账户/钱包
 → 提交申请及依据
 → 有权主体批准（如适用）
 → X 通过原授权通道发起一笔独立退款
 → 核实实际出款与投资者受领到账
 → 更新退款真实结果、剩余义务及审计
\`\`\`

已形成合法持有人权益的退出/清退不得借用普通退款流程。

### 6.3 募集款释放与划拨闭环

\`\`\`text
真实认购款 FinalMatched
 → 读取 Offering/Instrument/法律限制/退款/争议与 M12 适用事实
 → M11 生成同一 As-of 的受限资金快照
 → Eligible / Blocked / Unknown
 → Eligible 时 Issuer 提交有依据的划拨申请
 → 真实有权主体核验并授权
 → 唯一 Transfer Intent
 → X 真实执行
 → 核对实际出款及受款到账（足额/部分/Unknown/退回）
 → M11 记录真实划拨与审计
\`\`\`

不得把募集款划拨与 M13 投资者收益/本息付款混为一谈。

| 资产与发行 → Offering | 查看收款钱包和 Offering 固定配置；已发布收款目标变更走受控版本流程 |
| 企业管理 → 钱包管理 | 查看企业钱包有效性/授权；本模块不绑定或切换钱包 |
| Token 管理 | 查看收款合约/链事件所需关联，不在此 Mint/Burn |
| 收益与分配 → 到期与退出 | 处理赎回/清退/本息；不在本模块发起普通认购退款替代 |
| 数据与报表 | 受控只读导出；报表不创建第二套资金主账 |
| 工作台待办/异常 | 引用原退款/划拨/差异编号；工单关闭不覆盖资金事实 |

## 七、Free / Standard、降级、隐私与权限

| 企业状态 | 收款/对账 | 退款/异常 | 募集款结算 |
|---|---|---|---|
| KYB 未通过/审核中/补件 | 按统一认证门禁拦截，不展示真实资金详情 | 禁止 | 禁止 |
| Free 新企业 | 可查看 Offering 准备状态/说明；不生成真实付款指令、真实收款或模拟客户数据 | 不开放真实退款 | 不开放真实募集款释放/划拨 |
| Standard + KYB 通过但生产准入未通过 | 可只读查看已配置/待准入原因；不生成真实指令、不执行真实收款 | 可查看历史真实记录（若企业有历史合法业务）；不得发起未获准执行 | 只读显示待准入/受限，不允许真实划拨 |
| Standard + 生产准入通过 | 在批准的 USDT / OP Mainnet 收款安排内使用真实收款与对账；具体通道按Offering启用 | 仅合法事由、受权主体与真实执行通道齐备后开放 | 仅满足真实法律/资金/授权门槛后开放 |
| Standard 宽限期 | 按已批准 U01 规则处理，不新增未授权真实募资；既有退款/资金义务继续受控 | 必要存续处理不得因商业状态自动删除 | 在途资金与已承诺法定义务按受控方式承接 |
| 已降级 · 存续服务 | 历史资金与付款只读查询；原指令/事件不重置 | 仅可就降级前既有订单/退款/异常提交证据、补件与受控核验请求；不直接批准退款或代付 | 现有资金和合法划拨义务只读跟踪，可提交必要履约凭证与异常响应；不新建划拨或恢复资金执行权 |

**隐私**
- 投资者仅展示企业业务所需脱敏引用；不展示完整 KYC、证件、AML/制裁报告。
- 收款/退款/受领钱包地址默认脱敏，完整地址仅授权详情可见。
- 外部银行/支付/托管账户资料只向有合法业务必要的主体展示。
- 所有记录 Tenant 隔离；跨企业 URL 直达必须拒绝且不泄漏记录是否存在。
- 资金和交易事件不可删除；纠正以追加证据和新版本完成。

## 八、异常处理总表

| 场景 | 页面表现/下一步 | 禁止行为 |
|---|---|---|
| 收款方案缺失 | 「请先在 Offering 完成收款钱包和合法收款安排」 | 生成任意收款地址 |
| 收款钱包失效/合约未核验 | 「当前不能生成真实付款指令」 | 使用旧地址继续收款 |
| 投资者支付指令过期但链上已观察 | 「付款状态待核实」→ 查询原指令 | 直接标未付款/释放预留 |
| 重复回调 | 关联原事件并提示「重复事件已识别」 | 重复增加实收金额 |
| 两笔不同真实付款 | 分别记录并按订单规则核对 | 错误合并成同一交易 |
| 少付/多付 | 显示应付、实收和差额；进入异常 | 自动认购完成/超额自动退款 |
| 错链/假币 | 标记无效/待调查，展示真实 Token/网络 | 将同名代币认作 USDT |
| Unknown/数据源不可用 | 「暂不能确认资金结果」 | 视为失败或成功 |
| 付款最终到账但未匹配 | 「已观察真实资金，订单尚未匹配」 | 随意关联投资者/订单 |
| 退款目标不匹配 | 阻断提交/执行，要求合法受益人证据 | 默认退回原发送地址 |
| 退款批准但未执行 | 「已批准，等待实际退款」 | 显示退款完成 |
| 退款 Unknown | 查询原退款 Intent | 创建第二笔退款 |
| 退款部分完成 | 显示已退/剩余金额和责任 | 把部分退款标记全额完成 |
| 订单已配售且法定登记有效 | 普通退款入口阻断，跳转到期与退出 | 订单取消撤销持有人权利 |
| Eligible 但未获授权 | 「具备申请条件，等待有权审批」 | 显示可直接提款 |
| 划拨批准后收款方/用途/网络变更 | 旧批准失效，重新核验/授权 | 复用原批准或签名 |
| 划拨执行 Unknown | 查询原 Intent 并保留金额占用 | 盲重试/重复出款 |
| 部分划拨/受领 | 显示已出款、已到账、差额分列 | 标记全部 Settled |
| SaaS 降级/暂停 | 历史记录只读，保留在途和法定义务 | 删除或清零资金事实 |
| 订阅费与募集款混淆 | 显示资金域提示和来源 | SaaS 订阅余额抵扣募集款 |

## 十、V1 不扩张与交付结论
