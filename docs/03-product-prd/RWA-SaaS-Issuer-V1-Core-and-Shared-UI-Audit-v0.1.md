> 2026-10-22｜基于 [187 项交付候选分类](RWA-SaaS-Issuer-V1-Delivery-Candidate-Categorization-v0.1.md)、[第 04 份冻结流程与不变量](../04-business-workflows/RWA-SaaS-Core-Business-Workflows-and-State-Machines-v0.1.md)、[冻结功能树](RWA-SaaS-Product-Function-Tree-and-Module-Responsibility-Matrix-v0.1.md)、[ARCH-001](../../decisions/ARCH-001-api-first-unified-business-core.md)。
> **审核范围：仅 73 项“共享业务核心需实现”+42 项“共享界面/简化实现”=115 项，且全为 P0；未对另外 10 项外部执行、16 项条件性 P1、46 项其他功能作正式实现深度审定。**

## 1. 审核结论

**结论：产品负责人已确认 SCOPE-063～070 的跨模块主责/Guard、页面群与 API-First 设计原则，但没有批准具体页面路线和研发交付清单。**

1. **42 项“界面可简化”仍是 P0 业务能力。** 特别是 M01-F004/F006、M02-F004/F007、M03-F005、M05-F008、M06-F003 等，后端必须保证租户、权限、状态、证据与审计；“少做页面”绝不等于“删去服务器责任”。
2. **73 项“共享核心”也不代表 73 个独立服务或 API 端点**。ARCH-001 允许模块化单体；一个领域命令可在多个界面复用，多个事件仍须独立表示不同权威金融事实。
3. 识别八类跨模块“容易重复建设或错误合并”的边界（B01～B08），建议在后续详细 PRD 中统一标注权威主责任、支持模块及 API Guard。
4. 提议按**三个使用界面**（平台运营、发行机构、投资者）组织页面群，横向审批/通知/规则/审计集成统一复用。页面群只是信息架构建议，不代表页面数、导航已冻结。
5. 本轮不是代码审计；仓库中的产品规格与分类建议提供审查依据，具体实现、Build、API 契约、E2E 尚不存在或不属于本次审查范围，不能宣称工程验证通过。

## 4. 三个界面的页面群合并建议（不是固定页数）

| 页面群建议 | 用户侧 | 可以共用/收拢的内容 |
|---|---|---|
| **P-01 SaaS 客户开通与授权** | 平台运营端 | M01-F001～F007、M03-F001/F002；合同、租户和授权用同一生命周期，操作入口统一 |
| **P-02 平台支持与安全协助** | 平台运营端 | M03-F005、M17、M20；默认无越权访问，支持和审计经批准授权 |
| **I-01 工作台概览、组织与权限** | 发行机构端 | M02、M21-F001、M18；项目概览与统一待办，可有成员/权限设置子页 |
| **I-02 Asset / Instrument、发行资料** | 发行机构端 | M04、M06 归档与证明材料；资产与权利分层、版本不可覆盖 |
| **I-03 Project / Offering 配置与审批** | 发行机构端 | M05、M06、M19 规则；可集中在 Project/Offering 工作区，通过分步区块完成 |
| **I-04 投资者资格与认购订单** | 发行机构端 | M09、M10；表格/详情页共用，但审核和订单权威状态分开 |
| **I-05 Token 交付、配售登记** | 发行机构端 | M07、M12；配售/登记/Token 三类状态分别展示并可对账 |
| **I-06 支付、退款与异常** | 发行机构端 | M11、M17；共享订单关联与异常入口，资金仍以 M11 为权威 |
| **I-07 存续及基础报表** | 发行机构端 | M13、M21；按 Instrument 提供必要持有人权益与披露查询 |
| **V-01 Offering 发现与详情** | 投资者门户 | M08-F001～F003；只展示有权限且生效的条款 |
| **V-02 KYC/资格引导** | 投资者门户 | M08-F004 + M09；资格守卫统一由 M09 负责 |
| **V-03 购买与支付** | 投资者门户 | M08-F005～F007 + M10/M11；必要同意、稳定币支付状态及异常 |
| **V-04 订单和持仓** | 投资者门户 | M08-F007/F008 + M10～M13；不同权威事实状态派生 |
| **X-01 共享任务、通知与规则** | 横向共用 | M17～M19；通用组件不形成第二套金融事实 |
| **X-02 审计与服务商集成** | 横向共用 | M20、M22；多端可复用，后台独立 Guard |

**说明**：建议把“菜单页面数”和“功能数量”分开计算。例如一个 Offering 详情可以有资产/条款/资格/文档/审核/发布多个区域，却保持 M04/M05/M06/M09/M19 不同权威对象。图中 15 个**逻辑页面群**并不要求首期恰好开发 15 个 URL/页面；需要第 06 份 UI/UX 文档和实际用户旅程进一步评审。
