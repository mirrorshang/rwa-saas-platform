# RWA SaaS × USDable｜整体产品功能差距审计（排除二级交易）

> **版本：v0.2｜日期：2026-11-09｜状态：DEC-058 功能取舍已批准；V1 UI-Ready 补充规格已形成**
> **RWA SaaS 对比基线：** DEC-057 批准后的 V1.0 五端范围（W/I/V/M/P），157 项 V1 功能。
> **USDable 依据：** 用户个人 Library 中已保存的《USDable Mock 网站浏览器产品体验与审计报告》v1.0，审计日期 2026-11-05；本次不访问外网、不重新测试 USDable。
> **比较边界：** 全面比较官网、开户、KYB、Issuer 后台、资产、权益、发行、投资者、资金、Token、收益、清退、合规、钱包、套餐、运营和报表；排除 AMM、C2C、订单簿、流动性池及其他二级交易功能。

## 1. 结论摘要

### 1.1 两个平台的产品完整度不是同一个维度

USDable 本轮审计对象是一个 Issuer 发行方后台 Demo。**本次比较以其可见功能列表、页面结构、字段点和操作流程为参考，不以 Demo 是否真正完成生产级实现作为功能取舍标准。** 原始审计中的实际操作结果、页面说明和未覆盖项仍保留证据标记，但不因此否定相关功能作为产品参考的价值。

RWA SaaS 的 V1 产品范围为五端体系：W 官网、I Issuer 工作台、V Issuer 独立投资者门户、M 平台统一投资端、P 平台运营后台。DEC-057 已将 M23/M24 的 11 项功能纳入 V1。我们的产品范围与 USDable 的发行方 Demo 不是同一产品形态；本次重点是识别可借鉴的 Issuer 功能点，并判断是否纳入现有 V1 责任模块。

### 1.2 本轮已确认的功能取舍（DEC-058）

| USDable 功能点 | RWA SaaS 处理决定 | 版本 |
|---|---|---|
| 收款方名录 | 不建立独立收款方名录；每个 Offering 选择一个企业已配置的有效钱包作为最终收款钱包 | V1 有单一钱包选择，不提供独立名录 |
| 多收款方、比例分账 | 保留扩展，不做多方收款比例分配 | V2 |
| 使用型权益 Right | V1 继续只支持股权、债权、收益参与权 | V2 |
| 手动收益上报 | 补齐收益期间、Record Date、金额 U、说明、凭证、本期无收益、复核及后续批次衔接 | V1 / M13 |
| 清退/兑付申请 | 补齐法律依据、Offering、Record Date、兑付金额、原因、材料、审核、注资及结算进度 | V1 / M13 |
| 持有人管理 | 补齐持有人列表、筛选、详情、法定登记/Token 对账和受权限制处理入口；不提供强制转账 | V1 / M12、M07、M17、M20、M21 |

| Authenticator / TOTP | 不增加独立 TOTP 功能，继续采用邮箱验证码登录 | 不纳入 |
| 套餐资产数量配额 | 不照搬 2/5/10 个资产限制，不增加硬配额 | 不纳入；Free / Standard 为准 |

| AMM/C2C/订单簿/流动性 | 不属于本轮 V1 功能采纳范围 | 排除 V1 |

其中，收益上报、清退/兑付、持有人管理、资产相关方已通过独立补充规格细化；不新增正式功能 ID。V1 仍为 157 项，DEC-017 原 193 项主表不改写。

| 差距 | USDable 做法 | 推荐判断 |
|---|---|---|
| 多收款方名录与比例分账 | 收款方名录 + Offering 95%/5% | V1 每个 Offering 选择一个企业有效钱包；多受益方及比例分账明确后置 V2 |
| Usage 使用型权益 | Right 可选 Usage、面积/单位/期限 | V1 继续只支持股权/债权/收益参与权；Usage 的使用额度、核销和履约对象后置 V2 |
| TOTP/Authenticator 2FA | 有 Authenticator 扫码和六位码设置页 | 用户明确决定不增加独立 TOTP；继续采用 U01 邮箱验证码登录 |
| 托管方/受托方等资产相关方字段 | SPV、托管方、受托方、管理方、估值机构等 | 已批准 V1 条件字段补充；仅真实适用角色出现，不将 SPV/托管/受托设为所有资产必填 |
| 持有人冻结/限制名单及强制转账 | 拉黑/解冻、强制转账管控类型 | V1 展示限制状态并允许发起受权处理复核；不提供一键拉黑/解冻或强制转账 |
| 套餐资产配额 | 基础 2、高级 5、定制最多 10 | 不采纳；U01 E09 Free / Standard 权益矩阵为唯一权威，不设置资产/Offering/Token 数量硬配额 |

### P3｜可作为体验优化，不构成业务范围缺口

- 首页快捷入口、待办、最近活动和 CSV 的可见性；我们已有 I 首页与 M21，但应确保信息层级清楚。
- 宽表横向滚动和关键列固定；属于 UI/UX 细节。
- 多页面 CSV 入口统一；M21/M20 已有受控导出原则，需在页面 PRD 逐页落实。
- 公开首页 FAQ、安全介绍和帮助内容；W 已有相应页面组，后续以真实已实现能力更新文案。

## 4. USDable 本轮审计发现的 15 项问题：对我们的反向约束

本节保留原报告 F01～F15 的产品教训。二级交易相关 F02 不展开功能比较，仅记录为排除项。

| USDable 问题 | 审计事实 | 对 RWA SaaS 的设计约束 |
|---|---|---|
| F01 持久化不一致 | 收益和清算记录刷新/重登后丢失 | 所有订单、资金、收益、清退事件必须有持久化权威记录；不能靠页面局部状态 |
| F02 AMM/C2C 覆盖 | 同一 Offering 的市场行被覆盖 | 本次二级交易范围排除；仍要求不同业务对象不可互相覆盖 |
| F03 募集金额计算 | 5,000 份 × 100 USDC，募集上限却显示 5,000 USDC | 我们必须坚持本期最高募集额 = Token 份数 × 单价；金额与份数分字段展示 |
| F04 种子数据污染 | 新机构出现预置收益和其他资产领取记录 | Demo/Mock 数据按 Tenant 和 Offering 隔离；正式客户页面不展示固定预置资金/收益 |
| F05 时间状态错误 | 未来开始的 Offering 审核通过后立即显示发售中 | 已发布待开始、在售、暂停、结束、关闭必须按真实时区和时间事件转换 |
| F06 空持有人仍可注资 | 持有人为 0 仍可执行模拟收益/清退注资 | 注资/分配必须基于有效持有人快照、合法应付和真实资金，不允许无依据操作 |
| F07 Usage 周期显示异常 | 使用型 Right 的期限列显示为 — | 若未来支持 Usage，期限、单位、核销状态必须完整，不允许只做创建表单 |
| F08 关闭后容量未释放 | 0 认购关闭后仍占用全部权益容量 | 预留、实际配售、Mint、未分配释放分别定义；只释放确无在途义务的份额 |
| F09 收款方依赖体验差 | 未建收款方时发行向导不能继续，离开向导后重填 | Offering 依赖项应前置检查；草稿保留，提供就地补充或明确跳转，不丢表单 |
| F10 字段/媒体校验差 | 示例年份错误，图片预览与列表不一致 | 示例数据必须满足字段类型；上传、扫描、缩略图、列表展示状态一致 |
| F11 页面跳转断裂 | 资产市场页提示跳 Offering，但无对应入口 | 每个下一步提示必须有真实可达路由；无功能时不展示误导入口 |
| F12 投资者闭环缺失 | 无投资者/模拟认购入口，不能生成本次持仓 | V/M 投资者流程须与 M10/M11/M12/M07/M13 实际业务事实闭合；预览不能冒充认购 |
| F13 法律链接占位 | 隐私政策和服务条款链接为 # | W/V/M 上线前法律政策必须真实可访问、版本受控；Mock 不得宣传法律内容已完备 |
| F14 宽表可用性 | 关键列在横向滚动区域外 | 列表固定身份、状态、关键数量和操作列；响应式与横向滚动需验收 |
| F15 术语混用 | Right/Offering 中英文混用，关系不清 | 统一使用 Asset「资产」、Instrument「权益结构」、Offering「发行方案」；对象关系由页面明确说明 |

## 5. 本次功能参考的范围边界

本轮以原始审计报告中可见的导航、功能入口、字段和操作作为产品参考。未在该报告中出现的功能，只能表述为「本次审计未见」，不能推断 USDable 全部产品都不具备；资产类别、法域或其他未逐项列出的动态配置也不作超范围推断。原报告的 F01～F15 仍保留为交互与数据设计教训，但不以 Demo 的持久化、钱包或资金模拟完成度决定本轮功能是否采纳。

本轮比较排除 AMM、C2C、订单簿、公开二级交易和流动性池；它们不作为 V1 采纳依据。

## 6. 我们 V1 相比 USDable 的产品范围优势

1. **五端体系**：不仅有 Issuer 工作台，还包含 Issuer 自有 V 门户、跨 Issuer M 统一投资端、平台运营 P 和官网 W。
2. **跨 Issuer 一级投资**：Issuer 按 Offering 自愿申请上架，P 独立审核，M 统一账户和投资视图；这次 USDable 审计没有发现相应产品。
3. **投资者完整业务设计**：从身份、资格、报价、签署、订单、付款、退款、配售、法定登记、Token 到收益/本息/退出，均有明确主责模块和状态边界。
4. **资产与法律权益分离**：Asset、Instrument、Project、Offering 不混为一个对象；每 Token 权益量精确映射，不能整除则拒绝静默舍入。
5. **真实资金事实分层**：订阅款、认购款、募集款结算、收益/本息付款分别记账；到账、最终性、配售、登记、Mint、实付不能混成一个成功状态。
6. **文件版本与准备检查**：文件固定版本引用、扫描状态、Ready 失效联动、Offering 最终预览和生产 Gate 已有明确规则。
7. **多租户与统一投资者数据授权**：M/V 身份关系、Issuer 数据隔离和跨 Issuer 资料授权有明确边界；不是单个 Mock 账户的演示数据。
8. **生产准入独立**：产品页面、订阅、KYB、Provider、Signer、法律、资金、合约和真实执行权限分别检查，不以 Mock 按钮或 Standard 付费代替。

以上是产品规格和责任架构优势，不代表这些功能已经全部开发或通过独立验收。

## 7. USDable 有而 RWA SaaS 当前 V1 没有的功能点

以下按 DEC-058 处理后的实际差异列出；其中有些是明确后置/不采纳，有些需要另行判断，不应全部理解为 V1 必须增加。

| USDable 功能点 | 我们 V1 当前情况 | 处理结论 |
|---|---|---|
| 独立收款方名录 | 每个 Offering 直接选择一个企业有效钱包，不建立独立收款方对象 | 不做；V1 维持单一钱包选择 |
| 多收款方及比例分账 | 不支持一个 Offering 按比例向多个收款主体分配 | V2 |
| Usage 使用型权益 | Instrument 仅有股权、债权、收益参与权 | V2 |
| 预期年化收益区间 | Instrument 不要求发行方填写预测年化区间，避免把预测包装成承诺 | 不照搬；保留合同/法律收益口径 |
| 债权周期付息频率及具体付息日 | 当前有固定年利率、起息日、到期日和到期一次还本；尚未形成通用的周期付息计划/具体付息日 UI | **候选差距**；建议单独评估是否补充简单月/季/半年/年度付息规则，不在 DEC-058 中自动批准 |
| TOTP / Authenticator | U01 使用邮箱验证码登录，无独立 TOTP 页面 | 不纳入 V1 |
| 密码注册、登录、找回及修改 | 我们采用邮箱验证码无密码登录 | 有意差异，不复制 |
| 套餐资产数量硬配额 | Free / Standard 不设 Asset、Offering、Token 数量硬配额 | 不采纳 USDable 2/5/10 限额 |
| 一键拉黑/解冻、强制转账 | V1 只允许查看限制状态、发起受权复核；不允许普通 Issuer 用户直接强制转账 | 一键操作和强制转账不纳入 V1 |
| 全部资产类别的可创建模板 | 我们有 8 大类/24 子类目录，但 V1 实际只开放四种房地产模板 | 其他资产模板按既有 V2 规划后置 |
| AMM / C2C / 订单簿 / 流动性 / 公开二级交易 | 不属于 V1 | 排除 V1，沿用既有版本边界 |

**已经通过本轮补充设计、不再列为缺口的功能：** Issuer 收益上报、清退/兑付申请、持有人查询与管理视图、资产相关方字段。它们已分别补入 M13、M12、M04 的既有 V1 责任，不新增正式功能 ID。

## 8. 最终结论与后续使用

- **已批准并补齐 V1 详细设计**：M13 收益上报、M13 清退/兑付申请、M12 持有人管理/查询、M04 资产相关方条件字段；详见 [DEC-058](../../decisions/DEC-058-usdable-feature-reference-v1-scope-approved.md) 与 [V1 UI-Ready 补充规格](r2-current-baseline/USDABLE-V1-FUNCTION-ADOPTION-AND-UI-READY-ADDENDUM-2026-11-09.md)。
- **明确后置 V2**：多收款方名录/比例分账、Usage 使用型权益。
- **明确不纳入 V1**：TOTP、密码体系照搬、USDable 套餐资产硬配额、强制转账。
- **继续排除 V1**：AMM、C2C、订单簿、公开二级交易及平台自营流动性。
- Free / Standard 严格执行 U01 E09，不参考 USDable 资产数量限制。
- 所有状态必须区分：Product Approved、UI-Ready、Implemented、Independently Accepted、Production Ready。
