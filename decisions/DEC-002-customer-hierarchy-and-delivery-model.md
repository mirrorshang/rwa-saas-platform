# DEC-002｜客户层级与商业交付模式

- 日期：2026-10-16
- 状态：**Approved（已由产品决策确认）**
- 关联决策：DEC-001（客户独立资产门户与授权分发）、DEC-003（多资产架构与首期资产范围）、DEC-004（受监管活动责任边界）
- 关联文档：[第 02 份《产品战略与商业模式》](../docs/02-product-strategy/RWA-SaaS-Product-Strategy-Business-Model-v01.md)
- 决策范围：确认产品线和 V1 客户层级原则；不代表全部功能规格、定价、部署模式或法律责任已经确定，也不代表第 02 份战略文档整体冻结。

## 已确认决策

1. **Issuer SaaS（标准 SaaS）**：默认服务单一发行机构/资产管理客户，为其提供发行与存续期管理软件及配套投资者门户；不默认将不同客户合并到同一个资产管理或投资者门户空间。
2. **White-label（白标交付）**：V1 支持一个白标运营商管理多家发行机构，并运营自有品牌的投资者门户/平台。
3. **白标资产可见性与授权**：白标门户只展示运营商自有资产或获得明确分发授权的资产，并受组织权限、投资者资格、资产/Offering 条件和适用法域约束；该原则同时遵循 DEC-001。
4. **V1 不支持多级代理/转售层级**：一个白标运营商之下的多层代理、经销或转售关系不属于 V1 已确认范围。未来是否增加须另行产品、运营和法律评估。
5. **Open API / SDK 是独立商业交付线**：面向有自身系统和集成能力的金融科技公司及机构客户，独立验证 API/SDK 产品能力、开发者体验、用量模型与支持方式；不强制沿用 Issuer SaaS 或 White-label 的销售与套餐结构。
6. **共享核心、区分交付**：三条商业交付线可以共享核心数据模型、工作流和基础服务，但须按客户角色、数据访问、品牌、授权、部署、支持和合同边界分别配置，不能只通过换品牌来代替真实的租户隔离与权限控制。

## 不包含的决策

- 三条产品线的最终套餐、价格点、额度和 SLA（后续遵循 DEC-010）； 
- 是否提供专属部署、独立基础设施、源码交付或非标准定制；
- 白标运营商是否可转售第三方服务、收取渠道佣金或建立多层合作网络；
- 任何市场下发行、招揽/分销、支付、托管、登记、交易或收益支付的许可与责任分配（遵循 DEC-004，并须另行法律及合作方验证）；
- 投资者身份与 KYC 信息跨租户复用的具体机制（遵循 DEC-007）；
- 是否建设 SaaS 厂商自营的统一资产聚合市场。

## 对产品设计的约束

- 数据模型应明确 Tenant / SaaS Customer、Organization / Legal Entity、Issuer、White-label Operator、Investor Portal 和授权资产范围之间的关系。
- 权限校验必须同时覆盖租户、组织、角色、资产/Offering、门户授权与投资者资格，不能仅凭登录状态或品牌入口授予访问。
- 白标运营商管理多家发行机构不代表这些发行机构之间可以默认共享数据、投资者资料或资产分发权限。
- API/SDK 必须使用分级授权、可审计的凭证与权限边界；不能因为客户通过 API 接入就绕过与门户相同的业务、合规和数据隔离规则。
- SaaS 客户退出、白标授权撤销或合同终止时，应设计资产展示撤回、数据导出、记录保留、未完成业务处理及责任迁移机制。

## 后续工作

1. 在第 03 份总体 PRD 中明确三条产品线的用户角色、租户/组织模型、核心工作流及权限边界。
2. 在第 05 份合规与资格规格中细化资产授权、投资者资格和法域约束。
3. 在第 07 份架构文档中落实租户隔离、组织关系、授权检查、审计和 API 安全。
4. 在第 09 份商业运营文档中结合 DEC-010 验证套餐、计费维度、实施服务和支持等级。

本决策只有经后续明确的产品变更决议才能修改；竞品推断、工程便利或单一客户要求均不能自动覆盖上述原则。
