## 1. 设计目的与审计结论

本轮消除重复导航、过度管理页面及不必要企业操作；坚持用户只操作自己需要做的事，系统在合法授权和真实前置满足后自动处理；技术与审计细节按需展开。

### 1.1 七项已批准变更

| 项目 | 批准的新口径 | 不得误删的后端/业务事实 |
|---|---|---|
| 认购记录与锁仓记录 | 从「资产与发行」二级菜单移除；认购记录并入认购订单的「已完成」筛选；锁仓记录并入持有人详情/记录视图 | 唯一订单、交付及锁仓事件、历史快照、导出范围、三类限制、异常追溯 |
| Issuer 投资者门户管理 | 简化为「网站配置」+「网站地址与预览」，平台统一域名下企业前缀 | 企业及 Offering 披露校验、发布准入、环境与服务状态、Free/Standard 隔离 |
| 配售与持有人 | 前台更名「持有人管理」；正常基础配售由已获准规则自动处理，异常/依法需人工授权时显式跟进 | 配售唯一决定、法定名册权威、权益与 Token 分离、资金和能力守卫 |
| 数据与报表 | 仅「业务报表」「操作记录」二级菜单；待办并入工作台；消息留顶部；异常优先原业务页面 | 审计追加记录、通知与必要追踪、原业务异常/服务证据 |
| 企业管理 | 删除「规则设置」「外部服务」二级菜单；保留资料/KYB、钱包、套餐 | 强制业务规则、实际服务可用状态仍作为各原业务守卫 |
| 投资者管理 | 列表/详情精简为脱敏身份、KYC 当前结果、认购、持有 | KYC 平台权威、隐私隔离、必要历史留存、授权变更 |
| 资产与发行结构 | 改为「资产管理｜权益结构｜发行管理」三个二级入口；取消资产详情原「权益结构」「发行管理」TAB | Asset→唯一当前 Instrument→多期 Offering 的对象关系、版本快照与共享容量 |

### 1.2 交叉一致性检查（已完成）

- 认购历史只有订单主账；「已完成」必须为实收最终匹配且 Token 交付最终确认；法定登记状态仍单列。已完成认购允许按原权限受控导出脱敏结果；订单异常/退款仍在完整订单生命周期视图。
- 业务锁仓由已发布 Offering 锁仓条款+有效配售+Token 实际最终交付生成；交付前的事项只标为「待交付预期」；每个交付批次单独起算，不因为 UI 合并而合并期限。链上限制、法律/管理冻结与业务锁仓三种状态必须分开。
- 「持有人管理」是显示和跟进法定登记结果，而不是允许企业直接修改链上 Token 余额/法律权益；配售可以系统自动，但前提是规则获准、资金 FinalMatched、容量有效、适用签署/KYC/法律条件满足。需合法逐笔决定或登记的情形仍保留受控处理/证据，不假设 SaaS 用户天然有法定权限。
- 实际投资者可能与付款钱包、接收钱包、法定持有人不同；不能以钱包 Token 数量替代合法持有人。
- 资产权益容量唯一归 Instrument；权益列表只是跨 Asset 投影，不允许独立无资产创建 Instrument；Offering 只能引用确定的 Ready InstrumentVersion。Asset 一套当前权益结构，允许多个 Offering。
- 网站企业域名前缀是**平台统一域名体系内的受控租户标识**，不等于企业自定义域名，也不保证未获准的门户可公开访问；需要合法命名、唯一性、保留字与变更保护。
- 本地一键切换 Standard 只为内部 Web 验收，不能绕过真实生产准入，也不把本地 Mock 记录升级成生产事实。
- 页面精简不变更 V1 正式功能 ID 或历史版本归属，只调整企业 UI 可见入口、字段优先级及页面实现方式。

## 2. 九大一级导航（精简版）

| 一级导航 | 二级入口/形态 | 核心工作 |
|---|---|---|
| 工作台首页 | 一级首页，无独立二级 | 汇总业务与待办、异常提醒、快捷入口 |
| 资产与发行 | **资产管理｜权益结构｜发行管理** | 建资产、定义投资者权益、创建及准备 Offering |
| 投资者门户 | 一级入口单页 | 网站配置；网站地址及预览 |
| 投资者与认购 | **投资者管理｜认购订单｜持有人管理** | 查投资者、查/处理订单、查持有人及必要登记异常 |
| 资金与结算 | 收款与对账｜退款与异常｜募集款结算 | 查看到账、退款、结算 |
| Token 管理 | 合约管理｜Token 操作｜链上记录与对账 | 查看 Token 方案、受控发行/销毁及链状态 |
| 收益与分配 | 存续管理｜收益分配｜到期与退出 | 收益上报、计算支付、到期退出 |
| 数据与报表 | **业务报表｜操作记录** | 汇总和导出、查操作历史 |
| 企业管理 | **企业资料与 KYB｜钱包管理｜套餐订阅** | 管主体、钱包、套餐 |

全局但不产生二级菜单：工作台「待办」区、顶部「消息」入口；必要异常在原业务页展示，平台支持入口按需出现。取消独立 Issuer「异常工单」「规则设置」「外部服务」「安全与服务状态」复杂页面的常规导航暴露；原来源事实/服务守卫不取消。

## 3. 资产与发行：三个独立二级入口的 UI-Ready

### 3.1 资产管理

**列表字段**：资产名称/编号、一级/二级资产类型、关键资产摘要（不同模板按各自法律单位）、估值 U 与基准日（有来源时）、资料 Draft/Ready、权益配置状态、关联 Offering 数量、最近更新、操作「查看/继续编辑」。  
**列表交互**：关键词、资产类型、资料状态筛选；创建资产；分页；空态、错误及资料不足引导。创建资产仍用现有 7 大类/23 子类目录，V1 只开放房地产四个、普通非上市企业股权一个、单笔借款债权一个。  
**资产创建/编辑**：原五步及对应模板字段、必需/选填文件、关联主体、版本保护、示例填充全部保留；未开放子类不能进入通用假表单。
**资产详情结构**：页头名称/类型/资料状态及主动作；主体信息与资产类型专属字段；权利人/相关方；法律/估值与文件/版本；底部两张关联摘要卡「权益结构」「发行记录」并提供进入对应二级页面的深链。  
**取消**：资产详情不再以「权益结构」「发行管理」作为 TAB；避免同时保留等价的四 TAB 和三个二级入口。资产概览与资产资料可用同页分区或轻量锚点；不创建第二套业务数据。

### 3.2 权益结构

**入口**：从二级导航进入跨资产权益列表，或从某资产详情「配置/查看权益」深链进入并自动选中 Asset。  
**列表字段**：资产名称/编号、权益结构类型（股权/债权/收益参与权）、当前 InstrumentVersion、Draft/Ready、法律权益总量及单位、Token 最大份数、已占用/已预留/剩余可发行容量（仅可信来源）、关联 Offering 数、最近更新、操作。  
**操作**：「按资产配置权益」先选择现有 Asset；Asset 无当前权益时允许创建；已有时仅打开其唯一当前 Instrument，不允许建立第二套当前权益。可搜索、按类型/状态/资产筛选，空态直达选择资产。  
**详情/编辑**：保留已确认的单页三组「权益定义｜Token 拆分与容量｜法律文件」、主体与责任关系、精确映射/不能整除拒绝、Ready 与引用版本保护；不同资产只给推荐类型，不以资产分类简单硬禁其他两种。  
**关联动作**：Ready 且满足前置资料要求时显示「创建发行方案」跳到发行管理并带入 Asset 和确定 InstrumentVersion；未 Ready 时清楚提示缺项。

### 3.3 发行管理

**入口**：二级导航全企业 Offering 列表；或权益详情/资产详情「创建发行」深链，自动预选 Asset 及其 Ready InstrumentVersion。  
**列表字段**：Offering 名称/编号与期次、资产、权益类型、引用版本、本期 Token 份数、每 Token 价格 U、目标募资额 U、认购时间/时区、当前生命周期状态、发布/预览状态、最近更新、操作。  
**筛选**：关键词、Asset、发行状态、发行时间；基本分页、空态。默认最近创建/更新优先（依原 Offering 最终 PRD）。  
**创建前置**：先选 Asset → 系统展示其唯一当前 Ready InstrumentVersion 和剩余授权额度；不存在时提示「先配置权益」，并能跳转。不得从 Offering 单独创造资产或权益。  
**创建/编辑**：保留原 A「发行信息」B「认购规则」C「发行准备」单页三区，收款钱包选择、认购时间/额度/价格、文件披露、准备检查、内部最终预览及发布前守卫；不得新建 Project 二级菜单或独立发行准备页。  
**Offering 详情**：状态/阻断/唯一下一步、发行参数与固定快照、关联资产权益、投资者预览、订单/资金/Token 摘要及权威模块深链；取消资产详情内等价 Offering TAB。  
**Free/Standard**：Free 可编辑正式发行准备资料及内部只读预览；Standard 生产发布仍由独立真实准入决定。前端 Mock 发布只能显示明确的内部流程模拟，不能假装生产成功。

## 4. Issuer 投资者门户：两区单页 UI-Ready

### 4.1 网站配置

| 字段 | 规则/控件 |
|---|---|
| 企业网站名称 | 必填文本；仅影响对外展示标题，不修改法定主体 |
| Logo | 选填图片上传/预览/替换；文件格式与大小遵守现有文件规范 |
| 企业专属前缀 | 必填 slug 输入，展示完整预期地址；小写英文、数字及中划线，3–32 字符；不能以中划线开头/结尾或连续中划线；保留字禁止，大小写规范化 |
| 平台统一域名 | 只读，由环境/正式配置返回，不在前端硬编码真实域名 |
| 可用性检查 | 本地原型模拟格式/重复值；真实唯一性必须由未来服务端在保存和发布时再次校验 |
| 保存/取消 | Standard 基础配置可保存草稿并取消本次修改；保存不等于公开生效 |

**前缀策略**：同一平台正式命名空间必须唯一，禁 admin/api/login/support/system 等保留名，防钓鱼和近似冒用检查由后续服务完成。发布后修改前缀需要明确地址变更/历史链接失效风险及二次确认；真实变更依服务能力，当前 Web Mock 不可宣称已真实变更 DNS/路由。

### 4.2 网站地址、预览及状态

| 信息/交互 | 规则 |
|---|---|
| 门户状态 | 未创建/配置中/已发布/已暂停/待核实等，来自权威状态或明确的本地预览状态 |
| 网站地址 | Standard 只有在真实已获准创建且返回有效 URL 后才显示可复制/对外打开；未获准只显示「预期地址（未启用）」且不可作为公网真实链接 |
| 网站预览 | 反映名称/Logo/前缀及当前企业可展示 Offering 的效果；草稿预览明确标注内部预览 |
| Offering 列表 | 只读引用 Offering 发布与披露来源，不能在此编辑、人工强制上架、改变 Offering 状态 |
| 发布操作 | Standard 展示简明的发布检查结果与阻断原因；真实发布/暂停/恢复只有各项实际准入满足才可以执行，未知时不可强行通过 |
| Free | 只提供内部只读 Sandbox 预览；**不能编辑/保存配置，也不能建立真实可分享 URL**；可预览现有资产/Offering 的内部展示样式 |

不把法律链接版本、服务核验历史、技术运行记录、复杂门户操作历史做成六块常驻大页面。法律与披露由原资料/Offering 管理，状态有问题时显示一条可读原因及「去处理」链接。投资者登录/KYC/下单/持仓前台不在本轮 Issuer 页面中开发。

## 5. 投资者与认购：三入口 UI-Ready

### 5.1 投资者管理（精简）

**列表**：企业范围投资者引用号、脱敏名称、自然人/机构、当前平台 KYC 状态、已关联 Offering/认购数、关联持有人或权益摘要、最近业务时间、查看详情。  
**筛选**：关键词仅编号/脱敏名；KYC 状态；Offering；清空筛选；基本分页。  
**详情**：基本脱敏身份、当前 KYC 状态及必要失效/重新核验提醒、当前企业认购列表、关联持有人/权益列表；提供订单与持有人深链。  
**去除常驻 UI**：详细 KYC 技术时间线、服务商内部状态、复杂授权关系台账、投资者级权限配置、CRM 功能。必要来源/时间仅在异常或受控详情中展示。  
**边界**：Issuer 不审核/覆盖 KYC，不查看完整证件、联系方式及 Provider 原始材料；无本企业业务关系不得可见。KYC 通过仅代表这一道前置，不等于可认购任何 Offering。

### 5.2 认购订单（含已完成认购记录）

**列表**：订单号、脱敏投资者、Asset/Offering、Token 数量、订单金额 U、订单状态、付款状态、交付状态、创建/完成时间。  
**筛选**：全部、待付款、处理中、待交付、已完成、异常/退款；关键词/Asset/Offering/时间。已完成筛选替代旧「资产与发行→认购记录」。  
**详情**：订单固定条款、付款、Token 交付、配售/法定登记分别展示，必要时进入资金、Token、持有人管理；已完成可按原 U02-10 权限脱敏导出，不能把退款中新事实从历史中抹去。  
**主账**：一个订单 ID 和生命周期，没有第二个已完成记录主账；不可由前端手工标记付款或 Mint 成功。

### 5.3 持有人管理（含基础配售与锁仓）

**列表字段**：脱敏持有人/企业引用号、Asset/Offering、权益类型与合法权益数量及单位、Token 交付/持有数量（分列）、登记状态、锁仓到期与状态、对账差异、最近更新。  
**筛选**：关键词/Asset/Offering、登记状态、锁仓状态、差异；简明分页。  
**详情分区**：
1. 权益登记：登记主体、法定权益数量/单位、权威登记状态/必要凭证摘要；未知不假装已登记。
2. 来源：认购订单、受权基础配售决定与资金匹配摘要；常规自动配售不单列复杂工作台。
3. Token：交付数量/网络/状态与链上记录深链；不得把链上余额等于法律名册。
4. 锁仓与限制：Offering 锁仓条款、交付批次、真实起算/到期、业务期限、链上执行、法律/管理限制**分别展示**；历史可展开，必要时跳 Token 管理。
5. 差异/异常：仅当需处理时展示证据及责任入口；合法人工登记/受控配售需要确认权威主体与法律依据，普通企业账号不能直接「确认法定生效」或任意修改数量。
**锁仓唯一来源**：不保留资产与发行独立锁仓菜单，但必须保留可按 Asset/Offering/持有人/交付批次查询的历史记录视图（可作为持有人管理内页签或详情子视图）；交付前不开始计时，已确认到期不代表链上/法律限制解除。
**禁止**：手工改配售金额/份数、任意冻结/解冻、提前解锁、强制转账、随意登记或删除历史；V1 不做自由流通交易。依法需要的限制/更正/清退从相应模块受控操作，规则与证据仍按旧最终 PRD。

## 6. 数据与报表及共享能力

**二级仅保留**：
- 「业务报表」：按 Asset/Offering、时间、业务类型筛选；展示发行、认购、资金、持有、Token、收益可信汇总；按照原批准脱敏权限导出。不把不同法定单位混加，也不能以 Unknown 当 0。
- 「操作记录」：时间、来源模块、对象、操作、结果、必要来源与查看详情；必要条件筛选及受控导出。原审计信息与法定留存、事件证据继续保持，只是前台字段简化。

**全局功能改造**：我的待办→工作台首页待办区域和业务页面提醒；消息通知→顶部消息入口（未读、内容、原业务链接、已读）；业务异常→原模块内联提示/可选详情与支持入口。没有独立企业异常工单、平台级规则目录、外部服务监控、安全服务状态管理菜单。内部原始工单/通知/审计事实在必要时可以通过受控链接/平台运营侧留存。

## 7. 企业管理及订阅演示

**二级仅保留**：
1. 企业资料与 KYB：主体资料、五步认证状态、补件重提/历史摘要。
2. 钱包管理：平台 MPC 和已验证自有钱包、默认切换、Offering 收款钱包引用；真实 MPC/签名验证另行生产接入。
3. 套餐订阅：Free / Standard、月/年、订阅当前状态、升级/续费/降级和历史只读口径。

**Web Mock 验收 P1**：本地测试控制台必须能够在不进行真实支付的情况下激活 Standard、切换有效/宽限/到期/降级/恢复，且和权限联动；正式用户页不出现「一键假开通」生产控制。模拟订阅开通只解锁 Web 原型的权限/演示状态，不解锁真实门户发布、支付、法定登记、部署、Mint、生产资金或 Signer。

规则/外部服务页移除；强制规则的来源及服务可用性依旧作为相关原业务的受控检查和必要的阻断提示，不让企业在平台级服务页面配置 Provider/Signer。
