# RWA SaaS Issuer V1｜Figma 验收与现行 PRD 交叉审计及整改规格

> 日期：2026-11-13｜状态：产品交叉审计完成；作为下一轮原型整改依据，待用户审核后实施。  
> 范围：仅 Issuer SaaS V1 Web；基于 Figma Make 浏览器验收报告与 `docs/r2-current-product-baseline` 当前权威规格。  
> 本文不修改既有专项 PRD、DEC、Frozen、功能 ID 或版本归属；不授权源码开发、真实服务接入或生产金融/链上操作。

## 1. 审计结论

本次 Figma 验收发现的缺口并非全部属于 PRD 缺失。交叉核对后分为三类：

1. **已有 PRD 明确规定、Figma 未实现或实现错误**：房地产五步创建、文件必需行/扫描状态/Ready 阻断、债权资产核心字段、Instrument 三类权益责任主体与专属条款、Free/Standard 权限边界、认购/资金/配售/法定登记/Token 的独立状态、收益快照和分配批次唯一性等。
2. **已有 PRD 原则存在，但需要结合本次案例补充更明确的产品表达**：住宅租赁现金流字段如何归属资产/权益/收益上报；债权底层借款条件与投资者债权条款的清晰区分；收益批次重复键、零持有人/零可分配金额阻断反馈；Ready 与文件证据来源的可追溯展示。
3. **本轮不应扩大为新功能的事项**：真实投资者 KYC、真实支付、真实 Token 部署/Mint、真实法定登记、真实 MPC 钱包开通、自动法律判断、复杂债权摊还、复杂税务/费用模型等。均继续受原生产准入及 V1 范围约束。

**核心判断：先修复 Figma 对现行 PRD 的实现偏差，再补充少量业务案例明确的字段/状态表达；不推翻既有九大导航，不重做已批准的业务对象模型。**

## 4. 资产模板整改规格

### 4.1 房地产住宅模板

不重建资产模型，沿用已批准五步流程：

1. **分类**：房地产 → 住宅物业。
2. **基础信息**：名称、简介、国家/地区、城市/行政区、详细地址、展示媒体及公共字段。
3. **法律与估值**：登记权利人、权利性质、与发行企业关系、估值方式/基准日/估值金额/依据、必需权属与估值文件、条件性权利限制证明。
4. **住宅专属属性**：户型（两室一厅等）、建筑面积、住宅用途/状态等既有模板字段；不得重复填写公共字段。
5. **预览与资料检查**：汇总缺项、文件可引用状态，点击完成资料检查后由规则计算 Asset Draft/Ready。

本次案例需额外清楚承载以下租赁经营信息。优先映射至现有字段；若原模板确实没有，再作为本次建议新增的轻量字段组：

| 字段 | 规则 |
|---|---|
| 当前使用/出租状态 | 自住、空置、出租、其他 |
| 租赁合同 | 有/无；有则关联租赁合同文件及版本 |
| 租赁起止日期 | 有有效租约时填写 |
| 合同约定月租金 | 金额 + 原币种；不得与平台 U 混为一栏 |
| 租金支付频率 | 月/季/年/其他 |
| 租金收入证明 | 按需关联；实际每期收入在收益上报时记录，不在 Asset 表单重复上报 |
| 运营/物业管理主体 | 仅存在独立运营方时复用资产相关方卡片 |

**归属边界：** Asset 记录租赁现状与合同约定信息；Instrument 定义投资者对租金收益的合同权利；收益与分配记录每期实际发生收入、可分配金额、快照和支付。不得在三处重复录入同一个“每月实际收入”。

### 4.2 单笔企业借款债权模板

直接实现 2026-11-12 已批准字段，不新增第二套模板：

- 借款合同编号、签订日期；
- 债权人、债务人及各自主体角色；
- 合同本金、当前未偿本金（分开）；
- 合同利息类型、底层固定年利率；
- 起息日、底层合同到期日；
- V1 偿还安排（到期一次还本）；
- 当前债权状态（正常/逾期/已清偿/争议）及条件说明；
- 担保有无及担保摘要；
- 当前债权权利人、与发行企业关系；
- 估值方式、估值日期、资产估值金额；
- 权利转让/质押限制及说明；
- 借款合同、债权归属、余额/履约、估值及条件性担保/限制文件。

校验：
- 未偿本金不得大于合同本金；
- 已清偿债权不可作为可发行的当前债权；
- 逾期/争议必须明确提示风险并按既有规则阻断或要求进一步处理；
- 底层合同利率、投资者 Instrument 利率不可自动等同；
- Offering 结束日不可代替债权到期日。

## 5. Instrument 权益条款整改规格

维持一资产一套当前 Instrument、三类权益、单页三区域、精确拆分、不静默舍入。

### 5.1 收益参与权

必须可表达：
- 收益责任主体；
- 收益来源及对应 Asset/合同/经营活动；
- 投资者获得的权利说明；
- 收益参与比例及其分母/计算基数；
- 收益周期（如每月）；
- 权益期限/起止日期；
- 可分配收益口径及已批准扣项（没有依据时不得自行增加复杂费用引擎）；
- 到期后安排：终止、续期待确认、清退/其他有明确依据的方式；
- 核心收益参与协议及相关 Asset 文件固定版本引用。

**不得默认投资者享有房屋产权、租金保证、固定本金返还或未约定的升值收益。**

### 5.2 债权

必须分别表达：
- 投资者债权责任主体/债务人；
- 投资者债权本金总额；
- 年利率或约定利率；
- 利率类型（固定/其他仅在 V1 已支持范围内）；
- 计息口径/日数基础；本测试案例只采用完整自然月、年利率/12；
- 付息频率；
- 起息日与投资者债权到期日；
- 本金偿还方式（V1 本案例为到期一次还本）；
- 逾期/提前清偿等未覆盖情形明确标为不支持/待后续，不自动生成复杂流程；
- 投资者债权协议及必要责任主体文件固定版本引用。

底层债权和投资者债权可以在业务上有关联，但主体、金额、利率、期限及偿付义务必须各自明确，系统不自动把底层合同条件复制为投资者条款。

### 5.3 Token 映射

- 权利总量及单位与 Token 份数分开。
- 每 Token 对应权利量精确计算。
- 非整除拒绝，不静默舍入。
- 股数、债权本金 U、收益参与比例分别使用适当法律单位。
- Offering 只能引用 Ready InstrumentVersion，不得改写 Instrument 权利定义。

## 6. Offering 与发行确认

保留最新精简架构的「资产管理｜权益结构｜发行管理」三个入口，不恢复资产详情内重复 TAB。

创建 Offering 时：
1. 选择 Asset；
2. 自动引用该 Asset 唯一当前 Ready InstrumentVersion；
3. 显示可发行容量及其权威来源；
4. 设置本期 Token 数量、单价 U、最低认购、时间、收款钱包及披露；
5. 保存 Draft；
6. 完成业务检查与内部最终预览；
7. 点击「确认发行」时展示集中确认页/弹窗，列明缺项、容量、权利摘要、发行参数、钱包、披露及生产准入状态。

不保留独立「发行前准备」导航或重复资料录入页；但必须保留必要的检查规则和阻断原因。

**Free/Standard 规则修正：**
- Free 可以保存正式 Asset/Instrument/Offering 资料并完成资料检查、业务准备；可以内部只读预览。
- Free 不得真实发布、部署合约、Mint、公开上架、认购募资或进行发行后真实收益运营。
- Standard 付费也不自动构成真实生产准入；真实操作需独立条件满足。
- “准备就绪”只代表资料/业务检查完成，不得展示成“已部署/已发行/已募资”。

## 7. 认购、资金、配售、持有人、Token 的测试支撑

正式 Issuer 页面遵循原权威 PRD，不增加发行企业自行伪造投资者 KYC/订单/资金的生产按钮。

内部 Mock 控制台需要支持创建虚构投资者引用、测试订单、资金事件、配售/登记/Token 状态，用于本地端到端验收；每条记录标记为内部测试数据，并可按场景重置。不能把 Mock 结果转成正式生产账。

测试场景注入后，各模块仍按权威边界显示：
- 订单主账：订单及签署快照；
- 资金：真实/模拟收款匹配、退款与结算；
- 配售：唯一决定与容量；
- 法定登记：有权主体的权威结果；
- Token：部署、交付、链上最终性；
- 持有人：法定持有人结果，不简单等于钱包余额。

新建 Offering 不得自动生成“已部署”合约；只有显式执行内部部署场景后，才显示带 Mock 标记的模拟部署结果。

## 8. 收益与分配整改规格

### 8.1 共通规则

- 收益/本息事件读取有效 Instrument 条款与对应 Offering 快照。
- Record Date 读取权威持有人/权益快照；无有效快照时不能生成可确认的分配结果。
- 零有效持有人、零有效权益量或零可分配金额：阻止进入确认/付款；可允许保存资料草稿，但必须明确显示阻断原因。
- 分配批次唯一键：Offering + 收益/本息事件类型 + 期间 + Record Date + Instrument/规则版本。重复提交应返回既有批次或阻断，不得生成第二个可付款批次。
- 每一批次分别保留计算、复核/确认、资金准备、支付处理、最终支付核验状态；“已确认分配”不等于“已支付”。
- 更正或重跑必须引用原批次，保留差异和审计，不允许覆盖或删除历史付款。
- 本金偿还与利息/租金收益分开建事件、分配明细和付款记录。

### 8.2 住宅租金收益

- Asset 维护约定月租金/租约状态；每期收益上报录入实际租金收入、收入期间、证明文件、适用费用/扣项及可分配金额。
- Instrument 定义参与比例、分配基数和期限。
- Record Date 取得当时有效持有人快照。
- 按有效 Token/法律权益映射计算候选分配。
- 仅当来源、快照、金额及必要复核条件满足后才能确认批次。
- 测试数据：人民币 8,000 元实际租金；固定测试换算 1 U = 8 元；无费用假设下可分配 1,000 U；按 50/30/20 分配 500/300/200 U。
- 该换算仅是本地演示输入，不是实时汇率或生产兑换规则；平台正式金额展示仍遵循统一 U 规则，原币种和换算依据需可追溯。

### 8.3 债权利息及本金

- 读取 Instrument 投资者债权本金、利率、起息/到期、计息口径和付息周期。
- 按规则计算候选利息，不能要求用户把已可推导的金额重复手填为唯一来源。
- 对测试约定“完整自然月、年利率/12”：400,000 U × 12% ÷ 12 = 4,000 U。
- 根据有效权益/持有人快照，按本金比例分配 2,500 U / 1,500 U。
- 到期本金单独形成偿还事件：250,000 U / 150,000 U；本金已偿还后停止后续本金对应计息。
- 底层借款债务人对 Issuer 的付款，与 Issuer 对投资者的付款是不同资金事件；不得因底层回款“已上报”自动认定投资者已收到款项。
- V1 本案例不扩展分期本金摊还、复利、逾期罚息、税务或复杂日数基础；不支持的条款应明确限制，不做静默近似计算。

## 9. 状态与证据统一规则

- Asset Draft/Ready：Ready 只代表对应模板必填资料、文件及输入校验完成；不代表产权/债权真实性、法律有效或监管批准。
- Instrument Draft/Ready：Ready 代表权利定义、责任主体、映射及核心文件完整；不代表法律意见或发行批准。
- Offering Draft/业务检查完成/内部预览/生产准入/已发布：必须分开；Free 可完成前置资料准备，不得显示生产发布成功。
- 文件状态必须来自真实文件记录：未上传、上传中、待扫描、可引用、失败/不可用；无 file/version 引用不得显示已归档。
- Token 状态必须由真实/明确 Mock 事件驱动；无部署操作不能显示已部署。
- 任何 Unknown/Pending/冲突不能被绿色成功状态覆盖。
- Ready 检查由规则计算，用户不能用“通过 Ready 检查”按钮绕过字段/文件规则。
- 每个状态应显示来源、最近更新时间及必要的下一步，不暴露不必要技术细节。
