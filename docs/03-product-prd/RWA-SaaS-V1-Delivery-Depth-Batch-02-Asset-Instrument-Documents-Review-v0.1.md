## 一、业务定位与 V1 边界

- **M04** 管理底层 Asset 与 Instrument 的独立对象、适用法律/经济权利、实体主体关联、条件性 A/B 参数、内部审查及不可覆盖版本。**M06** 管理证据和法律/业务文件、适用材料清单/补件、受权审查意见、专业结论引用和投资者必要条款签署的文件侧。
- **Asset（底层资产）≠ Instrument（投资者得到的金融/法律权利）≠ Offering（一次有具体发行价格/数量/资格的销售安排）≠ Token（链上凭证）**。M04 不承诺每一种资产/权利家族都完成全套法域生产实现。
- 参考样本 **A**：固定票息和到期本金债务 Series，要求权利人/义务人、应计/记录日/后入定价/本金与 Token 单位区分，但金融计价公式由真实条款及后续审批确定。参考样本 **B**：SPV 股份/类似权益，要求公司法定形式/类别/授权/稀释/限制/可选分红，不能把股权等同于 SPV 物业所有权。
- **C/D/E** 仅保留未来权利家族可扩展的字段/权利模型边界；NAV 申赎、收入分成、储备仓单/实物交割等专项引擎不在本批自动生产化。
- 本批 **M04 9 项（7 P0 / 1 P1 / 1 P2）+ M06 8 项（6 P0 / 1 P1 / 1 P2）= 17 项**。M04-F008 模板与 M06-F007 深度协作仍 P1 后置；M04-F009 复杂组合及 M06-F008 服务商竞价仍 P2 后置，已确定最小业务控制不得因此删除。

## 二、业务角色及跨模块职责

| 角色 | 本批可做的业务 | 审批/权限边界 |
|---|---|---|
| Issuer 资产/发行录入人员 | 建 Asset/Instrument 草稿，上传资料、提交审查、处理补件 | 不能以“上传者”身份自动证明底层产权或法律可发行 |
| Issuer 受权审查人员 | 查看合法范围资料，审核 Asset/Instrument 是否内部可用，附理由 | 必须符合组织和业务范围，必要时与提交者分权 |
| 法律/评估及其他适格专业方 | 在其合法授权范围提供意见、证明、专业审查、必要签署 | M06 记录其身份与报告引用；SaaS 并不因此获执业资格 |
| Issuer Offering 负责人 | 引用经审核的 InstrumentVersion 来配置 Project/Offering | M05 自身发布 Gate 与首发法域/资金/签名就绪须后续独立通过 |
| 投资者 | 查看自己被允许看到的发行/风险文件，完成适用认购确认/签署 | 不能查看 Issuer 内部材料、别的投资者敏感资料或跨 Tenant 文书 |
| SaaS 平台运营 | 执行必要技术/商用支持并查看明确授权的审计信息 | 不得替代专业法律审查、发行机关批准或投资者真实签署 |

## 三、关键用户旅程与逻辑页面组（非正式 UI/路由冻结）

| 页面组 | 典型操作 | 当前建议的最小信息与 Guard |
|---|---|---|
| **Asset 列表和资产详情** | 搜索、过滤、草稿新建/编辑、提交审查、补件、查看版本与关联 | Asset 类型、标的描述、资产控制主体、法域/来源、状态和文件证明；不把 Asset 审查通过显示成“可发行” |
| **Instrument 列表与创建/详情** | 选 Asset/权利家族、设权利与义务、版本保存和提交 | A/B 条件字段组；债权本息与 SPV 股权/分红字段互不套用；权限/合法版本记录 |
| **证据与文件管理** | 分类上传、关联对象、预览/下载（受控）、版本比较、补件 | 文件来源、签署/生效日期、版本、审核结果、权限及缺项 |
| **审核与专业结论** | 资料提交→指定审查→退回/补件→内部审核认可/拒绝/暂停 | 审查人/来源、适格专业方报告引用、结果理由与受权记录 |
| **投资者文件签署（M06 依赖）** | Offering/Quote 使用准确条款版本展示和适用电子签 | 正式发行/报价阶段与 M08/M10 衔接；本批先定义文件证据/Guard，不提前交付完整投资者门户 |

**页面原则**：一个列表/详情页面组可以覆盖多个正式功能，不要求 17 项功能变成 17 个页面。正式 IA、具体字段字典、视觉风格、路由和 UI 统一设计待完整 PRD 后进行。

## 五、领域事实/版本与状态（按 Frozen WF-03，不新造核心状态机）

| 对象 | 典型领域命令（API-First 逻辑名称而非 URL） | 状态/业务事实 | 跨模块限制 |
|---|---|---|---|
| Asset | createDraft / updateDraft / attachEvidence / submitForReview / requestSupplement / review / suspend / archive | **Draft → PendingReview → ReviewedForUse**，补件 **NeedsSupplement → Draft**；可 Suspended/Archived | M04 唯一主责；审核时引用 M06 材料和 M20 审计 |
| Instrument | createDraft / setRightsFamily / updateTerms / submitForReview / requestRevision / review / suspend / retire | **Draft → PendingReview → ReviewedForUse**，需修改 **NeedsRevision → Draft**；可 Suspended/Retired | 版本包含权利/限制/计价的有效引用，M05 Offering 绑定经审版本 |
| Evidence/Document | upload / classify / linkToVersion / grantAccess / supersede / requestAdditionalEvidence | 受控版本与生效范围；“已上传/已扫描/已审核/已合法生效”不能合一 | M06 负责文件及审查证据；跨组织/投资者权限约束 |
| ReviewTask | assign / submitEvidence / requestMoreInfo / approveInternalReview / returnForChanges | 操作审计和补件版本，不直接改写金融法律事实 | 审查人需受权；法律专业意见应引用真实适格责任人 |
| SubscriptionLegalDocument | publishTermsReference / requestInvestorConsentOrSignature / verifySignatureEvidence | 受权的合同版本、签署意图、外部结果及效力条件独立 | M08/M10 只能引用确定的有效签署/确认版本，并受 M05 Gate 约束 |

**业务不变量**：
1. 已被 Offering、投资者合同或订单 Quote 引用的 Instrument/文书旧版本**不可无痕覆盖**；变更需新版本和影响分析（必要时重新审核、再确认、重签或暂停）。
2. 上传权属文件成功、内部审批 ReviewedForUse、法域合法所有权/发行批准、投资者签署有效性分别由不同责任方证明；不能设置一个全局“合规通过”按钮。
3. 一份 Asset 可有不同 Instrument/权利结构，但不能让同一个 Token 配置无合法依据跨越不同权利类别；具体多对多关系及发行组合校验将在详细字段/法律方案再确定。
4. A 的本金/收益计量与 B 的股权类别/稀释/分红受不同合同与公司批准约束；M04 不直接决定 M11 的实际收款、M12 的法定份额交付或 M07 的 Mint。
5. 外部审查/签署**Unknown** 时查询原任务或适用外部回执，不误判拒绝、不静默重新发不可逆法律签署、不重复绑定同一结果。
6. 用户调整与已发行 Offering 关联的权利时，必须先检查在售订单、文书、合规/资金/登记和存续权益的影响；未经受权更正不得直接修正法律历史。

## 六、A/B 样本字段差异（需求级，非表结构已批准）

| 参数主题 | 样本 A 固定收益债权 | 样本 B SPV 实体权益 |
|---|---|---|
| 法律主体 | issuer/obligor、agent/registrar（适用）、series_id | SPV 法人、章程/股东协议、受权公司机关 |
