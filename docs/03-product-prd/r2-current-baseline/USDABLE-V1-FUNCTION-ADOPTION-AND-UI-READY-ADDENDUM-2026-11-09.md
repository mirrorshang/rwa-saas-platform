## 2. M04｜Asset 相关方信息补充

### 2.1 设计原则

资产相关方用于说明底层 Asset 的持有、保管、受托、管理、运营、估值及其他实际参与主体。它不是 Instrument/Offering 的全部法律责任主体列表，也不是收款钱包名录。

- 继续保留 U02-03 已批准的「登记权利人」「权利性质」「与发行企业的关系」「资产运营/管理主体」「参考估值」「评估机构」等字段。
- 不强制每个资产都必须有 SPV、托管方或受托方；不适用时不创建该角色记录。
- 如果 SPV 本身就是登记权利人，应通过关联/复用既有主体信息表达，避免出现两条互相矛盾的主体记录。
- Asset 的资产相关方与 Instrument/Offering 的发行人、债务人、担保人、付款义务方、法定签署人、Token Signer 分开维护；后者由相应 Instrument/Offering/外部责任主体设计管理。
- MVP 采用结构化主体卡片，不建立复杂股权穿透、受益所有权图谱或多层信托关系引擎。

### 2.2 资产相关方角色

| 角色 | 适用条件 | 与现有字段的关系 |
|---|---|---|
| 资产持有主体 / SPV | 资产由独立 SPV 或专门持有实体持有时 | 若其为登记权利人，关联 R18 登记权利人；否则记录其持有/控制关系 |
| 托管方 | 资产存在独立保管、托管或受托保管安排时 | 新增条件角色；不自动代表法定登记人或资金托管人 |
| 受托方 / Trustee | 资产或权益采用信托/受托结构时 | 新增条件角色；需说明受托职责和依据 |
| 资产管理方 | 存在独立资产管理主体时 | 扩展既有资产运营/管理主体字段为结构化主体信息 |
| 资产运营方 | 日常经营、租赁、物业、设施或项目运营由独立主体承担时 | 可与资产管理方相同，也可分开记录 |
| 估值机构 | 采用第三方评估作为估值依据时 | 复用既有 R19「评估机构」条件必填规则，补齐机构信息 |
| 其他相关方 | 存在对资产权利、管理、运营或专业服务有实际影响的其他主体时 | 选择角色并填写职责说明；不得用作任意新增金融责任主体 |

### 2.3 主体卡片字段

每个已适用角色显示一张主体卡片。MVP 默认按角色维护一条主要记录；确有多个实际主体时允许添加记录，不建立复杂的多层关联图。

| 字段 | 控件 | 必填/校验 |
|---|---|---|
| 相关方角色 | 系统角色标签/下拉 | 选择上表角色；必填 |
| 主体名称 | 单行文本 | 角色记录存在时必填；使用法定/正式名称 |
| 主体类型 | 单选 | 企业、自然人、政府/公共机构、其他；必填 |
| 注册国家/地区 | 地区选择 | 企业/机构主体条件必填；使用稳定地区代码 |
| 注册编号 | 单行文本 | 选填；无统一注册编号时不强制 |
| 与资产的关系 | 单选 | 持有、保管/托管、受托、管理、运营、估值、其他；依据角色默认并允许修正 |
| 职责说明 | 多行文本 | 角色记录存在时必填，简明说明具体责任边界 |
| 与发行企业的关系 | 单选 | 同一主体、关联主体、受托/授权、独立第三方、其他；必填 |
| 关系/授权说明 | 多行文本 | 非「同一主体」时条件必填 |
| 许可/资质名称及类别 | 单行/多行文本 | 选填；仅对依法需要许可/资质的角色按适用法域条件要求 |
| 许可/资质编号 | 单行文本 | 有许可/资质时条件必填 |
| 发证/监管机构 | 单行文本 | 有许可/资质时条件必填 |
| 许可/资质有效期 | 起止日期 | 许可存在有效期时条件必填；结束日期不得早于开始日期 |
| 官方网站 | URL 输入 | 选填；必须为合法 URL |
| 联系人 | 单行文本 | 选填 |
| 联系邮箱 | 邮箱输入 | 选填；如填写必须符合邮箱格式 |
| 联系电话 | 电话输入 | 选填 |
| 委任/授权/服务协议/许可资质证明 | 文件关联/上传 | 按角色、适用法域和实际法律关系条件要求；不设所有角色统一必传文件 |
| 合作有效期 | 起止日期 | 适用时选填；结束日期不得早于开始日期 |
| 备注 | 多行文本 | 选填 |

### 2.4 条件校验与 Ready 规则

1. 登记权利人仍是 Asset 权属信息的必需主体，不得因新增 SPV 卡片而自动覆盖。
2. 发行企业与登记权利人不同，继续遵循 U02-03 的关系说明及相应授权/委托凭证规则；不得默认为所有情形都必须上传同一种授权书。
3. SPV、托管方、受托方、资产管理方、运营方按真实资产结构条件化出现；没有该角色时不产生空白必填项。
4. 选择第三方评估作为估值依据时，评估机构仍按现有规则条件必填；其注册信息、网站、联系人等补充资料不全部强制。
5. 任何角色记录存在但名称或职责为空，不能通过相关方信息完整性检查；缺少非适用角色不得阻断 Ready。
6. 文件上传、扫描和可引用状态继续服从 M06；上传成功不等于主体身份、授权或文件法律效力已被平台认证。
7. Asset Ready 仅表示已填资料满足产品定义的完整性检查，不代表平台确认产权真实、托管有效或主体适格。许可/资质信息及证明是结构化记录和后续审查依据，不代表平台代替监管机构确认牌照有效。

## 3. M13｜Issuer 收益上报 UI-Ready 补充

### 3.1 页面目的与业务边界

「收益上报」是发行方/有权业务主体向 M13 提交某一权益结构或发行系列在指定期间的实际收益事件及证明材料。它不是收益承诺，不直接生成每位投资者应付金额，不等于真实注资或实付。

- 收益事件类型由生效 Instrument 决定：债权合同利息/票息、依法批准的股息/分红、合同约定的收益参与/经营收益等。
- 固定利率债权的周期付息日期由生效 InstrumentVersion 定义；M13-F004 按付息期次生成合同付息事件，M13-F005 负责应付计算/复核，M13-F009 负责分配批次和资金衔接。不得让 Issuer 在收益上报中重复创建同一期付息事件。
- B 类 SPV 股权分红必须有合法公司决议、可分配利润及适用条件；不能因填写了收益金额就自动生成确定股息。
- 本金偿还、到期兑付和清退计划走本文件第4节，不混入周期收益上报。
- 金额界面使用 U（按 USDT 计价）；实际付款路径、资金义务方及网络仍受 M13/X 生产准入约束。
- 不增加收款方名录或多方比例分账；收益批次按现有 M13 规则处理。

### 3.2 收益上报列表

**筛选条件：**

- 资产
- 权益结构
- 发行方案/发行系列
- 收益类型
- 收益期间
- 上报状态
- 提交时间范围

**列表列：**

| 列 | 展示规则 |
|---|---|
| 上报编号 | 系统生成，租户内唯一 |
| 资产 / 权益结构 | 显示名称及必要编码 |
| 发行方案 | 显示关联 Offering/系列 |
| 收益类型 | 依据 Instrument 规则显示 |
| 合同付息期次/合同应付日 | 只读引用 InstrumentVersion 付息计划 | 债权周期付息事件必显示；不得在 M13 改写 Instrument 条款 |
| 收益期间 | 起止日期 |
| 权益记录日 | 已确定后显示 |
| 上报金额 | U；本期无收益显示 0 U |
| 有效持有人数 | 只有完成 M12 权威快照后显示 |
| 上报状态 | 独立于分配批次和资金状态 |
| 最近更新时间 | 日期与时间 |
| 下一步 | 按当前状态显示唯一主要操作 |

**主要操作：** 新建收益上报、查看详情、编辑草稿、按规则撤回待审申请、补充材料/修正、查看关联分配批次。已批准记录不可直接覆盖。

### 3.4 表单校验与业务 Guard

- Asset、Instrument、Offering/Series 必须属于当前 Tenant 且彼此关联有效；不得跨租户选择。
- 收益类型必须被当前 Instrument 允许；Instrument 已失效、版本不匹配或相关条款未知时阻断提交。
- 收益期间开始日不得晚于结束日；Record Date 必须满足适用法律/Instrument 规则，不能由系统静默替换。
- 本期无收益时金额固定为 0 U，不创建可领取金额、分配批次或注资任务；保留无收益声明及原因记录，依法需要披露时由 M13/M18 生成披露/通知任务。
- 未勾选无收益时，上报金额必须大于 0 U；不能用负数、空值或四舍五入后的 0 通过校验。
- 股息/分红必须关联有效公司决议及可分配依据；没有合法决议时不得形成已批准应付。
- 发行方上报的总收入不等于投资者应付总额。M13 后续依据生效 Instrument、M12 权威权益快照、适用税费/扣项和批准的计算规则生成应付结果。
- 如果没有有效持有人快照、持有人数量为 0、权益来源争议或金额计算无法核对，必须阻断进入真实注资/Claim；不得照搬 USDable 在 0 持有人时仍允许注资的表现。
- 资料更正生成新版本，保留原始提交、审批意见、旧金额和旧附件引用；不得覆盖历史。
- 上报审核通过不代表已注资；已注资不代表已付款；Claim/Push 的最终结果仍按 M13 实际资金证据记录。

### 3.5 收益上报状态与后续流程

收益上报自身状态（产品可读状态，非后端冻结枚举）：

Draft → Submitted → ReviewPending →（NeedsCorrection → Resubmitted）→ Approved / Rejected。

批准后进入独立的 M13 后续处理：

1. 依据合法 Record Date 引用 M12 权威持有人快照。
2. 按生效 Instrument 及批准的计算规则生成应付明细并复核。
3. 生成唯一分配批次；确认实际付款义务主体。
4. 受权主体真实注资，核验资金足额及资金来源。
5. 满足条件后启用 Claim，或安排依法适用的 Push/外部支付。
6. 持续对账已提交、Unknown、部分支付、最终实付和未领取状态。
7. V/M 投资者端只读取本人应付、可领、未领和实际付款事实。

无收益声明走单独的「NoIncomeDeclared / Approved」结果，不进入分配批次。

### 3.6 债权周期付息计划与 M13 事件（DEC-059 Approved）

- 付息计划属于 M04 Instrument 条款，不在 Offering 或 M13 收益上报表单中重新配置。仅债权「固定利率」模式支持周期付息；无息债权不生成付息计划。
- V1 付息频率：到期一次支付、每月、每季度、每半年、每年。周期付息需设置首个付息日、日期递推规则和计息日数规则。
- 日期递推以首个付息日为基准按频率生成；目标月份不存在对应日时取该月最后一个自然日。到期日为最后一个合同应付日；不规则末期、非工作日调整和其他合同例外必须按合同由有权人员确认并留痕。
- 计息日数规则支持 Actual/365 Fixed、Actual/360、30E/360；「合同其他约定」必须填写说明并由有权人员人工核算、复核。不得在规则不明确时静默套用默认公式。
- M13-F004 记录期次、计息期间、合同应付日及 InstrumentVersion；M13-F005 按合同规则计算或复核总应付利息和持有人明细；M13-F009 承接分配批次、真实注资、Claim/Push 和实付对账。
- 合同付息日、Issuer 计划分配日、资金注入日和投资者实际到账日必须分开记录。若本期金额与系统计算不一致，必须说明差异并复核。
- V1 不支持浮动/阶梯利率、复利、任意不规则付息日期列表、复杂本金分期摊还、自动逾期罚息或自动跨法域节假日调整。

## 4. M13｜Issuer 清退/兑付申请 UI-Ready 补充

### 4.1 名称与范围

页面名称建议为「清退/兑付计划」，用于发行方发起一项具有合同或合法公司行动依据的投资者本金偿付、提前赎回、合法回购或其他允许的退出/清偿安排。

**清退/兑付不等于认购退款：**
- 投资者尚未完成合法配售登记的认购退款属于 M11。
- 已形成合法权益后的到期本金、合同赎回、依法回购、清退/清偿属于 M13；必要时由 M12 更新权威登记、M07 处理 Token 限制/销毁。
- 不是所有 Instrument 都有到期回购或提前退出；只有生效 Instrument 允许的类型才可选择。

### 4.2 可选择的清退/兑付类型

| 类型 | 适用条件 |
|---|---|
| 合同到期兑付 | Instrument 明确到期本金/兑付义务及付款责任 |
| 合同允许的提前赎回 | Instrument 明确允许提前赎回及其条件 |
| 合法回购/公司行动 | 有权公司主体已作出有效决议，且法律/Instrument 允许 |
| 其他依法批准的清偿/退出 | 必须提供具体合同或法律依据；无依据的自由退出不开放 |

不提供「平台保证回购」「默认保本」或无合同依据的任意清退选项。

### 4.3 清退/兑付申请列表

**筛选条件：** 资产、权益结构、发行方案/系列、清退类型、申请期间、当前状态。

**列表列：** 申请编号、资产、权益结构、Offering/Series、类型、Record Date、涉及持有人数、申报总额（U）、已注资/待注资、投资者结算进度、申请状态、最近更新时间、下一步操作。

**主要操作：** 新建申请、查看详情、编辑草稿、补件/修正、查看计算、查看注资与投资者结算进度。已批准申请不得直接改写金额或对象。

### 4.4 新建申请表单

| 区域 | 字段 | 控件 | 规则 |
|---|---|---|---|
| 关联对象 | 资产 | 下拉选择 | 必填 |
| 关联对象 | 权益结构 | 只读/下拉 | 必填；必须是该资产当前适用 Instrument |
| 关联对象 | Offering/Series | 下拉选择 | 必填；只能选择允许清退/兑付的发行系列 |
| 申请类型 | 清退/兑付类型 | 下拉选择 | 必填；仅展示 Instrument 允许的类型 |
| 法律依据 | Instrument 条款 | 只读引用 | 必填；显示条款编号/版本 |
| 法律依据 | 公司决议/批准文件 | 文件关联/上传 | 回购、股息相关公司行动或依法需要批准的类型条件必需 |
| 申请说明 | 清退原因/事实说明 | 多行文本 | 必填 |
| 权益资格 | 权益记录日（Record Date） | 日期 | 必填；引用/确认合法权益快照日期 |
| 结算安排 | 计划结算日 | 日期 | 必填；须满足 Instrument 和适用法律时限 |
| 结算金额 | 兑付金额方式 | 单选 | 按单位金额 / 按总金额，必选其一 |
| 结算金额 | 每单位兑付金额 | 金额输入 | 选择按单位金额时必填；单位 U |
| 结算金额 | 兑付总额 | 金额输入 | 选择按总金额时必填；单位 U |
| 结算责任 | 法定付款义务主体 | 只读/确认 | 从 Instrument/合法公司行动读取；未明确时阻断提交 |
| 证明材料 | 清退/兑付依据 | 文件上传 | 至少一份适用合同、决议或结算依据 |
| 投资者披露 | 对投资者的说明 | 多行文本 | 必填；供 M13/M18 按适用流程披露/通知 |
| 确认声明 | 责任与金额确认 | 复选框 | 提交前必勾选；确认不代表平台代替法律审批 |

### 4.5 金额、资格与异常校验

- 每单位兑付金额与总金额二选一作为输入主值；系统依据 M12 有效 Record Date 权益快照计算另一项。
- 如用户同时提供每单位金额和总额作为辅助核对，两者必须在适用精度内一致；不一致时阻断，不静默舍入。
- 计算依据为合法权益数量和生效 Instrument，不以钱包实时余额单独推断权利。
- 仅允许对 Instrument 规定的全部适格持有人按合法比例进行结算；V1 不提供自由勾选个别持有人并改变其法律待遇的复杂分配器。
- 如果 Instrument 允许部分兑付/部分偿付，可在批准范围内形成部分结算批次；不得把部分付款显示为全部清偿。
- 没有有效持有人快照、持有人数为 0、权利登记存在争议、付款义务主体未知或法律依据缺失时，阻断申请批准及真实注资。
- 申报总额、已批准应付、实际已注资、Claim 可领金额、最终已实付分别显示；不能合并成一个「已清退」状态。
- 真实注资不足额时默认不开放整批 Claim；依法批准的部分批次应独立形成受控批次。
- Token Burn/冻结、法定名册调整和资金清偿分别核验；Burn 成功不代表本金已付或法律权利自动消灭。

### 4.6 清退/兑付流程与状态

申请自身状态（可读状态，不冻结工程 enum）：

Draft → Submitted → ReviewPending →（NeedsCorrection → Resubmitted）→ Approved / Rejected。

批准后进入独立结算流程：

1. 固定有效 Instrument 版本、法律依据和 Record Date。
2. 引用 M12 权威持有人快照并计算每单位/总金额。
3. 复核付款义务主体、总额、适格投资者及必要披露。
4. 生成唯一 M13 结算批次。
5. 受权主体真实注资并核验金额、币种、来源及足额状态。
6. 满足条件后启用 Claim 或安排依法适用的 Push/外部付款。
7. 逐笔跟踪已提交、Unknown、部分支付、最终实付及未领取。
8. 依法完成后，由 M12 更新登记结果、M07 处理适用的 Token 处置；M13 仅在相关资金和法律事实均满足时标记结算完成。

状态展示需区分：Approved、CalculationPending、FundingPending、PartiallyFunded、Funded、ClaimEnabled、Processing、PartiallySettled、Settled、Disputed/Unknown、Cancelled。以上为产品可读状态候选，不是冻结的后端枚举。

## 5. M12｜持有人管理与权威登记查询 UI-Ready 补充

### 5.1 页面职责

在现有「投资者与认购 → 持有人登记」下增加清晰的「持有人管理/查询」视图，服务发行企业查看本 Tenant 已依法登记的持有人、配售来源、Token 交付和限制状态。

- M12 法定登记结果是合法持有人/权益数量的权威来源。
- M07 提供 Token 余额、Token ID、钱包地址、链上交付及限制事实。
- M10 提供认购订单来源；M09 提供投资者身份与资格摘要。
- M20 提供访问控制和审计；M21 提供只读报表及受控导出。
- 页面不得创建第二套持有人名册，不得把 Token 余额自动等同于法律权利，不得直接修改配售数量或法定登记结果。

### 5.2 持有人列表

**筛选条件：**

- 资产、权益结构、Offering/Series
- 投资者姓名/机构名称、投资者编号
- 钱包地址（授权范围内）
- 投资者类型（自然人/机构）
- 国家/地区
- 法定登记状态
- Token 交付/对账状态
- 锁仓/限制状态
- 合法持有数量范围

**列表列：**

| 列 | 展示规则 |
|---|---|
| 持有人 | 姓名/机构名称按权限脱敏；显示内部投资者编号 |
| 投资者类型 | 自然人/机构 |
| 国家/地区 | 只显示业务所需信息 |
| 资产 / 权益结构 / Offering | 显示关联对象 |
| 法定登记数量 | 来自 M12；为权益登记权威值 |
| Token 余额 | 来自 M07；单独展示，不替代法定登记数量 |
| Token ID / 合约 | 仅在适用且有权限时展示 |
| 接收钱包 | 地址默认脱敏；授权人员可复制完整地址 |
| 锁仓/限制状态 | 显示当前有效状态及生效时间 |
| 登记状态 | PendingEvidence / Verified / Disputed / Corrected / Unknown 等可读状态 |
| Token 对账状态 | NotIssued / Pending / Confirmed / Failed / Unknown / Mismatch 等可读状态 |
| 最近更新时间 | 最近登记/链事件/更正时间 |
| 操作 | 查看详情、查看差异、发起受权限制复核 |

### 5.3 持有人详情

详情按四个信息区组织：

1. **法定权益登记**：合法持有人主体、登记数量/单位、登记来源、登记生效日、权威文件/回执引用、变更版本。
2. **Token 与链上记录**：接收钱包、Token ID、合约、链上余额、Mint/Transfer/Burn 事件摘要、链最终性和对账差异。
3. **认购与配售来源**：关联 M10 订单、M12 配售决定、支付匹配摘要；不得在本页修改订单或资金事实。
4. **限制与审计**：锁仓、限制、冻结/解除限制申请、M17 工单、M20 审计事件及相关审批结果。

### 5.4 受权操作与明确禁止项

| 操作 | V1 规则 |
|---|---|
| 查看持有人详情 | 按 Tenant、业务关系和最小必要权限开放；默认脱敏 |
| 查看登记/Token 差异 | 可查看；差异通过 M12/M07/M17 处理，不在页面直接改数 |
| 发起限制处理复核 | 仅在适用法律、Instrument 和授权范围允许时，提交原因、法律依据、证据与影响范围，进入 M17 受权任务 |
| 发起解除限制复核 | 同样进入受权任务；保留原限制与审批历史 |
| 导出持有人列表 | 通过 M21 查询与 M20 权限/审计控制；按需脱敏 |
| 编辑法定持有人/权益数量 | 不允许在普通列表直接编辑；走 M12 受权登记更正流程并保留证据版本 |
| 直接修改 Token 余额/链上记录 | 不允许；链上事实由 M07 产生 |
| 一键拉黑/解冻 | 不提供无依据的直接按钮；依法允许的限制/解除必须走受权流程 |
| 强制转账 | 不纳入 V1；不允许发行方通过普通后台直接改变持有人或转移权益 |

### 5.5 隐私与异常处理

- KYC 原件和敏感身份材料不在持有人列表直接展示；只有合法必要且获授权的人员可经 M09/M20 访问。
- 发生 M12 法定登记数量与 M07 Token 余额不一致时，明确标记差异，显示两侧数据源、更新时间和待处理任务；不得自动选一方覆盖另一方。
- 登记 Unknown、外部回执缺失、链交易 Unknown 时，先查询原始指令/证据，禁止重复登记或重复 Mint/Burn。
- 受限/冻结状态必须显示来源、依据、发起主体、生效时间、复核状态和解除条件；平台 SaaS 管理员不因系统权限自动取得法律冻结权。
- 发行企业暂停订阅或降级，不得删除历史持有人、法定登记或投资者权利；必要查询与存续履约按 M20/M13 继续受控。

| 本文件功能 | Free | Standard |
