## 2. 权益结构的业务责任

Asset 回答“投资者投资的是什么”；权益结构回答“投资者依法或依据合同取得什么权利”。

权益结构必须关联一个 Asset，并清楚定义：
- 权利主体及履约主体；
- 投资者取得的权利内容；
- 权利适用范围及计量单位；
- 期限及基础经济条件；
- 权益总容量/授权上限；
- Token 与权益单位之间的固定映射；
- 对应法律文件和投资者可读摘要。

权益结构不是发行方案。以下内容属于 Offering，不属于权益结构：
- 本轮发行数量和募集目标；
- Token 销售单价；
- 认购开始/结束时间；
- 投资者最小/最大认购金额；
- 本轮支付币种、认购规则及配售参数。

MVP 每家企业只有一个操作账号，不建设企业内部多角色、审核人员或审批流。

## 3. MVP 支持的权益类型

MVP 仅支持以下三类，其他类型不得作为可用选项展示：

### 3.1 Equity（股权权益）

表达投资者基于指定法律实体取得的股权类权利。

| 字段 | 业务定义 |
|---|---|
| 权利主体/法律实体 | 投资者股权所对应的法律主体 |
| 股份类别 | MVP 使用普通股（Common Shares）基础表达 |
| 股份数量 | 该权益结构对应的股份数量 |
| 持股比例 | 在有可用总股本依据时表达持股比例；不得与股份数量混为一项 |
| 权利摘要 | 用投资者能理解的方式说明股权权利及边界 |
| 法律依据 | 关联公司文件、股权证明及适用法律文件 |

MVP 不扩展优先股、可转换股权、复杂表决权分层或多级股权瀑布。

### 3.2 Debt（债权）

表达投资者基于债权安排取得的本金偿还及适用利息请求权。

| 字段 | 业务定义 |
|---|---|
| 债务人 | 承担偿还义务的法律主体 |
| 本金 | 债权本金，金额单位统一 U |
| 利率类型 | 固定利率或无息 |
| 固定利率 | 选择固定利率时填写 |
| 期限 | 债权适用期限 |
| 到期还本 | MVP 基础规则为到期偿还本金 |
| 权利摘要 | 说明本金、利率类型、期限和偿还责任 |
| 法律依据 | 关联借款/债权协议及适用证明文件 |

MVP 不扩展浮动利率、分层债务、可转换债券、复杂摊还计划或优先/劣后债务结构。不得将企业填写的利率或还款条件表述为平台保证收益。

### 3.3 Income Participation（收益参与权）

表达投资者按约定比例参与指定收益来源的权利。

| 字段 | 业务定义 |
|---|---|
| 收益来源 | 明确收益来自哪一资产、业务或合同来源 |
| 收益计算基础 | 总收入（Gross Revenue）或可分配净收入（Distributable Net Income） |
| 参与比例 | 固定比例，明确百分比 |
| 适用期限 | 该收益参与权的起止或适用期限 |
| 分配频率 | 月度、季度或年度 |
| 分配币种/金额单位 | 统一使用 U |
| 权利摘要 | 说明收益来源、计算基础、比例、期限和频率 |
| 法律依据 | 关联收益参与协议及适用披露文件 |

MVP 不建设复杂收益瀑布、优先/劣后分配、多层级参与比例、动态比例或复杂多资产组合分配。

### 3.4 三种权益不可混用

- Equity 按股份数/持股比例计量。
- Debt 按本金 U 计量。
- Income Participation 按指定收益来源的参与比例计量。
- 不同计量单位不得直接相加、互换或使用同一容量字段。
- 同一收益来源、期间及计量口径不得被重复承诺。
- 资产类别不决定权益类型；房地产资产不自动意味着投资者取得房屋产权或股权。

## 4. 页面结构

权益结构模块包含四个主要页面：

1. 权益结构列表；
2. 创建/编辑权益结构；
3. 权益结构详情；
4. 版本及操作记录。

不增加第三级导航。入口为：

**资产与发行 → 权益结构**

## 5. 权益结构列表

### 5.1 列表字段

| 字段 | 说明 |
|---|---|
| 权益结构名称 | 权益结构识别名称 |
| 关联资产 | 对应 Asset 名称 |
| 权益类型 | Equity / Debt / Income Participation |
| 权益总额度 | 按对应权益单位展示 |
| 已确认分配 | 已经确认分配的额度 |
| 发行中预留 | 当前有效 Offering 预留额度 |
| 剩余可发行 | 按已批准公式计算 |
| 状态 | Draft / Preparing / Ready / Active / Suspended / Terminating / Terminated |
| 操作 | 查看、编辑或按状态执行允许操作 |

列表不得将不同权益单位的额度合并求和。每行必须明确显示计量单位，例如股份数、U 或百分比。

### 5.2 列表交互

- 提供创建权益结构入口。
- 点击名称进入详情。
- 编辑入口按状态控制。
- Active 核心权益信息不得显示为普通可直接编辑。
- Suspended 不提供新发行入口。
- Terminated 只读。
- 无数据时显示创建引导；加载失败时保留页面状态并支持重试。

## 6. 创建/编辑页面

创建与编辑使用同一页面结构，按权益类型动态加载字段。

### 6.1 基本信息

- 权益结构名称；
- 关联资产；
- 权益类型（仅三种 MVP 类型）；
- 权利主体/责任主体的基础信息；
- 权利摘要。

关联资产必须处于可用于配置权益的 Asset 状态。一个 Asset 可以关联多个不同权益结构；每个权益结构有独立身份、容量及版本。

### 6.2 动态权益类型配置

选择 Equity 时显示第 3.1 节股权字段；选择 Debt 时显示第 3.2 节债权字段；选择 Income Participation 时显示第 3.3 节收益参与字段。

切换权益类型时：
- 只显示所选类型字段；
- 不把其他类型字段残留到当前提交数据；
- 已填写数据在用户确认切换前提示可能丢失；
- 类型切换不得在已被 Offering 或其他正式业务引用后直接修改核心权利。

### 6.3 权益容量

容量按权益来源和对应计量单位建立，不同单位独立管理。

| 权益类型 | 容量单位 |
|---|---|
| Equity | 股份数 |
| Debt | 本金 U |
| Income Participation | 指定收益来源的参与比例 |

权益结构应显示：
- 权益总授权/总容量；
- 已确认分配量；
- 有效发行方案预留量；
- 剩余可发行额度。

容量不得超出对应法律/合同依据所支持的授权范围。系统负责计算及一致性检查，企业负责其所填授权及权利依据。

### 6.4 Token 映射

- 每种权益结构必须明确权益单位与 Token 单位的固定映射关系。
- 不默认权益单位与 Token 数量 1:1。
- Equity 映射基于股份数/持股比例口径。
- Debt 映射基于本金 U 口径。
- Income Participation 映射基于固定收益参与比例口径。
- 页面必须同时展示权益单位、Token 数量/单位和映射比例，避免只显示 Token 数量。
- 映射规则一旦被正式 Offering 引用，不得静默覆盖；核心映射变更应创建新版本并重新检查适用影响。

本模块只配置业务映射，不代表已经生成、部署或启用真实智能合约。

### 6.5 法律文件

- 关联支持该权益结构的有效法律文件。
- 文件应显示名称、版本及可见范围。
- 文件在权益结构中的引用应固定到明确版本。
- 文件更新不覆盖已被历史 Offering 引用的版本。
- 文件上传不代表平台已核验法律真实性或效力。

## 7. 权益容量池与额度规则

### 7.1 账本层级

容量与发行占用遵循以下层级：

权益容量池 → Instrument 授权 → Offering 预留 → 订单预留（仅 Offering 内部）→ 已承诺 → 已 Mint。

各层记录不同业务事实，不得重复扣减。

### 7.2 剩余可发行额度

当前 R2-03 批准口径：

**剩余可发行额度 = 总授权容量 − 已确认分配量 − 尚未完成发行方案的有效预留量**

该公式按同一权益来源、同一计量单位计算。

- Offering 创建/最终确认时，按该轮最大发行上限形成有效预留。
- 订单预留属于该 Offering 内部的过程状态，不得在 Instrument/权益容量层再次扣减。
- 已承诺由有效预留转化，不得与同一笔预留重复占用。
- 已 Mint 是链上执行结果，不能再次作为同一权益的第二次容量扣减。
- 已确认分配与已 Mint 是两个不同事实，页面和记录必须分别表达。
- 同一权益来源可以支持多轮 Offering，但各轮有效预留与已确认分配总和不得超过总授权容量。

### 7.3 Offering 页面必须展示

- 权益总授权容量；
- 已确认分配量；
- 当前发行方案有效预留量；
- 其他未完成发行方案的有效预留量；
- 剩余可发行额度；
- 本轮最大可发行量。

本轮最大可发行量不得超过当前剩余可发行额度。用户创建发行方案时应直接看到剩余可发行额度，避免在后续发行准备阶段才发现超额。

### 7.4 额度变化规则

| 事件 | 容量处理 |
|---|---|
| Offering 最终确认 | 按本轮发行上限预留容量 |
| Offering 内部订单预留 | 仅更新 Offering 内部预留，不再次扣减权益池 |
| 订单转为已承诺 | 从相应预留转为已承诺，不重复扣减 |
| Offering 正常结束 | 释放尚未承诺的剩余预留 |
| Offering 暂停 | 保留当前有效预留，不释放 |
| Offering 失败/关闭 | 仅按已批准规则释放仍未承诺的预留；已承诺权益不自动释放 |
| 外部执行 Unknown | 保留容量，先查询原始执行意图和结果，不盲目重试或释放 |
| Mint 失败 | 不因失败记录直接释放已承诺权益；按原业务事实核对和恢复 |
| Token Burn | 默认不自动恢复权益容量 |

**重要区分**：已分配/已承诺的权益与已 Mint 的 Token 必须分开记录。Token 铸造失败不能抹除已经确认的业务分配；Token Burn 也不自动消除债务或权益义务。

### 7.5 并发及重复占用

- 多个 Offering 同时申请容量时，必须以服务端权威容量为准。
- 若并发预留后剩余额度不足，后提交的一方失败并返回最新可用额度。
- 重复提交不得重复建立 Offering 预留。
- 不同权益来源、不同计量单位不得混算。
- 同一收入来源/期间不得在多个 Income Participation 权益结构中重复承诺超过其可用范围。

## 8. Instrument（权益结构）状态机

### 8.1 状态定义

| 状态 | 含义 | 编辑/发行规则 |
|---|---|---|
| Draft | 权益结构草稿，核心信息尚未准备完成 | 可编辑 |
| Preparing | 权益资料、容量、法律文件和映射正在准备 | 可编辑 |
| Ready | 已满足基础配置条件，可被发行方案引用 | 可创建 Offering；修改后须重新检查 |
| Active | 首轮 Offering 已正式发布，权益结构已进入发行/存续使用 | 核心权益信息不可直接修改 |
| Suspended | 权益结构暂停使用 | 禁止新增发行；可查看并补充非核心资料 |
| Terminating | 正在结束权益结构，处理存续义务及未完成事项 | 不得启动新发行；按存续义务处理 |
| Terminated | 权益结构终止 | 只读，保留全部历史 |

### 8.2 状态转换

Draft → Preparing → Ready → Active

Active ↔ Suspended

Suspended → Terminating → Terminated

- Ready 可创建 Offering；若权益核心信息或适用资料发生变化，必须重新检查。
- 首轮 Offering 正式发布后，Instrument 进入 Active。
- Suspended 禁止创建新的发行安排，不影响已经发行的 Token、投资者既有权益或依法应履行的义务。
- 从 Suspended 恢复前必须重新检查权益资料、容量、法律文件和相关条件。
- Instrument 恢复不自动恢复其下已暂停的 Offering；Offering 必须按自身状态和条件单独恢复。
- Terminated 只读，历史文件、版本、Offering、分配及 Token 记录不得删除。

## 9. 版本与历史数据

### 9.1 版本规则

- 每个 Instrument 有独立身份和版本历史。
- Draft/Preparing 阶段可编辑并保存新版本。
- Ready 阶段可以修改，但修改后重新执行完整性检查。
- 核心权益被正式 Offering 引用后，不得原地覆盖权利主体、权利类型、计量单位、核心权利内容、容量依据或 Token 映射。
- 核心权益变化应创建新版本，并评估是否允许新 Offering 引用；历史 Offering 继续引用原版本。
- 普通资料更新也应保留版本和操作记录，不得改写历史发行快照。

### 9.2 Offering 固定引用

Offering 应固定引用创建/确认时使用的：
- Asset 版本；
- Instrument/权益结构版本；
- 相关法律文件版本；
- Token 映射配置版本。

历史发行不能因为企业更新当前资产、权益结构或文件而自动改变其原始法律/经济条款。

### 9.3 变更保护

- Active 状态下核心权益信息不允许普通编辑。
- 对已被 Offering 引用的核心权益提出变更时，必须创建新版本并进行影响检查。
- 对已经认购、已承诺或已 Mint 的权益，不得因新版本而静默改变投资者既有权利。
- 变更可能影响既有 Offering 时，应按业务事实暂停新发行或要求另行处理；不能自动改写旧订单、持仓或法律文件。

## 10. 权益结构详情页

详情页包含五个主要区域：

1. **基本信息**：名称、关联资产、权益类型、当前状态、当前版本。
2. **权益定义**：按 Equity/Debt/Income Participation 展示权利主体、权利内容、期限及经济条件。
3. **权益额度**：总授权、已确认分配、发行中预留、剩余可发行及计量单位。
4. **Token 信息**：权益单位、Token 单位、固定映射比例及当前映射版本；不得伪装成真实部署状态。
5. **关联发行**：关联 Project、Offering、历史发行、各轮预留/承诺/分配/Mint 的独立状态。

## 11. 版本及操作记录页

展示：
- 版本号；
- 版本创建时间；
- 修改摘要；
- 修改前后差异；
- 当前状态；
- 被哪些 Offering/发行快照引用；
- 容量变更及预留/释放记录；
- Token 映射变更记录；
- 暂停、恢复、终止等重要操作记录。

历史版本只读，不提供覆盖历史版本的保存入口。

## 12. 主要按钮与交互

| 操作 | 允许条件 | 行为 |
|---|---|---|
| 创建权益结构 | 关联 Asset 可用于配置权益 | 创建 Draft |
| 保存草稿 | Draft/Preparing | 保存当前内容，可未完成 |
| 完成准备 | Draft/Preparing | 校验权利定义、容量、映射和法律文件，满足后进入 Ready |
| 编辑 | Draft/Preparing；Ready 按规则编辑 | 创建新版本；Ready 修改后重新检查 |
| 创建发行方案 | Ready 或符合当前规则的 Active | 引导进入 Offering；显示剩余可发行额度 |
| 暂停 | 允许暂停的非终态 | 确认原因；停止新发行，不释放额度 |
| 恢复 | Suspended 且复核通过 | 恢复 Instrument；不自动恢复 Offering |
| 终止 | 满足结束条件并完成必要检查 | 进入 Terminating，处理未完成义务后进入 Terminated |
| 查看版本 | 全部状态 | 只读查看历史版本与差异 |

MVP 所有企业操作由该企业单一账号执行，不出现企业内部审核人、提交/审核双角色或审批队列。

## 13. 异常及恢复规则

| 异常 | 系统行为 |
|---|---|
| 未关联 Asset | 阻止完成准备 |
| Asset 为 Restricted/Archived | 阻止创建或继续新的权益结构使用，并说明原因 |
| 权益类型字段缺失 | 标记具体字段，阻止完成准备 |
| 容量单位不一致 | 阻止合并计算，提示分别核算 |
| 权益总容量超出可证明授权范围 | 阻止完成准备或发行引用，提示企业补充依据 |
| Offering 超出剩余可发行额度 | 阻止确认预留，显示最新剩余额度 |
| 并发预留冲突 | 拒绝本次预留，返回最新额度，不创建重复记录 |
| 订单重复提交 | 以原订单/原请求状态为准，防止重复预留 |
| Offering 暂停 | 保留该轮有效预留；不允许新增认购，已存在权利按既有义务处理 |
| Offering 关闭/失败 | 仅释放未承诺部分；不得释放已承诺权益 |
| 链上执行 Unknown | 保留容量，先查询原执行结果，不盲目重试 |
| Mint 失败 | 保留已确认业务分配事实，进入异常核对；不得自动清空权益 |
| Token Burn | 默认不恢复容量，不等于债务或权益终止 |
| Active 核心权益被编辑 | 阻止原地覆盖，提示创建新版本及影响评估 |
| Instrument Suspended | 禁止新增发行；不影响已发行 Token 和投资者既有权益 |
| 恢复 Instrument | 重新检查；下属 Offering 不自动恢复 |
| Terminated | 只读，不允许创建新 Offering 或覆盖历史 |

## 14. UI 与验收标准

### 14.1 布局

- 1440px：列表、创建/编辑、详情及版本记录均完整展示，额度卡片与单位清晰。
- 1280px：无页面级横向溢出；表格必要时可在局部容器内处理，不遮挡关键额度和状态。
- Equity、Debt、Income Participation 动态字段必须正确切换。
- 每一个容量值必须同时显示单位，禁止把股份数、U、百分比放在同一总计中。
- Active/Suspended/Terminated 的操作按钮必须符合状态守卫。
- Token 映射配置与真实合约部署状态必须分开展示。

### 14.2 必测验收场景

1. 分别创建 Equity、Debt、Income Participation，检查动态字段正确且互不混入。
2. 三种权益按各自单位展示容量，禁止跨单位求和。
3. 计算剩余可发行额度，Offering 最大数量不能超过该值。
4. 创建 Offering 后形成预留；订单内部预留不得再次扣减权益容量。
5. 订单转已承诺时由预留转化，不重复占用。
6. Offering 结束释放未承诺部分；暂停不释放。
7. Unknown 不释放额度；Mint 失败保留已确认分配事实；Burn 默认不恢复容量。
8. 并发申请容量时后提交请求得到最新可用额度，不产生超额预留。
9. Ready 可创建 Offering；核心修改后必须重新检查。
10. Active 核心权益不可直接覆盖；历史 Offering 仍引用原版本。
11. Suspended 禁止新发行，不影响已发行 Token 和投资者既有权益。
12. Instrument 恢复后，其下 Offering 不自动恢复。
13. Terminated 只读，历史版本和操作记录保留。
14. 在 1440px 和 1280px 完成列表、创建/编辑、详情、额度及版本记录验收。

## 15. 版本、网络、商业与生产边界

- MVP 金额及金额类权益计量统一使用 U。
- V1.0 投资者支付暂时仅支持 OP Mainnet USDT。该规则属于 Offering/认购支付配置，不属于权益类型或 Token 映射单位。
- Free Sandbox 只模拟业务流程，不得产生真实资金、真实链上 Token 或真实投资者权益。
- Standard 订阅不等于生产发行授权。
- 真实 Provider、Signer、链网络、合约部署、Mint、Burn、Claim、Push 等能力继续遵守原有生产技术决策门；未批准的不得开放。
- Token 映射配置、Token 发行数量、合约部署和链上 Mint 是不同业务事实。
- 平台提供通用 SaaS 配置和一致性检查；发行企业承担其法律权利、容量授权、披露及发行信息责任。平台不因字段完整或文件上传而确认法律有效性。
