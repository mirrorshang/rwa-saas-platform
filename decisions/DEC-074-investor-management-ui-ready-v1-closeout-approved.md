# DEC-074｜V1 投资者管理模块 UI-Ready 收口

> **日期：2026-11-11**  
> **状态：V1 企业 SaaS 产品/UI 规则收口**  
> **决策依据：用户授权产品负责人独立完成各模块 MVP 闭环，优先易用性、隐私最小化与业务闭环，尽量不逐页重复征求确认。**  
> **适用范围：Issuer 企业 SaaS「投资者与认购 → 投资者管理」。**

## 1. 决策背景

DEC-069 已将 V1 投资者身份核验统一收敛为：投资者在投资者端提交 KYC，第三方服务商执行核验，平台维护权威结果，Issuer 企业只查看当前 Tenant 授权范围内的脱敏资料与状态。

因此，Issuer「投资者管理」不应继续沿用早期把投资者档案、KYC 人工审核、AML 风险调查和 Offering 资格配置拆成多个页面的设计。V1 应提供最小但完整的企业端业务关系视图，让企业看清本企业相关投资者、KYC 当前状态及本企业认购/持有人关系。

## 2. 正式决策

### 2.1 模块定位

- 「投资者管理」是**本企业投资者业务关系的脱敏只读管理视图**，不是 CRM、平台全局投资者库或 KYC 工作台。
- 固定入口为「投资者与认购 → 投资者管理」。
- 页面仅包含投资者列表和投资者详情；不新增 KYC 审核、风险审核、投资者资格或投资者分级导航。
- I-42 原 KYC 审核结果只读展示并入 I-41；I-43 不作为 V1/MVP 独立页面。

### 2.2 投资者关系建立

- 仅当投资者通过当前企业门户建立账户关系并完成必要告知/授权，或在当前企业 Offering 发起需要建立身份关系的认购流程，或已经存在当前企业认购订单、配售/法定持有人登记记录时，才建立企业可见关系。
- 仅公开浏览 Offering 不自动建立企业可见投资者档案。
- 投资者关系按当前 Issuer/Tenant 隔离；不允许 Issuer 搜索全平台投资者。
- 不因姓名、邮箱、证件或钱包相同自动合并不同 Issuer 关系。
- 平台仅可在合法依据和必要授权范围内引用有效 KYC 结果；不默认跨租户共享原始资料，也不自动合并 M/V 账户、钱包、订单历史或持仓。

### 2.3 页面字段和交互

**列表**
- 摘要：本企业关联投资者数、当前 KYC 有效通过数、待投资者处理数。
- 搜索：本企业投资者引用编号、脱敏展示名称。
- 筛选：KYC 状态、自然人/机构、Asset、Offering。
- 列表字段：本企业投资者编号、脱敏名称/类型、KYC 状态、明确有效期（若平台提供）、关联 Offering 数、认购订单数、持有人登记数、最近业务活动和查看详情。
- 默认最近业务活动倒序，20 条分页。
- 不显示订单金额合计、投资者资产总额、收益或跨 Issuer 指标。

**详情**
- 展示本企业投资者编号、脱敏展示名称、自然人/机构、当前企业关系状态和关联时间。
- 展示平台统一 KYC 当前状态、状态更新时间、权威通过时间和明确有效期（若平台提供），以及企业可见的必要状态历史。
- 展示本企业 Asset/Offering 关联、订单数量/最近订单状态、已完成认购数量和法定持有人登记状态；分别引用 M10/M12/M07 等权威事实。
- 允许复制本企业投资者编号、查看关联 Asset/Offering、认购订单、已完成认购记录、配售与持有人登记。
- 不提供编辑、手工审核、删除、合并、导入、封禁、重置 KYC、导出或批量营销操作。

### 2.4 KYC 状态和企业端下一步

企业端统一映射为：
- 未开始；
- 核验中；
- 需补充资料；
- 已通过；
- 未通过；
- 已失效/需重新核验；
- 暂不可确认；
- 平台限制（仅平台允许向 Issuer 披露通用状态时）。

只有平台权威结果为当前有效「已通过」，才表示 KYC 前置条件满足；其他状态均不得按通过处理。

- 企业只看到必要状态、时间和通用投资者自助提示。
- 补件、重新核验由投资者本人在投资者端完成。
- Issuer 不查看原始证件、地址证明、人脸/生物识别、完整 Provider 报告、AML/制裁细节或内部风险备注。
- 「已通过」不等于任何 Offering 自动可认购；仍受 Offering 开放状态、时间、容量、订单规则和平台级强制限制约束。
- Unknown、过期、撤销、授权不可用和同步延迟不能按通过处理；企业不得手工覆盖。

### 2.5 套餐与权限

- KYB 未通过/补件/审核中，继续适用全局企业准入拦截。
- Free 新企业不展示模拟投资者或真实对外门户投资者；显示 Standard 套餐说明和空状态。
- Standard 且 KYB 通过，可查看本企业授权范围内的真实脱敏投资者关系。
- Standard 宽限期和降级 Free 后，按 U01 保留历史记录只读；不得新增真实投资者业务关系。
- MVP 一个账号对应一个企业，不新增团队角色和分权审核。

## 3. 数据最小化与责任边界

Issuer 默认不显示或导出：
- 完整法定姓名、完整证件号码、出生日期、国籍/地址等完整身份资料；
- 身份证件、地址证明、人脸/生物识别资料；
- 完整手机号、邮箱和社交账号；
- 第三方 KYC 原始报告、Provider Payload、AML/制裁细节和内部风险备注；
- 其他 Issuer/Tenant 的投资者资料、订单、持仓和钱包。

投资者账户、实际付款钱包、Token 接收地址和法定持有人不自动视为同一主体。法定持有人以配售与持有人模块中的权威登记事实为准。

投资者管理只读取并展示：
- M09 平台统一身份/KYC 的授权脱敏结果；
- M10 认购订单的当前企业范围状态；
- M12 配售/法定登记的当前企业范围状态；
- M07 Token 交付的必要引用；
- Asset/Offering 的关联信息。

不复制认购、资金、Token、法定登记或锁仓主账；不提供企业自由文本敏感备注和投资者数据批量导出。

## 4. 与历史规则的关系

- 本决策执行 DEC-069，并将早期 I-41/I-42/I-43 页面候选收敛为 V1 的「投资者管理」一个入口。
- 早期 M09-F001～F008 和 Step04/Step06 文件保留为历史范围/责任来源；其中 Issuer 人工 KYC/AML 审核、Offering 级资格判断、人工例外和跨租户资料复用的早期候选，不构成 V1 企业端页面授权。
- DEC-007 默认租户隔离、敏感原始资料不默认共享、跨场景复用须有合法依据和必要授权的原则继续有效。
- DEC-073 的认购记录只读视图与本模块相互链接；本模块不复制认购记录或认购订单主账。
