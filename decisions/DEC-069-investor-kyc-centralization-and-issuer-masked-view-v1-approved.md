# DEC-069｜投资者统一 KYC、Issuer 脱敏管理与 V1 资格流程简化

> **日期：2026-11-11**  
> **状态：Approved**  
> **批准范围：V1/MVP 产品规则、页面归属与 UI 设计范围**  
> **维护分支：docs/r2-current-product-baseline｜PR #8 Draft / Open / Unmerged**

## 1. 决策背景

原投资者与认购设计将投资者档案、KYC/KYB/AML 审核、Offering 资格判断、认购订单、配售及持有人登记拆分为多个企业端入口。用户明确补充：平台将接入第三方 KYC 服务商，由投资者在投资者端完成 KYC，平台接收核验结果并返回 Issuer SaaS。Issuer 企业只能查看脱敏投资者信息，不应接触投资者原始身份资料。

V1/MVP 应优先采用统一 KYC、结果回传和企业只读管理的基础闭环，不建设重复的企业人工 KYC 审核或复杂 Offering 资格配置。

## 2. 正式决策

### 2.1 KYC 统一服务与页面责任

1. 投资者在投资者端（Issuer 自有 V 门户或平台统一 M 入口）完成 KYC 资料提交及必要的补充/重新核验。
2. 第三方 KYC 服务商负责实际身份核验；平台负责接入服务、接收并维护权威核验状态、将结果提供给有权业务流程。
3. Issuer SaaS 的「投资者管理」读取平台提供的、按当前 Issuer/Tenant 授权范围过滤的脱敏资料及 KYC 状态。
4. 投资者端 KYC 提交/补件页面与 Issuer SaaS 管理页面仍是不同用户界面；合并的是统一 KYC 服务、核验记录和业务结果，不是把投资者端与企业端合并成同一个页面。
5. Issuer 企业不承担第三方 KYC 的人工审核职责，不得在企业后台手动批准、拒绝、覆盖或绕过 KYC 结果。

### 2.2 Issuer 可见资料与隐私边界

Issuer 企业仅可查看完成自身业务所必需的最小化脱敏信息，例如平台投资者引用编号、脱敏展示名称/联系方式（确有必要时）、KYC 状态及完成/有效时间，以及本企业范围内的认购、配售和持有人业务记录。

Issuer 企业不得查看或导出：
- 完整身份证件号码、护照号码及其他完整身份识别号码；
- 原始身份证件、地址证明、自拍/人脸影像或生物识别资料；
- 第三方 KYC 原始报告、完整 Provider Payload、非必要风险细节；
- 其他 Issuer/Tenant 的投资者资料、订单或持仓。

平台对原始 KYC 资料实行受控访问、最小权限和访问审计。跨入口/跨 Issuer 复用 KYC 结果必须具备合法依据及必要授权；复用结果不等于合并 M/V 账户、钱包或历史持仓。

### 2.3 V1/MVP KYC 与认购前置规则

1. KYC 是投资者进入认购流程的强制前置条件。
2. 只有平台收到第三方服务商的权威「通过」结果，投资者才可进入认购确认流程。
3. 未开始、核验中、未通过、需重新核验或结果 Unknown/暂不可确认时，均不得进入认购确认/付款流程；Unknown 不得按通过处理。
4. KYC 通过后，不再要求 Issuer 企业另行设置或审核投资者资格。
5. V1/MVP 不提供 Issuer 可配置的 Offering 级投资者资格条件、投资者分级、资格例外、企业人工批准/拒绝或资格覆盖操作。复杂资格规则及其企业配置界面列为 V2 后续能力。
6. Offering 仍保留正常发行和交易条件校验，例如 Offering 是否开放、认购时间、可用发行额度、最低/最高认购数量、锁仓条款、必要签署及付款状态。这些是发行/订单条件，不构成额外的投资者资格配置。
7. 适用法律或生产准入要求的强制性平台级阻断不因本决策而免除；如确有此类限制，应由平台/有权责任主体在平台级规则与生产准入中处理，不向 Issuer 暴露任意资格配置入口。

### 2.4 投资者与认购导航简化

Issuer「投资者与认购」二级导航收敛为三项：

1. **投资者管理**：投资者列表、脱敏档案、KYC 状态、该企业范围内的认购及持有人关联记录。
2. **认购订单**：认购订单列表、详情、订单状态、基础取消与异常记录。
3. **配售与持有人**：配售记录/结果、持有人登记、持有人列表/详情、登记与 Token 对账。

配售与法定持有人登记仍是不同业务事实和权威责任，只在导航与页面组织上归入同一入口；V1 不引入复杂配售模型或多层资格配置。

## 3. 页面映射与历史编号处理

- I-41「投资者列表/档案」扩展为统一「投资者管理」，在列表及详情中展示脱敏资料与 KYC 状态。
- I-42 原「KYC/KYB/AML 补件审核」不再作为 Issuer 独立页面；企业端所需的核验结果只读展示并入 I-41。投资者补件/重新核验发生在投资者端，平台接收第三方结果。
- I-43 原「Offering 资格与决策版本」不作为 V1/MVP 企业端页面或可配置功能；复杂 Offering 资格规则延后 V2。
- I-44/I-45 归入「认购订单」。
- I-46/I-47/I-48 归入「配售与持有人」；配售、法定登记、Token 对账及差异处理仍保留各自事实和权限边界。
- 九个 Issuer 一级导航不变；本决策不增加一级菜单，不改变「资产与发行」三个二级入口及资产详情四 TAB。
- 原页面 ID 仅作历史追踪，不因入口合并而重新编号或覆盖历史记录。

## 4. 与既有产品边界的关系

1. M 与 V 的投资者账户体系仍保持既有独立边界；统一 KYC 记录可在合法依据及授权范围内被引用，但不自动合并账户、钱包、订单历史或持仓。
2. 平台统一 KYC 结果不复制到各 Issuer 的原始身份资料库；Issuer 只获得本企业业务所需的脱敏结果视图。
3. KYC 状态通过后仅解除 KYC 这一前置门槛，不代表订单已成立、付款已到账、配售已完成、法定登记已完成或 Token 已交付。
4. 本决策优先于现行 R2 总览、页面草案和 Offering 字段候选稿中与「Issuer 人工 KYC 审核」「Issuer 可配置投资者资格」冲突的 V1 描述；历史专项 DEC、Frozen 文件和历史页面编号原文不被改写。

## 5. 功能编号与治理保护

- 本决策收敛 V1/MVP 的 Issuer 页面与客户可见功能，不新增功能 ID。
- 不修改 DEC-017 原 193 项正式功能 ID 和首次交付版本归属；DEC-057 追加的 M23/M24 11 项保持原样。当前功能追踪数字仍按现行主表记录，本决策不自行调整总数或版本分配。
- 不修改原 M01～M22 Frozen 正文、历史 DEC/SCOPE 或旧 Master PRD 原文。
- X-01～X-13 继续 Open；PR #6 保持 Draft / Open / Unmerged；PR #8 保持 Draft / Open / Unmerged。
- 本决策只批准产品规则和 UI 范围，不授权真实 KYC Provider 上线、生产身份核验、代码开发、资金、Signer、Token 或生产发行能力。

---

**执行口径：** 后续 V1 企业 SaaS 详细设计按「投资者管理｜认购订单｜配售与持有人」三个入口推进；企业端不再设计独立 KYC 审核页或 Offering 投资者资格配置页。
