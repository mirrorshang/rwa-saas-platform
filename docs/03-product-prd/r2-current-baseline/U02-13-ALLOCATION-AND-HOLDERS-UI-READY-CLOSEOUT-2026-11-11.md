# RWA SaaS V1｜配售与持有人 UI-Ready 最终规格

> 2026-11-11｜状态：**企业 SaaS 端产品/UI-Ready**（不代表研发、法律登记或生产执行通过）
>
> 唯一导航：**投资者与认购 → 配售与持有人**。维护分支 \`docs/r2-current-product-baseline\`；PR #8 Draft / Open / Unmerged。
>
> 适用依据：DEC-022、DEC-032、DEC-033、DEC-052、DEC-058、DEC-069、DEC-071、DEC-072、DEC-073、DEC-074、DEC-075，以及现行资产/权益/Offering/订单专项 PRD。用户授权产品负责人自主完成小模块 MVP UI 细节。**不改 Frozen、193 项正式功能 ID/首次交付版本归属或既有业务原则。**

## 一、页面职责与最小结构

### 1.1 目标

企业打开本页面即可回答四个问题：
1. 当前 Instrument 与各期 Offering 的**可用、预留、已配售**权益容量各是多少？
2. 哪些订单**已具备合法基础配售条件**，哪些处于待核、受阻或待有权主体处理？
3. 哪些人/机构有**权威法定登记记录**，权益数量与 Token 交付是否一致？
4. 限制、冻结、解冻、锁仓、登记纠正等事项由谁负责、下一步如何查看或提交受权复核？

### 1.2 信息架构（不新增二级导航）

\`\`\`text
投资者与认购
└─ 配售与持有人   ← 现有二级导航，保持
   ├─ [配售管理]  ← 页面内切换视图
   │  ├─ 权益容量摘要
   │  ├─ 配售候选/配售记录列表
   │  └─ 配售详情（订单、付款、容量、资格、决定/证据）
   ├─ [持有人登记] ← 页面内切换视图
   │  ├─ 法定持有人列表
   │  └─ 持有人详情（登记、Token、来源、限制、历史）
   └─ [差异与限制] ← 页面内切换视图，不新增二级菜单
      ├─ 差异/待处理事项列表与详情
      └─ 限制或解除限制申请抽屉（仅受权场景）
\`\`\`

三视图不是三份主账：
- **配售和容量权威**：现行配售/登记模块。
- **持有人法定登记权威**：依法有权登记主体的结果及其受控证据；系统只在具备适用依据时标记权威生效。
- **Token 与链上事实**：Token 管理；不因链上余额而自动确定法定持有人。
- 订单与签署：认购订单；真款/退款：资金与结算；投资者 KYC：平台统一身份；锁仓记录：资产与发行 → 锁仓记录；收益/赎回/清退：收益与分配。

页面顶部固定说明：**「配售、法定登记和 Token 交付是不同业务状态。仅在权威记录齐备时才能判定法律持有关系。」**

## 二、共享页面和交互规范

| 项目 | V1 规格 |
|---|---|
| 企业使用者 | 已通过 KYB、当前 Tenant 有权限的企业账号；一个账号对应一个企业，不新增 V1 分权后台 |
| 主入口 | 投资者与认购 → 配售与持有人；默认进入「配售管理」 |
| 页面内视图 | 配售管理｜持有人登记｜差异与限制；切换保留当前 Asset/Offering 过滤上下文 |
| 关联入口 | 订单详情、Offering 详情、投资者管理、资金与结算、Token 管理、锁仓记录、收益与分配 |
| 搜索 | 当前 Tenant 范围内订单号、配售编号、法定登记引用号、脱敏投资者引用编号；不支持用证件、完整个人邮箱/电话跨企业检索 |
| 共同筛选 | Asset、Instrument 版本、Offering/期次；提供「重置」；只显示当前企业有权访问的选项 |
| 时间展示 | 业务事件发生时刻 + 时区；法定生效日单独显示，不自动等同保存/提交时间 |
| 金额/单位 | 金额统一 U（USDT）；权益法律单位跟随 Instrument（股、债权本金 U、收益参与比例）；Token 份数用整数；权益单位不能与 Token 份数原值盲比 |
| 默认排序/分页 | 待处理优先，历史按最近更新倒序；20 条/页；筛选、页码返回时保留 |
| 状态可信度 | Pending/Unknown/失败绝不显示通过或完成；数据加载不以 0 代替未知 |
| 移动端 | 表格变卡片，保留名称、数量/法律单位、状态、差异、主操作；详情纵向分区，主动作固定底栏 |
| 共享审计 | 记录查看、受控申请、权限变化和重要状态更新；页面不允许清除历史真实交易/登记事件 |

### 2.1 状态页首横幅

- **正常**：「当前未发现待处理的配售、登记或 Token 对账问题。」仅基于已成功完成检查的范围显示。
- **有待处理**：「有 N 项待处理事项。」主按钮「查看待处理」→「差异与限制」对应筛选。
- **资料核对中**：「部分来源正在核对，暂不能确认最终结果。」不展示全绿。
- **无记录**：针对各视图区分无配售、无法定登记、无差异，与「未同步」不同。

### 2.2 前置事实与唯一下一步

- 未有 Offering：指向资产与发行 → 资产详情 → 发行管理。
- Offering 无真实订单：配售候选为空；可以查看发行容量，但不能创建虚构配售。
- 订单实收未确认：显示「待资金核对」，主操作「查看订单/资金」；不可手动通过。
- 具备真实配售准入且存在依法预先批准的基础自动配售规则：记录应自动走受权路径；企业只读查看事实。
- 依法要求逐笔批准且本企业/指定主体有权办理：显示「待有权主体处理」与受控提交/审批入口；普通企业账号无权限时不显示「批准配售」按钮。
- 配售已确认但登记尚未生效：主操作「查看登记事项」。
- 登记与 Token 不匹配：主操作「查看差异」，不能人为标记已一致。
- 登记有效且必要链事实已确认：显示法定持有摘要，主操作「查看持有人详情」。

## 三、视图一：配售管理

### 3.1 权益容量摘要

在选择 Asset + Instrument 后展示一行容量卡：

| 字段 | 控件/来源/校验 |
|---|---|
| 权益结构 | Asset 自动关联的当前 Instrument；只读，显示当前版本与权益类型 |
| 权益池最大 Token 份数 | Instrument 权威授权总量，只读整数 |
| 已确认占用 | 真实有效配售/发行事实对应已占用 Token 份数；只读 |
| 有效预留 | 已发布 Offering 的有效预留，排除已转换为最终占用的部分；只读 |
| 需要保护/冻结的数量 | 权益容量权威中因 Unknown、争议等不能释放的数量；仅有权威结果时显示 |
| 可用份数 | 唯一容量权威计算并返回；绝不由前端把几项来源随意相加减重算 |
| 本期 Offering 预留份数 | 在选择 Offering 后显示；本期内部订单占用不能再次从 Instrument 总额度重复扣减 |
| 更新时间 | 来源最后成功核对时间；未知显示「待核对」 |

**校验原则**
- 一个 Asset 只有一套当前有效权益结构及其共享额度；多期 Offering 不建立多个可重复使用的权益池。
- 「已配售」「已确认发行占用」「订单预留」不得重复累计；同一订单申请、配售决定必须有唯一引用。
- 未得到容量权威确认，所有「可售/剩余」数字显示「待确认」，新配售和额度释放不得展示为已完成。
- 正式容量、法律单位与 Token 映射按确定 InstrumentVersion 解释；股权、债权、收益参与三类的法律单位各自独立。
- 不提供增加容量、手动减少预留或一键释放额度的普通按钮。

### 3.2 配售列表

| 字段 | 控件/规则 |
|---|---|
| 搜索 | 订单编号、配售记录编号、当前企业投资者引用编号 |
| Asset / Offering | 下拉联动；默认全部当前企业 |
| 配售进度 | 全部、待核条件、可受权处理、处理中、已确认、受阻、存在差异、无法确认 |
| 资金核验 | 全部、未确认、实收已确认、异常、Unknown（只读筛选） |
| 创建/更新日期 | 日期区间；起始不得晚于结束 |
| 列表列 | 配售/候选编号；订单编号；脱敏投资者；Asset / Offering；申请 Token 份数；对应法律权利量/单位；实收摘要；配售状态；登记状态；最近更新；「查看详情」 |

**配售候选与决定区分**
- 配售候选是订单符合部分前置条件后的待核对象，**不是有效 Allocation**。
- 配售已确认时必须存在受权唯一配售决定、准确的法律权利量、对应 Token 份数、依据版本、发生时间和来源。
- 如果实际适用基础逐笔自动配售，由事先批准的规则返回已确认结果；列表不提供每条「一键批准」来代替前置授权。
- 若法律要求真正的人工作出决定，在存在有权主体已授权的业务流程时展示「提交授权审批」「查看审批结果」；如尚无被验证的有权主体，显示「待指定/待确认合法责任主体」，不能用 SaaS 普通角色冒充。
- 本模块 UI 的「提交审批」仅创建/提交受控待办，不在点击时写入已配售、已登记或 Token 已交付。

### 3.3 配售详情：五块只读区 + 受控操作区

**A. 订单与权益来源**

| 字段 | 必填/展示规则 |
|---|---|
| 配售候选/决定编号 | 权威存在则显示完整引用，可复制；候选和最终决定编号分开 |
| 订单编号 | 必须有唯一订单引用；点击进入认购订单 |
| 企业投资者引用 / 脱敏展示名 | 只读，来自当前 Tenant 许可范围 |
| Offering 发布快照版本 | 只读，必须存在并可追溯 |
| Instrument 权益类型及版本 | 只读，不用现行修改版本覆盖订单历史 |
| 订单认购 Token 份数 | 整数，来自订单快照 |
| 每 Token 对应法律权利 | 只读，来自 InstrumentVersion |
| 本单对应法律权利总量 | 以精确映射计算、显示法律单位；不静默舍入 |

**B. 最终配售守卫**

| 校验 | 结果显示 | 阻断条件 |
|---|---|---|
| 平台 KYC | 通过 / 未通过 / 需重核 / Unknown | 当前有效核验不是通过则阻断；不额外配置 Issuer 资格 |
| 合法销售及工具限制 | 通过 / 待有权确认 / 阻断 | 适用法律强制限制仍不可绕过 |
| 订单报价/合同/必要签署 | 通过 / 失效 / 缺失 / Unknown | 当前用于该单的有效快照和签署不充分 |
| 真实收款 | FinalMatched / 待核 / 异常 / Unknown | 仅最终合法匹配可通过 |
| 容量预留 | 有效 / 待核保护 / 已释放 / 不足 / Unknown | 没有有效、未重复占用额度 |
| Instrument 授权容量及合法权利 | 通过 / 待有权确认 / 阻断 | 公司授权、权利合法性、最大容量未知或不足 |

**C. 配售结果**
- 配售模式：已获预授权的基础自动配售 / 依法受权逐笔处理（只读）。
- 决定结果：未开始、待核、待处理、已确认、已拒绝/受阻、Unknown（用户文案，非工程冻结枚举）。
- 已确认 Token 份数、法律权利单位及总量；审批/规则依据版本；批准/处理主体展示名和角色；结果形成时间；固定证据/文件引用。
- 决定可见时显示「查看关联登记」。没有权威配售决定不能生成合法登记确认提示。
- **同一订单/预留只能有一个生效配售决定**；重复回调不能重复配售。

**D. 登记及交付摘要**
- 法定登记：未提交、待回执、已有效、受阻/争议、Unknown。
- Token：未触发、待交付、已交付、失败/Unknown。
- 页面分开显示，不用一个「配售成功」覆盖法律与链上结果。
- 入口：「查看持有人登记」「查看 Token 交付」。

**E. 事件与异常**
- 事件时间线：申请预留 → 条件核验 → 受权决定 → 转换容量 → 登记/交付 → 差异处理。
- 每事件有时间、来源、业务引用、状态、可见原因和证据版本。
- Payment Unknown、迟到账、资格变化、配售规则变动、重复决定、法律登记回执缺失等均进入异常，不覆盖历史。

**操作区**
- 普通可用：「查看订单」「查看资金匹配」「查看权益容量」「查看登记/交付」「查看异常」。
- 条件可用：「提交配售审批请求」：仅在依法适用的逐笔审批流程、拥有真实有权主体及已通过所有前置守卫时启用。提交后展示「等待有权主体确认」，**不是已配售**。
- 不提供企业手动改配售份数、直接批准法定配售、直接 Mint、假设资金已到账、强制释放额度等普通按钮。

## 四、视图二：持有人登记

### 4.1 法定登记对象边界

- **投资者账户**、**付款钱包**、**Token 接收钱包**、**合法持有人**可以是不同主体；不能因订单号或 Token 余额就默认相同。
- 法定持有人与其权益数量，以**依法有权登记主体的有效结果/引用**为权威。
- 登记责任分三类：①依法可以由发行企业有权主体管理；②依法委托合法登记合作方；③法律强制特定登记人。V1 **不强制所有发行企业聘用第三方**，也不把 SaaS 操作员视为当然法定登记者。
- 登记结果的权威主体、模式、依据和有效性按 Asset/Instrument 法律结构确定；无法核实时只显示「待有权确认/待证据」，不虚构合法生效。
- 不是所有资产的「份数」与 Token 一比一：法定数量按股/债权名义金额 U/收益参与比例等对应单位显示，并依固定 InstrumentVersion 精确映射。

### 4.1.1 登记材料/权威结果承接抽屉（条件展示）

登记不会因配售或 Token Mint 自动生效。为了让企业真正能够把合法登记结果接入后续持有人视图，提供统一的**「登记事项」抽屉**，但严格按现有批准的三种登记模式展示不同操作：

- **发行企业依法自管**：仅在当前 Instrument/法域确认「发行企业有权自管登记」且该企业账号确有对应合法授权、必要前置材料已备齐时，展示「录入权威登记结果」；普通企业账号不能凭 SaaS 订阅身份点击形成法律权利。录入的是已经由有权主体真实作出的权威结果和证据，不是 SaaS 自动赋权。
- **依法委托登记**：显示「查看委托资料 / 登记请求 / 回执」；仅当合法受权委托流程允许时可「提交登记材料」，不能自行填写「已生效」。
- **法定强制登记机构**：只能查看已授权的登记请求与机构真实回执；不可由 Issuer 自行确认法定生效。
- **登记模式或有权主体未确定**：所有提交按钮禁用，提示「请先确认本权益结构的合法登记责任方」；仅允许查看历史。

**共用字段与校验**

| 字段 | 控件 | 必填及条件 |
|---|---|---|
| 关联配售决定 | 自动只读引用 | 必须存在已确认的唯一配售决定；候选订单不能登记 |
| 法定持有人主体 | 从本次受权登记主体引用中选择，只读展示脱敏名称/引用 | 必须与有权证据所指主体匹配；不能以投资者账号或收款/接收钱包自动代入 |
| InstrumentVersion、权益类型 | 自动只读 | 固定与配售决定一致；不允许切换 |
| 拟登记法律权益量 | 只读精确法律单位（股、债权名义 U、收益参与比例等） | 来自已确认配售映射，不能手动改变法定份额 |
| 实际登记法律权益量 | 精确法律单位输入；仅合法结果与配售数量允许核对时显示 | 正数、不得超出受权决定范围；与配售不符阻断「一致」并要求差异说明和受控复核，不自动生成已生效 |
| 有权登记模式 | 单选结果只读 | 自管/委托/强制登记，取已确认的法律安排 |
| 权威登记主体 / 委托依据 | 引用卡片 | 必须有适用有权主体及固定的委托/资格依据版本 |
| 登记证明 / 回执 | 固定文件行，上传或选择已有效文件版本 | 权威结果录入时必需；待扫描/失败/无权版本不得引用 |
| 回执/名册编号 | 文本，最多 120 字 | 已有权威回执时必填；不能随意伪造由系统生成的法律编号 |
| 实际法律生效日期 | 日期 + 时间/适用时区（取回执事实） | 只有实际权威依据明确才允许填写；未确认时留空并标「待确认」 |
| 受权结果状态 | 只读受控状态 | 未提交 / 已提交待回执 / 回执待核 / 有效已确认 / 驳回 / 差异 / Unknown |
| 变更说明 | 多行文本，最多 500 字 | 更正/差异路径必填；普通新登记可选 |
| 提交人确认 | 复选框 | 必勾「我确认已核对有权主体、实际回执及权益单位，提交资料不等于平台自动赋予法定权益。」 |

**操作与反馈**

- 按当前模式显示唯一主操作：「提交登记材料」「提交权威结果记录供核对」或「查看有权主体回执」；次操作「取消」。
- 提交前二次确认展示合法持有人脱敏引用、权益单位/数量、实际责任主体、固定文件版本和拟生效依据。
- 提交完成仅显示「登记材料已提交」「等待权威登记核对」；只有已核验有权主体及其真实结果证据确立时，才显示「法定登记已有效」。普通表单保存或文件上传绝不直接转为已有效。
- 同一 Allocation 的重复提交、重复外部回执、Unknown 等情形先打开历史记录核对，不再次登记；幂等结果展示原事项编号。
- 已有效登记不可直接编辑覆盖；后续更正必须走「差异与限制 → 登记更正受权事项」，保留旧版证据及其有效期间。
- 本抽屉不提供填写原始 KYC 文件/个人证件上传入口。依法登记必须使用且获授权的敏感法律身份材料由受控合法登记流程处理，不向 Issuer 普通列表扩散。

**固定顶部**：脱敏主体名称 + 持有人引用编号、法定登记状态、对账状态、最近核对时间。异常时主动作「查看差异」；正常时「查看登记历史」。

**A. 法定权益登记**

| 字段 | 内容与可见规则 |
|---|---|
| 持有人引用号 / 权威登记引用号 | 只读、可复制；平台引用和外部合法名册引用分开 |
| 合法权利主体 | 受控脱敏名称、自然人/机构；如与投资者账户不同，明确提示差异，不能自动纠正 |
| Asset / InstrumentVersion / 来源 Offering | 只读，固定版本 |
| 登记模式 | 发行人依法自管 / 合法委托 / 强制登记主体（从已经确认的合法安排读取） |
| 权威登记责任主体 | 业务可见名称、授权依据引用；未确认时明确「待确定」 |
| 权益类型、法律单位、权益数量 | 必须按当前有效权威登记；禁止和 Token 份数混合 |
| 权益生效日期 | 有权主体确认的生效日期/时区；并非本地录入日 |
| 登记状态 | 待证据、处理中、已有效、受争议、更正中、拒绝、Unknown |
| 有效证明/回执 | 固定文件引用及版本、可查看状态；权限不足不展示证件原件 |
| 当前版本与历史版本 | 生效/更正/撤销等变更事件按版本追溯，不能覆盖原始证据 |

**B. Token 与交付**

- Token 网络：按产品 V1 的适用链上事实显示；投资者支付 OP Mainnet USDT 不自动意味着所有资产 Token 必然仅部署于同一网络。
- Token 标识、合约简短地址/网络（只有真实部署事实才显示）。
- Token 已确认交付数量、当前可核链上数量、冻结/限制状态与时间；所有字段标注来源与核对时间。
- Token 接收钱包缩略标识；完整地址只有另行授权的详情可见，不默认复制。
- Mint、转让、Burn 事件只读摘要；链上 Unknown 或失败不得标已成功。
- **映射核对**：根据固定 InstrumentVersion「每 Token 对应法律权益量」，换算出对应权益单位，与**同一法律持有人、同一适用时点、同一 Instrument/期次范围**的权威法律登记比较。无法建立一一对应的合法实体/持有人或缺少确定时点，显示「不可比较/待核」，不显示错误「一致」。
- 不允许直接改余额、Token 接收钱包、法定持有人或签名主体。

**C. 来源订单、配售和资金**
- 认购订单编号、订单 Token 份数、合同/报价快照；
- 配售决定引用、已获配法律权益单位/Token 数、决定时间；
- 资金最终匹配摘要（状态与时间；不是企业最终结算）；
- 如有非认购来源的依法登记更正/转让，展示权威变更引用与性质，不伪造一笔认购订单；
- 按来源跳转相应权威页面。

**D. 限制、锁仓、变更与审计**
- 当前基础锁仓：无/待交付/锁仓中/期限已到待核/解除待执行/解除处理中/已确认解除/异常或 Unknown，规则来源 Offering；实际锁仓记录跳转「资产与发行 → 锁仓记录」，业务锁仓状态、链上执行状态与法律/管理限制分别展示，详细字段和状态以 [DEC-079](../../../decisions/DEC-079-lockup-records-ui-ready-v1-closeout-approved.md) / [锁仓记录 UI-Ready 最终规格](LOCKUP-RECORDS-UI-READY-CLOSEOUT-2026-11-11.md) 为准。
- 法律/管理限制：无限制、复核中、限制有效、解除复核中、已解除、Unknown，可与锁仓并存。
- 每条限制展示影响对象/数量、限制类型、原因类别、依据文件版本、发起方、受权责任方、请求时间、生效时间、解除条件/到期及工单编号。
- 登记更正、转让/变更、赎回/退出、收益快照等仅展示权威结果和跨模块入口。
- 历史不能被覆盖；只读审计事件含操作类型、时间、结果及权威来源。

**更正/重试原则**
- Unknown 先查原请求/原回执，禁止重复登记、重复 Mint/Burn 或双重预留。
- 有权登记更正如确需执行，必须依据适用合法登记模式和授权，形成受控任务、证据、版本、结果。提交材料/任务 ≠ 法定登记结果已更正。
- 登记有效结果修订不能静默覆盖旧版本；Token 变动必须由 Token 管理独立验证。
- 差异只在有关权威来源已核对、纠正或合法解释且证据可追溯时显示「已解决」；关闭任务不等于法定/链事实被修复。

### 5.3 受权限制/解除限制申请（V1 适用，**不是一键冻结**）

仅在当前 Instrument 与法域允许、已明确有权请求主体及必要业务授权时显示：
- 「申请限制复核」
- 「申请解除限制复核」

默认没有直接「冻结」「解冻」「强制转账」主按钮。强制转账不在 V1。

**申请抽屉字段**

| 字段 | 控件/要求 |
|---|---|
| 申请类型 | 限制 / 解除限制（根据入口固定只读） |
| 关联持有人 | 当前详情自动带入只读引用 |
| Asset、InstrumentVersion、Offering/Series | 自动引用；必需，可追溯 |
| 影响范围 | 整个当前法定权益 / 部分单位（仅当权威 Instrument 与限制规则允许） |
| 影响法律权益量 | 精确法律单位；部分限制时必填，正数且不得超过当前可用依法可限制数量 |
| 映射 Token 份数 | 系统只读计算，如无法按 Instrument 精确拆分则阻断提交；不静默取整 |
| 原因类别 | 法定/司法要求、合同约定、争议核查、其他适用原因；必选 |
| 原因说明 | 文本 10–500 字，必填；禁止填写投资者完整证件或其他无关敏感数据 |
| 法律/合同依据 | 文件固定版本或已有有权决定引用；必填 |
| 拟生效时间 | 默认「待有权主体决定」，仅在适用规则允许时提供明确时间填写 |
| 解除条件或原限制编号 | 限制时条件化填写；解除限制时原限制编号必填且必须处于可解除的有效状态 |
| 申请人确认 | 复选框：「我确认本申请仅进入有权复核，不会因提交立即变更法定登记或链上限制。」 |
| 按钮 | 提交复核申请 / 取消；禁用重复提交；保存不完整内容不形成生效限制 |

**二次确认弹窗**显示持有人脱敏引用、Instrument、权益法律单位/数量、Token 映射、申请类型、依据版本、可能影响及「提交后待有权主体复核」文案。提交成功仅显示「申请已提交，等待受权复核」+ 事项编号，不显示「冻结成功」。

**状态**
- 草稿/待提交（界面暂存，不产生法律事实）→ 已提交 → 待有权核实 → 待合法执行 → 已生效 / 已拒绝 / 需补充资料 / Unknown。
- 解除限制同理：已提出解除申请 ≠ 已解除；需有合法生效结果和适用 Token 侧确认。
- 任何权限/依据/状态未知时只读，显示「请由有权主体确认适用条件」。
- 法律登记限制与 Token 链上限制可以不同步；必须并列显示差异并进入核对，不合并绿色状态。

## 六、跨模块流程与必需状态

### 6.1 基础配售

\`\`\`text
Offering 已发布并有合法可售容量
 → 投资者唯一订单与有效报价/协议/签署
 → 平台当前 KYC 通过 + 适用强制限制核查
 → 真实认购款 FinalMatched
 → M12 核验本期内部预留及 Instrument 授权容量
 → 事前批准的基础自动配售 / 必要时有权主体逐笔决定
 → 唯一有效 Allocation（附凭证版本）
 → 法定登记结果、Token 交付按适用合法顺序各自处理
 → 对账与必要异常复核
 → 持有人登记视图显示权威结果
\`\`\`

- 没有真实付款或合法授权不能宣告有效配售。
- 不在 V1 设计强制集中募集、批量竞价、超额配售、分层优先配售。
- 不把 Payment FinalMatched、Allocation、法律名册、Token 交付合并为「购买成功」。
- 法律上具体登记/交付先后顺序依 Instrument 与法域而定；UI 使用分状态并列展示，不强制统一先法定登记再 Mint。

### 6.2 持有人管理与后续事项

| 事项 | 本模块展示/允许动作 | 权威责任 |
|---|---|---|
| 权益登记与更正 | 受控登记结果/证据版本查询、差异复核入口 | 有权登记主体及 M12 |
| Token 持仓/链限制 | 摘要及差异入口 | Token 管理 |
| 锁仓/解锁 | 显示锁仓规则、已生效时点、预期到期和实际解除状态；前往「锁仓记录」 | 锁仓/Token 权威 |
| 冻结/解冻 | 仅有依据时提交受权限制或解除复核；不直接更改法律/链事实 | 依法有权主体、受控任务、M12/M07 |
| 普通转让 | 仅查询合法转让/登记/Token 变动的受权结果和引用；不新增本模块自由交易/强制转让 | 适用 Instrument 法律与 Token/登记责任模块 |
| 赎回/退出/清退 | 查询关联退出事项或跳转「收益与分配 → 到期与退出」；不在此计算、收款或执行清退 | 收益与分配、M12、M07、真实付款义务方 |
| 权益记录日 | 仅提供已有效的法定权益登记和历史，供收益模块引用合法快照 | M12 权威登记；收益与分配创建合法 Record Date 快照 |
| 企业降级/暂停发行 | 维持历史登记、持有人权利及在途义务只读可查；不得自动删除权益 | 适用存续责任及授权流程 |

### 6.3 全局异常与页面文案

| 场景 | 文案/下一步 | 不可做 |
|---|---|---|
| 无真实配售 | 「当前没有配售记录。符合条件的真实订单将按有权规则进入配售。」→ 查看认购订单 | 创建演示配售 |
| 无登记结果 | 「暂无法确认有效持有人登记。请核对有权登记者及必要回执。」→ 查看登记事项 | 自动标已登记 |
| 配售已确认、登记未回 | 「已确认配售，法定登记仍待有权主体确认。」→ 查看登记进度 | 把配售等于法律持有 |
| Token 已交付、登记 Unknown | 「Token 已交付，但合法登记仍待核对。」→ 查看差异 | 把 Token 当法律权利 |
| 登记已有效、Token 未交付 | 「法定登记已有效，Token 交付仍待确认。」→ 查看 Token 管理 | 把登记当已 Mint |
| 法律权益单位与 Token 数不 1:1 | 「按权益结构映射核对法律单位与 Token 份数。」→ 展示映射比例与时点 | 原值直接作差 |
| 缺法定责任主体 | 「尚未确认有权登记主体，本期登记不可标为生效。」→ 联系有权责任方 | 让 SaaS 代签 |
| 双重登记引用 | 「该来源已存在受权登记结果，请先核对历史。」→ 查看原事件 | 再登记一次 |
| 支付/链 Unknown | 「相关事实尚未确认，请先核对原指令。」→ 资金/Token 记录 | 释放、退款、Mint/Burn 重复执行 |
| 登记差异已提交复核 | 「复核已提交，实际登记或链上状态尚未改变。」 | 显示已纠正 |
| 限制申请已提交 | 「等待有权主体复核，法定和链上限制仍以各自真实状态为准。」 | 显示冻结成功 |
| 解除申请处理中 | 「解除申请处理中，限制尚未确认解除。」 | 提前解锁 |
| 跨租户访问 | 「记录不存在或无权访问。」→ 返回列表 | 泄漏主体/钱包地址 |
| 数据源不可达 | 「当前核对结果不可确认。历史信息仅供参考。」→ 刷新 | 显示全绿 |
| Free 无真实业务 | 「Free 支持资料准备与内部预览，真实配售及持有人运营仅在符合 Standard 和生产准入后开放。」→ 套餐 | 生成虚拟持有人 |
| Standard 降级 | 「历史权益记录保持只读，存续义务仍须依法履行。」 | 删除真实权益 |

## 七、Free / Standard、权限与隐私

| 企业状态 | 列表/详情 | 受权配售/登记处理 | 限制申请/纠正 |
|---|---|---|---|
| KYB 未通过/补件/审核中 | 按统一企业认证引导拦截，不显示业务详情 | 禁止 | 禁止 |
| Free 新企业 | 说明真实业务未开放，不创造 Mock 真实业务 | 禁止 | 禁止 |
| Standard KYB 通过 | 仅看本 Tenant 权威真实业务数据 | **仅法域/Instrument/主体和真实生产准入全部满足**才可能通过受控路径执行 | 仅符合法律依据和受权流程可提交申请；不直接执行 |
| Standard 宽限期 | 按已批准规则保留必需历史查询 | 不新增未授权真实业务；存续法定责任由有权主体处理 | 历史权利义务继续依法处理 |
| 降级 Free 的历史企业 | 历史记录只读可查 | 不因降级改变已有合法权利或已付款义务 | 不提供普通前台直接改权益按钮 |

- MVP 仍是一个账号对应一个企业，不开发复杂的用户角色权限配置页；**没有权威授权不能因为该账号是企业管理员而获得法定登记、冻结、资金或 Signer 权**。
- KYC 只显示企业可见脱敏状态，不显示身份证件、AML 调查、原始 KYC 文件/报告、完整手机号/邮箱/完整个人钱包地址。
- 只有依法必要且已有授权时，法律登记证据可经受控流程被适格主体访问；不在 Issuer 普通列表公开。
- 当前页面不提供自由批量修改持有人、法定登记或链上余额；导出经数据报表模块的授权/审计、默认脱敏。
- 数据来源变动、账户状态变化不自动改写已存在法定权益。
