## 一、版本的一句话目标

| 版本 | 业务定位 | V1首版交付与后续区别 |
|---|---|---|
| **V1.0** | **一家真实Issuer可以购买SaaS、管理企业账号、拥有标准投资者门户、合法创建发行产品、受权自动部署、完成认购支付/登记/Token交付、处理募资合法结算、按适用条款分配收益并管理退出** | 发行工作台与其投资门户的独立运营基础闭环，必须有适用外部服务与合法执行条件才能生产使用 |
| **V2.0** | **增强发行运营并规划新产品线：受控转让、专业White-label运营商、集中募集批次与更灵活的企业协作** | 不是对V1的“基本钱包/基本门户/基本结算”事后补票；其新增业务可与V1核心共用API与安全底座 |
| **V3.0** | **高级商业扩张：对外商业API/SDK、复杂多链/多资产策略、专业服务商市场、高级规则、分析与商业分发** | 高级与独立产品，不得误认为V1内部API-Ready实现必须等到V3才做 |

**版本候选统计（现193项正式功能ID，版本归属全部Draft）**：V1.0 **146** / V2.0 **22** / V3.0 **25**，合计 **193**。与旧187表的差额正是 [DEC-016批准的6个独立新ID](../../decisions/DEC-016-prop01-11-six-formal-function-ids-approved-version-assignments-draft.md)，非新增6个一级模块或六套重复业务账。

## 三、V2.0 / V3.0 的明确候选业务能力

### V2.0（现有原ID建议22项）
- **受控二级转让（M14-F001～006，6项）**：持有人转让申请、受让人适格/转让限制、发行方同意、转让对价结算、法定登记/Token变更与纠纷恢复。真实法域及转让许可仍是生效门，不等于公开撮合交易所。
- **专业White-label运营商（M15-F001～007，7项）**：多发行机构运营、机构授权与数据隔离、品牌域名与授权分发、退出责任交接；**普通Issuer独立URL/基础Logo已经是V1客户核心目标**。
- **发行及运营增强（其余9项）**：企业SSO、实施与客服工单、更复杂的集中募集/批量配售/部分订单与调整、在线专业服务任务协作以及营销消息偏好。这些完整增强不应让V1合法退款、实际结算或基本任务提醒无法工作。

### V3.0（现有原ID建议25项）
- **对外商业API/SDK产品（M16-F001～008，8项）**：外部开发应用、授权凭证、接口门户、Webhook、Sandbox、限额、API版本、应用生态。V1内部API-Ready与此不同。
- **复杂资产/多链/价格发行策略与支付增强**：复杂资产组合、合约升级/多链、动态定价、复杂认购与法币多通道支付。
- **复杂运营生态**：法律服务Marketplace/竞价、跨机构KYC数据网络、公开订单簿/AMM（法定业务条件另审）、营销推荐、代理分销。
- **高级运营底座**：高级CRM、低代码流程/规则、预测BI、高级数据安全与服务商智能选择。

**这里仅是版本建议**，没有批准V2/V3准确交付日期、法律许可、代码或整体成本预算。

## 六、版本规划进入 Approved 前必须过的门

1. XCHK-01～10 A **已由 DEC-015批准**；但这不是所有具体PROP/各原ID版本的自动批准。
2. 产品负责人确认本版本表的 **七段V1业务、V2增强、V3商业API与复杂能力**是否符合预期；有变化则先调整业务版图。
3. 对原187条按模块集中确认实际归属、必要时将大功能拆分不同可验收的基础与增强单元，避免一个ID同时跨版模糊。
