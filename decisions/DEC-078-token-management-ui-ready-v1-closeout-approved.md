## 1. 决策依据与批准边界

本决策承接并落实已批准的既有业务原则：
- DEC-021：Token 方案、受控链/标准、合约版本与部署审批、接收钱包、获批准 Mint、链上最终性/Unknown、配售/登记核对、必要转让限制、高风险权限/暂停、依法需要时的 Burn/授权调整。
- DEC-054：Token 管理页面方向及六项业务方向。
- SCOPE-186～193：TokenContractPlan/Version、外部受权执行、资金/配售登记/Token 链事实分离、投资者账户/付款地址/Token 接收钱包/法定持有人分离、必要合约级转让限制、职责分离与 Unknown 安全恢复。
- DEC-032/033：合法配售、登记、Token 交付、存续清偿/公司行动分别保留权威事实。
- DEC-068/U01：Free/Standard 权益和真实生产准入边界。
- DEC-071/U02-08：一资产一套当前权益结构、三类权益、Token 数量与每 Token 法律权益映射由 InstrumentVersion 唯一确定且精确计算。
- DEC-072/U02-09：Offering 固定引用 InstrumentVersion；本期发行数量不超过共享权益容量。
- DEC-076/U02-13：配售与法定持有人登记独立；Token 份数和法律权益单位分列；锁仓记录独立归资产与发行。
- DEC-077/U02-14：真实认购资金/退款/募集款结算由资金与结算负责。

本次只细化页面信息结构、字段、控件、校验、状态文案、操作守卫、异常、权限、跨模块入口和 UI 验收目标；不新增正式功能 ID，不重新批准既有功能的版本/优先级。

## 2. 页面与导航决定

一级导航保持 **Token 管理**；二级入口固定为：
1. **合约管理**：Token 方案列表、创建/编辑单页、方案详情、部署申请与结果。
2. **Token 操作**：Mint 与交付、限制与暂停、销毁与授权调整（仅适用时）。
3. **链上记录与对账**：链上事件列表/详情、Token 与配售/法定登记对账、差异调查。

不新增菜单，不恢复历史独立 Token 发行方案、Token 记录、钱包管理入口。

## 3. V1 核心产品规则

### 3.1 Token 方案与权益结构

- Token 总份数、每 Token 对应法律权益量、法律单位、当前权益版本全部从确定的 InstrumentVersion 继承；Token 管理不得重新定义、覆盖或静默舍入。
- 一个 Asset 只有一套当前有效 Instrument；多个 Offering 共用该权益容量。V1 默认同一 InstrumentVersion 复用同一份当前有效 Token 方案版本，各 Offering 引用该方案，不重复创建 Token 供给池。
- 若实际法律/合约模型要求独立合约或不同映射，必须在相应法律/生产准入中单独确认，不作为企业用户默认自由配置。
- 网络、标准和模板仅能从已批准、已开放的受控选项中选择；未获准时保留准备资料但阻断部署。
- Token 网络与投资者支付网络分离。投资者付款 OP Mainnet USDT 不意味着 Token 必须部署在 OP Mainnet。
- V1 每个 Token 方案仅选一个获准网络；复杂多链、跨链桥、复杂合约升级、代理升级不纳入 V1。
- 链上 decimals、模板参数等仅显示获批模板/网络来源的只读值；不允许任意 ABI、合约代码或秘密凭证输入。

### 3.2 合约部署与受权执行

- Token 方案批准、部署申请获批、Signer 实际执行、交易广播、链上最终性是不同事实。
- Issuer 页面负责方案准备、申请、状态查看和证据核对；真实部署由依法有权的 Issuer 主体或受权外部 Signer 执行。
- 没有法域/发行主体授权、获批网络/标准/模板、安全审查、真实 Signer 和适用生产准入时，不开放真实部署。
- Tenant Admin、SaaS 运营和普通页面编辑者不自动成为合约管理员或 Signer；SaaS 不保存生产私钥/助记词/Signer Secret。
- 已部署合约的方案、地址、网络、模板和关键参数固定；变更只能走新版本/受控授权，不提供直接覆盖或任意升级操作。
- Provider Accepted、Webhook 成功或存在 TxHash 不代表部署完成；必须核验适用链上最终性。

### 3.3 Mint 与交付

- Mint 只能从唯一有效配售决定发起，引用真实订单、资金核对状态、法定登记/适用交付条件、已核验 Token 接收钱包和有效合约。
- 资金与结算的 FinalMatched 状态、配售/登记结果及 Token Mint 各自独立；是否要求先资金、先登记或其他顺序按具体 Instrument/法域确认，不统一强制一个法律顺序。
- Token 数量由唯一配售决定和固定 InstrumentVersion 映射计算；Issuer 不可手工增加、减少或覆盖。
- V1 默认一项 Mint 申请对应一个唯一配售决定；不开放无来源 Mint、任意批量导入或任意转账。
- 同一配售不得有重复有效 Mint Intent；Unknown 必须查询原 Intent/Tx/链上事件，不得盲目重 Mint。
- 链上最终确认不自动代表法定登记已生效或资金义务已完成。

### 3.4 限制、暂停、锁仓与 Burn

- 法律/管理限制、合约冻结、合约级暂停、Offering 锁仓为不同事实；冻结/解冻不等于锁仓/解锁。
- 业务锁仓计划及投资者可见记录归「资产与发行 → 锁仓记录」；Token 管理只显示相应链上执行/限制事实，不创建第二套锁仓记录。
- 必要合约级转让限制属于 V1；不提供用户间自由转让、撮合或二级市场入口。
- 持有人/钱包级限制、解除、合约级暂停/恢复和权限撤销必须有合法依据、真实授权、适用合约能力及执行后链上核验；不允许任意冻结任意地址。
- Burn/授权调整只在具体 Instrument/法域/合同生命周期确实要求时开放；须引用有权到期/退出/公司行动、资金清偿和法定登记调整等适用事实。
- Burn 不等于实际付款、债务清偿或法律权利终止；不作为每期 Offering 默认步骤。

### 3.5 链上记录与对账

- 链上部署、Mint、Transfer（只读观察）、限制/解除、暂停/恢复、Burn 和权限变更均以真实链事件为来源。
- 对账按同一 Tenant、Asset、InstrumentVersion、Offering/适用权益范围、合法持有人、接收钱包及可比较时点核对。
- Token 份数与法律权益数量/单位分列；精确映射不成立、时点不一致或主体无法匹配时显示待核/不可比较，不显示错误一致。
- 不允许手工改写 Token 余额、交易哈希、链上数量或最终性状态；差异通过追加证据、受权复核和后续真实事件处理。
- Unknown、链重组、数据源不可达均保留最后已知状态和时间，不显示全绿。

### 3.6 Free / Standard

- Free 可完成 Token 方案业务准备和内部只读预览，但不能真实部署、Mint、Burn、改变生产限制或产生对外 Token 交付。
- Standard + KYB 通过可使用已开放的准备/查看能力；订阅付费本身不等于生产授权。
- Standard 只有在所有适用法律、发行主体、网络/标准/模板、安全、Signer、外部服务和生产准入均通过后，才可由真实有权主体执行相应操作。
- 降级后历史合约/Token/链上事实只读保留；不得删除真实持有人权益、在途任务或法定义务。
