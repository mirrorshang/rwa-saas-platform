### 1.1 企业操作路径（MVP）

`Offering Confirmed → 发行准备（单页）→ 查看七组检查/补缺 → 预览投资者页面 → 企业最终声明与确认 → Sandbox模拟发布或受控真实发布`

**Confirmed不等于Published。** 发行方案确认后仅建立本轮有效权益预留；发行准备完成和企业声明也不构成资金/Token生产准入。正式发布还必须通过适用法域/监管、KYB、平台自身生产服务门、Signer、Provider、合约及链网络等独立检查。

### 1.2 七组检查

| 检查组 | 业务来源与职责 | 页面状态口径 |
|---|---|---|
| 01 企业与发行环境 | Tenant、订阅、必要KYB、当前账号授权、Sandbox/Standard、生产服务门 | 通过/待补充/阻断 |
| 02 资产及文件 | Asset状态、权属及必要文件、扫描、版本和披露范围 | 通过/待补充/阻断 |
| 03 权益结构及容量 | Instrument状态、权益法律文件、授权容量、映射、版本 | 通过/待补充/阻断 |
| 04 Offering发行参数 | 单轮权益量/Token量/单价、总募集额、窗口、最低/累计限额、有效预留、快照 | 通过/待补充/阻断 |
| 05 投资者展示与必要准入 | KYC服务能力、强制AML/制裁/地区法律阻断机制、允许披露的资料和投资者预览 | 通过/待补充/阻断 |
| 06 支付及Token技术准备 | OP Mainnet USDT支付、Provider/Signer/合约/链网络的技术安全与生产Gate | 通过/待补充/阻断 |
| 07 企业最终声明 | 企业有权账号就自身资产、权益、披露和合法性责任作出最终确认 | 未确认/已确认；声明有版本、时间与引用快照 |

检查结果由对应权威数据/受控服务生成，**不得让企业通过人工按钮改写检查为“通过”**。待补充项提供“去补充/去修改/查看原因”入口并返回原业务对象处理。

### 1.3 责任边界与术语

- 平台做资料字段/文件版本/扫描状态/对象关联/容量/参数的技术和完整性检查，并维护自己服务、风险和生产准入门。
- 发行企业对其资产信息、真实权属、法律文件、合规资格、披露和发行合法性负责；平台检查“资料已提交”不等于对法律真实性作背书。
- KYC通过且有效只赋予MVP**基础认购资格**，不代表所有法域和工具均可以发行或销售；强制AML/制裁、法域适用及生产准入仍需阻断。
- 不引入企业内部多成员/多级审批；法律或监管所要求的第三方、专业机构及平台自身强制审批不能因MVP简化而省略。
- Free Sandbox模拟发布不能生成真实投资者权益、收款、链上Token、法定登记或Mint。
- Standard订阅不自动授予真实发布权限；合同/法域、KYB、Provider/Signer及平台风险Gate仍保持独立控制。
- 企业声明的正式法律措辞、文件要求及法域差异在法律与生产门确定前仍Draft，不在本批自称已获得有效法律审查。

### 2.1 四种检查结果及发布守卫

- **通过**：对应权威事实满足当前检查，可在本次版本快照下继续。
- **待补充**：缺字段/文件/声明等企业可处理内容，显示回源修复入口；不能直接发布。
- **阻断**：状态、容量、法律/风险或生产准入条件不允许继续相应真实动作；企业不能手动覆盖。
- **暂无法核实（Unknown）**：服务异常、超时或结果不确定；不得按通过处理，必须核对原请求/Intent。

检查结果来自各自权威数据服务，企业不能通过手动按钮把结果改成通过。修复后重新执行受影响检查；最终发布动作前再次校验全部关键版本和守卫。

### 2.2 企业最终确认之后：部署、Offering发布、Token Mint及投资者平台展示的区别

本节用于明确已批准R2-05-01/02与既有DEC-044、DEC-031的衔接，不表示新批准了真实生产技术方案。

1. **企业最终确认**：形成带有声明版本和业务快照引用的正式发布请求；不是自动完成合约部署、Mint、收款或统一投资端上架。
2. **Sandbox**：只模拟检查通过、模拟发布及模拟页面；不部署真实合约、不产生真实Token、不收取真实认购款、不产生真实投资者权利。
3. **Standard生产路径**：只有适用法域、KYB、平台生产服务、支付、Provider/Signer、合约与链网络等独立Gate满足后，系统才可调用获准的生产编排。是否先部署/绑定实际合约地址再完成法律文书、正式Offering发布，按Instrument/法域及有权法律主体确定；不能由产品UI假定统一时序。
4. **Contract与Token**：每个Instrument一个逻辑Token；同一Instrument多轮Offering复用逻辑Token和已获准的Contract实例，不因每轮Offering重复部署。首次需要部署/注册时按独立批准的架构执行并验证链上结果。V1“一个生产主合约”仍是产品目标，具体如何承载多个逻辑Token、合约标准、网络、地址/Token ID策略仍是独立技术Gate。
5. **Mint**：Offering正式发布时不会一次性Mint本轮最大供应量。只有投资者订单满足KYC及适用资格、资金已由权威主体确认、配售/权益分配事实完成、生产Mint Gate满足后，才对实际应分配数量执行受控Mint并核验。已分配不等于已Mint。
6. **Issuer正式发布与统一投资端上架**：二者不是同一状态。依DEC-044，Issuer按**每轮Offering自愿申请**上架统一投资端M；平台运营端P另行审核渠道准入。只有M渠道审批通过且当前展示授权有效，Offering才会在统一投资端相应范围展示。平台审核的是WDEX渠道准入，不代替Issuer法律发行审批。
7. **展示与可认购分离**：即使Offering已经在M展示，投资者是否能认购仍要独立检查销售窗口、KYC、适用法域/强制限制及该Offering的当前资格；未开售、暂停、关闭或投资者不符合条件时，可以依法展示但不能创建有效新订单。Issuer自有投资者门户V与统一投资端M的展示渠道配置彼此独立。
