# V1.0 → V1.1 兼容升级候选方案

**没有执行数据库迁移。** 实际后端仓库、DDL、API、生产数据量与工程师进度尚未取得，均为 NOT VERIFIED。本方案仅供工程师以现行实现复核。V1.0 冻结分支与既有订单、名册、分配、文件版本不得覆盖。

## 推荐顺序

1. 工程师记录真实后端仓库、分支、Commit、Schema、已上线端点和外部 Provider 状态；以 V1.0 正式 PRD/OpenAPI 对照。
2. 确认 [PRD 增量](V1.1-PRD-DELTA.md)、[Schema 差异](V1.1-DATA-SCHEMA-DIFF.md)、[API 差异](V1.1-API-DIFF.md) 与实际实现的一致性。存在差异先记录决策，不直接部署候选 DDL。
3. 在隔离环境备份原始数据库和文件元数据；校验备份可恢复。扩展可空的新列/关联表，保留旧接口和旧字段语义。
4. 对存量 Asset/Instrument/Offering 标注历史版本；新 SPV、回报、文件权限默认 **Unknown/未核实**。不得把空值写成“无 SPV”、0% 或“公开”。不从旧股权的收益参与比例推导新股权字段。
5. 只对经原始文件复核且有授权的记录补录新主体、权利、回报与公开权限；每次补录生成新版本和审计轨迹。历史已确认 OfferingSnapshot 原样保留。
6. 在隔离环境测试逐版读取、并发版本冲突、文件直达拒绝、M Listing Gate、价格变化失效、私密字段不外泄和回滚恢复。
7. 先上线可兼容读取的新服务，再接 V1.1 Issuer 与 V/M 前端；按 `PublishedOfferingDisclosure 1.1.0` 做实际同源联调。原接口不删除。
8. 工程师完成业务回归和安全审核后，另行决定正式升级。真实支付、登记、合约、收益与本金主账继续使用权威系统，不由本地 Mock 迁移。

## 兼容和回滚

- 旧 `localStorage` v4 仅是前端原型记录。新版新增字段均可缺省；旧记录显示待核实，读取时不隐式补事实。新建权益标注 `termsSchemaVersion=2`，新建发行标注 `disclosureSchemaVersion=2`，其确认必须通过新校验。
- 新版确认快照深拷贝 Asset、Instrument、Project、钱包、文件及回报披露；发布快照再固定确认版本。已确认条款不可原地编辑，已有订单及持仓引用原版。
- 回滚应先停新写入，依据备份与变更日志恢复服务和 Schema；不得以删掉新列的方式丢失 V1.1 记录。回滚后读取新版本的行为须明确拒绝并提示，不可静默当旧版。
- 每步保留操作时间、执行人、变更脚本 hash、前后数量和失败样本。真实迁移计划与回滚窗口由工程师依据真实部署制定。
