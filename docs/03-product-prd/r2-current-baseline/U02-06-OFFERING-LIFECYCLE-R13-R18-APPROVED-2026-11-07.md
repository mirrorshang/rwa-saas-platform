## 2. 合约收款 → Token 分配 → 企业结算（**Candidate/Open，不是本轮自动批准**）

用户提出「投资者付款理论上应进入合约，再确认收款、Mint Token、分账」。这是一条**优先研究的发行认购/交付付款 DvP 方向**，不是唯一可行的资金路径，也**不能**凭用户提出问题认定为已经授权部署或选择了精确链上实现。

### 用户可理解的目标流程（待专项审核）
```text
企业配置 Offering
   ↳ 选择并验证最终企业收款钱包（MPC / 已绑定自连接钱包）
   ↳ 关联固定版本 Instrument/披露/本期 Token 数量与价格
发布前：合规/身份/支付/Token 合约及权限检查均通过，企业主动确认
投资者符合条件并提交认购 → 获得唯一订单/份额锁定
   → 投资者对**经审核的认购合约**支付 USDT（不是直接打给企业钱包）
   → 以链上实际支付和订单状态为依据验证成功，核对投资者合规和额度
   → 通过受控合约/获授权 Mint 路径分配对应 Token
   → 按明示的法定/业务规则向企业收款钱包及适用费用收款方结算
任意失败：不得虚假显示已完成；资金按允许的协议留在可追踪待处理状态，
   按经批准的退款、撤销或人工受控恢复规则处理；不可吞款或重复 Mint
```

### 两种底层实现候选（均须安全、法律与技术团队专项批准）
| 方式 | 好处 | 必须解决 |
|---|---|---|
| **候选 A｜同链原子结算 / Payment-versus-Delivery** | 若收款/资格校验、Token Mint/转让、分账都能由**同一笔链上事务**确定性完成，则可做到全部成功或交易回滚，降低「付了钱却没领 Token」风险 | 合约必须拥有获授权 Mint/交付权限，链上能验证合规资格且无法绕过容量限制；付款 Token 兼容性、费用、签名权限、合约审计、法律适用性、拒绝/额度与失败安全门。**并非所有 RWA 合约与法域均允许在支付瞬间 Mint** |
| **候选 B｜受控认购托管 + 后续分配** | 容纳链下合规审查、签署、需受控发行人的审批/授权，以及不能同步 Mint 的发行流程 | 链上资金托管与法律资金控制主体、等待时间、退款与争议权、超时恢复、订单与资金对账、独立 Mint 回执及结算原子性/分阶段交付，**特别不能在 Mint 失败时自动向企业分账** |

- **不得把「付款交易确认」直接等同「Mint 成功」或「企业已结算到账」**，后端/索引服务应按真实事件、最终性与幂等状态核对。
- **「分账等」没有批准任何平台费率**；不得沿用 USDable 95%/5%、固定收款方或把平台自身设置为法定监管资金控制者。
- 合约的所有者/可升级性、暂停/紧急退款、重入保护、权限分离与签名门、身份与持有人白名单、抵御重复付款/双重 Mint、回滚/提款审计、资金与代币精度、实际合约部署/主网执行都保持 Draft。
- 可研究 ERC-3643 类具备资格与转让限制的 RWA Token 规则，但不由此指定最终 Token 标准或自动获得所有三类 Instrument 的法律适用性。
- **OP Mainnet USDT 合约重要事实核验门**：2026-09 主流交易平台公告显示 Optimism 网络 USDT 存在合约置换；截至当前必须由技术方核实**官方发行方支持、正确 OP Mainnet 合约地址、是否为原生/桥接资产、decimals、黑名单/冻结/升级、钱包及交易所兼容性**，绝不能根据老示例地址直接部署认购合约。公共资料供复核：[Binance 2026-09-14 公告](https://www.binance.com/en-AE/support/announcement/detail/134703caeb664402bb71c023be94c01c)、[KuCoin 已完成置换公告](https://www.kucoin.com/announcement/en-kucoin-has-completed-the-usdt-contract-swap-on-the-optimism-network)、[Tether 支持协议页](https://tether.to/en/supported-protocols/)；上述资料**不构成**新合约地址已获我方生产批准。
