# RWA SaaS V1.0 实际前端交付基线

> 基准：`codex/v1-final-frontend-integration-20261116` @ `05bda87a32de34e0324f480901b9024ab676f3d7`（源码提交 `b9e87be7`）。日期：2026-11-16。本文件只确认可从该提交观察的前端能力；Mock、生产服务、原批准范围分别记录。当前版本归属以 [2026-11-18 SaaS 版本决策记录](SAAS-VERSION-ALIGNMENT-DECISIONS-2026-11-18.md) 为准。

## 1. 产品与版本边界

当前工程交付为 Web 官网及邮箱登录入口 `apps/website`，以及独立 Issuer 企业后台 `apps/issuer`。Issuer 有九个一级导航。当前 V1.0 不交付独立投资者平台、平台统一投资端、二级市场、完整白标、完整 OpenAPI、平台运营后台或移动端。企业后台的“投资者门户”是配置和预览页面，不是独立投资者交易应用。

**证据层级**：源码中的可执行交互 → 本轮自动化测试 → 历史验收记录 → 产品批准文件。按钮、导航、示例数据、预置场景和静态文案本身不构成功能验收。全部生产身份、资金、法定登记、钱包及链上事实仍待真实后端和外部权威接入，见 [Backend Developer PRD](V1.0-BACKEND-DEVELOPER-PRD.md)。

**文档冲突与当前版本决策**：历史 R2 基线在 `docs/r2-current-product-baseline` @ `ae9762c` 记载 W/I/V/M/P、204 项及“8×24、四种房地产模板”；当前交付基线限定官网/邮箱登录/Issuer，采用“7×23”目录和六种已开放模板。六模板的专属字段与 Ready 完整度、三种权益结构独立化进入 SaaS V1.5；Project、Asset/Instrument 业务版本历史和 Offering 历史快照进入 V2.0 统一需求池。V1.0 保留 Asset→Instrument→Offering 的直接基础关联。DEC-017 的 193 项原版号及 DEC-057 新增 11 项的历史批准事实均不改写；其他平台功能不纳入本轮 SaaS 版本归属。

## 2. 官网和登录

官网正式路由定义于 `apps/website/src/main.tsx`；旧 Issuer 原型组件虽仍在网站源码中，但不在正式路由树。页面级审计如下。

| 页面/路由 | 当前可操作内容 | 限制与生产依赖 |
|---|---|---|
| 首页 `/` | 浏览定位和导航，前往产品、套餐、登录 | 内容页；无业务交易 |
| 功能 `/features`、方案 `/solutions`、套餐 `/pricing` | 浏览说明和跳转 | 价格/准入仅展示，非权威订阅 |
| 投资者平台说明 `/investor-platform` | 浏览筹备说明 | 非独立投资者平台 |
| 帮助 `/help`、联系 `/contact` | 浏览问答及前端联系表单 | 无真实工单/邮件服务 |
| 政策 `/policies`、`/policies/$policy` | 阅读静态政策 | 法律生效版本需独立确认 |
| 升级说明 `/standard-upgrade` | 阅读并跳转 | 不创建真实订阅 |
| 登录 `/login` | 邮箱、发送/填写验证码、条款确认、本地演示跳转 | `apps/website/src/pages/Login.tsx` 的演示码为 123456；正式认证、节流、安全会话和跨应用身份传递未接入 |
| `/register`、`/verify-email` | 兼容地址跳转登录 | 不构成独立注册流程 |

官网与 Issuer 目前是两个独立构建的应用。Issuer 从本地状态装载，不验证官网登录会话；跨应用认证闭环**未完成**。服务端必须提供首次登录建号、会话、租户绑定和退出契约。

## 3. Issuer 路由、持久化与判定

## 4. 业务关系和规则

当前原型保留 Asset → Instrument → Offering 的直接关联，投资者/订单/付款/持有人/Token/分配通过本地 ID 引用；源码没有独立 Project。**V1.0 不建设 Project、Asset/Instrument 业务版本历史及 Offering 通用历史快照**，这些进入 V2.0 统一需求池。V1.0 仍须在订单记录中固定交易所需的数量、单价、币种、费用和支付指令；收益分配按 Record Date 保留法定持有人快照。Offering 关联经验证钱包，订单生成时记录实际收款指令。已批准的精简导航要求认购历史归订单“已完成”筛选、锁仓归持有人详情；不另建菜单。

产品目录按本轮指令为 7 大类、23 二级类，拟开放住宅、写字楼、商铺、工业园/仓储物流、非上市企业普通股权、单笔企业借款债权。源码有六种示例资产与创建入口，但住宅和债权的 `assetMissing` 有专门 Ready 校验；其余模板的字段与约束不能仅凭示例视为完成。Asset、Instrument、Offering 保持独立业务对象并直接关联；Project 为 V2.0 增强对象；权益类型为股权、债权、收益参与权，三种结构独立化进入 V1.5。

金额 UI 使用 U，以 USDT 计价。投资者付款目标网络 OP Mainnet USDT；Token 部署网络须独立决定。“1 U = 8 元”在 Issuer 源码被用于住宅估值换算，**仅为已批准测试场景**，不能作为生产全局汇率。订单、付款、资金匹配、配售、法定登记、Token 交付和链上最终性须各自保留状态。零持有人只能保存分配草稿；本金不计入累计收益；债权全额还本或到期后不能继续自动计正常利息。当前前端相关守卫需要手工流程复验，生产主账尚不存在。

Free 可准备资产、权益和 Offering 并作内部预览；Standard 原型状态只解锁 Mock 演示。企业 KYB、钱包、发行、资金、Token 及门户公开发布还受独立生产条件约束。降级不能删除既有法定和业务义务。
